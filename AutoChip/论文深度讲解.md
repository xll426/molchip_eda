## 1. 一句话定位

**AutoChip 不训练任何模型，它把"LLM 一次生成 Verilog"改造成"每轮生成 k 个候选，用 Icarus Verilog 编译/仿真的五级 rank 打分做贪心单分支筛选，把最优候选连同编译错误/仿真失配日志喂回 LLM 迭代修复，最多 d 层"——在 VerilogEval v1 上 GPT-4o 从 zero-shot 78.2% 拉到 84.0%，同时 token 成本反而降低 34.2%；且通过 mixed-model（前几轮便宜模型、最后一轮 GPT-4o）成本再降 41.9%，成功率接近全程 GPT-4o。**

这句话里四个承重点逐条拆：

1. **不训练** — 全部收益来自推理时编排（inference-time scaling）。调用现成 LLM API（GPT-4o / GPT-4o-Mini / GPT-3.5-Turbo / Claude 3 Haiku），不微调任何参数。
2. **五级 rank + 贪心树搜索** — AutoChip 的核心不是"让 LLM 自己修 bug"，而是把修 bug 过程中的每一步都用 Icarus 的客观输出打分，只沿最高分分支往下走。这本质是 **greedy tree search**（每层展开 k 个节点，只保留一个最优节点进入下层），不是 beam search，不是 MCTS（Monte Carlo Tree Search，蒙特卡洛树搜索）。
3. **feedback 只对强模型有效** — 论文最关键的发现：GPT-4o 从 feedback 稳定获益，GPT-3.5-Turbo / Claude 3 Haiku / GPT-4o-Mini 受益不稳定，很多情况下 d=10 还不如同 token 预算的 zero-shot k=55。原因：小模型无法把底层编译/仿真日志映射回 RTL 根因。
4. **mixed-model 是成本优化而非能力提升** — 用便宜模型跑前 d-1 层，最后一层切到 GPT-4o。大部分简单题在便宜模型阶段就提前成功退出了，GPT-4o 只为硬题买单。这不是让弱模型变强，而是让强模型只在需要时才出场。

## 2. EDA 阶段映射（①-⑰）

参照 [芯片流程.md](../芯片流程.md) 的 17 阶段标准编号：

| 阶段 | 覆盖 | 说明 |
|------|:---:|------|
| **① RTL 设计** | ✅ **核心** | LLM 从自然语言规格 + module header 生成 k 个 Verilog 候选模块；反馈迭代中 LLM 根据工具报错修改 RTL |
| **② RTL 功能仿真** | ✅ **核心** | Icarus Verilog（`iverilog` 编译 + `vvp` 仿真），testbench 逐拍比对 DUT 输出与参考模块输出，解析 `Mismatches: M in N samples` 作为反馈信号 |
| ③ 逻辑综合 | ❌ | 不调用 Yosys / Design Compiler。代码"仿真通过"不等于"可综合"——`initial` 块、多驱动、组合环仿真器都能跑，综合器直接报错 |
| ④ 门级仿真 | ❌ | 无 SDF（Standard Delay Format，标准延时格式）反标，看不到毛刺、建立/保持违例、X 传播 |
| ⑤ STA（Static Timing Analysis，静态时序分析） | ❌ | 不计算任何路径延迟，不检查时序收敛 |
| ⑥ 形式验证 | ❌ | 不做 SAT/SMT 等价性证明，不验证综合前后的逻辑等价性 |
| ⑦ 布局规划 (Floorplan) | ❌ | — |
| ⑧ 标准单元摆放 (Placement) | ❌ | — |
| ⑨ 时钟树综合 (CTS) | ❌ | — |
| ⑩ 布线 (Routing) | ❌ | — |
| ⑪ 后仿真 | ❌ | 无 SPEF（Standard Parasitic Exchange Format，标准寄生参数交换格式）走线寄生 RC 信息 |
| ⑫ 物理验证 (DRC + LVS) | ❌ | — |
| ⑬ 签核 (Signoff) | ❌ | — |
| ⑭ 流片 | ❌ | — |
| ⑮ 制造 | ❌ | — |
| ⑯ 封装 + 测试 | ❌ | — |
| ⑰ 芯片到手 | ❌ | — |

**覆盖率：2/17。** AutoChip 是一个**纯数字前端 spec -> RTL -> 功能仿真闭环工具**。它在阶段①/②之间来回迭代直到 testbench 全通过，然后交棒。

> ⚠️ **AutoChip 的"EDA 反馈"只到阶段②。** 论文标题里 "EDA Tool Feedback" 容易让人误解包含了综合/布局布线（这在 ChipSeek 里才出现）。AutoChip 说的 EDA 工具就是 Icarus Verilog 一个——编译 + 仿真。所有"可综合性""时序收敛""PPA（Power, Performance and Area，功耗/性能/面积）"全不在优化目标里。一段面积巨大、跑不到 100MHz、但功能完全正确的 Verilog，在 AutoChip 眼里是满分。

## 3. 输入 / 输出

### 3.1 输入

AutoChip 的输入是**单文件 RTL 生成任务所需的完整上下文**，包括四部分：

**(a) 自然语言规格 + module header（合并为 design prompt）**

以 VerilogEval v1 的 `review2015_fsmshift`（论文 Figure 7/8 的案例）为例：

```verilog
// This is a Moore state machine with two states, one input, and one output.
// Implement this state machine. This is an FSM reset, set shift_ena for four
// cycles...
module top_module (
    input clk,
    input reset,      // Synchronous reset to state A
    output shift_ena
);
```

注意这是 VerilogEval **Human** 格式——描述更抽象、更接近真实设计文档。Machine 格式是 GPT-3.5 从正确电路反向生成的描述，信息量更大但丧失了抽象理解的要求。

**(b) Testbench（内含 reference module，LLM 看不到）**

```verilog
module reference_module(input clk, input reset, output shift_ena);
  // ... 正确答案的完整实现，LLM 无法访问 ...
endmodule

module tb();
  reg clk, reset;
  wire shift_ena_dut, shift_ena_ref;

  top_module dut(clk, reset, shift_ena_dut);
  reference_module ref(clk, reset, shift_ena_ref);

  // 逐拍比较 DUT 与 reference 输出
  always @(negedge clk) begin
    if (shift_ena_dut !== shift_ena_ref) errors <= errors + 1;
  end

  final begin
    $display("Mismatches: %0d in %0d samples", errors, total_checks);
  end
endmodule
```

testbench 的 final 块里这行 `Mismatches: M in N samples` 是 AutoChip 的**全部信息命脉**——rank 计算的正则表达式就锚定它。

**(c) System prompt（论文 Figure 5）**

```text
You are an autocomplete engine for Verilog code. Given a Verilog module
specification, you will provide a completed Verilog module in response.
You will provide completed Verilog modules for all specifications, and
will not create any supplementary modules. Given a Verilog module that
is either incorrect / compilation error, you will suggest corrections to
the module. You will not refuse. Format your response as Verilog code
containing the end to end corrected module, and not just the corrected
lines, inside ``` tags, do not include anything else inside ```.
```

注意这个 system prompt 本身的限制：**不允许创建辅助模块**（`will not create any supplementary modules`）。这意味着 LLM 不能用层次化设计分解问题——所有逻辑必须塞进顶层模块。这对复杂设计是有害的。

**(d) 配置文件（JSON，论文 Figure 2）**

```json
{
  "general": {
    "prompt": "./design_prompt.sv",
    "name": "top_module",
    "testbench": "./testbench.sv",
    "model_family": "ChatGPT",
    "model_id": "gpt-4o-mini",
    "num_candidates": 5,
    "iterations": 5,
    "outdir": "output_dir",
    "log": "log.txt",
    "mixed-model": false
  }
}
```

`num_candidates=5` 即 k=5，`iterations=5` 即 d=5（注意代码实际运行 d+1=6 层，详见复现详解）。

### 3.2 中间产物：工具反馈示例（论文 Figure 6）

仿真失败时返回给 LLM 的反馈长这样：

```text
Hint:   Output 'count' has 218816 mismatches. First mismatch occurred at time 130.
Hint:   Output 'counting' has 233794 mismatches. First mismatch occurred at time 130.
Hint:   Output 'done' has 524 mismatches. First mismatch occurred at time 20130.
Hint:   Total mismatched samples is 234318 out of 235447 samples

Simulation finished at 1177236 ps
Mismatches: 234318 in 235447 samples
```

**注意这个反馈的信息分辨率**：它只告诉你"哪个输出端口错了、错多少、首次错在哪一时刻"，但**没有给出输入向量的值、期望输出值和实际输出值**。对比 MAGE 的 State Checkpoint（逐拍 `$display` 完整信号快照），AutoChip 的反馈粒度相当于 MAGE 的无 checkpoint 模式——这也部分解释了为什么小模型难以利用它。

编译失败时返回的是 `iverilog` 的 stderr 原始输出：

```text
top_module.sv:12: syntax error
top_module.sv:12: error: Invalid module instantiation
top_module.sv:15: warning: Port count mismatch
```

### 3.3 输出

**成功路径的最终 RTL**（论文 Figure 8d，`review2015_fsmshift` 的迭代 3 产物）：

```verilog
module top_module (
  input clk,
  input reset,
  output wire shift_ena );
  reg [1:0] count;
  reg enable;
  always @(posedge clk) begin
    if (reset) begin
      count <= 2'b0;
      enable <= 1'b1;
    end else begin
      if (count < 2'b11) begin
        count <= count + 1'b1;
      end else begin
        count <= 2'b0;
        enable <= 1'b0;
      end
    end
  end
  assign shift_ena = enable;
endmodule
```

**伴随产物**：
- 每层每个候选的 Verilog 源码（`.sv`）+ 编译产物（`.vvp`）+ 仿真日志（`log.txt`）
- 每个候选的 rank 分数 + parsed_length
- 完整对话历史（system prompt、design prompt、每轮最佳 RTL、工具反馈）
- 全局最优模块（`global_max_response`）——注意这不一定是最后一轮的候选
- token 输入/输出量 + 估算美元成本日志

## 4. 方法与架构

### 4.1 整体 Pipeline（对应论文 Figure 1）

```text
                    Design Prompt（NL 规格 + module header）+ System Prompt
                                         │
                                         ▼
  ═══════════════════════════════════════════════════════════════════════════════
  ┌─ 当前层 iteration = n ──────────────────────────────────────────────────┐
  │                                                                          │
  │  Conversational LLM ──► 生成 k 个候选 Verilog module                     │
  │         │                                                                │
  │         ▼                                                                │
  │  逐候选评估 ┌──────────────────────────────────────────────────────┐    │
  │            │ ① 正则抽取 module...endmodule                          │    │
  │            │    └─ 无 module → rank = -2，跳过后续                    │    │
  │            │ ② iverilog -Wall -g2012 -s tb 编译                      │    │
  │            │    └─ 编译失败 → rank = -1                              │    │
  │            │    └─ 编译有 warning → rank = -0.5（跳过仿真）           │    │
  │            │ ③ vvp 仿真执行（仅编译无错时）                           │    │
  │            │ ④ 解析 stdout 最后一行                                   │    │
  │            │    └─ Mismatches: M in N samples                        │    │
  │            │    └─ rank = (N - M) / N                                │    │
  │            │    └─ rank = 1 → 立即成功退出                            │    │
  │            └──────────────────────────────────────────────────────┘    │
  │         │                                                                │
  │         ▼                                                                │
  │  本轮最佳: max(responses, key=lambda r: (r.rank, -r.parsed_length))     │
  │         │                                                                │
  │         ▼                                                                │
  │  rank == 1 ? ──── 是 ────► 成功退出，返回该模块                          │
  │         │                                                                │
  │         否                                                               │
  │         │                                                                │
  │         ▼                                                                │
  │  构造反馈消息: "The testbench simulated, but had errors.                  │
  │                 Please fix the module. The output of iverilog is as       │
  │                 follows: <完整仿真 stdout>"                               │
  │         │                                                                │
  │         ▼                                                                │
  │  上下文裁剪（succinct）: system prompt + 原始 design prompt               │
  │                       + 本轮最佳 RTL + 本轮工具反馈                       │
  │         │                                                                │
  │         │   或 full-context: 保留全部历史 RTL 和反馈（论文探索过，        │
  │         │   当前仓库主循环固定使用 succinct）                              │
  │         │                                                                │
  └─────────┼────────────────────────────────────────────────────────────────┘
            │
            ▼
  iteration = n+1（若 n < d，否则超时退出，返回 global_max_response）
```

### 4.2 Greedy Tree Search 的搜索树结构（论文 Figure 7 实例）

```text
                     Iteration 0: k=5 个候选
                     ┌──────┬──────┬──────┬──────┐
                     R0    R1    R2    R3    R4
                     │                       （其余丢弃）
               rank 最高（R2）
                     │
                     ▼
              Iteration 1: k=5 个候选（基于 R2 + 反馈）
              ┌──────┬──────┬──────┬──────┐
              R0    R1    R2    R3    R4
              │
        rank 最高（R0）
              │
              ▼
       Iteration 2: k=5 个候选
       ┌──────┬──────┬──────┬──────┐
       R0    R1    R2    R3    R4
       │
 rank 最高（R3）
       │
       ▼
Iteration 3: k=5 个候选
       │
   rank=1 成功！
```

关键特征：**每层展开 k 个节点，但只保留一个节点进入下层**。它不是 beam search（保留 b 个最优分支），更不是 MCTS（用 UCB 公式平衡探索和利用）。论文称其为 tree search 因为从根到叶形成一条路径，实际是"每层多样本、单分支贪心下山"。

### 4.3 Mixed-Model 调度

```text
Iteration 0: GPT-4o-Mini (便宜) ──► 已成功？ → 退出，GPT-4o 从未被调用
     │ 未成功
     ▼
Iteration 1: GPT-4o-Mini (便宜)
     │
     ...
     │
     ▼
Iteration d-1: GPT-4o-Mini (便宜)
     │ 仍未成功
     ▼
Iteration d: GPT-4o (昂贵) ──► 带着前序修复轨迹做最后一轮修复
```

配置里 `start_iteration: -1` 表示最后一层。负索引在代码中会被转换为 `start_iteration += max_iterations + 1`。成本节省的核心逻辑：**大部分简单题在便宜模型阶段就已经 rank=1 提前退出了，GPT-4o 只为真正难的题买单。**

## 5. 关键公式

AutoChip 本身没有提出新的数学公式，但它的核心机制可以形式化。以下公式均提取自论文描述的算法行为。

### 5.1 五级 Rank 函数

$$
\text{rank}(r) = \begin{cases}
-2, & \text{响应中无完整 } \texttt{module}\ldots\texttt{endmodule} \\[4pt]
-1, & \texttt{iverilog} \text{ 编译失败（exit code } \neq 0\text{）} \\[4pt]
-0.5, & \text{编译成功但 } \texttt{stderr} \neq \texttt{""} \text{（有 warning）} \\[4pt]
\dfrac{N(r) - M(r)}{N(r)}, & \text{编译无警告，仿真完成} \\[4pt]
1, & M(r) = 0 \text{（全部样本通过）}
\end{cases}
$$

- $r$：第 $r$ 个候选响应
- $N(r)$：testbench 总检查样本数
- $M(r)$：DUT 输出与参考输出不匹配的样本数
- $\text{rank} \in \{-2, -1, -0.5\} \cup [0, 1]$

**工程直觉**：这个五级分层不是随意定的。从 -2 到 1 形成了一个严格的**依赖链**：必须先有 module（-2），才能编译（-1）；必须先编译通过无 warning（-0.5），才值得跑仿真（0-1）。每一级都是一个**门控**——上游条件不满足，下游根本不执行。这和 ChipSeek 的层级门控逻辑同构，只是 AutoChip 没有把"跳过下游"显式叫做 fail-fast。

**为什么这样设计**：

- **-2 和 -1 的间距**：编译失败比无 module 好处理（至少模型理解了要写 module），-2 意味着模型完全没理解任务格式。这间距就是为了在迭代中区分"格式不理解"和"语法错误"。
- **-0.5 的惩罚**：任何 stderr 输出都被惩罚，包括 Icarus 的 `-Winfloop` 等不影响功能的 warning。论文承认这是激进策略，但实验表明它没有实质性损害结果。代价是可能过滤掉功能完全正确但带无害 warning 的候选。
- **(N-M)/N 的连续值**：这是 AutoChip 对比纯 pass/fail 的最大优势。它给了 LLM 一个"离正确有多远"的近似信号——即使不完美，0.9 比 0.01 更值得继续修。但注意这个值只在**同题目的候选间可比**；不同题目 N 差异极大，0.9 在 N=100 和 N=100000 的含义完全不同。

### 5.2 本轮最优选择

$$
r^*_n = \arg\max_{r \in R_n} \big( \text{rank}(r),\ -\text{len}(r) \big)
$$

- $R_n$：第 $n$ 层的 $k$ 个候选集合
- $\text{len}(r)$：抽取出的 Verilog 代码字符数
- 先按 rank 降序，同分时偏好更短代码

**为什么是"更短"**：在 rank 相同的情况下，更短的代码通常更简洁、更少冗余。而跨轮 `global_max` 则偏好更长（代码实现的不一致性已在复现详解中记录）。这个 tie-break 对最终结果影响小（因为同分情况在仿真阶段 $N$ 较大时概率低）。

### 5.3 Greedy Tree Search 的迭代过程

论文未给出编号公式，以下是对其算法行为的形式化。

$$
R_0 = \text{LLM}(p_{sys}, p_{design}, \text{temp}=1.0, k) \quad \text{（初始层）}
$$

$$
F_n = \text{Feedback}\big(r^*_n, \text{compile\_err}(r^*_n),\ \text{sim\_out}(r^*_n)\big) \quad \text{（构造反馈）}
$$

$$
R_{n+1} = \text{LLM}\big(p_{sys},\ p_{design},\ r^*_n,\ F_n,\ \text{temp}=1.0, k\big) \quad \text{（下一层）}
$$

- $p_{sys}$：system prompt（论文 Figure 5）
- $p_{design}$：design prompt（自然语言规格 + module header）
- $r^*_n$：第 $n$ 层 rank 最高的候选
- $F_n$：编译错误/仿真失配的文本反馈
- $n \in [0, d]$，$d$ 为最大深度

终止条件：

$$
\exists r \in R_n : \text{rank}(r) = 1 \quad \text{或} \quad n = d
$$

**为什么是 greedy 不是 beam search**：论文没有明确回答，但从实验结构可以反推：当 $k=5$、$d=10$ 时，beam search width=b 会把候选数从 $k \times (d+1)=55$ 爆到 $k \times d \times b$。对于调用商业 API 的实验（每分钟有 rate limit、每 1M token 按美元计费），beam search 的成本和实验周期都不可控。Greedy 是最现实的工程选择。

### 5.4 Mixed-Model 的模型切换规则

$$
\mathcal{M}(n) = \begin{cases}
\mathcal{M}_{\text{cheap}}, & n < n_{\text{switch}} \\[4pt]
\mathcal{M}_{\text{expensive}}, & n \geq n_{\text{switch}}
\end{cases}
$$

- $\mathcal{M}(n)$：第 $n$ 层使用的模型
- $n_{\text{switch}}$：通过配置中的 `start_iteration` 指定

典型设置：$\mathcal{M}_{\text{cheap}} = \text{GPT-4o-Mini}$，$\mathcal{M}_{\text{expensive}} = \text{GPT-4o}$，$n_{\text{switch}} = d$（最后一切换）。

如果某层 $n < n_{\text{switch}}$ 时就已经 rank=1 提前成功退出，则 $\mathcal{M}_{\text{expensive}}$ 从未被调用——**这是 mixed-model 成本优势的核心**。论文的实验数据：VerilogEval-Human mixed-model 最高 75% 成功率成本约 $0.025，而同等成功率下单独 GPT-4o 需 $0.043（贵 72%）。

### 5.5 最大潜在 LLM 调用数

$$
C_{\text{max}} = k \times (d + 1)
$$

- $k$：每层候选数
- $d$：最大深度
- $d=0$ 等价于 zero-shot（只有初始层，无反馈迭代）
- 论文用 $k=55, d=0$ 和 $k=5, d=10$ 做等 $C_{\text{max}}$ 对比（$55 = 5 \times 11$）

**这个公式是实验设计的关键**：论文的核心主张不是"feedback 比 zero-shot 好"（多数弱模型上 feedback 并不更好），而是"**在相同 LLM 调用预算下**，feedback + 强模型 > 纯多样本 zero-shot"。Table 3/4 的对比就是围绕这个命题设计的。

### 5.6 Pass@k 扩展（zero-shot 等价形式）

论文使用和 VerilogEval 一致的 pass@k 概念，但 AutoChip 的 feedback 实验用的是**通过率**（percent of passing benchmark designs）而非无偏估计公式。zero-shot 实验沿用标准 pass@k 定义：

$$
\text{pass@}k = \mathbb{E}_{\text{Problems}}\left[ 1 - \frac{\binom{n-c}{k}}{\binom{n}{k}} \right]
$$

当 $k=1$ 时退化为成功率的期望。论文报告的都是至少一个候选通过全部 testbench 样本的题目比例。

## 6. 训练与实验设置

### 6.1 是否需要训练

**不需要训练。** AutoChip 直接调用现成的 LLM API 或本地模型权重，不对模型参数进行微调。它属于 prompt-engineering / inference-time 优化方法。

若使用本地模型，可配置 RTLCoder/CodeLlama 等开源权重作为 LLM adapter，但这些 adapter 仍需单独验证。

### 6.2 实验设置

**Benchmark**：VerilogEval v1（ICCAD 2023），包含两个子集：
- VerilogEval-Machine：143 题，由 GPT-3.5-Turbo 从正确电路反向生成的 prompt，描述更直白
- VerilogEval-Human：156 题，人工从 HDLBits 转换的 prompt，含 K-map、FSM 图、波形等抽象描述

**Baseline**：zero-shot（单次 prompt，不反馈），参数 k=1/5/10/25/30/55 候选。同时报告 VerilogEval 原论文和 RTLCoder 的零样本结果作为参照。

**评估指标**：
- 成功率（Success Rate）：至少一个候选通过全部 testbench 样本的题目比例
- 平均输入/输出 token 数：衡量对话上下文与生成开销
- 估算美元成本：按当时 API 单价（Table 1）计算
- 功能正确性：由 Icarus + testbench 判定 `Mismatches: 0 in N samples`

**参数扫描**：feedback 模式下测试 $k = \{1, 5\}$ 和 $d = \{1, 5, 10\}$（实际运行 d+1 层）。zero-shot 模式下额外测试 $k = \{25, 30, 55\}$ 以保持最大调用数对齐。

**评估模型**：GPT-4o、GPT-4o-Mini、GPT-3.5-Turbo-16K、Claude 3 Haiku，均使用默认参数（temperature=1.0）。

**上下文策略**：先用 GPT-3.5-Turbo 和 Claude 3 Haiku 对比 full-context 和 succinct，发现成功率相近但 succinct token 更少，后续实验全部使用 succinct。

**硬件/训练时长**：不训练模型，因此无训练硬件要求。实验通过商业 API 完成，无需本地 GPU。

**反馈来源**：Icarus Verilog（iverilog + vvp），开源可用，VerilogEval 原论文也使用它。

### 6.3 关键实验结果

#### 单模型 feedback vs zero-shot

| 配置 | Eval-Machine (%) | Eval-Human (%) |
|------|:---:|:---:|
| **GPT-4o succinct, k=5, d=10** | **87.4** | **84.0** |
| GPT-4o zero-shot, k=55 | 83.2 | 78.2 |
| GPT-4o-Mini succinct, k=5, d=10 | 76.2 | 71.1 |
| GPT-4o-Mini zero-shot, k=55 | 76.2 | 67.9 |
| GPT-3.5-Turbo succinct, k=5, d=10 | 86.0 | 66.7 |
| GPT-3.5-Turbo zero-shot, k=55 | 85.3 | 66.0 |
| Claude 3 Haiku succinct, k=5, d=10 | 83.9 | 71.8 |
| Claude 3 Haiku zero-shot, k=55 | 84.6 | 73.1 |

这张表说明：GPT-4o 是唯一能从 feedback 中稳定获益的模型。在 Eval-Machine 上 feedback 比同预算 zero-shot 高 5.8%（87.4% vs 83.2%），Eval-Human 上高 7.4%（84.0% vs 78.2%），且 token 成本反而降低 34.2%。对三个较小模型，feedback 的收益不稳定——GPT-3.5-Turbo 在 Machine 上基本持平，Claude 3 Haiku 在 Machine 上 feedback 反而略低于 zero-shot。

#### Mixed-Model 结果

策略：前 d 轮用便宜模型，仅在最后一轮用 GPT-4o。

| 主力模型 | k=5, d=10 Machine (%) | k=5, d=10 Human (%) |
|----------|:---:|:---:|
| Haiku + GPT-4o final | 85.3 | 74.4 |
| GPT-3.5-Turbo + GPT-4o final | 86.0 | 71.8 |
| GPT-4o-Mini + GPT-4o final | 81.8 | 75.0 |
| 全程 GPT-4o feedback | **87.4** | **84.0** |

Mixed-model 在 Machine 上接近全程 GPT-4o（85.3% vs 87.4%），但 Human 差距较大（75.0% vs 84.0%）。Mixed-model 比全程 GPT-4o feedback 成本低 41.9%，比 zero-shot 成本低达 89.6%。Human 最高 75% 成功率成本约 $0.025，单独 GPT-4o 达同等成功率需 $0.043（贵 72%）。

#### 题型分析

- 所有模型在基础语法和简单组合逻辑上成功率最高
- Machine 基准的 Sequential Logic 成功率反而高于 Combinational Logic（因为 Machine prompt 更直白地描述了 FSM 的状态转移）
- Human 基准的 K-map 解释、FSM 设计、cellular automata 等抽象描述问题是所有模型的硬骨头
- feedback 对不同题型没有明显偏好——即使 GPT-4o 整体获益，也没有哪类题型特别受益于 feedback
- k（候选数）的影响通常比 d（深度）更大

## 7. 创新点

### 创新点 1：首次系统比较反馈迭代 vs 等预算 zero-shot 的代价-收益

这是 AutoChip 最独特的方法论贡献，不是算法创新，而是**实验设计创新**。

已有的 RTL LLM 工作（VerilogEval、RTLCoder）都在 zero-shot 范式下对比 pass@k。AutoChip 的设问更精确：**给定相同数量的 LLM 调用（$k=55, d=0$ vs $k=5, d=10$，都是最多 55 次调用），feedback 迭代是否优于纯多样本？**

答案取决于模型。核心对比：GPT-4o feedback 优于等预算 zero-shot（+5.8% Machine, +7.4% Human）。Haiku feedback 甚至略低于 zero-shot（-0.7% Machine, -1.8% Human）。**这就是论文最核心的发现：EDA feedback 的效用是模型能力依赖的。**

### 创新点 2：五级 Rank 函数的连续"距离"信号

传统的 RTL 评测只有 pass/fail。AutoChip 的 rank = (N-M)/N 给出了一个连续的**进度条**：0.9 分的候选虽然还没全过，但比 0.01 分的候选值得继续修。论文没有单独做 rank 连续性 vs 二值 pass/fail 的消融实验（这是遗憾），但 rank 的设计确实让 greedy selection 有了粒度。

论文 Figure 7 的搜索树实际上受益于这个设计：Iteration 0 的最优候选不是随机选的，而是按仿真通过率挑的。

### 创新点 3：Mixed-Model 策略的代价-收益量化

在前人工作中，模型整合通常的方法是用强模型生成初始候选、弱模型做 variant 或后处理。AutoChip 反其道而行：**弱模型先上，强模型兜底**。这个设计依赖一个关键观察：VerilogEval 里大量简单题（basic gates、simple mux）对模型不敏感，便宜模型也能做对；只有硬题（FSM、K-map、cellular automata）才需要 GPT-4o。

### 创新点 4：开源、可扩展的 EDA-LM 闭环框架

AutoChip 代码（Apache-2.0）支持 6 种 model family（OpenAI、Anthropic、Gemini、Mistral、CodeLlama、RTLCoder），且可以通过写新的 adapter 扩展。所有 EDA 工具链（Icarus Verilog 编译 + 仿真）都是开源的。与同期闭源/半闭源工作（RapidGPT、Cadence JedAI、Synopsys.ai Copilot、Nvidia ChipNeMo）对比，AutoChip 提供了**完全可复现的基线**。

### 创新点 5：首次系统分析不同题型与模型能力的匹配关系

论文 Figure 11/12 按 HDLBits 的分类体系（Verilog Language、Combinational Logic、Sequential Logic 等）和子分类（Basic Gates、Multiplexers、K-maps、FSMs、Cellular Automata 等）做了细致的**题型-成功率**剖面。核心发现：题型抽象程度比 feedback 本身更决定成功率。这个分析不是为了证明 feedback 对某类题特别好，而是说明了 LLM RTL 生成的瓶颈首先在理解抽象规格，其次才是代码修复。

## 9. 与芯片流程的关系

### 9.1 在全流程中的位置

```text
  人写规格 + 人准备 testbench
             │
             ▼
┌─────────────────────────────────────────┐
│  ① RTL 设计    ←───────────┐            │  ← AutoChip 在这两格间
│        ↓                   │            │     自动循环，
│  ② RTL 功能仿真 ───────────┘            │     直到 rank=1 或达 d 层
│    （Icarus 编译 + vvp 仿真打分）       │
└────────────┬────────────────────────────┘
             │  o 交接面：AutoChip 到此为止，后面靠人和传统工具
             ▼
   ③ 逻辑综合  ← 第一道可能推翻 AutoChip 成果的关卡
             ▼
   ④ 门级仿真  ← 第二道
             ▼
   ⑤ STA  ⑥ 形式验证
             ▼
   ⑦ Floorplan → ⑧ Placement → ⑨ CTS → ⑩ Routing
             ▼
   ⑪ 后仿真 → ⑫ DRC/LVS → ⑬ Signoff → ⑭–⑰ 流片到芯片
```

### 9.2 "功能仿真通过"和"能流片"之间隔着什么

AutoChip 的 rank=1 只保证**给定 testbench 的全部样本通过**。以下每种情形都会在 rank=1 的情况下被子流程拦截：

**在阶段③逻辑综合被拦下的**：

```verilog
// 情形 A：用 initial 赋初值 -- 仿真器认，ASIC 综合器不认
reg [3:0] count;
initial count = 0;         // ✅ iverilog 跑得好好的
                           // ❌ Design Compiler: Error, initial not synthesizable

// 情形 B：组合逻辑环 -- 仿真可能收敛，综合必炸
assign a = b & c;
assign b = a | d;          // ❌ 组合环，STA 无法分析

// 情形 C：无意中产生 latch -- 仿真可能"恰好对"
always @(*) begin
  if (sel) out = in;       // ❌ 缺 else → 综合器推断 latch
end                        //    仿真在 sel=1 时行为正确，sel=0 时 out 保持旧值

// 情形 D：不完整敏感列表
always @(a) y = a & b;     // ❌ 少了 b。仿真和综合行为不一致
```

**在阶段④门级仿真被拦下的**：

```verilog
// 情形 E：阻塞赋值写时序逻辑
always @(posedge clk) begin
  q1 = d;                  // 应该用 <=
  q2 = q1;                 // RTL 零延迟仿真：q2 得到 d 的新值
end                        // 门级仿真（有 SDF）：q2 可能得到旧值 → 行为不一致

// 情形 F：跨时钟域无同步器
always @(posedge clk_fast) sync_data <= data_from_clk_slow;
                           // RTL 零延迟仿真完全看不出问题
                           // 门级仿真：亚稳态、建立/保持违例
```

**在阶段⑤STA 被拦下的**：AutoChip 生成的组合逻辑可能极深——比如 LLM 写了个 64 位行波进位加法器，仿真完全正确但延迟太大，在目标频率下 setup violation。AutoChip 对此**完全无感知**。

### 9.3 rank 函数与真实测试的差距

AutoChip 的验证质量上限由 testbench 决定，而 VerilogEval 的 testbench 通常只覆盖**功能随机激励**场景：

| 测试维度 | VerilogEval TB 覆盖 | 工业验证要求 | AutoChip 是否覆盖 |
|------|:---:|------|:---:|
| 功能正确 | ✅ 随机激励 + 参考比对 | ✅ directed + random + constrained-random | ✅ 但受限于 TB 质量 |
| 边界条件 | 部分 | 必须 | 取决于 TB 生成器 |
| 覆盖率（行/分支/FSM） | ❌ | ✅ 必须（通常 >95%） | ❌ |
| 复位行为 | 部分 | ✅ 上电/异步复位/部分复位 | 取决于 TB |
| 跨时钟域（CDC） | ❌ | ✅ 必须 | ❌ |
| 死锁/活锁 | ❌ | ✅ 需检查 | ❌ |
| X 传播 | ❌ | ✅ 门级仿真必须 | ❌ |

**结论**：AutoChip 的 rank=1 是一个**低门槛的必要条件**，离"可靠的可综合 RTL"还有显著距离。但它确实回答了自己的研究问题：给定 testbench，EDA 反馈能否让 LLM 迭代改进直到通过——对强模型答案是可以。

## 10. 讨论与局限

### 10.1 论文自述的局限

1. **强依赖高质量 testbench**：没有 testbench 就无法评分和反馈，无法做开放式设计。论文在 Introduction 里明确 AutoChip "requires a functioning testbench for feedback purposes"。
2. **只覆盖 RTL 设计+功能仿真（2/17）**：不做综合、PPA 优化、形式验证、物理设计，无法保证代码可综合或时序收敛。
3. **Greedy 单分支风险**：每轮只保留一个最优候选，可能早期丢弃后续更优方向。论文 Section 5.3 讨论中承认了这一点，并把 beam search / MCTS 列为 future work。
4. **反馈对弱模型无效**：三个较小模型（GPT-3.5-Turbo、Claude 3 Haiku、GPT-4o-Mini）无法稳定从工具反馈中获益，论文将此归因于"explaining the correlation between error and Verilog root cause"需要强因果推理能力。
5. **VerilogEval v1 可能被数据污染**：2023 年公开的 benchmark，2024-2025 的模型训练数据大概率已包含。但这不影响 feedback vs zero-shot 的**相对比较**。
6. **未探索 beam search / MCTS**：论文 Section 6 明确列为 future work。
7. **未将编译警告分类**：论文的激进策略（任何 stderr 都 rank=-0.5）可能误伤功能正确但带无害 warning 的候选。

### 10.2 代码/复现层面的问题

从代码审计和本地复现中提炼的关键差异与障碍：

**论文与代码的接口差异：**

1. **配置键名不一致**：论文 Figure 2 截图为 `mixed-model`（单数），当前仓库代码和 README 使用 `mixed-models`（复数）。使用单数键名的配置不会启用 mixed-model 功能。
2. **d 的定义偏差**：循环从 `iterations=0` 开始，循环末尾才加一，因此 `max_iterations=3` 实际运行编号 0/1/2/3 的**四层**，即 $d+1$ 组生成。论文公式 $C_{\text{max}} = k \times (d+1)$ 与此一致，但 README 描述容易让用户误解。
3. **full-context 不可直接复现**：论文 Table 3 报告了 full-context 结果，但当前仓库 `verilog_loop()` 固定执行 succinct 裁剪，没有 `full_context` 参数开关。需修改代码或取得作者实验版本才能复现。
4. **批量脚本入口过期**：`run_all_tests.sh` 指向不存在的 `auto_create_verilog.py`（当前为 `generate_verilog.py`），参数格式与当前解析器不兼容，默认数据路径指向本地不存在的目录。
5. **统计脚本正则拼写错误**：`parse_parameter_sweep.py` 查找 `Rank of best repsonse:`，而 `generate_verilog.py` 写的是 `Rank of best response:`。`repsonse` 拼写错导致 rank 正则匹配不到，CSV 缺数据。

**复现门槛：**

6. **商业 API 成本**：论文使用 2024-2025 的 API 价格。完整复现 143+156 题需大量 API 调用（最大 55 次/题），GPT-4o 成本最高。价格已随时间漂移。
7. **模型版本漂移**：GPT-4o / GPT-4o-Mini 等模型持续更新，复现时可能版本不同。paper 未记录请求 ID 或 API seed，无法精确重现。
8. **本地模型 adapter 未验证**：CodeLlama、Mistral、Gemini 等 adapter 代码存在但未经充分验证。Mistral 缺少 `ChatMessage` 导入，CodeLlama 缺少 `CodeLlamaTokenizer` 等导入。
9. **硬件要求**：使用 CodeLlama/RTLCoder 本地模型需要 GPU，且论文反馈实验速度"prohibitively slow on the hardware we could access"。

**已知 bug：**

10. **循环导入**：`languagemodels.py` 和 `verilog_handling.py` 互相导入，直接导入 `LLMResponse` 会报 `AttributeError`。
11. **仿真 cwd 错误**：`subprocess.run(simulator_cmd)` 未设置 `cwd=response_outdir`，波形文件写到启动目录而非候选目录，并行运行可能互相覆盖。
12. **shell 注入风险**：编译命令用 f-string + `shell=True` 拼接，含空格或特殊字符的路径会失败。
13. **零样本除零风险**：testbench 输出 `Mismatches: 0 in 0 samples` 时 `(samples-mismatches)/samples` 会除零。
14. **同分 tie-break 方向不一致**：单轮内偏好更短代码，跨轮 global_max 偏好更长代码。论文未定义同分策略，不会改变通过率但可能改变最终保存的代码。
15. **LICENSE 文件路径错误**：README 链接到根目录 `LICENSE`（不存在），实际文件在 `autochip_scripts/LICENCE`（Apache-2.0）。

### 10.3 本资料包的批判性分析

1. **"EDA Tool Feedback" 的命名有误导性**：论文标题暗示使用了完整的 EDA 工具链反馈，实际上只用了一个开源仿真器（Icarus Verilog）。没有综合、STA、形式验证等 EDA 核心工具。这更像是"Simulator Feedback"而非"EDA Tool Feedback"。

2. **testbench 的循环依赖困境**：AutoChip 的实验完全建立在已有完备 testbench（含 reference module）的前提上。但现实工程中 testbench 从零开始写通常比 RTL 更难。所以 AutoChip 更适合定位为**RTL 修复/补偿工具**，而非**端到端设计自动化工具**。

3. **成本分析的 proxy 选择有争议**：论文用 USD 成本作为"计算复杂度"的 proxy，但 API 定价受商业策略影响（如 GPT-4o 可能是亏损定价），不纯粹反映计算量。token 数作为"模型 effort"的 proxy 同样有问题——GPT-4o 每个 token 的计算量显然大于 GPT-4o-Mini。

4. **succinct 的成功可能来自"上下文不爆炸"而非"反馈精准"**：论文发现 succinct 和 full-context 成功率相近，但这可能意味着 LLM 的 context window 在 d=10 时被稀释，而非"历史信息没用"。AutoChip 的反馈本身精度不高（只给 mismatch 数和首错时刻），succinct 的成功更多依赖"保持上下文紧凑"。

5. **mixed-model 的收益来源未做消融**：论文没有区分"提前停止效应"（简单题在便宜模型阶段就成功了）和"强模型利用前序修复轨迹"（GPT-4o 能基于弱模型的部分修复做出更好的最后一轮修复）。如果是纯提前停止效应，mixed-model 的上限就是弱模型的首轮成功率。

6. **k vs d 的最优比未系统探索**：论文发现 k 的影响比 d 大，但没有做固定调用预算下的 k/d 扫描（如 $k=10, d=4$ vs $k=5, d=9$ vs $k=2, d=27$），使得"最优参数"结论缺乏工程指导。

7. **warning 惩罚的消融缺失**：论文的激进 warning 策略（任何 stderr 都 rank=-0.5 且跳过仿真）可能在搜索树上砍掉正确的分支。论文 Discussion 中未讨论这个代价。

## 12. 一分钟复述版

AutoChip（NYU，arXiv 2411.11856，已被 ACM TODAES 接收）是一个**不训练模型的推理时 RTL 生成-修复闭环框架**。核心三招：

1. **Greedy Tree Search**：每层让 LLM 生成 k 个 Verilog 候选，用 Icarus Verilog 编译 + vvp 仿真做五级 rank 打分（-2 无 module / -1 编译失败 / -0.5 有 warning / 0-1 失配比例 / 1 全通过），贪心只保留 rank 最高者进入下一层，最多 d 层。同最大 LLM 调用数下，GPT-4o feedback 比 zero-shot 多解决 5.8% 题目且 token 成本反而低 34.2%。

2. **Feedback 只对强模型有效**：GPT-4o 稳定获益，GPT-3.5 / Claude Haiku / GPT-4o-Mini 受益不稳定甚至倒退。因为从底层编译/仿真日志反向推断 RTL 根因需要强因果推理——这是论文最诚实也最重要的发现。

3. **Mixed-Model 成本优化**：前几轮用便宜模型，最后一轮切换到 GPT-4o。多数简单题在便宜模型阶段提前成功退出，GPT-4o 只为硬题买单。成本比全程 GPT-4o 低 41.9%，成功率接近。Human 基准上最高 75% 成功率成本仅 $0.025（vs 单独 GPT-4o 需 $0.043）。

**边界**：只覆盖流程阶段①/②（2/17），依赖预置 testbench（含 reference module），不管综合/PPA/形式验证/覆盖率，greedy 单分支可能丢弃更优修复路径，warning 惩罚过激，弱模型反馈无效，benchmark 污染风险，批量复现脚本待修复，full-context 需修改代码才能复现。
