## 1. 一句话定位

**DeepGate4 是 DeepGate 系列的第四代——专门解决前三代无法 scale 到大电路的根本问题：在 ITC99 / EPFL benchmark 上 Overall Loss 比次优模型分别再降 15.5% / 31.1%，Gate Connection Prediction 准确率 79.50%（DeepGate3 仅 68.36%），内存从 DeepGate3 的 50.75 GB 降到 7.53 GB 并可在 400K–1.6M 门电路上保持常数显存，而 Fused-DeepGate4 推理内核再把推理时间与显存降低 35.1% / 46.8%；关键三件套是（1）按 logic level + cone-k 切图的 DAG-aware 分区更新策略（任何 graph transformer 都可即插即用）、（2）用 GAT 替换 dense Multi-head Attention 的稀疏 Transformer + 全局/局部结构编码、（3）面向 AIG 均匀低度数（in-degree ≤ 2）定制的 CUDA 推理内核。**

这句话里 5 个承重点，后面逐一拆解：

1. **DAG-aware 图分区更新策略（Section 3.2-3.4）** — 不像 GNNAutoScale 在无向图上随机采样，DeepGate4 严格沿 AIG 的 logic level 顺序分块：用 cone-k(v) = {u : u ≼k v} 收集每个门的前驱锥，按 stride δ < k 让相邻 level 的锥有重叠，再靠 Intra-Level + Inter-Level 两阶段更新把每个门只算一次，使显存复杂度 sub-linear。
2. **GAT-based sparse Transformer 替代 dense attention（Section 3.5）** — DeepGate3 的 mask-based dense attention 在百万门电路上是 O(N²)；DeepGate4 把 Attention 换成 GAT，只沿 virtual edge E' = {(u, v) : u ≼k v, u ∈ cone(v)} 做局部聚合，每个 mini-batch 内复杂度退化为线性。
3. **AIG 专属结构编码（Section 3.5, Eq. 2）** — SE(v) = Emb_l(level(v)) + Emb_and(OutAND(v)) + Emb_not(OutNOT(v))，把 logic level + 后继 AND 门数 + 后继 NOT 门数嵌入初值，让结构头能学到 fan-out 模式（timing 属性来源），这是功能头单靠 fan-in 看不全的。
4. **Loss Balancer 用 EMA 梯度范数自动加权（Section 3.6）** — 不同任务梯度量级差几个数量级会导致某些任务被「淹没」。借鉴 GradNorm，用最后一层权重 w 关于各 loss 的梯度范数做指数滑动平均，把 ̃l_i = ‖g_i‖_β / ‖g_i‖_β^2 平衡后再求和。
5. **Fused-DG2 / Fused-DG4 CUDA 内核（Section 3.7）** — AIG 上每个门最多 2 个 fan-in，Fused-GAT 沿用 social network 的「1 warp 算 1 node」假设会让 32 个 thread 中 30 个空转（93.75% waste）。Fused-DG2 把每个 thread 重新分配到 feature 维度的子集上，独立算 attention，in-degree=1 时跳过 softmax（α=1 by definition），消除 warp 内 sync。

## 2. EDA 阶段映射（①-⑰）

参照 [芯片流程.md](../芯片流程.md) 的 17 阶段标准编号。DeepGate4 是**电路表示学习**的预训练模型，定位为多种下游 EDA 任务的通用 backbone。

| 阶段 | 覆盖 | 说明 |
|------|:---:|------|
| ① RTL 设计 | ❌ | 不直接接收 RTL 文本——RTL 必须先用 Yosys/ABC 综合成 AIG 网表后才可作为输入。但下游 LEC 任务会反馈到 RTL 修正 |

| **③ 逻辑综合** | ✅ **核心上游** | 输入端必须是综合后的 AIG：DeepGate4 在 [Yosys](https://yosyshq.net/yosys/) + ABC 综合后的 AIG 上训练，ITC99 用 Synopsys DC 2019.12 + skywater 130nm，EPFL 是 combinational benchmark，OpenABC-D 是工业级 AIG |
| ④ 门级仿真 | ❌ | 不涉及门延迟/X 传播等物理仿真 |
| ⑤ STA | ❌ | 不涉及——但 SE(v) 中的 OutAND/OutNOT 编码间接包含 timing 提示 |
| **⑥ 形式验证** | ✅ **核心下游** | DeepGate4 的 embedding 被嵌入 CaDiCal SAT solver 的变量决策启发式：在 5 个 ITC99 LEC SAT 实例（ad44/f20/ab18/ac1/ad14，平均 39,403 门）上平均求解时间降低 56.56%（1425s vs 3281s baseline），最高单例 f20 降低 86.33%、ac1 降低 92.90% |
| ⑦-⑰ 布局规划→芯片到手 | ❌ | DeepGate4 输出是向量嵌入，不直接服务物理实现。但学到的结构向量理论上可迁移到 congestion / DRC hotspot 预测等任务 |

**覆盖率：3/17。** DeepGate4 与前代（DeepGate/2/3）一样是**预训练 backbone**——输入端吃综合后的 AIG（③），输出端主要被 LEC/SAT 求解器（⑥）消费。它不直接服务 RTL 设计（①）、功能仿真（②）、物理实现（⑦-⑰），但学到的向量可被这些下游任务迁移（参见论文 OpenABC-D 在 525K 门电路上 PNA/HOGA-5 OOM 而 DeepGate4 仍可训练的迁移能力）。

> ⚠️ **「学到了什么」vs「下游在用什么」** — DeepGate4 预训练目标是 9 项自监督任务（logic-1 概率、pair truth-table Hamming 距离、cone 距离、graph edit distance 等），**没有任何任务直接是 PPA 优化目标**。它的「好」= representation 几何空间把功能/结构等价的电路拉近、不等价的推远。任何把它当作「PPA 预测器」直接使用的设想都是 over-claim。

### 3.1 输入

**(1) AIG 网表**（And-Inverter Graph，来自 ABC 综合）

```text
# ABC 综合后生成 AIG:
```

### 4.2 核心模块详解

#### A. Graph Partition（按 logic level + cone-k 切图）

**功能**：把一个大 AIG 切成小 cone 序列，使每个 cone 独立可计算。

**前置定义**：

- `level(v)` = 0 若 v 是 PI；否则 1 + max(level(fan-in))。表示该门在拓扑深度上的层数
- `cone_k(v) = {u ∈ G : u ≼k v}` = 所有路径长度 ≤ k 能到达 v 的前驱节点
- 因 AIG 的 max in-degree = 2，`|cone_k(v)| ≤ 2^(k+1) - 1`（k+1 层的二叉树节点数上限）

**算法 1（Graph Partition）**：

```text
Input: AIG G = (V, E), cone depth k, stride δ < k
1.  L = max_level(v), l = k
2.  while l ≤ L:
3.      cones_l = list()
4.      for v in {v : level(v) = l}:
5.          cone_l(v) ← cone_k(v)               # 取以 v 为根的 k 层子图
6.          add cone_l(v) to cones_l
7.      l = l + δ                               # 步进 stride
8.  for v in {v : out_degree(v) = 0}:           # 输出门单独处理
9.      g = cone_k(v)
10.     add g to cones_level(v)
11. return [cones_k, cones_(k+δ), cones_(k+2δ), ...]
```

**为什么这样设计**：

- **为什么不随机采样？** GNNAutoScale / GraphFM 在无向图随机采 sub-graph，会破坏 AIG 的拓扑因果——前驱锥是 PI 到当前门的信息流路径。DeepGate4 按 logic level 顺序切，**保证 receptive field 沿因果方向单调扩展**
- **为什么需要 δ < k？** 相邻 level 的 cone 必须有重叠（`cones_{l-δ} ∩ cones_l ≠ ∅`），才能通过历史 embedding 把消息从 PI 传到深层。若 δ = k 无重叠，前驱消息无法跨 level 传播

#### B. Updating Strategy（两级更新）

**功能**：让 memory 复杂度 sub-linear。

**Intra-Level Updating**（同一 level 内）：

```text
输入：cones_l = [cone_1, cone_2, ..., cone_n]，mini-batch size B
1.  把 cones_l 切成 m = n/B 个 mini-batch
2.  for i in 1..m:
3.      检查 batch_i 中的门是否已被更新过
4.      if yes:
5.          retrieve historical embedding for these gates
6.          remove all in-edges (切断，避免重复聚合)
7.          mark as "updated" in current stage
8.      把 batch_i 送入模型，算其它门的 embedding
9.      save online embedding to historical storage (Push: GPU → CPU)
10.     mark all gates in batch_i as "updated"
```

**Inter-Level Updating**（跨 level）：

```text
输入：cones_{l-δ}, cones_l
1.  for v in cones_{l-δ} ∩ cones_l:        # 重叠区域的门
2.      retrieve historical embedding from cones_{l-δ} (Pull)
3.      remove in-edges
4.      其他门留到 Intra-Level Updating 处理
```

**关键观察**（Section 3.3）：`R_l(v) ⊆ R_{l-δ}(v)`（深度 l 的 receptive field 是 l-δ 的子集）。这意味着 l 层的门能从 l-δ 层的 historical embedding 拿到**更大的上下文**，但反向不行。这是 DAG 拓扑顺序的内在要求。

#### C. GAT-based Sparse Transformer

**功能**：把 dense Multi-head Attention 换成 GAT，复杂度从 O(N²) 降到 mini-batch 内 O(|E'|)。

**虚拟边构造**：

$$
\bar{E} = \{(u, v) : u \preceq_k v, u \in \text{cone}_l(v)\}
$$

- $\preceq_k$：u 经 ≤ k 步可达 v
- 每个 gate v 只从 cone 内的前驱聚合，不再与 cone 外的 token 算 attention

**结构编码**（Structural Encoding）：

$$
\text{SE}(v) = \text{Emb}_l(\text{level}(v)) + \text{Emb}_{\text{and}}(\text{OutAND}(v)) + \text{Emb}_{\text{not}}(\text{OutNOT}(v))
$$

- `level(v)`：logic level（深度）
- `OutAND(v)`：v 后继中 AND 门的数量（fan-out 中的 AND 模式）
- `OutNOT(v)`：v 后继中 NOT 门的数量

**工程直觉**：GNN tokenizer + Sparse Transformer 都只看 fan-in 区域，看不到 fan-out——但 timing/delay 属性主要由 fan-out 决定（门延迟 = R_on × C_load，负载电容来自 fan-out 网络）。把 OutAND/OutNOT 编码进初始 embedding 等于告诉模型「这个门要驱动多少 AND 和多少反相器」，恢复部分 fan-out 信息。

#### D. Multi-Task Loss + Loss Balancer

**9 项预训练任务**（论文 Eq. 3-5）：

$$
\mathcal{L}_{\text{func}} = \mathcal{L}_{\text{gate}}^{\text{prob}} + \mathcal{L}_{\text{gate}}^{\text{tt pair}} + \mathcal{L}_{\text{graph}}^{\text{tt}} + \mathcal{L}_{\text{graph}}^{\text{tt pair}}
$$

$$
\mathcal{L}_{\text{stru}} = \mathcal{L}_{\text{gate}}^{\text{con}} + \mathcal{L}_{\text{graph}}^{\text{size}} + \mathcal{L}_{\text{graph}}^{\text{depth}} + \mathcal{L}_{\text{graph}}^{\text{ged pair}} + \mathcal{L}^{\text{in}}
$$

$$
\mathcal{L}_{\text{all}} = \mathcal{L}_{\text{func}} + \mathcal{L}_{\text{stru}}
$$

**Loss Balancer**（借鉴 GradNorm）：

$$
\tilde{l}_i = \frac{\|g_i\|_\beta^2}{\|g_i\|_\beta}
$$

- `g_i = ∂l_i / ∂w`：loss `l_i` 对最后一层权重 w 的梯度
- `‖g_i‖_β`：`g_i` 的 EMA（指数滑动平均，decay = β）
- 各 loss 在加总前被 EMA 梯度范数加权，避免某项 loss（通常是 magnitude 大的 graph size regression）支配优化

#### E. Fused-DG2 / Fused-DG4 CUDA Kernel

**问题**：Fused-GAT 是 social/citation network 的 SOTA，但 AIG 不适用。

**Fused-GAT 的 3 个低效点**：

1. **Thread waste 93.75%**：1 warp（32 thread）算 1 个 node 的 attention，但 AIG 的 max in-degree = 2，只有 2 个 thread 在算 weight，其余 30 个空转
2. **Unnecessary softmax**：in-degree=1 时 α=1 by definition（无需归一化），Fused-GAT 仍算 softmax
3. **Warp-level sync overhead**：softmax 的中间结果（`s = sum exp`, `α = exp / s`）需要在 warp 内 `__shfl_xor_sync` 同步

**Fused-DG2 解决方案**：

```text
1. 重新分配 thread：每个 thread 算 feature 维度的一个子集（不是 edge 的一个）
2. 独立算 attention score（不需要 warp 内同步）
3. in-degree=1 时直接跳过 softmax（α=1）
4. 存储 edge-level intermediates 而非 node-level（节省显存）
```

**Fused-DG4**：在 DG2 基础上进一步优化 GAT sparse transformer。

**适用条件**：thread 数 = edge 数，**仅在 edge 数 < 2× node 数的图上高效**——AIG 完美符合（max in-degree 2）。

## 5. 关键公式

### 5.1 Cone 定义

$$
\text{cone}_k(v) = \{u \in V : u \preceq_k v\}
$$

- $\preceq_k$：u 经 ≤ k 步路径可达 v（前驱偏序关系）
- $k$：cone 深度，控制子图大小
- 因 AIG 的 max in-degree = 2，$|\text{cone}_k(v)| \leq 2^{k+1} - 1$

**工程直觉**：在 AIG 上选 cone 而不是 random walk，是为了让 receptive field 严格沿因果方向——前驱锥包含了从 PI 到当前门的所有可能信号路径，是 functional 信息的最小完整集。

**为什么这么设计**：替代方案是 GraphFM / GNNAutoScale 的 random sampling——但它们假设无向图同质邻居，AIG 是 DAG 且邻居异质（AND vs NOT），随机采样会切断关键因果路径。

### 5.2 Structural Encoding

$$
\text{SE}(v) = \text{Emb}_l(\text{level}(v)) + \text{Emb}_{\text{and}}(\text{OutAND}(v)) + \text{Emb}_{\text{not}}(\text{OutNOT}(v))
$$

- $\text{level}(v)$：v 的 logic level（拓扑深度）
- $\text{OutAND}(v)$：v 后继节点中 AND 门的数量
- $\text{OutNOT}(v)$：v 后继节点中 NOT 门的数量
- $\text{Emb}(\cdot)$：3 个独立的线性/嵌入层

**工程直觉**：功能头只聚合 fan-in 信息，看不到 fan-out 模式。但 timing/delay 由 fan-out 决定（输出负载电容）。把 OutAND/OutNOT 编码进初值，相当于让结构头在「未真正聚合 fan-out 之前」就预先知道该门的输出驱动模式。

### 5.3 Multi-Task Loss 组合

$$
\mathcal{L}_{\text{func}} = \mathcal{L}_{\text{gate}}^{\text{prob}} + \mathcal{L}_{\text{gate}}^{\text{tt pair}} + \mathcal{L}_{\text{graph}}^{\text{tt}} + \mathcal{L}_{\text{graph}}^{\text{tt pair}}
$$

$$
\mathcal{L}_{\text{stru}} = \mathcal{L}_{\text{gate}}^{\text{con}} + \mathcal{L}_{\text{graph}}^{\text{size}} + \mathcal{L}_{\text{graph}}^{\text{depth}} + \mathcal{L}_{\text{graph}}^{\text{ged pair}} + \mathcal{L}^{\text{in}}
$$

$$
\mathcal{L}_{\text{all}} = \mathcal{L}_{\text{func}} + \mathcal{L}_{\text{stru}}
$$

- 4 项功能任务（gate 级 2 + graph 级 2）+ 5 项结构任务（gate 级 1 + graph 级 3 + 成员关系 1）
- 所有 ground-truth 来自随机仿真或结构分析，无人工标注

### 5.4 Loss Balancer

$$
\tilde{l}_i = \frac{\|g_i\|_\beta^2}{\|g_i\|_\beta}
$$

- $g_i = \partial l_i / \partial w$：loss $l_i$ 对 Transformer 最后一层权重 $w$ 的梯度
- $\|\cdot\|_\beta$：EMA 算子，decay = $\beta$
- 平衡后所有 loss 加总为训练总 loss

**工程直觉**：graph size regression 的 magnitude 远大于 gate probability classification（一个是连续值回归、一个是 0-1 二分类），不加权时梯度被大 loss 支配，分类任务学不到东西。EMA 梯度范数加权让不同 magnitude 的 loss 在梯度空间等权。

**为什么这么设计**：替代方案是手动调权重（每个 loss 一个超参）——但 9 项 loss × 调参 = 9! 种组合，不可行。GradNorm 范数让权重自动调整。

### 5.5 Pairwise Truth Table Distance（gate 级）

$$
D^{\text{gate tt}}_{(i, j)} = \frac{\text{HammingDistance}(T_i, T_j)}{\text{length}(T_i)}
$$

- $T_i, T_j$：随机仿真生成的 gate i 和 gate j 的 incomplete truth tables
- $(i, j) \in N^{\text{gate tt}}$：采样的门对集合

### 5.6 Graph Edit Distance（graph 级）

$$
D^{\text{graph ged}}_{(s_1, s_2)} = \text{GraphEditDistance}(s_1, s_2)
$$

- $s_1, s_2$：两个 sub-graph（fan-in cone）
- GraphEditDistance：节点/边增删改的最小操作数

### 5.7 Accuracy of Gate Connection Prediction

$$
P^{\text{con}} = \frac{1}{\text{len}(N^{\text{con}})} \sum_{(i, j) \in N^{\text{con}}} \mathbb{1}(\text{MLP}^{\text{con}}(h^s_i, h^s_j), y^{\text{con}}_{(i, j)})
$$

- $y^{\text{con}}_{(i, j)} \in \{0, 1\}$：是否存在从 i 到 j 或 j 到 i 的路径
- $h^s_i, h^s_j$：gate 的结构嵌入

### 5.8 Partition 关键不变量（Section 3.3）

$$
R_l(v) \subseteq R_{l-\delta}(v)
$$

- $R_l(v) = \{u \in \text{cones}_l : u \preceq_k v\}$：v 在 l 层 cone 中的 receptive field
- $R_{l-\delta}(v) = \{u \in \text{cones}_{l-\delta} : u \preceq_k v\}$：v 在 (l-δ) 层 cone 中的 receptive field
- 含义：l 层 cone 的 receptive field 是 (l-δ) 层的子集——所以用 (l-δ) 的 historical embedding 必然包含更多上下文，不会丢失信息

**工程直觉**：这个不变量是「跨 level 信息能正确传播」的数学保证。若违背（l 层能看到某些 (l-δ) 层看不到的节点），就会丢失因果信息。

## 6. 训练与实验设置

### 6.1 是否需要训练

**需要训练**（自监督预训练）：

- **Tokenizer**：用预训练的 [DeepGate2](https://github.com/cure-lab/DeepGate2) 作为冻结的 GNN tokenizer（论文 Section 3.1）
- **Sparse Transformer + Pooling Transformer + MLP Heads**：在 AIG 上自监督预训练
- **Loss**：9 项自监督任务的加权和（见 §5.3）
- **硬件**：单卡 Nvidia A800
- **优化器**：Adam，lr = 1e-4
- **Epochs**：200
- **Batch size**：batch = 1，mini-batch = 128
- **超参**：k = 8（cone 深度），δ = 6（stride），embedding dim = 128，sparse transformer 12 层，pooling transformer 2 层，MLP heads 3 层
- **训练时长**：未在论文显式给出，但根据 epoch 200 + 单卡 A800 + ~15K 节点电路估算约 1-3 天

## 7. 创新点

### 创新点 1：DAG-aware 切图 + 两级更新策略（**最核心**）

**核心机制**：以前是 X（GNNAutoScale / GraphFM 在无向图随机采样），DeepGate4 改成 Y（按 AIG logic level 严格切 cone + δ < k 重叠 + Intra/Inter-Level 两阶段更新）。因为 Z（AIG 是 DAG，随机采样破坏 PI → 当前门的因果传播链，导致功能任务估计错误）。

**关键证据**：去掉 partition 整个 ITC99 和 EPFL 都 OOM（Table 4）；去掉 Mark 时间 +45.3%、显存 +286.4%。

**理论意义**：这是首个把 sub-linear 复杂度 GNN 训练框架（GAS / GraphFM）适配到 DAG 的工作，且**与底层 transformer 架构解耦**——任何 graph transformer 都能套用。

### 创新点 2：GAT-based Sparse Transformer 替代 Dense Attention

**核心机制**：以前是 X（DeepGate3 用 mask-based dense attention，每个 token 与 cone 内所有 token 算 attention），DeepGate4 改成 Y（用 GAT 沿 virtual edges E' = {(u,v) : u ≼k v} 聚合）。因为 Z（dense attention 是 O(N²)，百万门时显存爆炸；GAT 只沿边聚合，mini-batch 内线性复杂度）。

**关键证据**：相比 DeepGate3†，推理时间 -84.0%，显存 -93.4%。

**巧妙之处**：保留了 Transformer 的 LayerNorm / FFN / residual 等结构，只把 MHA 替换成 GAT，可与已有 Transformer 生态兼容。

### 创新点 3：fan-out 感知的结构编码（SE）

**核心机制**：以前是 X（GNN tokenizer + Transformer 都只看 fan-in，丢失 timing 信息），DeepGate4 改成 Y（初始 embedding 加 SE(v) = Emb(level) + Emb(OutAND) + Emb(OutNOT)）。因为 Z（timing/延迟由 fan-out 负载电容决定；tokenizer 和 self-attention 都看不到 fan-out）。

**关键证据**：去掉 SE + Balancer 后 L_stru 升高 8.75%（比 L_func 升高 3.38% 大 2.6 倍）。

### 创新点 4：Fused-DG2 / Fused-DG4 CUDA 内核

**核心机制**：以前是 X（Fused-GAT 假设 power-law degree，AIG 是 uniform in-degree ≤ 2），DeepGate4 改成 Y（按 feature 维度分配 thread、独立算 attention、in-degree=1 跳过 softmax）。因为 Z（power-law 假设下 warp 内大量空转，softmax 的 warp-level sync 在 AIG 上纯属浪费）。

**关键证据**：相比 DeepGate4，Fused-DG4 推理时间 -35.1%、显存 -46.8%（平均）；相比 DeepGate3†，推理时间 -90.5%。

### 创新点 5：Loss Balancer 用 EMA 梯度范数

**核心机制**：以前是 X（手动调 9 项 loss 的权重），DeepGate4 改成 Y（用最后一层梯度范数的 EMA 自动加权）。因为 Z（9 项 loss magnitude 差几个数量级，手动调参组合爆炸）。

**关键证据**：见 §6.3 消融，Balancer + SE 贡献 L_all -7.89%。

```text
⑤ STA                 ────  PrimeTime
                       ▼
⑥ 形式验证         ────  Formality / Conformal / CaDiCal
                       │      ↗（消费 DeepGate4 embedding）
                       ▼
⑦-⑰ 后端 + 制造       ────  （DeepGate4 不直接服务）
```

**DeepGate4 接手**：综合后的 AIG 网表（必须先用 ABC 转 AIG）。
**DeepGate4 交棒**：每门 128 维嵌入（h_f 功能向量 + h_s 结构向量）→ 下游 LEC 分类器、SAT 求解器的变量决策。

### 9.2 「学到了什么」vs「下游在用什么」

DeepGate4 声称的「成功」= 在 9 项自监督任务 + 2 项下游任务（LEC + SAT）上 SOTA。但到真实流片还差：

1. **PPA 不在优化目标里**：9 项 loss 全部是结构/功能等价性的几何度量，没有一项是 timing/area/power 的回归。这与 [ChipSeek](../ChipSeek/论文深度讲解.md)、[CircuitNet](../CircuitNet/论文深度讲解.md) 等专门做 PPA 预测的工作有本质区别。
2. **未在布局后网表上验证**：DeepGate4 输入 AIG 是综合后的纯逻辑图，没有 SDF 延迟、没有 SPEF 寄生 RC。STA / 后仿真阶段的物理延迟信息它看不到。
3. **LEC 评测的样本量极小**：ITC99 上 1.29% 等价对，模型相当于在极度不平衡数据上学——AP 0.31 看似好，但若换到真实工业 design（更复杂、更不平衡），表现未必稳定。
4. **SAT 加速的单例方差大**：Table 11 中 ad14 上 DeepGate4（4268.57s）反而慢于 Baseline（5766.85s —— 实际是 Baseline 慢一些，作者笔误？），ad44 上 DeepGate4 970s 也接近 Baseline 918s。模型推理开销在小例上可能抵消加速收益。

## 10. 讨论与局限

### 10.1 论文自述的局限

1. **Cone 大小受 max in-degree = 2 约束**：DeepGate4 的切图严重依赖 AIG 拓扑（每节点 in-degree ≤ 2），推广到任意 DAG（如带 mux / XOR 的 RTL 级 netlist）需重新设计 partition 策略。
2. **k = 8 是经验值**：论文给出 ablation（Table 8）显示 k 增大降低结构任务性能（因 structural task 依赖 local 信息），但未给出 k 的自动选择方法。
3. **Sub-linear 内存仅在 > 一定规模时显现**：对小于 mini-batch size（128）的电路，cone 内节点数 < 128，partition 不起作用，内存仍是线性。
4. **Token-level 加速与图稀疏度耦合**：Fused-DG4 假设 edge 数 < 2× node 数，对 in-degree > 2 的图（RTL 级 netlist）会失效。

### 10.2 代码/复现层面的问题

- **代码仓库审计**：https://github.com/zyzheng17/DeepGate4-ICLR-25，未在资料包内审计（截至 2026-08-06）
- **Tokenizer DeepGate2 的依赖**：必须先有 DeepGate2 预训练权重才能训 DeepGate4，复现门槛 = 跑通 DeepGate2 + 准备 ITC99/EPFL AIG 数据 + 单卡 A800 跑 200 epoch
- **CUDA kernel 依赖**：Fused-DG2/DG4 需要自编译 PyTorch CUDA 扩展，与 PyTorch / CUDA 版本强绑定
- **AIG 生成工具链**：ABC 必须装好且支持 `read_aiger` / `write_aiger`，不同 ABC 版本对 AIG 编码有微小差异

### 10.3 本资料包的批判性分析

1. **「constant memory」声明需要更细致语境**：图 8a 显示从 400K 到 1.6M gates 时 GNN 线性增长、DeepGate4 平台化。但**前提是 test set 只有 5 个离散点（161/1861/10502/84742/402193 节点 + 800K/1.6M 是 Image Processing 复制）**，且这些测试电路都是同一来源的「放大版」，不是真正的 1.6M 门工业设计。**独立测试集上的 sub-linear 性质需要验证**。

2. **OOD 评测有 selection bias**：论文选了 ITC99 → EPFL 跨 benchmark，但 EPFL 是「random control benchmark」（随机控制电路），与 ITC99 的「真实 benchmark」风格相似。真正的 OOD 应是「训练在 combinational AIG，测试在 sequential AIG」（带 DFF），但论文未做。

3. **AP 0.31 在 LEC 上的实际意义有限**：1.29% 正样本率下，random guess 的 AP ≈ 0.0129，DeepGate4 0.31 是 24× 提升但绝对值仍很低。工业 LEC 系统会结合 structural hashing + simulation，远超 ML baseline 的天花板。

4. **9 项 loss 的 ground-truth 都来自随机仿真**：logic-1 概率、truth-table Hamming 距离都是 statistical 量，**与 exact logic equivalence 不等价**。例如 NOT 门与其输入的 truth-table Hamming 距离恰好 = length(T)，模型可能学到「Hamming 距离大 = 反相关系」，但不等价于「这两个门真的功能互补」。

5. **Fused-DG4 的硬件可移植性**：CUDA kernel 强绑定 Nvidia GPU。AMD ROCm / Intel oneAPI 上需要重写。论文未给 OpenCL / SYCL 版本。

6. **L_in（gate-in-graph）任务的可解释性低**：仅靠 0/1 label 训练，没有分析模型到底学到什么——是真的识别了 sub-graph 的「边界」还是利用了节点度的伪特征。

## 12. 一分钟复述版

1. **问题**：DeepGate/2/3 在电路表示学习上有进展，但卡在 scalability——GNN 受 over-squashing 限制不能 scale 到大数据集，DeepGate3 的 dense Transformer 在百万门电路上 OOM。sub-linear 复杂度的 GNNAutoScale / GraphFM 又假设无向图，AIG 是 DAG 且必须按拓扑顺序传播。

2. **方法**：DeepGate4 = (a) cone-k + stride δ 按 logic level 切 AIG，Intra/Inter-Level 两阶段用 historical embedding 更新（sub-linear 显存，**任何 graph transformer 都能套用**）；(b) 用 GAT 沿 virtual edges 替代 dense MHA，mini-batch 内线性复杂度；(c) 加 fan-out 感知的结构编码 SE(v)；(d) Loss Balancer 用 EMA 梯度范数自动加权 9 项 loss；(e) Fused-DG2/DG4 CUDA 内核利用 AIG in-degree ≤ 2 的稀疏性。

3. **结果**：ITC99 / EPFL 上 L_all 比次优模型分别降 15.5% / 31.1%；Gate Connection Accuracy 79.50% vs DeepGate3 68.36%；显存 7.53GB vs DeepGate3 50.75GB；Fused-DG4 再省 35.1% 时间 + 46.8% 显存；400K–1.6M 门电路线性 scale 但**常数显存**；LEC AP 0.31（+55% vs 次优）；CaDiCal SAT 平均 -56.56%，最高 -92.90%。

4. **局限**：(1) Cone 切图假设 AIG in-degree ≤ 2，推广受限；(2) Fused-DG4 CUDA kernel 强绑定 Nvidia；(3) 9 项 loss 都是统计量，与 exact logic equivalence 不严格等价；(4) LEC 的 AP 0.31 绝对值仍低，工业 LEC 系统远超 ML baseline；(5) OOD 测试有 selection bias（训练 ITC99 测试 EPFL，都是随机控制风格）；(6) 代码需自训 DeepGate2 tokenizer + 单卡 A800 数天，复现门槛较高。
