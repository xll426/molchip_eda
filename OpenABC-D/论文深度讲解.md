## 1. 一句话定位

**OpenABC-D 不是一个新的神经网络模型，而是 EDA 领域首个大规模、标准化的逻辑综合数据集——它用 Yosys+ABC 开源工具链，对 29 个功能多样的开源 RTL IP（覆盖通信、控制、密码、DSP、处理器五类）各跑 1,500 条随机生成的长度为 20 的 synthesis recipe，保存每一步优化后的中间 AIG 图结构（共约 870,000 个 AIG），并标注技术映射后的 area/delay QoR 标签。它定义了 unseen recipe、unseen IP、unseen IP-recipe pair 三种泛化任务，并提供了 GCN+Conv1d 双分支融合的 QoR 预测 baseline（Variant 1 最佳 MSE 0.579）和 IP 分类 baseline（98.05% accuracy），为 ML-guided logic synthesis 领域提供了首个可复现、可比较的标准 benchmark。**

这句话里的四个技术承重点：

1. **数据集规模与多样性** -- 29 个 IP x 1,500 recipe x 20 步 = 约 870,000 个 AIG，生成耗费 200,000+ compute-hours。IP 功能覆盖通信/控制/密码/DSP/处理器五类，节点数从 462（ss_pcm）到 245,046（dft），depth 从 9（sasc）到 819（fpu）。
2. **完整 trajectory 保存** -- 不是只保存最终优化结果，而是保存每条 recipe 的每一步（step0 到 step20）的中间 AIG。这使研究者可以研究「综合过程本身」而非仅仅「综合结果」。
3. **三种 OOD 泛化任务** -- Variant 1: seen IP, unseen recipe；Variant 2: unseen IP（16 小 IP 训练，8 大 IP 测试）；Variant 3: unseen IP-recipe pair（随机切分组合）。
4. **GCN+Conv1d 双分支 baseline** -- AIG 图用两层 GCN 编码，recipe 序列用多尺度并行 Conv1d 编码，拼接后经 FC 输出归一化 QoR 标量。

## 2. EDA 阶段映射（①-⑰）

参照 [芯片流程.md](../芯片流程.md) 的 17 阶段标准编号：

| 阶段 | 覆盖 | 说明 |
|------|:---:|------|

| ② RTL 功能仿真 | ❌ | — |
| **③ 逻辑综合** | ✅ **核心** | Yosys+ABC 完成 RTL→AIG 综合 + 1,500 条 recipe 优化 + 技术映射（Nangate 45nm）。这是 OpenABC-D 的全部覆盖范围 |
| ④ 门级仿真 | ❌ | 但 area/delay 标签来自技术映射后的 estimate，非门级仿真 |
| ⑤ STA | ❌ | area/delay 由 ABC 技术映射估计（wireload model `5K_heavy`），不是 signoff STA |

| ⑦-⑰ 布局规划→芯片 | ❌ | — |

**覆盖率：2/17（① 作为输入源，③ 核心覆盖）。** OpenABC-D 是一个纯逻辑综合阶段的数据集。

> ⚠️ OpenABC-D 的 area/delay 是 ABC 技术映射后的估计值，不是 post-route signoff 时序。在 Nangate 45nm + `5K_heavy` wireload model 下，走线延迟是用统计线负载模型估算的，与实际 post-route 结果可能有显著偏差。

### 3.1 数据生成流程（论文 Figure 2）

```text
  29 个开源 RTL IP (Verilog/VHDL)
      │
      ▼
  ┌─────────────────────────────────────────┐
  │ Stage 1: RTL Synthesis                   │
  │   Yosys: RTL -> combinational logic      │
  │   ABC: structural hashing -> 初始 AIG    │
  │   ABC: 1,500 条 recipe x 20 步优化       │
  │   输出: 每步的 BENCH 格式 AIG            │
  └────────────────┬────────────────────────┘
                   │
                   ▼
  ┌─────────────────────────────────────────┐
  │ Stage 2: Graph-Level Processing          │
  │   BENCH -> NetworkX GraphML              │
  │   保留: node type + incoming inverter    │
  │         count + edge type (buffer/inv)   │
  └────────────────┬────────────────────────┘
                   │
                   ▼
  ┌─────────────────────────────────────────┐
  │ Stage 3: ML Preprocessing                │
  │   GraphML -> PyTorch Geometric Data      │
  │   添加: recipe 向量 + QoR 标签           │
  │   命名: designIP_synID_stepID.pt         │
  └────────────────┬────────────────────────┘
                   │
                   ▼
            OpenABC-D Dataset
            870,000 samples
```

### 3.2 数据样本结构（论文 Table 2）

每个 `.pt` 文件（如 `aes_syn149_step15.pt`）包含：

```text
Graph 部分:
  - adjacency matrix (edge_index): 有向 AIG 的稀疏邻接矩阵
  - node features [N, 4]:
      - node type embedding [N, 3]: PI / PO / Internal AND
      - incoming inverter count [N, 1]: 0/1/2
  - edge features [E, 1]: 0 = buffer, 1 = inverter

Recipe 部分:
  - recipe ID: 0~1499
  - recipe vector [20]: 每步的 operation ID
      (0=refactor, 1=refactor -z, 2=rewrite, 3=rewrite -z,
       4=resub, 5=resub -z, 6=balance)
  - step ID: 当前处于 recipe 的第几步 (0~20)

Label 部分:
  - individual labels: #PI, #PO, #nodes, #inverters, #edges, depth
  - final labels: 最终 AIG 的 #nodes, area, delay (post technology mapping)
  - IP name
```

### 3.5 数据集划分（三种变体）

| 变体 | 训练集 | 测试集 | 测试什么 |
|------|--------|--------|---------|
| Variant 1 | 每 IP 的前 1000 条 recipe | 每 IP 的后 500 条 recipe | 已知 IP，未知 recipe |
| Variant 2 | 16 个小 IP（< 20K 节点）全部 1500 条 | 8 个大 IP（>= 20K 节点）全部 1500 条 | 未知 IP（OOD 设计） |
| Variant 3 | 70% 随机 IP-recipe pair | 30% 随机 IP-recipe pair | 未知 IP-recipe 组合 |

**QoR 标准化**：每个 design 的 1,500 个 QoR 标签独立计算均值和标准差，标准化为 $y_{\text{norm}} = (y - \mu_{\text{design}}) / \sigma_{\text{design}}$。

**重要警告（oracle normalization）**：Variant 2 的测试 IP 标准化需要知道测试 IP 的全部 1,500 个 QoR 标签（$\mu$ 和 $\sigma$ 需要完整标签分布计算）。如果测试 IP 的 1,500 次综合还没跑（真实 unseen IP 场景），就无法标准化——这就是「先知道答案再答题」的 oracle 问题。

## 4. 方法与架构

### 4.1 Baseline 模型架构（论文 Figure 5）

```text
            AIG Graph Branch                    Recipe Sequence Branch
  ┌─────────────────────────────┐     ┌──────────────────────────────┐
  │ Node features [N, 4]        │     │ Recipe vector [20]            │
  │   (type emb 3d + inv cnt 1d)│     │   每个 ID -> 3d embedding     │
  │         ↓                   │     │         ↓                     │
  │ GCN Layer 1 (in->hidden)    │     │ 60d 序列 (20x3)               │
  │   + BatchNorm + ReLU        │     │         ↓                     │
  │         ↓                   │     │ 并行 Conv1d (多 kernel size)  │
  │ GCN Layer 2 (hidden->hidden)│     │   kernel sizes: 6,9,12 /      │
  │   + BatchNorm               │     │   12,15,18,21 / 21,24,27,30   │
  │         ↓                   │     │   stride = 3                  │
  │ Global Pooling              │     │         ↓                     │
  │   mean_pool || max_pool     │     │ 各 kernel 输出展平             │
  │         ↓                   │     │         ↓                     │
  │ Graph embedding [d_g]       │     │ Recipe embedding [d_r]        │
  └─────────────┬───────────────┘     └──────────────┬────────────────┘
                │                                    │
                └──────────┬─────────────────────────┘
                           ↓
                    Concatenate [d_g + d_r]
                           ↓
                    FC Layers -> 标量 QoR
```

| 参数 | Net1 | Net2 | Net3 |
|------|------|------|------|
| GCN layers | 128->128 | 64->64 | 64->64 |
| Graph embedding dim | 256 | 128 | 128 |
| Conv1d kernels | 6,9,12 | 12,15,18,21 | 21,24,27,30 |
| Fusion dim | 310 | 190 | 178 |
| FC layers | 310->128->128->1 | 190->512->512->512->1 | 178->512->512->512->1 |
| Dropout | 0 | 0 | 0.2 |

**Net1 vs Net2 vs Net3 的设计哲学**：Net1 用大 GCN（128 维）+ 小 kernel（6,9,12），关注图结构的局部模式；Net2/Net3 用小 GCN（64 维）+ 大 kernel（12~30），关注 recipe 序列的长程依赖；Net3 加 dropout 0.2 应对更深的 FC 带来的过拟合。

### 4.2 Conv1d Recipe Encoder 详解

Recipe 序列编码使用多尺度并行一维卷积，这是理解双分支融合的关键：

```text
Input: recipe vector [B, 20] (20 steps, each step is an operation ID 0-6)
  -> Embedding lookup [B, 20, 3] (each op ID -> 3-dim learnable embedding)
  -> Transpose to [B, 3, 20] (channel-first for Conv1d)

Parallel Conv1d branches (Net1 example, kernels 6, 9, 12, stride=3):
  Branch 1: Conv1d(in=3, out=1, kernel=6, stride=3) -> output length = (20-6)/3+1 = 5 -> [B, 5]
  Branch 2: Conv1d(in=3, out=1, kernel=9, stride=3) -> output length = (20-9)/3+1 = 4 -> [B, 4]
  Branch 3: Conv1d(in=3, out=1, kernel=12, stride=3) -> output length = (20-12)/3+1 = 3 -> [B, 3]

  Concat all branches -> recipe embedding [B, 5+4+3] = [B, 12] ... wait no
  
  Actually the paper uses different output channels. Let me correct:
  Each Conv1d kernel outputs a flattened feature vector. Net1 with kernels [6,9,12]:
  - kernel=6, stride=3: output [B, 1, 19] (note: (20-6)/1+1=15 with stride=3 -> 
    actually the paper reports specific output lengths)
  
  Net1: output lengths 19, 18, 17 -> recipe dim = 19+18+17 = 54
  Then: 256 (graph) + 54 (recipe) = 310 total fusion dimension
```

**为什么用多尺度 kernel**：不同长度的 kernel 捕获不同范围的 recipe 子序列模式——小 kernel（6）捕获局部相邻命令的组合效应（如 `rewrite` 紧接 `balance` 的效果），大 kernel（30）捕获长程命令序列的整体策略（如「前 10 步激进优化 + 后 10 步保守精调」）。

## 5. 关键公式

### 5.1 GCN 图卷积层

论文使用标准 GCN（Kipf & Welling, 2017）：

$$
H^{(l+1)} = \sigma\left(\hat{D}^{-\frac{1}{2}} \hat{A} \hat{D}^{-\frac{1}{2}} H^{(l)} W^{(l)}\right)
$$

- $H^{(l)}$：第 $l$ 层的节点特征矩阵，$\in \mathbb{R}^{N \times d_l}$
- $\hat{A} = A + I$：带自环的邻接矩阵
- $\hat{D}$：$\hat{A}$ 的度矩阵
- $W^{(l)}$：第 $l$ 层的可学习权重，$\in \mathbb{R}^{d_l \times d_{l+1}}$
- $\sigma$：ReLU 激活函数

**工程直觉**：每个节点的新特征 = 邻居特征的加权平均 x 权重矩阵 + 非线性激活。两层 GCN 意味着每个节点能聚合 2-hop 邻居的信息——AND 门看到它的 fanin（1-hop）和 fanin 的 fanin（2-hop，即 PI 或前级门）。

### 5.2 QoR 标准化

$$
y_{\text{norm}} = \frac{y - \mu_{\text{design}}}{\sigma_{\text{design}}}
$$

- $y$：原始 QoR 值（nodes / area / delay）
- $\mu_{\text{design}}$：该 design 的 1,500 个 QoR 标签的均值
- $\sigma_{\text{design}}$：该 design 的 1,500 个 QoR 标签的标准差

**为什么需要 per-design 标准化**：不同 IP 的绝对 QoR 尺度差异巨大（fpu 的 area 可能是 spi 的 100 倍），跨 IP 比较原始值没有意义。标准化后，模型学习「相对于这个 IP 的平均水平，这条 recipe 是更好还是更差」。

### 5.3 MSE 损失

$$
\mathcal{L}_{\text{MSE}} = \frac{1}{B} \sum_{i=1}^{B} (y_{\text{norm}}^{(i)} - \hat{y}_{\text{norm}}^{(i)})^2
$$

- $B$：batch size
- $y_{\text{norm}}^{(i)}$：第 $i$ 个样本的标准化 QoR
- $\hat{y}_{\text{norm}}^{(i)}$：模型预测的标准化 QoR

### 5.4 Recipe 操作集

$$
\text{Op} \in \{0: \text{refactor}, 1: \text{refactor -z}, 2: \text{rewrite}, 3: \text{rewrite -z}, 4: \text{resub}, 5: \text{resub -z}, 6: \text{balance}\}
$$

每条 recipe 是 $L=20$ 的序列，每个位置独立均匀随机采样。

## 6. 训练与实验设置

### 6.1 是否需要训练

**是，需要训练。** OpenABC-D 提供的是数据和 baseline 代码，不提供预训练权重。

| 训练要素 | QoR 回归 | IP 分类 |
|----------|---------|---------|
| 优化器 | Adam, lr=1e-3 | Adam, lr=1e-3 |
| 学习率调度 | ReduceLROnPlateau | — |
| Epochs | 80 | 35 |
| Batch size | 64 | 64 |
| Weight decay | — | 1e-2 |
| 损失函数 | MSE | Cross-entropy |

### 6.2 数据生成成本

- RTL synthesis: server-grade Intel CPU, 200,000+ compute-hours
- 完整数据量: ~1.4 TB（完整）/ ~19 GB（ML-ready）

### 6.3 关键实验结果

**QoR 回归 MSE（论文 Table 6）**：

| 任务 | Net1 | Net2 | Net3 |
|------|-----:|-----:|-----:|
| Variant 1 (Unseen recipe) | 0.648 | 0.815 | **0.579** |
| Variant 2 (Unseen IP) | 10.59 | **1.236** | 1.47 |
| Variant 3 (Unseen pair) | 0.588 | 0.538 | **0.536** |

**这张表说明什么**：Variant 1（已知 IP，未知 recipe）最容易，三个模型都在 0.5~0.8 MSE。Variant 2（未知 IP）极难——Net1 的 MSE 爆炸到 10.59（几乎完全失效），最好的 Net2 也才 1.236。这说明小 IP 训练的 GCN 图特征无法跨 IP 尺度泛化。Variant 3（未知 IP-recipe pair）与 Variant 1 接近，因为随机 70/30 切分中测试集分布偏移远小于 Variant 2。

**IP 分类**：两层 GCN 在 35 epoch 后 accuracy = 98.05%，说明不同 IP 的 AIG 图结构有极强的「指纹」效应。

## 7. 创新点

### 创新点 1：首个大规模标准化逻辑综合数据集

在 OpenABC-D 之前，ML-guided logic synthesis 论文各自使用不同的小规模 benchmark，实验设定不可比较。OpenABC-D 提供了 29 个 IP x 1,500 recipe x 20 step = 870,000 个 AIG 的统一数据集，让不同方法可以在同一标准下比较。

### 创新点 2：完整 synthesis trajectory 保存

不是只保存「初始 AIG + 最终 QoR」，而是保存每一步（step0->step20）的完整图结构。这为强化学习方法提供了天然的 MDP 状态空间。

### 创新点 3：三种 OOD 泛化任务设计

通过 unseen recipe / unseen IP / unseen pair 三种数据划分，系统性评估模型在不同分布偏移下的泛化能力，比简单的 random split 更能暴露模型的真实泛化瓶颈。

### 创新点 4：GCN + recipe Conv1d 双分支融合架构

证明将 AIG 图结构（GCN 编码）和 recipe 序列（Conv1d 编码）同时作为输入进行 QoR 预测是可行的。

## 9. 与芯片流程的关系

OpenABC-D 位于逻辑综合阶段（阶段 ③），从 RTL（阶段 ①）出发，产出标注的 AIG 图数据供 ML 模型训练。它解决的核心痛点是：在 OpenABC-D 之前，ML-guided logic synthesis 没有标准化的 benchmark——每个组用不同的电路、不同的 recipe 设定、不同的评估指标，结果无法比较。

**「MSE=0.579」和「选对最优 recipe」之间隔着什么**：MSE 低不等于 recipe ranking 准确。两条 recipe 可能都有接近真实值的 MSE 预测，但模型可能错误地排序了它们的相对优劣。真正有工程价值的是 top-k recipe 召回率、regret、Pareto 覆盖率——这些论文没有报告。

## 10. 讨论与局限

### 10.1 论文自述的局限

论文 Section 5「Discussion and further insights」的 Limitations 段落自陈三点：

1. **baseline 模型刻意做得简单**。论文只用一个 simple GCN 演示「这个数据集能怎么用」，不主张这是 QoR 预测的最优模型，明确鼓励社区在此之上开发更先进的模型。因此 OpenABC-D 上的 GCN 精度数字应读作「数据集可用性的下界」，不是该任务的 SOTA。

2. **开源工业级硬件 IP 稀缺，覆盖面仍有增长空间**。论文承认在任何 ML 引导的 EDA 流程里，模型必须训练在「能代表真实分布」的 IP 样本上；OpenABC-D 用不同功能的硬件 IP 生成数据只是朝这个方向迈出的第一步（"the first step towards this"），它比已有数据集更全面、更贴合 ML 用法，但"there remains a scarcity of industrial-scale open source hardware IPs"——29 个 IP 距离真实工业设计的多样性仍有差距。

3. **因此使用者必须做分布外检查**。论文原文的告诫是：EDA 工程师对推理结果要保持谨慎（"be cautious about using the inference results"），对任何未见过的硬件 IP 都应先做 out-of-distribution check，再决定是否信任模型输出、是否需要用新数据重训。论文在同节给出了一个可操作的手段——用 GCN embedding 的 t-SNE 图判断未知 IP 是否与已知 IP 相似（两层 GCN 做 IP 功能分类，35 epoch 后达到 98.05% 准确率），不相似就说明该重训了。

### 10.2 代码/复现层面的问题

| 问题 | 影响 |
|------|------|
| `args.epoch` vs `args.epochs` 命名不一致 | 训练脚本启动前报错 |
| README 命令与代码参数名不一致 | 按 README 无法运行 |
| GraphML->PyG 生成 `.pt.zip`，Dataset 期待另一命名 | 数据加载链断裂 |
| Variant 2 oracle normalization | 测试 IP 标准化需全量标签，破坏 unseen IP 假设 |
| Edge type 未使用 | baseline GCN 忽略反相边信息 |

### 10.3 批判性分析

**Edge type 信息被浪费**：AIG 的核心语义是「取反边」——区分 AND(a, b) 和 AND(!a, b)。但 baseline 把边都当同质无向连接处理，丢失了 AIG 最本质的信息。

**Recipe 编码太简单**：7 种操作被编码为 3 维可学习 embedding，没有利用操作之间的结构关系（如 `rewrite` 和 `rewrite -z` 高度相关）。

**200,000+ compute-hours 的门槛**：大多数研究组无法重新生成数据。

## 12. 一分钟复述版

OpenABC-D（NYU，arXiv 2021）是 EDA 领域首个大规模标准化逻辑综合数据集。核心：用 Yosys+ABC 对 29 个开源 RTL IP 各跑 1,500 条随机 20 步 recipe，保存 870,000 个中间 AIG 并标注 Nangate 45nm area/delay。定义三种 OOD 泛化任务（unseen recipe / unseen IP / unseen pair），提供 GCN+Conv1d 双分支 QoR 预测 baseline（Variant 1 MSE=0.579，Variant 2 MSE=1.236）。IP 分类 98.05% accuracy。核心局限：baseline 未用 edge type、Variant 2 存在 oracle normalization、200K+ compute-hours 生成成本、MSE 不等于 recipe ranking 效果。
