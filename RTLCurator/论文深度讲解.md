## 1. 一句话定位

**RTLCurator 是一个面向 RTL 生成训练数据的标签高效筛选框架：先用源语料上的渐进课程对比学习训练一个行为感知的 spec-RTL 兼容性编码器（无需仿真即可给每对打分），再用仅占目标池 10% 的验证标签校准这个分数，最后按 Alignment Score、表示覆盖度和 RTL 结构丰富度三个维度平衡分配保留预算 K，使得在 CodeV 和 RTLCoder 上保留 80% 数据训练时，10 项下游指标全部优于全量训练。**

这句话里的 4 个承重点，后面逐一拆解：

1. **行为感知兼容性先验** — 通过三阶段课程对比学习（随机负例 -> 同簇跨规格负例 -> 同规格功能失败负例），让 encoder 学会区分“表面相似但行为不同”的 RTL 实现，而非仅仅做文本匹配。
2. **小预算校准** — 用主动选择的最多 B 对（仅占池子 10%）做仿真验证并获取二进制对齐标签，训练一个轻量 MLP 校准器，将源域先验修正为目标域上的 Alignment Score。
3. **三维平衡选择策略** — 按 Alignment Score 分层分配配额、按表示簇比例填充、再在每层每簇内用 Structural Richness 修正排名，避免纯高分策略导致数据坍塌为短小简单模块。
4. **跨语料可迁移** — 编码器在 VeriCoder/OriGen 上训练，无需在 CodeV/RTLCoder 上重训即可迁移，Shift-Aware 预处理进一步缩小域差异。

## 2. EDA 阶段映射（①-⑰）

这节回答：RTLCurator 处于芯片设计全流程的什么位置，涉及哪些阶段、不涉及哪些阶段以及为什么。

参照 [芯片流程.md](../芯片流程.md) 的 17 阶段标准编号：

| 阶段 | 覆盖 | 说明 |
|------|:---:|------|
| **① RTL 设计** | ✅ **核心** | RTLCurator 的直接作用对象——从大规模 spec-RTL 数据池中筛选高质量训练子集，用于训练下游 RTL 生成模型，属于 RTL 设计阶段的数据准备环节 |
| ② RTL 功能仿真 | ✅ 依赖 | 验证流程使用编译+仿真+testbench 作为 alignment oracle，输出二进制对齐标签 $y_i \in \{0, 1\}$；但 validation 在这里是“筛选手段”而非“验证目标” |
| ③ 逻辑综合 | ❌ | 不涉及——RTLCurator 不做任何综合，筛选依据是 spec-RTL 的行为对齐而非网表级结构 |
| ④ 门级仿真 | ❌ | 不涉及——验证只到 RTL 仿真层面（iverilog/VCS），不注入 SDF 延时 |
| ⑤ STA（静态时序分析） | ❌ | 不涉及——不评估时序收敛或路径延迟 |
| ⑥ 形式验证 | ❌ | 不涉及——不使用 SAT/SMT 求解器证逻辑等价性 |
| ⑦ 布局规划 (Floorplan) | ❌ | 不涉及 |
| ⑧ 标准单元摆放 (Placement) | ❌ | 不涉及 |
| ⑨ 时钟树综合 (CTS) | ❌ | 不涉及 |
| ⑩ 布线 (Routing) | ❌ | 不涉及 |
| ⑪ 后仿真 | ❌ | 不涉及——不需要 SPEF 或寄生 RC |
| ⑫ 物理验证 (DRC + LVS) | ❌ | 不涉及 |
| ⑬ 签核 (Signoff) | ❌ | 不涉及——不生成 GDSII |
| ⑭ 流片 | ❌ | 不涉及 |
| ⑮ 制造 | ❌ | 不涉及 |
| ⑯ 封装 + 测试 | ❌ | 不涉及 |
| ⑰ 芯片到手 | ❌ | 不涉及 |

**覆盖率：2/17。** RTLCurator 严格限定在 RTL 设计阶段的数据工程问题——它不是芯片设计工具，而是为训练 RTL 生成模型提供数据质量保障的上游基础设施。

> **该论文最容易被误读的边界：**
> RTLCurator 的“功能正确”只由 testbench 的仿真通过/失败定义，不涉及可综合性、时序收敛、PPA 或形式等价。被标记为 $y_i = 1$（对齐）的 spec-RTL 对可能通过了仿真但在物理实现上不可综合、时序违例或面积过大。筛选出的训练数据能帮助模型更好地通过 VerilogEval 的功能仿真评测，但距离“这段代码能做成芯片”还有 ③-⑬ 整整十一个阶段的距离。

## 3. 输入 / 输出

### 3.1 输入

RTLCurator 接受以下输入：

**（1）目标语料库 $\mathcal{U}$**

格式为 $N$ 对 spec-RTL 对，每对包含自然语言规格和对应的 Verilog 实现。

具体例子（取自 RTLCoder 数据池）：

```
规格（si）:
"Design a D flip-flop with asynchronous reset. On the positive edge
of the clock, the output q should take the value of input d. When
reset is asserted high, q should be cleared to 0 immediately."

RTL 实现（ri）:
```

```verilog
module dff_async_reset (
    input  wire clk,
    input  wire rst,
    input  wire d,
    output reg  q
);
    always @(posedge clk or posedge rst) begin
        if (rst)
            q <= 1'b0;
        else
            q <= d;
    end
endmodule
```

目标语料规模：CodeV 164,111 对，RTLCoder 26,532 对。

**（2）源语料库 $D_{\text{src}}$**

用于训练兼容性先验编码器的 spec-RTL 对，论文使用公开的 VeriCoder/OriGen 数据，按 90/5/5（训练/验证/测试）切分。该源语料**不包含**任何 CodeV 或 RTLCoder 数据，保证跨语料迁移评估的无偏性。

**（3）验证预算 $B$**：可对池中样本进行仿真验证的最大数量，$B \ll N$。论文典型设置为池子大小的 10%。

**（4）保留预算 $K$**：最终保留用于下游 SFT 的子集大小，$K < N$。论文探索 50%–90%。

**（5）重写模型**：用于 Shift-Aware 预处理的辅助 LLM，将目标规格改写为源语料风格。论文未指定具体模型名称。

### 3.2 中间产物

**（1）源风格辅助规格 $\widetilde{s}_i$**

原始规格经 Shift-Aware 重写后得到的 encoder 视角文本，仅用于编码器和聚类，不替代原始规格：
```
原始 si: "Design a D flip-flop with asynchronous reset..."
重写 s̃_i: "Implement a sequential element that captures input d on
the rising clock edge and clears asynchronously when reset is high.
The output q reflects the stored value."
```

**（2）兼容性先验 $q_i$**

对于每对 $(s_i, r_i)$，经过 Shift-Aware 重写后 encoder 输出的余弦相似度：

$$
q_i = q_\theta(\widetilde{s}_i, r_i) = \cos(f_\theta(\widetilde{s}_i), f_\theta(r_i))
$$

- $s_i, r_i$：第 $i$ 对样本的自然语言规格与候选 RTL
- $\widetilde{s}_i$：Shift-Aware 重写后的规格文本
- $f_\theta$：共享参数 $\theta$ 的 encoder，把文本/代码映射到同一嵌入空间
- $q_i$：兼容性先验分数，取值 $[-1, 1]$，越高表示该规格-RTL 对越可能一致

这个分数在验证前即可获得，是整个框架在 $B \ll N$ 约束下工作的关键。

**（3）表示簇划分**

所有 $\widetilde{s}_i$ 的嵌入被聚类为 $C$ 个固定簇，用于后续采样路由和覆盖分配。簇的划分在 encoder 冻结后执行一次。

**（4）验证标签 $y_i \in \{0, 1\}$**

通过编译+仿真+testbench 获取，或经 LLM 法官/专家复审裁决。

**（5）Alignment Score $p_i \in [0, 1]$**

MLP 校准器 $g_\psi$ 的输出，将先验 $q_i$ 与结构特征 $\phi_i$ 联合映射为校准后的行为对齐分数。

**（6）结构特征向量 $z_i$**

每个 RTL 的标准化结构统计量，包含：
- Token 数、行数、端口数（百分位数标准化）
- 控制逻辑计数（裁剪）
- FSM 和时钟线索（二元特征）

### 3.3 输出

**最终输出：精选训练子集 $\mathcal{S}(B, K)$**

大小 $|\mathcal{S}| = K$，包含原始 spec-RTL 对（使用原始规格 $s_i$，而非重写后的 $\widetilde{s}_i$）。这个子集直接用于 DeepSeek-Coder-6.7B-Instruct 的监督微调。

端到端 walkthrough：以上述 DFF 例子为例，假设它的兼容性先验 $q_i = 0.78$，校准后 $p_i = 0.82$（落入高分层），所在簇有 1,200 个候选，该层该簇的配额为 45 对；它的 token 数在 70 分位、包含 FSM 二元特征和时钟信号，structural richness 加分后在该单元内排第 18 位——于是被保留。如果换成 Align. top 策略，因为它的行数较短（~12 行），很可能被其他更长的模块挤出，导致训练数据中缺少 DFF 类基础时序模块。

### 4.1 整体 Pipeline

下图与论文 Figure 2 对应，展示从源语料训练到目标语料筛选的完整三阶段流程：

**解读**：这个 pipeline 的核心设计哲学是“把昂贵的验证花在刀刃上”。兼容性先验提供了全池的粗粒度排名（零验证成本），然后主动选择信息量最大的少量样本做验证来校准这个排名，最后用三维平衡避免排名极值导致的数据坍塌。三个阶段的成本分布严重不均——编码器训练是一次性投入（在源语料上），验证是昂贵但只花 B 次，选择是纯计算几乎免费。

### 4.2 核心模块逐个详解

#### 模块 1：Spec-RTL Encoder（兼容性先验训练）

**为什么存在**：RTL 的表面文本和它的电路行为之间没有强相关性。同一个规格可以有多个看起来完全不同的正确实现，而把 `<=` 改成 `=`（非阻塞改阻塞赋值）能改变逐周期行为却几乎不改变文本外观（见论文 Figure 1）。因此需要一个不只看文本、能感知行为差异的编码器。

**三阶段渐进课程**：

- **Stage 1: Retrieval Initialization** — 用已验证正例 vs 随机跨规格 RTL 负例做多负例检索学习（$L_{\text{retr}}$），建立 spec 和 RTL 之间的全局对应关系。这一阶段让 embedding 空间形成有意义的邻域结构，为后续的负例挖掘提供基础。

- **Stage 2A: In-Cluster Contrastive** — 利用 Stage 1 的 embedding 空间，将每个正确 RTL 与来自同一表示簇但对应不同规格的 RTL 做对比。这些同簇负例与正例在语义/结构语境上相近，迫使 encoder 学会区分“看起来相关但实际不匹配”的 spec-RTL 对。同时重放 Stage 1 的关系以保持全局结构。

- **Stage 2B: Functional Contrastive** — 最关键的一步。固定规格不变，用多个生成源（CodeV-R1、MiniMax-M2.7、DeepSeek-V4-Flash）中“在 Stage 2A embedding 空间里看起来合理但仿真失败”的实现在作为困难负例。这教会 encoder 如何区分“同一个规格下哪个实现是对的”——这正是数据筛选要做出的核心判断。

**输出**：编码器 $f_\theta$ 输出归一化的 spec 嵌入和 RTL 嵌入，兼容性先验定义为余弦相似度 $q_\theta(s, r) = \cos(f_\theta(s), f_\theta(r))$。

#### 模块 2：Shift-Aware Preprocessing

**为什么存在**：源语料（VeriCoder/OriGen）和目标语料（CodeV/RTLCoder）的规格风格不同——CodeV 的规格是从爬取 RTL 反向总结的简短摘要，而 OriGen 的规格更详细。直接输入会导致 encoder 性能下降。

**做了什么**：对目标池每对 $(s_i, r_i)$，用一个重写模型同时看到原始规格和候选 RTL，生成源语料风格的辅助规格 $\widetilde{s}_i$。这个 $\widetilde{s}_i$ 仅用于 encoder 路径，不改变行为契约——testbench 生成和验证仍用原始 $s_i$，最终保留的也是原始对 $(s_i, r_i)$。

**实际效果**：从 Table 4 可以看到，使用 LLM 重写后，CodeV 上 R@1 从 43.11 提升到 71.85（+28.74 点），RTLCoder 上从 60.82 提升到 75.42（+14.60 点）。

#### 模块 3：Budgeted Validation & Calibration

**为什么存在**：验证一对 spec-RTL 是否真正对齐需要编译、仿真、testbench，成本高昂。但完全不做验证，仅靠先验 $q_i$ 做选择效果不佳（Align. top 策略在 pass@1 上低于 Random）。需要在验证成本和选择质量之间找到最优点。

**Acquisition Routing**：在每次采集轮次中，配额均分给 5 条路由——决策边界路由、排名中心路由、证据不足簇路由、排名头尾路由。这些路由决定“在哪里花验证预算”，而非“保留哪些对”。当多个保留预算同时请求时，路由覆盖所有请求的决策边界，标签跨子集共享。

**Validation Protocol**：验证管线包含编译、仿真和 testbench 证据评估。当 testbench 未充分锻炼出足以区分对齐/失配的行为时，修订并重跑最多 $R_{\text{tb}}$ 轮。超限后提交 LLM 多法官评审或专家复审，产出二进制对齐标签 $y_i$。

**Calibration**：校准器 $g_\psi$ 是一个轻量 MLP，输入兼容性先验 $q_i$ 和结构特征 $\phi_i$，输出 Alignment Score $p_i$。用 BCE 损失在已标注数据上拟合，每轮采集后重新拟合。最终的拟合覆盖全池 $U$。

**关键实验事实**：在 RTLCoder 上，0% 标签时 top-1000 vs bottom-1000 接受率差距仅 16.8pp；仅标注 1% 池子后差距跳升到 66.0pp（贡献了 79% 的总提升）；5% 和 10% 分别达到 75.8pp 和 78.8pp。说明极少量的主动标注即可大幅校准先验。

#### 模块 4：Retention-Budgeted Selection

**为什么存在**：纯按 Alignment Score 取 top-K 会导致子集崩塌向短小简单模块——Align. top 在 RTLCoder 上将平均模块长度从 46.7 行压到 30.6 行，在 CodeV 上从 37.6 行压到 29.2 行（Table 2），且下游表现甚至低于随机选择。因此需要多维平衡。

**三维平衡机制**：

1. **Alignment Score 分层**：将 $K$ 按分数分位分配，最高分层获得最大名义份额，其余分层获得均等较小份额。若某分层候选不足，超额按剩余容量重新分配。

2. **Representation Coverage**：每层配额按各簇的候选数比例分配到固定簇，确保不同语义/结构类型的 spec-RTL 对都有代表。这阻止了分数集中在某个特定类型的数据上。

3. **Structural Richness**：在每个（层, 簇）单元内，按结构特征 $z_i$ 的加权组合 $\rho(r_i) = w^\top z_i$ 算分位数，将分位 bonus 加到 Alignment Score 上做最终排名。这确保在同等对齐质量下，优先保留有 FSM、有时钟控制、有一定规模的结构丰富模块，而非最简单的组合逻辑。

**效果**：RTLCurator 保留子集的平均模块长度在 CodeV 为 33.6（Full 37.6，Align. top 29.2），在 RTLCoder 为 36.8（Full 46.7，Align. top 30.6）——在保持结构多样性的同时仍比全池紧凑，这是平衡策略的直接结果。

| 模块 | 输入 | 输出 | 用到的模型/工具 | 是否需训练 |
|------|------|------|-----------------|:---:|
| Spec-RTL Encoder | 源语料 spec-RTL 对 + 功能失败负例 | 兼容性先验 $q_i$、spec/RTL 嵌入 | Qwen3-Embedding-4B（骨干） | ✅ 对比学习 |

## 5. 关键公式

这节覆盖论文中的所有编号公式，并提供工程直觉解释。

### 5.1 最优子集定义（Equation 1）

论文定义了理想化的优化目标——虽然 RTLCurator 不直接求解此式，但它定义了框架的方向。

$$
S_K^\star = \arg\max_{\substack{S \subseteq U \\ |S| = K}} J(A(\theta_0, S))
$$

- $S_K^\star$：在保留预算 $K$ 下能使下游效用最大化的理想子集
- $U$：目标语料全池，$|U| = N$
- $K$：保留预算，$K < N$
- $A(\theta_0, S)$：从初始模型 $\theta_0$ 出发，在子集 $S$ 上做监督微调得到的新模型
- $J$：下游效用函数（如 VerilogEval Functional pass@1）

**工程直觉**：这是 NP 难组合优化问题——你不能对每个候选子集都训一遍模型再测。RTLCurator 的整个框架就是为了在 $B$ 次验证的约束下，用一个 proxy 信号逼近这个最优子集。

### 5.2 Shift-Aware 预处理（Equation 2）

$$
\widetilde{s}_i = \mathcal{R}(s_i, r_i)
$$

- $\widetilde{s}_i$：重写后的辅助规格（源语料风格）
- $\mathcal{R}$：重写模型
- $s_i$：原始目标规格
- $r_i$：候选 RTL 实现

**工程直觉**：这相当于给 encoder 戴上一副“翻译眼镜”——把目标域的风格翻译成 encoder 熟悉的源域风格。不改变 $s_i$ 定义的行为契约，只改变表达方式。

**为什么这么设计**：直接 finetune encoder 到目标域需要大量目标域标签（与 $B \ll N$ 矛盾）；不做域适配则 encoder 性能下降。重写是一种零标注的域适配方法——利用 LLM 的文本重写能力桥接域差异。

### 5.3 对比学习 Margin Loss（Equation 3 & 4）

Margin violation 项：

$$
\Delta_i = q_\theta(s_i, r_i^-) - q_\theta(s_i, r_i^+) + \mu
$$

- $\Delta_i$：第 $i$ 对的正负例 margin 违规量——正例分数应该比负例高至少 $\mu$，否则产生正的 violation
- $q_\theta(s_i, r_i^+)$：spec 与正确实现的兼容性分数
- $q_\theta(s_i, r_i^-)$：spec 与负例实现的兼容性分数
- $\mu > 0$：margin 阈值，正例需比负例高出至少 $\mu$ 才算“安全”

Logistic loss：

$$
\ell_i = \log(1 + \exp(\Delta_i))
$$

- $\ell_i$：单对的对比损失

**工程直觉**：这是 hinge loss 的平滑版本。当 $q_\theta(s_i, r_i^+) - q_\theta(s_i, r_i^-) \geq \mu$ 时，$\Delta_i \leq 0$，$\exp(\Delta_i) \approx 0$，$\ell_i \approx 0$——正例已经足够安全。当正例分数不够高或负例分数太高时，$\Delta_i > 0$，损失上升，推动 encoder 拉开两种实现的分数差距。

**为什么这么设计**：margin $\mu$ 确保 encoder 不仅区分正负例，还要拉开足够距离。这在数据筛选场景中很重要——如果正负例分数差距只有 0.02，后续的校准和分层就几乎没有区分度。

### 5.4 累积课程目标（Equation 5）

论文未给出单个编号公式，以方程组呈现三阶段目标：

$$
L_1 = L_{\text{retr}}
$$

$$
L_{2A} = \lambda_A^r L_{\text{retr}}^{\text{replay}} + \lambda_A^c L_{\text{cross}}
$$

$$
L_{2B} = \lambda_B^r L_{\text{retr}}^{\text{replay}} + \lambda_B^c L_{\text{cross}} + \lambda_B^f L_{\text{func}}
$$

- $L_{\text{retr}}$：Stage 1 的多负例检索损失
- $L_{\text{retr}}^{\text{replay}}$：在后续阶段重放 Stage 1 关系的重放损失——防止灾难性遗忘
- $L_{\text{cross}}$：Stage 2A 的同簇跨规格对比损失（负例来自同一簇但不同规格）
- $L_{\text{func}}$：Stage 2B 的同规格功能对比损失（负例来自同规格的仿真失败实现）
- $\lambda_{\cdot}^{\cdot} \geq 0$：各阶段各损失项的权重系数

**工程直觉**：这像学习骑自行车——Stage 1 学会“这是自行车”，Stage 2A 学会“这辆和那辆的区别”（防混淆），Stage 2B 学会“这辆车怎么骑才是对的”（防错误）。每个阶段都不忘前一阶段学到的东西（replay）。

### 5.5 Calibrator Prediction & BCE Fitting（Equation 6 & 7）

校准器预测：

$$
\hat{p}_{i\psi} = g_\psi(q_i, \phi_i)
$$

- $\hat{p}_{i\psi}$：参数为 $\psi$ 的校准器对第 $i$ 个候选的预测对齐分数
- $g_\psi$：MLP 校准器
- $q_i$：兼容性先验（encoder 输出）
- $\phi_i$：轻量校准特征（候选的结构统计量）

BCE 拟合：

$$
\psi^\star = \arg\min_\psi \sum_{x_j \in Q_t} \eta_j \, \ell_{\text{BCE}}\left(y_j, \hat{p}_{j\psi}\right)
$$

- $\psi^\star$：最优校准器参数
- $Q_t$：第 $t$ 轮采集时已解析的已验证集合
- $\eta_j > 0$：证据置信权重——对经专家复审确认的标签给予更高权重
- $\ell_{\text{BCE}}$：二元交叉熵损失
- $y_j \in \{0, 1\}$：二进制对齐标签

**工程直觉**：$q_i$ 是从源域来的“外国评分标准”，$\phi_i$ 是候选自身的“体检数据”，校准器的任务是把它们翻译成目标域的“本地评分标准”。BCE 拟合就是用一个小的“标准答案对照表”（$B$ 个已验证标签）来学这个翻译关系。

### 5.6 Structural Richness（Equation 8）

$$
\rho(r_i) = w^\top z_i, \quad w \succeq 0, \quad \mathbf{1}^\top w = 1
$$

- $\rho(r_i)$：第 $i$ 个 RTL 的结构丰富度分数
- $z_i \in [0, 1]^d$：标准化后的 $d$ 维结构特征向量
- $w$：固定权重向量，非负且归一化
- $\mathbf{1}$：全 1 向量

**工程直觉**：这是一个手工设计的“复杂度评分卡”。Token/line/port 的百分位数保证数据规模不会完全崩塌到极简模块；FSM 和时钟线索的二元特征确保时序设计有基本代表。权重 $w$ 在实验中固定而非学习——论文未报告 $w$ 的具体数值，也未报告权重敏感性分析。

## 6. 训练与实验设置

### 6.1 是否需要训练

RTLCurator **需要训练**，但分三层且目标不同：

| 训练对象 | 数据 | 目标 | 相对成本 |
|---------|------|------|:---:|
| Spec-RTL Encoder（$f_\theta$） | 源语料 VeriCoder/OriGen，90/5/5 切分 | 学习行为感知的 spec-RTL 兼容性先验 | 高（一次性） |

## 7. 创新点

### 创新点 1：行为感知的兼容性先验——通过对比失败实现来学习“什么是对的”

**已有方法的局限**：通用文本/代码嵌入模型（如 Qwen3-Embedding-4B、CodeBERT）只能衡量 spec 和 RTL 的文本/语义相似度。在 RTL 领域，文本相似度与行为正确性之间没有强相关——同一个规格下多个实现可以文本差异极大但行为相同，而一个阻塞赋值 vs 非阻塞赋值的微小编辑（一个字符的改变）却能彻底改变逐周期行为。

**RTLCurator 的改进**：通过三阶段渐进课程对比学习，特别是 Stage 2B 的同规格功能对比——将仿真失败的实现作为困难负例——教会 encoder 区分“看起来差不多但行为不一样”的实现对。关键的工程洞察是：**负例不需要手工标注**——只需在多源生成模型产出的候选上跑仿真，自动收集失败案例即可。

### 创新点 2：“验证用于校准而非筛选”——用 10% 的标注完成全池排序

**已有方法的局限**：VeriCoder 等现有工作验证每个候选并只保留通过的对，这意味着要么花全池的验证成本，要么无法对未验证的对做任何判断。且仿真是一个二分类结果（通过/失败），无法提供细粒度排序。

**RTLCurator 的改进**：将零成本的兼容性先验（全池可用）与昂贵的验证标签（少量可用）解耦——先验提供排序，验证提供校准。MLP 校准器将先验映射为目标域的 Alignment Score，使得全池 $N$ 对都有连续的排序分数。实验证明仅 1% 的标注预算就贡献了 79% 的区分能力提升，前 1,000 与后 1,000 的接受率差距从 16.8pp 扩至 66.0pp。

### 创新点 3：三维平衡选择策略——分数不是唯一标准

**已有方法的局限**：通用数据选择方法（DS2、LESS）的评分信号不直接衡量 spec-RTL 对齐，导致在 RTL 数据上效果不佳（甚至不如随机选择）。纯按行为对齐分数取 top 则导致保留子集坍缩为短小简单模块——Align. top 在 RTLCoder 上将平均模块长度从 46.7 压到 30.6 行，下游表现低于随机。

**RTLCurator 的改进**：三个维度的平衡解决了分数单一化的缺陷：
1. Alignment Score 分层——避免只取最高分，给中等分数区保留名额
2. Representation Coverage 分簇——避免所有名额集中在某一类 spec（如所有分数高的恰好都是组合逻辑）
3. Structural Richness 加分——在同等对齐分数下偏好结构更丰富的模块（有 FSM、有时钟、有一定规模）

三个维度的协同作用使 RTLCurator 在 RTLCoder 80% 保留下保持模块平均长度 36.8 行（vs Align. top 的 30.6 行），且在所有指标上优于全量训练。

### 创新点 4：跨语料迁移——encoder 对未见语料的泛化

**已有方法的局限**：大多数数据筛选方法需要在目标语料上训练或微调评分模型，当目标语料没有标签时无法工作。

**RTLCurator 的改进**：编码器在 VeriCoder/OriGen 上训练后可**直接迁移**到 CodeV 和 RTLCoder——训练数据和目标数据无重叠。Shift-Aware 预处理进一步缩小域差异，使 CodeV 上 R@1 提升 +28.74 点。这意味着一次 encoder 训练可服务于多个目标语料，大幅摊薄成本。

## 9. 与芯片流程的关系

### 9.1 在全流程中的位置

RTLCurator 严格处于阶段 ① RTL 设计的前置数据准备环节。它的上游是“合成 spec-RTL 数据池”（由 CodeV、RTLCoder 等 data generation pipeline 产出），下游是“用筛选后数据训练的 RTL 生成模型”（DeepSeek-Coder-6.7B-Instruct 的 SFT）。

**接手谁的输出**：合成的 spec-RTL 数据池——这些数据的形态是“文本配对”，质量参差不齐（CodeV 仅 53.5% 通过功能测试，RTLCoder 仅 24.4%）。

**交棒给谁**：RTL 生成模型（阶段 ① 的生成工具）——模型用精选子集微调后，接收新的自然语言规格，生成对应的 Verilog 代码。这个生成的代码随后进入 ② RTL 功能仿真做正确性验证。

**解决了什么痛点**：RTL 训练数据的“规模-质量”矛盾。合成能提供规模（CodeV 16.4 万对），但不保证质量；验证能确保质量，但成本高且过滤后的数据偏向简单模块。RTLCurator 在规模和质量的帕累托前沿上找到了一个低验证成本的工作点。

### 9.2 “功能仿真通过”和“能做成芯片”之间隔着什么

RTLCurator 筛选出的训练数据能帮助模型在 VerilogEval 上取得更好的功能仿真通过率，但这是“验证层面的成功”而非“物理实现的成功”。从被 RTLCurator 标记为 $y_i = 1$ 的 spec-RTL 对出发，到真正的芯片还有以下鸿沟：

1. **可综合性未验证**（③ 逻辑综合）：代码可能使用了不可综合的构造（如 `$display`、`initial`、`fork-join`、含 `#delay` 的 testbench 风格代码）。合成数据通常经过语法过滤，但语法正确不等于可综合。

2. **时序未验证**（⑤ STA）：即使代码可综合成网表，组合逻辑路径的延迟可能超过时钟周期。RTL 仿真假设零延迟，无法暴露时序违例。

3. **功耗未评估**（⑬ 签核）：无任何信息判断电路在 GHz 频率下的动态功耗（$\frac{1}{2}CV^2f\alpha$）和静态漏电功耗。

4. **面积/PPA 未优化**（③ 综合优化）：筛选标准不包含任何 PPA 信号，模型学到的是“功能正确”而非“面积小/功耗低/频率高”。

5. **物理可实现性未知**（⑦-⑫）：从 Floorplan 到 Post-layout Simulation，筛选出的数据不与任何工艺库绑定，不包含物理信息。

6. **评测集与真实设计的差距**：VerilogEval 的问题是 10-50 行的模块级设计；真实 SoC 设计包含多文件层次结构、跨模块接口协议、复杂的时钟域交叉和复位策略。

> **一句话总结**：RTLCurator 的数据适合训练一个“能通过蓝翔技校考试（VerilogEval）的模型”，距离训练出“能造真正芯片的模型”还有整个 ③-⑬ 物理设计流程的信息缺失。

## 10. 讨论与局限

### 10.1 论文自述的局限

论文结论部分指出了两个方向：将 coverage 和 structural richness 的贡献分离分析，以及扩展到其他硬件数据管线。论文未在正文中详细列出自述局限，但实验部分隐含了以下边界：

- 只在两个合成语料（CodeV、RTLCoder）上验证，未评估其他类型的 RTL 数据（如 GitHub 爬取的真实代码）
- 结构特征为手工设计，可能遗漏更细粒度的 RTL 结构信息
- 下游评测限于 VerilogEval 和 RTLLM 两个 benchmark

### 10.2 代码/复现层面的问题

1. **无官方代码**：截至 2026-08-04 未核验到作者公开的代码仓库，整个框架的复现需要自行实现三阶段编码器训练、MLP 校准器、Acquisition Routing、三维选择策略和 Shift-Aware 预处理的所有细节。

2. **超参数未在主文报告**：编码器训练的 batch size、学习率、epoch 数、margin $\mu$、各级损失权重 $\lambda$、聚类数 $C$、采样路由的具体实现、testbench 修订轮数 $R_{\text{tb}}$ 等关键超参数在论文 technical appendix 中——而 arxiv 版通常不包含 appendix。缺少这些参数将使复现充满试错成本。

3. **Stage 2B 的困难负例依赖多源生成模型**：需要 CodeV-R1、MiniMax-M2.7、DeepSeek-V4-Flash 三个模型产出的失败候选——这些模型的获取和使用都有门槛。

4. **重写模型未指定**：Shift-Aware 预处理显著影响迁移性能（提升 14-29 点 R@1），但论文没有说明使用哪个模型做重写，也没有提供重写的 prompt 模板。

5. **权重 $w$ 未报告**：Structural Richness 的 8 维权重组未给出具体数值，复现者只能自行调参。

### 10.3 本资料包的批判性分析

**1. 方法的隐含前提——源语料和目标语料的“失败模式”可迁移**

encoder 在 VeriCoder/OriGen 上学习区分正确实现 vs 仿真失败实现，然后推广到 CodeV/RTLCoder。这隐含假设两个语料上的“失败模式”在 embedding 空间中具有相似的几何分布。如果目标语料的失败来自完全不同的原因（如 domain-specific ISA 约定错误 vs 基础 Verilog 语法混淆），先验的校准效果可能大打折扣。论文在 RTLCoder（风格较近）上表现好但 CodeV（反向总结风格）上需要 Shift-Aware 预处理才达到相近水平，侧面印证了这个假设的脆弱性。

**2. 评测的公平性——训练超参数“完全相同”未必公道**

论文强调下游 SFT 对所有策略使用“identical hyperparameters”。但不同选择策略产出的数据分布不同（长度分布、模块类型分布），最优训练超参数可能也不同。用同一套超参数训练相当于隐性假设超参数对不同数据分布同样适用——这是一个有利于 RTLCurator 的假设（因为 RTLCurator 有意让数据分布更接近全池的趋势，而 Full 的超参数本身就是为全池调的）。

**3. 可扩展性天花板——验证成本的线性增长**

论文的验证预算是池子大小的 10%，CodeV 约 16K、RTLCoder 约 2.7K 次仿真。这对两个中等规模语料是可承受的。但如果扩展到百万级甚至千万级语料，即使 10% 也意味着数十万至百万次仿真——这在工业环境中不现实。框架本身没有提供“如何在不增加验证预算的前提下进一步降低预算比例”的机制。

**4. 结构丰富度的定义缺乏消融——无法区分三个维度的各自贡献**

论文在第 7 节提到“Isolating the contributions of coverage and structural richness is a valuable direction for future research”，承认了对 Coverage 和 Richness 的作用缺乏独立消融。因此无法判断三维平衡中的提升主要来自 Alignment Score 分层、表示覆盖、还是结构丰富度。如果是前两者贡献了 90% 的提升而 Richness 只有边际贡献，那整个 $w$ 权重设计就存在过度工程化的问题。

**5. 二分类标签的信息瓶颈**

验证管线产出的是二进制标签 $y_i \in \{0, 1\}$——对齐或不对齐。但“不对齐”的原因可能千差万别：语法相同但语义错误、周期级行为偏差、接口不匹配、功能部分正确。这些不同失败模式的区分信号在二分类标注中完全丢失。如果校准器能利用更细粒度的失败类别信号，校准效果可能显著提升。

## 12. 一分钟复述版

1. RTL 生成模型的训练数据靠合成获得规模，但合成数据功能正确率极低（CodeV 53.5%、RTLCoder 24.4%），需要筛选。
2. RTLCurator 提出三阶段框架：训练兼容性先验 → 小预算校准 → 三维平衡选择。
3. 兼容性先验通过三阶段渐进课程对比学习获得——从随机负例到同簇跨规格负例再到同规格仿真失败负例，教会 encoder 区分“表面相似但行为不同”的实现。
4. 关键创新：不做全池验证，而是用仅 10% 的主动选择验证标签校准先验——MLP 校准器将源域分数映射为目标域 Alignment Score。
5. 1% 的标注预算就贡献了 79% 的区分能力提升（top-1000 vs bottom-1000 接受率差距从 16.8pp 跳至 66.0pp）。
6. 纯按 Alignment Score 取 top 会导致数据崩塌——Align. top 将模块平均长度从 46.7 压到 30.6 行，性能低于随机选择。
7. 三维平衡策略：Alignment Score 分层分配配额 + 按表示簇比例填充 + Structural Richness 单元内排序修正。
8. 在 CodeV 和 RTLCoder 上，保留 80% 数据时 10 项下游指标全部优于全量训练——丢掉 20% 反而更好，因为丢的是“有毒”数据。
9. 对比全池验证后仅保留通过子集（全文最昂贵的 baseline），RTLCurator 用五分之一验证成本获得全面更优结果。
10. 整个框架的编码器是一次性训练、可跨语料迁移的——在 OriGen 上训练后直接用于 CodeV/RTLCoder，无需目标域标签。
11. 局限：依赖源目标域失败模式可迁移的假设、训练超参数公平性存疑、验证成本随语料规模线性增长、三维各自贡献未消融分离。
12. 代码未开源，大量超参数在 technical appendix 中未见于主文，完全复现需自行实现全部管线。
