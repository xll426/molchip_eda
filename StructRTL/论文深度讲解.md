## 1. 一句话定位

**StructRTL 不把 RTL 代码当 token 序列喂给 LLM，而是先把 Verilog 转成控制数据流图（CDFG），用 8 层 GIN 做图消息传递 + 8 层 Transformer 做长程依赖建模，再通过两个图自监督预训练任务（structure-aware masked node modeling + edge prediction）学习结构感知的图嵌入，最后接一个 3 层 MLP 预测综合后的面积和延迟——在 13,200 个设计的 benchmark 上，无 KD 时 Area R2=0.7463 vs LLM baseline 最优 0.6353，有 KD 时 Delay R2=0.8872，推理比完整综合快约 145 倍（0.096s vs 13.97s）。**

这句话里的五个技术承重点，后面逐一拆解：

1. **CDFG 替代 token 序列** -- LLM-based 方法（VeriDistill）把 Verilog 当代码文本处理，token 序列隐式编码结构语义但无法显式区分"a 和 b 经过加法器到 c"和"a 和 b 经过乘法器到 c"的数据流差异。CDFG 的节点类型直接告诉你这是 Add 还是 Mul，边类型直接告诉你数据从哪来到哪去。这种结构显式化对 delay prediction 尤其关键——关键路径的结构信息在 CDFG 里是一目了然的子图，在 token 序列里却被语法噪声淹没。
2. **post-GNN 嵌入上掩码而非原始图上掩码** -- GraphMAE 和 MaskGAE 直接在原始图的节点/边上掩码，但 CDFG 的节点有严格功能语义：如果把加法器掩码掉，减法器、乘法器看起来都"合理"，学习信号被稀释。StructRTL 让 GIN 先把邻居信息聚合到每个节点，再在上下文感知嵌入上掩码——被掩码的嵌入已经包含了"周围有 Addition 操作数、结果去哪了"的信息，模型必须利用这些上下文来推断被掩码的类型。
3. **双预训练任务互补** -- Masked node modeling 学局部语义（这个节点是什么运算？Add vs Mul 对面积影响不同）；edge prediction 学全局拓扑（这两个节点连不连？连接模式决定关键路径深度和 reconvergence）。消融证明两者缺一不可：单独移除任何一个都会导致 Area/Delay R2 下降约 0.02~0.05。
4. **跨阶段知识蒸馏** -- 从后映射网表（PM netlist，已绑定到标准单元）训练一个 20 层 GIN teacher，其面积/延迟预测天然更准（因为网表级别的信息更接近最终的物理实现）。通过 cosine + MSE 混合损失将 teacher 的末层激活迁移到仅依赖 RTL/CDFG 的 student。KD 把 Area R2 从 0.7463 推到 0.8676。
5. **30M 参数、145 倍加速** -- 对比 LLM baseline 的 7B 参数，StructRTL 只有 30M 参数（fp32 约 114MB），推理 0.096 秒/设计，而完整逻辑综合需要 13.97 秒/设计。这使它可以嵌入迭代式 RTL 设计空间探索流程。

## 2. EDA 阶段映射（①-⑰）

参照 [芯片流程.md](../芯片流程.md) 的 17 阶段标准编号：

| 阶段 | 覆盖 | 说明 |
|------|:---:|------|
| **① RTL 设计** | ✅ **核心** | StructRTL 的输入就是 Verilog RTL 代码。它不生成 RTL，而是在 RTL 写完之后、综合之前，快速预估这个 RTL 综合出来大概多大面积、多快延迟 |
| ② RTL 功能仿真 | ❌ | StructRTL 不涉及仿真验证。数据集构建时用 Verilator 仿真筛掉了功能不正确的设计，但模型本身不管功能对错——它只预测"如果综合，面积/延迟大概是多少" |
| **③ 逻辑综合** | ✅ **预测目标** | StructRTL 的核心任务就是预测逻辑综合后的 area 和 delay，从而**跳过真正的综合**。但注意：它预测的是综合结果，并不替代综合——如果实际要流片，仍然需要跑完整的综合+映射流程来生成网表。KD 阶段引入的 PM netlist 来自综合+技术映射后的结果 |
| ④ 门级仿真 | ❌ | 无 SDF 反标，不关心毛刺和建立/保持违例 |
| ⑤ STA | ❌ | 不计算任何路径延迟。论文说的"delay"是综合工具报出的关键路径延迟估计值，不是 STA signoff 级别的精确时序 |
| ⑥ 形式验证 | ❌ | — |
| ⑦ 布局规划 Floorplan | ❌ | — |
| ⑧ 标准单元摆放 Placement | ❌ | — |
| ⑨ CTS | ❌ | — |
| ⑩ 布线 Routing | ❌ | — |
| ⑪ 后仿真 | ❌ | 无 SPEF |
| ⑫ 物理验证 DRC + LVS | ❌ | — |
| ⑬ 签核 Signoff | ❌ | — |
| ⑭-⑰ 流片→制造→封装测试→芯片 | ❌ | — |

**覆盖率：2/17。** StructRTL 是一个**跨 ①→③ 的质量预估器**：在 RTL 阶段输入，预测综合阶段的输出。它的实际角色是替代"边改 RTL 边跑综合看面积/延迟"这个慢速迭代循环，让设计者拿到接近综合精度的即时反馈。

> 需要注意的是：StructRTL 的 KD teacher 依赖 PM netlist，而 PM netlist 是综合+技术映射的产物。所以在**训练阶段**，它确实需要跑完整的 ①→③ 流程来获取标签和 teacher 训练数据。但在**推理阶段**，它只需要 RTL/CDFG，绕开了综合。

## 3. 输入 / 输出

这节用一个 8 位可逆计数器的端到端例子，展示从 RTL 代码到 CDFG 图结构、再到质量预测的完整信息流。

### 3.1 输入

**(a) Verilog RTL 源代码（.v 文件）**

```verilog
module counter (
    input clk,
    input reset,
    input updown,
    output reg [7:0] count
);

always @(posedge clk) begin
    if (reset)
        count <= 8'b0;
    else begin
        if (updown)
            count <= count + 1;
        else
            count <= count - 1;
    end
end

endmodule
```

**(b) 由 RTL 自动提取的 CDFG（控制数据流图）**

CDFG 是 StructRTL 的核心输入表示，提取过程：RTL → Yosys 编译为 RTLIL → Stagira Verilog parser 生成 AST → 遍历 AST 构建 CDFG。

以上述 counter 为例，CDFG 包含以下节点（共 9 个）和边：

**节点清单**：

| 节点 ID | 类型 | 属性 | 在 RTL 中的角色 |
|---------|------|------|----------------|
| n1 | Input | width=1 | `clk` 时钟输入 |
| n2 | Input | width=1 | `reset` 复位输入 |
| n3 | Input | width=1 | `updown` 方向选择 |
| n4 | Const | width=8, value=1 | 常数 1（用于加/减） |
| n5 | Const | width=8, value=0 | 常数 0（复位值） |
| n6 | Add | width=8 | `count + 1` 加法运算 |
| n7 | Sub | width=8 | `count - 1` 减法运算 |
| n8 | Cond | width=8 | 第一个 mux：根据 updown 选择 Add 或 Sub 结果 |
| n9 | Cond | width=8 | 第二个 mux：根据 reset 选择 0 或第一个 Cond 结果 |
| n10 | Reg | width=8 | `count` 寄存器，保存跨周期状态 |
| n11 | Output | width=8 | `count` 输出端口 |

**边清单**：

| 源节点 | 目标节点 | 边类型 | 物理含义 |
|--------|----------|--------|----------|
| n10 (Reg count) | n6 (Add) | 数据流 | 当前 count 值参与加法 |
| n10 (Reg count) | n7 (Sub) | 数据流 | 当前 count 值参与减法 |
| n4 (Const 1) | n6 (Add) | 数据流 | 加 1 |
| n4 (Const 1) | n7 (Sub) | 数据流 | 减 1 |
| n3 (updown) | n8 (Cond) | 控制流 | 选择加法还是减法 |
| n6 (Add) | n8 (Cond) | 数据流 | 加法结果（候选值 A） |
| n7 (Sub) | n8 (Cond) | 数据流 | 减法结果（候选值 B） |
| n2 (reset) | n9 (Cond) | 控制流 | 选择复位值还是计数值 |
| n5 (Const 0) | n9 (Cond) | 数据流 | 复位值 0 |
| n8 (Cond) | n9 (Cond) | 数据流 | 计数值（来自 updown 选择） |
| n9 (Cond) | n10 (Reg) | 跨周期流 | 下一周期写入寄存器 |

**图结构的关键特征**：

- 有向图，包含环（寄存器→加法器→Cond→寄存器形成跨周期环）
- 三种边类型：数据流（data flow）、控制流（control flow）、跨周期流（inter-cycle flow）
- 32 种节点类型（完整列表见论文 Table 12），频率极度不均衡：Wire 占 40.05%，而 Div 只有 0.01%、Mod 只有 0.00%
- 数据集 13,200 个设计中，CDFG 节点数从 4 到 19,169，多数设计 < 600 节点

**(c) 训练阶段的额外输入**

- **后综合面积标签**：通过 Yosys + ABC 配合 SkyWater 130nm 工艺库综合后提取
- **后综合延迟标签**：同上，取自关键路径延迟
- **PM netlist（用于 KD teacher 训练）**：技术映射后的网表，每个 cell 包含 type、truth table、area、pin delay 信息

### 3.2 中间产物：节点初始嵌入

以上述 counter 的 Add 节点（n6）为例：

```
节点初始嵌入 h0_{Add} = concat(
    one-hot("Add"),     # 32 维 one-hot 向量，第 i 位 = 1 表示节点类型为 Add
    [8]                 # 1 维，位宽信息
)
# 总维度：32 + 1 = 33
```

经过 8 层 GIN 消息传递后，Add 节点的上下文感知嵌入 h^g_{Add} 已经包含了"它的两个操作数是 Reg count 和 Const 1，它的输出流向 Cond 做选择"这些邻居信息。

### 3.3 输出

**(a) 面积预测值**

例如 counter 模块：StructRTL 输出 `log_area_pred = 3.2`，还原后 `area_pred = exp(3.2) ≈ 24.5`（以工艺库面积单位计，如等效门数或平方微米）。

**(b) 延迟预测值**

例如 counter 模块：StructRTL 输出 `log_delay_pred = 1.8`，还原后 `delay_pred = exp(1.8) ≈ 6.05`（以工艺库延迟单位计，如纳秒）。

**(c) 图级结构感知嵌入**

Joint mean + max pooling 后的图级向量，可用于迁移到其他下游任务（如功耗预测、可布线性评估）。

**(d) 工业应用：pairwise 排序**

给定两个功能等价的 RTL 实现（如面积优化版 vs 速度优化版），StructRTL 预测两者的面积/延迟值并排序，输出"实现 A 的面积更小"这类比较结果。

### 4.2 核心模块逐个详解

#### 模块 1：CDFG 构建器

**做什么**：把 Verilog RTL 源码转成 CDFG。

**为什么这样设计**：LLM-based 方法直接读 token 序列，但 token 序列混入了大量语法噪声（`module`、`begin`、`end`、`;`），真正的结构信息（数据从哪来、到哪去、是什么运算）被稀释。CDFG 暴露了三个 LLM 看不到的东西：
1. **节点类型**：Add vs Sub vs Mul —— 不同运算的面积/延迟差异巨大
2. **数据流方向**：操作数 → 运算 → 结果 —— 定义了逻辑深度和关键路径
3. **控制流 vs 数据流分离**：if/else 形成 Cond 节点，控制边指示谁选谁

**实现细节**：
1. Yosys 将 RTL 编译为 RTLIL（中间表示，把所有行为规约到基本赋值和寄存器传输）
2. Stagira Verilog parser 从 RTLIL 生成 AST
3. 遍历 AST 提取 CDFG：每个操作符/寄存器/端口 → 节点；每个赋值关系 → 有向边；寄存器入边 → 跨周期流边（使 CDFG 成为有环图）

**输入/输出**：
- 输入：Verilog `.v` 文件
- 输出：CDFG $G = (V, E)$，32 种节点类型（完整列表见论文 Table 12），3 种边类型

#### 模块 2：节点初始化 + GIN 消息传递

**做什么**：把 CDFG 的节点变成向量，再通过 GNN 的局部消息传递让每个节点"知道"它的邻居是谁。

**为什么这样设计**：一个孤立的 Add 节点不能告诉你任何面积信息——8 位加法和 64 位加法面积差 8 倍。Add 节点的位宽信息来自它的输入边连接的节点。GIN 消息传递让每个节点聚合邻居的嵌入，形成上下文感知表示。

**GIN 消息传递方向**：从邻居节点到中心节点（标准 MPNN 范式）。以 counter 的 Add 节点为例：

```text
   Reg count (n10) ──→ Add (n6) ←── Const 1 (n4)
                     数据流边          数据流边

   消息传递方向: n10 → n6, n4 → n6
   聚合方式: Sum（GIN 的核心设计——求和聚合具有单射性，能区分不同的多集）
```

**GIN 第 k 层的更新规则**（基于 Xu et al. 2019）：

对于节点 v，第 k 层的嵌入更新为：

$$
h^{(k)}_v = \text{MLP}^{(k)}\left( (1 + \varepsilon^{(k)}) \cdot h^{(k-1)}_v + \sum_{u \in \mathcal{N}(v)} h^{(k-1)}_u \right)
$$

- $h^{(k)}_v$：节点 v 在第 k 层的嵌入向量
- $\mathcal{N}(v)$：节点 v 的邻居集合（有向图中为入边邻居）
- $\varepsilon^{(k)}$：可学习的比例参数，控制自身嵌入 vs 邻居嵌入的权重
- $\text{MLP}^{(k)}$：第 k 层的多层感知机（2 层线性 + ReLU）

**Readout / 图级读出**：GIN 输出的节点嵌入 $\{h^g_i\}$ 先送入 Transformer，Transformer 输出 $\{h^t_i\}$ 后，通过 joint mean + max pooling 得到图级表示：

$$
h_G = \text{concat}\left( \frac{1}{|V|} \sum_{i=1}^{|V|} h^t_i,\ \max_{i=1}^{|V|} h^t_i \right)
$$

- $h_G$：图级嵌入向量
- 第一项：Mean Pooling —— 捕获全局平均语义
- 第二项：Max Pooling —— 捕获最显著的特征（对关键路径延迟预测尤其重要）

**为什么是 joint mean + max**：Mean 捕获图的整体特征（对面积预测重要——总面积是所有节点面积之和），Max 捕获极端特征（对延迟预测重要——关键路径的延迟由最深的逻辑链决定）。

**关键参数**：GIN 层数 g=8，Transformer 层数 t=8，每层 4 个注意力头。

#### 模块 3：全局位置编码

**做什么**：给每个节点附加一个位置向量，让 Transformer 知道这些节点在原图中的相对位置。

**为什么这样设计**：Transformer 处理的是节点序列，所有节点被 flatten 成一维——图的连接信息在这一步完全丢失。没有位置编码，两个类型相同的 Wire 节点在 Transformer 看来完全一样，无法区分它们在图中的不同角色。

**计算过程**：

1. 为有向图计算对称归一化拉普拉斯矩阵：

$$
L = I - D_{\text{in}}^{-1/2} \left( \frac{A + A^T}{2} \right) D_{\text{out}}^{-1/2}
$$

- $A$：邻接矩阵
- $D_{\text{in}}$：入度对角矩阵
- $D_{\text{out}}$：出度对角矩阵
- $\frac{A + A^T}{2}$：将有向图对称化（因为标准拉普拉斯需要对称矩阵）

2. 求解特征值分解 $Lx = \lambda x$，取前 $k=16$ 个最小特征值对应的特征向量 $\{x_1, \ldots, x_k\}$

3. 对每个节点 i，位置编码 $p_i$ 由该节点在 k 个特征向量上的分量组成，经线性投影后与 GNN 输出相加：

$$
p_i = \text{LinearProj}\left( [x_{1,i},\ x_{2,i},\ \ldots,\ x_{k,i}] \right)
$$

- $x_{j,i}$：第 j 个特征向量在节点 i 上的分量
- $\text{LinearProj}$：线性投影层，确保维度与 $h^g_i$ 一致

4. **训练时随机翻转特征向量符号**：因为特征向量本身具有符号不确定性（$x$ 和 $-x$ 都是有效的特征向量），随机翻转迫使模型学习符号不变的特征，提高泛化能力。

5. 若节点数 < 16，用 0 补齐。

**输入/输出**：
- 输入：CDFG 的邻接矩阵 A
- 输出：$\{p_i\}$，维度与 $\{h^g_i\}$ 相同

#### 模块 4：两个自监督预训练任务

这两个任务都施加在**post-GNN 嵌入** $\{h^g_i\}$ 上，而非原始 CDFG 节点/边上。这是 StructRTL 的关键设计。

**为什么是 post-GNN 嵌入而非原始图**：如果直接掩码 CDFG 的 Add 节点（比如把 Add 替换成 [MASK]），模型可以把它猜成 Sub、Mul 或其他二元运算——在 token 层面这些都是"合理"的。但如果先跑 GIN 让 Add 节点聚合了"操作数是 Reg count 和 Const 1，结果去 Cond"这些上下文，再掩码——这时模型必须从上下文中推断出"这是一个产生（count+1）的节点，所以它最可能是 Add"。掩码在 post-GNN 嵌入上保护了 CDFG 的功能语义完整性。

**(a) Structure-Aware Masked Node Modeling**

```
操作流程:
  {h^g_i} ──→ 随机选择 20% 节点 ──→ 替换为 [MASK] 嵌入
           ──→ Transformer 编码 ──→ 对被掩码节点做 32 类分类
           ──→ Class-Balanced Focal Loss
```

**分层掩码策略（Algorithm 1）**：普通的随机掩码会导致罕见节点类型（Div、Mod、BitNXor）几乎没有被掩码的机会。分层掩码保证每类至少 $m$ 个节点被掩码：

```
对每个类别 c:
  统计该类已掩码节点数 k
  若 k < m:
    从该类中随机采样 (m-k) 个节点加入掩码集
```

**Class-Balanced Focal Loss（Algorithm 2）**：

$$
\mathcal{L}_{\text{mnm}} = -\frac{1}{N} \sum_{i=1}^{N} w_{c_i} \cdot (1 - p_{t,i})^{\gamma} \cdot \log(p_{t,i})
$$

- $\mathcal{L}_{\text{mnm}}$：masked node modeling 损失
- $N$：批次中被掩码的节点总数
- $c_i$：节点 i 的真实类别
- $w_{c_i}$：类别 $c_i$ 的平衡权重，$w_c = \frac{1-\beta}{1-\beta^{S_c}}$
- $S_c$：类别 c 的训练样本数
- $p_{t,i}$：模型对节点 i 真实类别的预测概率，$p_{t,i} = \exp(-CE(z_i, y_i))$
- $\beta = 0.9999$：控制重加权的平滑参数
- $\gamma = 2.0$：focal loss 的聚焦参数

**张量形状**：
- 输入 $\{h^g_i\}$：$|V| \times d_h$，其中 $d_h$ 为隐藏维度
- Transformer 输出 $\{h^t_i\}$：$|V| \times d_h$
- 分类 logits（对被掩码节点）：$N_{\text{masked}} \times 32$
- 损失值：标量

**(b) Edge Prediction**

```
操作流程:
  {h^t_i} ──→ 采样 20% 真实边 (正样本) + 等量伪边 (负样本)
          ──→ 对每条候选边 (u,v):
              concat(h^t_u, h^t_v) → 3 层 MLP → 二分类 logit
          ──→ Cross-Entropy Loss
```

$$
\mathcal{L}_{\text{ep}} = -\frac{1}{|\mathcal{E}_{\text{sample}}|} \sum_{(u,v,y) \in \mathcal{E}_{\text{sample}}} \left[ y \log(\hat{y}_{uv}) + (1-y) \log(1-\hat{y}_{uv}) \right]
$$

- $\mathcal{L}_{\text{ep}}$：edge prediction 损失
- $\mathcal{E}_{\text{sample}}$：采样的边候选集（20% 真实边 + 等量伪边）
- $y \in \{0, 1\}$：真实标签（1=真实边，0=伪边）
- $\hat{y}_{uv}$：模型预测的边存在概率

**张量形状**：
- 源节点嵌入 $h^t_u$：$d_h$
- 目标节点嵌入 $h^t_v$：$d_h$
- 拼接后：$2d_h$
- 3 层 MLP 输出：1（单 logit，经 sigmoid 得概率）
- 损失值：标量

**预训练总损失**：

$$
\mathcal{L}_{\text{pre}} = \alpha \mathcal{L}_{\text{mnm}} + (1-\alpha) \mathcal{L}_{\text{ep}}
$$

- $\mathcal{L}_{\text{pre}}$：预训练总损失
- $\alpha = 0.5$：两个预训练任务的平衡系数

预训练后验证准确率：masked node modeling 82.27%，edge prediction 95.77%。

#### 模块 5：下游质量估计头

**做什么**：把图级嵌入映射成面积和延迟的标量预测值。

**设计**：
1. Joint mean + max pooling → 图级嵌入 $h_G$
2. 3 层 MLP → log-area 或 log-delay 预测值
3. 对目标值取对数变换（因为面积和延迟的值跨度极大，对数变换使分布更接近正态）

**损失函数（Log-Cosh Loss）**：

论文未给出编号的损失公式，以下是形式化：

$$
\mathcal{L}_{\text{qe}} = \frac{1}{N} \sum_{i=1}^{N} \log\left( \cosh(\hat{y}_i - y_i) \right)
$$

- $\mathcal{L}_{\text{qe}}$：质量估计损失
- $\hat{y}_i$：对数域中的预测值
- $y_i$：对数域中的真实值
- $\cosh(x) = \frac{e^x + e^{-x}}{2}$

**为什么用 log-cosh 而非 MSE**：log-cosh 对小误差近似 MSE（$\log(\cosh(x)) \approx x^2/2$），对大误差近似 MAE（$\log(\cosh(x)) \approx |x| - \log(2)$），因此对离群设计更鲁棒。

#### 模块 6：跨阶段知识蒸馏

**做什么**：用后映射网表（PM netlist）训练的 teacher 预测器指导 CDFG-based student。

**为什么这样设计**：PM netlist 比 RTL/CDFG 更接近最终的物理实现——它已经完成了技术映射，每个 cell 绑定了具体的标准单元型号、面积和 pin delay。基于 PM netlist 的质量估计天然更准（teacher 的 Area R2=0.9334, Delay R2=0.9484）。通过 KD 将这些低层知识"蒸馏"到 student，让 student 从 RTL 阶段就能做出接近 PM 级别的预测。

**Teacher 架构**：
- 输入：PM netlist 的 cell 嵌入 = concat(one-hot(cell type), truth table, area, pin delay)
- 编码器：20 层 GIN（带残差连接）
- 读出：Mean + Max Pooling → 3 层 MLP
- 训练后冻结

**知识蒸馏损失**：

$$
\mathcal{L}_{\text{kd}} = \tau \cdot \mathcal{L}_{\text{cos}}(z^{-1}_{\text{CDFG}},\ z^{-1}_{\text{PM}}) + (1-\tau) \cdot \mathcal{L}_{\text{mse}}(z^{-1}_{\text{CDFG}},\ z^{-1}_{\text{PM}})
$$

- $\mathcal{L}_{\text{kd}}$：知识蒸馏损失
- $z^{-1}_{\text{CDFG}}$：CDFG-based student 的末层激活（MLP 最后一层之前）
- $z^{-1}_{\text{PM}}$：PM-based teacher 的末层激活
- $\mathcal{L}_{\text{cos}}$：余弦相似度损失，$\mathcal{L}_{\text{cos}}(a,b) = 1 - \frac{a \cdot b}{\|a\| \|b\|}$
- $\mathcal{L}_{\text{mse}}$：均方误差，$\mathcal{L}_{\text{mse}}(a,b) = \frac{1}{d} \sum_j (a_j - b_j)^2$
- $\tau = 0.7$：cosine 损失和 MSE 损失的平衡系数

**学生训练总损失**：

$$
\mathcal{L}_{\text{total}} = \mu \mathcal{L}_{\text{qe}} + (1-\mu) \mathcal{L}_{\text{kd}}
$$

- $\mathcal{L}_{\text{total}}$：学生训练总损失
- $\mu = 0.5$：质量估计损失和蒸馏损失的平衡系数

## 5. 关键公式

本节覆盖论文所有编号公式，并补充论文使用但未编号的核心公式。

### 5.1 初始节点嵌入（公式 1）

$$
h^0_i = \text{concat}\left( \text{one-hot}(\text{type}(v_i)),\ \text{width}(v_i) \right)
$$

- $h^0_i$：节点 $v_i$ 的初始嵌入向量，维度 $d_0 = 33$（32 类 one-hot + 1 维位宽）
- $\text{type}(v_i)$：节点类型（Wire、Add、Cond 等 32 类之一）
- $\text{width}(v_i)$：节点位宽（标量，如加法器输入位宽为 8）

**工程直觉**：one-hot 类型告诉模型"这是什么运算"（Add? Mul? Cond?），width 告诉模型"规模多大"（8 位和 64 位加法面积差 8 倍）。两者拼接就是节点初始"身份"。

### 5.2 对称归一化拉普拉斯矩阵（公式 2）

$$
L = I - D_{\text{in}}^{-1/2} \left( \frac{A + A^T}{2} \right) D_{\text{out}}^{-1/2}
$$

- $L$：对称归一化拉普拉斯矩阵，$|V| \times |V|$
- $I$：单位矩阵
- $A$：有向图的邻接矩阵，$A_{uv} = 1$ 表示存在 $u \to v$ 的边
- $D_{\text{in}}$：入度对角矩阵，$(D_{\text{in}})_{ii} = \sum_j A_{ji}$
- $D_{\text{out}}$：出度对角矩阵，$(D_{\text{out}})_{ii} = \sum_j A_{ij}$
- $\frac{A + A^T}{2}$：对称化操作，将有向图转为无向图

**工程直觉**：CDFG 是有向图，但标准拉普拉斯特征分解要求对称矩阵。通过 $(A+A^T)/2$ 做平均对称化后，得到的特征向量编码了图上的"平滑函数"——相邻节点的特征向量分量值相近。最小的 k 个特征值对应的特征向量描述了图的"低频"结构（大尺度社区划分），是有效的全局位置编码。

### 5.3 特征值分解（公式 3）

$$
Lx = \lambda x
$$

- $\lambda$：特征值
- $x$：特征向量

取前 $k=16$ 个最小特征值 $\{\lambda_1, \ldots, \lambda_k\}$ 对应的特征向量 $\{x_1, \ldots, x_k\}$，作为节点位置编码的基。

**为什么取最小的 k 个而非最大的**：小特征值对应图上变化最慢的函数——直观上就是"图的大尺度结构"。大特征值对应高频振荡，噪声成分更多。

### 5.4 GIN 消息传递（论文使用但未编号）

第 k 层 GIN 对节点 v 的嵌入更新：

$$
h^{(k)}_v = \text{MLP}^{(k)}\left( (1 + \varepsilon^{(k)}) \cdot h^{(k-1)}_v + \sum_{u \in \mathcal{N}(v)} h^{(k-1)}_u \right)
$$

- $h^{(k)}_v$：节点 v 在第 k 层的嵌入，$\mathbb{R}^{d_h}$
- $\mathcal{N}(v)$：节点 v 的入边邻居集合
- $\varepsilon^{(k)}$：可学习的自身权重参数，$\mathbb{R}$ 标量
- $\text{MLP}^{(k)}$：第 k 层的 2 层 MLP（Linear + ReLU + Linear）

**聚合方式**：Sum aggregation。GIN 理论证明 sum aggregation 是唯一具有单射性的聚合函数——不同的邻居多集总是映射到不同的聚合结果。Mean/max 聚合无法区分某些多集（如 {2,2} 和 {2} 在 mean 下相同）。

**消息传递方向**：沿 CDFG 的有向边，从源节点流向目标节点。对于 Add 节点，其入边来自 Reg 和 Const 节点 →消息从 Reg/Const 传递到 Add。

### 5.5 预训练总损失（公式 4）

$$
\mathcal{L}_{\text{pre}} = \alpha \mathcal{L}_{\text{mnm}} + (1-\alpha) \mathcal{L}_{\text{ep}}
$$

- $\mathcal{L}_{\text{pre}}$：预训练总损失
- $\mathcal{L}_{\text{mnm}}$：结构感知掩码节点建模损失（class-balanced focal loss）
- $\mathcal{L}_{\text{ep}}$：边预测损失（cross-entropy）
- $\alpha = 0.5$：平衡系数

**张量形状**：$\mathcal{L}_{\text{pre}}$ 是标量。

### 5.6 评估指标（公式 5-8）

**MAE**：

$$
\text{MAE} = \frac{1}{N} \sum_{i=1}^{N} |\hat{y}_i - y_i|
$$

- $\hat{y}_i$：对数域中的预测值
- $y_i$：对数域中的真实标签值
- $N$：验证集样本数

**MAPE**：

$$
\text{MAPE} = \frac{1}{N} \sum_{i=1}^{N} \frac{|\hat{y}_i - y_i|}{y_i}
$$

**R²**：

$$
R^2 = 1 - \frac{\sum_{i=1}^{N} (\hat{y}_i - y_i)^2}{\sum_{i=1}^{N} (y_i - \bar{y})^2}
$$

- $\bar{y} = \frac{1}{N} \sum_{i=1}^{N} y_i$：真实标签的均值

**RRSE**：

$$
\text{RRSE} = \sqrt{ \frac{\sum_{i=1}^{N} (\hat{y}_i - y_i)^2}{\sum_{i=1}^{N} (y_i - \bar{y})^2} }
$$

**工程直觉**：四项指标各有侧重。MAE/MAPE 告诉你"平均差多少"（MAPE 归一化后跨数据集可比），R² 告诉你"预测值解释了多少方差"（0=不解释，1=完美解释），RRSE 告诉你"相对误差"（值越小越好，是 RMSE 的归一化版本）。论文主要看 R²，因为设计空间探索关心的是相对排序而非绝对精度。

### 5.7 知识蒸馏损失（公式 9）

$$
\mathcal{L}_{\text{kd}} = \tau \cdot \mathcal{L}_{\text{cos}}(z^{-1}_{\text{CDFG}},\ z^{-1}_{\text{PM}}) + (1-\tau) \cdot \mathcal{L}_{\text{mse}}(z^{-1}_{\text{CDFG}},\ z^{-1}_{\text{PM}})
$$

- $\mathcal{L}_{\text{kd}}$：知识蒸馏损失
- $z^{-1}_{\text{CDFG}}$：CDFG-based student 的末层激活向量，$\mathbb{R}^{d_z}$
- $z^{-1}_{\text{PM}}$：PM-based teacher 的末层激活向量，$\mathbb{R}^{d_z}$
- $\mathcal{L}_{\text{cos}}(a, b) = 1 - \frac{a \cdot b}{\|a\| \cdot \|b\|}$：余弦相似度损失（方向对齐）
- $\mathcal{L}_{\text{mse}}(a, b) = \frac{1}{d_z} \sum_j (a_j - b_j)^2$：均方误差（幅度对齐）
- $\tau = 0.7$：cosine 损失权重，MSE 权重 = 0.3

**工程直觉**：cosine loss 管"方向对"（两个嵌入在高维空间指向同一个方向），MSE loss 管"大小对"（两个嵌入的值域范围一致）。只用 cosine 可能方向对了但值偏大/偏小，只用 MSE 可能值接近但几何方向不同。两者结合更全面地约束 student 的表示空间。

### 5.8 学生训练总损失（公式 10）

$$
\mathcal{L}_{\text{total}} = \mu \mathcal{L}_{\text{qe}} + (1-\mu) \mathcal{L}_{\text{kd}}
$$

- $\mathcal{L}_{\text{total}}$：学生模型训练总损失
- $\mathcal{L}_{\text{qe}}$：质量估计回归损失（log-cosh）
- $\mathcal{L}_{\text{kd}}$：知识蒸馏损失
- $\mu = 0.5$：平衡系数

**训练流程**：
1. 先训练 PM-based teacher → 冻结
2. 再训练 CDFG-based student = 自监督预训练 + 质量估计 + KD
3. 推理时只保留 CDFG-based student

## 7. 创新点

### 创新点 1：CDFG 结构表示替代 token 序列 —— 让模型"看到"数据流和控制流

**已有方法的做法**：VeriDistill 等 LLM-based 方法把 Verilog 代码当文本序列处理：`module counter(input clk, input reset, ...)` 被 tokenize 成 `["module", "counter", "(", "input", "clk", ...]`。LLM 通过 next-token prediction 预训练学到的隐式结构理解被用于质量估计。

**StructRTL 的做法**：在喂给模型之前，先把 RTL 转成 CDFG —— 一个明确标注了"这是 Add 节点、这条边是数据流、那条边是控制流"的图。结构信息从隐式变成了显式。

**为什么这样更好**：考虑两段功能不同但表面积相似的 RTL：

```verilog
// 设计 A: 全是简单逻辑
assign out = a & b & c & d;

// 设计 B: 有复杂数据通路
assign out = (a + b) * (c - d);
```

在 token 序列中，A 是 `[assign, out, =, a, &, b, &, c, &, d, ;]`，B 是 `[assign, out, =, (, a, +, b, ), *, (, c, -, d, ), ;]`。LLM 从 token 序列推断 A 和 B 的面积差异是间接的（需要从 `+`/`*` token 的上下文模式"猜"这些运算符的含义）。CDFG 直接告诉模型：A 有一条 BitAnd 链（深度 3），B 有 Add + Sub + Mul（深度 2 但含乘法器，面积更大）。延迟预测也类似——CDFG 的关键路径是一目了然的子图，token 序列需要从 token 排列"推理"出关键路径。

**证据**：Delay R² 的提升 (+0.235 vs LLM baseline 最优) 远大于 Area R² 的提升 (+0.111)。延迟比面积对结构更敏感，而 CDFG 显式编码了结构，所以延迟上的增益更大。

### 创新点 2：post-GNN 嵌入上掩码 —— 保护 CDFG 的计算语义

**已有方法的做法**：GraphMAE 直接在原始图的节点特征上做 mask/reconstruct，MaskGAE 在原始边上做 mask/reconstruct。

**问题**：CDFG 不是一般的图。它的节点有严格的功能语义——Add、Sub、Mul 在代数上不可互换。如果直接把 Add 节点替换为 [MASK]，模型可能猜它是 Sub（因为"两个操作数 → 一个结果"的模式类似），从而产生无意义的梯度信号。

**StructRTL 的做法**：先用 GIN 把邻居信息聚合到每个节点（此时 Add 节点的嵌入已经包含了"操作数来自 Reg count 和 Const 1，结果去 Cond"的上下文），再在上下文感知嵌入上掩码。模型被强制从周围未被掩码节点的上下文中推断被掩码节点的类型——这更接近真实的推理过程。

**证据**：架构消融（Appendix E, Figure 7）显示，"input masking"（掩码原始特征）的下游 R² 显著低于 post-GNN masking。这验证了"让 GIN 先聚合上下文信息"对保持学习信号质量的必要性。

### 创新点 3：双预训练任务互补 —— 局部语义 + 全局拓扑

**为什么需要两个任务**：

- **Masked node modeling** 学"这个节点是什么运算"——局部语义信息。不同运算类型的面积代价差异巨大（Mul >> Add >> BitAnd），这对 area prediction 至关重要。
- **Edge prediction** 学"这两个节点连不连"——全局拓扑信息。边的存在模式决定了逻辑深度、reconvergence 路径、关键路径结构，这对 delay prediction 至关重要。

两个任务在不同的层次上提供监督信号，迫使模型同时学习节点的局部角色和图的全局结构。

**证据**：移除 L_mnm 导致 Area R² 从 0.7463 降到 0.7249 (-0.0214)，Delay R² 从 0.7630 降到 0.7473 (-0.0157)。移除 L_ep 导致 Area R² 降到 0.7018 (-0.0445)，Delay R² 降到 0.7368 (-0.0262)。两个任务的移除都导致下降，且 L_ep 的移除对 Area 的伤害更大（说明边的存在模式对推断总面积确实很重要——因为边密度和逻辑深度直接相关）。

### 创新点 4：跨阶段知识蒸馏 —— 用"后端知识"教"前端表示"

**动机**：RTL/CDFG 距离最终的面积/延迟测量点（PM netlist）还隔着逻辑综合和技术映射两步。有些信息（如标准单元的具体面积、映射后的门级结构）在 RTL 阶段是无法获取的。KD 让 student 从 teacher 那里"偷学"这些信息。

**Teacher 的优势**：PM netlist 已经完成了技术映射，每个 cell 都绑定了具体的标准单元，面积和延迟可以直接从 cell 的属性累加/分析得到。所以 teacher 的 R² 可以高达 0.9334/0.9484。

**Student 的收益**：通过让 student 的末层激活逼近 teacher 的末层激活，student 的表示空间被"拉到"更接近 PM 级别的表示。KD 将 Area R² 从 0.7463 提升到 0.8676（+0.1213），将 Delay R² 从 0.7630 提升到 0.8872（+0.1242）。

### 创新点 5：类别不平衡的专门处理 —— 稀有运算也能学到有效表示

**问题**：CDFG 有 32 种节点类型，频率极度不均。Wire 占 40.05%，Cond 占 20.09%，而 Div 只有 0.01%（198 个样本），Mod 只有 0.00%（142 个样本），BitNXor 只有 0.00%（67 个样本）。

**分层掩码**：普通的 20% 随机掩码几乎不会选中 Div/Mod/BitNXor 节点。分层掩码保证每类至少有 m 个节点被掩码，让模型被迫学习这些稀有但关键的算术/逻辑运算符的表示。

**Class-balanced focal loss**：基于有效样本数 $S_c$ 计算类别权重 $w_c = (1-\beta)/(1-\beta^{S_c})$，稀有类获得更高权重。Focal loss 的 $(1-p_t)^\gamma$ 项让模型更关注难分类的样本。

**证据（Appendix D, Table 13）**：移除分层掩码后，总体准确率从 82.27% 微升到 82.44%（因为频繁类的准确率提高），但 Div 从 57.69% 暴跌到 16.67%、Mod 从 61.11% 暴跌到 0.00%、BitNXor 从 100.00% 暴跌到 0.00%。稀有运算节点的表示完全崩溃。这说明分层掩码虽然牺牲了一点点总体准确率，但保护了关键稀有类的表示质量，这对下游质量估计远比总体准确率重要——Div/Mod 的面积远大于 Add/Sub，它们的表示质量直接决定面积预测精度。

### 创新点 6：轻量高效 —— 30M 参数对标 7B

与 LLM baseline 的 7B 参数相比，StructRTL 只有 30M 参数——约 1/233 的参数量。推理速度 0.096 秒/设计 vs 综合 13.97 秒/设计 = 145x 加速。这使它适合嵌入迭代式设计流程：设计师改一行 RTL，StructRTL 0.1 秒后就能告诉 ta 面积和延迟的预估变化，不需要等综合跑完。

## 9. 与芯片流程的关系

### 9.1 在全流程中的位置

```text
  人写 RTL 代码
       │
       ▼
  ┌─────────────────────────────────────────────────┐
  │ ① RTL 设计                                       │
  │                                                  │
  │ StructRTL 在这一步被调用：                         │
  │   输入：刚写完的 .v 文件                           │
  │   输出：预估的 area / delay                       │
  │   耗时：0.096 秒                                  │
  │                                                  │
  │ "如果这个 RTL 综合出来，面积大概 XX，              │
  │  延迟大概 YY"                                    │
  └──────────┬──────────────────────────────────────┘
             │ 设计师根据预估结果修改 RTL
             │ 循环迭代直到满意
             ▼
  ┌─────────────────────────────────────────────────┐
  │ ③ 逻辑综合                                       │
  │                                                  │
  │ 此时才真正跑综合（可以只跑一次，而非每次改 RTL 都跑）│
  │ Yosys + ABC → 门级网表 + area/delay 实测值        │
  └──────────┬──────────────────────────────────────┘
             │
             ▼
    ④ 门级仿真 → ⑤ STA → ⑥ 形式验证 → ... → ⑰ 芯片
```

StructRTL 解决的核心痛点：**RTL 设计 → 综合的反馈循环太慢了**。传统流程中，设计师每改一次 RTL 就要跑一次综合（13.97 秒），一天迭代 100 次就是 23 分钟在等综合。StructRTL 把这个等待从 14 秒压缩到 0.1 秒，让迭代速度从"受计算限制"变成"受思考速度限制"。

### 9.2 StructRTL 预测的"质量"与真实芯片质量之间的差距

StructRTL 预测的是 Yosys + ABC + SkyWater 130nm 下的综合后面积和延迟。这个值和最终芯片的实际面积/延迟之间还隔着：

1. **技术映射差异**：综合时的技术映射选项（面积优先 vs 速度优先）影响最终结果，StructRTL 的标签来自默认映射策略
2. **布局布线影响**：综合后面积不包括走线面积（占芯片面积的 30-50%），综合后延迟不包括走线延迟（在先进工艺中往往 > 门延迟）
3. **时钟树开销**：CTS 引入的缓冲器和走线额外占面积 5-10%，功耗 20-40%
4. **工艺角差异**：SkyWater 130nm 是特定工艺，迁移到其他节点（如 TSMC 7nm、5nm）时面积/延迟分布完全不同
5. **时序模型简化**：综合工具报出的 delay 是粗略估计，signoff STA 使用了更精确的时序模型和 SPEF 反标

因此，StructRTL 更适合**相对比较**（"方案 A 比方案 B 的延迟小约 15%"）而非**绝对估计**（"方案 A 的面积是 0.573 mm²"）。论文在工业评估中使用了 pairwise ranking（82.35%/88.23% 准确率）而非绝对值预测，也印证了这一设计定位。

## 10. 讨论与局限

### 10.1 论文自述的局限

1. **大规模设计性能下降**：设计规模和复杂度增加时，预测精度下降，且显存/计算成本上升（20,000 节点需要 ~52 GB 显存）。
2. **时序电路表现弱于组合电路**：combinational vs sequential 的性能差异在 delay 预测上更明显（有 KD 时：Delay R² 0.9002 vs 0.8681），因为跨周期数据流和状态行为更难从静态 CDFG 推断。
3. **跨工艺节点迁移挑战**：后综合面积/延迟分布随工艺节点显著变化，开发跨节点的通用估计器仍是开放问题。
4. **依赖综合工具链获取标签**：训练需要完整的 Yosys + ABC + 工艺库合成流程，数据构建成本较高。

### 10.2 代码/复现层面的问题

1. **仓库成熟度**：官方代码已开源（https://github.com/cure-lab/StructRTL），但核验时提交较少且未检测到仓库级 LICENSE 文件。
2. **训练成本**：主模型在 L40 GPU 上需要约 40 小时训练，峰值显存约 42 GB。batch size 可缩减以适配更小显存的 GPU，但会增加训练时间。
3. **数据预处理复杂**：CDFG 提取需要 Yosys + Stagira parser + 自定义 AST 遍历脚本，环境配置有一定门槛。

### 10.3 本资料包的批判性分析

**(a) CDFG 是静态图，无法捕捉电路的动态行为**

CDFG 编码了数据流和控制流的静态结构，但它不编码：
- 信号的时序波形（哪个信号先变、哪个后变）
- 组合逻辑的毛刺行为（glitch propagation）
- 跨时钟域（CDC）的亚稳态风险
- 状态机的可达状态和死锁

这些动态特性会影响真实芯片的 delay（毛刺增加有效逻辑深度）和面积（CDC 需要额外的同步器），但 CDFG 完全无法表示。StructRTL 在 sequential circuits 上的性能下降（Appendix G）可能部分源于此。

**(b) 自监督预训练任务与下游任务的错位**

Masked node modeling 训练模型预测"这个被掩码的节点是什么类型"，但下游质量估计需要的是"这个 CDFG 综合出来的面积和延迟大概多少"。虽然预训练学到了有用的结构表示，但预训练目标（节点分类）和下游目标（图级回归）之间存在一个 gap——模型在预训练时从未被要求关注"哪些结构特征影响面积/延迟"，它只是被动地学到了 CDFG 的一般结构模式。这可能解释了为什么 StructRTL 需要 13,200 个设计做预训练——如果预训练任务和下游任务的对齐度更高，也许可以用更少的数据。

**(c) 评估体系的局限**

- 面积和延迟来自 Yosys + SkyWater 130nm，这是一个特定的开源工艺和工具链。切换到商业工具（Design Compiler）和其他工艺节点（TSMC 28nm/7nm/5nm）时，排序和绝对值可能变化。
- 论文主要强调 R² 指标，但 R² 对离群值敏感。在 13,200 个设计中，少数超大设计可能主导 R² 的变化。MAE 和 MAPE 的值在各表中也报告了（如 0.3649 和 0.06），但论文没有给出按设计规模分层的详细 MAE/R²。
- Pairwise ranking 的 82.35%/88.23% 是在 51 对设计上的结果，样本量较小，统计显著性有限。

**(d) 与 LLM-based 方法对比的公平性**

StructRTL 的参数量（30M）远小于 LLM baseline（7B），但 LLM baseline 的表示是通过 next-token prediction 在大量代码语料上预训练得到的——这些 LLM 的预训练数据量和成本远高于 StructRTL。从"总资源投入"的角度看，StructRTL 用更少的参数和更少的预训练数据（13,200 个 CDFG vs LLM 的数万亿 token）实现了更好的性能——这是结构归纳偏置（CDFG 显式编码结构信息）胜过数据规模偏置的实例。

但另一方面，论文没有报告 fine-tune LLM 做 quality estimation 的结果（Appendix K 展示了尝试，但 fine-tune 导致严重过拟合——训练集 R²=0.9915 验证集 R²=0.2685）。这暗示 13,200 个设计对于 fine-tune 7B LLM 来说是不够的，但对于 30M 的 GNN+Transformer 来说是足够的——更小的模型 + 更强的结构先验 = 在有限数据下的更好泛化。

**(e) 预训练任务验证准确率的相对性**

Masked node modeling 验证准确率 82.27% 看起来不错，但需要注意这包含严重的类别不平衡。Wire（40.05%）准确率 89.67%，Cond（20.09%）准确率 88.91%，这两类就贡献了超过一半的"正确"预测。而 Div 的准确率只有 57.69%，Mod 只有 61.11%，BitNXor 虽然 100% 但只有 67 个样本。虽然分层掩码缓解了不平衡，但稀有类的表示质量仍然不够好——而稀有类（Div、Mul）恰恰是面积贡献大的运算。

**(f) 知识蒸馏的双刃剑**

KD 显著提升了 StructRTL 的性能（Area R² 从 0.7463 到 0.8676），但这也是 StructRTL 训练成本的主要来源——需要额外训练一个 20 层 GIN teacher，并且需要为每个设计生成 PM netlist（即跑完整的综合+技术映射）。对于资源受限的环境，无 KD 的 StructRTL（Area R²=0.7463）已经比所有 baseline 好，是一个更实际的选择。

## 12. 一分钟复述版

StructRTL（ICML 2026，CUHK + 华为诺亚）不把 RTL 当 token 序列交给 LLM 处理，而是先转成**控制数据流图（CDFG）**——一个有 32 种节点类型（Add、Wire、Cond 等）和 3 种边类型（数据流/控制流/跨周期流）的有向有环图。通过 **8 层 GIN + 8 层 Transformer（4 头） + 拉普拉斯位置编码**学习结构感知的图嵌入。

核心机制是两个**自监督预训练任务**，都施加在 post-GNN 嵌入上（而非原始图）以保护 CDFG 的计算语义：**(1) Structure-aware masked node modeling** —— 掩码 20% 的 GNN 输出节点嵌入，用 Transformer 预测原始节点类型（32 类分类），配合分层掩码 + class-balanced focal loss 处理严重的类别不平衡；**(2) Edge prediction** —— 20% 真实边 + 等量伪边做二分类，学习全局拓扑结构。预训练总损失：$\mathcal{L}_{\text{pre}} = 0.5\mathcal{L}_{\text{mnm}} + 0.5\mathcal{L}_{\text{ep}}$。

下游质量估计：joint mean/max pooling → 3 层 MLP → log-area/delay 预测（log-cosh loss）。**跨阶段知识蒸馏**：从 PM netlist 训练一个 20 层 GIN teacher（Area R²=0.9334），将其末层激活通过 cosine + MSE 混合损失迁移到 student，把 Area R² 从 0.7463 推到 0.8676。

结果：13,200 设计 benchmark，Area R²=0.7463（无 KD）/ 0.8676（有 KD），Delay R²=0.7630/0.8872——全面超越 Graph-XGBoost、Graph-GNN 和 7B LLM baseline（最优 LLM 的 Area R²=0.6353）。**Delay 上的提升（+0.235 vs LLM）远超 Area（+0.111）**，因为延迟高度依赖关键路径结构，而 CDFG 显式编码了这些结构。推理 0.096 秒/设计 vs 综合 13.97 秒 = 145x 加速，30M 参数（7B LLM 的 1/233）。

**边界**：只覆盖 ①→③（2/17），不涉及物理实现（布局布线/时钟树/DRC），面积/延迟来自特定工艺（SkyWater 130nm）和工具链（Yosys+ABC），KD teacher 需要综合+映射数据（训练时仍需跑完整 ③），跨工艺节点泛化未解决，大规模设计（>20,000 节点）需要寄存器边界分区策略辅助。
