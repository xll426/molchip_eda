## 1. 一句话定位

**AlphaRoute 是首个把 LLM 真正塞进"全局布线（R&R）闭环"作为"语义策略优化器"的 VLSI 物理设计框架：用 SHAP 风格的"逐 net"拥塞归因把拥塞分解到具体的 net 上、用 3D Dijkstra 迷宫布线和自适应 PathFinder 策略做核心求解、再用 LLM 接收结构化 SHAP 拥塞指标动态调整历史惩罚增长率 alpha、当前惩罚权重 pf、Via 成本 wvia、最后用 RustworkX 知识图谱对 LLM 的提案做硬约束校验——在 ISPD 2025 基准上把 ARIANE 的 overflow 从 1,517,789 砍到 146,109（29.8 倍降低），把 S_orig 从 1.780 拉到 0.0538（33.1 倍降低），把 MEMPOOL 的 overflow 砍 98.6%。**

这句话里的七个技术承重点：

1. **"全局布线是 NP-hard"的真实战场**——现代 SoC 在 10+ 金属层、百万级 GCell 网格上布线；拥塞是高度非局部的"雪崩式"传播，单个过订阅通道会迫使远端绕路，经典 PathFinder 用静态 penalty schedule 抓不到这种"特定拥塞拓扑"
2. **SHAP 风格 overflow 分解**——受 SHAP（SHapley Additive exPlanations）启发的"置换重要性"分析器把整体拥塞归因到每根 net、每层、每个利用率-拥塞相关性上，让 rip-up 不再靠粗糙启发式而是"按 net 对拥塞的贡献排序"
3. **Slack 感知的 net 排序 + 三段式初始布线**——按 bounding-box area 优先（net 越大越先布），并把 slack（最负时序裕量）作为同面积 net 的决胜因素；小 net 走 Steiner tree，大 net 走 Prim MST + 灵活 L-routing（h-first / v-first），动态选层，初始 overflow 即降 2.2×（ARIANE 从 2,239,467 降到 1,029,699）
4. **3D Dijkstra 迷宫重布 + 自适应 PathFinder**——中等面积 net 在 bounding-box 局部 subgraph 上做代价感知 Dijkstra 搜索绕开拥塞热点；PathFinder 引入 SHAP 驱动的三个规则自动调整 α、pf、wvia，α 还按 1.15× 自动递增
5. **LLM 作为"语义策略优化器"（非评估器）**——LLM 接收 7 个字段的结构化 SHAP 指标，返回 JSON 形式的 parameter 更新 + 自然语言推理；三种 Llama 系模型（Llama 3.2 3B 本地 Ollama、Llama 3.3 70B、GPT-OSS 120B 通过 Groq API）皆可，证明 policy 层对同架构 LLM 变体不敏感
6. **RustworkX 知识图谱硬约束校验**——LLM 输出在应用前必须过 KG 的硬约束检查（Pattern / Strategy / Outcome 三类节点，记录 net 大小、主导层、α、pf、wvia、ΔΩ），LLM 不被允许越过物理边界直接改 wire
7. **纯 Python 实现 + ISPD 2025 四基准**——ARIANE（10 层 646×646 网格，105,924 net）、BSG（10 层 1384×1384，768,239 net）、MEMPOOL（10 层 1120×1120，157,744 net）、NVDLA（10 层 386×386，135,814 net）；承认 wall-clock 比 C++ 高 ~136× 但 S_orig 仍优于 SOTA

## 2. EDA 阶段映射（①-⑰）

参照 [芯片流程.md](../芯片流程.md) 的 17 阶段标准编号：

| 阶段 | 覆盖 | 说明 |
|------|:---:|------|
| **① RTL 设计** | ❌ | AlphaRoute 不接受 RTL 输入，吃的是 ISPD `.cap + .net` 格式（place 之后的物理 netlist + 容量约束）。RTL 阶段不在作用域。 |
| ② RTL 功能仿真 | ❌ | 不跑仿真。 |
| ③ 逻辑综合 | ❌ | 不做综合。 |
| ④ 门级仿真 | ❌ | 不跑门级仿真。 |
| ⑤ STA | ⚠️ **间接相关** | Slack（最负时序裕量）作为 net criticality σn = max(0, 1 − sn/smin) 进入初始 edge weight，但 AlphaRoute 不跑 STA，只是把 slack 当排序信号。 |
| **⑥ 形式验证** | ❌ | — |
| ⑦ 布局（Placement） | ⚠️ **前置输入** | 输入是已 placement 的 .net（pin locations / GCell access points）。AlphaRoute 不做 placement，但假设上游已做完 placement。 |
| **⑧ 布线规划（Routing Planning）** | ❌ | 不做 routing planning。 |
| **⑨ 全局布线（Global Routing）** | ✅ **核心** | AlphaRoute 全部工作集中在这一阶段——初始 Steiner/MST + L-routing、SHAP overflow 分析、rip-up/reroute、3D Dijkstra maze、LLM 策略调整、知识图谱校验。 |
| ⑩ 详细布线（Detailed Routing） | ❌ | 不做 detailed routing。 |
| ⑪ 时钟树综合（CTS） | ❌ | — |
| ⑫ ECO / 后优化 | ❌ | — |
| ⑬ 签核（Signoff） | ❌ | 不跑 signoff。 |
| ⑭-⑰ 流片→制造→封装→芯片 | ❌ | 纯算法工作，无 tape-out。 |

**覆盖率：1/17 核心。** AlphaRoute 是 **全局布线阶段（⑨）** 的纯算法改进，叠加 SHAP 可解释性 + LLM 语义策略优化 + 知识图谱安全约束。

> ⚠️ AlphaRoute 与 [DeepGate](../DeepGate/论文深度讲解.md) / [FuncGNN](../FuncGNN/论文深度讲解.md) / [DeepGate4](../DeepGate4/论文深度讲解.md) 等 AIG/网表表示学习工作的根本边界是 **EDA 阶段不同**：
> - DeepGate/FuncGNN/DeepGate4 在逻辑综合阶段（③）的门级 netlist 上做表示学习
> - **AlphaRoute 在布线阶段（⑨）的 GCell 网格上做 R&R 闭环**
>
> 这两类工作几乎不重叠：前者解决"逻辑门属性预测"，后者解决"信号 net 在物理网格上的路径分配"。

## 3. 输入 / 输出

### 3.1 输入

AlphaRoute 接收两个 ISPD 2025 contest 标准文件：

**(a) `.cap` 文件（容量定义）**

定义每个 GCell 在每个金属层的路由容量 $C \in \mathbb{R}^{N_L \times y_{\max} \times x_{\max}}$、层成本和评分权重：

```text
# ARIANE .cap 节选示意（10 layers, 646x646 grid）
# 格式：layer, ymin, ymax, xmin, xmax, capacity, layer_cost
metal1   0 645 0 645  10  2
metal2   0 645 0 645  10  2
metal3   0 645 0 645   8  3
metal4   0 645 0 645   8  3
metal5   0 645 0 645   6  4
metal6   0 645 0 645   6  4
metal7   0 645 0 645   4  6
metal8   0 645 0 645   4  6
metal9   0 645 0 645   4  8
metal10  0 645 0 645   4  8
# metal1 = via-only layer
```

**(b) `.net` 文件（net 定义）**

列出每根 net 的 pin 位置、GCell 接入点、pre-routing slack 估计：

```text
# ARIANE .net 节选示意
net001  5
  pin0  clk  INPUT   100 200  0.85
  pin1  a    INPUT   105 205  0.92
  pin2  b    INPUT   105 215  0.91
  pin3  out  OUTPUT  110 210  0.40
  pin4  rst  INPUT   100 220  0.95
#
net002  3
  pin0  data  BIDIR  50 60  0.50
  pin1  q     BIDIR  52 62  0.55
  pin2  en    INPUT  48 58  0.99
```

每行最后的数字是 pre-routing slack 归一化值，用于计算 criticality $\sigma_n$。

**(c) Slack + Criticality 推导**

对每根 net $n$，从其所有 pin 的 slack 取最差的（最负）值 $s_n$，归一化为 criticality：

$$
\sigma_n = \max\left(0, 1 - \frac{s_n}{s_{\min}}\right)
$$

其中 $s_{\min}$ 是全设计中 slack 最负的 net 的值。$\sigma_n = 1$ 表示该 net 是最关键的，$\sigma_n = 0$ 表示无时序约束。

### 3.2 中间产物

**(a) 加权 3D 网格图（RustworkX Graph）**

每个 GCell $g = (z, y, x)$ 映射到一个图节点：

$$
\text{idx}(z, y, x) = z \cdot Y_{\max} \cdot X_{\max} + y \cdot X_{\max} + x
$$

边的含义：
- 水平层 $(x, y, z) \leftrightarrow (x \pm 1, y, z)$
- 垂直层 $(x, y, z) \leftrightarrow (x, y \pm 1, z)$
- Via $(x, y, z) \leftrightarrow (x, y, z \pm 1)$（$z > 0$，固定 cost = 40）

初始 edge weight：

$$
W(e) = (10.0 - 3.0 \cdot \sigma_n) + (11 - c_{z,u}) + (11 - c_{z,v})
$$

**(b) R&R 闭环中的两类中间状态**

- `h^(k)(e)`：第 $k$ 次迭代累积的历史 cost 数组
- `ψ_n`：第 $k$ 次迭代 net $n$ 的 overflow score
- `(α^(k), pf^(k), w_via^(k))`：第 $k$ 次迭代的 PathFinder 标量参数
- KG 中的 `(Pattern, Strategy, Outcome)` 三元组

**(c) LLM 输入的 7 字段 SHAP 结构化 prompt**

```text
INPUT: Routing iteration 1 metrics:
- Overflow (L2): 258,229
- Overflow delta from init: +0.0%
- Congested cells: 1.15% of grid
- Util-overflow correlation: 0.237
- Top layer overflow: 50.1%
- Current alpha: 0.4000
- Current present factor: 2.000
- Current via cost: 40.0
- Vias ripped this iteration: 0
```

LLM 输出的 JSON：

```json
{
  "path_action": "INCREASE",
  "pf_action": "INCREASE",
  "via_action": "DECREASE",
  "alpha_value": 0.8,
  "pf_value": 4.0,
  "via_value": 30.0,
  "reasoning": "High overflow, concentrated congestion, and high top layer overflow indicate need for stronger penalties and via cost reduction to spread routing demand."
}
```

### 3.3 输出

**(a) 全局布线结果 `.route` 文件**

按 ISPD contest 规范的布线结果文件，列出每根 net 的 GCell 序列、使用的金属层、via 位置。

**(b) S_orig / Sscaled 评分**

按 ISPD 2025 contest 评分公式：

$$
S_{\text{orig}} = S_{\text{overflow}} + S_{\text{length}} + S_{\text{via}}
$$

AlphaRoute 在 ARIANE 上达到 $\mathbf{S_{\text{orig}} = 0.0538}$（vs SOTA $\mathbf{1.780}$，**33.1 倍降低**）和 $\mathbf{S_{\text{scaled}} = 0.0589}$（vs SOTA $\mathbf{1.74}$，**29.5 倍降低**）。

**(c) 拥塞分解报告**

每根 net 的 overflow score $\psi_n$、每层拥塞比例 $\lambda_z$、利用率-拥塞相关性 $r_{uo}$、拥塞 cell 占比 $f_c$——这些既是给 LLM 的输入也是给设计师的诊断信号。

### 4.1 整体 Pipeline

### 4.2 模块 1：输入解析 + 3D 加权图构建（III-A）

#### 4.2.1 输入 .cap 解析

读 `.cap` 文件，构造一个三维数组 $C \in \mathbb{R}^{N_L \times y_{\max} \times x_{\max}}$：
- $N_L$ 是金属层数（ARIANE = 10，metal1 是 via-only）
- $y_{\max}, x_{\max}$ 是网格尺寸（ARIANE = 646 × 646）

#### 4.2.2 输入 .net 解析

读 `.net` 文件，对每根 net $n$ 存：
- pin 列表 $\{p_1, p_2, ..., p_{k_n}\}$，每个 pin 有 $(x_p, y_p, z_p)$ 坐标
- pre-routing slack 列表 $\{s_{p_1}, ..., s_{p_{k_n}}\}$
- 计算该 net 的 criticality：$\sigma_n = \max(0, 1 - s_n / s_{\min})$

#### 4.2.3 3D 网格图构建

用 RustworkX 建图，每个 GCell 是一个节点，节点索引如 §3.2(a) 所述。

边的类型：
- **水平边**：连接 $(x, y, z)$ 和 $(x \pm 1, y, z)$
- **垂直边**：连接 $(x, y, z)$ 和 $(x, y \pm 1, z)$
- **Via 边**：连接 $(x, y, z)$ 和 $(x, y, z \pm 1)$，$z > 0$，固定 cost = 40

初始 edge weight $W(e)$：

$$
W(e) = (10.0 - 3.0 \cdot \sigma_n) + (11 - c_{z,u}) + (11 - c_{z,v})
$$

- 第一项反映 net criticality：critical net 拿 30% 折扣
- 后两项反映两个端点 GCell 的剩余容量：empty cell（$c=10$）只加 1，fully congested cell（$c=0$）加 11

### 4.3 模块 2：Slack 感知的 net 排序（III-B）

排序键为：

```
1) bounding-box area An = (xmax - xmin + 1) * (ymax - ymin + 1)
2) worst pin slack sn among same-area nets (越小越先)
3) trivial single-GCell nets last
```

**为什么 area 优先于 criticality？** 大 net 用完主干 channel 后，小 net 只能在剩余 channel 选路；如果先布小 net 抢了关键 channel，大 net 之后只能绕路——引发二次拥塞。criticality 用于同面积 net 内的 tie-break。

**为什么 criticality 用于 tie-break？** 时序紧的 net 需要最短、最不电阻的路径（"$30\%$ 折扣"），否则 timing violation 会传导到下游 signoff。

### 4.4 模块 3：初始布线策略选择（III-C）

按 bounding-box area $A_n$ 分三档：

| Net 面积 | 布线策略 | 实现 |
|---------|---------|------|
| $A_n \leq 2{,}500$ | Steiner tree | RustworkX 内置 Steiner tree 最小化总 wire |
| $2{,}500 < A_n \leq 15{,}000$ | MST + flex L-route（初布时） | Manhattan distance 权重 = Manhattan + 40·via 数 |
| $A_n > 15{,}000$ | MST + flex L-route（初布时） | 同上 |

**Manhattan distance 权重中的 40 = via 成本**，抑制不必要的层切换。

**flex L-shape** 对每对 2-pin 用 dual evaluation：
- H-first：先横后纵
- V-first：先纵后横
- 选拥塞代价 $\Omega(\text{path}) = \sum_{(z,y,x) \in \text{path}} \max(0, -c_{z,y,x})$ 更小的

**动态层选择**：对每段水平段，选 $z^* = \arg\max_z \bar{c}_z$（沿该段 GCell 范围内平均剩余容量最大的层）。

这一步把 ARIANE 的初始 overflow 从 2,239,467 降到 1,029,699（**2.2× 降低**）。

### 4.5 模块 4：SHAP Overflow Analyzer（III-D）

这是 AlphaRoute 把"启发式"升级到"可解释归因"的关键模块。受 SHAP 启发的置换重要性分析器（不调用外部 SHAP 库，在 4.17M-cell 网格上 < 0.1s 完成）输出四个指标。

#### 4.5.1 Per-net overflow score $\psi_n$（Eq. 3）

$$
\psi_n = \sum_{(z,y,x) \in \mathcal{G}_n} \max(0, -c_{z,y,x})
$$

$\mathcal{G}_n$ 是 net $n$ 占据的 GCell 集合。$\Omega \leq \sum_n \psi_n$ 因为不同 net 可能共享同一过载 GCell。**Top 20% $\psi_n$ 的 net 被 rip up。**

#### 4.5.2 Layer-wise overflow decomposition $\lambda_z$（Eq. 4）

$$
\lambda_z = \frac{\sum_{y,x} \max(0, -c_{z,y,x})}{\sum_{z,y,x} \max(0, -c_{z,y,x})}
$$

主导层 $z^* = \arg\max_z \lambda_z$ 被传给 LLM。若某一层过载 > 50%，触发 SHAP 规则 `λ_{z*} > 0.50 → Decrease via cost`（表 I）。

#### 4.5.3 Congested cell fraction $f_c$（Eq. 5）

$$
f_c = \frac{|\{(z,y,x) : c_{z,y,x} < 0\}|}{N_L \cdot y_{\max} \cdot x_{\max}}
$$

$f_c < 0.02$ 触发 `Increase pf` 规则（表 I）。

#### 4.5.4 Utilization-overflow correlation $r_{uo}$（Eq. 6）

Cell utilization 定义为 $u_{z,y,x} = 1 - c_{z,y,x} / c^{(0)}_{z,y,x}$，其中 $c^{(0)}_{z,y,x}$ 是 .cap 文件中的原始容量。

$$
r_{uo} = \frac{\mathrm{Cov}(u, \max(0, -c))}{\sigma_u \cdot \sigma_{\max(0,-c)}}
$$

$r_{uo} > 0.5$ 表示 cell 利用率能可靠预测过载，**拥塞是 demand-driven**（加 α 能缓解）；$r_{uo} \leq 0.5$ 表示拥塞是 **structurally driven**（被 macro blockage 等结构原因卡住，加 α 无效）。

### 4.6 模块 5：LLM Log Analyzer（III-E）

#### 4.6.1 Prompt 结构

LLM 接收 7 字段结构化指标：

```text
INPUT: Routing iteration k metrics:
- Overflow (L2): Ω_{L2}
- Overflow delta from init: ΔΩ
- Congested cells: f_c of grid
- Util-overflow correlation: r_uo
- Top layer overflow: 100 * λ_{z*}
- Current alpha: α^(k-1)
- Current present factor: pf^(k-1)
- Current via cost: w_via^(k-1)
- Vias ripped this iteration: <count>
```

#### 4.6.2 LLM 输出 schema（JSON）

```json
{
  "path_action": "INCREASE" | "DECREASE" | "MAINTAIN",
  "pf_action":   "INCREASE" | "DECREASE" | "MAINTAIN",
  "via_action":  "INCREASE" | "DECREASE" | "MAINTAIN",
  "alpha_value": <float in [0.1, 2.0]>,
  "pf_value":    <float in [0.5, 8.0]>,
  "via_value":   <float in [20, 80]>,
  "reasoning":   "<one-sentence natural language justification>"
}
```

#### 4.6.3 LLM 后端与 model-agnostic 证据

| 后端 | 模型 | 用途 |
|------|------|------|
| Ollama（本地） | Llama 3.2 3B | 默认本地推理 |
| Groq API | Llama 3.3 70B Versatile 128k | A7 ablation |
| Groq API | GPT-OSS 120B 128k | A8 ablation |

三家的 WNS / TNS 差异在统计上无意义——policy 层在三种 Llama 系变体之间表现一致。

### 4.7 模块 6：Knowledge Graph（III-I）

KG 是用 RustworkX 实现的图，记录所有 R&R 迭代中的 `(Pattern, Strategy, Outcome)` 三元组：

- **Pattern 节点**：net size（small / medium / large）、dominant layer $z^*$、overflow level $\lambda_{z^*}$
- **Strategy 节点**：routing algorithm（Steiner / MST / Dijkstra）、policy 参数 $(\alpha^{(k)}, pf^{(k)}, w_{via}^{(k)})$
- **Outcome 节点**：$\Delta\Omega = \Omega^{(k)} - \Omega^{(k-1)}$

KG 的作用是 **硬约束校验 + 历史检索**：LLM 的 proposal 必须满足：
1. 参数值在允许区间（$\alpha \in [0.1, 2.0]$, $pf \in [0.5, 8.0]$, $w_{via} \in [20, 80]$）
2. 同一 Pattern 上次使用的 Strategy 不能连续两次超过 $\Delta\Omega > 0$（防止震荡）
3. 若 KG 中有历史 Pattern 完全匹配的 Strategy 且 $\Delta\Omega < 0$，优先复用

**若 LLM 输出违反硬约束 → 回退到表 I 的 SHAP 自适应规则**——这保证 R&R 闭环的稳定性。

### 4.8 模块 7：Adaptive PathFinder Policy（III-F）

#### 4.8.1 历史 cost 更新（Eq. 7）

$$
h^{(k+1)}(e) = h^{(k)}(e) + \alpha^{(k)} \cdot \max(0, -c_e)
$$

$c_e = \min(c_{z,y_1,x_1}, c_{z,y_2,x_2})$ 是 edge 两端最小剩余容量。

#### 4.8.2 重路由 edge cost（Eq. 8）

$$
\mathrm{cost}(e) = W(e) + h^{(k)}(e) + pf \cdot \max(0, -c_e)
$$

三项对应：基础容量加权 cost、累积历史惩罚、当前拥塞惩罚。

#### 4.8.3 α 自动递增

$$
\alpha^{(k+1)} = \alpha^{(k)} \times 1.15
$$

即使 LLM 不调整 α，历史惩罚也会逐迭代增长，确保"上次拥塞的 channel 这次更贵"。

#### 4.8.4 SHAP 驱动的三条自适应规则（表 I）

| SHAP 信号 | 条件 | 策略动作 |
|----------|------|---------|
| Congested cell fraction | $f_c < 0.02$ | Increase $pf$（仅低密度拥塞：放大当前惩罚） |
| Util-overflow correlation | $r_{uo} > 0.5$ | Increase $\alpha$（demand-driven 可历史化） |
| Layer concentration | $\lambda_{z^*} > 0.50$ | Decrease $w_{via}$（强制分散到其他金属层） |

### 4.9 模块 8：Rip-Up 候选选择（III-G）

$$
R^{(k)} = \{n \in N : \psi_n \geq \psi_{\lfloor(1-\rho)|N|\rfloor}\}, \quad \rho = 0.20
$$

- 取 net set $N$ 中 $\psi_n > 0$ 的部分
- 按 $\psi_n$ 降序排序
- 取 top 20%

被 rip 的 net 占用容量在下一轮 R&R 开始前被恢复（"释放 cell"），然后 Dijkstra 重新计算最不拥塞路径，同时把被 rip 的 net 的路由需求累计到其通过的每个 GCell。

### 4.10 模块 9：3D Dijkstra 迷宫重布（III-H）

对 $2{,}500 < A_n \leq 15{,}000$ 的中等面积 net：

1. 在其 bounding-box 周围加 **margin $\delta = 2$** GCells，构造局部 subgraph
2. subgraph 上每条 edge 的 cost 用 Eq. 8（含 $W(e), h^{(k)}(e), pf \cdot \max(0, -c_e)$）
3. 用 Dijkstra 找源到目标的 shortest path
4. 路径会 **绕过局部拥塞热点**，因为 hot cell 上 Dijkstra 的 cost 远高于 cold cell

小 net（$\leq 2{,}500$）继续保持 Steiner；大 net（$> 15{,}000$）继续保持 MST + Flex-L。

### 4.11 模块职责矩阵

| 模块 | 输入 | 输出 | 工具/模型 | 是否需训练 |
|------|------|------|---------|-----------|
| 输入解析 (.cap / .net) | ISPD .cap + .net 文件 | 加权 3D RustworkX 图 | Python + RustworkX | ❌ |
| Slack-aware 排序 | net 列表 + slack | 排序后的 net 序 | 纯 Python | ❌ |
| 初始 Steiner | net + graph | Steiner tree | RustworkX.Steiner | ❌ |
| 初始 MST + Flex-L | net + graph | 2-pin L-route 序列 | Prim MST 变种 | ❌ |
| SHAP analyzer | routing 状态（post-initial） | ψ_n / λ_z / f_c / r_uo | 自实现 permutation importance | ❌ |
| LLM policy proposal | 7 字段 SHAP 指标 | JSON {α, pf, w_via, reasoning} | Ollama Llama-3.2-3B / Groq Llama-3.3-70B / Groq GPT-OSS-120B | 黑盒 API |
| Knowledge graph | Pattern, Strategy, Outcome | 硬约束校验 / 历史检索 | RustworkX | ❌ |

## 5. 关键公式

### 5.1 Edge 初始 weight

$$
W(e) = (10.0 - 3.0 \cdot \sigma_n) + (11 - c_{z,u}) + (11 - c_{z,v})
$$

- $\sigma_n$：net $n$ 的 criticality，$\sigma_n \in [0, 1]$，越大越关键
- $c_{z,u}, c_{z,v}$：edge 两端 GCell 在 layer $z$ 的剩余容量，$c \in [0, 10]$，越大越空

**工程直觉**：$\sigma_n = 1$（最关键 net）$W(e)$ 的第一项 = 7.0（30% 折扣），而 $\sigma_n = 0$ 时 = 10.0。空闲 cell（$c=10$）贡献 1，满载 cell（$c=0$）贡献 11——空 cell 比满 cell 便宜 11 倍。

### 5.2 Overflow 定义

$$
\Omega = \sum_{z,y,x} \max(0, -c_{z,y,x})
$$

- $c_{z,y,x}$：$(z,y,x)$ 这个 GCell 在 layer $z$ 的剩余容量（可为负）
- $\max(0, -c_{z,y,x})$：过载量（demand 超 capacity 的部分）

$\Omega = 0$ 即 routing 完美，没有任何过载 GCell。

### 5.3 Per-net overflow score

$$
\psi_n = \sum_{(z,y,x) \in \mathcal{G}_n} \max(0, -c_{z,y,x})
$$

- $\mathcal{G}_n$：net $n$ 占据的所有 GCell
- $\Omega \leq \sum_n \psi_n$（不同 net 可共享过载 cell）

### 5.4 Layer-wise overflow fraction

$$
\lambda_z = \frac{\sum_{y,x} \max(0, -c_{z,y,x})}{\sum_{z,y,x} \max(0, -c_{z,y,x})}
$$

主导层 $z^* = \arg\max_z \lambda_z$。

### 5.5 Congested cell fraction

$$
f_c = \frac{|\{(z,y,x) : c_{z,y,x} < 0\}|}{N_L \cdot y_{\max} \cdot x_{\max}}
$$

$f_c$ 越高，全网格拥塞密度越大。

### 5.6 Util-overflow 皮尔逊相关性

$$
r_{uo} = \frac{\mathrm{Cov}(u, \max(0, -c))}{\sigma_u \cdot \sigma_{\max(0, -c)}}
$$

- $u_{z,y,x} = 1 - c_{z,y,x} / c^{(0)}_{z,y,x}$：cell 归一化利用率
- $r_{uo} \in [-1, 1]$，$r_{uo}$ 越大表示"利用率高 → 过载"关联强

### 5.7 History cost 递推

$$
h^{(k+1)}(e) = h^{(k)}(e) + \alpha^{(k)} \cdot \max(0, -c_e)
$$

- $c_e = \min(c_{z,y_1,x_1}, c_{z,y_2,x_2})$：edge 两端最差剩余容量
- $\alpha^{(k)}$：第 $k$ 次的历史惩罚增长率

### 5.8 Reroute edge cost

$$
\mathrm{cost}(e) = W(e) + h^{(k)}(e) + pf \cdot \max(0, -c_e)
$$

- $W(e)$：基础容量加权 cost
- $h^{(k)}(e)$：累积历史 cost
- $pf \cdot \max(0, -c_e)$：当前拥塞惩罚（$pf$ 为 present factor 权重）

### 5.9 α 自动递增

$$
\alpha^{(k+1)} = \alpha^{(k)} \times 1.15
$$

### 5.10 Rip-up 候选集合

$$
R^{(k)} = \{n \in N : \psi_n \geq \psi_{\lfloor(1-\rho)|N|\rfloor}\}, \quad \rho = 0.20
$$

取 $\psi_n > 0$ 的 net 集合前 20%。

### 5.11 ISPD 2025 S_orig 评分

$$
S_{\text{orig}} = \alpha \cdot \Omega + \beta \cdot W + \gamma \cdot V
$$

- $\Omega$：总 overflow
- $W$：总 wirelength
- $V$：总 via 数
- $\alpha, \beta, \gamma$：ISPD contest 给定的权重

AlphaRoute 在 ARIANE 上 $\mathbf{S_{\text{orig}} = 0.0538}$ vs SOTA $\mathbf{1.780}$（33.1× 降低）。

## 7. 创新点

### 7.1 创新点 1：SHAP 风格 overflow 分解 + 逐 net rip-up

**贡献**：用置换重要性分析（不依赖外部 SHAP 库）把整体 $\Omega$ 分解到 (1) per-net score $\psi_n$、(2) per-layer fraction $\lambda_z$、(3) congested cell fraction $f_c$、(4) util-overflow correlation $r_{uo}$ 四类指标，让 rip-up 不再依靠"随机 / 按 cost / 按 net size"的粗糙启发式，而是 **按"谁对拥塞贡献最大"排序**。

**为什么重要**：传统 R&R 闭环比的是"循环次数 vs 残留 overflow"，但 **不能解释为什么残留**。SHAP 分解让"残留 overflow 是因为 net A 占用了 layer 4 上 50% 通道"这种归因成为可能——把"测量 → 归因 → 处方"连成因果链。

**与已有方法的关键区别**：
- 旧：CUGR / InstantGR / PathFinder / PAGR 用 cost-based 启发式（哪条 net 贵就 rip 哪条），但不区分"拥塞贡献"
- 新：AlphaRoute 用 SHAP 拆出"每根 net 对整体 $\Omega$ 的边际贡献"，top 20% 直接 rip，**理论上有 causality 支撑**

### 7.2 创新点 2：自适应 PathFinder 策略 + 三大 SHAP 规则

**贡献**：在经典 PathFinder cost model（$W(e) + h(e) + pf \cdot c_e$）上叠加三个 SHAP 驱动的自适应规则（表 I），让 $\alpha, pf, w_{via}$ 不再固定或按固定 schedule，而是按"$f_c < 0.02 → +pf$"、$"r_{uo} > 0.5 → +\alpha$"、$"\lambda_{z^*} > 0.50 → -w_{via}$"动态调整。

**为什么重要**：传统 routing penalty schedule 是"经验调参"的——打个比方，$\alpha$ 怎么从 0.4 涨到 1.2 完全靠历史 benchmark 经验。AlphaRoute 把这些 schedule 改成 **bottom-up from 拥塞信号**，物理可解释。

**与已有方法的关键区别**：
- 旧：fixed schedule / 手调 schedule，benchmark-specific
- 新：SHAP 信号驱动规则 + α 自动 1.15× 递增兜底，确保任何基准都不会"无信号"

### 7.3 创新点 3：LLM 作为"语义策略优化器" + 知识图谱硬约束

**贡献**：LLM 不被视为端到端控制器或 reward judge，而是 **结构化 JSON 参数编辑器**——读 7 个 SHAP 字段，返回 $(α, pf, w_{via})$ + 一句自然语言推理。在 LLM 输出前，RustworkX 知识图谱 `(Pattern, Strategy, Outcome)` 三元组做硬约束校验：
1. 参数值在允许区间（$\alpha \in [0.1, 2.0]$, $pf \in [0.5, 8.0]$, $w_{via} \in [20, 80]$）
2. 历史 Pattern-Strategy 组合防震荡
3. 校验失败时回退到 SHAP 启发式

**为什么重要**：这是 "LLM-as-Decider" 在 zero-tolerance 物理域（半导体设计）的 **safety wrapper**——LLM 提供柔软的语言推理，硬约束保证物理学不破。

**与已有方法的关键区别**：
- 旧：LLM-as-judge（reward model）有 bias 问题（position bias / verbosity bias / self-preference），RLHF 有 reward over-optimization 问题
- 新：LLM-as-structured-policy-editor + KG 硬约束——LLM 的输出永远是 JSON 参数 + 自然语言推理，KG 卡死后只剩 SHAP 兜底，**physics 不会因为 LLM hallucination 而破裂**

**同架构 LLM 变体一致性**：Llama-3.2-3B（本地）、Llama-3.3-70B、GPT-OSS-120B 三种 Llama 系模型在 WNS/TNS 上统计无差异——证明 **真正主导决策的是 SHAP 信号 + KG 硬约束，不是 LLM 本身的智能**。但注意该结论仅基于 Llama 架构模型，未验证 GPT-4o、Claude、Gemini 等其他架构。

### 7.4 创新点 4：基于 bounding-box subgraph 的 3D Dijkstra 迷宫重布

**贡献**：对 $2{,}500 < A_n \leq 15{,}000$ 的中等面积 net，在其 bounding-box 周围加 margin $\delta = 2$ GCells，构造 **局部 subgraph**，用 cost-aware Dijkstra（Eq. 8）找 shortest path。局部化让 Dijkstra 在 4.17M-cell 网格上仅需计算 bounding box 大小的子图。

**为什么重要**：全局 Dijkstra 在百万级 GCell 网格上不切实际（$O(N \log N)$）。Bounding box 局部化把搜索空间降到几百×几百，使 Dijkstra 能在 4.17M-cell 的 BSG 上数次迭代内收敛。

### 7.5 创新点 5：Slack-aware net 排序（area 优先于 criticality）

**贡献**：排序键 (1) bounding-box area、(2) worst pin slack、(3) trivial net last。**Area 优先于 criticality**——这与直觉相反（一般认为 critical net 优先），但论文解释："大 net 占主干 channel；小 net 抢了关键 channel 后大 net 只能绕路，引发二次拥塞"。

**为什么重要**：纠正了行业常见的"critical net 优先"谬误。Slack 用于同面积 net 的 tie-break，保证 critical net 在同尺寸 net 中也能拿到最短最不电阻的路径。

## 9. 与芯片流程关系

### 9.1 在 EDA 流程中的位置

AlphaRoute 是 **物理设计阶段（⑦-⑫）的全局布线（⑨）专项改进**。它接手 placement 的输出（.net 文件 + .cap 容量约束），不涉及前端 RTL/综合 / 后端 detailed routing / CTS / signoff。

```text
传统 EDA 流程：
①RTL → ②仿真 → ③综合 → ④门级仿真 → ⑤STA → ⑦布局 → ⑨全局布线 → ⑩详细布线 → ⑬签核

AlphaRoute 介入点：
                                        ⑦布局 (.net)
                                          │
                                          ▼
                              ┌──────────────────────┐
                              │ AlphaRoute 主要工作  │
                              │  - 输入解析           │
                              │  - 3D 加权图构建      │
                              │  - Slack-aware 排序   │
                              │  - 初始 Steiner/MST+FL│
                              │  - SHAP 拥塞分解      │
                              │  - LLM policy 调整    │
                              │  - KG 硬约束校验       │
                              │  - Dijkstra maze 重布 │
                              └──────────────┬───────┘
                                             │
                                             ▼ (.route)
                                       ⑩详细布线
```

### 9.2 与上下游的接口

**上游（⑦ Layout）**：AlphaRoute 接收 placement 产出的 .cap + .net，**不修改** placement。AlphaRoute 的 overflow 严格取决于 placement 的 macro 位置和标准 cell 分布。

**下游（⑩ Detailed Routing）**：AlphaRoute 输出的 .route 包含每根 net 的 GCell 序列和层分配。Detailed router（如 TritonRoute）把这些 GCell 序列转换为精确的 track 走线。如果 AlphaRoute 的 GCell 分配有严重 hot spot，detailed router 会无法完成 routing 或产生大量 DRC violation。

**与 CTS (⑪) 的连接**：AlphaRoute 不处理 clock net 的特殊 routing——ISPD contest 把时钟视为普通 net。但在实际工业设计中时钟 net 有专门的 CTS 流程，通常在 AlphaRoute 之后跑 CTS、然后局部 re-route 时钟区域。

> AlphaRoute 与 [ChatEDA](../ChatEDA/论文深度讲解.md) / [ORFS-Agent](../ORFS-Agent/论文深度讲解.md) 的根本区别是 **autonomy level**：
> - ChatEDA / ORFS-Agent 是 **L3-L4 agentic 编排**——LLM 调用整个 commercial EDA flow
> - AlphaRoute 是 **单步骤 LLM 调参**——LLM 只调 PathFinder 三个标量参数，路径仍由 Dijkstra/MST 几何求解
>
> 两者可以 **叠加使用**：AlphaRoute 作为 ORFS-Agent 内 "routing 子任务" 的 policy optimizer。

### 9.4 "仿真通过"和"能做成芯片"之间隔着什么

AlphaRoute 把 ISPD 2025 评分砍了 33× —— 但这只是 **算法竞赛分数**。从 "routing benchmark 完美" 到 "硅片流片成功" 至少还差：

1. **Detailed Routing 完成性**：AlphaRoute 不跑 detailed routing，其 GCell 序列可能包含 detailed router 无法实现的 patterns（如部分 GCell 间距过窄导致 pin access 失败）。需要把 AlphaRoute 的输出喂给 [TritonRoute](https://github.com/The-OpenROAD-Project/TritonRoute) 之类详细布线器，**DRC violation rate 是新的硬指标**
2. **CTS 与时钟 skew**：AlphaRoute 不区分 clock net，普通 routing 的 wirelength 最小化可能引入 clock skew。需要重跑 CTS 后局部 re-route
3. **信号完整性（SI）**：现代 5nm/3nm 工艺 crosstalk / electromigration 严重。AlphaRoute 的 overflow metric 完全不考虑 SI —— 需要在 post-routing 跑 SI 仿真（[PrimeTime-SI](https://www.synopsys.com/implementation-and-signoff/signoff/primetime.html) 之类）
4. **Power 网格完整性**：AlphaRoute 不感知 IR drop / EM，power grid 路由由单独流程处理
5. **多 pattern 化约束**：5nm/3nm 必须用 multi-patterning（LELELE…），颜色冲突 / 不同 parity 的 GCell 必须分配到不同 mask —— AlphaRoute 的容量模型不含此约束

AlphaRoute 在论文里明确承认这些 limitation（"Future work will address it through a C++/Rust re-implementation or GPU-accelerated path search"）。

## 10. 讨论与局限

### 10.1 论文自陈局限

#### 局限 1：Wall-clock runtime 显著高于 C++ 实现

论文自己承认 wall-clock runtime 约为 ISPD contest median 的 **136 倍**（$t_{\text{med}} = 19s$，AlphaRoute 约 43 min）。两个原因：

1. AlphaRoute 完全用 Python 实现（无 C++ 优化），而 contest top 用 C++
2. 实验在更受限的 cloud instance 上（A40 48GB vs 参考 A100 40GB + 200GB RAM + 8 cores）

论文明确把 C++/Rust 重写 + GPU 并行 path search 列为 **future work**。

#### 局限 2：纯 Python 单进程的推理开销

LLM policy 提案每 R&R 迭代调用一次 LLM（Ollama 或 Groq API），每次 ~1-5s。在 5-8 轮迭代中，LLM 推理的 wall-clock 占比可能达 20-40%。

#### 局限 3：依赖外部 SHAP 启发式未严格数学化

虽然论文说"借鉴 SHAP"，但实际是 **permutation-importance 的简化版**（$r_{uo}$ 是 Pearson 相关，不是真正的 SHAP value）。在数学严格性上，SHAP value 满足 efficiency / symmetry / dummy 三条公理；AlphaRoute 的 $\psi_n$ 只是 "net 占据的过载 cell 之和"，**不满足 efficiency 公理**。

#### 局限 4：KG 硬约束规则 hard-coded 偏少

KG 现在的硬约束只检查 (1) 参数值区间、(2) Pattern-Strategy 组合防震荡。**没有物理等价约束**（如"同一 via 在 0.5ns 内不能连续两次使用"）。这意味着 LLM 仍有可能建议违反物理规则的策略，KG 兜底不够全面。

### 10.2 代码 / 复现层面的问题

#### 问题 1：完全 Python，依赖 RustworkX + Ollama

```bash
pip install -r requirements.txt
python router.py -cap data/ariane.cap -net data/ariane.net -output artifacts/ariane.route
python router.py -cap data/ariane.cap -net data/ariane.net -output artifacts/ariane.route -enhanced
python router.py -cap data/ariane.cap -net data/ariane.net -output artifacts/ariane.route -enhanced -llm
```

LLM 后端需要：
- `GROQ_API_KEY` 环境变量（Groq API 模式）
- 本地 Ollama `http://localhost:11434` 本地模式（默认模型 `llama3.2:3b`）
- 或 template-based fallback（无 LLM）

复现门槛：**12 GB RAM（本地 Ollama）+ Groq API key（云端模式）+ ISPD 2025 benchmark（公开下载）**。

#### 问题 2：ISPD 2025 benchmark 获取

论文评测的 `.cap + .net` 文件来自 [ISPD 2025 contest GitHub](https://github.com/liangrj2014/ISPD25_contest)。复现时需要下载该 contest benchmark 包。

#### 问题 3：ISPD 评分公式不公开

$S_{\text{orig}} = \alpha \cdot \Omega + \beta \cdot W + \gamma \cdot V$ 的精确 $\alpha, \beta, \gamma$ 系数由 contest 发布。AlphaRoute 论文未公开 $\alpha/\beta/\gamma$，**完全独立复现 $\mathbf{S_{\text{orig}} = 0.0538}$ 需要 contest 评分器**（通常以 C++ binary 形式提供，不开源）。

#### 问题 4：LLM temperature / seed 未明确

论文未报告 LLM 调用的 temperature、top-p、seed。LLM 本身有非确定性，policy 提案会有 variance。LLM ablation 结论（"三种 Llama 系模型无显著差异"）仅基于同架构模型，可能依赖特定超参，也未验证跨架构泛化性。

### 10.3 本资料包的批判性分析

#### 批判 1：LLM 在此处的"贡献"被高估

论文 Fig. 3 明确显示：**A6（无 LLM）和 A7/A8（有 LLM）的 overflow 几乎完全相同**，且 A7/A8 略高于 A6（"LLM slightly over-penalize designs already near optimal"）。这意味着：

- LLM 的主要贡献是 **interpretability**（提供自然语言推理给设计师）而非 **直接降 overflow**
- 论文标题 "LLMs as Semantic Optimizers" 有点 misleading——LLM 不是 optimizer，是 interpreter
- S_orig 从 1.780 降到 0.0538 的 **核心贡献者是 Flex-L (A2) + SHAP (A3) + Dijkstra (A4)** 三件套，LLM 是锦上添花

#### 批判 2：Net overflow score $\psi_n$ 不满足 SHAP 公理

SHAP value 满足四条公理（Efficiency / Symmetry / Dummy / Additivity）。AlphaRoute 的 $\psi_n$ 只是"过载 cell 上的 negative capacity 求和"，**完全不满足 Efficiency**——$\sum_n \psi_n \geq \Omega$（因为不同 net 共享 cell）。这不是 SHAP，是 "per-net cost contribution"。

论文承认这一点，但用 "SHAP-based" 这个词容易让读者误以为是严格 SHAP。

#### 批判 3：KG 的硬约束是 "值域检查" 不是 "物理检查"

KG 现在只检查参数值是否在允许区间。这等于 **JSON schema 校验**，不构成 LLM 的真正物理防护。物理防护需要：cell 间 wire spacing 检查、track 资源 conflict 检查、layer antenna rule 检查——这些都不在 KG 范围内。

#### 批判 4：单一 forward pass 的 7 字段 prompt 太浅

LLM 只看 7 个标量字段，不知道当前 routing topology、不看具体拥塞热点位置、不看 net 间的相互依赖。LLM 的推理必然是 "粗粒度启发式规则"，无法捕捉 "net A 应该在 layer 3 而非 layer 7 因为 layer 3 在它 bounding box 内还剩 30% 容量"这种精细归因。

#### 批判 5：136× runtime overhead 被忽略

论文承认 136× runtime，但结论是 "overflow 降低 dominate runtime overhead"。这在 **学术 prototype 上可以接受**，但工业部署不切实际——一次完整 routing 跑 40+ 分钟，5nm/3nm 设计单次 P&R 需要 100+ 次迭代，不可接受。论文只承诺 future C++ 重写，对 LLM 部分没承诺。

#### 批判 6：单 LLM family ablation 不充分

LLM ablation 只比较 Llama-3.3-70B 和 GPT-OSS-120B（Groq API 两种）。没测 GPT-4o、Claude、Gemini 等其他家族。更严重的是没测 **Code-LLM 专用模型**（如 DeepSeek-Coder、Qwen-Coder）——这些模型对 Verilog / 编程任务通常更强，可能给出更准的 policy。

#### 批判 7：未考虑 multi-corner multi-mode（MC/MM）

工业 routing 必须满足 functional mode + test mode + 多个 PVT corner。AlphaRoute 只跑 single-corner 不算分。后续要扩展 MC/MM-aware 的 SHAP。

| 3D Dijkstra maze | ⭐⭐⭐ | bounding-box subgraph + cost-aware Dijkstra |
| LLM policy client | ⭐⭐ | Ollama / Groq API JSON 通信 |
| Knowledge graph | ⭐⭐⭐ | RustworkX + Pattern/Strategy/Outcome schema |
| ISPD 评分 | ⭐⭐⭐⭐ | 需要 contest 提供的 C++ 评分 binary |

### 11.3 复现注意事项

1. **Groq API key**：A7/A8 ablation 需要 Groq API key；本地 Ollama fallback 是 Llama-3.2-3B
2. **Python 版本**：3.9+ 要求（RustworkX 0.13+）
3. **运行时间**：单次 ARIANE run 约 30-50 分钟（含 LLM 调优）
4. **内存峰值**：BSG（1384 × 1384 × 10 = 19.1M cells）峰值约 16-20 GB（RustworkX graph）
5. **ISPD contest 评分器**：必须从 contest 官网下载独立 evaluator 才能复现 $S_{\text{orig}} = 0.0538$

## 12. 一分钟复述版

1. **核心问题**：VLSI 全局布线是 NP-hard；现代 SoC 在 10+ 金属层 + 百万级 GCell 网格上 routing，拥塞是高度非局部的雪崩式传播；经典 PathFinder 用静态 penalty schedule 抓不到"特定拥塞拓扑"需要何种 penalty 调整

2. **方法概述**：AlphaRoute = SHAP 风格 overflow 分解（per-net $\psi_n$ / per-layer $\lambda_z$ / $f_c$ / $r_{uo}$）+ 自适应 PathFinder（三大 SHAP 规则 + α 自动 1.15× 递增 + Eq. 7-8 cost model）+ 3D Dijkstra 迷宫重布（局部 subgraph 避拥塞）+ LLM 语义策略优化（7 字段 prompt → JSON $\alpha, pf, w_{via}$ + reasoning）+ RustworkX 知识图谱硬约束校验（Pattern-Strategy-Outcome 三元组）

3. **核心数据**：ISPD 2025 四基准（ARIANE 105K nets、BSG 768K nets、MEMPOOL 157K nets、NVDLA 135K nets），完全无训练，纯 Python 实现 + RustworkX + Ollama/Groq LLM

4. **关键结果**：ARIANE overflow 1,517,789 → 146,109（29.8× 降低），$S_{\text{orig}}$ 1.780 → 0.0538（33.1× 降低），MEMPOOL overflow -98.6%；wall-clock 136× SOTA 但被 $S_{\text{scaled}}$ 评分公式 severe discount；accumulation ablation 证明 99% overflow 降低来自 A2/A3/A4，LLM 主贡献 interpretability

5. **最大创新点**：把 SHAP 思想搬到 routing 域做"per-net 拥塞归因"，把 LLM 视为"结构化 JSON 策略编辑器 + 自然语言推理器"而非端到端控制器，用 RustworkX KG 做硬约束兜底——这是"LLM-as-Decider"在 zero-tolerance 物理域的 **safety wrapper**

6. **EDA 流程位置**：纯全局布线阶段（⑨）—— 接手 placement 的 .cap + .net，输出 .route 给 detailed routing。**不涉 RTL/综合/CTS/signoff**

7. **与同类工作的关系**：与 AlphaChip / TransPlace / DiffusionPlace / MaskPlace 等 placement 学习工作 **不重叠**（阶段不同）；与 [TopoRTL](../TopoRTL/论文深度讲解.md) 不重叠（RTL 阶段 vs routing 阶段）；与 [DeepGate4](../DeepGate4/论文深度讲解.md) / [CircuitFusion](../CircuitFusion/论文深度讲解.md) 不重叠（AIG 表示 vs routing）；与 [ChatEDA](../ChatEDA/论文深度讲解.md) / [ORFS-Agent](../ORFS-Agent/论文深度讲解.md) **互补可叠加**（ChatEDA 做 LLM-agent 全工具编排，AlphaRoute 可作其 routing 子任务）

8. **局限**：136× wall-clock（纯 Python 限制，未来 C++ 重写）；LLM 在 overflow 贡献上几乎为 0（图 3 显示 A6=A7=A8），主贡献是 interpretability；KG 硬约束仅值域检查，非物理检查；7 字段 prompt 太浅，看不到 topology；缺 MC/MM / multi-corner 验证

## 附录 A：SHAP Analyzer 的形式化校正

论文中 $\psi_n = \sum_{(z,y,x) \in \mathcal{G}_n} \max(0, -c_{z,y,x})$ 不严格满足 SHAP value 的四条公理。严格 SHAP value 定义：

$$
\phi_i(v) = \sum_{S \subseteq \{1,...,N\} \setminus \{i\}} \frac{|S|! \cdot (N - |S| - 1)!}{N!} \left[ f(S \cup \{i\}) - f(S) \right]
$$

AlphaRoute 的实现是 **置换重要性（Permutation Importance）的简化版**——把 "net $n$ 移除后 $\Omega$ 变化多少" 直接近似为 "net $n$ 占据的过载 cell 之和"。这是一种 **经验归因**，不是严格博弈论 SHAP。论文标题的 "SHAP-based" 是借名而非严格算法。

## 附录 B：Edge weight 第一项 $(10 - 3\sigma_n)$ 的物理含义解读

| $\sigma_n$ | 物理含义 | 第一项值 |
|:--------:|----------|:--------:|
| 0 | 完全非 critical net（slack 充足） | 10.0 |
| 0.5 | 中等 critical | 8.5（15% 折扣）|
| 1.0 | 最关键 net（slack = $s_{\min}$） | 7.0（30% 折扣）|

**为什么用 30% 折扣？** 数字上没有严格的理论推导。从经验看：critical net 通常需要 ~30% 更短路径才能满足 timing closure。30% 折扣让 Dijkstra 自然倾向给 critical net 选 shortest path，同时给非 critical net 留出绕路空间。
