## 1. 一句话定位

**PCB-Bench 是首个系统评估（多模态）大语言模型在 PCB 布局布线领域推理能力的综合基准：集成 ~3700 道文本 QA/CQ（含 ~1800 道自由问答 + 对应单选题）、~500 道图文多模态推理题、174 个完整真实 PCB 项目理解任务，覆盖 25+ 工程子主题（信号完整性、EMI/EMC、电源规划、差分对、DFM 等），用统一零样本协议（无示例、无微调）评测 GPT-4o / GPT-5 / Claude-Opus-4.1 / Gemini-2.5-Pro / DeepSeek-V3.1 / LLaMA-4-Maverick 等前沿模型，发现当前最强模型在 PCB 领域仍存在"选择题能做对但开放问答说不清"（discrimination ≠ generation）、多模态空间推理最弱（开源模型在布线错误识别上仅 45-55%）、领域特化（QLoRA 微调 + RAG）有效但不足以超越闭源 SOTA 三大核心结论。**

这句话里的六个技术承重点：

1. **"PCB 布局布线不是芯片布局布线"** — PCB 关注的是板级物理设计（元器件摆放、走线、过孔、层叠），而非芯片级的标准单元布局和金属层布线。两者的约束空间（PCB：差分对、阻抗控制、热管理 vs IC：时序收敛、拥塞、功耗密度）完全不同，但都需要 LLM 理解空间约束和物理规则。

2. **三任务互补设计（Text QA / Image QA / Design Understanding）** — 不是单一评测维度，而是覆盖文本推理（纯知识）、图文联合推理（视觉+文本）、真实工程理解（EDA 截图→功能描述）三个递进层级，模拟真实 PCB 工程师从"看书"到"看图"到"看板"的认知链条。

3. **discrimination ≠ generation 的核心发现** — 模型可能在选择题上选对答案（CQ accuracy 高），但在开放问答中说不出正确的理由（QA semantic similarity 低）。例如 InternVL3-78B 在 CQ 上表现强劲但在 QA 上落后，说明选择题可以靠"排除法"蒙对，而真正的领域理解需要开放生成来检验。

4. **多模态是最大短板** — 在 Basic Wiring Error Identification（BWEI）任务上，开源模型准确率骤降至 45-55%。这说明当前 MLLM 的视觉定位和文本推理对齐在专业工程图像（如 PCB 布线图、丝印层、钻孔图）上还远未成熟。

5. **领域特化的天花板** — QLoRA 微调将 Qwen2.5-7B 的 SBERT 从 ~0.22 提升到 ~0.48-0.60，但仍未超过 GPT-4o/Claude-Opus 等闭源模型。RAG 的效果也有限——说明在专业领域，"小模型+领域数据"的组合尚不能替代"大模型+通用能力"。

6. **真实工程数据的价值** — 174 个来自 OSHWHub（JLCPCB 运营）的完整 PCB 项目，包含原理图、布局文件、设计描述、元器件库、EDA 截图，构成目前最大的公开 PCB 设计理解数据集。每个项目附带 URL 链接保证 IP 透明和可追溯。

## 2. EDA 阶段映射（①-⑰）

> ⚠️ **领域说明**：PCB-Bench 聚焦 **PCB（印刷电路板）** 设计而非芯片 IC 设计。以下映射将 PCB 设计流程对接到数字芯片 17 阶段流程的最近似阶段。

参照 [芯片流程.md](../芯片流程.md) 的 17 阶段标准编号：

| 阶段 | 覆盖 | 说明 |
|------|:---:|------|
| ① RTL 设计 | ❌ | PCB 设计不涉及 RTL。PCB 的"设计输入"是原理图（schematic），对应的是元器件选型和互连定义，而非硬件描述语言。 |
| ② RTL 功能仿真 | ❌ | PCB 领域对应的是 SPICE 仿真 / 信号完整性仿真，不在本 benchmark 覆盖范围内。 |
| ③ 逻辑综合 | ❌ | — |
| ④-⑥ 门级/STA/形式验证 | ❌ | — |
| **⑦ 布局规划 (Floorplan)** | ✅ **近似核心** | PCB 的"元器件摆放（Component Placement）"对应芯片 Floorplan 阶段。Task 1 的 Placement 子任务直接评测模型对"哪些元件该放哪"的知识。 |
| **⑧ 电源网络** | ⚠️ **间接覆盖** | PCB 的电源规划（Power Planning）在 Task 1 中作为子主题出现（电源层分割、去耦电容摆放），但不是独立的评测任务。 |
| **⑨ 全局布线** | ✅ **近似核心** | PCB 的"走线策略（Routing Strategy）"对应芯片全局布线。Task 1 的 Routing 子任务覆盖差分对走线、阻抗控制、等长匹配等 PCB 特有的布线约束。 |
| ⑩ 详细布线 | ⚠️ | Task 2 的图文推理中包含"trace reasoning"和"via presence checking"子任务，可视为详细布线级别的推理。 |
| ⑪ 时序优化 | ❌ | PCB 的时序不是以 ps 为单位的 setup/hold，而是信号传播延迟和时序偏移（skew），评测标准不同。 |
| ⑫ DRC | ⚠️ | Task 1 包含设计规则合规（design rule compliance）子主题，但 PCB 的 DRC（线宽、间距、孔环）与芯片 DRC 内容不同。 |
| ⑬-⑰ 流片→制造→封装→芯片 | ❌ | — |

**覆盖率：0/17 直接覆盖 + 4/17 近似映射。** PCB-Bench 的核心价值不在芯片流程中，而在于为"物理设计的空间推理能力"提供了一个跨领域但方法通用的评测基准。它在芯片流程中最接近的阶段是 **⑦ Floorplan 和 ⑨ 全局布线**——这两个阶段恰好是 AI4EDA 中 LLM 应用的前沿方向（如 AlphaRoute 的布线优化）。

> ⚠️ **关键边界**：PCB-Bench 评测的是 LLM 对 PCB 设计知识的"理解和推理能力"，不是生成 PCB 设计文件的能力。它不评测模型能否输出 Gerber 文件或 KiCad 工程。和 [SchGen](../SchGen/论文深度讲解.md)（生成 KiCad 原理图）是互补关系：PCB-Bench 评测"懂不懂 PCB"，SchGen 评测"能不能画原理图"。

## 3. 输入 / 输出

### 3.1 Task 1：文本推理（Text-to-Text QA & CQ）

**(a) 自由问答（QA）**

输入是纯文本的 PCB 设计问题：

```text
Question: When routing a high-speed differential pair on a 4-layer PCB,
why should the reference ground plane be continuous under the pair?
Explain the impact of a split ground plane on differential impedance and EMI.
```

输出是自由文本答案，用 BERTScore 和 Sentence-BERT 与专家参考答案做语义相似度评估。

**(b) 单选题（CQ）**

同一知识点对应一道单选题：

```text
Question: On a 4-layer PCB, a differential pair crosses a split in the
reference ground plane. What is the most likely consequence?

A. Increased differential impedance and higher common-mode radiation
B. Decreased trace resistance and better signal quality
C. No effect because differential pairs are self-referencing
D. Reduced crosstalk to adjacent traces

Correct Answer: A
```

评测指标：Top-1 Accuracy。

### 3.2 Task 2：多模态图文推理（Image-and-Text QA/CQ）

输入是 PCB 布局截图 + 文本问题：

```text
[PCB Layout Image: 一段包含差分对、过孔、去耦电容的布线区域截图]

Question: Identify the component marked with the red arrow.
A. Decoupling capacitor
B. Pull-up resistor
C. Ferrite bead
D. Crystal oscillator

Question: Trace the signal path from U1 pin 3 to J2 pin 5. How many vias
does this net use?
```

输出是选择题答案或自由文本。

### 3.3 Task 3：真实 PCB 设计理解（Screenshot-to-Description）

输入是 EDA 工具截图（无额外文本/原理图）：

```text
[KiCad/EasyEDA PCB Editor Screenshot: 显示完整 PCB 布局，含元器件丝印、
走线、过孔、敷铜区域]

任务：Generate a free-form description of this board's function, structure,
and application scenario.
```

输出是自由文本功能描述，用 BERTScore + Precision/Recall/F1 评估。

### 3.4 数据规模

| 任务 | 实例数 | 题型 | 数据来源 |
|------|:---:|------|------|
| Task 1 (Text QA) | ~1800 | 自由问答 | 专家标注 |
| Task 1 (Text CQ) | ~1800 | 单选题 | 对应 QA 生成 |
| Task 2 (Image QA) | ~300 | 单选题 | 专家标注 |
| Task 2 (Image CQ) | ~100 | 完形填空 | 专家标注 |
| Task 2 (Image Free-form) | ~100 | 自由问答 | 专家标注 |
| Task 3 (Design Understanding) | 174 | 自由描述 | OSHWHub 真实项目 |
| **合计** | **~4274** | | |

### 4.2 三任务设计理念

**Task 1（文本推理）**：评测模型的"书本知识"——是否理解 PCB 设计的核心概念和原则。覆盖 25+ 子主题：

- **Placement 相关**：元件摆放策略、热管理、EMC 分区、高速/低速区域隔离
- **Routing 相关**：差分对布线、等长匹配、阻抗控制、串扰抑制
- **Power 相关**：电源层设计、去耦电容布局、PDN 阻抗
- **DFM 相关**：可制造性设计、测试点规划、装配约束
- **Signal Integrity**：反射、端接、眼图、抖动

**Task 2（多模态推理）**：评测模型的"看图能力"——能否从 PCB 布局截图中识别元件、追踪走线、发现设计缺陷。这是当前 MLLM 最薄弱的环节。

**Task 3（设计理解）**：评测模型的"全局理解力"——看到一张完整 PCB 的 EDA 截图，能否推断出这块板子是什么、做什么用的。

## 5. 关键公式

### 5.1 BERTScore

论文未给出编号公式，以下是对评测指标的严格形式化：

$$
\text{BERTScore}(c, r) = \frac{1}{|c|} \sum_{i=1}^{|c|} \max_{j} \mathbf{e}_{c_i} \cdot \mathbf{e}_{r_j}
$$

- $c$：模型生成的候选文本（candidate）
- $r$：专家参考答案（reference）
- $\mathbf{e}_{c_i}$：候选文本第 $i$ 个 token 的 BERT 上下文嵌入
- $\mathbf{e}_{r_j}$：参考答案第 $j$ 个 token 的 BERT 上下文嵌入

**工程直觉**：BERTScore 不是简单的 n-gram 匹配，而是用 BERT 的上下文嵌入来衡量两个文本在语义空间的相似度。"电容放在芯片旁边"和"去耦电容应靠近 IC 放置"在 BERTScore 下会得到高相似度，在 BLEU 下可能很低。

### 5.2 Pass@k（生成正确率，非 PCB-Bench 直接使用但相关）

PCB-Bench 使用的是 Accuracy 和 Semantic Similarity，不是 pass@k。但在与其他 RTL 生成类基准对比时，这是一个相关指标：

$$
\text{Pass@k} = 1 - \frac{\binom{n-c}{k}}{\binom{n}{k}}
$$

## 6. 训练与实验设置

### 6.1 是否需要训练

**不需要训练。** PCB-Bench 是一个纯评测基准——所有模型在零样本设定下评测，不使用示例或微调。领域特化实验（QLoRA 微调 Qwen2.5-7B）是额外的消融分析，不是 baseline 要求。

### 6.2 实验设置

- **评测协议**：统一零样本（unified zero-shot），每个实例独立回答，无对话历史，无 few-shot 示例
- **CQ 评测**：Top-1 Accuracy（四选一）
- **QA 评测**：BERTScore（F1）+ Sentence-BERT cosine similarity
- **Task 3 额外指标**：Precision / Recall / F1（基于关键词/实体匹配）

### 6.3 关键实验结果

> ⚠️ 以下数字来源：GitHub README、Figure 5 和 Table 2-4 中报告的公开结果。精确数值以论文正式版本为准。

| LLaMA-4-Maverick | ~82% | ~68% | ~88% | ~72% |
| Qwen2.5-7B (base) | ~60% | ~45% | ~65% | ~48% |
| Qwen2.5-7B (+QLoRA) | ~78% | ~65% | ~82% | ~68% |

**Image CQ Accuracy（Task 2 — 图文单选题）**：

| 模型 | 元件识别 | 布线追踪 | 过孔检测 | 差分对连续性 |
|------|:---:|:---:|:---:|:---:|
| GPT-4o | ~88% | ~75% | ~82% | ~72% |
| Claude-Opus-4.1 | ~90% | ~78% | ~85% | ~76% |
| Gemini-2.5-Pro | ~92% | ~80% | ~88% | ~78% |

| Qwen2.5-7B | ~55% | ~42% | ~48% | ~45% |

**这些表说明了什么**：

1. **Macro vs Micro 知识梯度**：所有模型在 Macro（全局原则）上远好于 Micro（细节实现）——说明 LLM 擅长"大道理"但缺乏"具体实施"的领域知识。
2. **闭源模型在视觉任务上遥遥领先**：Task 2 的图文推理是闭源模型和开源模型差距最大的维度，MLLM 的视觉理解能力是当前的核心瓶颈。
3. **QLoRA 微调有效但不足**：7B 模型经过 PCB 领域数据微调后有 15-20pp 的提升，但仍远低于数十倍参数量的闭源模型，说明单纯靠领域数据无法弥补基础能力的差距。

## 7. 创新点

### 创新点 1：首个 PCB 布局布线 LLM 评测基准

**和已有方法的区别**：已有的 PCB 相关数据集（PCB-DSLR、DeepPCB、FICS-PCB、PCB-Vision）全部聚焦于缺陷检测或元件识别（计算机视觉任务），没有一个是评测 LLM 对 PCB 设计知识的理解和推理能力的。PCB-Bench 填补了这一空白。

**为什么重要**：随着 SchGen、PCBSchemaGen 等 LLM 生成 PCB 设计的工作出现，业界急需一个评测"LLM 到底懂不懂 PCB"的标准——就像 VerilogEval 之于 RTL 生成。

### 创新点 2：discrimination ≠ generation 的方法论洞察

**和已有方法的区别**：传统 benchmark 倾向只用选择题（简单、可自动评分），PCB-Bench 为每个 QA 同时配了对应的 CQ，首次在 PCB 领域系统性揭示了"能做对选择题 ≠ 能说清为什么"的现象。

**为什么重要**：这对 benchmark 设计方法论有启示——只用选择题评测 LLM 可能会高估其真实能力。开放生成 + 语义相似度评估虽然更贵，但更接近真实工程场景。

### 创新点 3：真实工程数据的引入

**和已有方法的区别**：Task 3 的 174 个来自 OSHWHub 的真实 PCB 项目是首个面向 LLM 评测的"板级设计理解"数据集。这不是合成数据，而是工程师在真实项目中上传的完整设计。

**为什么重要**：真实 PCB 设计包含很多"工程约定"（如丝印标注风格、测试点命名规范、版本标记），这些信息在教科书和合成数据中不会出现，但对实际工程理解至关重要。

## 9. 与芯片流程的关系

### 9.1 在全流程中的位置

PCB-Bench 评测的是 **PCB 布局布线** 的知识推理能力，对芯片数字流程的 **⑦ Floorplan（布局规划）和 ⑨ 全局布线（Global Routing）** 两个阶段有方法论上的参考价值。

- **与 Floorplan 的关系**：PCB 的元件摆放和芯片的宏单元/Macro 摆放有相似的约束（热、电源、信号流），但 PCB 的约束更"粗粒度"（毫米级 vs 纳米级），更关注可制造性和装配而非时序收敛
- **与 Global Routing 的关系**：PCB 布线和芯片布线都是图搜索问题（在网格上找满足约束的路径），但 PCB 多了差分对、阻抗控制等"模拟"约束

### 9.2 "懂 PCB"和"懂芯片"之间的鸿沟

1. **尺度差异**：PCB 的线宽是 mil（千分之一英寸），芯片是 nm，差了 6 个数量级
2. **约束差异**：PCB 的核心约束是信号完整性、EMI/EMC、热管理；芯片的核心约束是时序、功耗、面积
3. **工具链差异**：PCB 用 Altium/KiCad/EasyEDA，芯片用 Innovus/ICC2/OpenROAD
4. **Benchmark 通用性**：PCB-Bench 的评测方法论（三任务互补、discrimination vs generation、多模态推理）可以直接移植到芯片布局布线基准的设计中——这是它对 AI4EDA 社区的最大价值

## 10. 讨论与局限

### 10.1 论文自述的局限

- **仅覆盖布局布线**：不包含原理图设计、元器件选型、BOM 生成等 PCB 设计的其他阶段
- **英文为主**：QA/CQ 全部使用英文，未覆盖中文/日文等其他语言的 PCB 设计社区
- **静态评测**：不评测模型在交互式设计（迭代修改布局）中的表现

### 10.2 代码/数据层面的问题

- **PDF 获取受限**：论文通过 OpenReview 发布，无 arXiv 版本，部分用户可能无法直接下载
- **OSHWHub 数据时效性**：174 个项目是快照，随时间推移链接可能失效
- **专家标注成本**：~1800 道 QA 的专家标注成本高，限制了数据集的扩展速度

### 10.3 本资料包的批判性分析

1. **"懂 PCB"和"能画 PCB"之间的 gap**：PCB-Bench 评测的是知识推理能力，不评测生成能力。即使一个模型在 PCB-Bench 上满分，也不代表它能生成正确的 KiCad 文件。这和 VerilogEval 评测 RTL 生成是一个道理——PCB-Bench 是"理论考试"，不是"实操考试"。

2. **与 [SchGen](../SchGen/论文深度讲解.md) 的互补性**：
   - SchGen 评测"能不能从 NL 生成 KiCad 原理图"（生成能力）
   - PCB-Bench 评测"懂不懂 PCB 设计知识"（理解能力）
   - 两者合在一起，构成了 PCB AI 的"理论+实操"完整评测体系

3. **芯片领域的可移植性**：PCB-Bench 的 benchmark 设计方法论（三任务互补 + discrimination vs generation + 零样本统一协议）对芯片物理设计基准（如评测 LLM 在 Floorplan/Routing 上的表现）有直接参考价值。目前 AI4EDA 领域缺乏类似的综合评测基准。

4. **跨领域定位**：PCB-Bench 和 SchGen 是资料包中唯二不直接属于芯片 17 阶段流程的论文。收录它们的原因是：(a) PCB 和 IC 在物理设计阶段的约束求解方法有共性，(b) LLM 在空间推理上的能力边界是跨领域的，(c) 它们为芯片领域的 benchmark 设计提供了方法论参考。

## 12. 一分钟复述版

PCB-Bench 是 ICLR 2026 发布的首个 PCB 布局布线 LLM 综合评测基准。它设计了三个互补任务：(1) ~3700 道文本 QA/CQ 评测 PCB 书本知识（25+ 子主题：信号完整性、EMI/EMC、电源规划、差分对等）；(2) ~500 道多模态图文推理题评测"看 PCB 图说话"的能力；(3) 174 个来自 OSHWHub 的真实 PCB 项目评测"看 EDA 截图猜功能"的全局理解。用统一零样本协议评测了 GPT-4o/5、Claude-Opus、Gemini、DeepSeek、LLaMA 等前沿模型，发现三个核心结论：选择题能做对但开放问答说不清（discrimination ≠ generation）、多模态视觉推理是最大短板（开源模型在布线错误识别上仅 45-55%）、QLoRA 领域微调有效但不足以超越闭源 SOTA。对 AI4EDA 社区的最大价值不是 PCB 领域本身，而是"三任务互补 + 零样本统一协议 + discrimination vs generation 分析"的 benchmark 设计方法论，可直接移植到芯片物理设计的评测中。
