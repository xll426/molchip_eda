## 1. 一句话定位

**Weave 是一个确定性的、零依赖的 SPICE 网表转 LTspice 原理图工具**：它用 Sugiyama 分层图布局算法将 netlist 变成可读的 .asc 原理图，然后用 round-trip 验证器将生成原理图重新解析为网表并与输入逐 net 比对，只有连通性分区完全一致才输出 MATCH 证书（等价于 GED = 1.0）。在 Schemato 使用的 117 电路公开测试集上 100% 编译 + 100% round-trip 连通性验证通过，在 3460 电路的 Analog Devices LTspice Demo 语料上 88.4% MATCH。不依赖 LLM、不需要 GPU、浏览器单文件即可运行。

这句话里的四个技术承重点，后面逐一拆解：

1. **确定性分层图布局管线** -- Weave 不生成概率输出，而是用 elkjs（Sugiyama 框架的工业级实现）按左到右信号流方向对电路元件做分层布局，placement 与 routing 由分层引擎联合完成。没有训练、没有采样、没有 GPU 依赖。
2. **Round-trip 连通性验证** -- 每个生成的 .asc 被重新解析为网表，与原输入做逐 net 二分集合比对。完全相同才输出 MATCH——这是二值正确性证书（等价于 GED = 1.0），不是相似度估计。论文确认验证器非空：删除 wire 或修改 net 会触发 mismatch。
3. **Safe-mode Ladder** -- 当默认布局无法产生连通性正确的原理图时，Weave 不直接失败，而是逐级降级布局模式（禁用 feedback pattern → 禁用 divider pattern → 纯 elkjs 布局 → 加宽通道间距），每级经 verifier 过滤，保留第一个 MATCH 结果。MATCH 永远不会错，只会更朴素。
4. **内嵌 5093 符号表 + Generic Fallback** -- Weave 内嵌了 LTspice 的 5093 个符号的 pin offset 与 SpiceOrder 索引，只存布局需要的信息。未知器件或 pin 数不匹配时，用等尺寸矩形 generic block 保证名称和连通性正确。这直接解决了 Schemato 的数据稀疏问题（训练数据中过半元件出现次数 < 10 次）。

## 2. EDA 领域与设计流程映射

> **关键认知**：Weave 处理的是**模拟/混合信号电路**的 SPICE 网表到 LTspice 原理图转换，不属于标准数字芯片 17 阶段流程（参照 [芯片流程.md](../芯片流程.md)）。数字和模拟使用的是两套完全不同的设计方法论。本节先梳理两种流程的根本差异，再定位 Weave 在模拟流程中的位置。

### 2.1 模拟设计与数字设计的根本差异

| 维度 | 数字流程（17 阶段） | 模拟流程 |
|---|---|---|
| **设计表述** | RTL 代码（Verilog/VHDL）描述行为 | Schematic（原理图）是核心设计载体 |
| **从行为到电路** | 逻辑综合：RTL → 门级网表（自动） | 拓扑选择 + 器件尺寸设计（工程师手工主导） |
| **单元库** | 标准单元库（AND/XOR/DFF 等，1000+ 种） | 无标准单元概念，每个晶体管 W/L 需单独设计 |
| **设计空间** | 离散：选哪个门、如何排列 | 连续：W/L、偏置电压、补偿电容值 |
| **验证方式** | RTL 仿真 + 门级仿真 + STA + 形式验证 | SPICE 仿真（瞬态/交流/直流/噪声/蒙特卡洛） |
| **版图** | 自动布局布线（P&R） | 通常手工绘制，部分辅助自动布线 |
| **物理验证** | DRC + LVS | DRC + LVS（相同，但模拟版图更不规则） |
| **签核** | STA + 功耗 + IR Drop | 多工艺角 SPICE 仿真 + 蒙特卡洛良率分析 |
| **典型规模** | 百万～百亿门 | 几个～几百个晶体管/元件 |
| **"功能正确"定义** | testbench 通过 + STA slack >= 0 | 仿真波形满足规格（增益/带宽/噪声/失真...） |

### 2.2 模拟设计的正向流程

```
    Schematic 绘制（工程师在原理图上放晶体管/电阻/电容，定义 W/L/偏置）
         │
         ▼
    SPICE 仿真（瞬态/AC/DC/噪声/蒙特卡洛）
         │  验证：增益够吗？带宽够吗？相位裕度够吗？
         ▼
    版图绘制（手工为主，部分辅助自动布线）
         │
         ▼
    寄生提取（RC Extraction）
         │
         ▼
    后仿真（带寄生的 SPICE 仿真）
         │
         ▼
    DRC + LVS（物理验证）
         │
         ▼
    签核 / 流片
```

### 2.3 Weave 在该流程中的位置：逆向可视化

Weave 做的是从 **netlist 回到 schematic** 的**逆向转换**。这在正向流程中不属于任何一个标准步骤，但在以下场景中有很强的工程价值：

| 场景 | 说明 |
|---|---|
| **ML 生成的电路审查** | 当 AI/RL 方法直接输出 SPICE netlist（如 RL 生成的运放拓扑），工程师必须看原理图才能审查和理解——20 个元件以上的 netlist 肉眼几乎无法理解拓扑 |
| **遗产网表恢复** | 老项目的 netlist 还在，但原始 .asc 原理图丢失——逆向重建可读原理图 |
| **跨工具迁移** | 从其他 SPICE 仿真器（HSPICE/Spectre）的 netlist 迁移到 LTspice 时自动生成原理图 |
| **仿真结果调试** | 从仿真网表快速生成原理图以定位问题节点和信号路径 |

**Weave 覆盖的模拟设计环节**：

| 模拟流程阶段 | Weave 是否覆盖 | 说明 |
|---|---|---|
| Schematic 绘制（正向） | ❌ | 正向流程是从 schematic 导出 netlist，Weave 正好相反 |
| **Netlist → Schematic（逆向）** | ✅ **核心** | Weave 的唯一任务：把 SPICE netlist 变回可读 LTspice 原理图 |
| SPICE 仿真 | ❌ | Weave 生成 .asc 后，用户可在 LTspice 中仿真，但 Weave 本身不跑仿真 |
| 版图绘制 | ❌ | — |
| 寄生提取 | ❌ | — |
| DRC/LVS | ❌ | 但 Weave 的 round-trip 验证在概念上类似于 LVS 的"版图提取网表 vs schematic 网表"比对——方向相反（Weave 是从 schematic 提取 vs 原始 netlist） |
| 签核 | ❌ | — |

### 2.4 与数字 17 阶段的逐阶段对照

| 阶段 | 覆盖 | 说明 |
|------|:---:|------|
| ① RTL 设计 | ❌ | 模拟电路无 RTL 层，schematic 即设计载体 |
| ② RTL 功能仿真 | ❌ | 对应模拟侧 SPICE 仿真，但 Weave 本身不跑仿真 |
| ③ 逻辑综合 | ❌ | 模拟电路不做布尔综合 |
| ④ 门级仿真 | ❌ | 无门级网表概念 |
| ⑤ STA（静态时序分析） | ❌ | 不涉及 |
| ⑥ 形式验证 | ⚠️ 类比 | Weave 的 round-trip verify 比对「从生成原理图再导出的网表」与「原始 SPICE netlist」，思想上接近等价性检查，但比对对象是拓扑连通性而非布尔函数 |
| ⑦ 布局规划（Floorplan） | ⚠️ 类比 | 元件在原理图画布上的坐标分配是「可读性布局」，与物理 floorplan 目标不同（美观/可读 vs 面积/时序） |
| ⑧ 标准单元摆放（Placement） | ❌ | 原理图布局不是物理布局，不含面积/密度约束 |
| ⑨ 时钟树综合（CTS） | ❌ | 模拟电路无同步时钟树 |
| ⑩ 布线（Routing） | ⚠️ 类比 | 原理图连线走线（正交折线、避免交叉）在算法上类似布线，但无层数/间距/寄生约束 |
| ⑪ 后仿真 | ❌ | 不涉及 |
| ⑫ 物理验证（DRC + LVS） | ❌ | 不涉及；LVS 只是概念类比，见 ⑥ |
| ⑬ 签核（Signoff） | ❌ | 不涉及 |
| ⑭ 流片 | ❌ | 不涉及 |
| ⑮ 制造 | ❌ | 不涉及 |
| ⑯ 封装 + 测试 | ❌ | 不涉及 |
| ⑰ 芯片到手 | ❌ | 不涉及 |

**覆盖率：0/17（严格口径），⑥⑦⑩ 为算法思想上的跨域类比。**

> **一句话定位**：Weave 位于模拟设计的 **netlist→schematic 逆向可视化环节**，不属于标准数字 17 阶段流程。如果把数字流程的 LVS（阶段 ⑫，从版图提取网表与原始网表比对）视为概念最近的类比，Weave 的 round-trip verify 是从原理图提取网表与原始 SPICE netlist 比对——方向相反但思想相通。

## 3. 输入 / 输出

### 3.1 输入

输入是一份标准 **SPICE netlist 文本**，覆盖以下元件类型：

| 类别 | 元件 | 说明 |
|---|---|---|
| 无源器件与独立源 | R, C, L, V, I, D | 电阻、电容、电感、独立电压源、独立电流源、二极管 |
| 有源器件 | Q, M, J | 双极型晶体管（BJT）、MOSFET、JFET（含衬底折叠处理） |
| 子电路 | X | 带参数尾部的子电路调用 |
| 受控源 | E, F, G, H | 电压控电压源、电流控电流源等 |
| 行为源 | B | 任意行为表达式源 |
| 开关/传输线/耦合/特殊器件 | S, W, T, K, A | 开关、传输线、磁耦合、特殊数字器件 |

支持 SPICE `+` 行连续符自动拼接（多行语句在解析前合并为一行）。

**最小具体示例——RC 带通滤波器（论文 Fig. 3 输入）**：

```spice
V1   N001 0    AC 1
C1   N002 N001 100n
R1   N002 Vout 10k
R2   Vout 0    10k
C2   Vout 0    100n
```

**更大规模的示例——32 元件 RLC 阶跃响应网络（论文 Fig. 4，节选）**：

```spice
V1 N004 0 10
L1 N005 N006 30m
R1 N004 N005 34.64
C1 N006 0 100u
L2 N007 0 30m
R2 N007 0 8.66
C2 N007 0 100u
I1 0 N007 10
V2 N009 0 10
L3 N010 N011 30m
R3 N009 N010 100
C3 N011 0 100u
...（共 32 个元件）...
V4 N001 0 SINE(0 1 91.93)
.tran 0 50ms 0 0.05ms
+ startup
```

评测使用的两个数据集均用 **LTspice 自身**导出网表（`XVIIx64.exe -netlist`），避免循环论证——Weave 的输入来自 LTspice，而非 Weave 自己的解析器：

- **Circuits-LTSpice（117 个）**：Schemato 使用的公开测试集，平均 11 元件/电路（中位数 9，最大 39），73% 的电路超过 5 个元件。
- **Analog Devices LTspice Demo（3460 个）**：LTspice 官方 demo 电路集（2026-07-01 抓取），平均 14.4 元件/电路（最大 138），包含大量 Circuits-LTSpice 中没有的密集多 pin 电源模块。

### 3.2 中间产物

Weave 的中间产物是流水线内部的图结构和坐标数据，不对外暴露为文件：

- **Net 分类结果**：每个 net 被标记为 ground / supply rail / signal
- **分层布局图**：elkjs 输出的节点位置和边路由坐标（16-unit grid 对齐）
- **Placement pattern 放置坐标**：反馈环、分压腿等图外元件的相对位置

### 3.3 输出

**主要输出：LTspice .asc 原理图文件**

- `.asc` 是 LTspice 的原生 ASCII 原理图格式，描述符号位置、走线坐标、flag 标签等图形元素
- 地和电源轨以 **flag**（局部连接标签，同名即电气连通）呈现，不画实线；只有 signal net 以正交走线出现在图上
- 所有坐标对齐到 LTspice 16 单位网格，确保 pin 坐标精确
- 器件符号从内嵌的 5093 个符号 pin 表中查表获取几何信息；未知器件用等尺寸矩形 generic block

**伴随输出：round-trip 验证结果**

- **MATCH**：从 .asc 反解出网表后，与原输入逐 net 二进制分区比对完全一致。等价于 GED = 1.0，但作为**二值证书**在生成时刻颁发，不是相似度估计。
- **partial**：连通性存在差异，报告具体哪些 net 不同。.asc 仍可下载和打开，但连通性未通过验证。
- **转换错误**：safe-mode ladder 全部降级后仍无法生成有效 .asc。主要来自 LTspice 符号库中缺失的新版器件。

**输出示例概念（论文 Fig. 3 的 RC 带通滤波器）**：

```text
原理图层级结构（ASCII 示意）：
┌──────┐    ┌──────┐
│  V1  │───→│  C1  │───→ R1/R2/C2 节点 ──→ Vout
│ AC 1 │    │100n  │    (正交走线, 左→右信号流)
└──────┘    └──────┘
GND flag    signal net    supply/output flags
```

更大规模的 32 元件 RLC 阶跃响应网络（论文 Fig. 4-5，超出 Schemato 的 5 元件阈值 6 倍以上）同样生成平衡布局并通过 round-trip 验证。

## 4. 方法与架构

> Weave **不是神经网络、不是 LLM、不需要训练**。它是一个确定性的 netlist→schematic 转换流水线。核心理念："正确性由构造保证，并由验证器确认"。

### 4.1 整体 Pipeline（对应论文 Figure 1）

```text
                    SPICE Netlist（文本）
                           │
                           ▼
              ┌─────────────────────────┐
              │  ① Parse（解析）          │  ← 覆盖标准 SPICE 元件集
              │     拼接行连续符 + 提取器件  │     R/C/L/V/I/D/Q/M/J/X/E/F/G/H/B/S/W/T/K/A
              └────────────┬────────────┘
                           ▼
              ┌─────────────────────────┐
              │  ② Classify Nets：        │
              │  ground / supply / signal │  ← 地/电源 → flag 标签（不进布局图）
              └────────────┬────────────┘   signal → 进入布局图
                           ▼
              ┌─────────────────────────┐
              │  ③ Layered Layout (elkjs) │  ← Sugiyama 分层算法，左→右流向
              │     去环→分层→排序→定位    │    正交走线，pin 对齐 16-unit grid
              └────────────┬────────────┘
                           ▼
              ┌─────────────────────────┐
              │  ④ Placement Patterns：    │  ← 图外处理四类特殊结构
              │  反馈环/分压腿/shunt/电源角 │    pattern 走线带 net 标签供验证
              └────────────┬────────────┘
                           ▼
              ┌─────────────────────────┐
              │  ⑤ Emit .asc：            │  ← 坐标映射为 .asc symbol/wire
              │  grid snap + 正交布线       │    内嵌 5093 符号 pin table
              └────────────┬────────────┘
                           ▼
              ┌─────────────────────────┐
              │  ⑥ Round-trip Verify：     │  ← 反解 .asc → netlist
              │  逐 net 二分集合比对        │    完全相同 → MATCH（GED = 1.0）
              └────────────┬────────────┘
                    MATCH  │  partial
              ┌────────────┘
              ▼
    ┌─────────────────────┐
    │  ⑦ Safe-mode Ladder  │  ← partial 时逐级降级重试
    │  逐级降级, 每级经验证   │    保留第一个 MATCH 结果
    └─────────────────────┘
```

### 4.2 核心模块详解

**模块 ① 解析（Parsing）**

做什么：将 SPICE netlist 文本解析为结构化元件列表。

为什么这样设计：SPICE 是模拟电路仿真的行业标准格式，覆盖这套元件集能处理绝大多数实际电路。行连续符处理是工程细节——SPICE 中长参数行（如传输线 `Td=50n`）经常需要折行。

输入：原始 SPICE netlist 文本（含换行符、注释、`+` 续行符）。

输出：结构化的元件列表（每个元件含类型、名称、节点列表、参数）。

**模块 ② Net 分类（Net Classification）**

做什么：将每个 net 分类为 ground、supply rail、signal 三类。

为什么这样设计：图布局只画 signal net，地和电源以 flag 标签形式呈现。这极大简化了布线空间——地的连接点可以散布在图上各处而不需要贯穿整图的线。这是模拟原理图绘制中的常见习惯（用 GND/VCC 符号而非实线），Weave 将其自动化。

**模块 ③ 分层图布局（Layered Layout with elkjs）**

做什么：将 signal 元件抽象为图节点，用 elkjs 的 Sugiyama 分层算法进行布局。

Sugiyama 框架的四个步骤：
1. **Cycle Removal**：检测并反转反馈边，使剩余图为有向无环图（DAG）
2. **Layer Assignment**：将节点分配到水平层级（层级方向 = 信号流方向，左→右）
3. **Crossing Minimization**：在每个层级内排序节点以最小化边交叉
4. **Position Assignment**：分配纵坐标

elkjs 保证节点盒不重叠、边正交、所有端口对齐到 LTspice 16-unit 网格。节点尺寸编码符号本体 + 预留 pin escape/flag stub 空间。

为什么选 elkjs：经典 ASG 方法手写布局启发式（Swinkels & Hafer [3]、Jehng et al. [4]）通常"settle for a good rather than an optimal arrangement"——因为自己实现完整的 Sugiyama 框架工程量大且容易出 bug。elkjs 是 Eclipse 基金会的成熟工业级实现，可以编译为 JavaScript 在浏览器运行，Weave 用它替代了手写启发式，获得了更好的布局质量保证。

**模块 ④ Placement Patterns（图外模式化放置）**

做什么：四类结构不在分层图内处理，而是在图外以 placement pattern 放置：

- **局部/远端反馈**（local/far feedback around amplifiers）：反馈元件放置在放大器旁边，走线直接连接
- **分压支路**（divider legs to ground/rail）：分压电阻垂直排列，一端接主信号节点，一端接地/电源 flag
- **悬垂 shunt**（hanging shunts）：并联到地的元件直接接地 flag
- **供电角**（supply corners）：电源去耦电容等

为什么这样设计：这些结构如果强制塞进分层图会破坏主信号链的清晰度。例如，运放的反馈电阻应该紧挨着运放符号放置，而不是被 Sugiyama 算法排到某个"最优"图位置。每个 pattern 的走线都带 net 标签，供 verifier 审计。

这直接继承了经典启发式 ASG 的思想 [Swinkels & Hafer 1990; Arsintescu 1996]，但结合了现代图布局引擎的全局优化能力。

**模块 ⑤ 符号表与 Generic Fallback**

做什么：Weave 内嵌 5093 个 LTspice 符号的 pin offset 与 SpiceOrder 索引。当网表调用未知器件或 pin 数不匹配时，用等尺寸矩形 generic block 占位。

为什么这样设计：Schemato 论文自述的数据稀疏问题——训练数据中过半元件出现次数 < 10 次，无法可靠放置不熟悉器件。Weave 的查表 + generic fallback 将"符号几何"与"连通性"解耦：连通性是图算法决定的（不走概率），几何是查表决定的（不受训练数据限制）。即使器件在表中缺失，连通性依然正确。

**模块 ⑥ Round-trip 连通性验证**

做什么：这是 Weave 正确性声明的核心。

验证流程：
1. 解析 .asc 文件：union wire 端点、flag、symbol pin 坐标重合的连通分量
2. 将连通分量划分为 net 集合（每个 net = 一组电气连通的 pin/端点）
3. 将原始 netlist 也划分为 net 集合
4. 逐 net 二进制分区比对：两个分区完全相同 → MATCH；否则报告差异

论文确认验证器非空：删除一条 wire 会触发 mismatch，修改 netlist 中一个 net 也会触发 mismatch。117 电路集的 100% MATCH 是真实的连通性等价，不是验证器接受了所有输出。

**模块 ⑦ Safe-mode Ladder（安全模式梯子）**

做什么：当默认布局模式无法生成连通性正确的原理图时，逐级降级重试。Ladder 的 rung：

```
Rung 0: 默认布局（所有 placement patterns 激活）
Rung 1: 禁用反馈 pattern
Rung 2: 禁用分压 pattern
Rung 3: 纯 elkjs 布局（所有 pattern 禁用）
Rung 4: 加宽通道间距（最后手段）
```

每级都经 verifier 过滤，保留第一个 MATCH 结果。

关键性质：因为正确性由 verifier 门控，更高 rung 的结果可能视觉上更朴素，但 MATCH 永远不会错。

### 4.3 模块职责矩阵

| 模块 | 输入 | 输出 | 核心工具 | 是否需训练 |
|---|---|---|---|---|
| Parse | SPICE netlist 文本 | 结构化元件列表 | 自定义 SPICE 解析器 | 否 |
| Net Classification | 结构化元件列表 | net 分类表（ground/supply/signal） | 规则引擎 | 否 |
| Layered Layout | signal 元件节点 | 节点坐标 + 边路由路径 | elkjs (Sugiyama) | 否 |
| Placement Patterns | 已布局节点 + 特殊结构识别 | pattern 元件坐标 + wire | 确定性模式匹配 + 相对坐标 | 否 |
| Emit .asc | 所有坐标 + 符号信息 | .asc 文件 | 符号 pin table (5093 条) | 否 |
| Round-trip Verify | .asc + 原始 netlist | MATCH / partial + 差异报告 | 自定义连通性提取 + 集合比对 | 否 |
| Safe-mode Ladder | 全部前述模块 | 最终 MATCH .asc 或 partial | 重试控制器 | 否 |

## 5. 关键公式与定义

Weave 是一篇系统/工具论文，侧重于工程实现和实验验证，未提供编号方程。以下定义出其核心机制的形式化表述，以利于理解其工作原理。

### 5.1 Round-trip 连通性等价定义

设输入 netlist 的 net 分区为 N_in，生成 .asc 反解析出的 net 分区为 N_out：

$$
\mathcal{N}_{\text{in}} = \{n_1, n_2, \ldots, n_k\}
$$

$$
\mathcal{N}_{\text{out}} = \{m_1, m_2, \ldots, m_l\}
$$

其中每个 net n 是电气连通节点集合（器件 pin + wire 端点 + flag 标签的连通分量）。

$$
\text{MATCH} \iff \mathcal{N}_{\text{in}} = \mathcal{N}_{\text{out}}
$$

- $\mathcal{N}_{\text{in}}$：原始 SPICE netlist 的 net 分区集合
- $\mathcal{N}_{\text{out}}$：从生成 .asc 反解出的 net 分区集合
- $n_i, m_j$：单个 net（电气连通分量）
- $k$：输入 netlist 的 net 数
- $l$：反解出的 net 数

**工程直觉**：net 分区是 connectivity 的最精确表达——两份 netlist 如果 net 分区完全相同，意味着所有元件之间的电气连接关系完全一致，不遗漏、不多余、不错接。这不是"相似"或"接近"，是集合相等。MATCH 等价于 GED = 1.0（图编辑距离为 1.0 表示两张图完全相同），但作为**二值证书**在生成时刻给出。

### 5.2 编译率

$$
\text{CR} = \frac{|\{\text{generated .asc opens in LTspice}\}|}{|\{\text{all input netlists}\}|}
$$

- $\text{CR}$：Compilation Rate，编译率
- 分子：LTspice 能成功打开的 .asc 数
- 分母：全部输入网表数

**与 MATCH 率的关系**：编译率 $\geq$ MATCH 率。一份 .asc 可能编译成功（语法正确、符号合法、LTspice 可打开），但 round-trip 验证发现连通性差异（partial）。Weave 在 117 电路集上两者相等（均为 100%），在 3460 电路集上编译率 96.7%（= 100% - 3.3% 转换错误），MATCH 率 88.4%。

### 5.3 Safe-mode Ladder 的形式语义

设有降级布局模式序列 $\mathcal{M}_0, \mathcal{M}_1, \ldots, \mathcal{M}_m$，其中 $\mathcal{M}_0$ 为默认模式（最丰富的 placement pattern），$\mathcal{M}_m$ 为最简模式（纯 elkjs + 最大通道间距）。验证器 $\text{Verify}(N, M) \in \{\text{MATCH}, \text{partial}\}$ 在模式 $M$ 下评估输入 netlist $N$。

$$
\text{Weave}(N) = \text{output}(\mathcal{M}_{i^*}, N), \quad i^* = \min\{i \mid \text{Verify}(N, \mathcal{M}_i) = \text{MATCH}\}
$$

- $\mathcal{M}_i$：第 $i$ 级布局模式
- $i^*$：第一个达成 MATCH 的模式索引
- $\text{output}(\mathcal{M}_i, N)$：模式 $\mathcal{M}_i$ 对 $N$ 的生成结果

**关键不变量**：对于任意 $i$，若 $\text{Verify}(N, \mathcal{M}_i) = \text{MATCH}$，则该输出的连通性绝对正确。不同 $i$ 之间的差异仅在布局的美观程度上——$i$ 越大，布局越朴素但同样正确。

## 6. 训练与实验设置

### 6.1 是否需要训练

**不需要训练。** Weave 是一个纯推理时的确定性工具，不对任何模型参数进行更新。它不依赖 GPU、不采样、不微调。所有行为由以下固定资源决定：

- 固定的 SPICE 解析规则（正则匹配 + 状态机）
- 固定的 elkjs 分层布局算法（Sugiyama 框架）
- 固定的 LTspice symbol pin 表（5093 条硬编码记录）
- 固定的布线、反解与 net 对比逻辑

Weave 运行在浏览器中（elkjs 编译为 JavaScript 在客户端执行），也有 Node.js 命令行工具用于批量转换和基准测试。

### 6.2 实验设置

**Benchmark 1：与 Schemato 头对头对比**

使用 Schemato 论文使用的公开测试集——**Circuits-LTSpice 仓库**。Weave 严格遵循 Schemato 的方法论：

- 从仓库的 `.asc` 文件出发，用 LTspice XVII 17.0.36.0 自身导出网表（`XVIIx64.exe -netlist`）
- 符号缺失的电路被排除（与 Schemato 相同），最终 **117 份**有效网表
- 117 个电路的平均元件数 11（中位数 9，最大 39），其中 **86 个（73%）超过 5 个元件**——正是 Schemato 论文自述连通性精度下降的区域

**Benchmark 2：大规模 Analog Devices LTspice Demo**

使用 LTspice 官方 demo 电路集（2026-07-01 从 Analog Devices 网站抓取）。原始 3610 个 `.asc` 电路，经 LTspice XVII 17.0.36.0 网表化后得到 **3460 份**有效网表。

| 统计量 | 值 |
|---|---|
| Source .asc circuits | 3610 |
| Netlistable | 3460 |
| Total circuit elements | 49,791 |
| Elements per circuit (mean) | 14.4 |
| Elements per circuit (median) | 12 |
| Elements per circuit (max) | 138 |
| 2–5 elements | 261 circuits |
| 6–10 elements | 1274 circuits |
| 11–20 elements | 1274 circuits |
| 21–50 elements | 615 circuits |
| 51+ elements | 36 circuits |

**评估指标**：

- **编译率（Compilation Rate）**：生成的 .asc 能被 LTspice 成功打开的比例
- **Round-trip MATCH 率**：.asc 反解出的网表与原输入逐 net 完全等价的比例（二值判定）
- **Partial 率**：生成成功但 round-trip 验证发现连通性差异的比例
- **转换错误率**：无法生成有效 .asc 的比例

Weave 的核心指标是 **round-trip MATCH**，不接受近似相似度分数（GED/MSSIM）。这与其他方法的评估哲学根本不同。

**Baseline 方法**：

| 方法 | 类型 | 指标 | 基础架构 |
|---|---|---|---|
| Schemato [2] | LLM 微调 | GED 相似度 + 编译率 | 8 GPU |
| GPT-4o | 通用 LLM | 编译率 | API |
| Weave | 确定性工具 | 编译率 + round-trip MATCH | 浏览器/CLI |

### 6.3 关键实验结果

**主实验：Circuits-LTSpice 117 电路头对头对比（论文 Table II）**

| 指标 | Schemato | GPT-4o | Weave |
|---|---|---|---|
| 编译率 | 76% | 63% | **100%** |
| 连通性 / 相似度 | GED 0.35 | GED 0.23 | **100% exact MATCH** |
| 正确性保证 | 无 | 无 | **每输出 round-trip 验证** |
| 基础架构 | 8 GPU | API | **浏览器 / CLI** |

**这张表说明什么**：在完全相同的 117 电路测试集上，Weave 以 100% 编译率和 100% 连通性等价碾压 Schemato 的 76% 编译和 0.35 GED。更关键的是，117 个电路中 86 个（73%）超过了 Schemato 自述的 5 元件阈值——这意味着 Weave 不仅在领域内（小电路）赢，在 Schemato 明确承认能力下降的区域（>5 元件）也全部通过。Weave 还确认了验证器非空：删除 wire 或修改 net 会触发 mismatch。

**大规模评测：Analog Devices LTspice Demo 3460 电路**

| 结果 | 数量 | 比例 |
|---|---|---|
| Round-trip verified MATCH | 3060 | **88.4%** |
| Partial（连通性差异，可下载） | 285 | 8.2% |
| 转换错误 | 115 | 3.3% |

**这张表说明什么**：在更困难、规模更大的数据集上，Weave 仍然维持了 88.4% 的 MATCH 率。失败高度集中在两类：
- **密集多 pin 电源模块**（占 partial 的大多数）：大型稳压器等器件的 pin 多、net 复用率高，分层布局在 pin 密度大的区域出现走线冲突
- **LTspice 版本缺失符号**（占转换错误的多数）：表内 5093 个符号无法覆盖 LTspice 新版引入的器件

## 7. 创新点

### 创新点 1：确定性验证优先（verification-first）流水线

已有学习式方法（Schemato、Hsu & Lin 的 RL）是"生成 → 打分"模式——生成原理图后用 GED/MSSIM 等连续相似度指标评价。Weave 的流水线是"构造 → 验证"模式——连通性由确定性算法从 netlist 直接构造，然后用 round-trip verifier 颁发二值证书。

与 Schemato 的本质区别在于问题分解方式：
- **Schemato**：端到端微调 LLM 学习从 netlist 文本直接输出 .asc 文件，连通性和符号几何一起学。当元件数增加时，生成空间指数增长，模型精度急剧下降
- **Weave**：连通性是图算法决定的（不走概率），符号几何是查表决定的（不受训练数据限制），两者解耦

代价是 Weave 目前不优化视觉美学指标（交叉数、弯折数、对称性），论文将此诚实定位为 future work。

### 创新点 2：Round-trip 连通性验证——E2E 二值正确性证书

在 ASG 历史上，这是第一个对每个生成原理图做 round-trip 连通性验证的系统。以前的验证层停留在"能打开吗？""像不像？"的层面。

验证器的设计要点：
- **二值而非连续**：MATCH vs partial，不是 0.35 GED 这样的分数
- **生成时刻颁发**：不是事后用外部工具评测，而是作为 pipeline 的一部分在生成时刻运行
- **非空**：论文明确验证了删除 wire/修改 net 会触发 mismatch，100% MATCH 不是验证器接受了所有输出
- **完整等价**：等价于 GED = 1.0——输入和生成的连通性图完全相同

### 创新点 3：Safe-mode Ladder——不牺牲正确性的降级策略

大多数工具在"做不出来"时直接报错或输出错误结果。Weave 的 safe-mode ladder 是一种正确性优先的降级策略：用更朴素但保证正确的方式做出来。

工程价值：用户拿到 MATCH 结果时有绝对的连通性信心——不管原理图多朴素，连通性是对的。这在工程工作流中比"可能漂亮但连通性不确定"更可依赖。

### 创新点 4：内嵌符号表 + Generic Fallback——解耦几何与连通性

5093 个 LTspice 符号的 pin 表 + generic block fallback 直接解决了学习式方法的数据稀疏问题。Schemato 的训练数据中过半元件出现 < 10 次，因此不可靠地放置不熟悉器件。Weave 不"学习"符号几何——它查表。查不到就用矩形 block——损失的是美观，不是正确性。

### 创新点 5：全客户端零依赖运行

Weave 以单个 JavaScript 文件在浏览器中运行，也有 Node.js CLI。不需要 GPU、不需要 API key、不需要安装依赖（除了 Node.js 运行环境本身）。对比 Schemato 需要 8 GPU、GPT-4o 需要 API 调用。这使得 Weave 可以离线工作、零成本批量处理、嵌入到其他 EDA 工作流中。

## 9. 与芯片流程的关系

### 9.1 模拟设计的独特性再强调

数字芯片 17 阶段流程（参照 [芯片流程.md](../芯片流程.md)）是为**标准单元 + RTL-to-GDSII** 方法论设计的。模拟设计使用完全不同的流程：

| 数字流程特征 | 模拟流程特征 |
|---|---|
| RTL 描述行为 | Schematic 才是设计表述 |
| 逻辑综合自动生成门级网表 | 拓扑选择和器件尺寸由工程师决定 |
| 标准单元库（离散选择） | 连续设计空间（W/L、偏置电压等） |
| STA 验证时序 | SPICE 仿真验证电路行为（增益、带宽、噪声...） |
| P&R 自动布局布线 | 版图通常手工绘制 |
| 百万门规模 | 几个到几百个元件 |

Weave 不落入 17 阶段的任何一个，因为它做的是模拟设计链中的**逆向可视化**任务——如第 2 节所述，它把 netlist 变回 schematic，在正向设计流程中没有对应步骤。

### 9.2 这项任务的工程动机

netlist→schematic 的逆向转换在三个场景中有实用价值：

1. **ML 生成电路的审查**：AI/RL 方法直接输出 SPICE netlist 后，工程师需要原理图来审查和信任生成结果。netlist 是纯文本，20 个元件以上的电路肉眼几乎无法理解拓扑。
2. **遗产网表恢复**：老项目的 netlist 还在但原始 .asc 原理图丢失——逆向重建可读原理图。
3. **跨工具迁移**：从其他 SPICE 仿真器（HSPICE、Spectre）的 netlist 迁移到 LTspice 时自动生成原理图。

### 9.3 这项任务的独特性与难度

**大多数 EDA 工作是正向的**（schematic → netlist），Weave 是逆向的（netlist → schematic）。两项独特难点：

- **布局美观性没有唯一标准**：同一份 netlist 可以画出完全不同的原理图——横排 vs 竖排、反馈环画上面 vs 下面、分压支路放左边 vs 右边——都是"对"的。但工程师对"好"原理图有强烈但难以形式化的审美判断（信号流左→右、反馈环画成闭合 U 形、差分对对称放置）。Weave 选择了一个务实立场：**先保证 100% 对，再尽量好看**。
- **信号流方向需要从 netlist 推断**：netlist 只有节点编号（N001, N002...），没有"信号从哪里流向哪里"的语义。Weave 通过 Sugiyama 分层布局隐式推断信号流——无需用户标注输入/输出方向。

### 9.4 与同批论文的对比定位

| 论文 | 任务方向 | 输入 → 输出 | 方法 | 与 Weave 的关系 |
|---|---|---|---|---|
| **SINA** | 正向识别 | schematic image → SPICE netlist | ML（目标检测 + OCR） | 方向相反：SINA 把"图"变"文本"，Weave 把"文本"变"图" |
| **CircuitWeave** | 多模态生成 | schematic + text → RTL | 多模态 LLM | schematic 是输入；Weave 的 schematic 是输出 |
| **Weave** | 逆向可视化 | SPICE netlist → LTspice schematic | 确定性图布局 + round-trip 验证 | 唯一的逆向任务，唯一不依赖 ML 的方案 |

## 10. 讨论与局限

### 10.1 论文自述的局限

1. **密集多 pin 电源模块导致 partial**：3460 电路集中 8.2% 的 partial 结果高度集中在多 pin 稳压器/电源模块——pin 多、net 复用率高，当前分层布局在 pin 密度大的区域出现走线冲突
2. **深层级联拓扑被拉长**：多级放大器等深级联结构在分层布局中形成长链——连通性正确但视觉紧凑度差
3. **不优化视觉美学指标**：论文定位为"连通性优先"，未主动优化交叉数、弯折数、对称性等
4. **Symbol 表覆盖有限**：5093 个符号受限于嵌入表，3.3% 的转换错误多来自 LTspice 新版器件的符号缺失
5. **输出格式绑定 LTspice .asc**：扩展到 KiCad/EAGLE/OrCAD 等其他原理图格式需要额外工作

### 10.2 论文提出的未来方向

1. **Box-contract hierarchical layout**：把反馈环和密集模块作为固定大小节点纳入图布局联合优化，取代当前的图外 pattern 处理。论文认为这可以同时解决 dense power module partial 问题和级联拓扑紧凑性问题
2. **美学指标引入**：在保持 MATCH 的前提下，优化交叉、弯折、对称性等指标
3. **符号表扩展**：支持更新或用户自定义符号

### 10.3 本资料包的分析

**GED = 1.0 vs "好看"的张力**：Weave 打通了连通性正确性这条路，但工程可用性的另一半——美观——目前是盲区。如果一份 netlist→schematic 工作需要工程师花同样多的时间重新布局才算"可读"，其实用价值大打折扣。论文把美观留给未来的 hierarchical layout 方向，这是一个诚实但"未完"的定位。

**验证范围仅限于连通性**：Round-trip 验证不检查仿真结果一致性（同激励下输出波形是否相同）、不检查器件参数值（100n vs 100u）、不检查 SPICE 模型层级。一个通过连通性验证的 .asc 可能因为模型路径缺失而无法仿真——但这不在 Weave 的责任范围内。

**Safe-mode Ladder 的隐含代价**：当降级到纯 elkjs 布局时，生成原理图可能失去信号链的语义可读性——所有元件排成抽象的"好图"，但丢失了放大器、偏置、反馈的工程直觉分组。safe-mode ladder 保证了一个 MATCH，但不保证可读。

**117 电路 100% 的合理解读**：Circuits-LTSpice 是 Schemato 使用的测试集，117 个电路规模适中（平均 11 元件）。这个 100% 不意味着 Weave 能处理所有电路——3460 电路集上的 88.4% 才是更真实的边界。不过 100% vs 0.35 GED 的对比仍然清晰展示了确定性方法在连通性上对概率方法的**结构性优势**——不是"稍好一点"，而是概念层面的不同（二值正确 vs 连续相似）。

**方法论的推广价值**：论文认为 "correctness by construction with verification" 的思路不限于 LTspice。任何需要从结构化文本生成可视化表示并保证语义正确性的 EDA 任务——将 SPICE/HSPICE/Spectre netlist 转成 KiCad/EAGLE 原理图——都可以复用这个 "parse → layout → verify" 的流水线架构。

**代码与符号表问题**：

- 代码仓库未包含开源许可证（本地核验时未检测到 LICENSE 文件），需在使用前单独确认再分发权利
- 内嵌的 5093 个符号 pin table 未提供外部更新机制，LTspice 版本升级后符号表可能逐渐过期
- 工具依赖 elkjs（Eclipse 开源项目，EPL 许可证），无其他运行时依赖

## 12. 一分钟复述版

Weave（Senol Gulgonul，Ostim Technical University，arXiv 2026.07）是一个**确定性的 SPICE 网表转 LTspice 原理图工具**，不需要训练、不需要 GPU、浏览器单文件运行。核心三招：

1. **分层图布局**：用 elkjs（Sugiyama 框架）将电路元件按左→右信号流方向分层排列，节点不重叠、走线正交，同时用 placement patterns 在外围处理反馈环、分压腿等特殊结构，避免破坏主信号链的清晰度
2. **Round-trip 验证**：每个生成的 .asc 被重新解析为网表，与原始输入逐 net 二进制分区比对——完全一致才输出 MATCH（等价于 GED = 1.0）。这不是相似度打分，是二值正确性证书
3. **Safe-mode Ladder**：验证不通过时逐级降级布局模式（禁用 pattern → 纯 elkjs → 加宽通道），每级经 verifier 过滤——MATCH 永远不会错，只会更朴素

实验结果：117 电路测试集（Schemato 的 benchmark）上 **100% 编译 + 100% MATCH**（Schemato: 76% 编译, GED 0.35），且 73% 的电路超过 Schemato 自述的 5 元件精度下降阈值；3460 电路大规模集上 **88.4% MATCH**。失败集中于密集多 pin 电源模块和 LTspice 新版符号缺失。

**边界**：模拟领域工具，不涉及数字 17 阶段中的任何一个；验证范围仅限连通性（不检查仿真结果/参数值/模型路径）；不优化视觉美学（交叉/弯折/对称）；输出格式绑定 LTspice .asc；CODE LICENSE 待确认。
