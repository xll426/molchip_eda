## 1. 一句话定位

**SpecAlign 是一个针对 LLM 生成 SVA（SystemVerilog Assertions）的语义对齐评估与迭代精化框架，核心反直觉发现是「JasperGold 证明成功 ≠ 语义正确」——在 APB+UART 两个设计上跑 AssertionForge 总共生成了 767 条 SVA，其中 JasperGold 证明成功的 101 条里 SpecAlign 仍判出 46 条（45.5%）与自然语言规范相矛盾；引入推理链式思维（CoT）+ 多路径自一致投票机制后，运行 3 轮 Property / SVA 双层对齐循环把 APB 的矛盾断言从 148 → 0、UART 从 142 → 6，entailing 断言从 8/21 提升到 66/92。** 论文同时定义了 ENTAILS / CONTRADICTS / UNKNOWN 三态分类、Alignment Score 量化指标，以及自动生成「可操作的反馈供 LLM 重新生成」的 Inconsistency Analysis 机制，全部流程**不依赖 golden RTL**，可在缺乏参考实现时替代或补充 JasperGold 类形式验证评估。

这句话里的 N 个技术承重点：

1. **「JasperGold Proven 不等于语义正确」是论文立论基石** — 论文 Table I 的实证数据：JasperGold 标 Proven 的 101 个样本中，55 个 SpecAlign 标 Entails、46 个标 Contradicts（论证观点成立：FV prove 不能担保语义）。同时 JasperGold 标 CEX 的 129 个样本中，23 个 SpecAlign 仍标 Entails（说明 FV 报 CEX 的断言反而可能语义正确，是 RTL 错了）。这种「FV 指标与语义指标脱钩」的二阶分析是文章最尖锐的发现
2. **三态对齐分类（CONTRADICTS / ENTAILS / UNKNOWN）** — 不同于 FV 的二态（proven/cex），SpecAlign 引入第三类「Unknown」专门表示「Spec 不提供足够信息判断」的 implementation-specific 假设（reset 行为、信号稳定性、时序约束等），这避免了把不确定断言「强行归类为错误」
3. **两个循环组成双层对齐架构** — Property Alignment Loop（PROPERTY → SPEC）与 SVA Alignment Loop（SVA → PROPERTY BANK）。前者先提取自然语言属性、对齐规范；后者再把生成的 SVA 转回自然语言、和已对齐的属性库比对。两层都跑相同的 3 阶段（Alignment Check → Evidence Extract / Inconsistency Analysis → Refinement）
4. **CoT + 自一致投票机制** — 每个自然语言描述 Xi 在分类时采样 k 条推理路径产生 sub-verdict vi,j ∈ {0,1,2}，再多数投票出最终 Vi。投票平票时按「CONTRADICTS > UNKNOWN > ENTAILS」顺序选最保守的解释，论文实验 k=3
5. **可操作反馈生成（Inconsistency Analysis）** — 当分类为 CONTRADICTS，LLM 被 prompt 成「资深 DV 工程师」去识别 SVA 行为意图 → 找出与 SPEC 矛盾的元素 → 引用 SPEC 原文 + 章节号给正确行为 → 提供 LLM-regeneration 可直接使用的反馈
6. **NL Summary Extraction 把 SVA 抬高回 NL** — 显式抽取 TRIGGER / disable iff / ANTECEDENT / IMPLICATION OP / CONSEQUENT 五个 SVA 组件，并用一句 NL 描述整个 SVA。这是把「形式化 SVA」降到「自然语言」的关键步骤，使 SVA 和 SPEC 能进入同一个 entailment 判定空间
7. **Alignment Score AS = E / n 作为可量化指标** — 论文核心指标，无 golden RTL 也能算。APB 从 AssertionForge 的 0.02 → SpecAlign 的 0.15；UART 从 0.06 → 0.28。该指标把语义对齐从「人工逐条看」变成「自动量化」
8. **不依赖 golden RTL，但能容纳它** — 整套框架在「没有 RTL」时用 SPEC 直接作 reference；若有对齐属性库，SVA Loop 可优先比 Property Bank 而不是原始 SPEC，避免 SPEC 的散落噪声干扰（详见 §4.2）

## 2. EDA 阶段映射（①-⑰）

参照 [芯片流程.md](../芯片流程.md) 的 17 阶段标准编号：

| 阶段 | 覆盖 | 说明 |
|------|:---:|------|
| **① RTL 设计** | ⚠️ **旁邻位置** | SpecAlign 不是 RTL 生成器，它消费 SPEC（自然语言设计说明书）+ 已生成 SVA。RTL 不是它的输入也不是它的输出，但其工作紧贴「已生成 RTL 后的验证规划」阶段 |
| **② RTL 功能仿真** | ❌ | 不做仿真。纯语义对齐 + 形式验证，避免仿真穷举不完备 |
| ③ 逻辑综合 | ❌ | 与综合无关 |
| ④ 门级仿真 | ❌ | 同上 |
| ⑤ STA（静态时序分析） | ❌ | 同上 |
| **⑥ 形式验证** | ✅ **核心** | SpecAlign 是 SVA 验证的「语义级」覆盖。它和 JasperGold 等 FV 引擎是正交关系：FV 判「断言对当前 RTL 是否成立」，SpecAlign 判「断言表达的行为是否在 SPEC 里被支持」。两者结果互为补充 |
| ⑦ 布局规划 (Floorplan) | ❌ | — |
| ⑧ 标准单元摆放 (Placement) | ❌ | — |
| ⑨ 时钟树综合 (CTS) | ❌ | — |
| ⑩ 布线 (Routing) | ❌ | — |
| ⑪ 后仿真 | ❌ | — |
| ⑫ 物理验证 (DRC/LVS) | ❌ | — |
| ⑬ 签核 (Signoff) | ⚠️ **评估目标（间接）** | 用 JasperGold 跑 prove/CEX 是工业验证流程的一部分。SpecAlign 改造的是这些 SVA 在 sign-off 前是否「值得信赖」，所以定位在 sign-off 前的语义质量闸门 |
| ⑭ 流片 | ❌ | 纯算法 + LLM 工作，无 tape-out |
| ⑮ 制造 | ❌ | — |
| ⑯ 封装 + 测试 | ❌ | — |
| ⑰ 芯片到手 | ❌ | — |

**覆盖率：1/17 核心（⑥ 形式验证）+ 1/17 关联（① RTL 设计）+ 1/17 评估目标（⑬ 签核）。** SpecAlign 完全聚焦在「⑥ 形式验证」阶段的 SVA 语义层补充。它**不**评估 RTL 时序 / 综合 / 布线是否正确，只回答「LLM 生成的断言是不是 SPEC 要的」，并把不能从 SPEC 推出的细节标 Unknown。

> ⚠️ **容易误读的边界**：
> - SpecAlign 是 **Spec-Centric 评估器**，不是 SVA 生成器。论文只评价「已有的 SVA」好不好，不负责从零写出 SVA（生成侧的 SOTA 包括 [HierSVA](../HierSVA/论文深度讲解.md)、[AssertionForge]、AssertLLM 等）
> - 论文三个对比 baseline 都基于现有的 LLM 后端（SANGAM / AssertionForge），不与「无 LLM 的传统方法」比较。所以结论是「LLM 流派之间 SpecAlign 更好」，不是「LLM 流 vs 人工写 SVA」的对比
> - 论文 APB/UART 仅 2 个设计 + APB 仅基于开源文档（不是真实芯片），外推性需谨慎。和 [CktFormalizer](../CktFormalizer/论文深度讲解.md)（基于 Lean 的形式化）、[Rtl2lean](../Rtl2lean/论文深度讲解.md)（同方向但目标不同）形成方法学对比
> - SpecAlign 用 **GPT-5**（OpenAI）作为 LLM 后端，闭源模型 + 闭源商业 FV 工具（JasperGold）。复现时这两个门槛要齐备

## 3. 输入 / 输出

### 3.1 输入

**(a) 设计规范文档 S（自然语言 + 表格 + 图）**

```text
来源：OpenCores APB-to-I2C 接口规范（12 页，2746 tokens via cl100k_base tokenizer）
     + SANGAM 论文 [5] 提供的 UART-to-Bus 接口规范（10 页，3160 tokens）

内容示例（APB 节选）：
- APB 接口时序：SETUP 阶段（1 周期）→ ENABLE 阶段（1 周期）→ 主设备驱动 PADDR/PSEL/PWRITE
- I2C 接口时序：START 条件（SDA 拉低而 SCL 高）→ 地址阶段（7-bit 地址）→ 数据阶段
- 中断行为：INT_RX 在 RX FIFO 空时被置高；INT_TX 在 TX 完成时被置高
- 复位行为：低电平异步复位（ARST_LVL），由 wb_rst_i 和 arst_i 控制

注：tokens 用 CL100K_BASE tokenizer（即 GPT-5 / GPT-4o 那一族）估算。
```

**(b) LLM 已经生成的 SystemVerilog 断言集 A = {A1, ..., An}**

这是「待评估」的输入。来自任意外部 SVA 生成器（AssertionForge、SANGAM、AssertLLM 等），既不要求语法完美也不要求先 run 过 FV。

**(c) LLM 已经生成的自然语言属性集 P = {P1, ..., Pn}（可选）**

如果 SVA 生成流程里有「先提 NL 属性再写 SVA」这一步，P 直接可用。否则 SpecAlign 的 Property Alignment Loop 会从 A 反向提取 P（A → NL Summary）。

**(d) 三个 LLM 调用配置超参**

- 推理 LLM：GPT-5（high reasoning effort）
- 自一致采样路径数：k = 3
- 最大精化迭代数：maxIter = 3（Property Loop 与 SVA Loop 各自独立计数）
- 输出维度：sub-verdict ∈ {0,1,2} 单字符

### 3.2 中间产物

**(a) 自然语言描述 Xi（每条 SVA 的 NL 等价表述）**

抽取 5 个 SVA 结构组件，转单句 NL 描述。例：

```text
TRIGGER:      @(posedge wb_clk_i)
disable_iff:  arst_i !== ARST_LVL || wb_rst_i
ANTECEDENT:   (none, this is an invariant)
IMPL_OP:      (none)
CONSEQUENT:   !$isunknown(wb_clk_i)

↓ 单句 NL:

"On every positive edge of wb_clk_i, except during reset, the signal wb_clk_i
is never X (unknown)."

这条 NL 是后续 Alignment Checking 的实际比对单元。
```

**(b) 推理痕迹 R = {R1, ..., Rk}（k 条 CoT 路径）**

每条路径是一段内部推理文本，描述 LLM 如何把 Xi 和 SPEC 逐节对照、查表 1 找冲突、查 Section 3 找一致等。Appendex A 给出真实例子：

```text
Reasoning Trace Example 1:
"Evaluating interrupt signal. I need to output either 0 or 1 based on
whether the property from the user-provided GLADCI document is met.
They're checking for the condition: 'when the RX FIFO is empty, the INT_RX
interrupt signal is asserted high on the rising edge of PCLK.' In Table 1,
it states the INT_RX output signals when the RX FIFO is empty. Additionally,
Section 3 discusses the module's operation regarding data write operations
after a reset. So, I'll choose either 1 or 0 accordingly."
```

**(c) 对齐裁决 Vi ∈ {CONTRADICTS, ENTAILS, UNKNOWN}**

多数投票结果。CONTRADICTS 优先级最高，投票相同时取保守裁决。

**(d) 结构化反馈 Fi（CONTRADICTS 触发）**

按 SVA BEHAVIORAL INTENT / CONTRADICTING ELEMENTS / CORRECT BEHAVIOR（引用 SPEC 章节）/ FEEDBACK（生成指令）四段组装，是 LLM 重新生成 P 或 A 的直接素材。

**(e) 证据集 Ei（ENTAILS 触发）**

按 BEHAVIORAL INTENT / EXPLICITLY SUPPORTED ELEMENTS / EVIDENCE（直接引语 + 页码）/ ASSUMPTIONS 四段组装。Ei 给人类审阅者用，论文明确说「evidence extraction enables manual review of entailment cases to further validate the results」。

**(f) 对齐属性库（Property Bank）**

每轮 Property Alignment Loop 中对齐（Entails）的 NL 属性都进 Property Bank，下游 SVA Loop 用它比对。

### 3.3 输出

**(a) 三个对齐的 SVA 集合 + 对齐分数**

```text
Outputs (3-iter run, Table III):
┌──────────────┬────────┬──────┬───────┬──────┬──────┐
│ Design       │ Method │#SVA  │ AS    │  E   │  C   │ U   │
├──────────────┼────────┼──────┼───────┼──────┼──────┤
│ APB          │ AF     │ 442  │ 0.02  │  8   │ 148  │ 286 │
│ APB          │ SpecAlign │ 442│ 0.15 │ 66   │   0  │ 376 │
│ UART         │ AF     │ 325  │ 0.06  │ 21   │ 142  │ 162 │
│ UART         │ SpecAlign │ 319│ 0.28 │ 92   │   6  │ 227 │
└──────────────┴────────┴──────┴───────┴──────┴──────┘

AF = AssertionForge baseline; AS = Alignment Score = E/n
```

**(b) 最终对齐属性库（Aligned Property Bank）**

可供后续 SVA 生成流程直接用作「高质量 few-shot 示例」。

**(c) 矛盾断言清单 + 反馈文档（供人工 review）**

`ENTAILS` 个例的「直接证据 + 页码」文档；`CONTRADICTS` 个例的「错误诊断 + 修复指令」文档；`UNKNOWN` 个例的「欠规说明」文档。

## 4. 方法与架构

### 4.1 整体 Pipeline

论文给出 3 张关键架构图：

- **Figure 3**：UART + APB 的 Alignment Score 随迭代轮数的曲线（UART 从 ~0.06 涨到 0.28，APB 从 ~0.02 涨到 0.15，2 轮后基本收敛）

### 4.2 核心模块逐个详解

论文 §IV-B/C/D 给出模块定义。下面按从外到内逐个拆解：

#### 模块 A：Alignment Checking（语义对齐裁决）

- **目的**：判定 NL 描述 Xi 是否与 reference 文档 S（或 Property Bank）一致
- **设计动机**：SPEC 通常很长（APB 2746 tokens / UART 3160 tokens），逐句调用 LLM 必漏点。需要先让 LLM「自己和自己辩论」
- **输入**：Xi（NL 描述）+ reference 文档 + k=3
- **输出**：最终裁决 Vi ∈ {0=CONTRADICTS, 1=ENTAILS, 2=UNKNOWN}
- **关键实现**：
  - 给 LLM 一个 System Prompt 设定角色：「senior digital design verification engineer」
  - 列 5 个内部分析步骤（提取信号 → 行为意图 → 查 SPEC 对应段 → 比较语义 → 决策）
  - 强制输出「exactly one character: 0 or 1」的决策（注意：Appendix B 的实际 prompt 输出只有 0/1，论文 §IV-B 又给出 0/1/2 三态 → 这是论文自述的「可扩展到 UNKNOWN」的版本差异，复现时需确认论文代码实现细节）
  - 采样 k 条推理路径 → 多数投票 → 平票保守规则
- **平票规则**（论文显式定义）：
  - 最保守值优先：CONTRADICTS > UNKNOWN > ENTAILS
  - 即「拿不准就当错」原则，符合「宁可漏检不错杀」的 SPEC 语义目标

#### 模块 B：Inconsistency Analysis（矛盾分析与反馈生成）

- **目的**：把「错的」这条 NL 描述变成「可执行」的修复指令
- **设计动机**：LLM 自反馈（Self-Refine）要靠「specific, actionable feedback」才能涨分（Cotton-Barratt et al., Madaan et al.），但 SPEC 内容散乱，反馈泛泛而谈 LLM 接收不到
- **输入**：Xi + Ri（推理痕迹集）+ reference 文档
- **输出**：四段结构化反馈 Fi，字段：
  1. **SVA BEHAVIORAL INTENT** — SVA 想表达的行为
  2. **CONTRADICTING ELEMENTS** — Xi 里哪些元素与 SPEC 矛盾
  3. **CORRECT BEHAVIOR** — SPEC 里正确的行为（强制引用「direct quotes + page/section numbers」）
  4. **FEEDBACK** — 给 LLM-regeneration 的「具体可操作指令」（不直接修改属性）
- **关键实现**：强制引文 + 不直接改 property 让 LLM 重新生成（避免反馈污染）
- **Appendix C 的真实 prompt 强制要求**：输出 4 个 heading，每个 heading 都不能少

#### 模块 C：Evidence Extraction（证据抽取）

- **目的**：给「对的」这条打证据给人审阅
- **设计动机**：LLM 分类错误难以检测，必须有「可审计」的输出
- **输入**：Xi + reference 文档
- **输出**：四段结构化 Ei（与 Fi 字段一致），区别在于 EXPLICITLY SUPPORTED ELEMENTS / EVIDENCE / ASSUMPTIONS 字段填实
- **关键实现**：提示词明确「design specification may provide conflicting information」——LLM 必须报告冲突
- **工程意义**：ENTAILS case 可直接审计，CONTRADICTS case 提供修复路径

#### 模块 D：NL Summary Extraction（SVA → NL）

- **目的**：把已生成的 SVA 抬回 NL 层，使其能进入 entailment 判定
- **设计动机**：SVA 是形式化表达式（`@(posedge clk) disable iff (...) |-> ...`），LLM 难和 SPEC 直接比较；转 NL 后同一空间
- **输入**：SVA Ai
- **输出**：单句 NL Ni
- **关键实现**：五元组显式抽取
  - TRIGGER（始终）
  - disable iff（可选）
  - ANTECEDENT（可为空 / 可被 `not` 反）
  - IMPLICATION OP（`|->` 与 `|=>`）
  - CONSEQUENT（必须在 OPTIM 窗口内为真）
- **举例**：Appendix F 的真实示例
  ```text
  Input:  @(posedge CLK) disable iff (RESET == 0) (WRITE == 1 && DATA == 0)
          |=> ##[1:2] SIGNAL == 0
  Output: "On the positive edge of CLK except when RESET is 0, if WRITE is
          1 and DATA is 0 then within 1-2 cycles SIGNAL is 0."
  ```
- **强约束**：输出「only one sentence claim, DON'T reference sva id, DON'T give any other text」。是 prompt engineering 的 nice case study

#### 模块 E：Alignment Score AS

- **目的**：把对齐质量量化
- **设计动机**：人工比对 SVA 慢且主观，必须有一标量
- **定义**（论文公式）：

  $$
  a_t = \frac{E_t}{n}
  $$

- $a_t$：第 $t$ 轮迭代后的对齐分数
- $E_t$：该轮 Vi = ENTAILS 的数量
- $n$：总数
- $t$：当前迭代轮次
- **目标**：让 $a_t$ 在 maxIter 内单调上升到满意值
- **副作用**：因为有 3 态而非 2 态，「C 上升但 AS 跌」也是可解释的（详见 §6.3 例子）

### 4.3 模块职责矩阵

| 模块 | 输入 | 输出 | 工具/模型 | 是否需训练 |
|---|---|---|---|---|
| Alignment Checking (Property) | Pi, S, k=3 | Vi ∈ {0,1,2} | GPT-5 (high reasoning) | 否，CoT+self-consistency 推理 |
| Alignment Checking (SVA) | Ni, PropertyBank 或 S, k=3 | Vi | GPT-5 | 否 |
| Inconsistency Analysis | Xi, Ri, S | Fi | GPT-5 | 否 |
| Evidence Extraction | Xi, S | Ei | GPT-5 | 否 |
| NL Summary Extraction | Ai | Ni | GPT-5 | 否 |
| Refinement（属性层） | Pi, S, Fi | Pi' | GPT-5 | 否 |
| Refinement（SVA 层） | Ai, S, Fi | Ai' | GPT-5 | 否 |
| SpecAlign AS 上层汇总 | {Vi} | a_t 数值 | 纯算数 | — |
| JasperGold（外部） | Ai, RTL | Proven / CEX | Cadence JasperGold | 商业形式验证 |

## 5. 关键公式

### 5.1 Self-Consistency 多路径投票裁决

$$
V_i = \arg\max_{y \in \{0, 1, 2\}} \sum_{j=1}^{k} \mathbb{1}[v_{i,j} = y]
$$

- $V_i$：第 $i$ 条自然语言描述 / SVA 的最终对齐裁决
- $v_{i,j}$：第 $j$ 条 CoT 推理路径给出的 sub-verdict（0 = CONTRADICTS, 1 = ENTAILS, 2 = UNKNOWN）
- $\mathbb{1}[\cdot]$：指示函数（条件成立为 1）
- $k$：自一致采样路径数（论文 k=3）
- $y$：候选类别之一

**工程直觉**：让多个独立推理员投票，多数同意的结论最稳。这把 LLM 的随机性「平均掉」。论文开篇就引用 Wang et al. [12] 自一致性方法的核心论断：「correct reasoning paths often converge on the same conclusion」。

**平票规则**（公式未显式编号，论文明文）：三个 verdict 中优先级为 CONTRADICTS > UNKNOWN > ENTAILS。即「不盲信 LLM，宁可错杀」。

**为什么这么设计**：相比无投票的单 LLM 分类，自一致性把随机误差从 $O(\epsilon)$ 压到 $O(\epsilon^2)$ 量级（Wang et al.）；相比投票三类别按数值取均值的做法，类别加权的多数投票保留了三态语义本身。

### 5.2 Alignment Score 量化指标

$$
a_t = \frac{E_t}{n}
$$

- $a_t$：第 $t$ 轮迭代后的对齐分数
- $E_t$：第 $t$ 轮 Vi = ENTAILS 的断言数
- $n$：待评估的 SVA 总数（在 paper 实验中保持不变）
- $t$：迭代轮次（$0 \leq t \leq \text{maxIter}$, maxIter = 3）

**工程直觉**：AS = 「最终通过 SPEC 的概率」（频次近似）。这是「无 golden RTL 也能算的 FOM（Figure of Merit）」。

**为什么这么设计**：传统 FV 用「prove 率」但它和「语义正确」不完全等价；这里直接用「人类可读的语义标签」比例作 FOM。一行公式能让你画出 Figure 3 的曲线。

### 5.3 三态语义分类

论文 §IV-B 给出 SVA 可分三类：

$$
\text{Vi} \in \{\text{CONTRADICTS}, \text{ENTAILS}, \text{UNKNOWN}\}
$$

- **CONTRADICTS**：Xi 中至少一个元素被 SPEC 否定
- **ENTAILS**：Xi 中所有元素被 SPEC 支持（可以是 explicit 或合理 assumption）
- **UNKNOWN**：至少一个元素既不被支持也不被否定（多见于 implementation-specific 约束）

**工程直觉**：第三类「UNCERTAIN」是真正的 paper-specific 创新点。它把「LLM 大规模押注」转化为「不确定就标灰」，对应论文 §III「spec-underspecified」哲学。

**为什么这么设计**：传统的 SVA 评估只能 proven/cex 两个标签；论文发现很多 LLM 生成 SVA 既不能直接否定又不能直接支持——若归到 ENTAILS 会高估，归到 CONTRADICTS 会漏报。第三类解决了这个二分类痛点。

> 注：论文没有给出「Implementation-specific assumption」的精确定义式，以上三态分类散见于 §III 和 §IV-B 的非形式化定义。

## 6. 训练与实验设置

### 6.1 是否需要训练

**零训练，零参数更新**。SpecAlign 是推理时（inference-time）的 LLM agent：

- LLM 后端：OpenAI **GPT-5**（[17] OpenAI GPT-5 System Card, 2025），闭源推理模型
- 不在 SpecAlign 框架里跑 SFT 或 RL
- 对比 baseline AssertionForge [9] 是外部 LLM-based SVA 生成器，论文「reproduced using default settings」——即 SpecAlign 调用其默认配置生成 SVA，再做语义对齐
- 设计意图：所有「学习」都来自 GPT-5 的预训练 + CoT prompt engineering + self-consistency

> 这点和 [HierSVA](../HierSVA/论文深度讲解.md)（也是 LLM-only，无训练）类似，但 [CodeV-R1](../CodeV-R1/论文深度讲解.md)、[CorrectHDL](../CorrectHDL/论文深度讲解.md) 走 RLVR 路线做训练。

### 6.2 实验设置

**Designs**（Table II）：

| Design | Source | Description | #Pages | #Tokens (cl100k_base) |
|---|---|---|---:|---:|
| APB | OpenCores [16] | APB to I2C Interface | 12 | 2,746 |
| UART | [5] AssertLLM 提供 | UART to Bus Interface | 10 | 3,160 |

**Baseline & Implementation**：

- LLM 后端：SpecAlign → GPT-5 with high reasoning effort（per [17] system card）
- baseline 对照：AssertLLM [5] 在 I2C 上的报告结果（from SANGAM [6]） + AssertionForge [9] 默认配置复现
- 自一致采样：k = 3 reasoning paths
- 最大迭代：maxIter = 3（Property Loop & SVA Loop 各自独立）
- SVA Loop 的 reference：直接用 Specification S 而**非 Property Bank**（论文明确这一选择，以限制外部依赖）

**评估指标**：
- `#SVA` = 最终集会里的 SVA 数
- AS = Alignment Score，按上面 §5.2 公式
- 把 AS 拆解为 E（ENTAILS 个数）、C（CONTRADICTS 个数）、U（UNKNOWN 个数）

### 6.3 关键实验结果

**Table I：JasperGold vs SpecAlign 标签交叉表**

| SpecAlign Label | JasperGold Proven | JasperGold CEX |
|---|---:|---:|
| Entails | 55 | 23 |
| Contradicts | **46** | 43 |
| Unknown | 51 | 63 |

- 46 个「JasperGold 判定 Proven + SpecAlign 判 Contradicts」的案例是论文核心反直觉证据
- 23 个「CEX + Entails」表明 FV 报错但语义没毛病（疑似 RTL bug，不是断言 bug）
- 51/63 个 Unknown 表明 FV 视角下两类问题都有大量灰区

**Table III：3 轮对齐迭代后的结果（核心表）**

| Design | Method | #SVA | AS | E | C | U |
|---|---|---:|---:|---:|---:|---:|
| APB | AssertionForge | 442 | 0.02 | 8 | 148 | 286 |
| APB | **SpecAlign** | 442 | **0.15** | **66** | **0** | 376 |
| UART | AssertionForge | 325 | 0.06 | 21 | 142 | 162 |
| UART | **SpecAlign** | 319 | **0.28** | **92** | **6** | 227 |

- APB：SpecAlign 把 C 从 148 降到 **0**，AS 从 0.02 涨 7.5× 至 0.15
- UART：SpecAlign 把 C 从 142 降到 6，AS 从 0.06 涨 4.7× 至 0.28
- U 上升（AF 286→SA 376；162→227）是设计性 trade-off——把「uncertain」从 AF 的「错」移到了 SA 的「标灰」
- #SVA 从 442/325 微降到 442/319：约 0.5% 的 SVA 在精化中被丢弃或合并

**Figure 3：APB + UART 的 AS vs Iteration 曲线（实验结果）**

论文 Figure 3 显示：
- UART：第 0 轮 0.06 → 第 1 轮大幅上升 → 第 2 轮继续 → 第 3 轮收尾在 0.28

## 7. 创新点

### 创新点 1：「JasperGold Proven ≠ 语义正确」的实证

**与已有方法的关键区别**：传统 SVA 评估（[HierSVA](../HierSVA/论文深度讲解.md) 用的 FPV / FTA / FC 套件、[AssertEval] 等）以「FV prove 率」作 FOM。SpecAlign 直接给出反例：**46 个 JasperGold-Proven 的 SVA 经 SpecAlign 仍是 Contradicts**——形式层通过的证明在语义层不通过。这是首次实证「FV 指标」与「语义指标」的脱钩。

**为什么之前没人发现**：之前工作都是「生成→FV 评分」一锤子买卖，FV 评分好坏被当作绝对真理。SpecAlign 引入「二次裁决」后才看到这条 bias。

### 创新点 2：引入 UNKNOWN 第三类，把不确定显式化

**与已有方法的关键区别**：现有 SVA 评估方法通常把 SVA 评估做成二分类（correct / incorrect）。SpecAlign 把「spec 不够信息」从「错误」里独立出来，成为第三类 Unknown。

**为什么这么做**：RTL 工程师写的 SVA 经常带实现细节（reset 时序、内部计数器假设），它们既非 SPEC 支持也非 SPEC 反对。若归到 ENTAILS 拉高 AS 但失去审计能力；归到 CONTRADICTS 误伤。Unknown 给「让人类补 SPEC」的明确信号。

### 创新点 3：Property + SVA 双层迭代循环

**与已有方法的关键区别**：AssertionForge 是单层「NL → SVA → FV 评」。SpecAlign 拆成两层各自对齐：上层先审查 NL 属性（Property Alignment Loop），下层再审查 SVA（SVA Alignment Loop）。

**优势**：(1) 错位诊断可定位在「NL 层把意图丢了」还是「SVA 层把意图翻译错了」；(2) Property Bank 可作为高质量 few-shot 留到下游 SVA 生成器；(3) 双层都跑同一对齐算法，但 reference 不同（Property Bank vs SPEC），可观察语义漂移。

### 创新点 4：CoT + 自一致投票迁移到 SVA 评估

**与已有方法的关键区别**：Wang et al. (2023) 自一致性原本解决数学 / 常识推理。SpecAlign 把同一机制搬到「形式-自然语言对齐」任务。用 k 条推理路径 + 多数投票 + 平票保守规则裁决 ENTAILS / CONTRADICTS / UNKNOWN。

**效果**：论文没显式给消融实验数据，但论文 §I（Introduction）明说「self-consistency acts as a semantic validation mechanism that improves the reliability of misalignment detection」。

### 创新点 5：可操作反馈 (Fi) 让 LLM 自迭代修复

**与已有方法的关键区别**：Self-Refine (Madaan et al.) 用「broad feedback」让 LLM 自改。SpecAlign 用「4 段结构化、强制 SPEC 引文、不可绕过限制」的反馈 Fi。

**优势**：(1)「SVA BEHAVIORAL INTENT」段保留意图，避免 LLM 改完后跑题；(2)「CORRECT BEHAVIOR」段强制引 SPEC，让 LLM 知道「正确答案」；(3)「FEEDBACK」段是「instructions not new properties」，LLM 重新生成时仍然用同一信息源。

## 9. 与芯片流程的关系

### 9.1 在全流程中的位置

```text
                    ┌────────────────────────────────────────────────────┐
                    │  SpecAlign 在 VLSI 全流程里「贴」形式验证 (⑥) 阶段  │
                    └────────────────────────────────────────────────────┘

┌────────┐  spec  ┌────────┐  NL props  ┌────────┐  SVA  ┌────────────┐  RTL  ┌────────┐
│ 市场/  │────────►│ LLM    │────────────►│ LLM    │──────►│ SpecAlign  │──────►│ 综合/  │
│ 算法/  │         │ Property│           │ SVA    │       │ 评审循环   │       │ 仿真/  │
│ 架构   │         │ 提取    │           │ 生成    │       │ (本文)     │       │ 后端   │
└────────┘         └────────┘            └────────┘       └─────┬──────┘       └────────┘
                                                               │
                                                  ┌────────────┴────────────┐
                                                  ▼                         ▼
                                            ENTAILS SVA             CONTRADICTS SVA
                                            → Aligned Bank           → 重新生成 OR 人工 review
                                                               ↓
                                                  JasperGold (FV) ← 是否有 golden RTL 都行
                                                               ↓
                                                  Final SVA Sign-off
```

**接手谁的输出**：任何 SVA 生成器的输出 S = {A1, ..., An}（AssertionForge、SANGAM、AssertLLM ……）。
**交棒给谁**：Aligned SVA Bank（去人工 review 后送 JasperGold 等 FV 引擎做最终签核）。
**解决的痛点**：当 golden RTL 不可得时（设计早期 / IP 厂商没法分享源码），LLM 生成的 SVA 无 FV 可跑——SpecsAlign 直接用 SPEC 做语义对齐，不依赖 RTL。

### 9.2 「SpecAlign 通过」和「能做成芯片」之间隔着什么

SpecAlign 评价「LLM 写的 SVA 是不是 SPEC 要的」——这只回答「验证规划」对不对，不保证「验证执行」成功：

1. **SpecAlign 不验证 SVA 语法 / 综合可实现** —— 一条 ENTAILS 的 SVA 可能在某些 EDA 工具下不支持某复杂序列算子（如 `|->` 的多层 `##[N:M]`）。上 JasperGold 之前还需过 vlog / Incisive 综合检查
2. **SpecAlign 不验证 RTL 与 SVA 的真等价** —— paper 自报「Entails 但 JasperGold CEX 的 23 个 case」是「RTL bug 不是 SVA bug」。SpecAlign 只能帮你定位「不会是 SVA 的错」，但不能告诉你 RTL bug 在哪
3. **SpecAlign 不验证覆盖率** —— paper 没说自己的反馈能让 SVA 覆盖 spec 的百分比。该工作偏向「逐条 correctness」而非「验证强度」（参考 [HierSVA](../HierSVA/论文深度讲解.md) 的 C5 formal core coverage 指标）
4. **SpecAlign 不验证非功能属性** —— 时序约束、面积、功耗（SPEC 常带）不在三态分类里。如果一条 SVA 是 ENTAILS 但时序过不了 STA，仍是废 SVA
5. **SpecAlign 不验证竞态 / 嵌套 race condition** —— NL Summary 抽取会丢失 SVA 内部并发事件的细节，对类似 `##0 a |-> ##[1:5] b` 的窗口描述粗糙

总结：SpecAlign 是「LLM 生成 SVA 的清洁器」，不是「验证规划的全套方案」。它对 [HierSVA](../HierSVA/论文深度讲解.md) 的「6 维 metric」是补充关系（HierSVA 拆 C1-C5 强度维，SpecAlign 拆 ENTAILS/CONTRADICTS/UNKNOWN 语义维）。

## 10. 讨论与局限

### 10.1 论文自述的局限

论文 §VI 明说三个未来方向，每个都是局限：

1. **更精细的分类方法**：当前三态粒度粗，不能区分「严重错」vs「轻微偏」
2. **精化过程要捕获语法错误**：当前 Inconsistency Analysis 主要修语义不动语法，但 LLM 生成的 SVA 常有 syntax issue（如缺 semicolon），feedback 没处理
3. **扩展到 RTL 生成 / 调试**：论文说「future works involves … extension to other hardware design automation tasks such as RTL generation and debugging」——即当前只覆盖 SVA 这一项

### 10.2 代码/复现层面的问题

论文没开源代码（备注栏写「未开源」），所以代码级 audit 暂无：

- **闭源 LLM 依赖**：GPT-5 闭源，复现结果会随 OpenAI 模型更新漂移。论文没给具体版本号 / checkpoint
- **闭源 FV 工具**：JasperGold 是 Cadence 商业产品，需 license。Table I 的 46:101 实证数据外部无法直接复现
- **实验设计只有 2 个**：APB 12 页 / UART 10 页，远不能代表整个 SOTA。论文自认「future works involves a more sophisticated classification methodology」
- **k=3 是工程默认**：无消融实验证明 k=3 优于 k=2 或 k=5
- **maxIter=3 同上**：Figure 3 显示 2 轮后已收敛，但论文没给 5 / 10 轮的对照
- **SANGAM I2C baseline**：论文引用 SANGAM [6] 报告的 I2C 数字，没自己跑过。SANGAM 是另一论文的工具，未必有公开权重 / API

### 10.3 本资料包的批判性分析

**优点（资料包视角）**：
- 论文的核心理念「语义 ≠ 形式」对所有 LLM4EDA 工作有镜鉴价值（[Rtl2lean](../Rtl2lean/论文深度讲解.md)、[CktFormalizer](../CktFormalizer/论文深度讲解.md) 都涉及，但角度不同）
- 三态分类可拓展到「formal spec → RTL」任务（如 [CorrectHDL](../CorrectHDL/论文深度讲解.md) 的 Pass/Fail 二态可以扩成 SVA-style 三态）
- 反馈生成可作为「LLM agent 的 RL reward signal」——自动标「bad SVA」比 JasperGold 标 CEX 更贴近设计意图

**缺陷（资料包视角）**：
- **公平性疑问**：论文对比 AssertionForge，但 AF 同时用了 spec + RTL 输入；SpecAlign 只用 spec。某种意义上 SpecAlign 的优势来自「信息不对称」（AF 看了 RTL 引入实现细节 → SpecAlign 不该归类这些 → U 上升 C 下降）。论文 §V-D 明说这是 trade-off 但没量化「spec-only vs spec+RTL」的 gap
- **可扩展性天花板**：APB + UART 是两个 IO 协议，规模有限。工业 SoC（千端口 + 子模块）的 SPEC 几 MB + 上万条 SVA，远超 GPT-5 context 上限。需要 hierarchical decomposition
- **GPT-5 推理成本**：每次 Alignment Check 跑 3 条 CoT × K iterations，总 LLM call ≈ 30 / assertions。工业场景（千条 SVA）成本不堪
- **评测的 fair-play**：Table III 里 AF 也跑 3 轮吗？文中只说「reproduced using default settings」，没说跑了多少次

**对资料包的隐含价值**：
- SpecAlign 的 Ei（证据 + 页码）输出格式可借鉴到 [PRO-V](../PRO-V/论文深度讲解.md) / [OpenSource-Formal-RTL](../OpenSource-Formal-RTL/论文深度讲解.md) 这类「verification artifacts」工作
- UNKNOWN 处理可借鉴到 [VGen] 等不会输出 spec 时的兜底

## 12. 一分钟复述版

```text
1.  问题：LLM 生成 SVA 现在主要看 JasperGold 跑 prove / cex，但「prove 成功 ≠ 语义正确」。
    表 1 实证：在 JasperGold 判定 Proven 的 101 条样本里，SpecAlign 还能找出 46 条
    与自然语言规范 Contradicts——形式层是对的，但语义层完全错位。

2.  解法：三态分类 + 双层迭代 + CoT 自一致投票
    (a) 三态分类：CONTRADICTS / ENTAILS / UNKNOWN。其中 UNKNOWN
        专门用于「规范没明说」的 implementation-specific 假设，避免粗暴归错。
    (b) 双层循环：Property Loop（NL 属性 vs SPEC）+ SVA Loop（SVA vs Property Bank）。
        每条 NL 描述走 Alignment Check → Evidence / Inconsistency → Refinement。
    (c) CoT + 自一致：k=3 条推理路径多数投票，平票取 CONTRADICTS > UNKNOWN > ENTAILS。

3.  反馈机制：Inconsistency Analysis 强制输出 SVA BEHAVIORAL INTENT /
    CONTRADICTING ELEMENTS / CORRECT BEHAVIOR (强制 SPEC 引文) / FEEDBACK
    四段，让 LLM 按反馈重新生成 SVA。

4.  量化指标：Alignment Score = ENTAILS 数 / 总 SVA 数。
    APB：0.02 → 0.15，CONTRADICTS 148 → 0。
    UART：0.06 → 0.28，CONTRADICTS 142 → 6。

5.  关键意义：
    - 不依赖 golden RTL，可在设计早期 / IP 黑盒时替代 JasperGold 评估
    - 与 LLM-for-SVA 生成器（AssertionForge / SANGAM）解耦
    - 给「verification quality」一个不靠 FV 的量化指标

6.  局限：闭源 GPT-5 + JasperGold license + 2 个小设计 + 无训练 + 无 syntax 修复
    + 无覆盖率度量。论文明确说未来工作包括更精细分类 + 修语法 + 拓展到 RTL 生成。
```

## 附录 A：附录 B-F 的真实 Prompt（论文直引，原文逐字摘录）

为方便资料包读者复制 prompt engineering 经验，下面把论文附录 B/C/D/E/F 的关键 prompt 直接归档。所有 prompt 都用 GPT-5 作为后端。

### A.1 Appendix B — Alignment Checking System Prompt（节选）

```text
SYSTEM ROLE: You are a senior digital design verification engineer performing
specification-to-property semantic alignment analysis.

OBJECTIVE: Given: 1) A reference document 2) A natural language description of
a property to be asserted
Your task is to determine whether the property semantically aligns with the
specification.

DEFINITIONS:
CONTRADICTS (0): The property can be any of the following:
  - Conflicts with the specification
  - Is mis-scoped relative to the described signals or timing
  - Is under-specified or over-specified relative to the reference document
  - Is vacuously true
ENTAILS (1): The property can have:
  - Explicit support from the specification, OR
  - Reasonable implementation-specific assumptions, even if not directly stated

Important: If the property introduces behavior that is not justified by the
reference document, classify as ENTAILS. If uncertain, default to ENTAILS
unless it clearly contradicts the reference document. If the reference document
contains conflicting behavior, classify it as ENTAILS.

ANALYSIS INSTRUCTIONS (DO INTERNALLY):
1. Extract all signals and conditions referenced in the property.
2. Determine the behavioral intent of the property.
3. Search the reference document for statements about those signals and behaviors.
4. Compare semantic intent of the specification and property.
5. Decide whether the specification entails the property.

DECISION RULE: Return:
1 → ENTAILS
0 → CONTRADICTS

OUTPUT FORMAT: Output exactly one character: 0 or 1
Do NOT output reasoning, explanation, punctuation, or any additional text.
```

注意：附录 B 的 prompt 把 verdict 限定到 0/1（CONTRADICTS/ENTAILS），但论文正文中讲三态（含 UNKNOWN）。这一不协调在 §10.2 已点出，复现时需对齐。

### A.2 Appendix C — Inconsistency Analysis（节选 Property Loop 部分）

```text
SYSTEM ROLE: You are a senior digital design verification engineer performing
natural language property refinement.

OBJECTIVE: Given: 1) A design specification 2) A semantically-inconsistent
natural language property 3) Feedback to guide regeneration of the SVA

Regenerate the natural language property so that it:
1. Correctly reflects the design specification
2. Fixes the semantic errors described in the feedback
3. Maintains the intended semantics of the SVA
4. Avoids introducing new signals, conditions, or behaviors not present in the
   specification or feedback
5. Clearly describes the trigger condition and required response behavior

DEFINITIONS:
SEMANTIC CONSISTENCY: The property:
  - Is explicitly supported by the specification, OR
  - Is logically consistent with and does not conflict with the specification,
    even if not explicitly stated

STRUCTURE: A good property should clearly contain:
  - Trigger condition (when the property becomes active)
  - Temporal behavior (sequence or delay constraints)
  - Expected response
  - Reset/disable conditions if present in the specification

IMPORTANT: Use the feedback as mandatory correction guidance, prioritize the
feedback and the design specification. DO NOT introduce new signals, timing
constraints, or conditions that are not present in the specification or
feedback. The regenerated property must be precise and unambiguous so it can
be directly translated back into an SVA assertion.

OUTPUT FORMAT: Output only the refined property and the property should be a
single sentence. Do NOT output reasoning, explanation, or any additional text.
```

SVA Loop 的版本强约束更多：它要求把每个 heading 都写出，包含 `SVA BEHAVIORAL INTENT / CONTRADICTING ELEMENTS / CORRECT BEHAVIOR (with page/section) / FEEDBACK` 四段。

### A.3 Appendix F — NL Summary Extraction（节选）

```text
You are a digital design verification engineer and I will provide you with
information about a SystemVerilog Assertion.

INFORMATION:
  - Clock: Identifies which clock the assertion should be sampled on and
    whether it is on the rising or falling edge
  - Disable iff: Optional component that identifies what condition the
    assertion should be disabled on
  - Antecedent: Identifies a boolean expression that is assumed to be true
  - Op: Identifies implication and when the consequent must be true, |->
    means it must be true in the same cycle and |=> means it must be true in
    the following cycle
  - Body: If there is no Op, then the SVA must be treated as a single
    invariant condition defined by the body
  - Temporal: Optional component that identifies a time frame in which the
    consequent must be true
  - Consequent: Identifies a boolean expression that must be true if the
    antecedent is true within the optional temporal constraints

TASK SUMMARY: Convert the SVA information into a natural language claim that
encompasses all required conditions.

STEPS:
1. Identify all the signals given from the information, ONLY USE SIGNALS FROM
   THE SVA
2. Use clock and disable iff to determine the exact conditions in which the
   SVA must trigger
3. Use Op and Body to determine what kind of SVA is provided. If there is no
   Op, it is an invariant and if there is Op, then ignore Body and skip to
   step 7
4. Use antecedent to determine what is assumed to be true
5. Use op and temporal to determine the timing of when the consequent must
   be true in relation to the antecedent
6. Use consequent to determine what must be true within a given timeframe
   from the antecedent
7. Summarize the results from previous steps into a single sentence claim

OUTPUT FORMAT: Only output a single sentence claim, DON'T reference sva id,
and DON'T give any other text aside from the claim.

EXAMPLE: On the positive edge of CLK except when RESET is 0, if WRITE is 1
and DATA is 0 then within 1-2 cycles SIGNAL is 0.
```

这个 prompt 有几个工程亮点：(1) 强约束「only single sentence」便于后续 entailment 判定时的稳定性；(2) Step 3 explicit 处理「no Op = invariant」分支，避免 LLM 把 every-cycle SVA 误判为 implication；(3) 用 EXAMPLE 而不是 template 让输出更鲁棒。
