## 1. 一句话定位

**OpenLS-DGF（简称 ACE）不是一个新的神经网络模型，而是一个面向逻辑综合的适应性数据集生成框架——它把逻辑综合的三大核心步骤（Boolean representation、logic optimization、technology mapping）封装成一条从 Verilog/AIG/BLIF 源设计到 PyTorch Geometric 张量的七步自动化管线，从 46 个组合设计出发，通过 1000 条随机优化 recipe 和 6 种 Boolean network 的 logic blasting，最终产出覆盖 7 种逻辑表示、ASIC+FPGA 双映射、含 STA 时序标注的 OpenLS-D-v1 母数据集（966,000 个电路），并配套一个 ACE Circuit Engine 供下游任务按需抽取子数据集。论文在电路分类（99.8% accuracy）、电路排序（F1=0.6651）、QoR 预测（Area MAPE 0.69%）、概率预测（PE=0.0002 with DeepGate2）四个下游任务上验证了数据的多样性和适用性。**

这句话里的四个技术承重点：

1. **七步数据生成管线** -- GTG 合成 → AIG 生成 → 1000 条 ABC 随机优化 recipe → LSILS logic blasting（AIG→OIG/XAG/MIG/PRIMARY/GTG）→ ASIC/FPGA 技术映射 → iEDA STA 标注 → ACE Circuit Engine 打包。每一步输出 Verilog + GraphML 双格式，支持半定制扩展。
2. **多表示覆盖** -- OpenLS-D-v1 覆盖 AIG / OIG / XAG / MIG / PRIMARY / GTG 共 7 种 Boolean network（含 ABC-AIG 和 LSILS-AIG 两个变体），每种各 1000 个优化变体，再加 ASIC 和 FPGA 映射网表，总 46×1000×21 = 966k 电路。
3. **ACE Circuit Engine** -- 一个 Python 电路抽象层，把不同格式的电路统一为 `Circuit`/`Node` 对象，支持 depth 计算、仿真、feature 初始化、to_torch_geometric 转换，是母数据集和下游任务之间的桥梁。
4. **四任务验证** -- 电路分类（验证表示多样性）、电路排序（新提出的任务——比较两条 recipe 的 QoR）、QoR 预测（从优化序列预测最终面积/时序分布）、概率预测（节点级 truth table 1 的频率回归）。

## 2. EDA 阶段映射（①-⑰）

参照 [芯片流程.md](../芯片流程.md) 的 17 阶段标准编号：

| 阶段 | 覆盖 | 说明 |
|------|:---:|------|
| ① RTL 设计 | ✅ **输入源** | 以 Verilog / AIG / BLIF 作为输入；Yosys 将其解析为 GTG |
| ② RTL 功能仿真 | ❌ | 论文不执行功能仿真验证；但生成的 Verilog 可用于仿真 |
| **③ 逻辑综合** | ✅ **核心** | Boolean 表示（GTG/AIG/OIG/XAG/MIG/PRIMARY）+ 逻辑优化（ABC 1000 recipe）+ 技术映射（ASIC Sky130 / FPGA LUT6）。这是框架的全部覆盖范围 |
| ④ 门级仿真 | ❌ | — |
| **⑤ STA（静态时序分析）** | ✅ **标注来源** | iEDA 计算 ASIC 网表的 arrival time，作为 QoR 标签 |
| ⑥ 形式验证 | ❌ | 但 Theorem 1 证明 logic blasting 保持依赖关系——这是形式化保证而非实验验证 |
| ⑦-⑰ 布局规划→芯片 | ❌ | — |

**覆盖率：3/17（① 作为输入源，③ 核心贡献，⑤ 作为标注来源）。** OpenLS-DGF 是一个**数据集生成框架**，它的覆盖范围精确等于逻辑综合的子步骤。它不解决任何具体的 EDA 优化问题——它提供训练数据，让别人去解决。

> ⚠️ OpenLS-DGF 不生成训练好的模型。它生成的是一套可以用作 GNN 训练输入的 PyTorch Geometric 数据文件。论文中的四个下游任务实验是为了**验证数据集的质量和多样性**，而非声称在某个 EDA 指标上达到 state-of-the-art。

## 4. 方法与架构

### 4.1 整体设计哲学

OpenLS-DGF 的核心设计问题是：**如何从一个固定的 benchmark 集合生成足够多样、足够规模的训练数据，同时保持电路的真实性（不是随机图）？**

答案分三层：
1. **表示层多样性**：同一个设计通过不同的 Boolean network（AIG/OIG/XAG/MIG/PRIMARY/GTG）呈现出不同的图结构，但保持相同的功能（Boolean equivalence 保证）。
2. **优化层多样性**：同一个 AIG 经过 1000 条不同的 recipe（随机命令序列）产生 1000 个结构不同的等价电路，覆盖 QoR 分布的全谱。
3. **物理层真实性**：经过真实的标准单元库映射（Sky130/LUT6）和 STA（iEDA），产出的网表具有真实的面积和时序属性。

### 4.2 ACE Circuit Engine 详解

**这个模块存在的理由**：不同 EDA 工具产出的中间文件格式各异（ABC 的 binary AIG、LSILS 的 GraphML、iEDA 的 JSON、Yosys 的 Verilog）。如果没有统一的抽象层，每个下游任务都要自己写解析器，且容易丢失原始信息（如 node index 映射、fanin 顺序、truth table）。

ACE Circuit Engine 提供了：

1. **统一的 `Circuit` / `Node` 类**：将 GraphML 中记录的 type/name/index/fanins/truthtable 完整保留为 Python 对象属性。
2. **`indexori` 保留**：原始 circuit 中 node 的 index 保留为 `indexori`，内部处理使用连续的 `index`。这对需要追溯 node 来源的任务（如等价节点识别）至关重要。
3. **torch_geometric 桥接**：`to_torch_geometric()` 方法将 `Circuit` 对象转为 PyG `Data`，包括 node feature 矩阵 `x`、edge index `edge_index`、以及可选的 truth table、depth 等附加属性。
4. **仿真能力**：`simulate()` 方法支持在 circuit 上执行逻辑仿真，用于生成 probability 标签。

### 4.3 下游任务模型

**任务 1：电路分类**
- 目的：验证不同 design 的 Boolean network 在 embedding 空间中有足够的区分度
- 模型：2 层 GCN + BatchNorm + ReLU + global mean readout + MLP + Softmax
- 输入：node type one-hot (21 维) + truth table (64 bit)
- 输出：15 类 design 标签
- 训练：cross-entropy，lr=1e-4，batch=16，10 epoch
- 结果：~99.8% accuracy

**任务 2：电路排序（新提出）**
- 目的：给定同一 design 的两条 recipe $(C_0, C_1)$，判断 $C_0$ 的 QoR 是否优于 $C_1$
- 模型：共享 GNN 分别编码两图 → 拼接为 block matrix → MLP comparator → binary output
- 训练：BCE loss，~120,000 pairs，70/30 train/val
- 结果（GraphSAGE）：Accuracy 99.49%，F1=0.6651
- 注意：F1 低但 Accuracy 高是因为类别不均衡（大多数 pair 的 QoR 差异明显，容易判断；少数接近的 pair 构成难例）

**任务 3：QoR 预测**
- 目的：从原始 AIG + 优化序列预测最终的面积和时序分布
- 变体设计：
  - Variant 1: Seen design, unseen recipe（测试 recipe 泛化）
  - Variant 2: Unseen design, seen recipes（测试 design 泛化）
  - Variant 3: Unseen design-recipe pair（最严格）
- 模型：GNN 图嵌入 + 序列线性嵌入 + 多尺度 Conv1d (kernel 14/15/16/17) + concat + MLP
- 结果 Variant 1：Area MAPE 0.69%，Timing MAPE 7.87%

**任务 4：概率预测**
- 目的：预测 Boolean network 中每个节点的 truth table 中 1 的频率
- 模型：T 层 directed gate aggregation（GraphSAGE / DeepGate2）
- 结果：DeepGate2 在 1000 recipe 设定下 PE=0.0002（vs GraphSAGE 0.0008）

## 5. 关键公式

### 5.1 布尔电路的形式化定义（论文 Section II-A）

论文将布尔电路定义为计算图：

$$
C = (V, E), \quad V = V^{PI} \cup V^{LG} \cup V^{PO}
$$

- $C$：布尔电路
- $V^{PI}$：主输入节点集合
- $V^{LG}$：内部逻辑门节点集合（logic gates）
- $V^{PO}$：主输出节点集合
- $E$：有向边集合，$(v_i \rightarrow v_j) \in E$ 表示信号从 $v_i$ 流向 $v_j$

### 5.2 路径延迟公式（论文 Section II-A）

$$
\text{path delay} = \sum (\text{gate delay}) + \sum (\text{wire delay})
$$

- gate delay：每个门内部的固有延迟
- wire delay：门之间连线产生的延迟
- 关键路径的 arrival time 用于判断电路能否在目标时钟周期内工作

### 5.3 GNN 节点更新公式（论文 Section II-A）

论文引用标准 GNN 消息传递框架：

$$
h_{N(v)}^k = \text{AGGREGATE}^k\left(\{h_u^{k-1}, \forall u \in N(v)\}\right)
$$

$$
h_v^k = \sigma\left(W^k \cdot \text{CONCAT}\left(h_v^{k-1}, h_{N(v)}^k\right)\right)
$$

- $h_v^k$：节点 $v$ 在第 $k$ 层的嵌入，$\in \mathbb{R}^d$
- $N(v)$：节点 $v$ 的邻居集合
- $\text{AGGREGATE}^k$：第 $k$ 层的可微聚合函数（sum/mean/max/attention 等）
- $W^k$：第 $k$ 层的可学习权重矩阵
- $\sigma$：非线性激活函数（如 ReLU）
- $\text{CONCAT}$：拼接操作

**工程直觉**：这是 GNN 的标准消息传递范式，论文本身并未提出新的 GNN 架构——它的贡献在于数据集，而非模型。四个下游任务展示的是"用好数据 + 标准模型就能拿到好结果"。

### 5.4 Theorem 1: Logic Blasting 保持依赖关系

**论文未给出数学公式编号，以下是对其定理陈述的翻译**：

> Logic blasting 方法保持原电路的依赖关系。logic blasting 步骤依赖于映射步骤，确保 blasting 前后的节点可以精确对应，因此它们保持相同的拓扑结构。匹配的节点保持依赖关系。

**工程直觉**：这意味着你可以把为 AIG 开发的所有逻辑优化算法（rewrite/refactor/resub/balance）通过 logic blasting 应用到其他 Boolean network 上——先 blast AIG 到目标格式，优化后的 AIG 再 blast 回去。Lemma 1 显式声明了这一点："We can equip the logic optimization capability of AIG to the other logic types through logic blasting."

**为什么这个定理重要**：如果没有这个保证，logic blasting 产出的 OIG/XAG/MIG 电路可能与原始 AIG 在功能上不等价——那样的话基于 blast 电路训练的模型就无法迁移到原始电路上。

## 6. 训练与实验设置

### 6.1 是否需要训练

**框架本身不需要训练（它是数据生成器）。四个下游任务各需要训练各自的 GNN 模型。**

| 任务 | 训练类型 | 损失函数 | 数据划分 |
|------|---------|---------|---------|
| 电路分类 | 监督 15 类分类 | Cross-entropy | 800 train / 200 test per class |
| 电路排序 | 监督二分类 (pairwise) | BCE | 70/30 train/val |
| QoR 预测 | 监督分布学习 | MSE-style | Variant 1/2/3 |
| 概率预测 | 监督节点级回归 | PE (MAE) | 按 recipe 数配置 |

训练超参数：lr=1e-4，weight decay=1e-5，batch=16，hidden=128。

### 6.2 数据集的关键特性

**与 OpenABC-D 的对比**（论文 Table IV）：

| 特性 | OpenABC-D | OpenLS-D-v1 |
|------|:---:|:---:|
| 源设计来源 | OpenCore, IWLS | OpenCore, IWLS, **EPFL** |
| 设计数 | 29 | **46** |
| Raw GTG | ❌ | ✅ |
| Recipe 数 | 1,500 | 1,000 |
| Recipe 长度 | 20 | 10 |
| LSILS Boolean networks (OIG/XAG/MIG/PRIMARY/GTG) | ❌ | ✅ (各 1,000) |
| ASIC 网表 | ❌ | ✅ (7,000) |
| FPGA 网表 | ❌ | ✅ (7,000) |
| STA/QoR | ❌ | ✅ |
| 总电路数 | ~870k | **~966k** |

### 6.3 关键实验结果

**电路分类**：10 epoch 后 accuracy 约 99.8%，说明 15 个不同 design 的 Boolean network 在 GNN embedding 空间中有极强的可分离性——数据集的设计多样性得到验证。

**电路排序**（论文 Table V）：

| 模型 | BCE Loss | Accuracy | Precision | Recall | F1 |
|------|--------:|---------:|----------:|-------:|-----:|
| GCNConv | 5.09 | 99.43% | 0.9939 | 0.4993 | 0.6647 |
| **GraphSAGE** | **4.31** | **99.49%** | **0.9949** | **0.4995** | **0.6651** |
| GINConv | 4.43 | 99.47% | 0.9944 | 0.4969 | 0.6627 |

**这张表说明什么**：99.49% 的 Accuracy 说明模型能很好地区分"明显好"和"明显差"的 recipe。但 F1 只有 0.665——Recall≈0.5 表明模型在"两条 recipe 产生的 QoR 非常接近"的难例上几乎等同于随机猜测。这是合理的——两个长度 10 的随机命令序列确实可能在 QoR 上产生相近的结果。

**QoR 预测**：Variant 1（seen design, unseen recipe）下 Area MAPE 0.69% 说明面积预测非常准确；Timing MAPE 7.87% 说明时序预测更难——时序对优化序列的微小变化更敏感。

**概率预测**（论文 Table VII）：

| Recipe 数 | GraphSAGE PE | DeepGate2 PE | DeepGate2 提升 |
|----------:|------------:|------------:|:---:|
| 100 | 0.011 | 0.0082 | 24% |
| 500 | 0.002 | 0.001 | 50% |
| 1000 | 0.0008 | **0.0002** | 75% |

**这张表说明什么**：recipe 越多，概率预测越准，因为更多的优化变体提供了更丰富的训练信号。DeepGate2 在所有设定下优于 GraphSAGE，且差距随数据量增大而增大——这说明 DeepGate2 的功能感知设计在更大的数据集上能更好地利用额外信息。

## 7. 创新点

### 创新点 1：首个覆盖逻辑综合全子步骤的数据集生成框架

在 OpenLS-DGF 之前，逻辑综合数据集（如 OpenABC-D）只产生中间文件，没有统一的数据格式和任务抽象。OpenLS-DGF 把"Boolean 表示 → 逻辑优化 → 技术映射 → STA"整条链封装为可配置的 TCL 脚本流程，并输出 ML 友好的 GraphML + PyTorch Geometric 双格式。

### 创新点 2：Multi-Representation Logic Blasting + 形式化保证

通过 LSILS 的 logic blasting 将每个 AIG 扩展为 6 种 Boolean network（AIG/OIG/XAG/MIG/PRIMARY/GTG），并给出 Theorem 1 的形式化保证（blast 不改变电路依赖关系）。这使同一个 design 在 6 种不同图结构下被表示，大幅增加了数据集的多样性和覆盖面。

### 创新点 3：ACE Circuit Engine 作为统一抽象层

Circuit Engine 将 Yosys/ABC/LSILS/iEDA 等不同工具产出的异构中间文件（binary AIG、GraphML、JSON、Verilog）抽象为统一的 `Circuit`/`Node` Python 对象，支持 depth 计算、仿真、to_torch_geometric 转换。这是母数据集能被四个完全不同性质的下游任务共用的关键。

### 创新点 4：新提出的 Circuit Ranking 任务

在逻辑综合中，给定一个 design 和两条候选优化 recipe，判断哪条 recipe 产生更好的 QoR——这是一个有实际工程价值的任务（指导 recipe 选择），但在此之前的 ML+LS 文献中未被显式定义。OpenLS-DGF 为这个任务提供了天然的标注数据（STS 的 area/timing）。

## 8. EDA 缩写表

| 缩写 | 全称 | 一句话解释 |
|------|------|-----------|
| GTG | Generic-Technology Graph | 通用技术图——Yosys techmap 产出的中间表示，包含 primitive gates + NAND3/NOR3/MUX21/AOI21/OAI21 等复杂门 |
| OIG | OR-Inverter Graph | 或-非图，功能完备集为 {NOT, OR2} |

| MIG | Majority-Inverter Graph | 多数-非图，功能完备集为 {NOT, MAJ3}（MAJ3 = 3 输入多数表决门） |
| PRIMARY | Primitive-Gate Graph | 原语门图，功能完备集为 {NOT, AND2, NAND2, OR2, NOR2, XOR2, XNOR2} |
| Logic Blasting | — | 将一种 Boolean network 通过功能完备集覆盖（covering）转换为另一种 Boolean network 的过程 |
| LSILS | — | 开源逻辑综合工具，提供 logic blasting 和 technology mapping |
| iEDA | — | 开源物理设计工具，提供 STA 功能 |

## 9. 与芯片流程的关系

### 9.1 在全流程中的位置

```text
  ① RTL 设计 (Verilog) 
       │
       ▼
  ② RTL 功能仿真
       │
       ▼
  ┌──────────────────────────────────────────────────────────┐
  │  ③ 逻辑综合  ← OpenLS-DGF 的全部覆盖范围                  │
  │                                                          │
  │  ┌─ Boolean 表示: GTG → AIG → OIG/XAG/MIG/PRIMARY ────┐ │
  │  │                                                     │ │
  │  ├─ Logic Optimization: ABC 1000 recipe                │ │
  │  │                                                     │ │
  │  ├─ Technology Mapping: ASIC (Sky130) / FPGA (LUT6)    │ │
  │  │                                                     │ │
  │  └─ STA: iEDA arrival time + area ────────────────────┘ │
  │                                                          │
  │  产物: OpenLS-D-v1 数据集 (966k circuits)                │
  └──────────────────────┬───────────────────────────────────┘
                         │
                         │ 供下游 ML 任务使用:
                         ▼
  ┌── 电路分类 ── 电路排序 ── QoR 预测 ── 概率预测 ─────┐
  │   (这些 ML 模型可以反过来指导逻辑综合的 recipe 选择)    │
  └──────────────────────────────────────────────────────┘
```

### 9.2 「数据集」和「更好的芯片」之间隔着什么

OpenLS-DGF 提供的是一个**训练数据平台**，而不是一个直接改善芯片质量的工具。从数据集到更好的芯片，中间需要：

1. **有人用这些数据训练出更好的模型**：OpenLS-DGF 证明了数据可用（四个下游任务），但没有证明"用 OpenLS-D-v1 训练的模型在真实逻辑综合流程中能做出比现有 heuristics 更好的决策"。
2. **模型嵌入综合工具**：即使训练出了好的 recipe 推荐模型，还需要像 DeepGate2 那样把它嵌入到 ABC/LSILS 的决策循环中——这不是数据集框架的职责。
3. **覆盖时序和功耗**：当前 STA 标注只有 arrival time 和 area，没有 power 分析。对于功耗敏感的 mobile/IoT 设计，这限制了数据集的适用范围。
4. **从组合到时序**：OpenLS-DGF 只覆盖组合逻辑。现实中的逻辑综合需要在保留寄存器/时钟边界的前提下优化，这需要扩展到 sequential circuits。

## 10. 讨论与局限

### 10.1 论文自述的局限

论文讨论部分 (Section VI) 承认：
1. 当前仅覆盖组合逻辑，未涉及 sequential circuits
2. 框架适合用于 ML 方法在逻辑综合中的快速原型开发，但距离直接在工业环境部署仍有距离

### 10.2 代码/复现层面的问题

从 [OpenLS-DGF论文与代码复现详解.md](./OpenLS-DGF论文与代码复现详解.md) 提炼的关键差异：

| 问题 | 论文/期望 | 代码实际 | 影响 |
|------|----------|---------|------|
| Recipe 共享 | 同一 recipe index 跨 design 应共享相同命令序列 | 每个 design/thread 内独立随机生成 | QoR 预测的 "unseen recipe" 实验定义不成立 |
| 数据可用性 | OpenLS-D-v1 可从 Hugging Face 下载 | README 仍显示 "uploading..." | **复现的根本障碍**——需要自己跑 76h+65h 生成流程 |
| 分类 feature | node type + truth table | 21 维 one-hot + 未固定种子的随机 padding | 实验结果不可精确复现 |
| 排序指标实现 | 标准 P/R/F1 | 代码把"预测是否正确"当"预测类别"计算 | 论文报告的 Precision/Recall/F1 需要重算 |
| QoR 序列长度 | 论文 recipe 长度 10 | 模型硬编码 sequence length 20 | 模型无法正确处理论文描述的输入 |
| 概率标签 | fanin 信号的真值表 | 代码把 fanin 节点编号当逻辑值 | 标签可能错误 |
| 许可证 | — | 根目录无覆盖全项目的 LICENSE | 商用或再发布存在法律风险 |

**数据规模门槛**：完整生成需要 32 线程 Xeon Platinum 8380 约 141 小时（raw 76h + 压缩 65h），产出 1.1 TB 文件。这对大多数研究组构成显著的算力/存储门槛。

### 10.3 本资料包的批判性分析

**「适应性」到底有多适应？** 论文声称 OpenLS-DGF 是 "adaptive"（适应性的），体现在：(a) 半可定制的 Verilog 中间文件允许插入额外步骤；(b) Circuit Engine 支持按需抽取子数据集。但当前框架的适应性局限在论文预设的四类任务（分类/排序/QoR/概率）——如果你想做 SAT 求解器的变量排序预测、或等价节点匹配、或功耗预测，你需要自己修改 Circuit Engine 的数据抽取逻辑和标注生成，这不是"开箱即用"的。

**966k 电路的「多样性」是否真的有用？** 46 个 design × 1000 条 recipe × 21 种产物 = 966k。但 1000 条 recipe 中有大量会产生相似 QoR 的"近邻 recipe"——这些变体对 GNN 训练的信息增益可能递减。如果只用 100 条精心挑选的 recipe（覆盖 QoR 分布的两端和中间），能否达到接近 1000 条的模型效果？论文没有做 recipe 数量的消融实验（概率预测有，但其他任务没有）。

**与 OpenABC-D 的关系**：OpenLS-D-v1 的源设计扩展了 EPFL（OpenABC-D 不含 EPFL），增加了 LSILS 的 6 种 Boolean network 和 STA 标注。可以说 OpenLS-D-v1 是 OpenABC-D 的超集+增强版，但它没有替代后者——OpenABC-D 包含物理设计阶段的中间文件（floorplan/placement/CTS/routing），而 OpenLS-D-v1 只停在了 STA（阶段 ⑤ 之后）。

## 12. 一分钟复述版

OpenLS-DGF（中科院计算所 + 鹏城实验室 + 多所高校，arXiv 2024）是一个**逻辑综合数据集生成框架**，不是新的神经网络模型。七步管线：(1) Yosys 把 Verilog/AIG/BLIF 源设计转成 GTG；(2) GTG 转 AIG；(3) ABC 用 1000 条随机 recipe（balance/rewrite/refactor/resub 及变体，每条长度 10）对每个 AIG 做 1000 次优化；(4) LSILS logic blasting 把 AIG 转成 OIG/XAG/MIG/PRIMARY/GTG 共 6 种 Boolean network；(5) Technology mapping 产出 ASIC (Sky130) 和 FPGA (LUT6) 网表；(6) iEDA 跑 STA 产出 timing + area 标注；(7) ACE Circuit Engine 打包为 PyTorch Geometric 格式。最终产出 OpenLS-D-v1：46 设计 × 1000 recipe × 21 产物 = 966,000 电路，raw 410GB + PT 700GB。

四个下游任务验证数据质量：电路分类 99.8%（设计可区分性）、电路排序 F1=0.665（新提出的 QoR 比较任务）、QoR 预测 Area MAPE 0.69%（面积可预测）、概率预测 PE=0.0002（节点行为可学习）。

核心创新：(1) 首个覆盖 Boolean 表示+优化+映射+STA 四环节的统一数据集框架；(2) 多 Boolean network logic blasting + 形式化依赖保持定理；(3) Circuit Engine 作为异构工具链和 PyG 之间的统一桥梁。

主要局限：数据 1.1TB 且状态"uploading..."、recipe 跨 design 不共享、代码多个实现与论文不一致、仅限组合逻辑、缺少完整 license。
