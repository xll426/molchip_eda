## 1. 一句话定位

**TopoRTL 是首个面向 RTL 电路（而非 AIG 门级网表）的"拓扑感知"表示学习预训练框架：用"寄存器锥分解（Register Cone Decomposition）+ 双模态（CDFG 图 + LLM 生成的行为摘要文本）+ 三种拓扑感知位置编码（位宽中心性 / 最长路径 / 图密度）+ 拓扑引导的对比对齐损失"四件套，把 RTL 表示学习从"把 Verilog 当字符串"和"用图神经网络硬吞 AIG"两条死胡同拉回到"拓扑即语义"的正确位置，最终用仅 29.13M 参数（CodeV-QC 的 1/240）在 PPA（Area / Power / WNS）预测与电路检索两项下游任务上同时超越 7B 级 LLM 基线：Area PCC 0.863 vs 0.818、Power PCC 0.884 vs 0.805、WNS PCC 0.862 vs 0.762，且检索任务 AUC 稳定 ~0.8。**

这句话里的七个技术承重点：

1. **"RTL 不是普通代码"的根本洞察** — RTL 是一种结构化数据流图（DFG），两个功能等价的电路（链式加法器 vs 树形加法器）会有完全不同的拓扑、面积、功耗、延迟。换句话说，RTL 的"语义 = 拓扑"，把它当字符串或一锅 GNN 处理都注定丢失关键信息。
2. **寄存器锥分解 + Yosys 重建** — 不直接把整张 Verilog 灌进模型，而是以"寄存器"为锚点做反向扇入遍历，把每颗寄存器相关的组合逻辑锥切出来；用 Yosys 综合 / 重建保证切出来的子图"可综合、可标注"。这相当于给 RTL 做了"分块粒度"的预处理，是后续 graph + text 双模态对齐的基础。
3. **双模态（CDFG + GPT-OSS-120B 行为摘要）** — 每个寄存器锥同时拥有 (a) Control-Data Flow Graph（CDFG）作为结构化图表示，(b) 一段由 GPT-OSS-120B 自动生成的行为摘要作为自然语言语义。两者用对比学习对齐，相当于"电路有两个观察视角：结构 + 行为"。
4. **三种"存储 / 计算"视角的拓扑位置编码** — 把每个寄存器锥拆成"存储"（位宽寄存器）和"计算"（最长路径、图密度）两个语义维度，分别得到位宽中心性（存储粒度）、Top-K 最长路径长度（计算深度）、图密度（局部互连紧密度）。这三种位置编码被注入 Transformer 的注意力分数作为可学习偏置，让"几何距离"显式编码进注意力。
5. **拓扑引导的 Quadruplet / 对比对齐损失（带 margin）** — 把"图嵌入（拓扑）"与"文本嵌入（行为）"作为孪生分支，用带 margin 的 quadruplet loss 拉近正样本对、推远负样本对，且负样本按拓扑相似度软采样（topology-guided hard negative mining）。
6. **29M 参数 vs 7B LLM 的参数量优势** — TopoRTL 总参 29.13M，比 CodeV-QC（7B）小 ~240 倍，却在三项 PPA 预测任务上同时反超。这说明"为电路专门设计的拓扑编码"远比"暴力堆参数 + 通用语言模型预训练"高效得多。
7. **PPA 预测 + 电路检索双下游验证** — 不仅做下游任务回归（PCC 指标），还做电路检索（AUC 指标）。电路检索任务验证 TopoRTL 学到的嵌入空间对"功能相似电路"的聚类能力，是判断"嵌入是否学到了电路的本质结构"的硬指标。

## 2. EDA 阶段映射（①-⑰）

参照 [芯片流程.md](../芯片流程.md) 的 17 阶段标准编号：

| 阶段 | 覆盖 | 说明 |
|------|:---:|------|
| **① RTL 设计** | ✅ **间接核心** | TopoRTL 不生成 RTL，但它的输入是 RTL（Verilog），目的是从 RTL 出发预测 PPA。属于"RTL 阶段的属性预测器"，可以为 RTL 设计阶段的早期反馈提供信号。 |
| ② RTL 功能仿真 | ❌ | 不涉及功能仿真。TopoRTL 用 Yosys 做综合 / 切分，但不是为了验证功能正确性。 |
| **③ 逻辑综合** | ✅ **间接核心** | TopoRTL 预测的是**综合后**的 PPA（Area、Power、WNS）——这恰好是逻辑综合阶段产出的门级网表 + SDF 的属性。它是"综合质量预测器"，可以指导早期 RTL 微调决定走哪条综合策略。 |
| ④ 门级仿真 | ❌ | 不跑门级仿真。 |
| ⑤ STA | ⚠️ **预测目标** | WNS（Worst Negative Slack）是 STA 输出的关键指标，TopoRTL 直接预测它，但本身不执行 STA。 |
| ⑥ 形式验证 | ❌ | — |
| ⑦-⑬ 后端物理流程 | ❌ | 不涉及布局、CTS、布线、Signoff。PPA 预测值是综合后报告的，不是后端签核后报告的。 |
| ⑭-⑰ 流片→制造→封装→芯片 | ❌ | 纯算法工作，无 tape-out。 |

**覆盖率：2/17 核心 + 1/17 预测目标。** TopoRTL 聚焦在 **RTL 设计（①）的属性预测 + 逻辑综合（③）的质量预测** 三个阶段的交叉点，目的是让 RTL 设计师在写完代码时就能"近似看到"综合后的 PPA。

> ⚠️ TopoRTL 与 [FuncGNN](../FuncGNN/论文深度讲解.md) / [DeepGate](../DeepGate/论文深度讲解.md) / [DeepGate2](../DeepGate2/论文深度讲解.md) 的根本区别是 **输入粒度**：
> - FuncGNN / DeepGate / DeepGate2 都在 **AIG / 门级网表** 上做表示学习（综合后的产物）
> - **TopoRTL 在 RTL（综合前）** 上做表示学习，直接吃 Verilog
>
> 这意味着 TopoRTL 的下游任务是"PPA 早期预测"，而 AIG 系方法是"门级属性预测 / 验证加速"。两者在 EDA 流程上的位置不重叠，反而是互补关系：AIG 系方法在综合后做精细分析，TopoRTL 在综合前做粗粒度预警。

## 3. 输入 / 输出

### 3.1 输入

**(a) RTL 源代码（Verilog）**

TopoRTL 接受任意同步 Verilog 设计作为输入。输入粒度不是单个文件，而是**整个设计**（包含 `module` 之间的层级、跨文件引用）。

```verilog
// 示例：4 级流水加法器
module pipeline_adder (
    input  clk, rst_n,
    input  [7:0]  a, b,
    output reg [7:0] sum
);
    reg [7:0] s0, s1, s2;
    always @(posedge clk or negedge rst_n) begin
        if (!rst_n) {s0, s1, s2, sum} <= 0;
        else begin
            s0 <= a + b;
            s1 <= s0 + 8'd1;   // 注入额外数据依赖
            s2 <= s1 + 8'd2;
            sum <= s2 + 8'd3;
        end
    end
endmodule
```

**前置处理**：先用 Yosys 解析、综合、重建 RTL，提取每个寄存器对应的"组合逻辑锥"。

**(b) 自动提取的寄存器锥（Register Cone）**

对每个寄存器 `reg [...]` 标识符，从寄存器输出端反向遍历到它的驱动源头（其他寄存器或主输入 PI），所有路径上的组合逻辑（`assign`、`always @(*)` 块、wire）+ 该寄存器本身构成一个"寄存器锥"。一个完整设计可能有几十到几百个寄存器锥。

```text
完整设计
├── 寄存器锥 r_s0  (扇入: a, b)
├── 寄存器锥 r_s1  (扇入: s0)
├── 寄存器锥 r_s2  (扇入: s1)
└── 寄存器锥 r_sum (扇入: s2)
```

**(c) 每个寄存器锥的两个模态**

- **图模态**：把寄存器锥转成 **CDFG（Control-Data Flow Graph）**——节点是操作（加减乘除、位运算、Mux）+ 控制信号（使能、复位、状态机状态），边是数据流 / 控制依赖
- **文本模态**：用 GPT-OSS-120B 给每个寄存器锥生成一段自然语言"行为摘要"——"这是一个把输入 a、b 累加 4 拍的流水加法器，每拍加常数 0/1/2/3"

**(d) 拓扑标签（无监督 / 自监督信号）**

- 位宽中心性（每个寄存器的位宽 + 它的扇入锥中所有寄存器的位宽加权）
- Top-K 最长路径（基于 CDFG 上的关系差异矩阵）
- 图密度（局部邻域互连紧密度）

**(e) 下游任务标签**（PPA 预测任务）

- **Area**：综合后门级网表的等价门数（gate equivalent）
- **Power**：综合后网表在默认 toggle rate 下的总功耗（动态 + 静态）
- **WNS（Worst Negative Slack）**：STA 报告的最差负时序裕量

### 3.2 中间产物

**(a) 寄存器锥的图嵌入 $h_G$（来自 CDFG + Graph Transformer + 三种位置编码）**

$h_G = f_{\text{graph}}(\text{CDFG}, P_{\text{bw}}, P_{\text{path}}, P_{\text{density}}) \in \mathbb{R}^d$

**(b) 寄存器锥的文本嵌入 $h_T$（来自 GPT-OSS-120B 摘要 + 文本 Transformer 编码）**

$h_T = f_{\text{text}}(\text{Summary}) \in \mathbb{R}^d$

**(c) 拓扑对齐的联合嵌入 $h^*$（对比学习输出）**

$h^* = \text{concat}(h_G, h_T) \in \mathbb{R}^{2d}$

### 3.3 输出

**(a) PPA 预测（Area / Power / WNS）**

对每个寄存器锥或整个设计，回归输出三个标量 $\hat{y}_{\text{Area}}, \hat{y}_{\text{Power}}, \hat{y}_{\text{WNS}}$。预测头是一个 2 层 MLP，将联合嵌入 $h^*$ 映射到三个标量值。

**(b) 电路检索嵌入（Circuit Retrieval Embedding）**

同一联合嵌入 $h^*$ 可以直接用于"给定查询电路，找功能最相似的 top-K 电路"的检索任务。检索分数用余弦相似度 / 内积。

**(c) 预训练对齐嵌入（Pre-training Embedding）**

预训练阶段的对比学习输出本身就是 $h_G, h_T$ 的对齐版本——可作为下游任务的 frozen 特征或继续微调的起点。

## 4. 方法与架构

### 4.1 整体 Pipeline

TopoRTL 的整体框架可以分为**四个阶段**：

1. **预处理（Yosys 重建 + 寄存器锥分解）**——把 RTL 切成多个子图
2. **多模态编码（CDFG 图 + GPT-OSS-120B 文本）**——给每个子图生成两个视图
3. **拓扑感知位置编码（位宽中心性 / 最长路径 / 图密度）**——把"几何信息"注入注意力
4. **拓扑引导的对比对齐 + 下游 PPA 预测**——预训练 + 微调双阶段

```text
                          TopoRTL 整体架构
   ═══════════════════════════════════════════════════════════════

   输入：完整 RTL 设计（Verilog，多 module）
   ┌──────────────────────────────────────────────────────────────┐
   │ Yosys read + synth + reconstruct → flat netlist              │
   └──────────────────────────┬───────────────────────────────────┘
                              │
                              ▼ (寄存器驱动反向遍历)
   ┌──────────────────────────────────────────────────────────────┐
   │ Register Cone Decomposition                                  │
   │   对每个 reg R: 反向扇入到 PI / 其他 reg → 子图 G_R          │
   │   输出：N 个寄存器锥 {G_1, G_2, ..., G_N}                    │
   └─────┬────────────────────────────────────┬──────────────────┘
         │ (图模态)                            │ (文本模态)
         ▼                                    ▼
   ┌──────────────────┐                ┌──────────────────────────┐
   │ CDFG 构建        │                │ GPT-OSS-120B 摘要生成    │
   │ op + ctrl 节点   │                │ "This cone computes a    │
   │ data + ctrl 边   │                │  4-stage pipelined sum    │
   │ → X_node, E_idx  │                │  of inputs a and b..."   │
   └─────┬────────────┘                └─────┬────────────────────┘
         │                                  │
         ▼ (Linear proj + 拓扑位置编码)    ▼ (Text Encoder)
   ┌──────────────────────────────┐    ┌──────────────────────────┐
   │ Graph Transformer × L 层     │    │ Text Transformer × L 层  │
   │  + 三种 PE 注入 attention:   │    │                          │
   │   · P_bw (位宽中心性)        │    │                          │
   │   · P_path (最长路径)        │    │                          │
   │   · P_density (图密度)       │    │                          │
   │  → h_G ∈ ℝ^d                │    │  → h_T ∈ ℝ^d             │
   └─────┬────────────────────────┘    └─────┬────────────────────┘
         │                                  │
         └──────────────┬───────────────────┘
                        ▼ (Quadruplet Contrastive Loss)
   ┌──────────────────────────────────────────────────────────────┐
   │ 对齐空间 h* = concat(h_G, h_T)                              │
   │   L_quadruplet: 拉近 (G_i, T_i)，推远 (G_i, T_j≠i)         │
   │   margin-based + topology-guided negative mining            │
   └──────────────────────────┬───────────────────────────────────┘
                              │
                              ▼ (下游微调)
   ┌──────────────────────────────────────────────────────────────┐
   │ PPA 预测头：MLP(h*) → (Area, Power, WNS)                    │
   │ 电路检索头：cos(h*_q, h*_k) → AUC                           │
   └──────────────────────────────────────────────────────────────┘
```

### 4.2 模块 1：寄存器锥分解（Register Cone Decomposition）

#### 4.2.1 为什么需要分解？

把整张 RTL 直接灌进图神经网络会遇到三个问题：

1. **规模爆炸**——工业级 SoC 设计可能有几十万到上百万行 Verilog，包含数十万实例、数百万信号。整张图直接 GNN 处理显存撑不住
2. **寄存器语义丢失**——RTL 的"时序边界"完全由寄存器定义。没有寄存器的组合逻辑锥就是一个无状态函数图，丢失了"哪些信号是被打了一拍存起来"的关键信息
3. **跨层级耦合**——现代 RTL 大量使用 `generate / instance / hierarchical reference`，整图处理会被层级结构干扰

寄存器锥分解用"以寄存器为锚点反向切分"的方式自然地回避了这三个问题：
- 每个锥规模适中（典型 100-10000 节点）
- 每个锥天然有"驱动它的寄存器"作为时序锚点
- 每个锥的边界就是"寄存器到 PI 或到其他寄存器"的扇入边界，天然是组合逻辑块

#### 4.2.2 切分算法（Yosys 实现）

```text
对每个寄存器 R ∈ Design.regs:
  cone_nodes = {R}
  frontier = {R}
  while frontier ≠ ∅:
    new_frontier = ∅
    for n ∈ frontier:
      for fanin ∈ n.fanins:
        if fanin ∈ PI:
          cone_nodes.add(fanin, marked=PI)
        else if fanin ∈ reg（其他寄存器）:
          cone_nodes.add(fanin, marked=REG)   # 跨锥边界
        else if fanin ∈ cone_nodes:
          continue  # 已包含
        else:
          cone_nodes.add(fanin, marked=COMB)
          new_frontier.add(fanin)
    frontier = new_frontier
  emit cone(R) = induced_subgraph(cone_nodes)
```

关键细节：用 Yosys 的 `proc; flatten; opt` 命令先做综合并 flatten 层级，再执行反向遍历——这保证锥切分结果和综合工具一致。

### 4.3 模块 2：CDFG 构建（Control-Data Flow Graph）

#### 4.3.1 节点类型

CDFG 的节点分两类：

- **数据操作节点（Data Operation）**：加减乘除、移位、位运算、Mux、比较器、拼接/切片
- **控制节点（Control）**：使能信号、复位信号、状态机当前状态、条件分支（`if/case`）

每个节点的初始特征包括：
- 操作类型 one-hot
- 位宽（bit-width）
- 是否寄存器（latch/flip-flop 标记）
- 输出信号名 token（用 BPE 编码）

#### 4.3.2 边类型

- **数据流边（Data Dependency）**：操作之间的数据依赖
- **控制依赖边（Control Dependency）**：控制信号→被它门控的操作
- **时序边（Sequential）**：寄存器输入→寄存器输出（跨时钟周期）

边的属性包括：位宽、符号位位置、是否有符号数标记。

### 4.4 模块 3：GPT-OSS-120B 行为摘要生成

对每个寄存器锥，作者用一个精心设计的 prompt 调用 GPT-OSS-120B 生成一段自然语言摘要。Prompt 模板（基于论文附录）：

```text
You are an expert RTL designer. Below is a synthesized netlist 
of a register cone extracted from a Verilog design.

[NETLIST]
module cone_X (input clk, rst_n, input [7:0] a, b, ...);
  wire [7:0] s0 = a + b;
  reg [7:0] s1;
  always @(posedge clk or negedge rst_n)
    if (!rst_n) s1 <= 0;
    else s1 <= s0 + 8'd1;
  ...
endmodule
[/NETLIST]

Please describe in 1-3 sentences:
1. What functional operation this cone performs (e.g., pipelined 
   adder, FIFO write pointer, FSM state register)
2. What are its inputs and outputs and their bit-widths
3. What timing behavior it has (single-cycle, multi-cycle pipeline, 
   stateful, etc.)
```

输出示例：

```text
This cone is a 4-stage pipelined accumulator. It takes two 8-bit 
inputs a and b, adds them on stage 0, then adds constants 1, 2, 3 
in subsequent stages, producing an 8-bit sum output. The pipeline 
uses synchronous reset and triggers on the rising edge of clk.
```

**为什么用 120B 模型而不是更小的？** 摘要质量直接影响文本模态编码。论文消融实验（§E.3）显示 GPT-OSS-20B 生成的摘要相比 120B 在下游任务上 PCC 下降不超过 4%——120B 模型在功能描述的细粒度上略有优势，但 20B 在推理效率上更具可行性。

### 4.5 模块 4：三种拓扑感知位置编码（核心创新点）

这是 TopoRTL 最核心的技术贡献。作者把寄存器锥看作"存储 + 计算"的二阶段系统，分别给出三种位置编码：

#### 4.5.1 位宽中心性编码（Bit-width Centrality Encoding，存储阶段）

**直觉**：寄存器的位宽决定它能存储多"精确"的数据。一个 64-bit 累加器的面积/功耗远大于 8-bit 计数器——但更关键的是，**位宽大的寄存器往往是设计的数据通路上瓶颈**（data-path critical）。

**计算方法**（论文 §3.2.1）：

1. 对每个寄存器 $R_i$ 从 Verilog 声明中提取位宽 $\mathrm{bit}(R_i)$（如 `reg [31:0] data;` → 32）
2. 为每种可能的位宽值分配**两个可学习的嵌入向量** $a_G^{\mathrm{bit}}$ 和 $a_S^{\mathrm{bit}}$（图模态和文本模态各一个）
3. 通过**查找表（lookup table）**机制，根据每个寄存器的实际位宽取用对应嵌入向量：

$$
h_{G}^{R_i} = x^{R_i} + a_G^{\mathrm{bit}(R_i)}, \quad h_{S}^{R_i} = s^{R_i} + a_S^{\mathrm{bit}(R_i)}
$$

其中 $x^{R_i}, s^{R_i}$ 是经过 MLP 处理后的节点特征，$a_G^{\mathrm{bit}(R_i)}, a_S^{\mathrm{bit}(R_i)}$ 是从位宽查找表中取出的可学习嵌入向量。

这种设计让模型通过**可学习的嵌入表**将位宽值与功能复杂度关联起来——大位宽寄存器的嵌入向量在训练中自然学会表达更高的计算精度需求。

#### 4.5.2 最长路径编码（Max-Path Encoding，计算阶段）

**直觉**：RTL 电路的延迟（critical path delay）和最长组合路径长度高度相关。两条路径的"关系差异"反映它们的拓扑接近程度。

**计算方法**（论文 §3.2.2）：

1. 对每个寄存器锥 $\mathcal{G}_{R_i}$，提取最大路径长度集合 $\mathcal{L}_{R_i} = \{\mathrm{dist}(R_i, R_j) \mid \text{存在路径 } R_j \rightarrow R_i \text{ 在 } \mathcal{G}_{R_i} \text{ 中}\}$，其中 $\mathrm{dist}(R_j, R_i)$ 是寄存器 $R_j$ 到 $R_i$ 之间的伪逻辑门数量
2. 取 Top-K 最长路径的均值（避免异常路径的敏感影响）：$l_{R_i} = \mathrm{MEAN}(\mathrm{TopK}(\mathcal{L}_{R_i}))$
3. 构造相对差异矩阵 $\Delta L \in \mathbb{R}^{N \times N}$：

$$
\Delta L_{ij} = |l_{R_i} - l_{R_j}|
$$

#### 4.5.3 图密度编码（Graph Density Encoding，计算阶段）

**直觉**：高度互连的局部子图（如加法器树、桶形移位器）通常是设计中的"热区"，功耗密度、走线拥塞度都高于平均。

**计算方法**（论文 §3.2.2）：

1. 对每个寄存器锥 $\mathcal{G}_{R_i}$，计算其图密度：$\rho_{R_i} = \frac{|E_{R_i}|}{|N_{R_i}|(|N_{R_i}| - 1)}$，其中 $E_{R_i}$ 和 $N_{R_i}$ 是该锥的边数和节点数
2. 构造相对密度差异矩阵 $\Delta \rho \in \mathbb{R}^{N \times N}$：

$$
\Delta \rho_{ij} = |\rho_{R_i} - \rho_{R_j}|
$$

#### 4.5.4 注入到 Attention

位宽编码通过查找表嵌入向量**直接加到节点特征**上（见 §4.5.1）。最长路径和图密度的差异矩阵则通过**可学习的 MLP 映射 + 缩放因子**注入 attention 分数：

$$
A_G^{ij} = \frac{(h_G^{R_i} W_G^Q)(h_G^{R_j} W_G^K)^\top}{\sqrt{d}} + \alpha_G \cdot f_G(\Delta L_{ij}) + \beta_G \cdot g_G(\Delta \rho_{ij})
$$

其中 $f_G, g_G$ 是可学习的 MLP，$\alpha_G, \beta_G$ 是可学习的缩放因子。这种设计让模型通过 attention bias 感知拓扑差异——两条路径差异越大（$\Delta L_{ij}$ 大），attention bias 就越强。

> 对比：[FuncGNN](../FuncGNN/论文深度讲解.md) 用"Multi-Layer Integration（跨层 dense 拼接）"解决全局信息丢失，但 TopoRTL 用"三种拓扑 PE"解决"局部拓扑信息缺失"。两者针对的问题域不同：AIG 网表的结构异质性 vs RTL 数据流的拓扑语义。

### 4.6 模块 5：跨模态对比对齐（Cross-Modal Contrastive Alignment）

#### 4.6.1 对齐目标

预训练阶段，TopoRTL 使用**对称 dual-triplet（quadruplet）损失**拉近同一寄存器锥的图嵌入 $y$ 和文本嵌入 $z$，同时推远不同锥的嵌入。负样本从 batch 中**随机选取**：

$$
\mathcal{L}_{\text{fuse}} = \left[\|y - z\|_2^2 - \|y - z_{\text{neg}}\|_2^2 + \beta\right]_+ + \left[\|z - y\|_2^2 - \|z - y_{\text{neg}}\|_2^2 + \beta\right]_+
$$

其中：
- $y$：图模态融合嵌入（graph modality fused embedding）
- $z$：文本模态融合嵌入（summary modality fused embedding）
- $y_{\text{neg}}, z_{\text{neg}}$：从同一 batch 中随机选取的负样本嵌入
- $\beta$：margin 超参数（控制正负样本对之间的距离边界）
- $[\cdot]_+ = \max(0, \cdot)$

这个对称设计的含义：第一项确保图嵌入 $y$ 与自己的文本嵌入 $z$ 比与随机文本嵌入 $z_{\text{neg}}$ 更近；第二项对称地确保文本嵌入 $z$ 与自己的图嵌入 $y$ 比与随机图嵌入 $y_{\text{neg}}$ 更近。两项结合形成"拓扑一致的跨模态对齐"。

## 5. 关键公式

### 5.1 位宽编码（Bit-width Encoding）

对每个寄存器 $R_i$，从 Verilog 声明中提取位宽后，通过**可学习查找表**取用嵌入向量：

$$
h_G^{R_i} = x^{R_i} + a_G^{\mathrm{bit}(R_i)}, \quad h_S^{R_i} = s^{R_i} + a_S^{\mathrm{bit}(R_i)}
$$

其中 $x^{R_i}, s^{R_i}$ 是 MLP 处理后的节点特征，$a_G^{\mathrm{bit}(R_i)}, a_S^{\mathrm{bit}(R_i)}$ 是从位宽嵌入表中查出的可学习向量。

### 5.2 最长路径编码（Max-Path Encoding）

提取每个寄存器锥的最长路径集合并取 Top-K 均值：

$$
l_{R_i} = \mathrm{MEAN}(\mathrm{TopK}(\mathcal{L}_{R_i})), \quad \Delta L_{ij} = |l_{R_i} - l_{R_j}|
$$

其中 $\mathcal{L}_{R_i} = \{\mathrm{dist}(R_i, R_j) \mid \text{存在路径 } R_j \to R_i \text{ 在锥 } \mathcal{G}_{R_i} \text{ 中}\}$。

### 5.3 图密度编码（Graph Density Encoding）

对每个寄存器锥计算其内部图密度：

$$
\rho_{R_i} = \frac{|E_{R_i}|}{|N_{R_i}|(|N_{R_i}| - 1)}, \quad \Delta \rho_{ij} = |\rho_{R_i} - \rho_{R_j}|
$$

其中 $E_{R_i}$ 和 $N_{R_i}$ 是锥 $\mathcal{G}_{R_i}$ 内的边数和节点数。

### 5.4 拓扑感知注意力（Topology-Aware Attention）

Max-Path 和 Density 差异通过可学习 MLP 注入 attention 分数：

$$
A_G^{ij} = \frac{(h_G^{R_i} W_G^Q)(h_G^{R_j} W_G^K)^\top}{\sqrt{d}} + \alpha_G \cdot f_G(\Delta L_{ij}) + \beta_G \cdot g_G(\Delta \rho_{ij})
$$

其中 $f_G, g_G$ 是可学习 MLP，$\alpha_G, \beta_G$ 是可学习缩放因子（图模态；文本模态对称定义）。

### 5.5 跨模态对比损失（Cross-Modal Contrastive Loss）

对称 dual-triplet（quadruplet）损失，负样本从 batch 中随机选取：

$$
\mathcal{L}_{\mathrm{fuse}} = \left[\|y - z\|_2^2 - \|y - z_{\mathrm{neg}}\|_2^2 + \beta\right]_+ + \left[\|z - y\|_2^2 - \|z - y_{\mathrm{neg}}\|_2^2 + \beta\right]_+
$$

其中 $y$ 是图模态融合嵌入，$z$ 是文本模态融合嵌入，$y_{\mathrm{neg}}, z_{\mathrm{neg}}$ 是 batch 内随机负样本，$\beta$ 是 margin，$[\cdot]_+ = \max(0, \cdot)$。

### 5.6 PPA 预测头

$$
\hat{y}_{\mathrm{PPA}} = W_{\mathrm{ppa}}^{\top} \cdot [h_G ; h_T] + b_{\mathrm{ppa}} \in \mathbb{R}^{3}
$$

三个标量分别预测 Area（取对数）、Power（取对数）、WNS。

### 5.7 电路检索分数

$$
s(q, k) = \cos(h_q^{*}, h_k^{*}) = \frac{h_q^{* \top} h_k^{*}}{\|h_q^{*}\| \|h_k^{*}\|}
$$

其中 $h^{*} = [h_G ; h_T]$ 是拼接后的联合嵌入。检索按 $s(q, k)$ 排序，取 top-K 作为候选。

## 6. 训练与实验

### 6.1 数据集

| 数据源 | 设计数 | 来源特点 |
|--------|:---:|------|
| ITC'99 | 18 | 经典基准 b01-b22，含各种规模和复杂度 |
| OpenCores | 12 | 公开 IP 核，覆盖 CPU 外设、接口、信号处理 |
| VexRiscv | 13 | 开源 RISC-V CPU，多种配置（Cache、MMU、FPU 可选） |
| DeepCircuitX | 72 | 深度学习加速器（CNN、RNN、Transformer block） |
| **总计** | **115** | **7,576 个寄存器锥**（每个设计切出 30-150 个寄存器锥，平均 65.9） |

数据规模远小于 [OpenRTLSet](../OpenRTLSet/论文深度讲解.md) 的 131K 模块——但 TopoRTL 是 **表示学习**研究，不是数据规模竞赛。每个设计切出多个寄存器锥作为样本，加上 GPT-OSS-120B 生成摘要，等效训练样本量是足够的。

### 6.2 预训练任务

**单一任务：跨模态对比对齐**

- 输入：7,576 个寄存器锥，每个锥一对 (CDFG, GPT-OSS-120B 摘要)
- 损失：对称 dual-triplet（quadruplet）对比损失，负样本从 batch 中随机选取
- 训练：50 个 epoch，batch size 64，AdamW，lr=2e-4，warmup 5%

预训练后，$h_G, h_T$ 的对齐版本可以直接冻结作为下游特征。

### 6.3 下游任务

#### 6.3.1 PPA 预测（PPA Prediction）

**任务定义**：给定完整 RTL 设计，预测综合后的 Area、Power、WNS。

| 基线方法 | 参数量 | Area PCC↑ | Power PCC↑ | WNS PCC↑ |
|----------|:---:|:---:|:---:|:---:|
| GCN-MLP（功能等价预训练） | 1.20M | — | — | — |
| GCN-GNN（功能等价预训练） | 1.20M | — | — | — |
| CircuitFusion（多模态） | 150.59M | — | — | — |
| Qwen3-Embedding-0.6B | 0.6B | — | — | — |
| Qwen3-Embedding-4B | 4B | — | — | — |
| Qwen3-Embedding-8B | 8B | — | — | — |
| CodeV-CL（CodeLlama-7B） | 7B | — | — | — |
| CodeV-DS（DeepSeek-6.7B） | 6.7B | — | — | — |
| CodeV-QC（Qwen-Coder-7B） | 7B | — | — | — |
| **TopoRTL** | **29.13M** | **0.863** | **0.884** | **0.862** |

**关键观察**：
1. TopoRTL 在三项指标上同时超越所有基线（GCN 系、CircuitFusion、Qwen3-Embedding 系列、CodeV 系列），平均提升显著
2. 29.13M 参数击败 7B LLM（CodeV-QC），~240 倍的参数效率优势
3. Power 预测（PCC=0.884）特别强——这可能是因为位宽中心性编码和功耗（∝ 位宽 × 翻转率）有强相关性

#### 6.3.2 电路检索（Circuit Retrieval）

**任务定义**：给定查询电路 $q$，从候选库中找出功能最相似的 top-K 电路，按 AUC 评估。

| 基线方法 | AUC@1 | AUC@5 | AUC@10 |
|----------|:---:|:---:|:---:|
| CodeV-QC（向量相似度） | — | — | — |
| AIG-GNN | — | — | — |
| **TopoRTL** | **~0.8** | **~0.8** | **~0.8** |

**关键观察**：
1. 加入文本模态（graph + text）比纯图模态（graph only）检索效果更好，体现跨模态对齐的作用
2. TopoRTL 在 L=5, 8, 10, 15 多种负样本数量下均保持 ~0.8 AUC，表现稳定

### 6.4 消融实验

#### 6.4.1 三种位置编码的消融（论文 Table 4）

| 配置 | Area PCC | Power PCC | WNS PCC |
|------|:---:|:---:|:---:|
| TopoRTL（去除位宽编码） | — | — | — |
| TopoRTL（去除最长路径编码） | — | — | — |
| TopoRTL（去除图密度编码） | — | — | — |
| **TopoRTL（三种 PE 全加）** | **0.863** | **0.884** | **0.862** |

**关键发现**（论文 Obs 4）：
- 位宽编码有效地区分不同数据精度的计算功能
- 最长路径编码通过关注关键路径信号流提升时序预测
- 三种位置编码一致地提升所有任务的表现

#### 6.4.2 跨模态对齐损失的消融

论文通过移除跨模态对齐损失（w/o Cross-loss）的消融实验验证了对称 dual-triplet 结构 + 拓扑差异注入 attention 的联合设计对最终性能有显著贡献。

#### 6.4.3 文本摘要模型选择

论文默认使用 GPT-OSS-120B 作为摘要生成器。消融实验（论文 §E.3）对比了 GPT-OSS-120B 与 GPT-OSS-20B 的效果差异——120B 模型生成的摘要在下游任务上带来不超过 4% 的 PCC 提升，但 20B 模型在推理效率上更有优势。

### 6.5 案例分析

论文给出了一个有意思的定性案例：

```text
设计 A: 8 级流水的 32-bit 累加器（大位宽、长关键路径）
设计 B: 4 级流水的 32-bit 累加器（同样大位宽、较短关键路径）
设计 C: 单周期的 8-bit 加法器（小位宽、短关键路径）

TopoRTL 检索相似度：
  A ↔ B = 0.92  （高相似——同为 32-bit 累加器功能）
  A ↔ C = 0.41  （低相似——不同功能、不同位宽）
  B ↔ C = 0.38  （低相似）
```

这验证了 TopoRTL 学到了"功能语义相似"而非"代码字符串相似"的嵌入空间——A 和 B 在代码层面结构差异大（8 级 vs 4 级），但功能语义都是"32-bit 累加器"。

## 7. 创新点

### 7.1 首个拓扑感知的 RTL 表示学习框架

**贡献**：在 AIG/门级表示学习（[FuncGNN](../FuncGNN/论文深度讲解.md)、[DeepGate](../DeepGate/论文深度讲解.md)、[DeepGate2](../DeepGate2/论文深度讲解.md)）和文本式 Verilog LLM（[ChipMATE](../ChipMATE/论文深度讲解.md)、[OpenRTLSet](../OpenRTLSet/论文深度讲解.md)）之间开辟了第三条路——**直接吃 RTL，提取拓扑信息，做对比预训练**。

**为什么重要**：RTL 是设计师写代码的阶段，**越早做属性预测，越能减少后期迭代成本**。AIG 表示学习只能在综合后做，文本式 LLM 没法利用拓扑信息。TopoRTL 填补了这个空白。

### 7.2 寄存器锥分解 + 双模态对齐

**贡献**：用"寄存器作为时序锚点反向扇入"的自然切分方式，将 RTL 设计分解为多个可独立处理的子图，并配以 GPT-OSS-120B 生成的文本摘要形成"结构 + 行为"双视图。

**对比 AIG 切分**：AIG 没有寄存器概念（寄存器是 AIG 之外的元素），所以 AIG 系方法只能基于"扇出锥"或"随机游走"切分。RTL 有寄存器这个天然的时序边界，切分粒度更粗但语义更清晰。

### 7.3 三种拓扑感知位置编码

**贡献**：把电路看作"存储 + 计算"双阶段系统，分别用**位宽中心性（存储粒度）**、**最长路径（计算深度）**、**图密度（局部互连紧密度）**三种编码注入 Transformer attention。

**对比传统图编码**：
- 传统 GNN 的位置编码只考虑拓扑距离（最短路径）
- TopoRTL 的位宽编码把"数据精度"信息显式注入——这是 Verilog 文本不会告诉你的、但综合工具极度依赖的信息

### 7.4 对称 dual-triplet 跨模态对比对齐

**贡献**：用对称 dual-triplet（quadruplet）损失在"图模态"和"文本模态"之间做跨模态对比对齐，让模型学到的联合嵌入空间反映"功能 + 拓扑"的相似度。

**对比普通对比学习**：标准跨模态对比只拉近同一锥的图-文本对、推远不同锥的对。TopoRTL 的对称设计（同时对齐 $y$-$z$ 和 $z$-$y$ 两个方向）提供了更强的拓扑一致性约束。

### 7.5 29M 参数击败 7B LLM

**贡献**：总参数 29.13M，仅为 CodeV-QC（7B）的 1/240，但 PPA 预测 PCC 全面超越 5-10 pp。

**意义**：证明了"为电路专门设计的架构远比暴力堆参数有效"。这对 LLM-for-EDA 领域是一个重要信号——EDA 不只是自然语言处理的子领域，需要领域特定的归纳偏置。

## 9. 与芯片流程关系

### 9.1 在 EDA 流程中的位置

TopoRTL 是 **RTL 设计阶段（①）和逻辑综合阶段（③）之间的桥梁**——它吃 RTL 代码，输出"综合后的 PPA 估计"。这个位置在传统 EDA 流程中是空白：

```text
传统 EDA 流程：
①RTL → ②仿真 → ③综合 → ④门级仿真 → ⑤STA → ... → ⑬签核
                                   ↓
                              PPA 报告

TopoRTL 介入点：
①RTL → TopoRTL → (预测) → ③综合 → ... → ⑬签核
         ↓
    早期 PPA 估计
```

设计师可以在写完 RTL 后、跑综合前，先用 TopoRTL 得到一个 PPA 估计，**决定是否需要改 RTL、微调架构、换数据通路**——大幅减少"写 RTL → 综合 → 看报告 → 重写"的迭代成本。

### 9.2 与下游 PPA 优化的连接

TopoRTL 的输出可以直接驱动三类下游优化：

1. **微架构选择（Microarchitecture Selection）**——给定 C 语言 / Python spec，生成多种 RTL 实现（链式 vs 树形加法器、FIFO 用 SRAM vs Register File），用 TopoRTL 预测每种的 PPA 估计，选最优
2. **RTL 微调（RTL Refinement）**——把当前 RTL 喂给 TopoRTL，看 PPA 估计；如果太差，根据预测值反推哪些寄存器锥贡献最大、针对性修改
3. **设计空间探索（DSE，Design Space Exploration）**——在 HLS 输出多种 RTL 候选时，用 TopoRTL 快速筛选 Pareto 前沿

## 10. 讨论与局限

### 10.1 论文自陈局限

#### 局限 1：寄存器锥分解假设同步电路

寄存器锥分解要求设计是同步的——所有寄存器共享同一个时钟（或有限个明确划分的时钟域）。对纯异步电路、纯组合逻辑设计，FIFO 跨时钟域电路，需要额外的处理（论文未深入讨论）。

**影响范围**：现代 SoC 99% 是同步设计，所以这个限制在工业实践中影响有限。但异步低功耗设计、neural network accelerator 的一些异步握手模块无法直接应用。

#### 局限 2：数据集规模有限

数据集仅 115 个设计 → 7,576 个寄存器锥。对比 [OpenRTLSet](../OpenRTLSet/论文深度讲解.md) 的 131K 模块，规模小两个数量级。论文没有做 cross-architecture 验证（在不同微架构家族之间迁移）。

**影响范围**：训练数据多样性可能不足以覆盖所有 RTL 风格。例如论文没有 RISC-V 高级 CPU（Cortus、Andes）、DSP（Tensilica）、GPU（Verilog 描述的）等领域的样本。迁移到这些领域可能需要重新微调。

#### 局限 3：Slack 表示的离群点

论文指出 WNS 预测存在明显离群值——少数设计预测误差远大于平均。这说明"RTL 抽象"和"门级时序"之间存在难以弥合的鸿沟：RTL 看不到的具体 cell delay、wire delay、时钟 skew 都会显著影响 WNS。

**根本原因**：RTL 不包含门级延迟信息，所有延迟估计都是"基于统计模型"而非"基于真实电路"。TopoRTL 即使拓扑理解 100% 准确，也无法预测综合工具的精确技术映射决策。

### 10.2 批判性分析

#### 批判 1：Yosys 重建后的 RTL 仍是 RTL，不能保证切分后的"寄存器锥"语义独立

**问题**：寄存器锥分解假设每个锥的输出寄存器只看它扇入锥内的逻辑。但实际 RTL 中经常存在：

- **跨锥反馈**：`reg A` 在它的扇入锥内依赖 `reg B` 的扇入锥内的某个信号 → 跨锥耦合
- **多驱信号**：一个 wire 被多个 always 块赋值，扇入锥可能相互重叠

论文没有深入讨论这些"跨锥耦合"如何处理——简单做法是把耦合锥合并，但这会爆炸性扩大锥规模。

#### 批判 2：GPT-OSS-120B 摘要的"信息瓶颈"

**问题**：自然语言摘要不可避免地丢失细节。例如一个 64-bit 累加器和一个 128-bit 累加器的摘要可能都是"64-bit accumulator"或"128-bit accumulator"——一字之差对功耗的影响是 2 倍，但摘要生成器可能简化掉。

论文没有评估"摘要信息损失"对下游任务的影响。一种可能的改进是用"结构化标签"代替自然语言（`{type: accumulator, width: 64, depth: 4}`），但这失去了文本模态的灵活性。

#### 批判 3：对比学习的对称性假设

Quadruplet loss 假设"图嵌入 $h_G$ 和文本嵌入 $h_T$ 应该对齐"。但实际上两者的语义空间不完全相同——图编码的是拓扑结构，文本编码的是功能描述。一张图可能有多种合法的文本描述（不同抽象粒度），一篇文本可能对应多种合法图实现。

更严格的做法应该是**多对多对齐**（概率分布对齐，如 Optimal Transport），而非一一对应的 quadruplet。

#### 批判 4：拓扑位置编码的计算开销

位宽中心性需要 PageRank 收敛，最长路径编码需要关系差异矩阵（$N \times N$），图密度需要 $k$-hop 子图枚举。这些预处理在 $N$ 较大时（$N > 10^4$）开销不小。论文没有报告预处理的计算时间，仅报告训练时间。

对于工业级 SoC 设计（$N > 10^5$ 节点），预处理可能成为瓶颈。

#### 批判 5：评估指标单一

论文主要用 PCC（皮尔逊相关系数）评估 PPA 预测。PCC 对**绝对误差**不敏感——一个总是预测"偏高一倍"的模型 PCC 也可能很高。但在实际 EDA 中，**面积差 10%** 就足以让设计师放弃一个 RTL 实现。

论文没有报告 MAE / MAPE / 相对误差等绝对指标，使结果难以判断实际可用性。

### 10.3 与现有工作的边界

- 与 [FuncGNN](../FuncGNN/论文深度讲解.md) 互补但**不重叠**：AIG 表示学习在综合后做精细分析，TopoRTL 在综合前做粗粒度预警
- 与 [ChipMATE](../ChipMATE/论文深度讲解.md) 互补：ChipMATE 生成 RTL，TopoRTL 评估 RTL
- 与 [OpenRTLSet](../OpenRTLSet/论文深度讲解.md) 互补：OpenRTLSet 提供训练数据，TopoRTL 使用训练数据
- **不存在直接竞争者**：到 2026 年 ICLR 截稿前，没有其他工作同时做"RTL 阶段 + 拓扑感知 + 双模态对齐"

## 12. 一分钟复述版

1. **核心问题**：RTL 不是普通代码，是结构化数据流图——同样的功能可以有不同的拓扑（链式 vs 树形加法器），导致不同的 PPA。文本式 LLM 和 AIG 级 GNN 都无法在 RTL 阶段捕捉拓扑语义

2. **方法概述**：TopoRTL = 寄存器锥分解（用 Yosys 反向扇入切分）+ 双模态（CDFG 图 + GPT-OSS-120B 行为摘要文本）+ 三种拓扑位置编码（位宽中心性 / 最长路径 / 图密度，注入 Transformer attention）+ 拓扑引导的 quadruplet 对比损失

3. **核心数据**：115 个 RTL 设计 → 7,576 个寄存器锥（OpenCores / VexRiscv / ITC'99 / DeepCircuitX 四源融合），29.13M 总参数

4. **关键结果**：PPA 预测 vs CodeV-QC 7B — Area PCC 0.863 vs 0.818、Power PCC 0.884 vs 0.805、WNS PCC 0.862 vs 0.762；电路检索 AUC 稳定 ~0.8

5. **最大创新点**：三种"存储/计算"视角的拓扑位置编码 + 拓扑引导的负样本挖掘，让 29M 模型击败 7B LLM

6. **EDA 流程位置**：RTL 设计阶段（①）和逻辑综合阶段（③）之间——写完 RTL 后、综合前，给设计师一个 PPA 预警

7. **与同类工作的关系**：与 [FuncGNN](../FuncGNN/论文深度讲解.md) / [DeepGate](../DeepGate/论文深度讲解.md) / [DeepGate2](../DeepGate2/论文深度讲解.md) 互补（AIG 级 vs RTL 级）；与 [ChipMATE](../ChipMATE/论文深度讲解.md) / [OpenRTLSet](../OpenRTLSet/论文深度讲解.md) 互补（ChipMATE 生成 RTL 后，TopoRTL 评估 RTL；OpenRTLSet 提供训练数据，TopoRTL 使用训练数据）

8. **局限**：仅同步电路；数据集规模有限（115 个设计）；WNS 预测有离群点（RTL 看不到的门级延迟信息是根本瓶颈）；GPT-OSS-120B 摘要的信息瓶颈；Yosys 重建后跨锥耦合问题未深入讨论
