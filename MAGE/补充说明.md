## 1. LLM 采样参数：`T` / `top_p` / `n`

这是 RTL Generation Agent 生成 Verilog 时控制大模型"怎么吐下一个字"的三个开关，不是 EDA 概念。论文 Sec IV 配置里给了两组：

| 配置 | T (temperature) | top_p | n (采样次数) | 用途 |
|---|---:|---:|---:|---|
| **低温** | 0 | 0.01 | 1 | 首轮生成 1 份确定性候选 |
| **高温** | 0.85 | 0.95 | 20 | 撒 20 份多样候选，再由仿真排序挑优 |

来源：论文实验配置原文「低温度（T=0, top p=0.01, n=1）和高温度（T=0.85, top p=0.95, n=20）」。[论文]

> 论文重点讲的是 **temperature**（Sec II-B）；`top_p` 的机制论文未展开，下面的原理解释属于 LLM 通用知识，标 `[推断]`。

### 1.1 `T`（temperature，温度）

模型生成下一个 token 前，先算出词表每个词的分数（logits），再用 `softmax(logits / T)` 转概率：

- **T 越高** → 概率分布越"平坦" → 越敢选低概率词 → 输出越随机多样；
- **T 越低** → 概率分布越"尖锐" → 概率最高的词越被压制性地选中；
- **T = 0** → 退化为**贪心解码（argmax）**：永远选当前概率最高的那一个 token。

**后果**：`T=0` 时同一道题问 100 遍，模型给的代码一模一样，**零随机性**。代价是低温 Pass@1 只有 89.1%——一旦这唯一的答案错了，没有备选。[论文]

### 1.2 `top_p`（核采样 / nucleus sampling）——重点

**本质一句话**：把那些概率太小的词直接砍掉，只在高概率词里抽签。`p` 就是允许参与抽签的总概率上限。它存在的意义是踢掉词表里几万个"凑数垃圾词"，防止抽到离谱的词。

**完整机制（5 步）**：

1. 模型对词表每个词算出概率（softmax 后总和 = 1）；
2. 按概率**从大到小排序**；
3. 从大到小**往下累加概率**，累加到**第一次 ≥ p** 的那个词就停；
4. 累加进来的词组成"核（nucleus）"，把核内概率**重新归一化**（让和重新 = 1）；
5. **只在核内**按归一化概率随机抽一个。核外所有小概率词完全不参与。

**用带数字的说明性例子**（非论文真实数据，仅示意）：模型刚写到 `count_reg <= count_reg + ???`，预测下一个 token 的概率分布——

| 排名 | 候选词 | 概率 | 累积概率 |
|---:|:---|---:|---:|
| 1 | `1` | 0.60 | 0.60 |
| 2 | `1'b1` | 0.15 | 0.75 |
| 3 | `en` | 0.10 | 0.85 |
| 4 | `8` | 0.05 | 0.90 |
| 5 | `2` | 0.03 | 0.93 |
| 6 | `0` | 0.02 | 0.95 |
| 7… | 其他几百个词 | 各 < 0.01 | → 1.0 |

- **`top_p = 0.01`**：第一个词 `1`(0.60) 已 ≥ 0.01 → 核 = {`1`} → **100% 选 `1`**。
- **`top_p = 0.85`**：累加到 `en` 时 = 0.85 ≥ 0.85 → 核 = {`1`, `1'b1`, `en`} → 大概率选 `1`，偶尔选别的。
- **`top_p = 0.95`**：核 = {`1`, `1'b1`, `en`, `8`, `2`, `0`} 共 6 个 → 更多样。
- **`top_p = 1.0`**：不裁剪，几万个词全能参与 → 最多样也最易抽到垃圾。

**一个反直觉点**：`top_p` 按**概率累积值**截断，不是按**个数**截断。所以它是**自适应**的——概率集中（第一个词就 0.99）时 `top_p=0.95` 也只取 1 个；概率分散（前 50 个词才累积到 0.95）时 `top_p=0.95` 会取 50 个。这正是它比固定取前 k 个的 `top_k` 优雅之处（保留概率质量集中的"核心"，故名"核采样"）。[推断：LLM 通用知识]

### 1.3 `n`（采样次数）

`n` = 对同一道题采样**几份** RTL：低温 `n=1`（1 份），高温 `n=20`（20 份候选交给 Judge 用仿真分数排序挑最好的）。[论文]

### 1.4 低温配置里 `top_p=0.01` 为何是"冗余"的

**`T=0` 已经是 argmax，这时 `top_p` 取 0.01 还是 0.95 结果都一样**（都选最高概率那个）。论文照样写 `top_p=0.01`，是为了和高温配置 `top_p=0.95` 形成**对称、可复现的参数记录**，是 API 调用的如实登记，不是它在这里真在起作用。**真正让低温"确定、无随机性"的是 `T=0`，不是 `top_p`。**[推断：基于采样机制]

### 1.5 `temperature` vs `top_p` 对比

| | temperature (T) | top_p |
|---|---|---|
| 干什么 | **拉伸/压平**整个概率分布的形状 | **砍掉尾部**小概率词 |
| 改什么 | 改概率的"尖锐度" | 改参与抽签的词**数量** |
| T=0 / top_p 很小 | 都趋向"只选最高概率词" | 同 |

两者可叠加：先 `temperature` 调形状，再 `top_p` 砍尾部，最后抽签。MAGE 高温 = `T=0.85`（压平分布让小词概率升高）+ `top_p=0.95`（保留 95% 概率质量的词）+ `n=20`（抽 20 次），三管齐下制造**多样性**，再靠仿真挑最优。[推断：基于采样机制]

## 2. RTL 生成输入：`规格 + header + TB'`

对应 RTL Generation Agent 把三样东西拼成 prompt 喂给 LLM，产出 1 份（低温）或 20 份（高温）Verilog。详见 [论文深度讲解.md §3.1](./论文深度讲解.md)。

> 论文正文公式写作 $r_i \sim P_T(r \mid p_{sys},\, SP_i,\, TB_i)$——系统提示、规范、测试平台三个变量，**公式里没有把 header 单独列出**。实际上 header 被拼进 SP_i（或 p_sys 模板）里一起喂给 LLM。讲解文件把它单拎出来叫 "module header"，是为了讲清楚——它源自 **VerilogEval 数据集的题目格式**。[推断：基于 VerilogEval 题目格式]

### 2.1 三件套各自的角色

| 输入 | 管什么 | norgate 题里是 |
|---|---|---|
| **规格 SP_i** | 告诉模型"**做什么**" | `Implement a NOR gate... two inputs a and b, one output out.` |
| **header**（module 接口头） | 告诉模型"**长什么样**"（端口名/方向/位宽） | `module top_module (input a, input b, output out);` |
| **TB'**（改造后 testbench） | 告诉模型"**输入信号按什么节奏变**"（激励时序） | 带 `[CHECKPOINT]` 的逐拍 testbench |

三者缺一不可：缺规格 → 不知实现什么；缺 header → 不知端口名/位宽，写出来 testbench 连不上、仿真崩；缺 TB' → 时序逻辑（如计数器）会写错时序。

### 2.2 重点：`header` 是什么

`header`（module header / 模块接口头）= Verilog `module` 的**端口声明那一段**，只说"模块叫什么名、有哪些端口、输入还是输出、几位宽"，**不含任何内部逻辑**。norgate 的 header：

```verilog
module top_module (
    input  a,
    input  b,
    output out
);
```

**核心洞察：MAGE/VerilogEval 是"补全题"，不是"从零写题"。** 题目已把端口声明写好给你，模型只需在 header 和 `endmodule` 之间补逻辑。模型要产出的（标准答案）：

```verilog
module top_module (input a, input b, output out);
    assign out = ~(a | b);     // ← 只需补这一行（+ endmodule）
endmodule
```

> 本地 Qwen2.5-Coder-1.5B 实测产出 `~a & ~b`，与 `~(a|b)` 在 1 位逻辑下等价，219 个采样点 0 mismatch。[本地资产]

**header 的三个作用**：

| 作用 | 没有 header 会怎样 |
|---|---|
| ① 锁死接口 | 模型可能把端口叫 `in1/in2`，testbench 写的是 `dut(.a(a)...)` → 端口名对不上 → 仿真编译失败 |
| ② 评分能自动化 | testbench 是固定的，必须知道端口叫 `a/b/out` 才能驱动输入、读输出、比对 |
| ③ 约束模型 | 告诉模型"只能用这几个端口，不能自己加、不能少" |

VerilogEval 的 system prompt 甚至明令 **"Do not include module, input and output definitions"**——禁止模型重复声明端口，因为 header 已给定了。`header` 就是答题卡上印好的固定格式，你只在答题区写答案。[来自 VerilogEval 数据集格式]

### 2.3 `TB'`（带撇号 = 改造后的 testbench）

`TB` = testbench；撇号 `'` 表示已被 TB 生成 Agent 改造过的版本。原始 golden TB 是"哑巴"的，仿真结束只输出一句 `Mismatches: N in M samples`；TB Agent 在每个时钟沿插入 `$display [CHECKPOINT]`，打印 `{时间, 输入, 期望输出, 实际输出, match}`。RTL Agent 看 TB' 是为了**理解输入信号的激励时序**。详见 [论文深度讲解.md §3.2](./论文深度讲解.md) 及 [MAGE论文与本地复现详解.md §3.1](./MAGE论文与本地复现详解.md)。

## 3. `iverilog -t null`（纯语法检查）——抓语法错，不查功能、也不查可综合性

`iverilog` = **Icarus Verilog**，论文配置采用的开源 Verilog 编译器/仿真器。[论文]

- `-t` = `--target`，指定后端目标代码生成器；
- `-t null` → 只跑**前端**：词法分析 + 语法分析 + elaboration（模块例化展开），**不生成可执行文件、不运行仿真**。

等价于 C 里 `gcc -fsyntax-only`——**纯编译前端检查**。作用：快速验证 LLM 生成的 Verilog 能否过编译，不去跑慢得多的仿真（真仿真要 `iverilog` 编译 + `vvp` 执行，那是 Judge Agent 的活）。[论文/代码]

### 3.1 这个流程输出什么？

输出**一份（低温 `n=1`）或 20 份（高温 `n=20`）、能过 `iverilog -t null` 编译的 Verilog 候选代码**（`rtl.sv`）。注意：到这里只保证了"语法站得住"，**逻辑对不对还不知道**——那是 Judge Agent 跑仿真数 mismatch 的活（见 §5）。换句话说，这一步的产物是"合法的 Verilog 文本"，不一定是"正确的电路"。

### 3.2 "语法错误"到底指什么？（它拦的）

指 **Verilog 语言规则层面的错误**——编译前端当场就能发现的，分三类：

| 类别 | 例子 | iverilog 报错样 |
|---|---|---|
| 词法 / 拼写 | `modul top(...)`（关键字拼错） | `syntax error` |
| 语法结构 | `assign out = ~(a + );`（表达式缺操作数）、括号没闭合、漏分号 | `unexpected ';'` |
| elaboration 连接 | 例化了不存在的模块、端口数对不上、引用未声明的标识符 | `count_reg not declared` |

这正是 §4 `s=5` 重试要修的东西——把这些报错信息喂回 LLM 让它重写。

### 3.3 它**不**查的两件事（最容易误以为它管）

- **不查功能 / 逻辑对错**：`assign out = a & b;`（本该是 NOR 却写成 AND）语法完全合法，`-t null` 照过。逻辑对不对要 Judge 跑仿真数 mismatch 才知道（见 §5）。
- **不查可综合性**：⚠️ iverilog 是**仿真器**，支持完整 Verilog 标准（含不可综合结构）。`#10`（延时）、`initial`、`$display` 这些 testbench 常用语，**对 iverilog 都是合法语法**，混进 RTL 它照样编译通过——只有**综合器**（Yosys / Design Compiler）才会因不可综合报错。所以 `-t null` **拦不住**"把 testbench 语句误抄进 RTL"。[推断：基于工具性质——iverilog 是仿真器非综合器]

> 一句话：`-t null` 只回答"**这串字符是不是合法的 Verilog、模块能不能连起来**"，仅此而已。功能对不对、能不能做成芯片，它都不管。

## 4. `s=5`（语法重试上限）

## 5. 验证与判分：机器怎么知道生成的 RTL 对不对

生成（§1–2）和语法检查（§3–4）之后，还差最后一步：**逻辑对不对？** 这由 Judge Agent 跑仿真完成。要理解它，先得看清 testbench 有两种、判分方式完全不同。

### 5.1 两种 testbench，两种判分方式

| 类型 | 长啥样 | 内置"正确答案"吗 | 谁来判 |
|---|---|:---:|---|
| **刺激型**（stimulus-only）/ "空壳" | 只生成输入激励（时钟/复位/随机值/边界值），把 DUT 输出打印成表或画波形 | ❌ 没有 | **人**看波形人工核对 |
| **自校验型**（self-checking） | 内置一个**参考模型**（reference model），和 DUT 跑同样输入、逐拍比输出 | ✅ 参考模型实时算出 expected | **机器**自动比、数 mismatch，直接 PASS/FAIL |

- **刺激型例子**：[MAGE复现详解 §1.5.4 / counter_tb（行 1826）](./MAGE论文与本地复现详解.md)——`$monitor` 盯着信号变化打印"时间-rst-count"表格，跑完只是一张表，**正确与否要人对着规格看**。[来自资料包 counter_tb]
- **自校验型例子**：VerilogEval / MAGE 的 golden TB——内置 `expected` 参考逻辑 + `if (count !== expected) mismatch_count++`，跑完直接 `PASS=17, FAIL=3`。[代码] 见 [MAGE复现详解 §3.0（行 3600-3617）](./MAGE论文与本地复现详解.md)。

**关键**：benchmark（VerilogEval / MAGE 算 Pass@k）**必须用自校验型**——否则没法机器批改、没法自动打分。刺激型只适合人工调试单题。

### 5.2 CHECKPOINT 行里的 `expected` 是怎么来的？（不是查表）

改造后的 TB' 每拍打印一行：

```text
[CHECKPOINT] time=25: rst=0 en=1 | expected=001 | actual=001 | match=1
```

里面 `expected=001` 是**查表查出来的、预先存好的正确答案**吗？——**不是。** 它是 TB 里的**参考模型在那拍实时算出来的**。看 golden TB 的参考逻辑（[MAGE复现详解 行 3600-3607](./MAGE论文与本地复现详解.md)）：

```verilog
reg [2:0] expected;                        // ← 这就是"参考模型"，跟 DUT 用同样的 rst/en 跑
always @(posedge clk) begin
    if (rst)     expected <= 0;            // 复位→0
    else if (en) expected <= expected + 1; // 使能→+1
    // en=0 时保持                          // 暂停→不变
end
```

`expected` 用**和 DUT 同样的功能、但最直白的写法**重算一遍"正确值"，每个时钟沿跟 DUT 输出 `count` 比：相等 → `match=1`，不等 → 数一次 mismatch。所以 `expected` 是**现场算的**，不是预先存的。为什么不能查表？因为输入/状态组合太多（状态空间爆炸），存不下，只能现场算。[推断：基于状态空间]

> TB Agent 改造 TB 时（[§3.1 行 3638](./MAGE论文与本地复现详解.md)）**不动**这段参考逻辑，只在外面套一层 `$display` 把对比细节打印出来——把"哑巴 TB"（只报总数）变成"逐拍播报员"。

### 5.3 "都没有正确答案了，机器怎么自动判？"——参考模型 / 双实现比对

这是最容易被卡住的点。破除它，一句话：

> **机器从不"判断"对错，机器只"比对"——把 DUT 和一个已知正确的参考实现喂同样输入，比输出一不一样。正确答案不是机器算的，是人预先准备好的参考模型算的。**

`expected`（参考模型）凭什么可信？三层来源，越往上越根本：

1. **数学定义本身**（简单电路）：NOR 的参考实现 `~(a|b)` 就是 NOR 的定义，不证自明。拿它比 LLM 写的 `~a & ~b`，行为一致即正确。[本地资产：norgate 219 点 0 mismatch]
2. **更简单 / 更高层的重写**（复杂电路）：计数器的参考模型用 `expected = rst ? 0 : (en ? expected+1 : expected)` 一句话显然对的写法——它可以**不可综合**，因为它只在仿真里跑、不流片；DUT 必须用时序逻辑（能综合但易写错）。两者**抽象层不同**，所以参考模型可信度来自"简单到一眼看出对"，**不是循环论证**（它不是"另一个可能错的 DUT"）。[推断：基于验证方法学]
3. **成熟 IP / 形式化证明 / 人工审查**（工业级）：已流片旧 IP、C 系统模型、数学证明过的模型。

**正确性的根最终是人**：人写规格 → 人确认参考模型符合规格 → 机器只负责"比对"这件机械、重复、量大的活。机器自动化的是搬运和比对，不是发明正确性。

类比**考试判卷**：学生答题 = DUT；标准答案 = 参考模型（出题人预先写好）；机器阅卷 = 比对（不需要懂题，只比答案一不一样）。

VerilogEval 就是这个模型：作者预先写好 golden reference（标准答案），机器拿它和 LLM 输出比对。证据——[VerilogEval 讲解 行 20]「把候选 Verilog 与 golden reference 同时接入 testbench……比较瞬态输出是否一致」、[行 219]「候选在给定 testbench 激励空间上的行为与 golden reference 完全一致」。

> ⚠️ 反过来：如果一道题**真的没有任何参考实现**（连参考模型都没有），那就**没法机器自动判**——这正好退回 §5.1 的刺激型，只能靠人看波形。机器自动判的前提，永远是"先有一个可信的参考实现"。
