## 1. 一句话定位

**RTL-Sequencer 把 RTL 的逻辑锥（logic cone）经广度优先遍历（BFT）线性化为节点序列，用 Mamba-2 序列模型替代传统图神经网络做预综合时序预测——在 21 个开源 RTL 设计上，Arrival Time 的 MAPE 降至 17.24%，R 达到 0.92，且内存复杂度与节点数呈线性关系，从根本上解决了图方法感受野受限和二次复杂度的问题。**

这句话里的四个技术承重点，后面逐一拆解：

1. **逻辑锥序列化范式** -- 不再把 RTL 的逻辑锥当作图来处理，而是用逆 BFT 从 endpoint register 出发逐层展开成有序节点序列。这使得模型获得了全局感受野（不受网络深度限制）、线性计算复杂度（相对于节点数和锥深度）、以及显式的信号方向性保留。
2. **序列随机打乱（Sequence Shuffling）** -- 训练时在每个 BFT depth level 内以 50% 概率随机置换节点顺序，作为结构级数据增强。推理时改用基于出入度统计的启发式确定性排序。消融实验表明这是四项技术中贡献最大的单项（AT MAPE 恶化 +8.23% 当移除此模块）。
3. **双向 + 可微序列建模** -- 正向序列捕获信号传播方向，反向序列捕获负载反传方向；可微机制通过 global embedding 减去 depth-local embedding 并配以可学习门控系数，削弱无关的 depth-local 结构干扰、强化全局时序行为。
4. **图-序列混合架构** -- GatedGCN 捕获节点局部邻域结构，Mamba-2 捕获跨层级长程时序依赖。所有图-序列转换均为可微操作，支持端到端梯度优化。

**覆盖率：2/17。** RTL-Sequencer 定位在阶段 ① 和阶段 ③ 之间：它在 RTL 完成后、逻辑综合前，利用 RTL 的逻辑锥结构预测如果跑完综合+布局布线+STA 会得到什么样的时序结果。本质上是一个 **shift-left 早期时序预测工具**——不等综合跑完，先给一个时序估计。

> ⚠️ **RTL-Sequencer 的预测值不能替代 STA 签核。** 它是一个 pre-synthesis 估计工具，用于早期设计迭代和候选排序，而非 signoff 级别的时序验证。此外，训练标签的生成需要完整的商业 EDA 工具链（Synopsys DC + Cadence Innovus + Synopsys PrimeTime），这限制了开源社区的复现能力。

## 3. 输入 / 输出

### 3.1 输入

RTL-Sequencer 的输入是从 RTL 设计中提取并结构化后的逻辑锥序列。以一个简单的 RTL 片段为例：

**原始 RTL 代码**（阶段 ① 的产物）：

```verilog
module example (
    input  wire [7:0] In1,
    input  wire       clk,
    output reg  [7:0] Out1
);
    wire [7:0] W1, W2;
    assign W1 = In1 & Out1;      // 组合逻辑：AND
    assign W2 = W1 ^ 8'hFF;      // 组合逻辑：XOR
    always @(posedge clk)
        Out1 <= W2;              // 时序逻辑：寄存器
endmodule
```

**步骤 1：构建布尔算子图（BOG）**

RTL 被解析为有向图 `G = (V, E)`，节点 V 包含寄存器（Out1）和组合逻辑单元（AND 门、XOR 门），边 E 表示信号连接关系。

**步骤 2：抽取逻辑锥（Logic Cone）**

以 endpoint register `Out1` 为根，反向遍历其完整 fan-in cone：

```text
Cone C（root = Out1）:
  Level 0: Out1 (endpoint register)
  Level 1: XOR_gate (W2)  ← fanin of Out1
  Level 2: AND_gate (W1)  ← fanin of XOR_gate
  Level 3: In1 (input register)
```

**步骤 3：BFT 线性化为节点序列**

用逆广度优先遍历（inverse BFT）从 endpoint 出发逐层展开：

```text
Sequence S = BFT(C) = (Out1, XOR_gate, AND_gate, In1)
                      = (n_1,   n_2,      n_3,      n_4)
```

**步骤 4：节点特征向量**（论文 Table 2，每个节点 21 维特征）

| 特征 | 类型 | 维度 | 说明 |
|------|------|:---:|------|
| cell type | one-hot | 12 | 节点类型：寄存器 / AND / XOR / OR / NOT / MUX 等 |
| fan-out number | int | 1 | 该节点驱动的下游节点数 |
| fan-in number | int | 1 | 驱动该节点的上游节点数 |
| load capacitance | float | 1 | 负载电容值 |
| slew | float | 1 | 信号转换时间（slew rate） |
| node order in current BFT-level | int | 1 | 当前 BFT 层级内的序号 |
| number of nodes in current BFT-level | int | 1 | 当前 BFT 层级的总节点数 |
| start flag of each BFT-level | one-hot | 1 | 是否为该 BFT 层的起始节点 |
| end flag of each BFT-level | one-hot | 1 | 是否为该 BFT 层的结束节点 |
| order of parent node in next BFT-level | int | 1 | 父节点在下一个 BFT 层中的序号 |

### 3.2 中间产物

**训练标签生成流程**（不参与推理，仅用于训练）：

```text
RTL 设计 → Synopsys Design Compiler（逻辑综合）
         → Cadence Innovus（布局布线，NanGate 45nm 工艺库）
         → Synopsys PrimeTime（STA 签核级时序分析）
         → 提取 AT / WNS / TNS 作为 ground truth 标签
```

### 3.3 输出

对每个 endpoint register，模型输出三个时序指标的预测值：

- **AT（Arrival Time，到达时间）**：信号从发射寄存器经组合逻辑路径到达该 endpoint register 的总延迟预测值，单位为纳秒。

- **WNS（Worst Negative Slack，最差负时序裕量）**：所有 endpoint register 中最差的 slack 值。Slack = 时钟周期 - AT，负值表示时序违例。

- **TNS（Total Negative Slack，总负时序裕量）**：所有 slack 为负的 endpoint 的 slack 绝对值之和，衡量设计中时序违例的总严重程度。

以之前的 AND-XOR-Register 电路为例，输出可能为：

```text
Endpoint 'Out1': AT_pred = 1.23 ns
Design-level:   WNS_pred = -0.05 ns  (最差路径 slack 为负)
                TNS_pred = 0.15 ns   (所有负 slack 之和)
```

### 4.2 核心模块逐个详解

**模块 A：BOG 提取与 Cone 抽取**

做什么：将 RTL 代码解析为布尔算子图，再以每个 endpoint register 为根，逆序遍历其完整 fan-in cone。

为什么这样设计：论文观察到 RTL 阶段的逻辑锥通常很深（最大深度超过 100）且节点数巨大（超过一万个节点）。传统的图方法（GNN、GNN-Propagation、Graph Transformer）在处理这种深而大的锥时要么感受野受限，要么计算复杂度过高。将锥从中抽取出来作为独立预测单元，使得模型可以聚焦于每个 endpoint 的信号传播路径。

关键实现细节：cone 定义为 "the transitive fan-in subgraph rooted at the endpoint register"——包含了从该 endpoint 回溯到所有输入寄存器的完整组合逻辑和时序单元。

**模块 B：BFT 序列化**

做什么：对抽取出的逻辑锥执行逆广度优先遍历，将其从有向图结构转化为有序节点序列。

为什么这样设计：这是论文的核心范式转换。BFT 按层级展开节点，保留了信号在组合逻辑中自前向后的层级推进关系。与深度优先遍历（DFS）相比，BFT 不会因为递归深入某一条路径而打乱同层节点的时序关系。同时，序列化后的锥可以直接输入现代线性序列模型（Mamba-2 等），享受其线性复杂度和全局感受野的优势。

输入：逻辑锥 `C = (V_C, E_C)`
输出：节点序列 `S = BFT(C) = (n_1, n_2, ..., n_N)`，其中 N 为锥中节点总数

**模块 C：序列随机打乱（t1）**

做什么：训练时在每个 BFT depth level 内以 50% 概率随机置换节点顺序。子节点在后续层级的顺序同步调整以保持层级依赖。推理时使用基于节点出入度统计的启发式确定性排序——连接度更高的节点靠近 output register。

为什么这样设计：确定性 BFT 产生的固定节点顺序会导致模型过拟合特定的综合器节点排序。打乱作为结构级数据增强，让模型看到同一锥的多种序列变体，学习到对节点顺序不敏感的时序特征。消融实验证明这是四项技术中贡献最大的（移除后 AT MAPE 恶化 +8.23%）。

关键实现细节：打乱发生在 BFT level 内部而非跨层，保证层级间的因果依赖不被破坏。子节点的置换同步确保 "父节点 A 连接到子节点 B" 这种关系在打乱后仍可追踪。

**模块 D：双向序列建模（t2）**

做什么：除了正向序列 `S = (n_1, ..., n_N)` 外，额外构建反向序列 `S_flip = (n_N, ..., n_1)`。用另一个序列模型处理反向序列，使后续节点也能影响前面节点的表示。

为什么这样设计：这个设计的灵感来自实际设计流程。静态时序分析（STA）在计算 arrival time 时需要同时考虑前向的信号传播和反向的负载效应。逻辑综合也需要双向分析。单向建模把信息流限制在了 "前向节点 → 后向节点"，违背了电路物理本质中的双向反馈。

**模块 E：可微序列建模（t3）**

做什么：在 BFT level 内部运行额外的 depth-specific 序列模型，计算每个节点在其 BFT 层内的局部嵌入 `h_i^dfw` 和 `h_i^dbw`。然后用 global embedding（跨层级序列模型的输出）减去经可学习门控系数 λ 加权后的 depth-local embedding。

为什么这样设计：BFT 序列化有一个副作用——同一 BFT 层内的节点按遍历顺序相邻排列，序列模型不可避免地会让同层邻居节点相互影响。但在时序分析中，关键路径上的节点关系（跨层级的深度依赖）远比同层邻居关系重要。可微机制的本质是让模型自适应地 "减去" 不相关的 depth-local 信息，保留跨层级的全局时序信号。

自门控系数 `λ` 由 MLP 计算并经 Sigmoid 约束到 [0, 1]。理想情况下 `λ ≈ 0` 表示节点主要关注全局时序行为，`λ ≈ 1` 表示节点更关注 depth-local 结构。

**模块 F：图-序列混合架构**

做什么：先对锥中的每个节点用 GatedGCN 做局部邻域聚合，再把锥转回序列送入 Mamba-2 做长程时序建模。GNN 和序列模型的输出分别接 FFN，最后通过残差连接融合。

为什么这样设计：序列模型擅长跨层级的长程依赖，但节点周围的局部拓扑信息（比如某个 AND 门的 fan-in 结构）在序列化过程中会丢失。GNN 补充了这部分局部结构信息。两者互补：GNN 负责 "这个节点的局部邻居是谁"，序列模型负责 "信号从第 1 层传到第 100 层的累积延迟是多少"。

## 5. 关键公式

### 5.1 监督学习目标

论文的优化目标是最小化 endpoint register 上预测到达时间与 STA 真实值之间的 L2 误差：

$$
\min_{\theta} \sum_{n_{ep} \in V_{ep}} \| AT_{\text{pred}}(n_{ep}; \theta) - AT_{\text{label}}(n_{ep}) \|^2
$$

- $V_{ep} \subseteq V$：所有 endpoint register 节点的集合
- $n_{ep}$：某个 endpoint register 节点
- $AT_{\text{pred}}(n_{ep}; \theta)$：模型对节点 $n_{ep}$ 的到达时间预测值
- $AT_{\text{label}}(n_{ep})$：由 PrimeTime STA 提取的 ground-truth 到达时间
- $\theta$：模型所有可学习参数

**工程直觉**：这是一个标准的监督回归任务。模型看到的训练信号是 "你预测的到达时间和 PrimeTime 算出来的差多少"，优化目标就是让这个差距尽可能小。

**为什么用 L2 而非 L1**：L2 对大误差的惩罚更重（误差平方），这在时序预测中是合理的——一个 2ns 的偏差比两个 1ns 的偏差严重得多，因为大的时序误判可能导致错误的设计决策。

### 5.2 序列模型基本更新公式

论文对序列模型的基本操作给出了形式化定义：

$$
h_i = \text{Sequencer}(S, h_{i-1}, x_i)
$$

$$
y_i = \text{Projection}(h_i)
$$

- $S = (n_1, n_2, ..., n_i, ..., n_N)$：节点序列
- $x_i \in \mathbb{R}^k$：节点 $n_i$ 的输入特征向量
- $h_{i-1} \in \mathbb{R}^k$：从 $n_1$ 到 $n_{i-1}$ 的历史信息编码（隐藏状态）
- $h_i$：更新后的节点 $n_i$ 的隐藏状态
- $y_i$：节点 $n_i$ 的输出表示
- $\text{Sequencer}$：序列模型的核心操作，捕获当前节点与历史信息的依赖
- $\text{Projection}$：通道级特征精炼

**工程直觉**：这个公式描述的是一种 "流式处理"——序列模型按顺序逐节点更新隐藏状态，每个节点看到的是它之前所有节点的累积信息。这与 Transformer 的 self-attention（每个节点显式地看所有其他节点）形成对比。前者的计算复杂度是 O(N)，后者是 O(N^2)。

### 5.3 正向序列嵌入

对 BFT 序列化后的逻辑锥，正向序列嵌入定义为：

$$
h_i^{\text{fw}} = \text{Sequencer}(S, h_{i-1}, x_i)
$$

- $h_i^{\text{fw}}$：节点 $n_i$ 的正向隐藏状态嵌入
- $S$：逆 BFT 生成的节点序列
- $h_{i-1}$：上一个节点传递来的隐藏状态
- $x_i$：节点 $n_i$ 的输入特征

### 5.4 反向序列嵌入

反向序列 $S_{\text{flip}} = (n_N, ..., n_i, ..., n_2, n_1)$ 的反向嵌入：

$$
h_i^{\text{bw}} = \text{Sequencer}(S_{\text{flip}}, h_{i+1}, x_i)
$$

- $h_i^{\text{bw}}$：节点 $n_i$ 的反向隐藏状态嵌入
- $S_{\text{flip}}$：反转后的节点序列
- $h_{i+1}$：从序列末尾方向传来的隐藏状态

**为什么需要反向**：电路中的时序行为不是单向的。一个门的扇出负载会影响其驱动能力、进而影响其输入端的 arrival time。反向建模让后续节点（靠近输出的负载节点）能够影响前面节点（驱动门）的表示。

### 5.5 Depth-Specific 嵌入

对每个节点 $n_i$，在其所属的 BFT-level 子序列 $D_i$ 上分别计算 depth-specific 的正向和反向嵌入：

$$
h_i^{\text{dfw}} = \text{Sequencer}(D_i, h_{i-1}, x_i)
$$

$$
h_i^{\text{dbw}} = \text{Sequencer}(D_{i\_\text{flip}}, h_{i+1}, x_i)
$$

- $D_i$：节点 $n_i$ 所在 BFT-level 的子序列（仅包含同层节点）
- $D_{i\_\text{flip}}$：$D_i$ 的反转
- $h_i^{\text{dfw}}$：depth-specific 正向嵌入
- $h_i^{\text{dbw}}$：depth-specific 反向嵌入

### 5.6 自门控融合与最终节点表示

这是可微序列建模的核心公式：

$$
\lambda = \text{Sigmoid}(\text{MLP}(h_i^{\text{dfw}} + h_i^{\text{dbw}}))
$$

$$
h_i = h_i^{\text{fw}} + h_i^{\text{bw}} - \lambda \cdot (h_i^{\text{dfw}} + h_i^{\text{dbw}})
$$

- $\lambda \in [0, 1]$：可学习的门控系数，控制 depth-local 信息的衰减程度
- $h_i^{\text{fw}}$：全局正向嵌入
- $h_i^{\text{bw}}$：全局反向嵌入
- $h_i^{\text{dfw}}$：depth-specific 正向嵌入（同层内）
- $h_i^{\text{dbw}}$：depth-specific 反向嵌入（同层内）
- $h_i$：节点 $n_i$ 的最终融合表示

**工程直觉**：这个公式做的事可以理解为 "差分放大器"。`h_i^fw + h_i^bw` 是包含所有信息的全局信号。`h_i^dfw + h_i^dbw` 是只包含同层邻居影响的局部信号。两者相减（经 λ 调节强度）得到的是 "跨层级的全局时序信息"。λ 趋近 0 时，局部信号被完全减去，节点只保留跨层级时序特征；λ 趋近 1 时，局部信号全部保留。

**为什么这么设计**：BFT 序列化的副作用是同层节点在序列中相邻排列，序列模型会默认认为相邻节点的信息是相关的。但在时序分析中，第 3 层的 AND 门和第 3 层的 XOR 门之间的 "相邻" 是 BFT 遍历造成的人为产物，并非真实的时序依赖关系。可微机制让模型自己学会区分哪些同层节点关系是有意义的、哪些应该被削弱。

### 5.7 WNS 和 TNS 的汇总定义

论文未给出编号公式，以下是对其从 AT 汇总到 WNS/TNS 的形式化：

$$
\text{WNS} = \min_{n \in V_{ep}} \left( T_{\text{clk}} - AT_{\text{pred}}(n) \right)
$$

$$
\text{TNS} = \sum_{n \in V_{ep}} \min\left( T_{\text{clk}} - AT_{\text{pred}}(n),\ 0 \right)
$$

- $T_{\text{clk}}$：时钟周期
- $AT_{\text{pred}}(n)$：endpoint register $n$ 的预测到达时间
- $\text{WNS}$：所有 endpoint 中最差的 slack——单个最严重的时序违例
- $\text{TNS}$：所有负 slack 的绝对值之和——设计中时序违例的总体严重程度

### 6.1 是否需要训练

**需要从头训练。** RTL-Sequencer 是一个监督学习的回归模型，不对预训练大模型做微调，而是使用专门的 GNN + 序列模型架构从头训练。

### 6.2 实验设置

**数据集**：21 个开源 RTL 设计，规模从 6K 到 510K 门，覆盖多种主流硬件描述语言。采用 5 折交叉验证，训练集和评估集严格按设计划分（不跨设计混合）。

**标签生成流程**：
```text
Synopsys Design Compiler（逻辑综合）
  → Cadence Innovus（布局布线，NanGate 45nm 工艺库）
    → Synopsys PrimeTime（STA 签核级分析）
      → 提取 AT / WNS / TNS 作为 ground truth
```

**Baseline 方法**（按类型分类）：
- **传统 ML**：RTL-Timer（XGBoost）
- **GNN**：GCN、GAT（图卷积/图注意力网络）
- **GNN-Propagation**：RTLDistill、NUA-Timer（逐层传播的 DAG 图神经网络）
- **Graph Transformer**：CircuitFusion、SG-Former
- **Transformer**：TF-Predictor

所有 baseline 在同一设置下重新实现，排除了 post-synthesis 的辅助特征（如 layout 信息），确保对比的公平性。

**评估指标**：

- **Pearson Correlation Coefficient（R）**：预测值与真实值的线性相关程度

$$
R = \frac{\sum_i (y_i - \bar{y})(\hat{y}_i - \bar{\hat{y}})}{\sqrt{\sum_i (y_i - \bar{y})^2 \sum_i (\hat{y}_i - \bar{\hat{y}})^2}}
$$

- $y_i$：第 $i$ 个样本的真实时序值
- $\hat{y}_i$：第 $i$ 个样本的预测时序值
- $\bar{y}$：真实值均值
- $\bar{\hat{y}}$：预测值均值

- **Coefficient of Determination（R^2）**：模型对真实方差的比例解释

$$
R^2 = 1 - \frac{\sum_i (y_i - \hat{y}_i)^2}{\sum_i (y_i - \bar{y})^2}
$$

- **Mean Absolute Percentage Error（MAPE）**：平均相对预测误差

$$
\text{MAPE} = \frac{1}{N} \sum_i \left| \frac{y_i - \hat{y}_i}{y_i} \right| \times 100\%
$$

- $N$：endpoint register 总数

**预测目标**：Arrival Time（AT）、Worst Negative Slack（WNS）、Total Negative Slack（TNS）

## 7. 创新点

### 创新点 1：逻辑锥序列化范式——把图问题转化为序列问题

这是 RTL-Sequencer 最根本的创新。已有方法把 RTL 的逻辑锥当作图来处理，使用 GNN、GNN-Propagation 或 Graph Transformer。这些方法面临三个根本性困境：

- **GNN 的感受野受限于网络深度**：要建模第 100 层的节点关系，需要至少 100 层 GNN，但这会引发过平滑问题——所有节点的表示趋同，失去区分能力。
- **GNN-Propagation 的训练复杂度与锥深度呈二次关系**：因为层间有严格的依赖，无法并行计算，且误差随层数累积。
- **Graph Transformer 的复杂度与节点数呈二次关系**：self-attention 需要计算每对节点之间的关系，大锥直接爆显存。

RTL-Sequencer 的解决方案是：**用 BFT 把逻辑锥线性化，然后用现代线性序列模型处理**。这个转换带来了三个关键性质：(1) 全局感受野——序列模型的前向传播天然覆盖了从第一个节点到最后一个节点的完整信息流；(2) 线性复杂度——Mamba-2 的计算量与节点数 O(N) 成正比；(3) 显式的信号方向性——BFT 的层级顺序天然对应信号的传播方向，不需要像 Graph Transformer 那样额外注入位置编码。

**对比 CircuitFusion**：CircuitFusion 是同期最强的 RTL 时序预测 baseline（AT MAPE 20.29%），它使用 Graph Transformer 架构。RTL-Sequencer 比它好在两点：(1) 序列模型显式保留了信号传播方向，而 GT 的 attention 是 isotropic 的（所有节点对等看待），建模的是 "节点与节点的关系" 而非 "信号如何流过节点"；(2) 线性复杂度意味着可以处理更大的设计，而 GT 在大设计上会因显存超限而无法训练。

### 创新点 2：序列随机打乱——结构级数据增强

传统 ML 中的数据增强通常在输入特征空间做（加噪声、dropout 等）。RTL-Sequencer 的序列打乱是一种结构级增强：修改的是节点的排列顺序（拓扑不变），而非节点特征。

这个创新的巧妙之处在于：一个逻辑锥在 BFT 下有多种合法的节点序列——第 k 层的 n 个节点可以以任意顺序排列，只要子节点在后续层的顺序相应调整即可。每种排列都是同一个锥的等价表示。打乱让模型接触到同一个锥的多种序列变体，学会对节点顺序不敏感，从而不再过拟合某个特定的合成器节点排序。

消融实验证明这是四项技术中贡献最大的——移除后 AT MAPE 恶化 8.23 个百分点。这个数字远超其他三项（3%~5%），说明在 RTL 时序预测中，结构表示的不变性比模型架构的精巧设计更重要。

### 创新点 3：可微序列建模——全局与局部的自适应平衡

BFT 序列化的副作用是同层节点在序列中相邻排列。序列模型（包括 Mamba-2）的核心机制是让相邻节点的信息相互影响。但在时序分析中，关键路径穿过多个层级，同层节点之间往往没有直接的时序依赖关系。

可微序列建模的解决方案非常优雅：单独在同层子序列上再跑一遍序列模型得到 "depth-local" 嵌入，然后从全局嵌入中把它减去。这个 "减法" 不是硬减——由可学习的门控系数 λ 控制减多少。λ 趋近 0 时节点只关注跨层时序；λ 趋近 1 时节点保留同层结构信息。

这个机制让每个节点可以自适应地选择自己的 "信息食谱"：靠近输出端的节点可能更需要全局信息（累计路径延迟），而同层邻居密集的节点可能更需要局部信息（共享 fan-in 结构）。

### 创新点 4：图-序列混合——互补而非替代

序列模型的弱点是丢失了局部拓扑信息。一个 AND 门有两个 fan-in，这个 "2" 的信息在序列化后变成了一个标量特征，但它在图中的结构意义（两个扇入来自不同层级的节点、驱动能力不同）丢失了。

RTL-Sequencer 的方案是在序列模型之前加一层轻量 GNN（GatedGCN）：先在图上跑一层 neighborhood aggregation，把局部拓扑编码进节点特征，然后再序列化送入 Mamba-2。这样 Mamba-2 拿到的节点特征已经包含了 "这个节点的邻居是什么结构" 的信息，可以专注于跨层级的长程时序依赖。

| PE | Pearson Correlation Coefficient | 皮尔逊相关系数——度量两个变量线性相关程度，1 表示完全正相关 |
| R^2 | Coefficient of Determination | 决定系数——度量模型对因变量方差的解释比例，1 表示完美拟合 |
| SDC | Synopsys Design Constraints | 设计约束文件——定义时钟周期、输入/输出延迟等时序约束 |
| SDF | Standard Delay Format | 标准延时格式——记录每个门和每条路径的延迟值，门级仿真时反标 |
| SPEF | Standard Parasitic Exchange Format | 标准寄生参数交换格式——从版图提取的走线寄生 RC 参数 |
| NanGate 45nm | — | NanGate 公司提供的 45 纳米开源工艺设计套件（PDK） |
| BFS | Breadth-First Search | 广度优先搜索——与 BFT 同义，图遍历算法 |

## 9. 与芯片流程的关系

### 9.1 在全流程中的位置

```text
  人写 RTL 代码
       │
       ▼
┌─────────────────────────────────────────────────┐
│  ① RTL 设计                                       │
│     ↓                                             │
│  RTL-Sequencer 在此介入：                          │
│  读 RTL → 提取 BOG → 抽取 cone → BFT 序列化       │
│  → Mamba-2 序列模型 → 预测 AT / WNS / TNS         │
│     ↓                                             │
│  输出："你这个设计综合+布局布线后的                │
│         AT 大概 1.23ns，WNS 大概 -0.05ns"         │
└──────────────────────┬──────────────────────────┘
                       │  ⚠️ RTL-Sequencer 到此结束
                       ▼
             ③ 逻辑综合（Design Compiler / Genus）
                       ▼
             ④ 门级仿真 → ⑤ STA → ⑥ 形式验证
                       ▼
             ⑦ Floorplan → ⑧ Placement → ⑨ CTS → ⑩ Routing
                       ▼
             ⑪ 后仿真 → ⑫ DRC/LVS → ⑬ Signoff → ⑭ 流片
```

RTL-Sequencer 处于阶段 ① 的输出端和阶段 ③ 的输入端之间。它的价值主张是：在跑逻辑综合之前（数小时到数天），用秒级推理告诉你综合后的时序大概是什么样子。如果预测显示 WNS 为负（时序违例），工程师可以立刻在 RTL 层面修改设计（加流水级、重组逻辑等），而不是等综合跑完再返工。

### 9.2 「预综合时序预测」和「STA 签核」之间隔着什么

RTL-Sequencer 的预测值与 STA 签核之间存在多重信息差距：

**信息不对称 1：没有真实的门级映射**。RTL-Sequencer 看到的是 RTL 的 BOG 抽象，而 STA 看到的是综合工具（DC）经过技术映射后选定的具体标准单元（AND2X1、XOR2X1...）。同一句 `assign y = a & b` 在 45nm 库里可能被映射为驱动能力 1X、2X、4X 的不同 AND 门，延迟差 2~3 倍。模型学到的是一种 "平均映射行为"，但对具体的映射偏差没有建模。

**信息不对称 2：没有真实的物理布局信息**。STA 的走线延迟来自布局布线后的真实物理版图（SPEF 提取的寄生 RC），而 RTL-Sequencer 完全没有物理信息。对于大规模设计，走线延迟可能占路径总延迟的 50% 以上。模型实际上是在学习 "逻辑深度" 和 "最终时序" 之间的统计关系，而非物理因果关系。

**信息不对称 3：单工艺库、单 corner 的局限性**。论文的训练数据基于 NanGate 45nm 工艺库、特定版本的 Synopsys DC + Cadence Innovus + PrimeTime。换一个工艺库（比如 TSMC 28nm 或 7nm）、换一个 corner（SS/FF）、换一个版本的 EDA 工具，映射行为和延迟特征都会变化。模型需要针对每个工艺/工具版本重新训练。

**信息不对称 4：预测的是统计期望，不是确定性值**。17.24% 的 AT MAPE 意味着一个 1.0ns 的路径可能被预测为 0.83ns 或 1.17ns。对于 WNS 接近 0 的边界情况，这个误差范围可能导致误判——预测显示 slack 为正但实际为负（假阴性）、或预测显示 slack 为负但实际为正（假阳性）。

## 10. 讨论与局限

### 10.1 论文自述的局限

论文在承认自己的边界方面相当诚实：

1. **预综合估计，非 signoff 替代**：论文明确将 RTL-Sequencer 定位为 "early-stage timing estimation" 工具，用于设计迭代和候选排序，而非替代 STA 签核。
2. **标签获取成本高**：ground-truth 需要完整的 Synopsys DC + Cadence Innovus + PrimeTime 工具链，这是商业闭源工具，数据构建流程重。
3. **跨设计泛化未充分验证**：21 个开源 RTL 设计的规模上限为 510K 门，远小于工业级设计的百万门到千万门规模。

### 10.2 代码/复现层面的问题

1. **论文未开源代码**：截至目前，RTL-Sequencer 没有任何公开代码仓库、预训练模型或训练数据集。所有架构细节和实验结果仅能从论文文本中推断。
2. **商业 EDA 工具依赖**：即使代码开源，复现也需要 Synopsys DC、Cadence Innovus、Synopsys PrimeTime 三套商业工具生成训练标签。学术界的开源替代（Yosys + OpenROAD + OpenSTA）的功能覆盖度和精度与商业工具存在差距，用开源工具生成的标签训练出的模型精度会打折扣。
3. **工艺库不公开**：NanGate 45nm PDK 虽然是开源工艺库中比较成熟的，但获取仍需签署协议。

### 10.3 本资料包的批判性分析

**隐含前提 1：BOG 抽象忠实于 RTL 的时序行为**。RTL-Sequencer 的第一步是把 RTL 转换为 BOG。这一步的质量取决于 BOG 提取工具的准确性。如果 BOG 中漏掉了某些逻辑结构（比如复杂的 always 块中的隐式优先级逻辑），后续的序列建模就无法补偿这个信息损失。

**隐含前提 2：BFT 序列化的层级顺序等于真实信号传播顺序**。对于纯前馈的组合逻辑锥来说这个假设是成立的。但对于存在 reconvergent fan-out（一个信号分叉后经不同路径再汇聚）的锥，BFT 的层级编号可能与真实的关键路径深度有偏差——一条经过 5 个慢门的路径可能比一条经过 8 个快门的路径更关键，但 BFT 不会区分门的 "权重"。

**隐含前提 3：序列模型能 "学到" 时序物理**。Mamba-2 是一个通用序列模型，设计用于语言建模。它没有任何电感、电容、RC 延迟的物理先验。17.24% 的 MAPE 说明它确实学到了 RTL 结构与最终时序之间的统计映射，但这个映射是 "经验性的" 而非 "物理性的"——换一个工艺角或工具版本，映射关系可能完全改变。

**评测公平性**：Baseline 的对比是公平的——所有方法都在相同的 21 个设计、5 折交叉验证、排除 post-synthesis 特征的前提下重新实现。但 "排除 post-synthesis 特征" 这一设计选择对某些 baseline（特别是依赖综合后信息的传统 ML 方法）不利，而对 RTL-Sequencer 有利（因为它设计的出发点就是纯 RTL 输入）。

**可扩展性天花板**：RTL-Sequencer 的内存复杂度与节点数呈线性关系，这是它相对于 GT 的核心优势。但线性系数取决于隐藏维度（32）和块数（L=3）。当设计规模从 510K 门扩展到 500 万门时，单 GPU 的 24GB 显存仍然可能成为瓶颈——尽管时间复杂度是线性的。论文没有讨论模型剪枝、量化或分布式训练等大规模部署策略。

**序列打乱的泛化代价**：训练时打乱节点顺序让模型学会了 "顺序不变性"，但推理时的启发式确定性排序（按出入度）可能与训练时的随机打乱分布不一致。这个 "训练-推理分布偏移" 在论文中没有被量化分析。

**与 TF-Predictor 对比的不对称性**：论文用 TF-Predictor 作为 "序列模型在时序预测中表现差" 的反例。但 TF-Predictor（使用 naive Transformer，只建模 specified path）和 RTL-Sequencer（使用 Mamba-2，建模完整 cone）在架构选择和输入粒度上差异太大，这个对比不太公平——它更多是在说明 "建模完整 cone 比建模单条 path 好"，而非 "Mamba-2 比 Transformer 好"。

## 12. 一分钟复述版

RTL-Sequencer（HKUST，DAC 2026）是一个面向 RTL 阶段的预综合时序预测模型。核心做法四步走：

1. **逻辑锥序列化**：把 RTL 从图（BOG）转化为序列——用逆 BFT 从 endpoint register 出发逐层展开逻辑锥为有序节点序列，以 21 维节点特征（cell type + fan-in/out + capacitance + slew + BFT position）作为输入。

2. **四项协同技术**：(a) Sequence Shuffling 在 BFT 层级内随机打乱节点顺序作为结构数据增强（消融贡献最大，+8.23% MAPE）；(b) Bidirectional Sequence Modeling 同时学习正向序列和反向序列以捕获双向信号传播；(c) Differentiable Sequence Modeling 用 global embedding 减去 depth-local embedding 并配以可学习门控 λ，削弱无关的同层邻居信息；(d) Hybrid Graph-Sequence Architecture 用 GatedGCN 捕获局部拓扑 + Mamba-2 捕获跨层级长程时序依赖。

3. **从 RTL 直接预测 STA**：跳过综合+布局布线+STA 的数小时流程，在秒级推理中预测 AT（到达时间）、WNS（最差负裕量）、TNS（总负裕量）。

4. **性能与可扩展性**：在 21 个开源 RTL 设计（6K~510K 门）上，AT MAPE 降至 17.24%（R=0.92，R^2=0.85），超越所有图模型 baseline（GCN/GAT/CircuitFusion 等）。内存复杂度与节点数呈线性关系，可处理 GCN（深度受限）和 Graph Transformer（二次内存）无法处理的深而大的锥。

**边界**：覆盖阶段 ① 和 ⑤（2/17）的预测映射关系，不做综合/布局/门级仿真/签核。预测值不能替代 STA——它是早期设计迭代工具。训练标签依赖商业闭源 EDA 工具链（DC+Innovus+PrimeTime），代码未开源，缺乏跨工艺和跨设计规模的泛化验证。
