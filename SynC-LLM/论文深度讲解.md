## 1. 一句话定位

**SynC-LLM 是首个用「层级化 LLM 流水线」生成大规模合成 Verilog 电路代码的框架：先由图扩散模型（基于 EDGE）学习真实电路的寄存器依赖骨架（skeleton）并生成新的有向图，再用自监督多模态对比学习训练一个 GraphSAGE 检索器把骨架的图嵌入对齐到每个寄存器对应的组合逻辑功能描述，最后用 GPT-4o-mini 在「逐层（layer-by-layer）命名 + 深度约束」prompt 下逐寄存器锥（cone）合成 HDL 代码、并行合并为完整顶层模块；最终在 22 个真实设计（ITC'99 + OpenCores + Chipyard 的 RISC-V）上合成 25 个新设计，中位数 22K 门 / 7K 行（远超 RTLLM 的 0.1K 门 / 0.05K 行 和 VerilogEval 的 0.01K 门 / 0.01K 行），并使下游 MasterRTL/SNS/RTL-Timer 三类 PPA 预测模型在 Register Slack、TNS、Area 三个指标上分别获得 +9 pp、+14 pp、+4 pp 的 R→1 提升。**

这句话里的 7 个技术承重点：

1. **"骨架 + 血肉"两阶段电路分解** — 把每个 RTL 设计看成 (a) 一张寄存器（Sequential Element）相互依赖的有向图，即 skeleton，与 (b) 每对寄存器之间的纯组合逻辑块，即 cone（flesh）。前者用图扩散生成，后者用 LLM 生成，互不耦合。
2. **有向图扩散模型（EDGE + 边方向预测器）** — 不像 GraphRNN / DVAE 必须先拓扑排序、拆环，SynC-LLM 直接在有向、可能含环的寄存器图上学扩散，复杂度从 $O(N^2)$ 降到 $O(R^2T)$，其中 $R$ 是寄存器数（典型只占节点数 1%-10%），$T=64$ 是扩散步数。
3. **多模态自监督对比检索器（GraphSAGE + 文本对齐）** — 把骨架的图嵌入与 GPT-4o-mini 生成的功能描述嵌入做 triplet 对齐，CCA=0.98，Top-1 平均距离 0.177（vs 随机 0.739、最优文本检索 0.167），为每个新生成的寄存器找回「功能最相似」的真实代码片段作为参考。
4. **逐层 LLM prompt（Layer-by-Layer Prompt）** — 在 prompt 里强制 LLM 按 `layerN_K` 命名规则把组合逻辑逐层展开，并要求每层至少一个赋值来自上一层，变量下标区间 [0, i-1]，从而把逻辑深度从无控制时的 ~3 层拉到 ~10 层，更接近真实电路的 path slack 分布。
5. **大规模 + 真实相似** — 中位数 22K 门（vs RTLLM 0.1K）、Degree MMD 0.005（vs GraphRNN 0.015、DVAE 0.043）、TNS/NVP 分布接近真实设计，证明合成电路既大又像。
6. **下游数据增强直接有效** — 25 个 SynC-LLM 合成设计直接加入 MasterRTL/SNS/RTL-Timer 训练集，三项预测指标全面超越「仅真实数据」「+GraphRNN」「+DVAE」「+SynC-LLM w/o retriever」四个基线。
7. **复杂度低、成本可控** — 25 个设计的 skeleton 阶段在 RTX 4090 上用时 <10% GraphRNN/DVAE；约 5000 个 cone 代码用 5 并行 GPT-4o-mini 在 8 小时内生成，总成本约 30 USD（功能标注 <$10 + 代码生成 ~$20）。

## 2. EDA 阶段映射（①-⑰）

参照 [芯片流程.md](../芯片流程.md) 的 17 阶段标准编号：

| 阶段 | 覆盖 | 说明 |
|------|:---:|------|
| ① RTL 设计 | ✅ **核心** | SynC-LLM 的核心产物就是新的 RTL（Verilog）代码。每个生成的模块可以由 Synopsys DC 直接综合成 netlist，与真实 RTL 无差异。它服务于"RTL 阶段数据稀缺"问题。 |
| ② RTL 功能仿真 | ⚠️ **可选** | 论文要求"每个生成的电路是 complete, self-contained, syntactically valid, simulatable, and will produce deterministic outputs"——即必须能跑仿真，但 SynC-LLM 本身不跑功能仿真，只保证语法可综合 + 可仿真。 |
| ③ 逻辑综合 | ⚠️ **验证目标** | SynC-LLM 不执行综合，但所有 22 个真实训练设计 + 25 个合成设计都通过 Synopsys Design Compiler 2021 + NanGate 45nm 综合以生成 Area / TNS / register slack 标签。 |
| ④ 门级仿真 | ❌ | 不涉及。 |
| ⑤ STA | ⚠️ **预测目标** | TNS / register slack 都是 STA 的输出。SynC-LLM 本身不跑 STA，但通过合成电路 + 下游预测器让 AI 模型学会"在综合前预测 STA 指标"。 |
| ⑥ 形式验证 | ❌ | — |
| ⑦ Floorplan | ❌ | — |
| ⑧ Placement | ❌ | — |
| ⑨ CTS | ❌ | — |
| ⑩ Routing | ❌ | — |
| ⑪ DRC | ❌ | — |
| ⑫ LVS | ❌ | — |
| ⑬ Sign-off | ❌ | — |
| ⑭ Tape-out | ❌ | — |
| ⑮ 制造 | ❌ | — |
| ⑯ 封装 | ❌ | — |
| ⑰ 测试 | ❌ | — |

**覆盖率：1/17 核心 + 2/17 间接验证目标 + 1/17 预测目标。** SynC-LLM 聚焦在 **RTL 阶段（①）的合成数据生成**，并通过下游 PPA 预测任务间接验证合成电路在 **综合（③）/ STA（⑤）** 阶段的有效性。它不做任何后端物理工作。

> ⚠️ **本论文最容易被误读的两个边界**：
> 1. **"功能正确"≠"功能指定"**：论文明确说 specific generated circuit functions are not strictly required。SynC-LLM 不保证每个生成的电路做"指定的逻辑"，它保证的是"每个生成的电路是 self-contained、syntactically valid、simulatable、deterministic"——也就是可以跑综合 / 仿真 / STA 的完整设计，但不是"按指令生成特定功能"。
> 2. **"LLC"层控制 ≠ "层次化综合"**："Layer-by-Layer" 是 LLM 生成 HDL 时的命名 + 深度约束技巧，不是真实电路的 hierarchical synthesis。生成的代码逻辑深度从 3 层提升到 ~10 层，但仍远小于工业 RTL（数十层）。

## 3. 输入 / 输出

### 3.1 输入

**(a) 真实电路的 Verilog 源代码 + 综合标签**

```verilog
// ITC'99 b19 的简化片段（仅展示结构，完整版含 CPU 控制逻辑）
module b19 (
    input clk, rst,
    input [31:0] instr_in, data_in,
    output reg [31:0] result_out
);
    reg [31:0] ir, pc, acc;
    wire [31:0] alu_b = (opcode == 5'h05) ? data_in : imm_ext;
    always @(posedge clk) begin
        if (rst) {ir, pc, acc} <= 0;
        else begin
            ir <= instr_in;
            pc <= pc + 4;
            acc <= (opcode == 5'h05) ? acc + alu_b : acc - alu_b;
        end
    end
    assign result_out = acc;
endmodule
```

前置处理：用论文实现的 parser 解析出 (a) 寄存器集合 $S = \{s_1, ..., s_n\}$、(b) 每个寄存器对应的输入 cone（覆盖到主输入 PI 或其他寄存器的纯组合逻辑）。

**(b) 22 个真实电路组成的数据集（附录 A）**

| 来源 | 设计数 | 门数范围 (#K) | 代码行数范围 (#K) |
|------|:---:|:---:|:---:|
| ITC'99（Corno et al., 2000） | 6 | {9, 19, 45} | {5, 10, 10} |
| OpenCores（Albrecht, 2005） | 8 | {2, 6, 35} | {2, 8, 76} |
| Chipyard RISC-V（Amid et al., 2020） | 8 | {12, 19, 52} | {3, 12, 24} |
| **总计** | **22** | **2–52K** | **2–76K** |

7 个被随机留出做下游 PPA 预测的 test set，剩下 15 个用于 skeleton 生成 + 检索库 + 下游模型训练。

**(c) GraphSAGE 初始化用的 logic-level features**

每个寄存器节点 $v$ 的初始特征 = 寄存器到 skeleton 中各 source 节点的最短路径距离（详情见 Appendix E 注释 6）。这让 GraphSAGE 在学习对比嵌入前已经具备位置感。

**(d) GPT-4o-mini 的功能描述（仅用于 Stage 2 训练时）**

对训练集中的 ~10K 个 cone code，用 GPT-4o-mini 生成 1-3 句自然语言功能摘要（prompt 见 Appendix F）。例如：

```
This code implements the input selection logic for an ALU operation. It selects
between two source operands based on a 1-bit control signal and computes the
second operand's bit-by-bit AND with a mask. Typical position: input stage of
a large processor design.
```

### 3.2 中间产物

**(a) Skeleton（阶段 1 输出）：有向属性图 $G = (V, E)$**

每个节点 $v \in V$ 是寄存器 $s_i$（及少量 IO），每条边 $u \to v$ 表示"从寄存器 $u$ 的输出到寄存器 $v$ 的输入之间存在至少一条组合逻辑路径"。节点属性包括寄存器位宽、IO 标记、寄存器 / IO 区分。22 个训练设计 + skeleton 内部包含约 5,000-10,000 个 cone code 段。

**(b) 检索库（阶段 2 输出）：$D = \{(\text{register-id}, h_g^v, h_t^v, \text{cone code})\}$**

每条记录包含寄存器 ID、GraphSAGE 训练后产生的图嵌入 $h_g^v$、GPT-4o-mini 生成的功能描述的文本嵌入 $h_t^v$（text-embedding-ada-002），以及对应的真实 cone code 文本。约 10K 条记录。

**(c) Functional annotation（阶段 2 输出）：每个新寄存器 $s_i$ 的功能描述文本**

对每个 Stage 1 生成的新寄存器，用训练好的 GraphSAGE 提取其图嵌入 $h_g^{s_i}$，再到检索库 $D$ 中做 top-K 文本检索，返回 top-K 真实功能描述 + cone code 作为 Stage 3 的上下文。

**(d) Layered cone code（阶段 3 输出）：每个寄存器锥的 Verilog 代码**

按 `layerN_K` 命名规则、按 ~10 层逻辑深度组织的纯组合逻辑（`assign` + `wire`），外加一个将最后一个 `layer10_wire1` 接到寄存器 $s_i$ 的 `always @(posedge clk)` 块。

### 3.3 输出

**(a) 完整合成的 Verilog 模块（顶层 `module top_module(...)`）**

```verilog
// SynC-LLM 合成示例的简化版（基于 Figure 2 的 sa32_sr）
module top_module(
    input clk,
    input [7:0]  sa31_sr, sa01_sr,
    input        ld_r,
    input [127:0] text_in_r,
    input [7:0]  sa11_sr, sa21_sr,
    input [31:0] u0_w_1_,
    output [7:0] sa32_sr
);
    sa32_sr u_sa32_sr (
        .sa31_sr(sa31_sr), .sa01_sr(sa01_sr),
        .ld_r(ld_r), .text_in_r(text_in_r),
        .sa11_sr(sa11_sr), .sa21_sr(sa21_sr),
        .u0_w_1_(u0_w_1_), .clk(clk),
        .sa32_sr(sa32_sr)
    );
    // ... 其他 cone module 实例化 ...
endmodule

// 单个 cone module 示例（layer-by-layer 生成）
module sa32_sr(
    input [7:0] sa31_sr, sa01_sr,
    input ld_r, clk,
    input [7:0] sa11_sr, sa21_sr,
    output reg [7:0] sa32_sr
);
    wire [7:0] layer1_wire1;
    wire [7:0] layer2_wire1;
    // ...
    wire [7:0] layer9_wire1;
    wire [7:0] layer10_wire1;
    // Layer 1
    assign layer1_wire1 = sa31_sr & sa01_sr;
    // Layer 2
    assign layer2_wire1 = ld_r ? sa11_sr : sa21_sr;
    // ... Layer 3~9 省略 ...
    // Layer 10: 接到输出寄存器
    assign layer10_wire1 = layer9_wire1;
    always @(posedge clk) begin
        sa32_sr <= layer10_wire1;
    end
endmodule
```

**(b) 可综合的 netlist（由 Synopsys DC 派生）**

合成代码经 DC 2021 + NanGate 45nm 综合后得到 gate-level netlist，与真实设计的 netlist 在门数、面积、TNS、register slack 分布上高度相似。

**(c) 下游 AI 模型增强的训练集**

合成设计加入 MasterRTL/SNS/RTL-Timer 训练集后，下游 PPA 预测器在 7 个留出 test 设计上的 R→1、MAPE、RRSE 全面改善。

## 4. 方法与架构

### 4.1 整体 Pipeline

SynC-LLM 的整体流程分三个阶段，每阶段独立可替换：

```text

   输入：22 个真实 Verilog 设计 + Synopsys DC 综合标签
   ┌──────────────────────────────────────────────────────────────┐
   │ Parser：解析 HDL → 寄存器集合 S、寄存器锥 cones             │
   │ 输出：每个寄存器 s_i 的图嵌入 h_g + 文本嵌入 h_t            │

### 4.2 模块 1：图扩散（Stage 1）

#### 4.2.1 骨架的图表示

每个电路被解析为有向属性图 $G$，节点 $v \in V$ 是寄存器（含少量 IO），边 $u \to v$ 表示存在组合逻辑路径从寄存器 $u$ 的输出到寄存器 $v$ 的输入。节点属性至少包括位宽；可能含 IO 标记。

为什么用寄存器做节点？
- 寄存器天然是时序锚点，构成 "sequential skeleton"
- 每个寄存器的输入 cone 是纯组合逻辑，可以用 LLM 独立生成
- 寄存器数量 $R$ 远小于总节点数 $N$（典型 $R/N \approx 0.01 \sim 0.1$）

#### 4.2.2 EDGE 扩散 + 边方向预测器

论文采用 Chen et al. (2023) 的 EDGE（Efficient Degree-guided Graph Generation）作为 backbone，再叠加边方向预测器。

**前向过程**（加噪）：

$$
q(A_t | A_{t-1}) = \mathcal{N}(A_t; \sqrt{\alpha_t} A_{t-1}, (1 - \alpha_t) I)
$$

其中 $A_t$ 是 $t$ 时刻的邻接矩阵，$\alpha_t \in [0, 1]$ 是噪声调度参数。

**反向过程**（去噪）：

$$
p_\theta(A_{t-1} | A_t) = \mathcal{N}(A_{t-1}; \mu_\theta(A_t, t), \Sigma_\theta(A_t, t))
$$

$\mu_\theta, \Sigma_\theta$ 由神经网络学习。

**边方向预测**（EDGE 之外的增量）：

对任意候选边 $(u, v)$，从 GNN 取两个节点的嵌入 $h_u, h_v$，拼接后过 MLP 输出 $u \to v$ 的概率：

$$
p(u, v) = \sigma(\text{MLP}_E([h_u; h_v]))
$$

训练时这个概率指导反向采样；推理时直接决定边方向。

#### 4.2.3 复杂度优势

| 方法 | 空间复杂度 | 时间复杂度 | 备注 |
|------|:---:|:---:|------|
| GraphRNN | $O(N)$ | $O(N^2)$ | 必须自回归、必须先破环、必须按拓扑序 |
| DVAE | $O(N)$ | $O(N^2)$ | 自编码器结构，节点级生成 |
| **SynC-LLM** | $O(R^2)$ | $O(R^2 T)$ | $R \approx 0.01N \sim 0.1N$, $T=64$ |

论文报告在 RTX 4090 上 SynC-LLM 生成一个 skeleton 只需数秒，用时 < 10% 的 GraphRNN/DVAE。

### 4.3 模块 2：多模态检索器（Stage 2）

#### 4.3.1 数据准备

把 22 个真实设计中所有 ~10K 个 cone code 切成：
- 寄存器 $v$ → graph encoder（GraphSAGE）→ $h_g^v \in \mathbb{R}^d$
- 对应 cone code → GPT-4o-mini → 自然语言描述 → text-embedding-ada-002 → $h_t^v \in \mathbb{R}^d$

训练正负样本选择：

$$
P(v) = \{j \in V \setminus \{v\} : j \in \text{NN}_{k_p}(v)\}
$$

$$
N(v) \subset V \setminus (\{v\} \cup P(v))
$$

$k_p$ 默认为 20（top-20 文本最近邻为正），$k_n$ 默认为 200（随机 200 个为负）。

#### 4.3.2 三元组损失

$$
\mathcal{L}_{v, j, i} = \max\{0,\; d(h_g^v, h_t^j) - d(h_g^v, h_t^i) + \delta\}
$$

$$
\mathcal{L} = \frac{1}{|V|} \sum_{v \in V} \frac{1}{|P(v)| \cdot |N(v)|} \sum_{j \in P(v)} \sum_{i \in N(v)} \mathcal{L}_{v, j, i}
$$

- $d(\cdot, \cdot)$：作者默认用 cosine 距离
- $\delta$：margin 超参

#### 4.3.3 检索器评估

论文 Table 5 给出的关键数据（Top-K 平均距离 ↓ 越小越好）：

| 配置 | K=1 | K=10 | K=20 | |CCA-1| |
|------|:---:|:---:|:---:|:---:|
| Random Retrieval | 0.739 | 0.739 | 0.739 | — |
| Nearest Labels（最优文本） | 0.1673 | 0.175 | 0.179 | — |
| GCN | 0.181 | 0.194 | 0.201 | 0.975 |
| GAT | 0.193 | 0.202 | 0.208 | 0.972 |
| GraphSAGE（无 logic-level features） | 0.1823 | 0.195 | 0.203 | 0.976 |
| **GraphSAGE（with logic-level features）** | **0.177** | **0.187** | **0.189** | **0.979** |

**CCA 0.98 表明图嵌入与文本嵌入高度线性相关**——也就是说 GraphSAGE 学到的向量空间几乎可以用线性投影映射到功能语义空间。

### 4.4 模块 3：逐层 LLM 生成（Stage 3）

first operand of the ALU operation...
ALU input selection: ...
ALU operations: ...
Branching decision: ...
Summary: This code implements the logic of ...
### end design description ###

Please use what I just described to write similar verilog code with the 
following requirements:
Given 7 inputs named sa31_sr, sa01_sr, ld_r, text_in_r, sa11_sr, sa21_sr, 
u0_w_1_ with bit widths of 8, 8, 1, 128, 8, 8, 32 respectively. Also, a 
one-bit clk signal is also an input port and one output named sa32_sr with 
bit width of 8.
The Verilog code should contain ... (specific requirements)
Put the complete pure code between ##code## and ##end code##. Please 
consider the design description provided in the prompt beginning to guide 
your code writing.
```

#### 4.4.2 Layer-by-Layer 控制（Logic Level Control, LLC）

论文的两个关键约束：

**变量命名规则**：每个变量命名为 `layerN_K`，$N$ 是它所在的层号，$K$ 是该层内序号。这强制 LLM 把代码组织成"按层"的层次结构。

**层一致性约束**：对任何第 $i$ 层的变量，其赋值表达式中至少要引用一个第 $i-1$ 层的变量；其他被引用的变量必须来自第 $0$ 到 $i-1$ 层。

**效果**：Figure 5 显示加了 LLC 后，cone code 的逻辑深度分布显著右移（更多 5-10 层路径），更接近真实电路的 path depth 分布。

#### 4.4.3 语法检查与并行合成

- 每个 cone 单独生成 → 可并行（论文用 5 路 GPT-4o-mini 并发）
- 每段代码必须通过 syntax check（能跑过 DC 解析）
- 最终将所有 cone code 集成到顶层 `module top_module(...)` 中

## 5. 关键公式

### 5.1 图扩散前向过程

邻接矩阵逐步加噪：

$$
q(A_t | A_{t-1}) = \mathcal{N}(A_t; \sqrt{\alpha_t} A_{t-1}, (1 - \alpha_t) I)
$$

- $A_t$：$t$ 时刻的邻接矩阵
- $\alpha_t \in [0, 1]$：噪声调度
- $I$：单位矩阵
- $\mathcal{N}(\mu, \Sigma)$：高斯分布

**工程直觉**：$t=0$ 时 $A_0$ 是真实的稀疏邻接矩阵；$t=T$ 时 $A_T \sim \mathcal{N}(0, I)$ 是纯噪声。模型学习"从噪声一步步去噪回 $A_0$"。

### 5.2 图扩散反向过程

去噪网络预测前一时刻的均值 / 方差：

$$
p_\theta(A_{t-1} | A_t) = \mathcal{N}(A_{t-1}; \mu_\theta(A_t, t), \Sigma_\theta(A_t, t))
$$

- $\mu_\theta$：神经网络预测的均值
- $\Sigma_\theta$：神经网络预测的协方差（论文通常简化为对角）

### 5.3 边方向预测

对任意候选边 $(u, v)$：

$$
p(u \to v) = \sigma(\text{MLP}_E([h_u; h_v]))
$$

- $h_u, h_v$：节点 $u, v$ 的 GNN 嵌入
- $\sigma$：sigmoid 函数
- $\text{MLP}_E$：边方向预测的多层感知机

**为什么这么设计**：扩散 backbone 输出的是"边是否存在"，但 RTL 中边是有向的（寄存器 $a$ 是寄存器 $b$ 的输入锥成员，反过来不一定）。需要一个独立预测器决定方向。

### 5.4 三元组对比损失

$$
\mathcal{L}_{v, j, i} = \max\{0,\; d(h_g^v, h_t^j) - d(h_g^v, h_t^i) + \delta\}
$$

$$
\mathcal{L} = \frac{1}{|V|} \sum_{v \in V} \frac{1}{|P(v)| |N(v)|} \sum_{j \in P(v)} \sum_{i \in N(v)} \mathcal{L}_{v, j, i}
$$

- $h_g^v$：寄存器 $v$ 的图嵌入
- $h_t^j, h_t^i$：正 / 负样本的文本嵌入
- $d(\cdot, \cdot)$：距离度量（cosine 距离）
- $\delta$：margin
- $P(v), N(v)$：正 / 负样本集合

### 5.5 CCA（Canonical Correlation Analysis）

两个嵌入空间的线性相关性：

$$
\rho = \max_{a, b} \frac{a^\top \Sigma_{XY} b}{\sqrt{a^\top \Sigma_{XX} a} \cdot \sqrt{b^\top \Sigma_{YY} b}}
$$

约束 $a^\top \Sigma_{XX} a = 1$ 和 $b^\top \Sigma_{YY} b = 1$。

- $\Sigma_{XX}, \Sigma_{YY}$：图嵌入、文本嵌入的协方差矩阵
- $\Sigma_{XY}$：交叉协方差矩阵
- $a, b$：线性投影向量

论文报告 $\rho = 0.98$，非常接近 1。

### 5.6 Layer-by-Layer 约束

对第 $i$ 层的任意变量 $v_i$：

$$
\exists\, u \in \text{deps}(v_i) : u \in \text{Layer}_{i-1}
$$

$$
\forall\, w \in \text{deps}(v_i) : w \in \bigcup_{j=0}^{i-1} \text{Layer}_j
$$

**工程直觉**：强制每一层都"消费"前一层的输出，构成一个明确的深度方向。这避免了 LLM 把所有逻辑塞到第 1 层的 "flat" 输出。

### 5.7 下游评估指标

三个回归指标：

$$
R \to 1 = \text{Pearson}(y_{\text{true}}, y_{\text{pred}})
$$

$$
\text{MAPE} = \frac{1}{N} \sum_{k=1}^{N} \left| \frac{y_k - \hat{y}_k}{y_k} \right|
$$

$$
\text{RRSE} = \sqrt{ \frac{\sum_{k=1}^{N} (y_k - \hat{y}_k)^2}{\sum_{k=1}^{N} (y_k - \bar{y})^2} }
$$

- $y_k$：真实 PPA 值
- $\hat{y}_k$：预测 PPA 值
- $\bar{y}$：均值
- $N$：样本数

R→1 越高越好（1=完美），MAPE / RRSE 越低越好（0=完美）。

## 6. 训练与实验设置

### 6.1 是否需要训练

**需要训练的部分**：
- Stage 1 的图扩散模型（EDGE + 边方向 MLP），基于 22 个真实电路的 skeleton（约 22K 寄存器 / 边）
- Stage 2 的多模态对比检索器（GraphSAGE + 文本对齐），基于 ~10K cone code

**不训练**：
- Stage 3 的 LLM（直接调 GPT-4o-mini API）
- Parser、Syntax checker、整合器（纯规则）
- 下游 PPA 预测模型用各自原始论文的配置

### 6.2 训练设置

**Stage 1（Graph Diffusion）**：
- Backbone：EDGE（Chen et al., 2023）
- 数据：22 个真实设计的 skeleton
- 扩散步数 $T = 64$
- 硬件：RTX 4090

**Stage 2（Multimodal Retriever）**：
- Backbone：GraphSAGE（带 logic-level features 作为初始 node features）
- 文本编码：text-embedding-ada-002（OpenAI）
- 文本生成：GPT-4o-mini
- 正样本数 $k_p = 20$，负样本数 $k_n = 200$
- Margin $\delta$：默认 0.2（triplet loss 标准值）
- 优化器：Adam

**Stage 3（LLM Generation）**：
- 模型：GPT-4o-mini（5 并行）
- 输出格式：每段 cone code 包在 `##code## ... ##end code##` 之间
- 总时长：8 小时（25 个设计 × ~5000 cone 段）

### 6.3 实验设置

**对比方法**：
- GraphRNN（You et al., 2018）：自回归图生成
- DVAE（Zhang et al., 2019）：变分自编码器图生成
- SynC-LLM w/o retriever：Stage 2 不用检索器，直接 prompt LLM
- No synthetic data augmentation：只用 15 个真实设计训练下游模型

**下游任务**（基于 MasterRTL/SNS/RTL-Timer）：
1. **Register slack prediction**：每个寄存器在 STA 后最差 slack
2. **TNS prediction**：整个设计的 total negative slack
3. **Area prediction**：综合后的等价门数

**评估指标**：R→1（皮尔逊）、MAPE（绝对百分比误差）、RRSE（相对平方根误差）

### 6.4 关键实验结果

#### 6.4.1 Skeleton 相似度（Table 2）

| 方法 | Degree MMD ↓ | Cluster MMD ↓ | Orbit MMD ↓ | Spectral MMD ↓ |
|------|:---:|:---:|:---:|:---:|
| GraphRNN | 0.015 | 0.343 | 0.136 | 2.46 |
| DVAE | 0.043 | 0.458 | 0.371 | 0.036 |
| **SynC-LLM** | **0.005** | **0.022** | **0.007** | **0.003** |

**解读**：所有 4 个图统计指标上 SynC-LLM 都显著优于 GraphRNN 和 DVAE，特别是 Cluster / Orbit / Spectral 三个——这些捕捉的是局部、全局结构特征，SynC-LLM 的层级化生成更接近真实电路的"寄存器依赖骨架"。

#### 6.4.2 合成电路规模对比（Table 1）

| Benchmark | Source | 设计规模 (#K Gates) {Min, Median, Max} | 设计规模 (#K Lines) {Min, Median, Max} |
|-----------|--------|:---:|:---:|
| RTLLM v1.0 | LLM 直接生成 | {1e-1, 2} | {5e-2, 5e-1} |
| VerilogEval | LLM 直接生成 | {1e-2, 2e-1} | {1e-2, 6e-2} |
| **SynC-LLM** | 层级化生成 | **{22, 56}** | **{7, 17}** |

**解读**：SynC-LLM 合成电路的**中位数**门数 = 22K 行 = 56K，分别是 RTLLM 的 ~110 倍、~220 倍，VerilogEval 的 ~1100 倍、~1100 倍。这是"大规模"的核心数字。

#### 6.4.3 下游 PPA 预测（Table 3，核心结果）

**真实数据集** = 15 个真实设计。**扩展数据集** = 15 真实 + 25 合成。

| 模型 | Register Slack R→1 | MAPE ↓ | RRSE ↓ | TNS R→1 | MAPE ↓ | RRSE ↓ | Area R→1 | MAPE ↓ | RRSE ↓ |
|------|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| 无合成数据 | 0.70 | 27% | 0.83 | 0.81 | 50% | 0.97 | 0.89 | 30% | 0.62 |
| + GraphRNN | 0.70 | 27% | 0.83 | 0.80 | 54% | 0.97 | 0.84 | 44% | 0.75 |
| + DVAE | 0.69 | 29% | 0.94 | 0.78 | 50% | 0.97 | 0.84 | 61% | 0.86 |
| + SynC-LLM w/o retriever | 0.76 | 24% | 0.76 | 0.85 | 47% | 0.83 | 0.85 | 33% | 0.70 |
| **+ SynC-LLM w/ retriever** | **0.79** | **17%** | **0.73** | **0.95** | **42%** | **0.58** | **0.93** | **25%** | **0.43** |

**关键观察**：
1. SynC-LLM w/ retriever 在所有 9 项指标上都是最优
2. Register slack R→1 从 0.70 → 0.79（+9 pp）
3. TNS R→1 从 0.81 → 0.95（+14 pp，最大提升）
4. Area R→1 从 0.89 → 0.93（+4 pp）
5. **GraphRNN / DVAE 不仅没帮助，甚至有损**（Area 的 MAPE 从 30% 涨到 44%/61%）
6. **SynC-LLM w/o retriever 仍比 GraphRNN/DVAE 好**——证明 skeleton 阶段本身就有价值，retriever 只是锦上添花

#### 6.4.4 逻辑深度分布（Figure 5）

SynC-LLM（with LLC）生成的 cone code 的逻辑深度分布**显著右移**，主峰从 ~3 层移到 ~10 层，与真实电路的 5-10 层分布高度匹配。
- 无 LLC：主峰在 3 层（"flat" 输出）
- 有 LLC：主峰在 8-10 层，分布接近真实
- GraphRNN/DVAE：因为完全没做逻辑深度控制，分布接近 0（基本无组合逻辑）

#### 6.4.5 TNS/NVP 分布（Figure 6）

Netlist timing 上，SynC-LLM w/ retriever 的 TNS/NVP 分布最接近真实设计；GraphRNN/DVAE 的 TNS/NVP 极小（说明生成的电路几乎没有时序违例路径，与真实电路差异巨大）。SynC-LLM w/o retriever 比 w/ retriever 明显差——证明 retrieval 对时序真实性影响重大。

### 6.5 消融实验

#### 6.5.1 检索器架构对比（Table 5）

| 架构 | Top-1 距离 | Top-20 距离 | CCA-1 |
|------|:---:|:---:|:---:|
| Random | 0.739 | 0.739 | — |
| Nearest Labels（文本最优） | 0.1673 | 0.179 | — |
| GCN | 0.181 | 0.201 | 0.975 |
| GAT | 0.193 | 0.208 | 0.972 |
| GraphSAGE w/o logic-level features | 0.1823 | 0.203 | 0.976 |
| **GraphSAGE w/ logic-level features** | **0.177** | **0.189** | **0.979** |

**结论**：
1. GraphSAGE 是最好的骨架编码器（与 GCN/GAT 对比）
2. Logic-level features（最短路径距离）作为初始 node feature 显著提升检索质量

#### 6.5.2 LLC 的贡献

去掉 LLC 后，cone logic depth 主峰从 10 层回到 3 层，TNS/NVP 分布显著退化，下游 PPA 预测指标全面下降。

## 7. 创新点

### 7.1 首次用 LLM 生成大规模 Verilog 电路

**贡献**：把 LLM 的代码生成能力从「几十到几百门的小模块」（RTLLM、VerilogEval）扩展到「万门级、十万行级」的完整电路。

**为什么重要**：之前的 LLM-for-RTL 论文（RTLCoder、BetterV、CodeV、OriGen 等）都被局限在小规模——一个 LLM 调用最多生成 ~2K 门的设计，根本无法模拟真实工业电路的规模。SynC-LLM 用"骨架 + 血肉"分离 + 并行 LLM 调用 + 整合三个技巧，把规模提到 22K-56K 门（中位数），首次让"LLM 生成大电路"成为现实。

### 7.2 层级化"Skeleton + Flesh"分解

**贡献**：将 RTL 电路自然地分成"寄存器依赖骨架（有向图）"和"每对寄存器间的纯组合逻辑锥"两层，分别用图扩散 + LLM 生成。这是对「电路结构 = 拓扑 + 行为」这一洞察的形式化。

**对比之前的图生成（GraphRNN / DVAE）**：它们直接把电路当无向图或简单有向图生成，丢失了"寄存器是时序锚点"这一关键信息。SynC-LLM 的 skeleton 显式建模寄存器之间的有向依赖，每条边对应"是否存在组合逻辑路径"——这与综合工具（Yosys/DC）内部的 timing graph 语义一致。

### 7.3 多模态 GraphSAGE 检索器

**贡献**：用自监督 triplet 对齐损失，把"寄存器在 skeleton 中的图嵌入"与"该寄存器对应的组合逻辑功能描述"映射到同一向量空间，CCA=0.98。

**为什么重要**：这一步把"图生成"和"代码生成"耦合起来——LLM 不是凭空生成 HDL，而是看到「这个新寄存器的邻居结构最像训练集中的哪个寄存器」然后照葫芦画瓢。这避免 LLM 在没有参考时 hallucinate 出语法正确但功能离谱的代码。

### 7.4 Layer-by-Layer Prompt（LLC）

**贡献**：用「`layerN_K` 命名规则 + 层一致性约束」让 LLM 自然生成深度 ~10 层的组合逻辑代码，显著提升合成电路的 path slack 分布真实性。

**对比之前的 LLM-for-RTL**：默认 LLM 倾向于生成 "flat" 输出（一层搞定所有逻辑），但真实电路是层次化的——加法器树、Mux 级联、流水线站、ALU 多级选择。LLC 用最简单的命名约束实现了这一深度结构。

### 7.5 复杂度可控、成本极低

**贡献**：从 $O(N^2)$ 降到 $O(R^2 T)$，其中 $R \ll N$；完整 25 个新设计生成总成本约 30 USD。

**对比 GraphRNN / DVAE**：它们必须按拓扑序生成节点，复杂度与电路节点数平方成正比。SynC-LLM 只需要生成「寄存器之间的边」，寄存器数远小于节点数，效率高 1-2 个数量级。

## 9. 与芯片流程关系

### 9.1 在 EDA 流程中的位置

SynC-LLM 是 **RTL 设计阶段（①）的合成数据生成器**——它生成的 Verilog 代码与人工写的 RTL 在 EDA 工具链视角下完全等价：

```text
传统 RTL 流程（数据稀缺）：
spec → ①RTL(人工) → ③综合 → ⑤STA → ⑥形式验证 → ...

SynC-LLM 介入点：
spec → ①RTL(SynC-LLM 合成) → ③综合 → ⑤STA → ...
       ↑ 填补数据稀缺的空白
```

下游任务（MasterRTL/SNS/RTL-Timer）用 SynC-LLM 合成数据 + 真实数据训练，在 RTL 阶段（综合前）预测 TNS / Area / register slack，从而把 "RTL → 综合 → STA → 反馈重写" 的迭代成本从「每次都要跑到综合」降到「RTL 阶段直接估算」。

### 9.2 "能跑综合"和"能做芯片"之间隔着什么

SynC-LLM 解决了"有 RTL 数据"，但一个真实可制造的芯片还需要：

1. **功能性正确** — SynC-LLM 不保证合成电路做"指定的功能"，只保证它是 self-contained / simulatable / deterministic。论文明确说 specific generated circuit functions are not strictly required。
2. **可综合到门级网表** — SynC-LLM 设计的代码可以通过 Synopsys DC 综合，这一步已验证。
3. **满足时序** — SynC-LLM 设计的 TNS/NVP 分布与真实设计相似，但每个具体设计的 TNS 不一定满足设计目标。
4. **可布局布线** — 论文没做 PnR 验证，但 Figure 9-10 展示了用 Innovus + Nangate45 跑 PnR 的合成电路版图，说明至少可以走通 PnR 流程。
5. **DRC / LVS clean** — 没有公开数据。
6. **签核 (sign-off)** — 需要 IR drop、crosstalk、aging 等检查，远超 SynC-LLM 的范围。

> **本资料包的提示**：SynC-LLM 的"成功"是 **AI 模型训练数据增强** 意义上的成功，而不是 "生成可流片的芯片"。下游任务（MasterRTL/SNS/RTL-Timer）也确实只在 PPA 预测上验证，没有声称能流片。

## 10. 讨论与局限

### 10.1 论文自述局限

#### 局限 1：功能正确性不保证

论文第 3 节明确说 specific generated circuit functions are not strictly required。SynC-LLM 保证每个设计是完整的、可仿真的，但**不保证做的是设计者想要的功能**。这意味着它只能用于数据增强，不能直接用于生成具体应用电路。

#### 局限 2：合成电路评估缺乏成熟框架

论文第 9 节（Limitations）指出：generating large-scale synthetic hardware designs is a novel research direction, and consequently, a standardized or mature evaluation framework for rigorously quantifying design similarity does not yet exist。

目前用的 MMD (Degree / Cluster / Orbit / Spectral) + TNS/NVP 分布 + 下游任务指标都是 reasonable but not comprehensive。没有统一标准来评判"合成电路到底有多像真实电路"。

#### 局限 3：复杂度可比性复杂

GraphRNN / DVAE 的 $O(N^2)$ 是论文基于"节点级自回归 + 全连接边预测"的理论估计。真实实现可能更高效。但 SynC-LLM 在 RTX 4090 上 < 10% 时间是论文实测，更可信。

### 10.2 代码/复现层面

#### 复现门槛

1. **数据**：22 个真实设计的 Verilog 需自备（来自 ITC'99、OpenCores、Chipyard，附录 A 列了具体来源）
2. **综合标签**：需要 Synopsys Design Compiler 2021 + NanGate 45nm（商业 + 学术免费混合）
3. **LLM API**：GPT-4o-mini 需要 OpenAI API key（22 个设计的 skeleton 训练 + 25 个设计的 cone 生成，总成本约 30 USD）
4. **Stage 1 训练**：基于 EDGE 的官方代码 + 边方向预测器增量代码
5. **Stage 2 训练**：GraphSAGE（PyG/DGL）+ triplet loss

#### 已知差异

- **Synopsys DC vs Yosys 综合**：论文用商业 DC；用 Yosys 复现 PPA 标签会有数值差异
- **GPT-4o-mini 版本波动**：OpenAI 会更新模型版本，不同时刻生成结果可能略有差异
- **检索库规模**：10K cone code 是论文的实验设置，可调整；缩到 1K 检索质量明显下降

### 10.3 本资料包的批判性分析

#### 批判 1：合成电路对 PPA 预测的"帮助"可能是过拟合

SynC-LLM 合成 25 个设计 + 15 个真实训练下游模型 → 测试集 7 个真实设计。提升指标从 R→1 0.70 → 0.79。但 7 个测试样本的方差可能很大，±0.05 的 R→1 波动是常见的。需要 cross-validation 才能确认提升是稳健的。

#### 批判 2：LLC 的"10 层"远低于工业实际

论文生成的 cone code 逻辑深度 ~10 层。但真实工业 RTL 的 path depth 经常在 30-50 层（multi-cycle 数据通路、复杂 FSM）。SynC-LLM 的"逻辑深度"统计可能在"层数"的定义上有简化——可能没有递归计算 instance 内部深度。

#### 批判 3：检索器只是缓解 LLM 的 hallucination，并未根治

GraphSAGE 检索能保证 LLM 写出的代码"和某个真实代码片段相似"，但**不保证功能正确**。如果检索到的参考代码本身有 bug（来自训练集的真实设计），LLM 可能继承。

#### 批判 4：与 [MasterRTL](../MasterRTL/论文深度讲解.md) / [RTL-Timer](../RTL-Timer/论文深度讲解.md) 的真正价值是"数据增强 vs 算法改进"

MasterRTL 用 XGBoost + 多级特征就做到 TNS R→1 = 0.81。SynC-LLM 加 25 个合成设计涨到 0.95——这是 ~14 pp 的提升。但这个提升能否在跨数据集（in-house vs ITC'99）保持？论文没做 cross-domain 验证。

#### 批判 5：API 依赖与开源的边界

SynC-LLM 的 Stage 3 完全依赖 OpenAI API（GPT-4o-mini）。论文开源了 skeleton + retriever + prompt 模板，但没有开源"用 GPT-4o-mini 生成的 cone code"——因为 OpenAI 的输出条款限制。这意味着复现者必须自己跑 Stage 3，总成本 ~30 USD。

## 12. 一分钟复述版

1. **核心问题**：AI4EDA 受限于真实 RTL 数据稀缺——工业 RTL 是 IP，公开只有 22 个小到中等设计。LLM 可以生成代码但只能生成 ~2K 门，远不够训练下游 PPA 预测器。
2. **方法概述**：SynC-LLM = 图扩散（学真实电路寄存器骨架）+ GraphSAGE 多模态检索器（让 LLM 参考真实功能）+ Layer-by-Layer GPT-4o-mini（生成 10 层深度组合逻辑）+ 顶层模块整合。
3. **核心数据**：22 真实设计（ITC'99 + OpenCores + Chipyard）→ 25 合成设计，中位数 22K 门 / 7K 行，是 RTLLM 的 100 倍以上。
4. **关键结果**：下游 PPA 预测 Register Slack R→1 +9 pp（0.70→0.79）、TNS R→1 +14 pp（0.81→0.95）、Area R→1 +4 pp（0.89→0.93）；GraphRNN/DVAE 不仅没帮反而退步。
5. **最大创新点**：Skeleton + Flesh 分解让 LLM 不必一次生成整个电路，而是并行生成可独立验证的 cone；LLC 让 LLM 自然生成深度组合逻辑。
6. **EDA 流程位置**：RTL 设计阶段（①），下游被 MasterRTL/SNS/RTL-Timer 用作训练数据。
7. **与同类工作的关系**：与 [RTLCoder](../RTLCoder/)、[BetterV](../BetterV/)、[CodeV](../CodeV/) 等 LLM-for-RTL 工作互补（它们生成小设计）；与 [MasterRTL](../MasterRTL/)、[RTL-Timer](../RTL-Timer/) 是直接上下游关系。
8. **局限**：合成电路不保证功能正确；评估指标不统一；LLC 逻辑深度 ~10 层仍远低于工业实际；依赖商业综合工具 + OpenAI API。

## 附录 A：SynC-LLM 与 [CraftRTL](../CraftRTL/论文深度讲解.md) 的对比

虽然 CraftRTL 和 SynC-LLM 都在 EMNLP/ICLR 同期、都做"LLM-for-RTL 合成数据"，但目标完全不同：

| 维度 | SynC-LLM | CraftRTL |
|------|----------|----------|
| 目标产物 | 新的 Verilog 设计（数据增强） | 训练样本（提升 LLM 微调效果） |
| 规模 | 25 个完整设计，22K-56K 门 | 110K 个 (problem, solution) 对 |
| 生成方法 | 骨架图扩散 + 检索增强 LLM | LLM Self-Instruct + Correct-by-Construction + Repair |
| LLM 角色 | 生成器（API 调用） | 既是数据源（80K SDG），又是被训练对象（Starcoder2-15B） |
| 解决的问题 | 真实 RTL 数据稀缺 | LLM 微调数据质量差 + 训练不稳定 |
| 评估方式 | 下游 PPA 预测 R→1 提升 | VerilogEval / RTLLM pass@1 提升 |
| 关键技巧 | Skeleton + Flesh 分解、Layer-by-Layer Prompt | Correct-by-Construction（KMap/FSM/Waveform）、Targeted Repair |
| 与下游 EDA 工具的关系 | 生成的代码走 DC / Innovus 验证 | 不涉及综合，仅 LLM pass@k |
| 阶段定位 | EDA 流程上游（数据源） | EDA 流程外（LLM 训练方法） |

两者都属于"AI4EDA 中的合成数据"大方向，但研究问题不同：SynC-LLM 解决"没数据"，CraftRTL 解决"有数据但数据质量差 + LLM 学不好"。
