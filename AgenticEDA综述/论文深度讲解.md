## 1. 一句话定位

**AgenticEDA 综述是首篇系统化梳理 EDA 自主性演进的 survey：提出 L0-L4 五级自主性分级（手工到算法到 AI Copilot 到 Agentic Orchestration 到 Self-Driving Design 4.0）类比 SAE 自动驾驶分级，提出 Perception-Cognition-Action 三层认知栈（多模态对齐到神经符号规划与推理到确定性工具执行）作为分析所有 40+ 框架的统一透镜，把行业从"AI as prediction"的认识升级到"AI as constrained neuro-symbolic optimization"——Frontend 重点是 dual-loop syntactic-semantic repair（AutoChip / VerilogCoder），Backend 重点是 algorithm-centric solver vs agent-centric orchestrator 的二分（AlphaChip RL / DiffusionPlace / GNN / ChatEDA / ORFS-Agent 等），并把 Trustworthiness gap（hallucinations vs trojans、Sim-to-Silicon gap、缺乏工业级 benchmark）作为开放问题批判性剖析。**

这句话里的七个技术承重点：

1. **"Productivity Gap + Design Complexity Outpace Human Capacity"** — 几十年来晶体管数指数增长而工程师数线性增长，verification 单项已占 60-70% 开发周期，传统 "siloed optimization" 解决单个 stage 的 sub-problem 但跨 stage 失语（RTL 改动如何影响 routing congestion 没法反馈）
2. **L0-L4 自主性分级（类比 SAE J3016 自动驾驶）** — L0-L1: 手工 + 算法求解（pre-1980s 至今）；L2: AI Copilot（2018-2023, AI 预测但不执行，Human Drives）；L3: Agentic EDA Orchestration（2024+, Agent drives，Human Monitors，闭环修复）；L4: Self-Driving Design 4.0（AI drives full RTL-to-GDSII，Human defines intent）
3. **Perception-Cognition-Action 三层认知栈（统一分析透镜）** — Perception 把 Netlist Graph + HDL Text + Layout Geometry 用 contrastive learning 统一进 shared latent space（CircuitFusion / GenEDA）；Cognition 用 LLM 做启发式搜索 + SAT/SMT/SPICE 当地面验证 + Hierarchical Memory 防 "Design Intent Drift"；Action 做 NL2SL 翻译控制商业 EDA 工具 + 在沙箱里 checkpoint rollback 防 "destructive hallucination"
4. **Methodological Taxonomy 三类范式** — Prompt-Based Reasoning（ChatEDA 用 ReAct training-free）/ Specialized Models SFT-RLHF（AlphaChip 用大规模 RL pretrain 获得 "layout intuition"）/ Multi-Agent Collaboration（ArchPower 用多 agent 调协商）
5. **Frontend dual-loop repair 是 Verilog 生成类工作的骨干结构** — Inner Syntactic Loop 喂 compiler logs 快速过滤语法错误（AutoChip）；Outer Semantic Loop 喂 simulation waveforms + AST 做功能因果推理（VerilogCoder）；SI-CoT（Structured Instruction CoT）让 agent 先 "think-before-code" 再下笔
6. **Backend dichotomy: Neural-Augmented Solvers vs Agent-Centric Orchestrators** — Solvers 内部替换启发式（AlphaChip sequential RL / DiffusionPlace conditional denoising / TransPlace GNN / DeepGate4 sub-linear memory transformer）；Orchestrators 外部编排商业工具（ChatEDA 98.3% success rate / Chip-Chat conversation / REvolution 24.5% power reduction / Cross-Stage Closure 让 agent 读 backend PPA 倒推 RTL 改动）
7. **Trustworthiness Gap 是 Agentic EDA 的最大障碍** — 三类风险：Model-Centric Risks（TrojanStego 嵌入恶意 logic + HaVen 的 hallucination）+ Infrastructure-Centric Risks（DRC-Coder 注入恶意 rules + CircuitNet 数据隐私）+ Verification & Explainability 缺位——呼吁 Sim-to-Silicon Benchmarks + Formal Grounding 把 brittle prototype 转成 resilient engineering system

## 2. EDA 阶段映射（①-⑰）

参照 [芯片流程.md](../芯片流程.md) 的 17 阶段标准编号：

| 阶段 | 覆盖 | 说明 |
|------|:---:|------|
| **① RTL 设计** | ✅ **核心** | VerilogCoder / AutoChip / VeriGen / RTLLM / Chip-Chat / Spec2RTL-Agent 直接处理 NL → RTL 或 RTL 修复；这是 frontend dual-loop repair 的主场 |
| ② RTL 功能仿真 | ✅ **核心** | VerilogCoder 用 simulation waveform + AST 做 semantic 反馈；PRO-V-R1 / Saarthi 生成 UVM stimuli 驱动 testbench |
| ③ 逻辑综合 | ⚠️ **间接相关** | RTL-to-GDSII flow 必然穿越综合；ChatEDA / ORFS-Agent 编排 commercial synthesis 作为 Step A |
| ④ 门级仿真 | ❌ | 综述不专门讨论；门级仿真通常只在 verification 阶段提及 |
| **⑤ STA** | ✅ **核心** | ChatEDA / ORFS-Agent 解析 backend 报告中的 negative slack 触发 ECO；ArchPower 做 fast power 估计；PPA 预测是这个阶段的硬指标 |
| **⑥ 形式验证** | ✅ **核心** | FVDebug 用 LLM + FV tool 做反推理（causal graphs from failure traces）；SANGAM 用 MCTS 生成 SystemVerilog Assertions；VeriMaAS 把 FV solvers 当 Grounding Mechanism |
| ⑦ 布局（Placement） | ✅ **核心** | AlphaChip RL pretraining + MaskPlace CNN canvas + DiffusionPlace conditional denoising + TransPlace GNN transfer——这是 backend solver 范式的主战场 |
| ⑧ 布线规划（Routing Planning） | ⚠️ **间接相关** | routing 拥塞预测（RouteNet CNN）属于 L2 copilot 范畴；agent 直接产出 Tcl 编排布线工具 |
| **⑨ 全局布线（Global Routing）** | ✅ **核心** | CodeNotCanvas 用 multi-agent negotiation 生成 Tcl；ChatEDA 把 routing 作为 Step B 编排 |
| ⑩ 详细布线（Detailed Routing） | ⚠️ **间接相关** | detailed routing 输出 hot spot 是 ECO 触发器；不直接被综述讨论 |
| ⑪ 时钟树综合（CTS） | ❌ | 综述未专门讨论 CTS agent |
| **⑫ ECO / 后优化** | ✅ **核心** | ChatEDA / REvolution 触发 ECO（修改 RTL 解决 timing violation）；这是 Cross-Stage Closure 的核心 |
| ⑬ 签核（Signoff） | ⚠️ **目标但未达成** | 综述明确指出"no LLM-driven agent has demonstrated complete human-free tape-out of industrial chip"——signoff 是 Sim-to-Silicon Gap 终点 |
| ⑭-⑰ 流片→制造→封装→芯片 | ❌ | 纯算法 / 软件层工作，无 tape-out |

**覆盖率：6/17 核心 + 3/17 间接相关。** AgenticEDA 综述横跨前端 RTL 生成与验证 + 后端 placement 与 routing + signoff-aware 闭环——是 **跨 stage EDA 框架** 的代表性 survey。

> ⚠️ 综述论文与同资料包其他论文的根本区别：
> - [ChipMATE](../ChipMATE/论文深度讲解.md) / [RTLCoder](../RTLCoder/论文深度讲解.md) / [VerilogCoder](../VerilogCoder/论文深度讲解.md) 等是 **单点工作的深讲解**——集中解决 "NL → RTL" 或 "RTL 修复"
> - **AgenticEDA 综述是横向 survey**——把 40+ 个工作的方法、范式、阶段、能力做 **统一 mapping**，给读者一个全局地图

## 3. 输入 / 输出

### 3.1 输入

综述论文本身无单一输入或代码仓库，但它 **组织** 三大类被调研工作的输入：

**(a) Frontend 工作输入（Verilog / Spec / Testbench）**

```verilog
// 典型 VerilogEval 输入（来自 [VerilogCoder 综述条目]）
module top_module (
    input  [7:0] a, b, c, d,
    output [7:0] out
);
    // 任务：构建 4-input mux
endmodule
```

NL spec 输入：

```text
Prompt: Design a 4-to-1 multiplexer. The output is selected by sel[1:0]
from {a, b, c, d}. When sel=00 select a, sel=01 select b, sel=10
select c, sel=11 select d. The output should be registered on rising
edge of clk with synchronous reset.
```

**(b) Backend 工作输入（netlist + 容量约束 / placement）**

```
# ISPD / ICCAD placement input 典型
.kpl  # kernel placement file: cell positions
.cap  # capacity per GCell
.net  # pin access + slack
.def  # DEF format（LEF/DEF standard）
.lib  # Liberty timing library
.lef  # library exchange format
```

**(c) Verification / Debug 工作输入（RTL + cex trace + log）**

```text
# FVDebug 输入
- RTL 源文件
- cex (counterexample) trace from FV solver
- 失败 trace text dump
- 输出：fix/patch diff
```

**(d) Foundation Model 训练数据输入**

```text
- ChipNeMo: NVIDIA 内部 chip corpus + Design Document + Bug Report
- SynC-LLM: hierarchical generation of synthetic Verilog
- CraftRTL: correct-by-construction 非文本表示 + targeted code repair
- DeepGate4: 大规模 netlist (sub-linear memory transformer)
- ArchPower: architecture-level power modeling CPU 设计
```

### 3.2 中间产物

**(a) Perception 层产物：共享 latent embedding**

```
Netlist (DAG) ---[Graph Encoder]---\
                                     \
HDL Text ----------[Text Encoder]----> Shared Latent Space
                                     /
Layout (PNG/GDS) --[Vision Encoder]-/
```

**(b) Cognition 层产物：hierarchical plan + reasoning trace**

```text
Plan tree:
├── Goal: 修复 hold violation at net_42
│   ├── Sub-goal 1: 找到 net_42 的物理路径
│   ├── Sub-goal 2: 评估 buffer insertion 候选位置
│   └── Sub-goal 3: 调用 Tcl script insert_buffer net_42 pos=[x,y]
├── Rollback: 若 DRC 校验失败 → 回退到上一个 checkpoint
└── Reflection: 写入 KG 节点记录本次 action 的 Δ outcome
```

**(c) Action 层产物：可执行的 NL2SL script（Tcl / Python / SDC）**

```tcl
# ChatEDA 风格 Tcl 输出
set_db design_stage place_opt
add_buffer -net net_42 -location [list 100.5 200.3]
route_detail -incremental
report_timing -path_type summary -max_slack 0.0
```

## 4. 方法与架构

### 4.1 整体 Taxonomy 框架

综述提出 **三大切片轴**，覆盖所有 40+ 工作的分析维度：

```text
                                Agentic EDA 分析透镜
   ════════════════════════════════════════════════════════════════
                                                     
   切轴1: 自主性等级 (L0-L4)
   ┌──────────────────────────────────────────────────────────────┐
   │ L0  Manual               手工 layout (pre-1980s)             │
   │ L1  Algorithmic          模拟退火 + 逻辑综合 (1980s-2018)    │
   │ L2  AI Copilot           预测但不执行 (2018-2023)             │
   │ L3  Agentic Orchestration 自主闭环 (2024+)                   │
   │ L4  Self-Driving         完整 RTL-to-GDSII (未来)             │
   └──────────────────────────────────────────────────────────────┘
                                                     
   切轴2: 三层认知栈 (Perception-Cognition-Action)
   ┌──────────────────────────────────────────────────────────────┐
   │ Perception   多模态对齐 (CircuitFusion / GenEDA / DeepGate4) │
   │ Cognition    神经符号规划 (MCTS / Tree-of-Thoughts / SI-CoT)│
   │ Action       确定性工具执行 (Tcl / Python / NL2SL)          │
   └──────────────────────────────────────────────────────────────┘
                                                     
   切轴3: 三类方法范式 (PRT / SFT / MAS)
   ┌──────────────────────────────────────────────────────────────┐
   │ PRT   Prompt-Based Reasoning    training-free               │
   │ SFT   Fine-Tuned Specialization 训练驱（RLHF / 大规模预训） │
   │ MAS   Multi-Agent Collaboration 系统级多 agent 协商          │
   └──────────────────────────────────────────────────────────────┘
```

### 4.2 模块 1：L0-L4 自主性分级（类比 SAE J3016）

| 等级 | 名称 | 角色分配 | 代表工作 |
|:---:|------|---------|----------|
| **L0** | Manual / CAD Era | Human 完全手工 layout | 1980s 前手画版图 |
| **L1** | Tool-Assisted Human Design | Human 定义 flow + Tool 求解 sub-problem | 模拟退火 placement（Kirkpatrick 1983）、逻辑综合（Brayton 1984）、SPICE 仿真 |
| **L2** | AI-Assisted Copilots | Human drives + AI predicts | RouteNet 拥塞预测（Xie 2018）、Bayesian Optimization 调参、MaskPlace CNN placement |
| **L3** | Agentic EDA Orchestration | AI drives + Human monitors | Chip-Chat conversational（Blocklove 2023）、ChatEDA multi-agent（He 2024, 98.3% success）、ORFS-Agent tool-using（Ghose 2025）、REvolution evolutionary agent |
| **L4** | Self-Driving Design 4.0 | AI drives + Human defines intent | 尚未实现——综述预测 5+ 年达到，需要 certified guarantees + Sim-to-Real benchmarks 桥接 |

**关键 L3→L4 gap**：L3 仍需 Human monitor；L4 需要"system autonomously navigates full RTL-to-GDSII treating entire toolchain as differentiable or black-box environment to optimize for PPA with zero human intervention"（Thakur et al., 2023）。

**关键 L2→L3 gap**：L2 Agent 只 predict 不 execute；L3 Agent 自主 decompose tasks + generate scripts + interact with tools + close loop（autonomously fix syntax errors or hold violations）。ChatEDA 98.3% 任务规划成功率是 L3 的代表证据。

### 4.3 模块 2：三层认知栈（Perception - Cognition - Action）

#### 4.3.1 Perception 层：多模态对齐

**目标**：把 Netlist（Graph）、HDL（Text）、Layout（Geometry）三种异构数据统一进 shared latent space。

**代表工作**：
- **CircuitFusion** [Fang 2025b]：跨模态 contrastive learning 把 HDL 代码和 netlist 嵌入对齐
- **GenEDA** [Fang 2025a]：跨模态 encoder-decoder 对齐做 generative netlist functional reasoning
- **DeepGate4** [Zheng 2025]：sub-linear memory graph transformer 处理超大规模 netlist

**Granularity Mismatch 问题**：HDL 是 hierarchical（模块化）描述而 netlist 是 flattened DAG。CircuitFusion 用 hierarchical-aware pooling 解决。

**Data Scarcity 缓解**：
- SynC-LLM：用 hierarchical generation 合 成大规模 Verilog
- CraftRTL：correct-by-construction 非文本表示 + targeted code repair 提升生成质量

#### 4.3.2 Cognition 层：神经符号规划与推理

**目标**：解决"概率 LLM vs 确定性 physics"的根本张力。LLM 提供 Exploration（非凸搜索空间导航），SAT/SMT/SPICE 提供 Exploitation & Verification（物理约束）。

**代表机制**：
- **Hierarchical Planning**：MAS 演化为 Cooperative Games——"Manager" agent 仲裁 specialized agents 解决 deadlock；"Critic" 用形式验证 prune 无效分支
- **Long-Horizon Consistency**：用 Hierarchical Memory Systems 或 Constraint Databases 防 "Design Intent Drift"（多周/多月 flow 中跨阶段意图偏移）
- **Domain-Specific RAG**：不仅检索 documentation，还检索 **structured design rules（DRC）+ historical error logs** 来引导推理
- **Type II Planner（vs Type I Reactionary Retry）**：从"盲目 log-fixing"升级到用 Tree-of-Thoughts lookahead 模拟执行结果再决定动作

**代表工作**：Saarthi（formal verification engineer agent）、SANGAM（MCTS for SVA generation）、VeriMaAS（FV as grounding）、ChatEDA（multi-agent orchestration）。

#### 4.3.3 Action 层：确定性工具执行

**目标**：把推理结果转成可执行的 NL2SL（Natural Language → Shell Language）脚本，**LLM never 输出最终 chip** ——LLM 输出 candidate scripts，必须过 deterministic compiler/timer/DRC engine 校验。

**Safety and Grounding 机制**：
- 所有 agent-generated scripts 在沙盒中执行
- 检查点（checkpoint-based rollback）—— 一旦 destructive hallucination detected（删错 file / 错改 netlist）→ 回退到上一个 valid checkpoint
- 物理约束 verification 在执行后 running

**代表工作**：CodeNotCanvas（Yang & Ren 2025）—— 多 agent layout generation 用 Tcl 作 action。ChatEDA—— 编排完整 EDA tool stack。

### 4.4 模块 3：三方法范式（PRT / SFT / MAS）

#### 4.4.1 PRT: Prompt-Based Reasoning（ICL / RAG）

- 训练自由（training-free）
- 用 general-purpose LLM（GPT-4o, Llama-3.3）通过 ReAct prompting 配合 tool feedback refine scripts
- 优势：灵活、便宜、起步低
- 劣势：surface-level adaptation，深度物理知识弱
- 代表：ChatEDA、AutoChip、Chip-Chat、Saarthi、FVDebug、DRC-Coder、SoCureLLM

#### 4.4.2 SFT: Fine-Tuned Specialization（训练驱动）

- 用 Supervised Fine-Tuning + RLHF + 大规模 pretraining 把 domain 物理 internalized
- 代表：**AlphaChip**（大规模 chip placement 预训练获得 "layout intuition"）
- 优势：高性能
- 劣势：高训练成本、难 transfer 到其他 stage
- 代表工作：AlphaChip（RL）、VeriGen（Verilog SFT）、TrojanStego（steganography SFT）、DRC-Coder（DRC SFT）、ChipNeMo（DAPT + Tokenizer）

#### 4.4.3 MAS: Multi-Agent Collaboration（系统级多 agent）

- 多 agent 系统通过复杂 planning 对齐 intent
- 每个 agent 专门化（"Manager" / "Critic" / "Frontend" / "Backend"）
- 优势：解 long-horizon task、迭代 tool use
- 劣势：稳定性差、inference 慢
- 代表：ChatEDA、ArchPower（多 agent 协商 architectural decisions）、SoCureLLM（red-teaming agent）、ORFS-Agent、CodeNotCanvas

### 4.9 模块 5：Challenges 与 Future Direction（Sec. 6）

**The Grand Challenge: Sim-to-Silicon Gap**

- 关键批评：当前 Agentic EDA 缺乏 Ground Truth 通过实际 tape-out 验证
- Silicon-Proven Solvers（如 AlphaChip）已 industrial tape-out
- Agentic Prototypes —— "no LLM-driven autonomous agent has yet demonstrated a complete, human-free tape-out of an industrial chip"

**Future Directions**：

- **Direction I: Technical Grounding（Reliability & Interface）**
  - Constraint Grounding: Neuro-Symbolic Alignment（生成输出被形式验证数学 bounded）
  - Tool Grounding: Semantic EDA Interfaces（APIs exposing internal tool states 作为 structured embeddings 而非 raw text log）
  - Open Agentic EDA Standard（类比 LSP 统一 EDA 接口协议）

- **Direction II: Operational Grounding（Deployment & Economics）**
  - Economic Grounding: 单次 GPT-4o debugging session ~30 USD，但 TTM premium 让 agent 在 critical path 上 24/7 运行成为赢家
  - Wall-clock Efficiency（Time-to-Result）应当与 token cost 共同报告
  - Failure Mode Taxonomy: Deadlooping、Context Loss、Tool Hallucination

- **Visionary Outlook: Recursive Self-Improvement** —— agents 设计下一代训练更强 agents 的 chips

- **Pragmatic Roadmap**:
  - Near-term (1-2 yr): L3 agents 作 "strong copilots" for Tcl generation（human oversight）
  - Mid-term (3-5 yr): autonomous block-level flows（前提 Sim-to-Real benchmark bridging）
  - Long-term (5+ yr): full-chip agentic architecture exploration（需要 certified guarantees）

## 5. 关键定义（综述无显式公式，但有 "formal" 定义）

### 5.1 L3 Agentic EDA 定义

$$
\text{Agentic EDA} := (\mathcal{A}, \mathcal{M}, \mathcal{E}, \mathcal{T})
$$

其中：
- $\mathcal{A}$：LLM agent（probabilistic policy $\pi(a|s)$）
- $\mathcal{M}$：Memory（含 Hierarchical Memory System / Constraint DB）
- $\mathcal{E}$：EDA tool environment（deterministic, sandboxed）
- $\mathcal{T}$：Tool API（NL2SL interface）

**综述未给出该公式**——此为对 "L3: AI drives tasks, Human monitors" 描述的形式化。**论文中给出的核心定义**是"Neuro-Symbolic Handshake"（§2.3）：

$$
\mathbf{LLM} = \text{Exploration}(s \rightarrow a) \quad \mathbf{EDA\ Tool} = \text{Exploitation}(a \rightarrow \text{verify})
$$

最终 chip 输出 **not probabilistic**——是 probabilistic search grounded in deterministic verifier。

### 5.2 Productivity Gap（Markov 2014）

晶体管数随 Moore 定律指数增长而 designer 数线性增长：

$$
\frac{d(\text{transistors})}{dt} \sim 2^{t/2yr} \quad \frac{d(\text{designers})}{dt} \sim O(1)
$$

导致每代 designer 需负责 ~ 2× 复杂度——"Design Productivity Gap"。

### 5.3 Verification 占开发周期比例

$$
f_{\text{verification}} = \frac{T_{\text{verification}}}{T_{\text{total\ cycle}}} \in [60\%, 70\%]
$$

- $T_{\text{verification}}$ 含 simulation / formal / debugging time
- $T_{\text{total\ cycle}}$ 含 RTL + 综合 + P&R + verification

综述声称"verification consumes over 60% of design cycle"。这是 Agentic EDA 的关键 motivation。

### 5.4 Dual-Loop Repair 时间预算

$$
T_{\text{semantic\ loop}} \gg T_{\text{syntactic\ loop}}
$$

其中 syntactic loop 仅调用 iverilog/yosys（秒级），semantic loop 调用 Verilator + waveform dump（分钟级）。Hierarchy 让 agent 先快过滤 syntax 错误，只把可疑 case 推给 semantic loop——coarse-to-fine 策略。

### 5.5 Trust Deficit 量化（综述未给出严格公式）

综述描述"agents are probabilistic and opaque" vs "传统 EDA 算法 (A* search) deterministic and mathematically bounded"。可形式化为：

$$
D_{\text{trust}} = \mathbb{E}_{\pi, s} \left[ \Pr(\text{hallucination}) \cdot \text{DamageCost} \right]
$$

综述未给出具体数值——这是开放问题。

### 5.6 Sim-to-Silicon Gap

$$
\text{Gap} = \text{Industrial\ Tape-out\ Success\ Rate} - \text{Benchmark\ Pass\ Rate}
$$

- Industrial Tape-out Success Rate: 实际硅片工作的概率（极少 LLM-driven 完成）
- Benchmark Pass Rate: VerilogEval 等单元测试 pass@k

综述未量化数值，但指出"agents trained on toy data cannot generalize to industrial scenarios"。

## 6. 训练与实验设置

### 6.1 是否需要训练

综述 **本身不训练任何模型**——它分析 40+ 已发表工作的训练范式。这些工作分为：

| 范式 | 是否训练 | 代表 | 训练数据规模 |
|------|:---:|------|:---:|
| PRT | ❌ | ChatEDA, AutoChip, FVDebug | 0（prompt-only）|
| SFT | ✅ SFT | VeriGen, VerilogCoder | 万 ~ 十万 RTL 样本 |
| RL | ✅ RL | AlphaChip | 数千万 placement rollouts |
| Pretrain | ✅ 大规模 | ChipNeMo, DeepGate4 | 百万级 corpus |
| MAS | ❌（仅 prompt） | CodeNotCanvas, ORFS-Agent, REvolution | 0 |

**关键观察**：综述强调"训练成本 vs 性能"权衡——RL pretrain 贵但 precision 高；PRT 便宜但 depth 浅。

### 6.2 实验设置（综述无单一实验）

各被调研工作实验设置差异巨大：

| 工作 | 训练硬件 | 评估基准 | 评估指标 |
|------|---------|---------|---------|
| VerilogCoder | 4 × A100 | VerilogEval (156 problems) | pass@k, compile rate |
| AlphaChip | 32 × TPUv4 | TPU block placement | wirelength, congestion |
| DiffusionPlace | 8 × V100 | ISPD 2015, ICCAD 2015 | HPWL, congestion, timing |
| ChatEDA | 1 × A100 | 6 designs | task success rate (98.3%) |
| REvolution | 8 × A100 | 7 designs | power ↓ 24.5% |
| ChipNeMo | multi-node | internal NVIDIA corpus | downstream task accuracy |
| DeepGate4 | multi-GPU | OpenABC-D | function accuracy, scalability |

### 6.3 关键综述结论（来自论文 Table 1 + Table 2）

**Frontend VerilogEval Pass Rate Benchmark（综述观察）**：
- GPT-4o: ~63%
- VerilogCoder 修复后: ~75%
- 工业级系统级 benchmark（RTLLM）: 仍显著低于 VerilogEval（说明"Unit-Test Fallacy"）

**Backend PPA Comparison**：
- AlphaChip RL: placement WL ↓ 大量但 transfer 难
- DiffusionPlace: zero-shot transfer 强但缺 precision
- GNN (TransPlace, DeepGate4): scalability 强 + precision 中
- MAS (ChatEDA, CodeNotCanvas): end-to-end 完整但 stability 弱

**ChatEDA 98.3% Success Rate**：是 L3 agent 在 EDA tool orchestration 上最优结果之一。

**REvolution 24.5% Power ↓**：evolutionary agent 在 PPA 优化上的代表性证据。

### 6.4 Future Benchmarks（综述呼吁）

- **System-Level Benchmarks**（RTLLM、ChipNeMo、ChiPBench）—— 取代 Unit-Test Fallacy 的 VerilogEval
- **Sim-to-Silicon Benchmarks** —— 工业级 multi-patterning / electromigration 约束
- **End-to-End PPA Benchmarks**（ChiPBench）—— 取代 pass@k 的端到端衡量

## 7. 创新点（综述论文的贡献）

### 7.1 贡献 1：L0-L4 自主性分级（类比 SAE J3016）

**贡献**：借用自动驾驶 SAE 等级，把 EDA 自主性分解为 L0（手工）、L1（算法）、L2（AI Copilot）、L3（Agentic Orchestration）、L4（Self-Driving）五级，给行业一个共同语言。

**意义**：之前"AI for EDA" 工作分布在不同成熟度，但无统一分级。L0-L4 让 ChatEDA 这种 L3 工作和 RouteNet 这种 L2 工作有了 **可比尺度**。

### 7.2 贡献 2：三层认知栈（Perception-Cognition-Action）

**贡献**：把 agent 系统拆解为 (1) Perception：多模态对齐进 shared latent space；(2) Cognition：神经符号规划；(3) Action：NL2SL 工具执行。三层栈为分析任一 agent 系统提供 **统一透镜**——CircuitFusion / DeepGate4 属 Perception 强；Saarthi / SANGAM 属 Cognition 强；CodeNotCanvas / ChatEDA 属 Action 强。

**意义**：之前 survey（如 Pan 2025）按 "coding / verification / P&R" 横切，本综述按认知栈 **纵切**——两种切法 orthogonal，但纵切更适合工程设计师理解架构选型。

### 7.3 贡献 3：Methodological Taxonomy 三类范式

**贡献**：把已有工作划分为 PRT（training-free）、SFT（训练驱动）、MAS（系统级多 agent）三类。

**意义**：明确每类范式的 trade-off——便宜/浅 vs 贵/深 vs 灵活/不稳。给从业者选型指南。

### 7.4 贡献 4：Problem Taxonomy（Frontend / Backend / Security）

**贡献**：按 EDA 阶段组织——

- **Frontend**：Spec-to-RTL + Dual-Loop Repair + Instruction Alignment
- **Backend**：Neural-Augmented Solvers vs Agent-Centric Orchestrators
- **Foundation & Security**：DAPT、synthetic data、Knowledge Distillation、Trojan detection

每个领域单独深讲，让读者可选择性精读。

### 7.5 贡献 5：Trustworthiness Gap 批判性分析

**贡献**：明确指出"Simulation-Real Gap"——benchmark high pass rate 不等于 industrial success；指出 Sim-to-Silicon Gap 是当前最大瓶颈；呼吁 Industrial-grade Benchmarks + Formal Grounding 把 brittle prototype 转成 resilient engineering system。

**意义**：综述 + 批判——不只是 survey 还有 roadmap，对从业者有指导价值。

### 7.6 贡献 6：Sim-to-Silicon Gap 形式化

**贡献**：明确区分 "Silicon-Proven Solvers"（AlphaChip 已 industrial tape-out）vs "Agentic Prototypes"（no LLM-driven agent has yet demonstrated complete human-free tape-out）。批判当前"agent 工业级"宣传。

**意义**：让 "agent 完成某 K 个 chip" 的宣传话术有 ground truth 基线。

### 9.3 "仿真通过"和"能做成芯片"之间隔着什么

AgenticEDA 综述把这一鸿沟命名为 **Sim-to-Silicon Gap**。具体表现为：

1. **Benchmark 失真**：VerilogEval 等单元测试 pass rate 63-75%，但这些是 module-level "toy data"—— 工业级 SoC 有 multi-clock domain、CDC、power intent、UPF 等 AgenticEDA 当前未涵盖的约束
2. **PDK 失真**：academic agent 用 Sky130 等 open-source PDK，不反映 advanced node (TSMC N3) 的多 patterning、electromigration 等复杂物理
3. **Proxy metric fallacy**：以 wirelength / pass@k 为代理指标，但 PPA + 多模式时序收敛才是真实门槛
4. **L3 → L4 Gap**：L3 仍需 human monitor，工业部署无法接受——需要 L4 full autonomous
5. **没有 tape-out validation**：目前没有 LLM-driven agent 完成过完整 human-free 工业级芯片流片

## 10. 讨论与局限

### 10.1 综述自陈局限

#### 局限 1：分析 40+ 工作但深度有限

综述讨论每个工作 1-2 段，无法像 **单论文 deep-dive** 那样彻底拆解架构细节。读者**不能仅靠综述选型**——需要回到原论文。

#### 局限 2：引用透明度受限

arXiv 截止 2026.02.07 的所有工作都被引用，但综述承认**"the field is now witnessing a necessary transition"**——许多引用是预印本，未经同行评审。

#### 局限 3：缺乏量化对比表

综述提供 Taxonomy 表格（Table 1, 2, 3），但**没有 cross-system benchmark 数字对比**——同一 benchmark 上 ChatEDA 98.3% success rate vs VeriGen pass@1 = X 不能直接对比（任务不同）。

#### 局限 4：未区分 Foundation Model vs Application

综述混合讨论 DeepGate4（circuit representation）和 ChatEDA（agentic orchestration）—— 但前者是 L2 Perception 工具，后者是 L3 Action 框架。两者的 "autonomy level" 完全不同。读者需自行心算。

### 10.2 调研方法局限

#### 问题 1：survey paper 中"powerful"工作 vs "marginal improvement"工作未分级

综述对每个工作都给正面贡献，但**未明确 caveat** 哪些工作的工业采用度低（如学术 prototype 跑一次没复现）。

#### 问题 2：开源 / 闭源分布未明

综述提到 ChipNeMo（NVIDIA 内部数据，未公开）、VerilogCoder（公开）、DeepGate4（公开）—— 但**未对每个工作明确开源状态**。复现者需自行查 GitHub。

#### 问题 3：各工作的"可复现性"未评估

综述未提"每个工作的复现门槛"——这是本资料包的特色（参考 §11）但综述里没有。

### 10.3 本资料包的批判性分析

#### 批判 1：SAE 类比过度简化

L0-L4 类比 SAE 自动驾驶，但 EDA 自主性与自动驾驶有本质差异：

- 自动驾驶的 L1→L2→L3→L4 是**渐进提升**，每级有清晰功能差异
- EDA 自主性更像**多维度**——前端 L3 不代表后端 L3（ChatEDA 后端很强但前端较弱）

类比有助传播，但**降低了精度**。

#### 批判 2：三层认知栈未必 mutually exclusive

一个真实 agent 可能 Perception + Cognition 强同时 Action 弱（Foundation model），或者 Cognition + Action 强同时 Perception 一般（ChatEDA 用 GPT-4o embedding）—— **三层不是孤立维度**。

#### 批判 3：MAS 范式 inference 成本被低估

综述称 MAS 在 long-horizon tasks 上有优势，但**未量化 inference cost**——一次 50 分钟的 agent run 用 GPT-4o 可能 $30+，对比 P&R 工程师时薪 $50/h 优势不显著。

#### 批判 4：Sim-to-Silicon Gap 论述缺乏 actionable 路径

综述说 "lack of industrial-grade benchmarks is primary barrier"—— 但**没说谁该建这些 benchmark**、用什么 PDK、用什么 baseline、什么 reward function。

#### 批判 5：Pretraining 路线（SFT / RL）的可迁移性被高估

AlphaChip 在 TPU block placement 上 pretrain，但**迁移到 GPU 或 CPU block placement 是否 work** 未明确。综述只说"methodological transferability remains valid"，**但 industrial scale 上是否 work 未知**。

#### 批判 6：安全章节偏硬件 trojan 而非 data poisoning

Table 3 详细讨论 Hardware Trojans（LLM 输出恶意 logic），但**未深入讨论 data poisoning**（攻击训练数据让 LLM 学习恶意 patterns）。这是 **模型训练阶段** 的攻击面，综述可加强。

#### 批判 7：未涵盖 analog / mixed-signal

综述末段提 AnalogSeeker + Agent-guided Bayesian Optimization 作为 emerging frontier，但**未深入**。Analog 设计是 EDA 的另一大领域，survey 应有专门章节。

## 12. 一分钟复述版

1. **核心问题**：EDA 行业面临 "Productivity Gap"——晶体管数指数增长但设计师数线性增长，verification 占 60-70% 开发周期；传统 "siloed optimization" 解决单 stage 子问题不解决跨 stage 冲突；2 AI Copilot (L2) 只能预测不执行

2. **方法概述**：综述提出 L0-L4 自主性分级（SAE 类比）、三层认知栈（Perception-Cognition-Action）、三方法范式（PRT/SFT/MAS）三大切轴分析 40+ 工作；Frontend 重点是 dual-loop syntactic-semantic repair（AutoChip inner / VerilogCoder outer）；Backend 重点是 dichotomy: Neural-Augmented Solvers（AlphaChip RL / DiffusionPlace / GNN）vs Agent-Centric Orchestrators（ChatEDA 98.3% / REvolution 24.5% power ↓）；Trustworthiness gap 表 3 详列 model + infrastructure risks

3. **核心数据**：覆盖 40+ 工作，含 ChatEDA 98.3% success rate、REvolution 24.5% power reduction、VerilogCoder AAAI 2025、AlphaChip Nature 2021、CodeNotCanvas ASP-DAC 2025

4. **关键结果**：调研发现 L3 是当前 frontier；L4 (Self-Driving) 未实现——"no LLM-driven autonomous agent has yet demonstrated complete human-free tape-out of industrial chip" 是 Sim-to-Silicon Gap 的核心证据；benchmarks high pass rate 不等于 industrial success；呼吁 Industrial-grade Benchmarks + Formal Grounding 把 brittle prototype 转成 resilient engineering system

5. **最大创新点**：把"AI for EDA"从 "prediction" 认识升级到 "constrained neuro-symbolic optimization"；借用 SAE 分级 + 认知栈纵切 + 范式横切的"三轴切片"分析透镜；批判性指出 Sim-to-Silicon Gap 是当前最大瓶颈

6. **EDA 流程位置**：横向覆盖 — Frontend（①RTL 设计 + ②功能仿真 + ⑥形式验证）+ Backend（⑦布局 + ⑨全局布线 + ⑫ECO）+ Foundation & Security（跨 stage 防御）—— 是少数从 spec 到 tape-out 都讨论的 survey

7. **与同类综述关系**：与 [Pan 2025 ACM TODAES](https://dl.acm.org/doi/10.1145/...) 互补（横切 vs 纵切）；与 [Fang 2025 Circuit Foundation Models](https://arxiv.org/abs/2503.x) 是子集-超集关系（Foundation Models ⊂ Perception 层）；与本资料包其他论文（如 [ChatEDA 论文深度讲解](../ChatEDA/论文深度讲解.md)）是"调研对象 vs deep-dive"关系

8. **局限**：综述无单一代码；分析 40+ 工作但深度有限；SAE 类比过度简化；MAS inference 成本被低估；Sim-to-Silicon Gap 论述缺 actionable 路径；analog/mixed-signal 覆盖不足；data poisoning 风险未深入讨论
