## 一、一句话定位

**GenEDA 是首个将基于图神经网络(GNN)的电路编码器(Circuit Encoder)与基于大语言模型(LLM)的电路解码器(Circuit Decoder)在共享潜空间(Shared Latent Space)中进行跨模态对齐(Cross-Modal Alignment)的统一框架，使其能够反向(从门级网表→高层 RTL 描述)生成电路功能描述、实现细节乃至精确 RTL 代码。**

### 2.1 阶段⑥的"不可逆"特性与 GenEDA 的突破

逻辑综合 (Logic Synthesis) 是数字 IC 设计流中典型的 **信息损失瓶颈**。在从 RTL 走到门级网表的过程中，多个高层语义信息被丢弃或永久改变：

| 损失信息 | 描述 | 影响 |
|---|---|---|
| 变量名/信号名 | `enable_pipe_stage_3` 变成 `n137` | 可读性归零 |
| 注释/语义标签 | 寄存器用途、状态机含义 | LLM 几乎无法理解 |
| 抽象层级 | `if-else` 控制流 → 多路选择器 (MUX) 网络 | 结构不可还原 |
| 算术操作 | `a*b` 被位爆破为 AND/OR 阵列 | 字级算术被拆解为位操作 |
| 字长结构 | `reg[7:0]` 边界在网表中无显式标记 | 字级信息消失 |

正是这种"不可逆"使得 GenEDA 必须借助 **图结构编码器 (NetTAG)** 才能把分散在门与连线中的结构信号重新聚合、提取出与原始 RTL 等价的语义。这也是为什么论文强调 GenEDA 是首个"真正具备生成式网表理解能力"的框架。

## 三、输入输出

### 3.1 任务 1：功能描述生成 (Function Description Generation)

- **输入 (Input)：**
  - 网表文本：Verilog 格式的位爆破门级网表 (`N = .v`)
  - 问题提示 (Question Prompt)：询问接口、目的、功能、约束
  - 网表图结构 (`G_N`)：作为 Graph 模态输入
- **输出 (Output)：** 高层自然语言功能描述文本 (`Spec`)

### 3.2 任务 2：实现细节生成 (Implementation Detail Generation)

- **输入 (Input)：** 同任务 1，但提示询问组合逻辑、时序行为、控制流
- **输出 (Output)：** 分步骤的信号传播与逻辑行为描述

### 3.3 任务 3：算术 RTL 代码生成 (Arithmetic RTL Code Reasoning)

- **输入 (Input)：**
  - 来自 GNN-RE 数据集的算术电路门级网表
  - 提示：要求先推理 word-level 算术功能，再写 RTL
  - (在 Paradigm 2 中) 来自编码器的逐门功能注释 `T_pred`
- **输出 (Output)：** 可综合的 Verilog RTL 代码，使用 word-level 操作符

### 3.4 模态对比

| 模态 | 任务 1&2 | 任务 3 |
|---|---|---|
| Graph (`G_N`) | ✔ 编码器主输入 | ✔ 编码器主输入 |
| Text (Netlist Verilog `T_N`) | ✔ 信号名输入 | ✔ 含门注释输入 |
| Text (Instruction `T_in`) | ✔ Prompt | ✔ Chain-of-Thought Prompt |
| Embedding (`H_g`) | ✔ 通过 connector 注入 LLM | ✘ |
| Gate Prediction (`T_pred`) | ✘ | ✔ 作为 LLM 文本输入 |

## 四、方法与架构

### 4.1 整体框架 (Overview)

GenEDA 框架将 SOTA 网表编码器 **NetTAG** (Fang et al., DAC 2025) `f_enc` 与 LLM 解码器 `f_dec` 在共享潜空间内对齐。论文提出 **两种范式 (Two Paradigms)**，分别适配 **开源可训练 LLM** 与 **商业冻结 LLM**。

### 4.2 范式 1：基于 Embedding 的对齐 (Embedding-Based Alignment, Paradigm 1)

```
  ┌─────────────────────────────────────────────┐    ┌──────────────────────────────────┐
  │            Circuit Netlist (N)              │    │      Text Instruction (T_in)     │
  │  ┌───────────────┐    ┌────────────────┐    │    │  • Instruction Prompt            │
  │  │ Graph G_N     │    │ Netlist Verilog│    │    │  • Signal Names                  │
  │  │ (Text-Attr.)  │    │ Text T_N       │    │    └─────────────┬──────────────────┘
  │  └───────┬───────┘    └────────────────┘    │                  │ tokenize
  │          │                                  │                  ▼
  │          ▼                                  │            ┌──────────┐
  │  ┌────────────────────┐                     │            │  H_t     │  Text Embed.
  │  │ Pretrained Netlist │                     │            │ (Word)   │
  │  │ Encoder f_enc      │                     │            └────┬─────┘
  │  │ (NetTAG)           │                     │                 │
  │  └─────────┬──────────┘                     │                 │
  │            │ N_g  (graph-level embed.)      │                 │
  │            ▼                                │                 │
  │  ┌────────────────────┐                     │                 │
  │  │ Modality Connector│                     │                 │
  │  │ MLP  f_c           │                     │                 │
  │  │ (3-layer: 768→2048 │                     │                 │
  │  │           →4096)   │                     │                 │
  │  └──────────┬──────────┘                     │                 │
  │            │ H_g  (text-alike tokens)       │                 │
  │            ▼                                │                 ▼
  │  ┌───────────────────────────────────────────────────────────────┐
  │  │     LLM Decoder f_dec  (DeepSeek-Coder 1B / 7B, trainable)    │
  │  │                                                               │
  │  │  f_dec( H_g , H_t )  ⇒  Generative Reasoning                  │
  │  └───────────────────────────────────────────────────────────────┘
  │                                       ▼
  │                            ┌──────────────────────────┐
  │                            │ Task 1: Description      │
  │                            │ Task 2: Implementation   │
  │                            │      Details             │
  │                            └──────────────────────────┘
  └─────────────────────────────────────────────┘
```

### 4.3 范式 2：基于预测的对齐 (Prediction-Based Alignment, Paradigm 2)

```
  ┌──────────────────────────────────────────────┐
  │           Circuit Netlist (N)                │
  │  ┌────────────────┐  ┌─────────────────────┐ │
  │  │ Graph G_N      │  │ Netlist Verilog T_N │ │
  │  │ (Text-Attr.)   │  │                     │ │
  │  └────────┬───────┘  └─────────────────────┘ │
  │           ▼                                   │
  │  ┌────────────────────┐                       │
  │  │ Pretrained Netlist │                       │
  │  │ Encoder f_enc      │                       │
  │  │ (NetTAG, frozen)   │                       │
  │  └─────────┬──────────┘                       │
  │            │ N_i  (per-gate embed.)           │
  │            ▼                                  │
  │  ┌────────────────────┐                       │
  │  │ Function Predictor │                       │
  │  │ MLP f_p            │                       │
  │  │ (3-layer, dim 256) │                       │
  │  └─────────┬──────────┘                       │
  │            │ T_pred  (gate function labels)   │
  │            ▼                                  │
  │  ┌─────────────────────────────────────────┐  │
  │  │ Netlist Text + Gate Annotations        │  │
  │  │   e.g. AOI22 adder_U1 ...              │  │
  │  │        NOR3  multiplier_U2 ...         │  │
  │  │        OAI21 comparator_U3 ...         │  │
  │  │        MUX2  controller_U6 ...          │  │
  │  └────────────────┬────────────────────────┘  │
  │                   ▼                           │
  │  ┌─────────────────────────────────────────┐  │
  │  │ Frozen LLM Decoder f_dec                │  │
  │  │ (GPT-4o / DeepSeek-V3)                 │  │
  │  │                                         │  │
  │  │ Chain-of-Thought:                       │  │
  │  │  Step1: Reason word-level arithmetic    │  │
  │  │  Step2: Generate RTL code               │  │
  │  └────────────────┬────────────────────────┘  │
  │                   ▼                           │
  │         ┌─────────────────────────┐           │
  │         │ Task 3:  Exact RTL Code │           │
  │         └─────────────────────────┘           │
  └──────────────────────────────────────────────┘
```

### 4.4 训练流程 (两阶段)

1. **模态对齐预训练 (Pre-training for Modality Alignment)**
   - 编码器 `f_enc` 与解码器 `f_dec` 均 **冻结**
   - 仅训练 connector MLP `f_c` —— 最大化自回归损失
   - 作用：将电路 embedding `H_g` 对齐到 LLM 词嵌入 `H_t`，相当于 LLM 的"电路 tokenizer"

2. **端到端微调 (Fine-tuning End-to-End)**
   - 编码器 `f_enc` 仍 **冻结**
   - connector `f_c` 与 LLM `f_dec` 同时训练
   - 使用 LoRA + DeepSpeed ZeRO

### 4.5.1 Paradigm 1 详细步骤拆解

**Step 0 - 双模态输入构造：** 给定一个门级网表 `N`，同时构造两种模态的表示：
- `G_N` (Text-Attributed Graph)：保留门间连接 + 每门的文本化布尔符号表达式
- `T_N` (Netlist Verilog Text)：仅保留信号名 (signal name)，把结构性细节留给 encoder

**Step 1 - 编码：** `f_enc(G_N) → N_g` (graph-level embedding)。该 embedding 蕴含结构与功能双重信息。

**Step 2 - 模态投影：** `f_c(N_g) → H_g`。3 层 MLP 把 768 维电路 embedding 升到 4096 维，使其与 DeepSeek-Coder 的词嵌入空间同维。

**Step 3 - 文本指令编码：** `T_in` (指令 + 信号名) → tokenize → `H_t` (词嵌入)。

**Step 4 - 拼接生成：** `f_dec(H_g ⊕ H_t)` → 自回归生成规格说明/RTL 描述。

### 4.5.2 Paradigm 2 详细步骤拆解

**Step 0 - 编码器冻结：** NetTAG 编码器 `f_enc` 完全冻结。

**Step 1 - 逐门嵌入：** 对每个门 `i` 提取嵌入 `N_i`。

**Step 2 - 门功能分类：** `f_p(N_i) → y_i ∈ {adder, multiplier, comparator, subtractor, controller}`。

**Step 3 - 文本注释注入：** 把 `y_i` 翻译成 `T_pred` (例如 `Adder`, `Multiplier`)，插入到原网表 Verilog 的对应位置作为注释：

```verilog
AOI22 adder_U1(.A(n0), .B(n1), ...);     // [注释: adder]
NOR3 multiplier_U2(.A(n2), .B(n3), ...);  // [注释: multiplier]
OAI21 comparator_U3(.A(n4), ...);         // [注释: comparator]
MUX2 controller_U6(.S(n10), ...);         // [注释: controller]
```

**Step 4 - CoT 两步推理：** Frozen LLM 接收带注释的网表，按"先推理 word-level 功能、再生成 RTL 代码"的两步 CoT prompt 输出最终 RTL。

### 4.6 关键技术细节

- **指令微调 (Instruction Tuning)：** GenEDA 在 50k 子电路的"多模态指令-响应对"上自回归训练。
- **模态 Connector 的关键作用：** MLP connector 相当于 LLM 的"电路 tokenizer"，把离散电路信号转换为 LLM 可理解的 token-like 序列。
- **两阶段训练策略：** 先对齐(只训练 connector)，再端到端微调(connector + LLM)，避免破坏 LLM 预训练知识。
- **Chain-of-Thought 提示：** Task 3 中 CoT 显式要求"先 word-level 后 bit-level"，避免 LLM 退化为门级网表重写。

### 4.7 两种范式对比

| 维度 | Paradigm 1 (Embedding) | Paradigm 2 (Prediction) |
|---|---|---|
| LLM 状态 | 可训练 (trainable) | 冻结 (frozen) |
| LLM 典型代表 | DeepSeek-Coder 1B/7B | GPT-4o / DeepSeek-V3 |
| 信息粒度 | 粗粒度 graph-level embedding | 细粒度 gate-level textual prediction |
| Connector 类型 | MLP (`768→2048→4096`) | 无显式 connector |
| 输入到 LLM | `H_g + H_t` 拼接 | `T_pred + T_N` 文本 |
| 适配任务 | Task 1, Task 2 (spec 推理) | Task 3 (精确 RTL) |
| 额外技术 | LoRA + 自回归指令微调 | Chain-of-Thought (CoT) |

## 五、关键公式

### 5.1 范式 1 的对齐架构

$f_{dec}(H_g, H_t) \Rightarrow \text{Generative Reasoning}$

$H_g = f_c(N_g), \quad N_g = f_{enc}(G_N)$

其中 `H_g` 与 `H_t` 的维度相同，可直接拼接输入到 `f_dec`。

### 5.2 范式 1 的自回归指令微调目标

$L_{align}^{1} = -\sum_{i=1}^{L} \log p(y_i \mid y_{<i}, G_N)$

- `y_{<i}`：在生成 token `y_i` 之前已生成的所有 token
- `G_N`：输入的网图(由编码器隐式捕获)
- `L`：目标真实文本序列长度

### 5.3 范式 2 的逐门功能预测损失

$L_{align}^{2,pred} = -\sum_{i} y_i \log(f_p(N_i))$

- `y_i`：第 `i` 个门的真实功能类别标签
- `N_i`：编码器为该门生成的嵌入
- 类别共 5 类：`adder / multiplier / comparator / subtractor / controller`

### 5.4 范式 2 的生成过程

$f_{dec}(T_{pred} + T_N) \Rightarrow \text{Generative Reasoning}$

$T_{pred} = f_p(f_{enc}(G_N))$

- $f_{dec}$：LLM 解码器（GPT-4o 或 DeepSeek-V3，冻结）
- $T_{pred}$：逐门功能预测标签（文本化注释，如 "adder", "multiplier"）
- $T_N$：原始网表 Verilog 文本
- $f_p$：门功能预测器 MLP（3 层，dim 256）
- $f_{enc}$：NetTAG 编码器（冻结）
- $G_N$：输入的文本属性图（Text-Attributed Graph）

### 5.5 公式之间的协同关系

公式 (2) 与公式 (3) 是 GenEDA 的两大训练支柱：
- **公式 (2)** 服务于 Paradigm 1：在 token 序列层面做端到端自回归对齐
- **公式 (3)** 服务于 Paradigm 2：在逐门级别做监督分类，为后续文本化注释提供输入

两者共同使"电路图结构信息"能够流入 LLM 解码器，前者走"潜空间通道"，后者走"显式文本通道"。

### 6.7 关键发现

- GenEDA 在所有 NLP 指标上 **显著** 优于通用 LLM (GPT-4o / DeepSeek-V3)
- GPT-Score 增益尤为显著 (Task 1: 0.21→0.62, 即 **3 倍提升**)
- RTLCoder-7B (电路专用 LLM) 在反向任务上甚至 **弱于** 其基础模型 DeepSeek-7B，说明 RTL 前向训练对反向任务有负迁移
- Task 3 中 GenEDA (w. DeepSeek-V3) 将功能通过率从 16% 提升至 69% (**4.3 倍**)

### 6.7.1 Task 1 案例研究 (Fig. 6)

论文给出 GenEDA 在 RISC-V CSR 模块上的功能描述生成对比：
- GenEDA 正确识别"处理 CSR (Control and Status Register) 与 PMP (Physical Memory Protection)"等关键概念
- 输出与 Ground Truth 在"功能描述"段落高度对齐，涵盖 CSR 读写、内存保护配置、地址解码、控制信号生成等
- "约束"段落正确识别时钟和复位信号
- 关键优势：GenEDA 能捕捉"csr_reg_pmp_3_addr"等信号名中的领域语义(这是单纯基于文本的 LLM 难以做到的)

### 6.7.2 Task 3 案例研究 (Fig. 8)

GenEDA 处理一个 4-bit 输入 `a, b`，8-bit 输出 `Result` 的算术电路：
- GenEDA 正确识别三个组件：adder、multiplier、comparator
- 输出 word-level RTL：`assign Result_1 = a + b;` `assign Result_2 = a * b;` `assign Result = n1 ? Result_2 : Result_1;`
- 而 GPT-4o 单独仅能产生 bit-level 表达式 (例如 `assign Result_1[5] = a[1] + b[1] + (a[2] & b[2]);`)，无法还原高层 word-level 操作
- 这一对比清楚展示了 GenEDA 在 Paradigm 2 中"门级功能注释"如何引导 LLM 完成高层语义重建

### 6.8 消融实验

| 实验 | Task 1 GPT-Score | Task 2 GPT-Score | Task 3 Function Rate |
|---|---|---|---|
| **完整 GenEDA (Paradigm 1)** | **0.62** | **0.51** | — |
| 移除对齐 (仅 SFT) | 0.32 | 0.21 | — |
| **完整 GenEDA (Paradigm 2)** | — | — | **69%** |
| 替换为弱编码器 GNN-RE (acc 83%) | — | — | 40% |

> 结论：编码器-解码器对齐是关键，且编码器质量 (NetTAG 97% vs GNN-RE 83%) 直接决定下游生成质量。

### 6.8.1 消融实验的具体解读

**实验 1：移除对齐 (SFT w/o encoder alignment)**
- 仅对 LLM 做监督微调 (使用相同的 prompt 与标签)，不注入电路 embedding
- Task 1 GPT-Score 从 0.62 跌至 0.32 (约 -48%)
- Task 2 GPT-Score 从 0.51 跌至 0.21 (约 -59%)
- 证明"对齐"是不可替代的模块，而非简单的 SFT 能替代

**实验 2：替换为弱编码器 (Less effective encoder)**
- 将 NetTAG (97% 分类精度) 替换为 GNN-RE (83% 分类精度)
- Task 3 Function Pass Rate 从 69% 跌至 40% (约 -42%)
- 证明编码器质量具有"放大效应"：下游生成任务的精度 = f(编码器精度) × g(LLM 能力)

## 七、创新点

1. **首个跨模态编码器-解码器对齐框架 (First-of-its-kind)：** 提出统一框架，将 GNN 类电路编码器与 LLM 类电路解码器映射到同一共享潜空间。

2. **双范式设计 (Two Paradigm Design)：** 同一框架下支持
   - 范式 1：基于 embedding 的对齐 (适配开源可训练 LLM)
   - 范式 2：基于预测的对齐 (适配商业冻结 LLM)
   实现生态全覆盖。

3. **首个生成式网表基础模型 (Generative Netlist Foundation Model)：** 让 LLM 真正具备对"位爆破 (bit-blasted)"低层级门级网表的生成式推理能力，突破过去"逐门分类"的限制。

4. **三个全新生成式网表功能推理任务 (Three New Tasks)：**
   - Task 1: Function Description Generation
   - Task 2: Implementation Detail Generation
   - Task 3: Arithmetic RTL Code Reasoning
   突破传统"门功能分类"上升到"全电路功能生成"。

5. **公开基准 (Open Benchmarks)：** 释放 ITC99/OpenCores/Chipyard/VexRiscv + GNN-RE 的反向任务基准数据，鼓励后续研究。

6. **验证 SOTA LLM 性能大幅提升：** 实验证明 GenEDA 在所有三个任务上显著提升 GPT-4o / DeepSeek-V3 的表现。

## 九、芯片流程关系

### 9.1 数字 IC 标准设计流程 (正向 VLSI Flow)

```
Spec  →  RTL Code  →  [Synthesis]  →  Gate-Level Netlist  →  [P&R]  →  Layout  →  Tape-out
                                  ↑                                                  ↑
                       (Synthesis 不可逆！)                              (Layout 不可逆！)
                                  ↓                                                  ↓
                       丢失：变量名、注释、抽象层级                  丢失：高层结构意图
```

### 9.2 GenEDA 在流程中的位置

GenEDA 解决 **Synthesis 不可逆** 的根本痛点：

| 阶段 | 信息量 | 可读性 | GenEDA 贡献 |
|---|---|---|---|
| Spec | 高 | 高 (人可读) | — |
| RTL Code | 高 | 高 (人可读) | — |
| Gate-Level Netlist | 低 | 低 (位爆破、信号名随机化) | **GenEDA 重建高层语义** |
| Layout | 最低 | 最低 (几何坐标) | 未来工作 |

### 9.3 与现有工作的"位置"对比

| 工作 | 阶段 | 方向 | 模态 |
|---|---|---|---|
| DeepGate, DeepGate2, DeepGate3 | 网表 | 预测 | Graph |
| CircuitFusion | RTL | 预测 | Graph + Text |
| MGVGA | AIG | 预测 | Graph + Text |
| NetTAG | Netlist | 预测 | Graph + Text (多模态) |
| RTLCoder, ChipGPT | Spec → RTL | 生成 (前向) | Text |
| HDLDebugger | RTL debug | 生成 (前向) | Text |
| AssertLLM | Spec → Assertion | 生成 (前向) | Text |
| DeepRTL | RTL ↔ Spec | 生成 (双向) | Text (T5) |
| **GenEDA (本文)** | **Netlist → Spec/RTL** | **生成 (反向)** | **Graph + Text 跨模态** |

### 9.4 实际应用场景

1. **功能验证 (Functional Verification)：** 把低层网表翻译回 RTL，等价性验证更可扩展
2. **数据通路优化 (Datapath Optimization)：** 在加载到 EDA 工具前，先识别设计的数据通路/控制逻辑，选择针对性的优化策略
3. **恶意硬件检测 (Hardware Trojan Detection)：** 分析网表识别异常/未授权的功能行为

### 9.5 Synthesis 不可逆性的深入剖析

逻辑综合(Logic Synthesis)将 RTL 描述转换为门级网表，本质上是"信息压缩"过程：

**1. 命名信息丢失**
- RTL 中的信号名携带丰富的领域语义，例如 `enable_pipe_stage_3`、`fifo_full_flag`
- 综合后变成 `n137`、`net_42` 之类的无意义名字
- GenEDA 通过 NetTAG 在 Text-Attributed Graph 中**间接保留**门类型(AOI22、OAI21 等)的语义

**2. 抽象层级降维**
- RTL 中的 `if-else` 控制流被综合为多路选择器(MUX)网络
- 算术表达式 `a*b` 被位爆破为 AND 阵列
- GenEDA 利用 GNN 在图空间聚合这些分散的"位级门"为"字级功能"

**3. 注释与文档剥离**
- RTL 中的 `// 注释` 不会进入网表
- GenEDA 通过 LLM 的预训练知识隐式补充这些语义

**4. 时序意图模糊**
- RTL 中的 `always @(posedge clk)` 触发器在网表中只是 FF 实例
- GenEDA 通过结构(FF 之间、FF 与组合逻辑之间的连接)推断时序意图

## 十、讨论局限

### 10.1 论文自陈局限

1. **任务范围聚焦算术电路：** Task 3 目前仅覆盖 9 个算术设计 (源自 GNN-RE)，非算术电路 (如复杂控制逻辑、I/O 控制器) 的 RTL 重生成尚未充分验证。

2. **基准规模有限：** Task 1 & 2 的测试集仅 400 个子电路，规模相对小。

3. **Ground-truth 依赖 LLM 生成：** 由于真实世界的 RTL specification 极少，论文使用 GPT-4o 生成 ground-truth specification 并经人工核验，可能引入偏置。

4. **编码器质量瓶颈：** Paradigm 2 严重依赖编码器的逐门分类精度 (NetTAG 97%)，若换用弱编码器，功能通过率从 69% 降至 40%。

5. **训练资源：** 8 张 A800 80G 训练，复现门槛较高。

### 10.2 未解决问题 / 未来方向

1. **扩展到 RTL 与布局阶段：** 论文第七节指出，可将同一对齐框架应用到 RTL 级 (结构感知生成) 与布局级 (image ↔ layout 跨模态)。

2. **更复杂的 connector：** 论文自承当前 MLP 较简单，未来可探索 Q-Former [49, 50]、Cross-Attention 等更复杂的模态连接器。

3. **更大规模 LLM 解码器：** GenEDA-1B/7B 表明规模仍有提升空间。

4. **工业级电路扩展：** 当前 benchmark 来自学术开源 RTL；真实工业级设计(完整 SoC、复杂流水线)的可扩展性待验证。

5. **环路闭合 (Closed-loop Verification)：** GenEDA 输出 RTL 后，如何与原网表做形式等价性检查，构成完整"反向工程 + 验证"流水线。

### 10.3 与同领域工作的横向对比与隐含局限

GenEDA 并非"万能"，其能力受制于多个维度的耦合：

**1. 编码器模态锁定**
- 当前 GenEDA 依赖 NetTAG (处理 AIG + 文本)，但 NetTAG 不能直接处理包含模拟模块、I/O 单元的混合网表
- 未来若将 GenEDA 扩展到混合信号/射频电路，需先有相应编码器

**2. 解码器上下文窗口**
- 对于大型设计(百万门级 SoC)，即使 Paradigm 2 的"门注释"也无法装入 GPT-4o 的上下文窗口
- 需要分层/分块推理策略，论文未涉及

**3. 评估指标的可信度**
- GPT-Score 本身依赖 LLM 评判，与 ground-truth spec 的"循环依赖"风险存在
- BLEU/ROUGE 对长文本语义不敏感

**4. 训练分布与真实分布的偏差**
- 训练数据来自学术开源 RTL，与工业 IP (ARM Cortex、x86 等) 的代码风格差异显著
- 论文未在工业级设计上做迁移实验

**5. 计算效率问题**
- Paradigm 2 中每次推理都需先跑 NetTAG 编码器 + 门功能预测 + 冻结 LLM 调用，端到端延迟可能超过传统 EDA 工具
- 工业落地需考虑吞吐

- **LLM API：** OpenAI GPT-4o + DeepSeek-V3 (按调用付费)

## 十二、一分钟复述

> **GenEDA = 跨模态编码器-解码器对齐 + 网表生成式功能推理。**
>
> 传统电路基础模型只有两类 —— 编码器(GNN)做预测、解码器(LLM)做生成 —— 两者各做各的，潜空间不互通。GenEDA 提出"第一种"统一框架：用 NetTAG 当编码器，配 DeepSeek-Coder / GPT-4o / DeepSeek-V3 当解码器，提出 **Embedding-Based** (开源 LLM) 与 **Prediction-Based** (冻结 LLM) 两种对齐范式，把电路 graph embedding 通过 MLP connector 注入到 LLM 的文本 embedding 空间(范式 1)，或把编码器生成的逐门功能注释作为文本提示喂给冻结 LLM(范式 2)，从而把 LLM 的生成能力扩展到"位爆破门级网表"上。
>
> 基于此，论文首创 **三个反向生成任务**：从网表生成功能描述 (Task 1)、实现细节 (Task 2)、乃至算术 RTL 代码 (Task 3)。实验表明 GenEDA-7B 在 Task 1/2 上 GPT-Score 从 0.21 提到 0.62 (**3 倍提升**)，GenEDA + DeepSeek-V3 在 Task 3 上功能通过率从 16% 提到 69% (**4.3 倍提升**)，且消融证明了对齐与编码器质量都不可或缺。
>
> 它不仅把"反向翻译"从梦想到落地，还把对齐范式扩展到 RTL 级、布局级的可能路径全部勾勒出来，是 EDA 基础模型走向"统一多模态"的奠基之作。

### 12.1 三句话技术总结

1. **架构核心：** NetTAG (编码器) + MLP/CoT (connector) + DeepSeek-Coder/GPT-4o/DeepSeek-V3 (解码器)
2. **范式创新：** Paradigm 1 (embedding 对齐，可训练 LLM) + Paradigm 2 (prediction 对齐，冻结 LLM)
3. **任务创新：** Task 1 (Function Description) + Task 2 (Implementation Details) + Task 3 (Arithmetic RTL)

### 12.2 三句话实验结论

1. **Task 1&2：** GenEDA-7B GPT-Score 从 0.21→0.62 (3×)，BLEU 从 5→14 (近 3×)
2. **Task 3：** GenEDA + DeepSeek-V3 Function Rate 从 16%→69% (4.3×)，Pass@5 达 78%
3. **消融：** 对齐贡献最大(-48%~59% GPT-Score)，编码器质量次之(-42% Function Rate)

### 12.3 三句话应用展望

1. **验证加速：** 网表→RTL 反向工程 + 等价性检查流水线
2. **安全检测：** 识别硬件木马与未授权功能
3. **流程扩展：** RTL 级(结构感知生成)、布局级(image→macro placement) 跨模态对齐
