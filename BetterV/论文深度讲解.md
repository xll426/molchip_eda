## 一、一句话定位

BetterV 是首个把"判别器引导的可控文本生成"思想引入电子设计自动化（Electronic Design Automation, EDA）下游优化的 Verilog 生成框架：通过将开源 6.7B/7B 的代码大语言模型（Large Language Model, LLM）在自构造的 Verilog↔C 配对数据上进行领域特定指令微调（domain-specific instruction tuning），并训练一个生成式判别器（generative discriminator），在解码阶段以加权 Bayes 准则引导 LLM 直接产出对综合（AIG (And-Inverter Graph), 与-反相图）节点数更少与形式验证（SAT (Boolean Satisfiability), 布尔可满足性）求解时间更短的 Verilog 实现，从而在 VerilogEval 上以 7B 规模超越 GPT (Generative Pre-trained Transformer) -4。

## 三、输入输出

### 3.1 输入

- 自然语言任务描述（problem description）
- Verilog 模块头（module head），包含 `module` 名、port 列表（input/output）、reg/wire 声明
- （消融/分析时）参考实现 `Reference Verilog`，用于：
  - 形式等价性判别（Yosys `eqy`）
  - 语法正确性（Yosys `prep`）
  - 综合后 AIG 节点比较（Yosys `proc; aigmap; stat`）
  - SAT 求解时间比较（Yosys `hierarchy; proc; opt; sat -verify -seq 100 -tempinduct -prove-asserts`）

### 3.2 输出

- 一段完整的 Verilog（或 SystemVerilog）模块实现：
  - 通过 `endmodule` 闭合
  - 通过 Yosys 语法检查（syntactic correctness）
  - 通过单元测试 / 等价性检查（functional correctness）
  - 与参考实现相比，AIG 节点数显著降低（synthesis optimization）
  - 与参考实现相比，SAT 求解时间显著降低（verification runtime optimization）

### 3.3 训练数据来源（流水线输入）

BetterV 以"自动采集 + 自动处理 + 自动增强"的方式构造训练集，不再额外依赖人工标注的问题—答案对。详细的数据源、过滤规则、V2C 翻译与 Definition-Body 拆分等具体步骤见 §4.2 与 §4.3；评测侧的 pass@k 度量在 §3.4 给出。

为与 §4 配合，这里只列出三类数据来源：

- **抓取的数据池**：GitHub 上开源 Verilog / SystemVerilog 仓库（许可证允许修改与分发）。
- **二次处理得到的配对样本**：用 V2C 工具把 Verilog 转写为等价 C 程序；把 Verilog module 拆分为"头（module 头 + IO 声明）"与"body"。
- **EDA 过滤后的增强样本**：用 instruct-tuned LLM 在高温度下补全 module 头，由 EDA 工具筛除语法错误样本。

### 3.4 评测基准与指标

- 数据集：VerilogEval（Liu et al. 2023b），含 machine-generated 与 human-crafted 两个子集
- 指标：pass@k 无偏估计

$$
pass@k := E_{\text{problems}}\left[1 - \frac{\binom{n-c}{k}}{\binom{n}{k}}\right]
$$

其中 $n$ 为每题生成的总样本数，$c$ 为通过单元测试的样本数，$k$ 为从中抽取的样本数；每题生成 $n$ 个样本，$k$ 个中只要存在 1 个通过单元测试即算通过。

### 3.5 主要对照模型

GPT-3.5、GPT-4、CodeLlama-7B-Instruct、DeepSeek-Coder-6.7b-Instruct、CodeQwen1.5-7B-Chat、BetterV-CodeLlama、BetterV-DeepSeek、BetterV-CodeQwen、ChipNeMo、Thakur et al.、VerilogEval（基线）、RTLCoder-Mistral、RTLCoder-DeepSeek。

### 4.1 框架总览（Section 3.1）

- 第一步：从 GitHub Verilog 出发构造 customized dataset（Section 3.2）
- 第二步：在 customized dataset 上做 domain-specific instruct-tuning（Section 3.3）
- 第三步：基于（可能是增强后的）数据训练生成式判别器（Section 3.5）
- 第四步：在 decoding 阶段用 Bayes rule 加权，引导 LLM 偏向期望方向

### 4.2 数据处理（Section 3.2）

- 参考 Dehaerne 等人的做法抓取 GitHub 上 Verilog / SystemVerilog 仓库
- 强制要求许可证允许修改与分发
- 过滤 auto-generated 文件 / 非宽松许可文件 / 过短 / 过长
- 用正则抽取 module 与 function
- 用 tokenizer 的 token 数过滤超过最大长度的内容（理由：超长内容会被截断，含义残缺）
- 过滤有语法错误的样本

### 4.3 两条处理路线

#### 路线 A：Code Knowledge Transfer（Code⇄Verilog 对齐）

- 用 V2C 工具把 Verilog 翻译成 C
- 翻译结果不超最大 token 数才追加到数据集中
- 这样做的动机：Verilog 语料稀缺，但 C 在 LLM 预训练语料中极为丰富；通过 C⇄Verilog 双向翻译任务，LLM 能"借"已学到的 C 语言知识来理解 Verilog

#### 路线 B：Definition-Body Split（定义—Body 拆分）

- 把每个 module 拆为头部（module 头 + IO 声明）和 body
- 头部当作 instruct-tuning 的输入、body 当作目标输出（Verilog Autocompletion）
- 这样在 instruct-tuning 时不再额外加入自然语言描述，把"实现"本身当作功能性描述
- 最终得到的定制数据 = { Verilog-C pairs } ∪ { Verilog definition-body pairs }

### 4.4 域特定 Instruct-Tuning（Section 3.3）

两类指令：

- Task A: Code Knowledge Transfer
  - Instruction："把下面 Verilog 翻译成 C 程序" → Answer：C 代码
  - Instruction："把下面 C 程序翻译成 Verilog 模块" → Answer：Verilog
- Task B: Verilog Autocompletion
  - Instruction：Verilog module 头（端口列表）→ Answer：完整 module body（含 `endmodule`）

训练目标遵循 auto-regressive 因式分解（Equation 1、2）：

LLM 用参数 $\theta$ 预测序列概率，对数据集 $D$ 最小化负对数似然（NLL, Negative Log-Likelihood）：

$$
L = -\frac{1}{|D|} \sum_{i=1}^{|D|} \frac{1}{n} \sum_{t=1}^{n} \log p_\theta(x_t^i | x_{<t}^i)
$$

其中 $|D|$ 为训练序列总数，$n$ 为每条序列的长度，$x_t^i$ 表示第 $i$ 条序列的第 $t$ 个 token，$x_{<t}^i$ 为其前缀。

论文图 2 给出 d_latch 例子用以示意；其中"Verilog⇆C 对齐"对应左边示例，"Verilog Autocompletion"对应右边示例。

### 4.5 数据增强（Section 3.4）

#### 4.5.1 对 instruct-tuning 的数据增强

- 收集阶段已经得到一批 module 头
- 用 instruct-tuned LLM 在高 temperature 下做 module 补全，得到多样化样本
- 用 EDA 工具做语法正确性过滤
- 把通过过滤的合成样本追加到数据集中（提升鲁棒性、泛化、并强化生成"语法正确 Verilog"的能力）

#### 4.5.2 对判别器训练的数据准备

- 数据标签分两类：
  - 绝对正确/错误（如语法 / 行为等价）→ 直接给 desired / undesired 标签
  - 相对好坏（如综合后网表节点、SAT 求解时间）→ 与参考 Verilog 对比，再给 desired / undesired
- 做法：用 LLM 在 module 头上补全得到多个变体，再用 EDA 工具按属性打标

### 4.6 生成式判别器（Section 3.5）

#### 4.6.1 形式化（CC-LM (Class-Conditional Language Model) 视角）

对于类条件语言模型（class-conditional LM）：

$$
p_\theta(x | c) = \prod_{t=1}^{n} p_\theta(x_t | x_{<t}, c)
$$

- 二元（binary）情形：分别有 control code $c$ 与 anti-control code $\bar{c}$
- 期望 / 非期望两种属性对应到 $c$ 与 $\bar{c}$

#### 4.6.2 Bayes 引导公式

对每个候选 token $x_t$，由 Bayes rule 得到序列归属某类的判别概率：

$$
p_\theta(c_y | x_{1:t}) = \frac{p(c_y)\, p_\theta(x_{1:t} | c_y)^{\alpha / t}}{\sum_{c' \in \{c, \bar{c}\}} p(c')\, p_\theta(x_{1:t} | c')^{\alpha / t}}
$$

其中：
- $c_y \in \{ c, \bar{c} \}$ 为序列标签
- $\alpha$ 是可学习尺度参数
- $p(c) = \mathrm{softmax}$ over learnable bias $b_c$

#### 4.6.3 双目标联合训练

- 生成损失 $L_g$：对每个属性 $c' \in \{ c, \bar{c} \}$ 做生成式预测（即语言建模目标）

$$
L_g = -\frac{1}{|D|} \sum_{i=1}^{|D|} \frac{1}{n} \sum_{t=1}^{n} \log p_\theta(x_t^i | x_{<t}^i, c')
$$

- 判别损失 $L_d$：在给定完整序列时预测类别

$$
L_d = -\frac{1}{|D|} \sum_{i=1}^{|D|} \log p_\theta(c_y^i | x_{1:n}^i)
$$

- 总损失（论文 Equation 7）：

$$
L_{\text{total}} = \lambda\, L_g + (1 - \lambda)\, L_d
$$

其中 $\lambda \in [0, 1]$ 用于在生成 / 判别两个目标间取平衡。

#### 4.6.4 Bayes 加权解码（Equation 8）

在解码时刻，对所有 token $x_t$ 计算加权分数：

$$
p_w(x_t | x_{<t}, c) \propto p_{\text{LLM}}(x_t | x_{<t})\, p_\theta(c | x_t, x_{<t})^w
$$

- 右侧第一项是 LLM 的下一 token 概率
- 右侧第二项是判别器在已经把 $x_t$ 并入上下文后的判别概率的 $w$ 次幂
- $w$ 越大，判别器的引导越强

#### 4.6.5 Token 过滤（Equations 9 与上下文）

为了避免被引导到语法不通顺或判别器高判别概率但语言模型概率极低的 token，论文采用 token-filter 两步走：

- 取累积概率阈值 $\rho$：先把所有候选 token 按 **判别器概率** $p_\theta(c | x_t, x_{<t})$ **排序**得到 $V_{\text{rank}}$，然后取前 $m$ 个使 $p_w$ 的累计质量 $\geq \rho$，得集合 $V_m = V_{\text{rank}}[1:m]$
- 取判别置信度阈值 $\tau$：对所有 $p_\theta(c | x_t, x_{<t}) > \tau$ 的 token 强制保留，记为 $V_\tau$
- 最终候选集合 $V_k = V_\tau \cup V_m$
- 在 $V_k$ 上做 softmax 采样

## 五、关键公式汇总

### 5.1 Auto-regressive 因式分解（Equation 1）

$$
p_\theta(x) = \prod_{t=1}^{n} p_\theta(x_t | x_{<t})
$$

其中 $x = (x_1, \dots, x_n)$ 是长度为 $n$ 的 token 序列，$x_{<t}$ 为 $t$ 之前的前缀。该式是对联合分布 $p_\theta(x)$ 沿 token 顺序作链式分解（Chain Rule）；它使得训练与解码只需对条件概率 $p_\theta(x_t | x_{<t})$ 建模，而无需直接估计完整序列的联合分布。

### 5.2 LLM 训练目标 / NLL（Equation 2）

$$
L = -\frac{1}{|D|} \sum_{i=1}^{|D|} \frac{1}{n} \sum_{t=1}^{n} \log p_\theta(x_t^i | x_{<t}^i)
$$

其中 $|D|$ 为训练序列数，$n$ 为序列长度，求和遍历数据集中所有 token。把式 5.1 取对数后再取负号、并对数据集按样本 / token 做平均，就等价于最大似然估计（MLE）；这就是标准的负对数似然（NLL）训练目标。

### 5.3 Class-Conditional LM 因式分解（Equation 3）

$$
p_\theta(x | c) = \prod_{t=1}^{n} p_\theta(x_t | x_{<t}, c)
$$

其中 $c$ 为控制码（control code），用以指定 desired / undesired 属性。

### 5.4 Bayes 引导的判别概率（Equation 5）

$$
p_\theta(c_y | x_{1:t}) = \frac{p(c_y)\, \prod_{j=1}^{t} \left( p_\theta(x_j | x_{<j}, c_y) \right)^{\alpha/t}}{\sum_{c' \in \{c, \bar{c}\}} p(c')\, \prod_{j=1}^{t} \left( p_\theta(x_j | x_{<j}, c') \right)^{\alpha/t}}
$$

其中 $c_y \in \{c, \bar{c}\}$ 为序列标签，$\alpha$ 为可学习尺度参数，分母对所有候选类做归一化。这是用 Bayes 公式把"已知前缀 $x_{1:t}$ 的情况下序列属于类 $c_y$ 的后验"用"先验 $p(c_y)$ × 类条件似然的 $\alpha/t$ 次幂"表达；类条件似然通过式 5.3 的链式分解得到，$\alpha/t$ 起到了对前缀长度做归一化的作用。

### 5.5 判别器生成损失 $L_g$（Equation 4）

$$
L_g = -\frac{1}{|D|} \sum_{i=1}^{|D|} \frac{1}{n} \sum_{t=1}^{n} \log p_\theta(x_t^i | x_{<t}^i, c')
$$

其中 $c' \in \{c, \bar{c}\}$ 遍历期望与非期望两种属性。

### 5.6 判别器判别损失 $L_d$（Equation 6）

$$
L_d = -\frac{1}{|D|} \sum_{i=1}^{|D|} \log p_\theta(c_y^i | x_{1:n}^i)
$$

其中 $c_y^i$ 为第 $i$ 条序列的真实类标签，$x_{1:n}^i$ 为完整序列。

### 5.7 总损失（Equation 7）

$$
L_{\text{total}} = \lambda\, L_g + (1 - \lambda)\, L_d
$$

其中 $\lambda \in [0, 1]$ 为生成损失与判别损失之间的平衡系数。$L_g$（式 5.5）保证判别器本身仍是一个语言模型（保留生成能力），$L_d$（式 5.6）则在完整序列上训练其判别能力；通过 $\lambda$ 在二者间插值可兼顾两项目标。

### 5.8 Bayes 加权解码（Equation 8）

$$
p_w(x_t | x_{<t}, c) \propto p_{\text{LLM}}(x_t | x_{<t})\, p_\theta(c | x_t, x_{<t})^w
$$

其中 $\propto$ 表示正比于，$w$ 为引导强度超参。该式把 LLM 的下一 token 概率与判别器在把 $x_t$ 并入前缀后的判别概率的 $w$ 次幂相乘；$w$ 越大，引导越强，但过强会牺牲 LLM 流畅度，所以 §5.9 的 token-filter 会进一步剔除判别概率虽高但 LLM 概率极低的 token。

### 5.9 Token-filter 中的累积概率阈值（Equation 9）

$$
\sum_{x_t \in V_{\text{rank}}[1:m]} p_w(x_t | x_{<t}, c) \geq \rho
$$

其中 $V_{\text{rank}}[1:m]$ 是按判别器概率 $p_\theta(c | x_t, x_{<t})$ 排序后的前 $m$ 个 token，$\rho$ 为累积质量阈值。

### 5.10 pass@k 无偏估计（Equation 10）

$$
pass@k := E_{\text{problems}}\left[1 - \frac{\binom{n - c}{k}}{\binom{n}{k}}\right]
$$

其中 $n$ 为每题生成的样本数，$c$ 为通过数，$k$ 为抽取数。直观解释：从 $n$ 个样本中无放回抽 $k$ 个，全不通过的概率是 $\binom{n-c}{k}/\binom{n}{k}$；$1$ 减去它就是"至少一个通过"的无偏估计。

## 六、训练与实验

### 6.1 训练配置

- 训练硬件：两卡 NVIDIA Tesla V100S PCIe 32 GB，CUDA 11.4
- 训练框架：DeepSpeed-Chat（Yao et al. 2023） + DeepSpeed ZeRO (Zero Redundancy Optimizer)（Rajbhandari et al. 2020）
- 微调方法：LoRA (Low-Rank Adaptation)（Hu et al. 2021），dim = 128（LLM 与判别器均如此）
- 优化器：Adam（Kingma & Ba 2014），β1 = 0.9，β2 = 0.95
- 学习率策略：cosine learning rate decay（Loshchilov & Hutter 2016）
- 训练超参
  - LLM 微调：4 epoch，初始学习率 9.65e-6，batch size 4
  - 生成式判别器：3 epoch，初始学习率 9.65e-6，batch size 8
- 可学习参数：$\alpha$ 初始化为 1，$b$ 初始化为 0
- 任务敏感超参：$\lambda$、$w$、$\rho$、$\tau$ 在不同下游任务上取值不同（论文按下游任务调优）

## 七、创新点（按贡献位次）

1. **首次把判别器引导的可控文本生成范式应用到工程优化领域**
   - 不是控制语义 / 风格等文本属性，而是直接优化 EDA 下游目标
   - 为 EDA 与可控生成两条线都打开新方向

2. **首个"下游任务驱动"的 Verilog 生成方法**
   - 用 EDA 工具（AIG、SAT、Yosys 等）作为下游任务 oracle
   - 把"如何实现 Verilog"翻译为"如何优化 Verilog 实现"
   - 训练效率和工业可用性明显提升

3. **以 6.7B/7B 规模微调 LLM + 判别器，无需 prompt engineering 即超越 GPT-4**
   - VerilogEval 上 BetterV-CodeQwen 在 pass@1 上比 GPT-4 高 8.1（machine）/ 2.6（human）
   - 表明 instruction-tuning + discriminative guidance 的算力—性能比优于商业大模型基线

4. **可在 LLM 与判别器训练间复用的数据增强管线（在论文实验的 Verilog 风格范围内）**
   - 数据稀缺时通过 instruct-tuned LLM 在高温度下补全 module 头
   - EDA 工具做语法过滤，保证加入数据集的样本都是"语法正确 Verilog"
   - 增强样本可同时用于 instruct-tuning 和判别器训练
   - 适用范围仍限于论文评测过的常见 Verilog 编码风格，不应外推为"任意 Verilog 规格"

5. **Code Knowledge Transfer（Verilog ⇆ C）的代码知识迁移设计**
   - 用 V2C 工具（Mukherjee et al. 2016）让 LLM 利用已有的 C 语言知识
   - 缓解 Verilog 语料稀缺对 LLM 学习的限制

6. **类条件生成式判别器 + Bayes-rule 加权解码的统一抽象**
   - 训练损失：$L_g + L_d$ 的加权和（Equation 7）
   - 解码公式：$p_w \propto p_{\text{LLM}} \cdot p_\theta(c | x_t, x_{<t})^w$（Equation 8）
   - Token-filter（$\rho$ 累积概率 + $\tau$ 判别置信度）保证引导不破坏 LLM 流畅度

### 9.2 下游"工业迭代闭环"被压缩的原理

- 工业生产中"Verilog 实现 → 综合 → 检查 PPA → 物理设计 → 验证 → 改 Verilog" 通常需要多轮人工迭代
- BetterV 在生成阶段就让 Verilog 实现偏向 PPA 友好（综合节点少）+ SAT 时间短
- 即下游任务目标（论文中演示的 AIG 节点与 SAT 时间两类）直接进入 LLM 的解码引导信号，相较传统多轮迭代可减少部分"写—测—改"的循环

（需注意：该压缩目前只在论文评测的 AIG 节点 / SAT 时间两类目标上得到验证，并未覆盖时序、功耗、面积、PPA 完整闭环等更广泛的下游任务。）

## 十、讨论局限（Section 5.1 及留白处）

1. **闭源 LLM 上的可推广性受限**
   - 论文明确指出闭源模型（如 GPT-4）通常不暴露 token-level 概率，因此 Bayes-rule 加权解码所需的 p_LLM 与 p_θ 无法被原作者直接获取

2. **判别器引入的额外推理开销**
   - 即使论文采用 TinyLlama / DeepSeek-Coder-1.3b 这种小模型，每一步解码都要调用一次判别器（含 $c$ 与 $\bar{c}$ 两个分支）
   - 自动机加速（量化、剪枝）应该是降低开销的研究路径
   - 论文没有给出具体的推理延迟 / 吞吐量评测

3. **下游任务种类有限**
   - 论文只演示了"综合后 AIG 节点"与"形式验证 SAT 时间"两个下游目标
   - 其它 EDA 关键目标（时序、功耗、面积、形式属性覆盖率、ATPG (Automatic Test Pattern Generation) 友好度）尚未被引导

4. **数据稀缺问题缓解但未根治**

5. **超参数对任务敏感**

## 十二、一分钟复述

BetterV 把 Verilog 生成从一个"写出可编译代码"的任务，重定义为一个"在 Verilog 一开始就把 EDA 下游目标同时考虑进去"的优化任务。它从 GitHub 抓取开源 Verilog，经过定义—Body 拆分和 V2C Verilog→C 对齐，做成 (Verilog, C) 与 (Definition, Body) 两种指令—答案对；用 LoRA 把 6.7B/7B 代码大模型（CodeLlama / DeepSeek-Coder / CodeQwen）在这套数据上 instruct-tuning，并在高温度采样 + EDA 工具语法过滤下不断扩充数据集。

判别器是一个二元生成式 CC-LM，用 EDA 工具（AIG 节点数 / Yosys `eqy` / Yosys `prep` / SAT 时间）给 desired / undesired 两种属性打标；它的训练目标由生成损失 + 判别损失组合而成（$\lambda$ 平衡），解码时通过 Bayes rule 把 LLM 的 token 概率和判别器的类概率相乘，再做一次"累积概率 $\geq \rho$ + 判别置信度 $> \tau$"的 token 过滤。

在 VerilogEval 上，BetterV-CodeQwen 把 pass@1 拉到 68.1（machine）/ 46.1（human），比 GPT-4 高 8.1 / 2.6；在综合后 AIG 节点上和参考 Verilog 相比平均少 46.52%，比自己的 base 版本少 31.68%；在 ANSI-C Benchmark 上把 SAT 求解时间相对参考省 22.45%。BetterV 把"判别器引导的可控文本生成"从控制语言风格带到了控制部分 EDA 工程指标（综合后 AIG 节点 / SAT 时间），在该范围内可减少多轮"写 Verilog—综合—改写"的迭代；代价是对词表一致性的依赖、对闭源模型难移植、以及对下游任务敏感的若干超参数。
