## 1. 一句话定位

**R2G 是首个标准化多视图电路图 benchmark，覆盖从 RTL 综合到布局布线的完整物理设计流程（RTL→GDSII）。它在 30+ 个开源 IP 核上构建了 5 种信息等价的 stage-aware 图表示视图（逻辑图、空间图、超图等），通过将"表示选择"和"模型选择"解耦，首次定量回答了 EDA 图学习领域的核心 confounding 问题：对于固定 GNN 架构，表示视图的选择会让 Test R² 差出 0.3 以上——也就是说，你用什么图表示比用什么 GNN 架构重要得多。**

这句话里的 4 个承重点：

1. **5 种信息等价的图视图** — 同一个电路可以有多种合法的图表示（netlist graph, spatial graph, hypergraph 等），每种视图在信息量上等价（同样的属性集），但在消息传递路径上不同。R2G 标准化了 5 种视图
2. **覆盖 synthesis→placement→routing 三阶段** — 从 DEF 文件直接提取，覆盖 30+ 开源 IP 核，节点/边规模最高 10⁶
3. **核心发现：表示选择 > 模型选择** — 固定 GNN 架构，不同视图的 Test R² 差距 > 0.3，模型排名在不同视图间翻转
4. **Decoder 深度是主要精度驱动力** — 3-4 层 decoder head 远比 GNN backbone 深度重要，R² > 0.99

## 2. EDA 阶段映射（①-⑰）

| 阶段 | 覆盖 | 说明 |
|------|:---:|------|
| ① RTL 设计 | ❌ | R2G 的数据起点是综合后的网表，不涉及 RTL 生成 |
| ② 架构设计 | ❌ | 不涉及系统/模块架构设计 |
| **③ 逻辑综合** | ✅ | 综合后的门级网表是第一阶段的图构建来源 |
| ④ 门级仿真 | ❌ | — |
| ⑤ STA | ❌ | 不包含时序分析数据 |
| ⑥ 形式验证 | ❌ | — |
| **⑦ 布局规划** | ✅ | 布局后的 DEF 提供空间坐标，是空间图视图的来源 |
| **⑧ 标准单元摆放** | ✅ **核心** | placement 阶段是 R2G 主要的数据来源之一（HPWL 预测任务） |
| ⑨ CTS | ⚠️ 间接 | routing 阶段数据包含时钟网络布线的部分信息 |
| **⑩ 布线** | ✅ **核心** | routing 阶段是第二个主要数据来源（线长预测任务） |
| ⑪-⑰ | ❌ | — |

**覆盖率：4.5/17。** R2G 跨越了 EDA 流程中最核心的三个物理设计阶段（综合、布局、布线）。它不是工具而是 benchmark——它的价值在于提供受控实验环境来研究"电路图表示方法"本身对 GNN 性能的影响。

> ⚠️ R2G 本身不做任何预测或优化——它是一个数据集 + 评测框架。论文中的 GINE/GAT/ResGatedGCN 实验是用来验证 benchmark 设计的合理性，不是 R2G 的"方法"部分。

## 3. 输入 / 输出（Benchmark 提供的数据）

### 3.1 数据来源

**起点**：30+ 开源 IP 核的 RTL 设计（来自 OpenCores、GitHub 等）

**处理流程**：
1. RTL → Yosys 综合 → 门级网表
2. 门级网表 → OpenROAD 布局 → Placed DEF
3. Placed DEF → OpenROAD 布线 → Routed DEF
4. 从各阶段 DEF 提取图结构、节点特征、边特征、标签

### 3.2 五种图视图（Information Parity）

每个 stage 的同一个电路提供 5 种图表示，所有视图共享同样的节点/边属性集，仅在**属性附着的拓扑结构**上不同：

| 视图 | 节点 = ? | 边 = ? | 适用阶段 |
|------|---------|--------|:---:|
| **(a) Netlist Graph** | 标准单元（cell） | 单元间的 net 连接 | Synthesis/Placement |
| **(b) Node-Centric Spatial** | 标准单元 | k-NN 空间近邻 + net 连接 | Placement/Routing |
| **(c) Grid-Based Spatial** | 布局网格单元 | 空间邻接 | Placement |
| **(d) Routing Resource Graph** | 布线轨道交点 | 轨道段连接 | Routing |
| **(e) Hypergraph** | 标准单元 + net（超边） | net 超边连接多个 cell | All stages |

### 3.3 任务与标签

| 任务 | 粒度 | 标签 | 指标 |
|------|------|------|------|
| **HPWL Prediction** | Node-level (回归) | 每个 cell 的半周长线长 | R², MAE |
| **Wire Length Prediction** | Edge-level (回归) | 每条 net 的实际布线长度 | R², MAE |
| **Congestion Prediction** | Node/Grid-level | 布线拥塞程度 | R² |

### 3.4 数据规模

- **30+ IP cores**：从简单处理器到复杂 SoC 组件
- **节点数**：10³ ~ 10⁶
- **边数**：10⁴ ~ 10⁶（路由资源图视图下可达 O(W×H×L)）
- **特征维度**：含单元类型、尺寸、坐标、方向、时序属性等

### 3.5 基准设计一览（论文 Table 1 精简）

R2G 包含 30 个开源 IP 核，覆盖 5 大类别：

| 类别 | 代表设计 | 图特征 |
|------|---------|--------|
| **Video/Audio** | vga_lcd, tv80, ac97 | 结构化数据流，中等 IO 数 |
| **Communication/System** | uart, i2c, spi, pci, usb, wb_dma, wb_conmax | 协议中心，强调握手和仲裁，高外部连通性 |
| **Crypto** | aes, des3, sha256, md5, kasumi | 密集组合逻辑，算术密集型数据通路 |
| **DSP** | fir, jpeg, idft | 宽数据通路，结构化流水线，重复算术模式 |
| **Processor** | tinyRocket, swerv, bp_multi | 混合控制-数据通路，最大规模（最高 158K 节点） |

不同类别的电路在规模、拓扑、IO 密度上差异显著——这验证了 R2G 的核心论点：**不存在对所有设计都最优的单一图表示**。

### 3.6 特征 Schema（论文 Table 2）

R2G 定义了分阶段的特征集。Placement 阶段 gate 仅有静态属性（cell type, area, power leak），Routing 阶段 gate 增加 x/y 坐标和 orientation。Net 特征包括 net type（signal/power/ground/clock/reset/scan）、pin count、HPWL。所有离散字段使用稳定的整数编码（如 cell type→0-95, orientation→0-7）。

**信息等价性的保证**：同一属性集在所有视图中可用，仅在"附着位置"上不同——这使得跨视图公平比较成为可能。

### 4.2 从电路到图的实体映射

R2G 定义了 4 种基本实体类型，同一实体在不同视图中可以扮演 node 或 edge 的角色：

| 实体 | 含义 | 视图 (b) 中角色 | 视图 (c) 中角色 | 视图 (d) 中角色 | 视图 (e) 中角色 | 视图 (f) 中角色 |
|------|------|:---:|:---:|:---:|:---:|:---:|
| **Gate** (逻辑门) | AND/OR/NOT/... | Node | Node | Node | Edge (incidence) | Node |
| **Pin** (引脚) | 门的输入/输出/双向端口 | Node | Edge (gate-net) | — (聚合到 edge attr) | Edge (incidence) | — (聚合) |
| **Net** (电气网线) | 多端电气连接 | Node | Node | Edge (gate-gate) | Node | Edge (gate-gate) |
| **IO** (宏端口/Pad) | 芯片级输入输出 | Node | Node | Node | Node | Node |

**关键设计决策**：
- Net 在视图 (b)(c)(e) 中作为 node 出现 → 保留了多端连接语义
- Net 在视图 (d)(f) 中作为 edge 出现 → 退化为 pairwise 连接
- Pin 在视图 (c) 中作为 edge → 保留了方向性信息（input/output/inout）
- Pin 在视图 (f) 中被聚合 → 牺牲方向性换取可扩展性

这种"同一实体在不同视图中的角色转换"是 R2G 多视图设计的核心 insight——不是创建不同的数据集，而是从同一底层数据中通过不同的"投影"构建不同的图结构。

### 4.3 核心设计原则

#### 设计原则 1：Information Parity（信息等价）

**做什么**：所有 5 种视图编码同样的属性集（cell 类型、尺寸、坐标、时序 slack 等），仅在"属性附着在哪里"和"消息传递沿什么路径"上不同。

**为什么这样设计**：之前的 EDA benchmark（CircuitNet、OpenABC-D 等）将图表示和任务标签耦合在一起——你换一种图表示就换了一个数据集。R2G 通过信息等价实现了"固定电路、固定任务、只变图表示"的受控实验。

#### 设计原则 2：Stage-Aware Views

**做什么**：不同物理设计阶段的图表示在空间语义上有本质差异。Placement 阶段的 cell 有精确坐标，但 routing 阶段才确定金属层分配和拥塞信息。

**为什么这样设计**：同一个电路在综合/布局/布线三个阶段的"最佳图表示"可能完全不同。R2G 通过 stage 维度 × view 维度的矩阵设计，可以定量研究这种差异。

#### 设计原则 3：Decoder-Head Depth 控制变量

**核心实验发现**：将 decoder head 从 1 层增加到 3-4 层，Test R² 从 -0.17 提升到 0.99——这个提升幅度远超换 GNN backbone 的效果。

**含义**：在电路图预测任务中，decoder 的容量（如何从节点嵌入映射到具体数值）比 encoder 的容量（如何聚合邻居信息）更关键。

### 4.4 实验设计矩阵

| 维度 | 选项 |
|------|------|
| GNN Backbone | GINE, GAT, ResGatedGCN |
| View | (b)-(f) 五种视图（注意：原论文 (a) 是原始电路示意图，实验中用 (b)-(f)） |
| Stage | Placement (HPWL) , Routing (Wire Length) |
| Task | Node-level regression, Edge-level regression |

### 4.5 实验设计的关键决策

**为什么只用同质 GNN（GINE/GAT/ResGatedGCN）？**
R2G 将类型化的异质图转换为统一节点/边类型的同质图，同时保持属性等价性。这样可以使用经典同质 GNN 做公平的跨视图比较。论文明确将异质表示和 hetero-GNN 留给了 future work。

**为什么选择这 3 种 GNN？**
- GINE：GIN 的边特征版本，EDA 图学习中最常用的 baseline
- GAT：注意力机制的代表，测试图拓扑是否需要非均匀聚合
- ResGatedGCN：带残差门控的卷积网络，测试门控机制对几何耦合的稳定性

### 4.6 跨视图比较的关键方法学贡献

R2G 的实验设计实现了一个之前 EDA benchmark 无法做到的事情：**固定电路、固定任务、固定模型，只改变图表示**。这使得"表示选择 vs 模型选择"的 confounding 被首次定量分离。

## 5. 关键发现（实验结论）

### 5.1 Placement 实验结果（论文 Table 3）

在 placement 阶段的 HPWL 预测任务上，所有 3 种 GNN × 5 种视图的结果：

| View | GINE Test R² | ResGatedGCN Test R² | GAT Test R² |
|------|:---:|:---:|:---:|
| (b) Node-Centric Spatial | **0.8878** | **0.8803** | 0.8049 |
| (c) Grid-Based | 0.8003 | **0.8519** | 0.1889 |
| (d) Routing Resource | 0.7109 | 0.6866 | 0.5085 |
| (e) Hypergraph (Incidence Edges) | **-0.0107** | **-0.0610** | 0.0472 |
| (f) Net Edges (no pins) | 0.6151 | **0.7067** | 0.0634 |

**关键观察**：
- 视图 (b) 对所有 3 种 GNN 都表现最优或次优——是最稳定的默认选择，论文 §D.1 解释为"中等 degree（~2.40）+ 长路径（~16.43）平衡了局部与全局信息"
- 视图 (e) 上 GINE 和 ResGatedGCN 的 R² 为**负值**（-0.0107、-0.0610）——这是论文核心发现之一：incidence-edge 表示与经典 GNN 消息传递机制存在根本性 mismatch，模型预测甚至不如直接猜均值。只有 GAT 的注意力机制能从这种稀疏 incidence 结构中勉强提取信号（0.0472，barely positive）
- GAT 在视图 (c)(f) 上严重退化（0.1889、0.0634），但在视图 (e) 上反而是唯一正值的模型——注意力机制对图的连通性结构高度敏感

### 5.2 Routing 实验结果（论文 Table 4）

Routing 阶段（更难的任务）：

| View | GINE Test R² | ResGatedGCN Test R² | GAT Test R² |
|------|:---:|:---:|:---:|
| (b) Node-Centric Spatial | **0.8596** | **0.8763** | 0.8131 |
| (c) Grid-Based | 0.6471 | **0.8618** | 0.1260 |
| (d) Routing Resource | 0.5758 | 0.5467 | 0.0389 |
| (e) Hypergraph | 0.4277 | 0.6673 | **0.8389** |
| (f) Net Edges | 0.2972 | 0.3179 | 0.0014 |

**Routing 比 Placement 更具挑战性**——所有视图的 R² 都有所下降。GAT 在视图 (d)(f) 上的极端退化（R² < 0.04）印证了注意力机制在稀疏/edge-only 结构上的弱点。

### 5.3 发现 1：表示选择 > 模型选择

固定 GNN 架构，不同视图的 Test R² 差异：

| 架构 | 最优视图 R² | 最差视图 R² | Δ |
|------|:---:|:---:|:---:|
| GINE (Placement) | 0.8878 (b) | -0.0107 (e) | **0.899** |
| ResGatedGCN (Placement) | 0.8803 (b) | -0.0610 (e) | **0.941** |
| GAT (Placement) | 0.8049 (b) | 0.0472 (e) | **0.758** |
| GINE (Routing) | 0.8596 (b) | 0.2972 (f) | **0.562** |

**差距远超换 backbone 带来的提升**（通常 ΔR² < 0.1）。结论：**先选对表示，再选模型。**

### 5.4 发现 2：Node-Centric Views 跨阶段泛化最优

视图 (b) 在 placement 和 routing 两个阶段上对所有 GNN 架构都是最优或次优——说明在节点上集中编码局部空间信息的表示方式具有跨阶段泛化性。

视图 (e)（超图 incidence edges）是 edge-oriented 任务上的最优选择（GAT 在 placement 0.8633, routing 0.8389），适合需要多端 net 语义的场景。

视图 (f)（纯 net edges）应避免——Routing R² < 0.32，信息损失严重。

### 5.5 发现 3：GNN Backbone 深度 3-4 层最优（论文 Tables 5-6）

在视图 (b) 上测试 3-6 层 GNN：

| #Layers | GINE Test R² (Placement) | ResGatedGCN Test R² (Placement) |
|:---:|:---:|:---:|
| 3 | 0.8851 | 0.8885 |
| 4 | 0.8915 | 0.8815 |
| 5 | 0.8853 | 0.8797 |
| 6 | 0.8348 | 0.8766 |

**超过 4 层后精度下降**——over-smoothing 和梯度衰减是经典 GNN 在电路图上的真实瓶颈。不需要 deep GNN。

### 5.6 发现 4：Decoder Head Depth 是主要精度杠杆（论文 Tables 7-8）

这是 R2G 最颠覆性的发现。在视图 (b) 上，固定 GNN 深度 4 层，变化 decoder head 深度：

| Head Depth | GINE Test R² (Placement) | ResGatedGCN Test R² (Placement) | GINE Test R² (Routing) |
|:---:|:---:|:---:|:---:|
| 1 | 0.8514 | **-0.1689** | NaN (训练崩溃) |
| 2 | 0.8685 | 0.8832 | 0.8586 |
| 3 | **0.9883** | **0.9889** | **0.9891** |
| 4 | **0.9962** | **0.9891** | **0.9965** |

**Head 深度从 1→4，R² 从负数/NaN 飙升至 0.99+**。而 GNN backbone 深度增加几乎没有额外收益。

**为什么 Head Depth 如此关键？** 1-2 层的浅 head 无法将节点嵌入非线性地映射到连续坐标/线长值——placement 和 routing 的标签空间是非线性的。3-4 层的 head 提供了足够的非线性变换能力和 normalization 容量。

**实践建议**（论文直接给出）：
- 默认使用视图 (b)（node-centric spatial）
- GNN backbone 3-4 层（避免 over-smoothing）
- **Decoder head 配置 3-4 层**（比增加 backbone 深度重要得多）
- 模型选择：ResGatedGCN 在视图 (b)(c) 最稳，GAT 在视图 (e) 有效但跨视图不稳定

## 6. 实验设置

### 6.1 是否需要训练

**R2G 是 benchmark，不需要训练。** 但论文提供了完整的 baseline 实验来验证 benchmark 设计的合理性。

### 6.2 Label 定义

Placement 阶段的 HPWL 标签：

$\text{HPWL} = (x_{\max} - x_{\min}) + (y_{\max} - y_{\min})$

即 net 所连接的所有 pin 的 bounding box 的半周长。

Routing 阶段的 wire length 标签（逐金属层）：

$\text{wire length} = \sum_{\ell \in L} \sum_{(x_1,y_1),(x_2,y_2) \in \ell} |x_2 - x_1| + |y_2 - y_1|$

其中 $L$ 为 DEF 中已布线的金属层集合。额外的辅助标签包括 via count（过孔数量）。

标签根据视图附着到相应实体：net 为 node 时（视图 b/c）标签在 node 上，net 为 edge 时（视图 d-f）标签在 edge 上。

### 6.3 Baseline 实验

- **模型**：GINE, GAT, ResGatedGCN
- **训练**：标准图回归训练（MSE loss, Adam optimizer）
- **评估指标**：R², MAE, RMSE
- **数据划分**：按 IP core 做 train/val/test split（防止同一设计的不同子图泄漏到训练/测试集）
- **同质图转换**：将类型化异质图转为统一节点/边类型的同质图，保持属性等价性

### 6.4 可复现性

- 完整的 DEF-to-graph 提取管线（开源）
- 统一的 PyG/DGL data loader
- 预定义的 train/val/test split
- 所有 baseline 的训练脚本和超参配置

## 7. 创新点

### 创新点 1：首个标准化多视图电路图 benchmark

**已有资源**：CircuitNet（单视图，back-end）、OpenABC-D（单视图 AIG，front-end）、EDA-schema（跨阶段但多模态混合，不对比视图）。

**R2G 的贡献**：
- 5 种信息等价的图视图，首次让"表示选择"成为独立实验变量
- 覆盖 placement→routing 两个物理设计阶段，30+ IP 核
- 标准化评测协议（统一 loader, split, metrics, baselines）
- 端到端 DEF-to-graph 管线，支持 PyG/DGL

### 创新点 2：定量揭示「表示选择 > 模型选择」

**已有认知**：EDA 图学习社区默认"模型创新"是性能提升的主要驱动力。

**R2G 的颠覆性发现**：固定 GNN 架构，改变图表示带来的 ΔR² > 0.3（placement）甚至 > 0.5（routing），而换 backbone 带来的提升通常 < 0.1。这个发现对 EDA 图学习方法论有方向性指导意义——**先选对表示，再优化模型**。

### 创新点 3：发现 Decoder Head Depth 是 EDA 图学习的被忽视杠杆

**已有认知**：大多数 EDA GNN 工作关注消息传递层的设计（GIN vs GAT vs TransformerConv），decoder 通常是简单的 1-2 层 MLP。

**R2G 的发现**：Decoder head 深度从 1→4，R² 从负数/NaN 提升到 0.99+，这是之前所有 EDA benchmark 都未报告过的现象。这改变了 EDA GNN 架构设计的优先级——**在 decoder head 上的投入可能比设计新的消息传递机制更有效**。

### 创新点 4：Information Parity 的方法论贡献

通过在所有视图中保持完全相同的属性集、仅在拓扑上变化，R2G 首次实现了真正的受控变量实验——这在之前的 EDA benchmark 中是不可能的，因为换一种图表示通常意味着换一个数据集。这个设计原则为未来的 EDA graph benchmark 设立了新标准。

## 8.5 R2G 使用指南

### 如何在自己的研究中使用 R2G

**场景 1：你想测试一种新的 GNN 架构在电路图上的效果**

1. 选择视图 (b)（node-centric spatial）作为默认表示
2. 使用 R2G 提供的统一 PyG/DGL loader 加载数据
3. 用 R2G 预定义的 train/val/test split 进行公平比较
4. 同时报告 placement HPWL 和 routing wire length 两个任务的结果
5. 比较至少 2 种视图（如 (b) 和 (e)），以证明你的架构不只在一种表示上有效

**场景 2：你想研究"什么图表示最适合电路任务 X"**

1. 为任务 X 定义合适的标签和评价指标
2. 在所有 5 种视图上运行同样的 GNN baseline
3. 用 R² 差异量化视图选择的效应大小
4. 报告"视图推荐"为社区提供指导

**场景 3：你想做跨阶段迁移学习**

1. 在 placement 阶段的视图 (b) 上预训练 GNN
2. 迁移到 routing 阶段的视图 (b) 上微调
3. 比较 with/without 预训练的 R² 差异
4. 控制 head depth 以隔离"表示迁移"和"任务适配"的效应

### 避免的常见错误

- ❌ 只在视图 (f)（AIG 等价）上评估——信息损失严重
- ❌ 只报告 placement 结果而不测试 routing——跨阶段泛化才是真正的考验
- ❌ 用 1-2 层 decoder head——head 深度不足会导致训练不稳定和 R² 虚低
- ❌ 不做跨视图比较就宣称"我们的 GNN 比 baseline 好"——可能只是因为 baseline 的视图选择不当

## 9. 与芯片流程的关系

### 9.1 在全流程中的位置

```text
R2G 数据覆盖范围
┌──────────────────────────────────────┐
│ ③ 逻辑综合 → ⑦ 布局 → ⑧ 摆放 → ⑩ 布线 │
│  (Synth DEF)  (Place DEF)  (Route DEF) │
└──────────────────────────────────────┘
         │                              │
         ▼                              ▼
    图表示 a,b,c,d,e              预测任务: HPWL / Wire Length
```

R2G 的价值不在于"做预测"，而在于提供一个受控实验平台来回答方法论层面的问题："对于给定的 EDA 预测任务，应该怎么把电路表示成图？"

### 9.2 R2G 与物理设计流程的精确对应

R2G 从 OpenROAD 流程中提取数据，对应关系如下：

| 物理设计步骤 | OpenROAD 命令 | R2G 数据输出 | 图视图可用性 |
|------------|-------------|-------------|:---:|
| 综合 | `run_synthesis` | Synth DEF → 仅 netlist 连接 | (a)(e)(f) |
| 布局规划 | `run_floorplan` | Floorplan DEF → 宏单元坐标 | + 空间坐标 |
| 全局布局 | `run_placement` | Place DEF → 所有 cell 坐标 | (b)(c) 可用 |
| CTS | `run_cts` | CTS DEF → 时钟 buffer 插入 | 作为上下文特征 |
| 全局布线 | `run_routing` | Route DEF → 精确金属层线长 | (d) 可用 |

R2G 聚焦 placement 和 routing 两个阶段，因为这两个阶段最大程度决定了时序、功耗和可布线性。

### 9.3 R2G 对 EDA 实践者的价值

1. **快速原型验证**：在投入完整的物理设计流程之前，用 R2G 快速评估新的 GNN 架构在图表示选择上的敏感度
2. **表示选择指导**：对于新任务，先在 R2G 的 5 种视图上做 ablations，找到最优表示后再部署到生产数据上
3. **方法论教育**：R2G 的实验矩阵（view × model × head depth × GNN depth）是理解"EDA 图学习中的 confounding 因素"的最佳教学工具

### 9.4 R2G 对 EDA ML 研究社区的方法论启示

R2G 最深远的影响可能不是数据本身，而是它揭示的方法论问题。以下是可以从 R2G 中提炼的几条方法论原则：

**原则 1：表示和模型必须解耦评估**
在 R2G 出现之前，当一篇论文说"我们的 GNN 比 baseline 好 X%"，读者无法判断这个提升是因为更好的图表示、更好的 GNN 架构、还是更好的训练策略。R2G 的信息等价设计使得这三个因素可以被独立控制。

**原则 2：Decoder capacity 是 EDA 图学习的被忽视维度**
大多数 EDA GNN 工作默认使用 1-2 层 MLP decoder head，精力集中在消息传递层。R2G 的实验表明这是一个优化方向的错误——具体来说，增加 decoder head 深度带来的 R² 提升远比设计新的 GNN 层大。这对后续研究有直接的方法论指导：在比较两种 GNN 架构之前，先确保两者都有足够的 decoder capacity。

**原则 3：任务-视图匹配是应用 GNN 到 EDA 的第一步**
R2G 的跨视图实验清楚地表明：同一 GNN 在不同视图上的表现可能从 R² = -0.06 到 R² = 0.89。在新任务上应用 GNN 之前，先用类似 R2G 的多视图 ablations 确定最佳表示，应该成为标准实践。

**原则 4：负 R² 不一定是模型的问题——可能是视图选择的问题**
R2G 中 GINE/ResGatedGCN 在视图 (e) 上的负 R² 是一个警示：如果你发现一个 GNN 在你的数据上表现极差，在归咎于 GNN 架构之前，先检查图表示是否与任务匹配。

### 9.5 Benchmark 的局限性

1. **物理设计范围有限**：不覆盖 CTS（⑨）、DRC/LVS（⑫）、Signoff（⑬）
2. **时序信息不完整**：不含 STA 数据（⑤），无法做 timing prediction——这是物理设计中最关键的任务之一
3. **IP 核的多样性有限**：30+ IP 核主要来自 OpenCores，不一定代表最先进的工业设计（7nm/5nm/3nm）
4. **技术节点单一**：所有设计使用同一技术库，未测试跨节点的泛化能力
5. **仅测试经典 GNN**：GINE/GAT/ResGatedGCN 是 2018-2020 年的架构，未验证 Graph Transformers、Equivariant GNN、或更近期的方法

## 10. 讨论与局限

### 10.1 论文自述的局限
- 目前仅支持数字后端，不涉及模拟/混合信号
- 仅覆盖 placement 和 routing 两个阶段（不涉及 CTS、DRC/LVS、Signoff）
- DEF 提取的属性缺少 timing、IR-drop、详细功耗信息
- 设计覆盖有限的技术节点
- GNN baseline 仅测试了 3 种经典架构，未覆盖 Graph Transformers、MoE 等新架构
- 不包含跨阶段迁移学习的实验

### 10.2 代码/复现层面的问题
- 依赖 OpenROAD flow（需要配置完整的开源 EDA 工具链：Yosys + OpenROAD）
- 大规模设计的图构建（10⁶ 节点）需要较大的内存
- 代码和数据已开源：https://github.com/ShenShan123/R2G

### 10.3 本资料包的批判性分析

1. **"表示选择 > 模型选择"这个发现在多大程度上可推广？** 论文在 HPWL prediction 和 wire length prediction 两个任务上验证了该结论。在更复杂的任务（如 congestion prediction、timing prediction、DRV prediction）上结论是否仍然成立，需要进一步验证。但该发现的方法论意义已经足够重要——它提醒 EDA 图学习社区不要盲目追新模型架构，而应首先审视"电路应该如何表示为图"。

2. **与 CircuitNet 系列的对比**：
   - [CircuitNet](../CircuitNet/论文深度讲解.md)：单视图（AIG equivalent），专注后端 PPA 预测
   - [CircuitNet 2.0](../CircuitNet2.0/论文深度讲解.md)：扩展到更多设计，仍是单视图
   - [CircuitNet 3.0](../CircuitNet3.0/论文深度讲解.md)：多模态（RTLDistil + MOSS），关注数据增强 + 多模态融合
   - **R2G**：多视图 + 信息等价，关注图表示方法论
   - R2G 和 CircuitNet 系列是互补关系：CircuitNet 提供了更大规模的数据和更多样的任务，R2G 提供了更严谨的方法论实验平台

3. **R² > 0.99 意味着什么——以及不意味着什么**：
   - ✅ 意味着：对于 placement HPWL prediction 这个特定任务，3-4 层 head 的 GNN 可以几乎完美地从局部图结构预测线长
   - ❌ 不意味着：EDA 预测问题已经"解决"——HPWL 本身是一个局部的、几何定义明确的任务（坐标 → bounding box 半周长），与其他更复杂任务（timing、congestion、DRV）有本质区别
   - ❌ 不意味着：GNN 可以替代物理设计工具——预测 HPWL 只是 placement 优化中的一个小环节

4. **"信息等价性"的实际边界**：论文声称 5 种视图"信息等价"，但这仅指属性集相同。消息传递路径的不同意味着某些信息在某些视图中更难被学习到——"信息等价"不等于"学习效率等价"。视图 (f)（纯 net edges）的差劣表现正是因为这个原因：虽然坐标属性仍然存在（在 gate 节点上），但缺少 pin/net 节点使得空间邻接关系更难被 GNN 捕获。

5. **视图 (e) 上 GINE/ResGatedGCN 的负 R²**：在 placement 任务上，GINE 和 ResGatedGCN 在视图 (e) 上的 Test R² 分别为 -0.0107 和 -0.0610（负值！），而 GAT 为正（0.0472）。这说明 incidence-edge 表示与 GINE/ResGatedGCN 的消息传递机制存在根本性 mismatch——只有注意力机制能从这种表示中提取有用信号。这个反常结果本身就是 R2G 多视图设计的价值所在。

6. **Decoder head 深度的含义——对 EDA GNN 架构设计的启示**：
   - 当前大多数 EDA GNN 工作把精力放在设计更好的消息传递机制上（GIN、GAT、TransformerConv、EdgeConv...）
   - R2G 的结果表明：对于节点/边级别的回归预测任务，decoder head 的容量可能是更被低估的瓶颈
   - 这一发现与 NLP 和 CV 中的观察一致（BERT 的 classification head, ViT 的 MLP head），但在 EDA 图学习领域是首次被定量验证

7. **为什么之前的 benchmark 没发现 Head Depth 的重要性？**
   - 之前的 benchmark（CircuitNet, OpenABC-D）使用固定的单视图 + 固定的 head 配置，无法做 head depth 的受控实验
   - R2G 的信息等价设计使得 head depth 成为一个可以独立变化的实验变量——而之前的 benchmark 中，换一种图表示意味着换一个数据集，无法区分是"表示变了"还是"数据变了"

8. **R2G 的真正价值不在于"预测精度"**：R² > 0.99 看起来很惊人，但这不意味着 EDA 预测问题已经解决——HPWL prediction 本身是一个相对简单的任务（局部坐标 → 局部线长）。R2G 的真正价值在于提供了一个方法论实验平台，让研究社区可以在受控条件下研究"如何表示电路图"这一根本问题。

## 12. 一分钟复述版

1. **问题**：EDA 图学习领域缺少标准化多视图 benchmark，"用什么图表示电路"和"用什么 GNN 架构"这两个因素一直混淆（confounding），社区默认"模型创新"是主要驱动力
2. **方案**：R2G——30+ IP 核（5 大类：Video/Audio、Communication、Crypto、DSP、Processor）、5 种信息等价视图（(b) all-elements-as-nodes, (c) pins-as-edges, (d) nets-as-edges, (e) net-gate incidence, (f) net edges without pins）、覆盖 placement→routing 两阶段、端到端 DEF-to-graph 管线
3. **核心发现 1**：表示选择 >> 模型选择——固定 GNN 架构，不同视图的 Test R² 差距 > 0.3（placement）甚至 > 0.5（routing），远超换 backbone 的收益（< 0.1）
4. **核心发现 2**：Node-centric view (b) 跨阶段泛化最优——在 placement 和 routing 两种不同标签类型上都表现最强或次强
5. **核心发现 3**：Decoder head 深度（3-4 层）是主要精度杠杆——R² 从 -0.17/NaN 飙升至 0.99+，而 GNN backbone 深度（3→6 层）几乎没有额外收益甚至有负作用
6. **核心发现 4**：模型-视图匹配很重要——GAT 在 hypergraph 视图 (e) 上效果最好但跨视图不稳定，ResGatedGCN 在 node-centric 视图上最稳健
7. **方法论贡献**：Information Parity 设计原则——所有视图共享同样的属性集、仅在拓扑上变化，首次实现了"固定电路、固定任务、固定模型、只变图表示"的受控变量实验
8. **实践建议**：默认用视图 (b) + ResGatedGCN + 3-4 层 GNN + 3-4 层 decoder head；避免用视图 (f) 作为主视图（信息损失严重）；在 decoder head 上的投入比设计新的消息传递机制更有效
9. **局限**：仅覆盖 placement/routing 两阶段，缺少 timing/IR-drop/power 属性，仅测试了 3 种经典 GNN（未验证 Graph Transformers），设计覆盖有限的技术节点
10. **意义**：对 EDA 图学习方法论有方向性指导——先选对表示，再优化模型，最后才考虑增大 backbone
