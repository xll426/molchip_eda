## 1. 一句话定位

**OmniLayout 不是模型，而是 PCB（Printed Circuit Board，印刷电路板）布局领域的首个大规模多模态 benchmark——它定义了从原理图+网表到元件物理摆放的四层评测体系（几何合法性、可布线性、电气功能保持、工具增强迭代），以 1,681 个真实工业级原理图耦合 PCB 设计、77.24K 元件 placement instance、12 项评估指标、10 个 LMM（Large Multimodal Model，大视觉-语言模型）的系统评测，公平比较现有多模态模型在约束感知几何推理任务上的能力。结论是颠覆性的：当前最强 LMM 在密集布局、多层空间利用、电气功能保持上的表现远不及人工工程师——GPT-5.5 零样本端到端通过率仅 15.23%，最优零样本端到端通过率也不超过 58.18%，且约 80% 元件被放在单层上。**

这句话里的五个承重点，后面逐一拆解：

1. **1,681 设计大规模数据集** — 从 SparkFun、Arduino、Adafruit、GitHub 等六大开源硬件平台收集 Autodesk EAGLE 项目，通过自动标注流水线提取原理图结构/布局位置/连通性三层标注，单设计最多 327 元件、1,172 引脚、840 网络，远超以往 PCB 布局数据集的规模（上一最大数据集 Cypress 仅 10 个设计）。
2. **四类约束感知几何推理任务** — 几何推理（不重叠、在板框内）、可布线性感知布局（最小化 HPWL/NC/NS，FreeRouting 实际布线验证）、电气功能保持（保持原理图子电路拓扑关系）、工具增强迭代（LMM 调用 layout visualization / overlap check / routability verification 工具逐步优化）。
3. **12 项评估指标** — 覆盖几何合法性（OO/OoB/P-Pass/RT）、可布线性（HPWL/NC/NS/PRWL/RR/#Vias/R-Pass）、电气功能（Sch./Ref.）和 Agentic 效率（Step），其中 PRWL/RR/#Vias 由 FreeRouting 实际布线后统计，不满足于 HPWL 估计。
4. **10 个 LMM 系统评测** — GPT-5.5、GPT-5-mini、Claude-Sonnet-4.6、Gemini-3.1-Pro-Preview、Gemini-2.5-Flash-Lite、LLaMA-4-Maverick（400B）、Mistral-Medium-3.5（128B）、Ministral（14B）、Qwen3.5-9B、Qwen3.6-35B-A3B，在 zero-shot / few-shot / agentic 三种设置下评估。
5. **LMM 在 PCB 布局上存在关键缺陷** — 几何推理在 >40 元件时性能断崖式下降；空间利用率极差（80% 元件被放在顶层）；电气功能与参考布局平均相似度低于 60%；Few-shot 虽然降低 OO/OoB 但增加了 HPWL 和 NC（过拟合到示例）；Qwen 模型在 agentic 设置下甚至无法输出结构化 placement JSON。

## 2. EDA 阶段映射：PCB 布局与数字芯片 17 阶段的对比

### 2.1 PCB 设计流程与数字芯片 17 阶段的本质差异

PCB 设计有自己的独立流程，与数字芯片 17 阶段**不存在一对一映射**。两者的根本差异在于物理载体、设计粒度和约束类型：

| 维度 | 数字芯片流程（①-⑰） | PCB 设计流程 |
|------|------|------|
| **物理载体** | 硅晶圆（die），矩形，约 mm² 级别 | FR-4 板材，任意多边形板框，约 cm² 级别 |
| **被摆放对象** | 标准单元（AND/XOR/DFF/BUF），百万~亿级，等高、宽度离散 | 分立元件（电阻/电容/IC 封装/连接器），百~千级，形状各异 |
| **层叠结构** | 多层金属互连（M1~M10+），单面放置 | 顶层/底层双面放置 + 多层铜箔走线 |
| **核心约束** | 时序（setup/hold）、拥塞（congestion）、功耗密度（IR drop） | 不重叠、在板框内、散热间距、电磁兼容（EMC）、机械固定孔/keep-out 区、高压爬电距离 |
| **目标函数** | 线长（HPWL/WL）+ 时序 slack + 拥塞 | 线长（HPWL）+ 可布线性 + 热分布 + EMC |
| **求解方法** | 解析法 + 合法化 + 详细摆放（商业 EDA 核心 IP） | 模拟退火/力导向/启发式搜索；本文用 LMM 推理 |
| **制造文件** | GDSII（给晶圆厂） | Gerber（给 PCB 厂） |
| **工具链** | Synopsys/Cadence/Siemens 商业工具，开源 OpenROAD | Autodesk EAGLE/Altium Designer/KiCad，开源 FreeRouting |

### 2.2 本文在流程中的精确位置

**OmniLayout 聚焦 PCB Component Placement（元件布局）**——在问题结构上与芯片流程的阶段 ⑦（Floorplan）和 ⑧（Placement）有类比关系，但具体约束和求解方法完全不同：

| 数字流程阶段 | 覆盖 | PCB 对应活动 | 关系说明 |
|------|:---:|------|------|
| ① RTL 设计 | ❌ | 原理图设计（Schematic Capture） | 都定义"电路应该做什么"——RTL 用代码，原理图用符号+连线。问题结构类比但技术手段完全不同 |
| ② RTL 功能仿真 | ❌ | — | PCB 无功能仿真概念 |
| ③ 逻辑综合 | ❌ | 网表导出（Netlist Extraction） | 都产生元件及连接关系清单——芯片产生门级网表，PCB 产生元件-引脚-网络 |
| ④-⑥ 门级仿真/STA/形式验证 | ❌ | — | PCB 无对应阶段 |
| **⑦ 布局规划 + ⑧ Placement** | ✅ **核心类比** | **PCB 元件布局（本文核心任务）** | 数学形式上都是"带约束的二维矩形装箱 + 最小化线长"，但 PCB 约束维度更多（热/电磁/机械），规模更小（百~千 vs 百万~亿） |
| ⑨ CTS | ❌ | PCB 无时钟树概念（时钟由独立晶振/IC 内部提供） | — |
| **⑩ 布线** | △ 部分类比 | PCB Routing（FreeRouting 作为固定 backbone 评测 placement 质量） | 都是连通所有网络——芯片用多层金属互连，PCB 用铜走线+过孔。本文不直接研究 LMM 布线能力 |
| ⑪ 后仿真 | ❌ | — | — |
| **⑫ 物理验证 (DRC)** | △ 部分类比 | PCB DRC（走线间距/焊盘环宽/阻焊桥） | 都检查制造可行性——芯片查金属间距/通孔包围，PCB 查走线间距/焊盘环宽。本文的几何合法性指标（OO/OoB）是 DRC 的前置条件 |
| ⑬-⑰ Signoff/流片/制造/封装 | ❌ | — | PCB 的对应阶段是生成 Gerber 发板厂 |

**覆盖率：本文在问题结构上可类比数字流程的 ⑦⑧⑩⑫（4/17），但属于 PCB 设计流程而非数字 IC 设计流程。**

> ⚠️ **不要将 PCB 布局硬套进数字芯片的 Placement（阶段⑧）。** PCB 元件布局的"元件"是分立器件（电阻/电容/IC 封装），形状差异大（0402 电阻 1.0mm×0.5mm vs BGA 封装 35mm×35mm），板框可以是任意多边形，允许双面放置，还需要考虑散热/电磁/机械等多维约束。而数字芯片 Placement 的对象是标准单元（所有单元等高、排成行），die area 是矩形，单面放置，约束以时序和拥塞为主。两者数学形式同源（NP-hard 矩形装箱）但物理约束维度和求解规模差 3~6 个数量级。

## 3. 输入 / 输出

### 3.1 输入

OmniLayout 的输入是**多模态、结构化的完整 PCB 设计上下文**。"多模态"指三种信息形态同时进入评测：

**文本模态：结构化设计数据**

```
Board Boundary: (0, 0) to (53.34, 40.64), size 53.34mm × 40.64mm, 2-layer
Board outline defined by board_boundary.dxf_details (JSON)

Component Block Dimensions:
- U1: ATmega328P, TQFP-32, 7.0mm × 7.0mm
  block: pad:smd (front) 0.5mm × 1.2mm at (3.0, -2.5)
  block: pad:smd (front) 0.5mm × 1.2mm at (3.5, -2.5)
  ... (32 pads total)
- R1: Resistor, 0805, 2.0mm × 1.2mm
  block: pad:smd (front) 0.6mm × 1.0mm at (-0.8, 0)
  block: pad:smd (front) 0.6mm × 1.0mm at (0.8, 0)

Allowed rotation codes:
  R0: front side, 0°      R180: front side, 180°     R270: front side, 270°
  MR0: back side, 0°       MR180: back side, 180°     MR270: back side, 270°

Netlist (connections):
- Net 'N$3': U1:5, R1:2, C3:1
- Net 'N$7': R1:1, GND
- Net 'SCL': IC2:16, R1:1  (spatial weight: 0.58)
```

**图像模态：原理图渲染图**

从原始 `.sch` 文件渲染的原理图图像（PNG/JPEG），包含符号位置、连线、网络标号等视觉信息。LMM 需从图像中理解电路拓扑——哪些元件在原理图上靠近、哪些信号路径属于同一功能模块。

**图模态：拓扑结构图**

- **Sch. SW-Net.（Schematic Spatial-Weighted Netlist）**：带空间权重的原理图坐标系网表，每条 pin-pin 边的 weight 反映两符号在原理图上的相对距离
- **Full-Graph（空间-语义联合图）**：原理图拓扑 + 元器件语义属性（类型、值、封装）的异构图，额外包含符号/引脚/网络节点的属性标注

**Agentic 变体的额外输入**

每轮迭代额外接收：上一轮的 placement JSON + 当前布局渲染图像 + 工具检查结果（overlap 违规列表/越界报告/HPWL/routability 分数）+ 历史摘要 `history_summary_json`。

### 3.2 输出

**布局结果 JSON**（schema-valid，所有元件必须恰好出现一次）：

```json
{
  "placements": [
    {"name": "U1", "x": 15.2, "y": 22.8, "rotation": "R0"},
    {"name": "R1", "x": 18.5, "y": 20.1, "rotation": "R90"},
    {"name": "C1", "x": 12.0, "y": 25.3, "rotation": "MR0"}
  ]
}
```

- `x/y`：元件中心相对板框原点的毫米坐标（浮点数）
- `rotation`：R0/R90/R180/R270（顶层）或 MR0/MR90/MR180/MR270（底层镜像放置）
- Agentic 模式下额外包含 `decision` 对象（action/inspection_tools/quality_score/thought/visual_feedback）

**评价指标值**：四维度 12 项指标（详细定义见第 6 节）

## 4. Benchmark 构建方法

### 4.1 数据来源与采集

OmniLayout 的 1,681 个 PCB 设计来自六大开源硬件平台的 Autodesk EAGLE 项目：

- **SparkFun Electronics**：开源电子模块设计
- **Arduino**：开源微控制器平台
- **Adafruit Industries**：开源电子元件与开发板
- **GitHub**：社区贡献的 PCB 设计项目
- **Seeed Technology**：开源硬件设计
- **ProtoCentral**：开源医疗电子

选择 EAGLE 格式的工程原因是：EAGLE 使用 XML 格式存储设计文件，可以**程序化解析**电路结构和连接信息，无需手工标注。

### 4.2 自动标注流水线（论文 Figure 5）

论文开发了一套**源驱动（source-driven）的自动标注流水线**，直接从 EAGLE XML 文件中提取需要的所有标注信息：

**原理图侧标注**：采用 OmniSch（Lu et al. 2026）的渲染引擎，解析 EAGLE XML 原理图文件生成高保真原理图图像，同时输出像素对齐的符号实例、引脚、文本属性、网络标签、连线和结点标注。这些标注作为评估电气功能保持的参考信号。

**布局侧标注**：开发专用 PCB 布局渲染引擎，解析 EAGLE XML 版图文件中的元件实例名称、参考封装定义、焊盘级块尺寸、网络拓扑和每个元件的位置/旋转属性。版图边框几何从嵌入版图文件的 DXF 编码边界基元中恢复。

**跨文件对齐**：通过共享的元件实例标识符，将原理图侧的连通性信号与布局侧的 placement ground truth 自动配对。

**三层标注体系**：

1. **Schematic-Coupled Layout Design**：每个布局元件标注名称、值、参考位号、位置、方向、层分配；对应原理图符号标注位置与引脚连通性
2. **Connectivity Annotations**：显式 pad-pad 连接关系与网络语义标签（139.4K 网络）
3. **Functional Spatially-Weighted Netlist Annotations**：两种空间加权网表图——layout 坐标系（参考布局元件距离）和 schematic 图像坐标系（原理图符号距离），用于评估电气功能保持

### 5.2 四类任务定义

OmniLayout 将 PCB 布局形式化为四类约束感知几何推理任务：

| 任务 | 核心问题 | 输入差异 | 关键评估维度 |
|------|------|------|------|
| **Task 1: 几何/空间推理** | 在 irregular 板框内放置元件，满足不重叠、在边界内、层约束 | 基础信息（板框、元件尺寸、旋转码、层约束） | OO, OoB, P-Pass |
| **Task 2: 可布线性感知布局** | 在几何合法基础上，最小化 HPWL，减少 net crossing，使布局对布线友好 | 基础信息 + 空间加权网表 | HPWL, NC, NS, PRWL, RR, #Vias, R-Pass |
| **Task 3: 电气功能保持** | 预测布局保持原理图定义的子电路拓扑、引脚连通性与信号路径 | 基础信息 + 原理图网表图 / Full-Graph | Sch., Ref. |
| **Task 4: 工具增强迭代** | 将布局建模为迭代决策，LMM 调用外部工具逐步优化 | 每轮额外输入：布局渲染图 + 工具检查结果 + 历史摘要 | OO, OoB, Step, 所有可布线性指标 |

### 5.3 评测设置

**Zero-shot 评测**：LMM 被 prompt 一次，不做中间交互。五种 prompt 变体：
- **Zeroshot**（Baseline）：仅板框 + 元件尺寸 + 网表 + 旋转码
- **Sch. SW-Net.**：附加带空间权重的原理图网表图（JSON 格式）
- **Sch. Sem.**：附加元器件语义属性（类型、值、封装）
- **Sch. Img.**：附加原理图渲染图像（PNG/JPEG）
- **Fewshot**：附加 1 个完整示例（原理图+网表+专家布局），要求模仿布局策略

**Agentic 评测**：LMM 配备三个工具，在 ReAct 循环中迭代优化，最多 50 轮。四种工具配置：
- **Visualization**：仅提供布局渲染图像作为反馈
- **Geo. Check**：仅提供确定性几何重叠检测结果
- **Routing Score**：仅提供 HPWL-based 可布线风险评分
- **All Tools**：同时提供三种工具，LMM 自主选择使用哪些

**Baseline 对比**：Quilter（RL-based 商业 PCB 布局器）、PCBAgent（LLM + RL Agent）、SA-PCB（模拟退火布局器）、NS-Place（力导向+搜索）、Cypress（GPU 加速布局器）、Chen et al.（GNN 方法）、Human Engineer（专家参考布局）。

### 5.4 评测的 LMM 清单

## 6. 评测协议与打分

### 6.1 问题形式化

PCB 布局评估被形式化为约束优化评估问题。给定元件集合 $V$、网络集合 $E$ 和板框边界 $B$，布局质量由以下目标函数衡量：

$$
\min_{x,y,\theta,l} \; W(x, y, \theta) + \lambda_1 C_{\text{p2p}}(x, y) + \lambda_2 D(x, y, \theta, l) + \lambda_3 F(x, y, x^*, y^*)
$$

subject to:

$$
\theta_i \in \{0^\circ, 90^\circ, 180^\circ, 270^\circ\},\quad l_i \in \{\text{top}, \text{back}\},\quad \forall v_i \in V,\quad (x_i, y_i) \in B
$$

- $W(x, y, \theta)$：总线长（HPWL），作为布线效率的代理指标
- $C_{\text{p2p}}(x, y)$：pad-to-pad 间距违规惩罚
- $D(x, y, \theta, l)$：元件重叠惩罚（跨两层分别计算）
- $F(x, y, x^*, y^*)$：电气功能保持指标

### 6.2 几何合法性指标

**归一化重叠面积 OO（Overlap Overlap）**：

$$
OO(P) = \frac{\sum_{i<j} \text{Area}(B_i \cap B_j)}{\sum_i \text{Area}(B_i)}
$$

- $B_i$：元件 $i$ 的包围矩形（含所有 block：焊盘、本体、孔）
- $\text{Area}(B_i \cap B_j)$：$B_i$ 和 $B_j$ 的重叠面积
- 理想值 $OO = 0$，表示无元件碰撞

**越界比例 OoB（Out-of-Boundary）**：

$$
OoB(P) = \frac{\sum_i \text{Area}(B_i \setminus B_{\text{board}})}{\sum_i \text{Area}(B_i)}
$$

- $B_{\text{board}}$：板框多边形区域（非矩形包围盒，支持 irregular outline）
- $\text{Area}(B_i \setminus B_{\text{board}})$：元件 $i$ 落在板框外的面积
- 理想值 $OoB = 0$

**P-Pass（Placement Pass Rate）**：OO 和 OoB 同时满足阈值要求的测试样本比例（%）。

**RT（Reasoning Time）**：LMM 端到端推理耗时（秒），不含工具调用时间。

### 6.3 可布线性指标

**HPWL（Half-Perimeter Wirelength，半周长线长）**：

$$
HPWL(P) = \sum_{n \in N} \left[ \left(\max_{i \in n} x_i - \min_{i \in n} x_i\right) + \left(\max_{i \in n} y_i - \min_{i \in n} y_i\right) \right]
$$

- $N$：所有网络的集合
- $(x_i, y_i)$：网络 $n$ 中引脚 $i$ 的物理坐标
- HPWL 是最常用的布线前线长估计量，值越小说明连通元件放置越紧凑

**NC（Net Crossing，网线交叉数）**：

$$
NC(P) = \sum_{n_i \in N} \sum_{n_j \in N, j > i} \mathbb{I}\left[ e_{n_i} \cap e_{n_j} \neq \emptyset \right]
$$

其中 $e_{n_i}$ 和 $e_{n_j}$ 分别表示网络 $n_i$ 和 $n_j$ 的直线段连接。NC 是预测布线拥塞的简单代理指标。

**NS（Net Separation，引脚平均间距）**：

$$
NS(P) = \frac{1}{|N|} \sum_{n \in N} \frac{1}{|n|} \sum_{i \in n} \|p_i - \bar{p}_n\|_2
$$

- $p_i$：引脚 $i$ 的位置
- $\bar{p}_n$：网络 $n$ 的引脚质心
- 值越小说明连通引脚越靠近

**PRWL（Post-Routing Wirelength，实际布线后总线长）**：

$$
PRWL(P) = \sum_{n \in N} \sum_{e \in R_n} \|e\|_2
$$

- $R_n$：网络 $n$ 布线后的线段集合
- $\|e\|_2$：线段 $e$ 的欧氏长度
- 使用开源布线器 FreeRouting 完整布线后统计，是**可布线性的最终 ground truth**

**RR（Routing Rate，布线成功率）**：

$$
RR(P) = \frac{|N_{\text{routed}}|}{|N|}
$$

- $N_{\text{routed}}$：FreeRouting 成功布线的网络数
- $|N|$：总网络数
- 理想值 $RR = 1.0$（所有网络布线成功）

**#Vias（过孔数）**：FreeRouting 布线产生的过孔总数，值越小越好。

**R-Pass（Routing Pass Rate）**：RR 超过阈值的样本比例（%）。

### 6.4 电气功能保持指标

**Sch.（Schematic Distance，原理图相对距离偏差）**：

$$
D_{\text{sch}}(P, S) = \frac{1}{|G|} \sum_{(i,j) \in G} |d_P(i, j) - d_S(i, j)|
$$

- $G$：同一子电路内的元件对集合
- $d_P(i, j)$：预测布局中元件 $i$ 和 $j$ 的欧氏距离（归一化）
- $d_S(i, j)$：原理图图像中符号 $i$ 和 $j$ 的像素距离（归一化）
- 衡量布局是否保持了原理图中的子电路视觉拓扑邻近性

**Ref.（Reference Distance，参考布局偏差）**：

$$
D_{\text{ref}}(P, R) = \frac{1}{|G|} \sum_{(i,j) \in G} |d_P(i, j) - d_R(i, j)|
$$

- $d_R(i, j)$：专家参考布局中元件 $i$ 和 $j$ 的距离（归一化）
- 与 Sch. 形式相同但将原理图坐标系替换为专家参考布局坐标系

**E2E Pass（端到端通过率）**：同时满足几何合法 + 布线通过 + 电气功能通过的样本比例（%），是最严格的综合指标。

### 6.5 Agentic 指标

**Step（收敛步数）**：Agent 达到合法布局所需的平均工具调用步数。在 50 轮上限内，Step 越小收敛效率越高。论文还定义了 Constraint Satisfaction Rate（最终布局满足约束的比例）和 Placement Refinement Quality（连续迭代改善的比例），但以 Step 为 agentic 主指标。

## 8. 创新点

### 创新点 1：首个 PCB 布局大规模多模态 benchmark

在 OmniLayout 之前，AI4EDA 的布局研究几乎全部聚焦于数字 IC。OmniLayout 首次将评测体系扩展到 PCB 领域，规模达 1,681 个工业级设计、77.24K 元件——远超以往任何 PCB 布局数据集（上一最大数据集 Cypress 仅 10 个设计，1.2K 元件）。所有设计均来自真实开源硬件项目，非合成数据。论文 Table 1 系统对比了 OmniLayout 与已有数据集的差距——不仅规模大两个数量级，而且是首个同时提供原理图配对、专家参考布局、电气功能标注和语义属性的 benchmark。

### 创新点 2：原理图耦合的多模态设计上下文

与现有工作仅给网表不同，OmniLayout 同时提供原理图渲染图像、拓扑图、空间加权网表和语义属性。这种"多模态"的核心动机是：PCB 布局工程师在工作时不是只看网表——他们同时参考原理图理解功能分组和信号流向。OmniLayout 首次在 benchmark 层面复现了这一真实工作流。实验数据验证了模态的差异化价值：Sch. SW-Net.（空间加权网表）在所有模型上普遍改善了 PRWL 和 RR，但 Sch. Img.（原理图图像）对多数模型的提升有限——GPT-5.5 的 Sch. Img. 结果与 Zeroshot 几乎一致（OO 0.07 vs 0.07，HPWL 628.78 vs 628.78），说明当前 LMM 从原始原理图渲染图像提取拓扑信息的能力仍然有限。

### 创新点 3：四维统一评估协议 + 实际布线验证

现有 PCB 布局评测最多做到几何合法（不重叠），OmniLayout 将评估扩展到四个维度：几何合法性 → 可布线性（FreeRouting 实际布线验证）→ 电气功能保持（原理图拓扑一致性）→ Agentic 收敛效率。特别是**实际布线验证**——不满足于 HPWL 估计，而是用 FreeRouting 跑完整布线后统计 PRWL/RR/#Vias。这是业界首次在 benchmark 层面集成该验证。实验数据显示 HPWL 和 PRWL 之间的相关性并非总是线性——低 HPWL 不一定意味着高 RR（GPT-5.5 Agentic Visualization 的 PRWL=113.94 但 RR=0.59），验证了实际布线在评测体系中的必要性。

### 创新点 4：源驱动的自动标注流水线

基于 Autodesk EAGLE XML 格式自动解析 layout/schematic/netlist，实现原理图符号与版图元件的自动配对。这一流水线避免了昂贵的人工图像标注，同时布局渲染引擎还可在 agentic 评测中作为交互式可视化工具，向 LMM 提供当前 placement 状态的视觉反馈。相比纯手工图像标注，源驱动策略提高了一致性、消除了密集元件布局中的几何歧义，并可高效扩展到大规模 benchmark 集合。

### 创新点 5：系统揭示 LMM 在几何推理上的关键缺陷

通过 zero-shot / few-shot / agentic 三重设置 + 10 个 LMM + 7 个 baseline 的系统评测，论文揭示了若干此前未被量化的缺陷：
- 几何推理在 >40 元件时性能断崖式下降
- 约 80% 元件被放在顶层，多层板空间利用率极低
- 与专家参考布局的平均相似度低于 60%
- Few-shot 提升 P-Pass 但牺牲 HPWL/NC——过拟合到单一样例
- Qwen 模型在 agentic 设置下完全无法输出结构化 placement
- "All Tools" 对某些模型反而增加收敛步数

## 10. 评测公平性与可信度分析

### 10.1 Benchmark 的公平性

**正面因素**：

1. **全自动化评测**：所有 12 项指标均为工具自动判分（几何算法、FreeRouting、视觉-距离计算），不依赖人工评分
2. **统一布线环境**：所有方法使用相同的 FreeRouting backbone 和 DSN 导出规则，布线设置（2 层、via radius 16 mil、clearance 8-10 mil）保持一致
3. **Baseline 覆盖全面**：包括商业工具（Quilter）、学术方法（SA-PCB/NS-Place/Cypress/PCBAgent/Chen et al.）和人工专家，横向对比维度完整
4. **原理图耦合的设计使"作弊"困难**：如果只给网表，LMM 可以通过随机放置+后处理优化达到可接受的 HPWL；但原理图子电路拓扑距离（Sch.）要求布局保持功能分组，这迫使模型真正理解电路结构
5. **多模型多设置横向对比**：10 个 LMM × 5 种 prompt × 4 种 agentic 配置 = 全面覆盖，避免"挑最好模型+最好配置"的选择性报告

**需要谨慎解读的方面**：

1. **数据来源偏 DIY/开源**：主要来自 SparkFun/Arduino/Adafruit 等开源硬件平台，对高速数字、射频、高密度 HDI（High Density Interconnect）等先进工业 PCB 覆盖不足。开源硬件的布局复杂度（平均 45.95 元件/设计）可能低于工业 PCB
2. **Fewshot 示例可能不公平**：论文只提供 1 个示例，且该示例的策略（"把退耦电容放在 IC 附近"）可能对某些类型的设计有效、对另一些无效——这引入了"示例匹配度"的不可控变量
3. **Agentic 50 轮上限**：复杂设计可能需更多迭代，50 轮不足以判断真实收敛极限。论文自己承认了这一点
4. **PCB 布局不存在唯一 ground truth**：Sch. 和 Ref. 指标衡量的是相对距离偏差，但两个完全不同的布局可能有相同的拓扑保持分数——这使得 E2E Pass 的定义偏向"接近参考布局"而非"功能等价"

### 10.2 实验的局限性

1. **工具组合未穷尽**：Agentic 评测只覆盖了单工具和全部工具两种极端，未探索部分组合（如 Geo. Check + Routing Score 不给 Visualization）的效果
2. **LMM 不参与布线决策**：使用 FreeRouting 作为固定 backbone 评估 placement 质量，placement → routing 的协同优化留待未来——这可能低估了 LMM 在 placement 阶段为 routing 做优化决策的潜力
3. **电气功能指标是代理指标**：Sch. 和 Ref. 是拓扑/距离相似度，不等价于完整的功能验证（SPICE 仿真）或信号完整性 signoff
4. **输出鲁棒性问题**：Qwen 模型在 agentic 设置下无法生成结构化 placement JSON，这表明当前 benchmark 对模型的 schema-following 能力有隐性要求——一个本来几何推理能力尚可的模型可能因为无法输出正确 JSON 而被判零分

### 10.3 与数字 IC Placement benchmark 的对比

| 维度 | ICCAD/ISPD Placement Contest | OmniLayout |
|------|------|------|
| 领域 | 数字 IC 标准单元 | PCB 分立元件 |
| 规模 | 百万~亿级标准单元 | 百~千级元件 |
| 评测重点 | HPWL + 拥塞 + 时序 slack | HPWL + 实际布线 PRWL/RR + 原理图拓扑保持 |
| 优化器类型 | 解析法/合法化/详细摆放（C++） | LMM 推理（自然语言+图像+图） |
| 对 AI 研究的意义 | 为传统 EDA 算法提供 benchmark | 为 LMM 的几何推理和约束满足能力提供评测平台 |
| 数据开放性 | 多为 synthetic/industrial（受限） | 开源硬件平台（CC-BY-4.0） |

## 11. 讨论与局限

### 11.1 论文自述的局限

1. **迭代轮数上限**：Agentic 最多 50 轮，复杂设计可能需更长收敛过程。论文指出主要限制是迭代推理的计算成本和资源需求
2. **工具组合未穷尽**：仅评估了单工具和全部工具两种极端，如 Visualization + Geo. Check 的部分组合未探索
3. **布线优化未直接研究**：使用 FreeRouting 作为固定 backbone，LMM 不参与布线决策——placement → routing 的协同优化是独立研究方向
4. **数据集来源偏 DIY**：主要来自开源硬件平台，可能缺少高速/射频/HDI 设计，未知偏差可能影响评估结果
5. **电气功能指标是代理**：Sch. 和 Ref. 是拓扑相似度，非完整功能验证

### 11.2 代码/复现层面的问题

1. **Benchmark 可复现性待核验**：论文声称以 CC-BY-4.0 发布代码与数据，但截至成文，项目页面（omnieda.com）仅提供 Google Drive 样本数据和可视化代码。完整 benchmark 的评估 pipeline、schema 校验器、FreeRouting 集成脚本等可执行入口仍需社区验证
2. **Baseline 方法需要独立复现**：Quilter（商业）、SA-PCB、Cypress 等 baseline 需要各自的环境配置，论文未提供统一的 baseline 运行脚本
3. **Prompt 模板的敏感性**：论文在附录 C 中给出了完整 prompt 模板，但不同 LMM 对 prompt 措辞的敏感度差异未被系统研究——同一个 placement 问题，prompt 微调可能导致 5-10% 的性能波动

### 11.3 本资料包的批判性分析

**关于"多模态"的真实效用**：

实验数据揭示了一个关键事实：**不同模态输入的收益高度依赖模型和指标**。Sch. SW-Net.（结构化图输入）在所有模型上普遍改善了 PRWL 和 RR——GPT-5.5 的 PRWL 从 479.03 降至 390.10。但 Sch. Img.（原理图图像）对多数模型的提升有限——GPT-5.5 的 Sch. Img. 结果与 Zeroshot 几乎一致。这意味着：
- 结构化图输入比原始图像对当前 LMM 更有效——LMM 从原始原理图渲染图像中提取拓扑信息的能力仍然有限
- "多模态"的边际收益不是均匀的——benchmark 设计者应意识到，某些模态可能只是增加了 prompt 复杂度而没有提供可操作的信号

**Few-shot 的"退化"风险**：

Few-shot 几乎在所有模型上提升了 P-Pass（GPT-5.5 从 72.04% 升至 99.01%），但同时**增加了 HPWL 和 NC**。这是典型的过拟合到单一样例——示例布局可能是"元件均匀分散放置"策略，这保证了不重叠但牺牲了可布线性。当前 Few-shot 设计（仅 1 个示例）存在严重的选择偏差，未来应研究 multi-example 或 adaptive example selection。

**Agentic 模式的现实性**：

Agentic 模式下最优配置（Gemini 3.1 Pro-Pro-Preview, All Tools）的 OO=0.000、OoB=0.000、Step=5.04——几何上几乎完美。但这是建立在**外部确定性几何检查器**基础上的。Agent 本身不"理解"重叠，而是依赖黑盒工具报告违规后被动修正。这引出关键问题：当前的 LMM 到底是"学会了几何推理"还是"学会了调用工具绕过几何障碍"？如果移除确定性 overlap checker，给一个基于视觉图像判断重叠的"软检查器"，性能会如何？这将是未来的关键消融实验。

**Qwen 模型的输出鲁棒性**：

Qwen3.5-9B 和 Qwen3.6-35B-A3B 在 Agentic 评估中完全无法生成符合 schema 的 placement JSON（表格中全为"—"），但在 zero-shot 下反而能输出结构化结果。这表明当 prompt 长度和复杂度增加（agentic 的上下文包含多轮历史+工具反馈+渲染图描述），小模型的 schema-following 能力急剧退化。这为 LMM-based Agent benchmark 的设计者提出了重要问题：**benchmark 是否应该在评估 geometric reasoning 前先评估 schema adherence 并据此筛选模型？**

**对 AI4EDA 数字芯片方向的启示**：

OmniLayout 的评测框架设计对芯片 AI4EDA 研究有直接参考价值：
1. **四维评测协议**可迁移到芯片布局评测：几何合法（对应 Congestion）+ 可布线性（PRWL/RR）+ 功能保持（对应时序）+ Agentic 效率
2. **实际布线验证**的思路——不满足于 HPWL 估计，跑真实 router——同样适用于芯片 Placement 评测
3. **PCB 的多模态输入（原理图图像+网表+板框）天然适合 LMM**，而芯片 Placement 的输入是纯结构化数据（门级网表+LEF/DEF），图像模态无天然对应——这提示芯片 AI4EDA 可能需要开发相应的"版图渲染图作为视觉反馈"机制

## 13. 一分钟复述版

OmniLayout（arXiv 2026，Penn State + 上海交大 + Microsoft Research）是 PCB 布局领域的首个大规模多模态 benchmark——不训练模型，只评测 LMM 的约束感知几何推理能力。

数据集：1,681 个真实 PCB 设计（SparkFun/Arduino/Adafruit 等开源硬件平台），77.24K 元件，168.8K 焊盘，139.4K 网络。每个设计配对原理图渲染图 + 空间加权网表图 + 专家参考布局。

任务：四个递进层次——几何推理（不重叠+在板框内）、可布线性（FreeRouting 实际布线验证 PRWL/RR/#Vias）、电气功能保持（原理图子电路拓扑一致性）、工具增强迭代（LMM 调用可视化/重叠检查/布线评分工）。

评测：10 个 LMM（GPT-5.5 到 Qwen3.5-9B），zero-shot / few-shot / agentic 三种设置，7 个 baseline 对比（Quilter 商业工具到 Human Engineer）。

核心发现：当前 LMM 在 PCB 布局上表现远不及人工——最优 E2E Pass 仅 58.18%（Gemini 3.1 Pro + Sch. SW-Net.），空间利用率极差（80% 元件单层堆积），与专家布局相似度低于 60%。Agentic 工具反馈可显著改善几何合法性（OO/OoB 降至接近 0），但对可布线性的提升有限——低 HPWL 不一定意味着高 RR。Few-shot 提升 P-Pass 但牺牲 HPWL（过拟合）。Qwen 模型在 agentic 下完全无法输出结构化 placement。

工程价值：为 LMM 几何推理能力提供了前所未有的系统评测平台。其四维评测协议（几何+布线+功能+agentic）和"实际布线验证"思路可迁移到芯片 AI4EDA。数据集规模比此前最大 PCB 数据集大 100 倍以上，且是首个提供原理图配对和电气功能标注的 benchmark。
