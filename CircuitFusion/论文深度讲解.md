## 1. 一句话定位

本节要解决的问题是：CircuitFusion 到底把什么信息编码到一个可迁移的电路表示中，以及这种表示带来了多大的早期设计质量预测收益。

**CircuitFusion 是一个面向 RTL 的多模态、实现感知电路编码器：它把同一寄存器子电路的 HDL 代码、结构图和功能摘要通过三个单模态编码器与 summary-centric cross-attention 融合，再用 RTL--netlist 对齐注入实现信息，并以检索增强推理支持五类设计质量预测；在 41 个设计、7,166 个对齐 RTL/netlist 子电路对和等价变换扩充到 57,328 个子电路的实验中，微调后的 MAPE 达到 slack 12%、WNS 11%、TNS 15%、power 13%、area 11%，且 top-1 零样本检索的 MAPE 分别为 21%、36%、35%。**

这句话里的 6 个承重点，后面逐一拆解：

1. **从整电路转成寄存器子电路** — 电路具有并行执行特性；论文按 sequential-element boundary 拆分，每个寄存器向后回溯所有组合输入逻辑。这样既保留一个时钟周期内的状态更新，又把原本数万图节点、数百万代码 token 的输入缩小到可编码的粒度。

2. **三种 RTL 模态互补** — HDL code 同时含有功能和实现线索，graph 强调运算符连接结构，summary 用自然语言概括功能与实现细节。论文不是把三种输入简单拼接，而是分别编码后再做跨模态融合。

3. **四个电路特性对应四个策略** — P1 并行执行对应 S1 子电路生成；P2 功能等价变换对应 S2 语义-结构预训练；P3 多设计阶段对应 S3 implementation-aware alignment；P4 电路可复用对应 S4 retrieval-augmented inference。

4. **实现感知而非只看 RTL** — 训练时额外使用 gate-level netlist graph encoder，将 RTL 子电路的融合表示与同一子电路的 netlist 表示拉到共享空间。推理 RTL 阶段没有 netlist，因此 auxiliary netlist encoder 会被丢弃。

5. **从预训练表示到设计质量** — 模型服务于 register slack、WNS、TNS、total power、total area 五个任务；前者在子电路级评估，后四者在整电路级评估。CircuitFusion 在 Table 2 的五个任务上均超过列出的硬件、文本和软件代码基线。

6. **检索让零样本成为可能** — 先把已知电路的融合 embedding 存入 VectorStore，再为新子电路取 cosine similarity 最高的已知子电路；其 timing、power、area 等指标可以直接做 zero-shot 预测，或作为额外特征交给回归器。

## 2. EDA 阶段映射（①-⑰）

本节要解决的问题是：CircuitFusion 位于数字芯片流程的哪里，哪些阶段是它直接处理的，哪些阶段只是产生训练标签或属于下游。

参照[芯片流程.md](../芯片流程.md)的 17 阶段标准编号。需要特别区分“模型预测该阶段产生的质量指标”和“模型亲自执行该阶段”。

| 阶段 | 覆盖 | 说明 |
|------|:---:|------|
| **① RTL 设计** | ✅ **核心** | 输入是 RTL 阶段的 HDL code；模型学习 RTL 的功能、结构和实现线索，为设计者在写 HDL 时提供早期 quality feedback。 |
| **② RTL 功能仿真** | ❌ | 论文没有把功能仿真或 testbench 作为 CircuitFusion 的输入，也没有报告仿真通过率；其训练目标是表示学习与设计质量预测。 |
| **③ 逻辑综合** | ✅ **标签生成** | 论文用 Synopsys Design Compiler 和 NanGate 45nm library 把 RTL synthesis 成 gate-level netlist；这一阶段为实现感知对齐和 PPA 标签提供数据，但不是模型推理阶段。 |
| **④ 门级仿真** | ❌ | 原文未将 SDF gate-level simulation 纳入方法、标签或实验任务。 |
| **⑤ STA（静态时序分析）** | ✅ **预测目标** | PrimeTime 在综合后产生 register slack、WNS、TNS；CircuitFusion 在 RTL 阶段预测这些 post-synthesis timing 指标，避免设计者等待完整下游流程。 |
| **⑥ 形式验证** | ❌ | 论文没有做形式等价性证明或 SAT/SMT 验证。 |
| **⑦ 布局规划（Floorplan）** | ❌ | 没有使用宏单元位置、IO、供电网络或 floorplan 特征。 |
| **⑧ 标准单元摆放（Placement）** | ❌ | 没有执行或预测标准单元的物理摆放。 |
| **⑨ 时钟树综合（CTS）** | ❌ | 论文讨论单时钟以及 multi-clock 的 timing-group 评估，但没有 CTS 建树或 clock skew 优化。 |
| **⑩ 布线（Routing）** | ❌ | 没有提取布线长度、寄生参数或 routing congestion。 |
| **⑪ 后仿真** | ❌ | 没有使用 SDF、SPEF 或带寄生 RC 的门级仿真。 |
| **⑫ 物理验证（DRC/LVS）** | ❌ | 没有版图几何规则检查，也没有 layout-versus-schematic 比较。 |
| **⑬ 签核（Signoff）** | ❌ | 预测 WNS、TNS、power、area 不等于完成 STA、功耗和 IR-drop signoff；论文没有生成 GDSII。 |
| **⑭ 流片** | ❌ | 不涉及把版图发送给代工厂。 |
| **⑮ 制造** | ❌ | 不涉及光刻、刻蚀、掺杂等制造工序。 |
| **⑯ 封装 + 测试** | ❌ | 不涉及晶圆切割、封装或 ATE 测试。 |
| **⑰ 芯片到手** | ❌ | 不涉及实物芯片的实验反馈。 |

**覆盖率：3/17。** CircuitFusion 的准确定位是“① RTL 设计阶段的表示学习与早期质量预测”，借助 ③ 逻辑综合生成实现阶段数据，并把 ⑤ STA 产生的时序指标以及综合后的功耗、面积作为预测标签；它没有替代后续物理实现。

> ⚠️ 最容易被误读的边界：论文的“实现感知”来自训练时可获得的 netlist 以及 PrimeTime/Design Compiler 产生的标签；RTL-stage inference 时 netlist encoder 被丢弃。因此它不是一个在推理时运行综合或 STA 的 EDA 工具，而是学习跨阶段相关性的预测模型。

## 3. 输入 / 输出

本节要解决的问题是：从一段真实 HDL 到模型可以使用的子电路 embedding，数据到底长什么样，并如何回到设计质量预测。
### 3.1 输入
#### 输入 A：RTL HDL code

论文接受的原始 HDL 可以来自 Verilog、VHDL 或 Chisel；为统一处理，使用开源工具自动转换为 Verilog。下面选用论文 Appendix B.2 的 `coi` 设计片段，保留了输入、内部 wire、组合 assign 和时序寄存器。

```verilog
module coi (clk, rst, shift_cnt, shift_tip, shift_data,
            wb_adr_i, clgen_pos_edge, ctrl, clgen_neg_edge,
            wb_stb_i, wb_cyc_i, shift_s_out);
  input clk, rst, clgen_neg_edge, clgen_pos_edge, ctrl;
  input [4:0] wb_adr_i;
  input shift_cnt, shift_data, shift_tip, wb_cyc_i, wb_stb_i;
  output reg shift_s_out;
  wire _008_, _019_, _056_, _088_, _093_, _096_, _097_, _177_;
  wire [7:0] _184_, _185_;
  wire clgen_last_clk, shift_tx_clk, _179_, _180_, _194_;
  assign _008_ = wb_cyc_i & wb_stb_i;
  assign _019_ = wb_adr_i[4:2] == 32'd1;
  assign shift_tx_clk = _194_ && _096_;
  assign _088_ = ! shift_tip;
  assign _093_ = ! _177_;
  assign clgen_last_clk = ! _179_;
  assign _096_ = ! clgen_last_clk;
  assign _097_ = shift_tx_clk || _088_;
  assign _177_ = | ctrl[6:0];
  assign _179_ = | shift_cnt;
  assign _180_ = _510_[shift_tx_bit_pos[6:0] +: 1];
  assign _184_ = { _093_, ctrl[6:0] } - shift_cnt;
  assign _185_ = shift_cnt - 8'h01;
  assign _056_ = _097_ ? _180_ : shift_s_out;
  assign shift_tx_bit_pos = ctrl[11] ? _184_ : _185_;
  assign _194_ = ctrl[10] ? clgen_neg_edge : clgen_pos_edge;
  always @(posedge clk) begin
    shift_s_out <= _056_;
  end
endmodule
```

这段代码中，`shift_s_out` 是目标寄存器；`_056_` 是其下一状态输入；`_097_`、`_180_`、`shift_tx_bit_pos` 等信号构成一个寄存器的组合输入锥。论文的子电路生成算法正是从寄存器出发，沿组合逻辑回溯，直到相关输入或寄存器。
#### 输入 B：RTL 结构图

HDL 先解析成 AST，再构建 control data flow graph。图节点包括 sequential registers 和组合 operators，论文 Figure 7b 举例的运算节点包括 AND、ADD、EQUAL、MUX；HDL 中连接元素的 wire 变为 graph edge。

下面是对上述片段的**最小可读图格式示例**。它用于说明数据格式，不声称是论文图中全部节点；完整图还会包含其它寄存器、输入和中间运算。

```text
[Input wb_cyc_i] ──┐
                   ├──▶ [AND _008_] ──▶ [EQUAL _019_]
[Input wb_stb_i] ──┘

[Input shift_tip] ──▶ [INV _088_] ──┐
                                    ├──▶ [OR _097_] ──▶ [MUX _056_]
[shift_tx_clk] ─────────────────────┘                    │
                                                         ▼
                                                [Register shift_s_out]
                                                         ▲
[ctrl] ─▶ [OR _177_] ─▶ [INV _093_] ─────────────────────┘
```

图的重点不是把 Verilog token 原样复制，而是把操作类型、寄存器、输入以及连接关系显式化。这样 graph encoder 能利用 operator connectivity，且同一个 register cone 可以和 netlist-stage 的 gate graph 对齐。
#### 输入 C：功能摘要

论文用 GPT-4o（原文写作 GPT-4o from Open-AI）为每个 sub-circuit 生成 functionality 与 implementation details 摘要。Figure 7c 给出的摘要强调 `shift_s_out`、shift register control、SPI transmission、control signals 和 data shifting。其格式可以具体写成：

```text
Functionality Summary
The Verilog design, `shift_s_out`, is a combinational circuit that takes
multiple inputs and produces a single output, `shift_s_out`. The circuit
appears to be a part of a larger system, likely a SPI (Serial Peripheral
Interface) transmitter, and is responsible for shifting data out of a shift
register.

Implementation Details
Assignment statements define intermediate relationships such as
`assign _008_ = wb_cyc_i & wb_stb_i;`. An always block updates
`shift_s_out` on the rising edge of `clk` with `shift_s_out <= _056_;`.
```

论文同时说明，子电路只聚焦单个寄存器一个时钟周期的组合逻辑，摘要模型不必处理整电路复杂的 sequential state transitions。
#### 输入 D：netlist graph（只在预训练）

训练数据中的 RTL 会通过工业标准逻辑综合流程变成 gate-level netlist。论文使用 Synopsys Design Compiler 的 `compile ultra`、NanGate 45nm technology library；netlist 中的 registers/flip-flops 和 AOI、INV、FA、AND 等 logic gates 作为节点，连接这些门的 wires 作为边。

```text
RTL register cone                    Netlist register cone
[shift_s_out]                        [DFF shift_s_out]
       ▲                                      ▲
   [MUX _056_]                         [AOI / MUX gates]
       ▲                                      ▲
[OR _097_], [INV _088_]             [OR, INV, AND, FA ...]
```

该 netlist 是训练时的 auxiliary input，不是 downstream RTL-only inference 的输入。它还提供后续 quality labels：PrimeTime 产生每个 register 的 slack 以及每个 RTL design 的 WNS、TNS、total power、total area。
### 3.2 中间产物
#### 中间产物 1：按寄存器切分的 sub-circuit

对每个 register，算法从该寄存器开始 breadth-first search，沿 outgoing connection 回溯组合逻辑；遇到 `reg` 或 `in` 类型节点就加入集合并停止沿该节点继续搜索。输出是该 register 及其相关输入/寄存器的集合。

```text
Whole RTL design
        │  sequential-element boundaries
        ▼
SC_1: register R0 + its combinational input cone
SC_2: register R1 + its combinational input cone
SC_i: register Ri + its combinational input cone
        │
        ├── HDL snippet C_i
        ├── operator graph G_i
        ├── GPT-4o summary S_i
        └── aligned netlist graph N_i (pre-training only)
```

切分有三个直接作用。第一，RTL 多模态与 cross-stage netlist 在功能上严格对齐。第二，一个 sub-circuit 覆盖该寄存器一个 clock cycle 的完整 state transition、timing paths 和 logic computations。第三，它提供 token/node 与整电路之间的中间粒度，使 slack 这类 sub-circuit-level task 有自然的表示。
#### 中间产物 2：三个 unimodal embedding 序列

每个 `SC_i` 进入三个独立 encoder，得到：

```text
G_i = {G_cls, G_1, ..., G_n}
S_i = {S_cls, S_1, ..., S_m}
C_i = {C_cls, C_1, ..., C_q}
```

其中 `[CLS]` embedding 代表整个 sub-circuit。Graph encoder 输出维度为 768；NV-Embed-V1 先生成 4096 维 code embedding，再线性投影到 768；summary encoder 使用 BERTbase 的前 6 层初始化。
#### 中间产物 3：融合表示与索引

Graph node embeddings 与 code token embeddings 先经过维度对齐与 mixup，summary token 作为 cross-attention query，混合的 graph-code embeddings 作为 key/value；最终得到融合序列 `{R_cls, R_1, ..., R_m}`。已知电路的融合表示被写入 VectorStore，供新设计检索。
### 3.3 输出
#### 输出 A：sub-circuit embedding

输出的核心不是一段新 Verilog，而是可用于不同下游任务的 `R_cls`。一个端到端的最小数据关系如下：

```text
coi RTL code
   │ parse / split at shift_s_out register
   ▼
(C_i, G_i, S_i, N_i)
   │ three RTL encoders + summary-centric fusion
   ▼
R_cls for the shift_s_out sub-circuit
   │
   ├── slack regression: one register-level quality value
   ├── retrieval: nearest known sub-circuit quality metrics
   └── circuit-level aggregation: combine all SC_i embeddings
```

论文不把 `R_cls` 解释成“某个固定物理量”；它是从多模态 RTL 学到的通用 circuit representation，后续由 task-specific regression model 映射到质量指标。
#### 输出 B：质量预测

五类输出及粒度为：

| 输出 | 粒度 | 含义 |
|---|---|---|
| Register slack | sub-circuit | 综合后寄存器满足或违反 timing constraint 的余量 |
| WNS | circuit | 全设计最大的 timing violation |
| TNS | circuit | 全设计所有 negative slack 的总和 |
| Total power | circuit | 综合后电路总功耗估计 |
| Total area | circuit | 实现该设计所需的总硅面积估计 |
#### 输出 C：zero-shot 或 fine-tuning 结果

对于 zero-shot，top-1 检索到的已知 sub-circuit 的质量指标可以直接作为预测。对于 fine-tuning，检索到的 metrics 与目标 embedding 拼接，再交给回归模型；整电路任务则先把每个子电路的 embedding 与检索指标累加，并拼接 operator counts 等 design-level features。

## 4. 方法与架构

本节要解决的问题是：CircuitFusion 如何把三个模态、两个设计阶段和四个学习任务组织成一个可训练、可部署的 pipeline。
### 4.1 整体 Pipeline

Figure 2、Figure 3 和 Figure 4 分别对应数据预处理、预训练与 retrieval-augmented inference。下图把三张图串成一条从 RTL 到早期 quality prediction 的主线。

### 4.2 核心模块逐个详解
#### 模块 A：HDL 统一化、图构建与子电路生成

**核心理由**：硬件组合逻辑并行执行，寄存器在每个 clock cycle 更新；以寄存器为边界的 cone 比固定 token 截断更能保持一个状态更新的完整逻辑。

原始 HDL 可以是 Verilog、VHDL 或 Chisel，先用开源工具统一成 Verilog，再解析为 AST/CDFG。图节点包括 register、AND、ADD、EQUAL、MUX 等，wire 成为 edge；netlist 图则使用 FF、AOI、INV、FA、AND 等 gate-level 节点。

对每个 register，从该寄存器开始 breadth-first search，沿 outgoing connection 回溯组合逻辑，遇到 `reg` 或 `in` 就加入集合。输出 `SC_i`，每个包含 code、graph、summary，并在预训练集包含 aligned netlist graph。这样 RTL 三模态与 netlist 在功能边界上对齐，同时覆盖一个 clock cycle 的 state transition 和 timing paths；论文称子电路的 node/token 规模约比整电路小 1000 倍。
#### 模块 B：Graph、Summary 与 Code 三个 encoder

- **Graph encoder**：从头训练 7-layer Graphormer/graph transformer；graph positional encoding 支持最多 256 的 in-degree/out-degree，最大 spatial distance 为 5，edge dimension 为 12，hidden dimension 256、3 heads，输出 768 维 `{G_cls,G_1,...,G_n}`。
- **Summary encoder**：用 BERTbase 前 6 层初始化的 6-layer Transformer，编码 GPT-4o 为每个 `SC_i` 生成的 functionality/implementation summary，输出 `{S_cls,S_1,...,S_m}`。
- **Code encoder**：用最大 32K token 的 NV-Embed-V1 编码长 HDL；原始 4096 维经过线性投影到 768，encoder frozen，以便未来接入其它 LLM-based encoders。
#### 模块 C：Summary-centric fusion encoder

graph node embeddings 和 code token embeddings 先维度对齐，再用 interpolation coefficient `lambda` mixup。summary token 作为 cross-attention queries，mixup graph-code embeddings 作为 keys/values，融合输出 `{R_cls,R_1,...,R_m}`，其中 `R_cls` 是下游主要使用的表示。

summary 被置于中心是因为它提供 high-level semantic insights，graph/code 提供结构与实现细节。Figure 5 的 Grad-CAM visualization 显示，summary 描述 input signals 时会突出 code/graph 中对应信号，描述 conditional logic 时会突出相关 operations/signals。
#### 模块 D：Auxiliary netlist encoder

netlist encoder 只在 pre-training 出现。它把 gate-level netlist sub-circuit 编成 node embeddings，并对全部节点 mean pooling 得到 `N_pool`；由于 graph transformer 难处理 large、bit-blasted netlist，论文采用 3-layer GraphSAGE，hidden dimension 256，输出 768 维。它先用 netlist 的 masked graph modeling 与 graph contrastive objectives 预训练，RTL downstream inference 时被 discard。
#### 模块 E：四个 self-supervised tasks

1. **Task #1 intra-modal**：masked graph modeling 恢复 operator type；graph 与 summary 用 functionally equivalent transformation 生成 positive，batch 中其它功能样本作 negative。
2. **Task #2 cross-modal**：将同一 sub-circuit 的 summary 分别与 graph、code 对齐到 shared latent space。
3. **Task #3 multimodal fusion**：masked summary modeling，以及判断 summary 与 graph-code mixup 是否 matched 的 binary classification。
4. **Task #4 implementation-aware**：双向拉近同一功能子电路的 RTL `R_cls` 与 netlist `N_pool`。
#### 模块 F：Retrieval-augmented inference

Indexing 阶段将已知 circuits split、编码并把 embeddings 与 quality metrics 放入 VectorStore `VS_kn`。新 sub-circuit 按 cosine similarity 取 top-k 相似样本；zero-shot 直接使用 retrieved metrics，fine-tuning 则把 timing/power/area metrics 与目标 embedding 拼接后输入回归器。sub-circuit task 直接拼接，circuit task 对所有子电路的 embedding/指标求和，再拼 design-level operator counts。
### 4.3 模块职责矩阵

| 模块 | 输入 | 输出 | 用到的模型/工具 | 是否需训练 |
|---|---|---|---|:---:|
| HDL 统一化 | Verilog/VHDL/Chisel | Verilog HDL | 开源转换工具 | 否 |
| AST/CDFG 构建 | Verilog HDL | operator/register graph | HDL parser、AST/CDFG 流程 | 否 |
| 子电路切分 | RTL graph、register | `SC_i` 及其 cones | BFS | 否 |
| 摘要生成 | `SC_i` HDL | functionality/implementation summary | GPT-4o | 外部生成，不是 CircuitFusion 训练 |
| Graph encoder | `G_i` | `{G_cls,G_1,...}` | 7-layer Graphormer | 是，从头训练 |
| Summary encoder | `S_i` tokens | `{S_cls,S_1,...}` | 6-layer Transformer/BERTbase 初始化 | 是 |
| Code encoder | `C_i` tokens | `{C_cls,C_1,...}` | frozen NV-Embed-V1 | 否，冻结 |
| Fusion encoder | summary + mixup graph/code | `{R_cls,R_1,...}` | BERTbase 后 6 层、cross-attention | 是 |
| Netlist encoder | `N_i` graph | `{N_1,...,N_w}`, `N_pool` | 3-layer GraphSAGE | 仅预训练 |
| Pre-training tasks | RTL/netlist 模态及变换样本 | 共享表示 | MSE、InfoNCE、CE | 是 |
| VectorStore/Retriever | 已知 embeddings、新 embedding | top-k 相似电路 | cosine similarity | 否 |
| Downstream regressor | `R_cls`、检索指标、design features | 五类 quality metrics | XGBoost 等轻量模型 | 任务级微调 |

矩阵揭示了 CircuitFusion 的两个边界。训练期组件多，但推理时只保留 RTL 三模态 encoder/fusion 和可选 retriever；netlist encoder 不在线运行。另一方面，主干表示被冻结后，每个任务只需很轻量的回归模型，论文报告每个任务 fine-tuning 约 5 分钟。

## 5. 关键公式

本节要解决的问题是：论文的四类预训练目标如何写成可检查的数学对象，以及这些损失在工程上分别约束什么。
### 5.1 Task #1：Masked Graph Modeling

论文的公式（1）用 MSE 让 masked graph node 恢复原 operator type。输入图中随机把 operator node 替换为 `[MASK]`，模型根据周围节点 embedding 预测它。

$$
\mathcal{L}_{\mathrm{MGM}}^{\#1}
= \mathbb{E}_{\hat{G}\sim D}
\left[
\left(
 y_{\hat{G}}^{\mathrm{msk}}
 - p^{\mathrm{msk}}(\hat{G})
\right)^2
\right]
$$

- $\mathcal{L}_{\mathrm{MGM}}^{\#1}$：Task #1 的 masked graph modeling 损失
- $\hat{G}$：被 mask 后的电路图
- $D$：电路图数据集
- $y_{\hat{G}}^{\mathrm{msk}}$：被 mask 节点真实 operator type 的 one-hot vector
- $p^{\mathrm{msk}}(\hat{G})$：根据周围节点 embedding 预测的 operator type
- $\mathbb{E}$：在数据集分布上的期望

**工程直觉**：如果图只保留局部连接，模型仍能由邻域推断是 ADD、OR、MUX 等哪一种 operator，表示就不只是节点类型词典，而是包含 connectivity context。

**实现参数**：每个训练 epoch 随机 mask RTL 与 netlist 图中 30% 节点；使用 hidden dimension 为 256 的三层 MLP 重构 node type；node type 用 one-hot 表示。
### 5.2 Task #1：同模态功能对比

公式（2）在 graph 和 summary 两个模态中分别拉近功能等价样本。论文将等价变换得到的新 sub-circuit 作为 positive，其它功能不同样本作为 negative。

$$
\mathcal{L}_{\mathrm{CLG}}^{\#1}
= \mathbb{E}_{G\sim D}
\left[
\operatorname{CL}(G_{\mathrm{cls}},G_{\mathrm{cls}}^{+},G_{\mathrm{cls}}^{-})
\right]
$$

- $\mathcal{L}_{\mathrm{CLG}}^{\#1}$：graph 模态的 intra-modal contrastive loss
- $G$：原始 graph sub-circuit
- $G_{\mathrm{cls}}$：原始 graph 的 sub-circuit embedding
- $G_{\mathrm{cls}}^{+}$：等价变换后、功能相同的 positive embedding
- $G_{\mathrm{cls}}^{-}$：batch 中功能不同的 negative embeddings
- $\operatorname{CL}$：论文采用的对比学习损失

$$
\mathcal{L}_{\mathrm{CLS}}^{\#1}
= \mathbb{E}_{S\sim D}
\left[
\operatorname{CL}(S_{\mathrm{cls}},S_{\mathrm{cls}}^{+},S_{\mathrm{cls}}^{-})
\right]
$$

- $\mathcal{L}_{\mathrm{CLS}}^{\#1}$：summary 模态的 intra-modal contrastive loss
- $S$：功能摘要 sub-circuit
- $S_{\mathrm{cls}}$：原始 summary 的 sub-circuit embedding
- $S_{\mathrm{cls}}^{+}$：等价变换样本对应的 summary embedding
- $S_{\mathrm{cls}}^{-}$：功能不同的 summary negative embeddings
- $D$：用于构造原始、positive、negative 样本的数据分布

**工程直觉**：AND-OR 组合、代数重写或其它 Boolean 等价实现可能有不同结构，但它们应该在功能表示空间接近；这正是论文所说的 functional equivalent transformation property。
### 5.3 Task #2：跨模态对齐

公式（3）把 summary 与 graph、summary 与 code 分别配对。这样三种 modality 可以进入共享 latent space，为后面的融合提供相同电路语义坐标。

$$
\mathcal{L}_{\mathrm{CLmodal}}^{\#2}
= \mathbb{E}_{(S,G,C)\sim D}
\left[
\operatorname{CL}(S_{\mathrm{cls}},G_{\mathrm{cls}}^{+},G_{\mathrm{cls}}^{-})
+\operatorname{CL}(S_{\mathrm{cls}},C_{\mathrm{cls}}^{+},C_{\mathrm{cls}}^{-})
\right]
$$

- $\mathcal{L}_{\mathrm{CLmodal}}^{\#2}$：cross-modal contrastive loss
- $(S,G,C)$：同一 sub-circuit 的 summary、graph、code 三元组
- $S_{\mathrm{cls}}$：summary anchor embedding
- $G_{\mathrm{cls}}^{+}$：与该 summary 对应的 graph positive embedding
- $C_{\mathrm{cls}}^{+}$：与该 summary 对应的 code positive embedding
- $G_{\mathrm{cls}}^{-}$：不匹配 graph negatives
- $C_{\mathrm{cls}}^{-}$：不匹配 code negatives
- $D$：对齐三模态的训练数据

**工程直觉**：同一寄存器 cone 的“做什么”“怎么连接”“怎么写”不是三条无关样本；跨模态 loss 迫使它们互相可检索。
### 5.4 Task #3：Masked Summary Modeling

融合 encoder 以 masked summary embedding 为 cross-attention query，以 graph-code mixup embedding 为 key/value，并预测被 mask 的 summary token。公式（4）使用 cross-entropy。

$$
\mathcal{L}_{\mathrm{MSM}}^{\#3}
= \mathbb{E}_{(\hat{S},G,C)\sim D}
\left[
\operatorname{CE}\left(
 y_{\hat{S}}^{\mathrm{msk}},p^{\mathrm{msk}}(\hat{R})
\right)
\right]
$$

- $\mathcal{L}_{\mathrm{MSM}}^{\#3}$：masked summary modeling loss
- $\hat{S}$：被 mask 的 summary token 序列
- $G,C$：同一 sub-circuit 的 graph 与 code
- $\hat{R}$：由 masked summary query 和 graph-code mixup 得到的融合表示
- $y_{\hat{S}}^{\mathrm{msk}}$：masked summary token 的 ground-truth one-hot vocabulary distribution
- $p^{\mathrm{msk}}(\hat{R})$：融合表示预测出的 token distribution
- $\operatorname{CE}$：cross-entropy loss

**工程直觉**：summary 缺失一个高层语义片段时，graph 和 code 应该能够提供线索把它补出来；这把“融合”从向量拼接变成跨模态条件预测。
### 5.5 Task #3：Summary-mixup Matching

公式（5）让模型判断一对 summary 与 graph-code mixup embedding 是 matched 还是 unmatched。它是二分类的 cross-entropy 目标。

$$
\mathcal{L}_{\mathrm{match}}^{\#3}
= \mathbb{E}_{(S,G,C)\sim D}
\left[
\operatorname{CE}\left(
 y^{\mathrm{match}},p^{\mathrm{match}}(R^{+},R^{-})
\right)
\right]
$$

- $\mathcal{L}_{\mathrm{match}}^{\#3}$：summary-mixup matching loss
- $S,G,C$：同一 sub-circuit 的三种模态
- $R^{+}$：matched summary 与 graph-code mixup pair 的表示
- $R^{-}$：unmatched pair 的表示
- $y^{\mathrm{match}}$：pair 是否匹配的二元 ground-truth
- $p^{\mathrm{match}}$：模型给出的 matching probability
- $\operatorname{CE}$：binary classification 使用的 cross-entropy

**工程直觉**：MSM 检验能否从细节恢复 summary；matching 检验能否拒绝“功能描述与实现细节不属于同一电路”的错误配对。
### 5.6 Task #4：RTL-netlist implementation-aware alignment

公式（6）在两个方向上对齐 RTL fusion embedding 与 netlist pooled embedding。netlist encoder 在该任务前已经通过 netlist graph 的 masked graph modeling 和 graph contrastive objectives 预训练。

$$
\mathcal{L}_{\mathrm{CLimpl}}^{\#4}
= \mathbb{E}_{(R,N)\sim D}
\left[
\operatorname{CL}(R_{\mathrm{cls}},N_{\mathrm{pool}}^{+},N_{\mathrm{pool}}^{-})
+\operatorname{CL}(N_{\mathrm{pool}},R_{\mathrm{cls}}^{+},R_{\mathrm{cls}}^{-})
\right]
$$

- $\mathcal{L}_{\mathrm{CLimpl}}^{\#4}$：implementation-aware contrastive loss
- $R$：RTL fusion representation
- $R_{\mathrm{cls}}$：RTL sub-circuit 的融合 embedding
- $N$：对应 netlist sub-circuit
- $N_{\mathrm{pool}}$：netlist node embeddings 的 mean-pooled graph embedding
- 上标 $+$：同一功能、跨设计阶段的 positive
- 上标 $-$：不匹配的 negative
- $D$：对齐 RTL/netlist 的数据分布

**工程直觉**：RTL 侧更有 semantic，netlist 侧更有 implementation detail；共享空间让早期表示吸收综合后可观测的实现信息，而不要求部署时带着 netlist。
### 5.7 完整预训练目标

公式（7）把四个任务联合起来；其中 Task #1 自身包含 MGM、graph contrastive 和 summary contrastive，Task #2 是 cross-modal，Task #3 包括 MSM 与 matching，Task #4 是 implementation-aware。

$$
\mathcal{L}
=\left(
\mathcal{L}_{\mathrm{MGM}}^{\#1}
+\mathcal{L}_{\mathrm{CLG}}^{\#1}
+\mathcal{L}_{\mathrm{CLS}}^{\#1}
\right)
+\mathcal{L}_{\mathrm{CLmodal}}^{\#2}
+\left(
\mathcal{L}_{\mathrm{MSM}}^{\#3}
+\mathcal{L}_{\mathrm{match}}^{\#3}
\right)
+\mathcal{L}_{\mathrm{CLimpl}}^{\#4}
$$

- $\mathcal{L}$：CircuitFusion 的完整 self-supervised pre-training objective
- $\mathcal{L}_{\mathrm{MGM}}^{\#1}$：masked graph modeling 项
- $\mathcal{L}_{\mathrm{CLG}}^{\#1}$：graph intra-modal contrastive 项
- $\mathcal{L}_{\mathrm{CLS}}^{\#1}$：summary intra-modal contrastive 项
- $\mathcal{L}_{\mathrm{CLmodal}}^{\#2}$：cross-modal alignment 项
- $\mathcal{L}_{\mathrm{MSM}}^{\#3}$：masked summary modeling 项
- $\mathcal{L}_{\mathrm{match}}^{\#3}$：summary-mixup matching 项
- $\mathcal{L}_{\mathrm{CLimpl}}^{\#4}$：RTL-netlist implementation-aware 项

**工程直觉**：结构恢复、功能等价、跨模态对应和跨阶段实现关系被同时约束；单项 loss 的 ablation 都会使 MAPE 上升，说明四个监督信号不是只保留一个即可。
### 5.8 InfoNCE 具体形式

论文 Appendix C.2 给出对比学习采用的 InfoNCE 公式（8），Task #1、Task #2、Task #4 的所有 contrastive schemes 都使用它。

$$
\operatorname{NCE}(E,E^{+},E^{-})
=-\log
\frac{\exp\left(\operatorname{sim}(E,E^{+})/\tau\right)}
{\exp\left(\operatorname{sim}(E,E^{+})/\tau\right)
+\sum_{E^{-}}\exp\left(\operatorname{sim}(E,E^{-})/\tau\right)}
$$

- $\operatorname{NCE}$：InfoNCE 对比损失
- $E$：anchor circuit embedding
- $E^{+}$：functionally equivalent 或对应模态的 positive embedding
- $E^{-}$：batch 中 negative embeddings
- $\operatorname{sim}$：embedding similarity function
- $\tau$：temperature scaling parameter
- $\exp$：指数函数

论文将 temperature parameter 设为 0.3；intra-modal weight 为 1.0，cross-modal 与 implementation-aware weights 均为 0.2。公式的作用是增大 anchor-positive 相似度相对 negative 的概率。
### 5.9 预测指标的解释

论文正文使用 correlation coefficient（R）与 mean absolute percentage error（MAPE）评估回归准确度；没有给出二者的编号公式。读表时只需记住：R 越高表示标签与预测越相关，MAPE 越低表示百分比误差越小。主实验数字以论文 Table 2、Table 3 及 Tables 5--9 为准。

**边界说明**：MAPE 与 R 是评估指标，不是 CircuitFusion 预训练的新增损失；预训练损失仍是公式（1）到公式（8）所列的 MSE、对比学习和 CE 目标。

## 6. 训练与实验设置

本节要解决的问题是：模型用什么数据和硬件训练、下游怎样评估，以及数字结果是否支持“通用、多模态、可零样本”的主张。
### 6.1 是否需要训练

**需要训练，但不是每个下游任务从头训练一个模型。** CircuitFusion 先做 50 epochs 的 self-supervised pre-training，再冻结预训练表示，用轻量模型 fine-tune 各个 quality task；code encoder 保持 frozen。
#### 数据规模

- 原始数据：41 个 RTL designs，来自 ITC’99、OpenCores、VexRiscv、Chipyard 等开源 benchmark。
- 对齐数据：7,166 个 RTL/netlist sub-circuit pairs。
- 等价扩充：用 Yosys 与 ABC 进行 functionally equivalent transformations，总计 57,328 个 sub-circuits。
- 划分：按完整 design 做 80/20 split，33 个 designs 训练，8 个 designs 测试。
- 目的：避免把同一个完整 design 的不同 sub-circuits 同时放入 train/test，从而保持设计级隔离。
#### 预训练超参数

| 项目 | 论文设置 |
|---|---|
| epoch | 50 |
| batch size | 128 |
| optimizer | AdamW |
| activation | GELU |
| learning rate | 前 1,000 iterations warm up 到 `1e-4`，之后 cosine decay 到 `1e-5` |
| contrastive temperature | 0.3 |
| intra-modal loss weight | 1.0 |
| cross-modal loss weight | 0.2 |
| implementation-aware loss weight | 0.2 |
| graph mask ratio | RTL 与 netlist graph 每 epoch 随机 mask 30% nodes |
#### 训练硬件与时间

论文 Experimental Settings 使用 2.9 GHz Intel Xeon(R) Platinum 8375C CPU、512 GB RAM 和 4 张 NVIDIA A4000 GPU；预训练约 20 小时的表述出现在方法实验部分，Appendix C.4 进一步给出 4 张 A4000 约 10 小时、单张约 32 小时的 model-development 时间说明。这里保留原文两个口径，不把它们强行合并成一个数字。

下游 fine-tuning 使用 frozen CircuitFusion 加 lightweight model；XGBoost 在作者试过的 MLP、GNN 和 tree-based models 中表现最好，每个 task 约 5 分钟。
### 6.2 数据预处理与标签获取
#### 训练数据的 RTL 到 netlist

1. 开源 benchmark 提供 RTL HDL，表示 functional behavior。
2. Design Compiler 使用 NanGate 45nm technology library synthesis RTL。
3. 按 baseline 流程使用 `compile ultra`，使 netlist 质量位于 Pareto frontier、不同配置间方差较小。
4. PrimeTime 读取综合后设计，产生每个 register 的 slack，以及每个 RTL design 的 WNS、TNS、total power、total area。

这一步解释了为何模型可以在 RTL 阶段预测 post-synthesis 质量：标签来自实际综合/时序/功耗/面积流程，而不是人工对 HDL 的主观打分。
#### 五个 quality tasks

| Task | 预测对象 | 评估粒度 | 论文给出的工程含义 |
|---|---|---|---|
| Register slack | 单个 register 的 slack | sub-circuit | 表示 post-synthesis 满足或错过 timing constraint 的 margin |
| WNS | worst negative slack | circuit | 全设计最大 timing violation |
| TNS | total negative slack | circuit | 全设计 negative slack 的总严重程度 |
| Total power | 总功耗 | circuit | 能源效率评估 |
| Total area | 总面积 | circuit | 物理可行性与成本评估 |
#### Baselines

硬件基线包括 task-specific RTL-Timer、MasterRTL 和 self-supervised SNS v2；通用文本基线为 32K-token 的 NV-Embed-V1；软件 code 基线为 CodeSage、CodeT5+ Encoder、UnixCoder。软件 code encoder 最大输入为 1024 tokens，因此论文对长 HDL 进行 crop；这也凸显了子电路切分和 32K code encoder 的必要性。

| Area | SOTA MasterRTL | 16% | 33% | 46% | 56% | N/A |
| Area | **CircuitFusion** | **11%** | **30%** | **45%** | **51%** | **58%** |

这组结果显示，CircuitFusion 不是只有 full-shot 才有效：训练数据从 13% 到 100% 时，它在每一项都低于对应 SOTA baseline。没有 task-specific label 时，它仍能用 retrieved metric 输出 zero-shot 结果。
### 6.6 规模、消融和模态实验
#### 模型与数据规模

- 模型从 270M 增大到 500M parameters，平均 error 从 19% 降到 12%。
- 预训练数据从 25% 增至 100%（约 7k RTL sub-circuits），平均 error 从约 24% 降到 12%。
- Table 4：CircuitFusion 为 500M 加 7B frozen NV-Embed-V1，embedding dimension 768，最大 token 32768。
#### 策略消融

Figure 9 的结论是：去掉 S1 splitting 在所有任务引起最显著 error increase，因为模型无法处理大规模 circuit，也失去 slack 需要的 fine-grained embedding；去掉任一 pretraining objective 都会提升 MAPE；去掉 S4 retrieval 也会让所有任务 MAPE 明显增加。
#### 模态消融

Figure 10 的结论是：去掉 code 或 graph modality 都会使各任务误差显著上升，其中 graph 的贡献更大，因为它包含丰富 structural information；only graph、only code、only summary 都不如完整融合。
#### 迁移策略消融

Table 10 显示，把 S1 与 S4 施加到基线也能提升其表现。例如 NV-Embed-V1 的 WNS MAPE 从 26% 降到 17%，TNS 从 55% 降到 27%，power 从 44% 降到 20%，area 从 24% 降到 17%。但 CircuitFusion 仍优于这些增强后的 baseline，说明硬件特定预训练仍有额外价值。
#### 融合变体

Table 11 的平均 MAPE 为：完整 CircuitFusion 12%；aligned graph-centric 15%；aligned code-centric 16%；aligned summary+graph 15%；aligned summary+code 20%；aligned graph 16%；aligned code 23%；aligned summary 16%；only graph 19%；only code 23%；only summary 22%；SOTA baselines 20%。这支持 summary-centric fusion 优于其它 modality-centric、partial fusion、only-alignment 和 single-modality 变体。
#### Multi-clock 补充实验

Table 12 中，single-clock 的 `itc1`（1.5 GHz）Slack R 0.91、MAPE 6%，WNS MAPE 5%，TNS MAPE 8%；`chipyard1`（1.5 GHz）Slack R 0.88、MAPE 12%，WNS 16%，TNS 15%。multi-clock 组合中，`itc1`（1.5 GHz）保持 0.91、6%、5%、8%；`chipyard1` 使用 1 GHz 时为 0.89、13%、15%、16%。论文指出跨 asynchronous clock domain 的 signal transfer 仍超出方法范围。

## 7. 创新点

本节要解决的问题是：CircuitFusion 的贡献不是“用了三个 encoder”这么简单，而是哪些设计是由电路的独特性质推导出来的。
### 创新点 1：P1 并行执行到 S1 寄存器子电路

普通按 token 或节点截断会切断一个状态更新的逻辑 cone。CircuitFusion 利用硬件并行执行和 sequential-element boundaries，以每个 register 为单位回溯组合输入，使 sub-circuit 在 RTL 与 netlist、code/graph/summary 之间保持功能对齐。
### 创新点 2：P2 功能等价到结构-语义预训练

同一电路功能可以由结构完全不同的逻辑表达实现。论文使用 Yosys、ABC 生成等价变换 positive sample，并联合 masked graph modeling、graph/summary contrastive、cross-modal contrastive 与 summary fusion 任务，让表示同时编码 structural 和 semantic 信息。
### 创新点 3：P3 多设计阶段到 implementation-aware alignment

RTL 更接近 functionality，netlist 更含 implementation detail。论文不是把 netlist 当作部署输入，而是在预训练阶段对齐 `R_cls` 与 `N_pool`；推理时移除 netlist encoder。这是“早期预测最终实现指标”的关键机制。
### 创新点 4：P4 电路复用到 retrieval-augmented inference

企业或产品代际会复用相似 circuit/IP block；论文把已知设计 embedding 与质量指标建立 VectorStore。新电路可检索 top-k 相似样本，既能增强 fine-tuning，也能在没有 task labels 时直接 zero-shot。
### 创新点 5：统一 backbone 服务多任务

已有硬件工作常为某一个 quality task 做 task-specific supervised model。CircuitFusion 以同一预训练表示支持 slack、WNS、TNS、power、area，后面只换轻量回归器；论文称这种方式在五项任务上都超过各自的 SOTA baseline。

## 9. 与芯片流程的关系

本节要解决的问题是：CircuitFusion 交接的是哪一阶段的产物，为什么它能在 RTL 阶段预测后续质量，以及它和资料包内其它 circuit representation 工作的分工是什么。
### 9.1 在全流程中的位置

CircuitFusion 的主位置如下：

```text
① RTL 设计
   │  HDL code 描述功能；CircuitFusion 读取并切成 register cones
   ▼
[ CircuitFusion representation + early prediction ]
   │  输出 slack / WNS / TNS / power / area 的预测
   ▼
③ 逻辑综合
   │  论文用 Design Compiler 生成 gate-level netlist 作为训练阶段实现信息
   ▼
⑤ STA / PrimeTime 及功耗、面积测量
   │  真实 labels 来自这里，模型目标是提前估计它们
   ▼
⑦-⑬ 物理实现与 signoff
   │  不在 CircuitFusion 的训练任务或推理输出内
   ▼
⑭-⑰ 流片、制造、封装测试、实物芯片
```

**它接手什么**：开源 benchmark 的 RTL HDL，统一后的 Verilog，经过 AST/CDFG 得到的 graph，以及 GPT-4o 为 sub-circuit 生成的功能摘要；训练时还接手与 RTL 对齐的 netlist graph 和 PrimeTime quality labels。

**它交棒什么**：对新 RTL 的 sub-circuit embedding 和 quality prediction。它不交付门级 netlist、layout、GDSII 或已签核芯片，因此应被视为“综合前的预测/决策辅助层”。

**痛点是什么**：RTL 只有 functional information，缺少后续 implementation details；设计者若每次都完成耗时的 downstream EDA process 才知道 timing/power/area，会延迟优化。CircuitFusion 用跨阶段对齐和检索参考把反馈提前到写 HDL 时。
### 9.2 “仿真通过”和“能做成芯片”之间隔着什么

CircuitFusion 的实验成功标准是 quality metric prediction，不是 tape-out success。即便预测 MAPE 较低，仍隔着以下环节：

1. **真实综合依赖**：论文的 labels 由 Design Compiler `compile ultra`、NanGate 45nm library 以及 PrimeTime 生成；换 library、constraint 或 synthesis optimization，质量标签的分布可能改变。
2. **时序路径完整性**：模型预测 WNS/TNS 或 register slack，但不执行新的 STA；预测准确不等于每条路径都已经通过约束。
3. **功耗/面积实现**：power 和 area 是综合后实现指标的估计目标，不等于完成 placement、routing 或 physical signoff。
4. **物理阶段信息缺失**：论文没有使用 floorplan、placement、CTS、routing、SPEF、DRC/LVS，也不生成 GDSII。
5. **跨时钟域**：论文补充实验表明多-clock timing group 可以做，但 asynchronous clock-domain signal transfer 更复杂，当前方法未覆盖。
6. **工艺与产品变化**：论文强调可复用 circuit/IP 作为 retrieval 参考；没有相似设计时可以省略 retrieval，但参考池的代表性仍决定其校准价值。
### 9.3 与资料包内其它论文的关系
#### 与 DeepGate 的关系

[DeepGate](../DeepGate/论文深度讲解.md)代表论文文本中提到的 graph-only hardware representation 路线：CircuitFusion 的 related works 将 DeepGate 作为电路表示学习工作之一，并指出许多既有工作主要关注 circuit graph。CircuitFusion 没有否定 graph，而是把 graph encoder 作为一条核心模态，再添加 code 和 summary，解决仅图表示对 HDL 功能语义覆盖不足的问题。

两者的流程关系也不同。DeepGate 系列偏向从逻辑/网表图学习结构与功能表示；CircuitFusion 的输入重点是早期 RTL，并进一步通过 RTL-netlist alignment 预测 post-synthesis design quality。换句话说，CircuitFusion 将 graph representation 扩展为“RTL 三模态 + cross-stage + retrieval”。
#### 与 DeepGate2 的关系

[DeepGate2](../DeepGate2/论文深度讲解.md)在论文参考文献中被描述为 functionality-aware circuit representation learning；CircuitFusion 的功能等价变换、graph contrastive learning 和 cross-modal alignment 与“功能信息应进入表示”这一方向相通。

区别在于 CircuitFusion 的功能载体不只来自 graph：摘要提供高层自然语言语义，HDL code 直接提供实现文本，netlist 对齐提供后阶段实现细节。其 Table 2 的任务也从 representation 本身扩展到 slack、WNS、TNS、power、area 五种 RTL-stage early quality prediction。
#### 与 R2G 的边界说明

本论文原文没有提到 R2G，因此这里不把 R2G 的方法或数字写成 CircuitFusion 的事实。按本资料包的交叉阅读规则，CircuitFusion 可与 repo 中其它 RTL/graph 表示工作对比，但能直接由本文支持的交叉引用是 DeepGate 和 DeepGate2。
### 9.4 这项工作在工程闭环中的使用方式

一个设计团队可以把流程分成两个时间点：

- **训练/建立参考库**：已有 RTL 经过 synthesis 与 PrimeTime，得到 netlist 与 quality labels；同时切 sub-circuit、生成三种 RTL 模态，训练 CircuitFusion 并把已知 embeddings/metrics 写入 VectorStore。
- **新 RTL 评估**：新代码无需先完成全部后端流程；编码每个 register cone，取相似已知设计，输出 zero-shot 或 fine-tuned quality estimates。
- **优化决策**：论文 Appendix F 讨论了把更好的 timing prediction 用于 fine-grained synthesis optimization，也讨论和 RTL code generation/optimization decoder 结合的方向；这属于应用展望，不是本文已完成的 RTL 重写系统。

## 10. 讨论与局限

本节要解决的问题是：哪些限制是论文明确承认的，哪些是从数据、部署边界和评测协议可以直接看出的工程条件。
### 10.1 论文自述的局限

1. **训练数据仍然有限**：论文承认，即使覆盖多个 benchmark，训练数据量仍小于构建 robust circuit foundation model 的理想规模。
2. **扩展方向依赖数据生成**：作者计划探索 circuit data generation，并在更大 synthetic circuit 数据上预训练；未来希望发布大规模 foundation model。
3. **multi-clock 不是完整解决方案**：论文的补充实验显示按 clock group 可以得到相近 timing accuracy，但 asynchronous clock-domain crossing 仍超出范围。
4. **实现阶段只作为对齐/标签来源**：netlist encoder 在 inference 丢弃，因此模型无法在新设计上直接观察该设计的真实综合网表。
### 10.2 代码与复现层面的边界

论文提供了公开仓库和 step-by-step replication scripts：[CircuitFusion GitHub](https://github.com/hkust-zhiyao/CircuitFusion)。本资料包的 CircuitFusion 目录只归档原文 PDF/TXT，没有把仓库代码和数据复制进来，因此本文不宣称已在本地重跑数字。

复现需要重建的环节包括：

- 用开源 benchmark 获得 ITC’99、OpenCores、VexRiscv、Chipyard HDL。
- 准备 HDL 转换、AST/CDFG、sub-circuit generation、graph construction 和 summary generation 脚本。
- 运行 Yosys、ABC 等等价变换生成 positive samples。
- 运行 Synopsys Design Compiler、NanGate 45nm library 和 PrimeTime 获得真实 labels；这些是论文数据生成流程的关键工具链。
- 准备 4 张 NVIDIA A4000 或等效资源完成约 50 epochs pre-training；下游任务还需相应回归器和 retrieval VectorStore。

这些门槛影响的不是“模型能否写出 Verilog”，而是能否复现论文的 post-synthesis quality labels、implementation-aware alignment 和 zero-shot numerical results。
### 10.3 从论文设定可直接推出的批判性分析
#### 评测外推边界

41 个 designs、33/8 design-level split 是有意义的设计隔离，但仍不能等同于跨公司、跨工艺、跨综合约束的泛化。特别是 quality labels 来自固定 NanGate 45nm 和固定 synthesis flow；换 PDK 或 timing constraint 后，模型是否保持 Table 2 的数值没有在本文中验证。
#### 摘要噪声边界

Summary 由 GPT-4o 生成；摘要本身是第三模态的语义输入。论文 Figure 5 说明 summary 能引导 cross-attention，但不同摘要质量可能改变融合输入。原文没有报告人工摘要与自动摘要的单独对照，因此不应把摘要误认为无噪声 ground truth。
#### retrieval 的数据依赖

zero-shot 依赖 VectorStore 中存在 functionally similar known circuits；Table 3 的 top-1 MAPE 说明在论文数据池中有效，但没有相似设计时只能省略 retrieval，论文仅说会有 slight performance decrease。由此可知 zero-shot 不是脱离历史数据的纯模型先验。
#### 长度与规模边界

S1 将全设计拆成约小 1000 倍的 sub-circuit，这是可扩展性的关键，但 circuit-level inference 仍要聚合许多 sub-circuit；Table 1 中 VexRiscv 最大有 694 个 sub-circuits，Chipyard 最大有 23K。论文没有把所有最大规模 design 的端到端检索/回归成本单列出来，因此大规模聚合仍是部署时需要测量的变量。
#### 物理意义边界

模型输出的是预测质量指标，不是物理实现约束的证明。一个低 MAPE 的平均预测器仍可能在关键 register、极端 timing path 或新工艺条件下产生误判；论文的任务定义是 early feedback，而不是 signoff replacement。

## 12. 一分钟复述版

本节要解决的问题是：如何在一分钟内完整说出 CircuitFusion 的问题、方法、结果和限制，而不是只背一个模型名称。

1. **问题**：传统 AI-assisted circuit work 常常 task-specific，且很多表示学习只看 graph；RTL 同时拥有 code、structure、functionality，后续 netlist 又含实现细节。
2. **数据**：CircuitFusion 把 41 个 design 切成 7,166 个对齐 RTL/netlist sub-circuit，并用 Yosys/ABC 等价变换扩到 57,328 个 sub-circuits。
3. **方法一**：利用硬件并行执行，以每个 register 为边界回溯组合逻辑，得到一个 clock-cycle state update cone，而不是粗暴截断整段 HDL。
4. **方法二**：用 Graphormer 编 graph、BERT 初始化 Transformer 编 summary、冻结 NV-Embed-V1 编长 code，再用 summary-centric cross-attention 融合。
5. **方法三**：四个预训练目标分别做 intra-modal、cross-modal、multimodal fusion 和 RTL-netlist implementation-aware alignment。
6. **应用**：把已知电路 embedding 和 timing/power/area 指标放入 VectorStore；新 RTL 取相似子电路，可 zero-shot 或拼接指标后 fine-tune。
7. **结果**：五任务 supervised MAPE 为 slack 12%、WNS 11%、TNS 15%、power 13%、area 11%，均优于列出的 baseline。
8. **零样本**：top-1 retrieval 的 slack、sub-circuit power、sub-circuit area MAPE 为 21%、36%、35%；模型规模 270M 到 500M 时平均 error 从 19% 降到 12%。
9. **流程位置**：它在 ① RTL 设计阶段提供早期质量反馈，借助 ③ synthesis 和 ⑤ PrimeTime 标签学习，但不替代综合、布局、布线或 signoff。
10. **限制**：数据规模仍有限；固定 45nm/工具链的标签可能限制迁移；zero-shot 需要相似参考电路；异步跨时钟域与真正物理实现仍未解决。
