## 1. 一句话定位

**ChipSeek 是 MAGE 的镜像方案：不把 EDA 反馈用在推理时，而是把它做成强化学习奖励直接更新模型参数——策略每生成一段 Verilog，就依次过 Icarus 编译（语法）、testbench 仿真（功能）、Yosys 综合（可综合）、OpenROAD 报 PPA（功耗/延迟/面积），得到五个层级七维的奖励向量，用新提出的 CDPO 算法（解耦 advantage + 课程权重 + 偏好向量）训练，让 7B 模型内化"怎么写功能正确且 PPA 更优的 RTL"，在 RTLLM v2.0 上 pass@5 提升 11.4%、EDAP 平均降低 18%。**

一个表格先立住 MAGE 与 ChipSeek 的对照（这是理解本文位置最关键的框架）：

| 维度 | MAGE | ChipSeek |
|------|------|----------|
| 改进发生在 | **推理时**（多候选 + 仿真打分 + 迭代修复） | **训练时**（RL 更新参数） |
| EDA 工具的角色 | 给 Debug Agent 提供反馈信号 | 给 RL 提供 reward 信号 |
| 反馈粒度 | 逐拍信号级（state checkpoint） | 整条回答的组内 advantage |
| 优化目标 | 功能正确（$s(r)=1$） | 功能正确 **+ PPA**（EDAP 越低越好） |
| 部署成本 | 每题 20~50 次 LLM 调用 | 训练后一次前向生成 |
| 覆盖流程阶段 | ①② | ①②③（+⑤ 的快速近似） |
| 知识积累 | ❌ 每题独立 | ✅ 参数吸收 PPA 优化模式 |

**Figure 1 是全文的动机图**：把所有模型的生成结果送去综合，横轴是模型，纵轴是平均 EDAP（Energy-Delay-Area Product，能量-延迟-面积积，越低越好）。RTLLM benchmark（人类专家写的 RTL）EDAP = 1.00，而 GPT-4o \approx 1.02、Qwen2.5-Coder \approx 1.06、CodeQwen \approx 0.94……**大多数模型的生成结果比专家手写的还差**。ChipSeek 的训练目标就是把这个数字压到 1.0 以下。

## 2. EDA 阶段映射（①-⑰）

参照 [芯片流程.md](../芯片流程.md) 的 17 阶段标准编号：

| 阶段 | 覆盖 | 用途（关键：是训练时奖励，不是交付物） |
|------|:---:|--------------------------------------|
| **① RTL 设计** | ✅ **核心** | 策略 $\pi_\theta$ 从设计描述生成可综合 Verilog |
| **② RTL 功能仿真** | ✅ **核心** | Icarus Verilog 编译 + testbench 仿真，$r_{fun}=1$ 当且仅当全部用例通过 |
| **③ 逻辑综合** | ✅ **核心** | Yosys（或 Design Compiler）把 RTL 综合成门级网表，$r_{sys}=1$ 当且仅当综合成功；同时提取面积/延迟 |
| ④ 门级仿真 | ❌ | 不做 SDF 反标仿真 |
| **⑤ STA** | ⚠️ **近似** | OpenROAD 报告 `max_path_delay_ns` 作为延迟奖励 $r_{delay}$ 的来源。这只是**训练信号**，不是 signoff 级 STA |
| ⑥ 形式验证 | ❌ | 不做等价性证明（论文 future work 明确提到） |
| ⑦ 布局规划 | ❌ | — |
| ⑧ 标准单元摆放 | ⚠️ 间接 | OpenROAD 内部流经的部分步骤为 PPA 数值服务，但论文明确这不是 placement 级优化 |
| ⑨ CTS（Clock Tree Synthesis，时钟树综合） | ⚠️ 间接 | 同上，OpenROAD 流程内部步骤 |
| ⑩ 布线 Routing | ⚠️ 间接 | 同上 |
| ⑪ 后仿真 | ❌ | 无 SPEF 时序仿真 |
| ⑫ DRC（Design Rule Check，设计规则检查）/LVS（Layout Versus Schematic，版图与原理图一致性） | ❌ | 不做物理验证 |
| ⑬ 签核 Signoff | ⚠️ 近似 | PPA 奖励的目标就是"早期签核"，但论文明确说了 "PPA 数值仅作训练信号参考"，非 tapeout 级 |
| ⑭-⑰ 流片→制造→封装→芯片 | ❌ | — |

**覆盖率：约 3.5/17。** 比 MAGE 多覆盖了 ③ 和 ⑤/⑬ 的快速近似。但必须强调一个容易误读的点：

> **ChipSeek 的"EDA 集成"发生在训练阶段**。训练时，每一条候选都要完整过一遍工具链（这是它贵的原因）；**推理时，模型一次前向生成，零 EDA 调用**。所以阶段 ③⑤⑬ 不是 ChipSeek 系统的一部分，而是它训练时的"判卷老师"。对比 MAGE：MAGE 的 EDA 调用发生在推理时，每题都跑。

## 3. 输入 / 输出举例

### 3.1 训练输入（RL 阶段，8,453 条）

**(a) Augmented Prompt** —— 设计描述 + 设计优先级标签：

```text
Design an 8-bit barrel shifter. The circuit takes an 8-bit input 'in'
and a 3-bit control signal 'ctrl', and produces an 8-bit output 'out'
by shifting 'in' right by 'ctrl' positions.

[Design Priority: Focus on minimizing the hardware area.]
```

注意 `[Design Priority: ...]` 是**训练时才有的**。推理时用户同样可以用它来控制优化方向。

**(b) Preference Vector** `p(q) = (p_P, p_D, p_A)`，从 prompt 标签解析，和为 1：

```text
[low_power]  →  p(q) = (0.7, 0.1, 0.2)
[high_perf]  →  p(q) = (0.1, 0.7, 0.2)
[small_area] →  p(q) = (0.2, 0.1, 0.7)
```

它在公式 (6) 里直接决定 PPA advantage 的加权——**这是"可控多目标优化"的机制载体**。

**(c) Golden Testbench** —— 由 GPT-5 根据设计描述 + 参考 Verilog 生成的多用例 TB，经 Icarus 验证过滤，只保留参考代码能通过的 TB。

**(d) Reference PPA** —— 参考设计（benchmark 里的人类实现）经 Yosys + OpenROAD + NanGate45 提取的 `{ref_power, ref_area, ref_delay}`。奖励 `r_m = ref_m / gen_m` 的分母。

### 3.2 SFT 冷启动输入（29,127 条）

裸 Verilog 代码 → DeepSeek-R1 反向生成设计描述 + CoT 推理链，格式：

```text
<thinking> The design implements a NOR gate: out = ~(a | b). ... </thinking>
<answer> module top_module (input a, input b, output out);
           assign out = ~(a | b);
         endmodule </answer>
```

### 3.3 输出

**训练产物**：经 SFT + CDPO 训练后的 ChipSeek 模型（4 个基座：CodeLlama-7B / CodeQwen-7B / DeepSeek-Coder-v1.5-7B / Qwen2.5-Coder-7B-Instruct）。

**推理输出**：
1. `<thinking>` 内的逐步设计推理（CoT）
2. `<answer>` 内的可综合 Verilog

**训练时的中间产物**（不输出给用户）：
- 7 维奖励向量 `{r_fmt, r_syn, r_fun, r_sys, r_power, r_area, r_delay}`
- 每维的组内 advantage
- EDAP = power × delay × area（越低越好）

### 3.4 barrel shifter 案例（论文 Figure 5，最有信息量的一个例子）

**基准方案（人类/其他 LLM 的典型写法）**：

```verilog
module barrel_shifter (in, ctrl, out);
  input  [7:0] in;  input [2:0] ctrl;  output [7:0] out;
  wire [7:0] x, y;
  mux2X1 ins_27 (.in0(in[7]), .in1(1'b0), .sel(ctrl[2]), .out(x[7])); // 4-bit shift
  mux2X1 ins_17 (.in0(x[7]), .in1(1'b0), .sel(ctrl[1]), .out(y[7])); // 2-bit shift
  mux2X1 ins_07 (.in0(y[7]), .in1(1'b0), .sel(ctrl[0]), .out(out[7])); // 1-bit shift
  // …… 8×3=24 个 mux 实例
endmodule
module mux2X1 (in0, in1, sel, out);
  assign out = (sel) ? in1 : in0;
endmodule
```

**ChipSeek 学到的写法**：

```verilog
module barrel_shifter (input [7:0] in, input [2:0] ctrl, output [7:0] out);
  wire [7:0] shift_4, shift_2, shift_1;
  assign shift_4 = ctrl[2] ? (in >> 4) : in;
  assign shift_2 = ctrl[1] ? (shift_4 >> 2) : shift_4;
  assign shift_1 = ctrl[0] ? (shift_2 >> 1) : shift_2;
  assign out = shift_1;
endmodule
```

**效果：行数 -63.9%，面积 -13.3%。**

**为什么第二种更好（技术解读）**：
1. 第一种把 MUX 层次**显式硬编码**成 24 个 `mux2X1` 实例，综合器只能做局部门级优化，无法重排结构；第二种用行为级 `>>` 运算，把结构选择权交还给综合器——综合器看到 `>>` 会做 **operator inference**（运算符推断），在面积/延迟约束下自己选 barrel shifter 的最优拓扑（包括 `shift_4` 这种两阶段移位合并、甚至交换律优化）。
2. 第一种有 8 位 × 3 级 = 24 个实例 + 24 个端口连线 + 层次引用，RTL 解析和综合的前端处理开销大；第二种只有 3 条 assign。
3. 更根本的：**RTL 描述越靠近行为级，留给综合器优化的自由度越大**；显式实例化等于提前锁死了微架构。ChipSeek 通过 RL 学会了这个工程直觉——这正是 Figure 6 里 "Operator Inference 21.4%" 的含义。

### 4.2 层级门控（Hierarchical Gating）—— "fail-fast" 原则

评估依赖链是单向的：

```text
Format → Syntax → Function → Synthesis → PPA
```

规则：**高层奖励仅当紧邻低层奖励为正时才计算**。

```text
r_syn = 0（编译都不过）  →  r_fun = 0（不跑仿真）      →  r_ppa = 0（不跑综合）
r_fun = 0（仿真失败）    →  r_sys = 0（不综合）        →  r_ppa = 0
```

**为什么必要**：一次完整的 PPA 评估 = Yosys 综合（几十秒）+ OpenROAD 全流程（几分钟）。训练时每个 prompt 要采 8 个候选，其中大量候选是语法错或功能错的垃圾——如果不门控，97% 的计算花在给垃圾算 PPA 上。Figure 7 的数据：门控 + 线程池并行 + 等奖励样本过滤，把**单步奖励计算时间从 869s 压到 58s（-93.5%）**，step 更新时间从 962s 压到 177s（-81.6%）。

还有一个更微妙的过滤：**丢弃"所有候选奖励完全相同"的训练样本**——如果 8 个候选全错或全对，组内标准化后 advantage 全是 0，这个样本对梯度毫无贡献，纯浪费。

## 5. 关键公式（LaTeX）

### 公式 (1)：解耦 token 级 Advantage

$$
\hat{A}^{(k)}_{i,t} = \frac{r_{k,i} - \mu_k}{\sigma_k + \epsilon}, \quad \forall t \in \{1, \ldots, |o_i|\}
$$

- $k$：第 $k$ 个奖励分量（fmt / syn / fun / sys / power / delay / area）
- $i$：同一 prompt 组内的第 $i$ 个候选（$i \in [1, G]$，$G=8$）
- $t$：候选 $o_i$ 内的第 $t$ 个 token——**注意 advantage 是 token 级的，但 reward 只有整条回答一个值**，所以同一候选的所有 token 共享同一个 advantage
- $\mu_k, \sigma_k$：**组内**（同 prompt 的 $G$ 个候选）第 $k$ 维奖励的均值与标准差
- $\epsilon$：防除零的小常数

**这个公式是 CDPO 的第一根支柱：解耦（decoupled）。**

标准 RLVR（Reinforcement Learning with Verifiable Rewards，基于可验证奖励的强化学习）的做法是先把各路 reward 加权求和成一个标量 $r_i^{total} = \sum_k w_k r_{k,i}$，再对这个标量做标准化。问题在于：**各路 reward 尺度完全不同**。

具体算一笔账（这就是论文说的 scale mismatch）：

```text
候选 A：r_fmt=1, r_syn=1, r_fun=1, r_sys=1, r_delay=1.2
候选 B：r_fmt=1, r_syn=1, r_fun=0, r_sys=0, r_delay=0

标准 RLVR 加权和（w 都取 1）：A=5.2, B=2  →  组内优势 A 略大于 B
解耦后：A 在 fun/sys/delay 维全是正 advantage，B 在 fun/sys 维是强负 advantage
```

解耦的收益：**即使 sum 维度上 A、B 差距被稀释（5.2 vs 2），每个维度内部仍然保留了自己的信号强度**——尤其对 PPA 这种连续值，组内可能 A 延迟 1.2、C 延迟 0.8、D 延迟 0.5，均值 0.83，方差一摊开，C 和 D 才真正被区分开。如果混进 0/1 奖励的标量求和，PPA 的细微差距会被二进制奖励的噪声淹没。

### 公式 (2)(3)(4)：课程权重—— 自适应从"学会"衰减

$$
\bar{\mu}^{(s)}_k = \frac{1}{B \times G} \sum_{j=1}^{B} \sum_{i=1}^{G} r^{(s)}_{k,ji} \tag{2}
$$

$$
\hat{\alpha}^{(s)}_k = \max\!\left(0,\ 1 - \bar{\mu}^{(s)}_k\right) \tag{3}
$$

$$
\alpha^{(s)}_k = \beta\,\alpha^{(s-1)}_k + (1-\beta)\,\hat{\alpha}^{(s)}_k \tag{4}
$$

- $\bar{\mu}^{(s)}_k$：**整个训练 batch**（$B \times G$ 个 rollout）上第 $k$ 个过程奖励的成功率——注意这和公式 (1) 的 $\mu_k$（组内均值）是**两个不同的量**：$\mu_k$ 是空间上的组内标准化，$\bar{\mu}_k$ 是时间上的全局成功率
- $\hat{\alpha}^{(s)}_k$：瞬时课程信号。成功率高 → 权重趋近 0；成功率低 → 权重趋近 1
- $\beta$：EMA 平滑因子（防 batch 间振荡）。附录用 $\beta$ 默认接近 0.9

**机制直觉（从梯度信号视角）**：

```text
训练早期：format/syntax 成功率只有 30%
  → α_fmt \approx 0.7, α_syn \approx 0.7  →  梯度大头压在"把格式写对、把语法写对"上
  → 这是课程学习的"易"阶段：先学会产出合法代码

训练后期：format 成功率 95%+, syntax 90%+
  → α_fmt \approx 0.05, α_syn \approx 0.1  →  过程奖励对梯度的贡献自动让位
  → 梯度转向 function 和 PPA，这是"难"阶段
```

**为什么需要这个机制（对比 DAPO）**：Figure 8 显示，DAPO（没有课程衰减）的 PPA 奖励收敛更慢、最终值更低。原因论文在附录 F 说得很清楚：没有衰减时，format/syntax 这种"永远容易满足"的奖励在后期仍持续贡献非零梯度，**挤占了 function/PPA 的学习信号**。模型会"满足于表面约束"（overly satisfied with meeting superficial constraints），不再往深处优化。课程机制就是给每路奖励装了一个随掌握程度自动关小的阀门。

### 公式 (5)(6)(7)：advantage 聚合

$$
A^{pro}_{i,t} = \sum_{k \in R_{pro}} \alpha^{(s)}_k\, \hat{A}^{(k)}_{i,t} \tag{5}
$$

$$
A^{cor}_{i,t} = w_{func}\,\hat{A}^{(func)}_{i,t} + \sum_{m \in \{P,D,A\}} p_m(q)\, \hat{A}^{(m)}_{i,t} \tag{6}
$$

$$
A^{total}_{i,t} = A^{pro}_{i,t} + A^{cor}_{i,t} \tag{7}
$$

- $R_{pro} = \{fmt, syn, sys\}$：过程奖励集合
- $w_{func}$：功能奖励的固定权重（论文设 1.0，不随训练衰减——功能正确永远是底线）
- $p(q) = (p_P, p_D, p_A)$：从 prompt 解析的偏好向量，$\sum p_m = 1$
- $m \in \{P, D, A\}$：Power / Delay / Area

**公式 (6) 是"可控多目标"的数学载体**：

```text
[low_power] prompt → p=(0.7,0.1,0.2) → power 维 advantage 权重最大
     → 同组 8 个候选里，功耗最低的那个获得最大正向更新
     → 模型学会"这个 prompt 下要优先省功耗"

[small_area] prompt → p=(0.2,0.1,0.7) → area 维被放大
```

注意一个细节：**公式 (5) 的 $\alpha_k$ 对所有 prompt 全局共享，公式 (6) 的 $p_m$ 随 prompt 变化**。前者是时间上的课程，后者是空间上的条件——两个自由度，分别解决"学什么阶段"和"按什么目标学"。

### 公式 (8)(9)(10)：CDPO 目标函数（PPO 框架 + 解耦裁剪）

$$
J(\theta) = \mathbb{E}_{\{o_i\}_{i=1}^{G} \sim \pi_{\theta_{old}}} \left[ \frac{1}{\sum_{i=1}^{G} |o_i|} \sum_{i=1}^{G} \sum_{t=1}^{|o_i|} O_{i,t}(\theta) \right] \tag{8}
$$

$$
O_{i,t}(\theta) = \min\!\left( r_{i,t}(\theta)\, A^{total}_{i,t},\ \ \text{clip}\!\left(r_{i,t}(\theta),\, 1-\varepsilon_{low},\, 1+\varepsilon_{high}\right) A^{total}_{i,t} \right) \tag{9}
$$

$$
r_{i,t}(\theta) = \frac{\pi_\theta(o_{i,t} \mid q, o_{i,<t})}{\pi_{\theta_{old}}(o_{i,t} \mid q, o_{i,<t})} \tag{10}
$$

这是 PPO 的标准 objective（$\min$ 截断：概率比偏离 $[1-\varepsilon_{low}, 1+\varepsilon_{high}]$ 时，对梯度做保守截断），**但注意两个 ChipSeek 的改动**：

1. **非对称裁剪**：$\varepsilon_{low} = 0.20,\ \varepsilon_{high} = 0.28$（附录 B）。标准的 PPO 是对称 0.2/0.2。论文的解释："asymmetric clipping ratios to provide more flexibility for positive policy updates while maintaining strict constraints on negative updates"——**允许模型朝好的方向（$A>0$，概率比可以冲到 1.28）走得更快，但朝坏的方向最多降到 0.80**。对 Verilog 这种"错一点全错"的任务，保守的负向约束是合理的。

2. **advantage 是解耦聚合的**：公式 (8) 的归一化 $\frac{1}{\sum|o_i|}$ 是 token 级平均（总目标对序列长度归一），与标准 PPO 一致。

### 公式 (11)：Pass@k

$$
\text{pass@}k = \mathbb{E}_{\text{task}}\left[ 1 - \frac{\binom{n-c}{k}}{\binom{n}{k}} \right] \tag{11}
$$

与 MAGE 的公式 (7) 相同（Codex 标准无偏估计）。ChipSeek 评估时 n 取候选数，报告 pass@1/5/10。**注意 ChipSeek 的 pass@k 没有 MAGE 那么强的"成本不对等"争议**：训练完成后推理就是单次采样，多采样只发生在评测时，和 vanilla 模型同样公平。

### 公式 (12)(13)(14)：PPA 复合指标

$$
ADP_{gen} = area_{gen} \times delay_{gen} \tag{12}
$$

$$
EDP_{gen} = delay_{gen} \times power_{gen} \tag{13}
$$

$$
EDAP_{gen} = area_{gen} \times delay_{gen} \times power_{gen} \tag{14}
$$

- $area_{gen}$：综合后生成设计的面积
- $delay_{gen}$：关键路径延迟
- $power_{gen}$：总功耗
- ADP：Area-Delay Product（面积-延迟积）
- EDP：Energy-Delay Product（能量-延迟积）
- EDAP：Energy-Delay-Area Product（能量-延迟-面积积），**ChipSeek 的主报告指标**，越低越好

三个指标把三维 PPA 压成标量，但各有侧重：ADP 关心"面积换速度"，EDP 关心"能量效率"，EDAP 是三者的乘积——**对任何一维的恶化都惩罚**。因为乘积结构，EDAP 对"同时小幅优化三维"比"单维大幅优化"更敏感，这正好匹配 ChipSeek 的多目标定位。

### 公式 (15)-(21)：评测时的归一化协议

$$
S_d = \{ s \in G_d \mid s \text{ passes the testbench} \} \tag{15}
$$

$$
Perf_{norm}(s) = \frac{Perf(s)}{Perf_{ref}(d)}, \quad Perf \in \{Delay, Area, Power, ADP, EDP, EDAP\} \tag{16}
$$

$$
Score_{best}(d) = \min_{s \in S_d} Perf_{norm}(s), \quad Score_{avg}(d) = \frac{1}{|S_d|}\sum_{s \in S_d} Perf_{norm}(s), \quad Score_{worst}(d) = \max_{s \in S_d} Perf_{norm}(s) \tag{18-20}
$$

$$
Perf_{method} = \frac{1}{|T|} \sum_{d \in T} Score_{method}(d) \tag{21}
$$

**这个协议有三个值得注意的决策**：

1. **只有功能正确的设计才进入 PPA 评测**（公式 15 的过滤）——防止"模型牺牲功能换 PPA"的作弊路径。这是评测层的安全阀。
2. **归一化到 benchmark 参考设计**（公式 16）——不同题目 PPA 绝对值差几个数量级（一个寄存器堆和一个 64 位乘法器的面积差 100 倍），不归一化没法跨题平均。**这和训练奖励的设计（$r_m = ref_m/gen_m$）完全同构**——训练和评测用了同一把尺子，这是方法论上的一致性。
3. **同时报告 best/avg/worst**——单看 best 会高估模型（候选多时 best 必然好），单看 avg 会被质量分布误导，worst 反映稳定性下限。Table 2 里 ChipSeek 三个值都很低（0.85/0.76/0.74），说明**不仅上限好，下限也好**——模型很少产出"又对又差"的设计。

## 6. 训练与实验设置

### 6.1 训练管线

**需要训练**，且为两阶段：

**Stage 1: SFT 冷启动**（29,127 条 instruction-CoT-RTL 三元组）
- 数据来源：DeepSeek-R1 输入裸 Verilog，反向生成自然语言设计描述 + `<thinking>` 推理过程 + `<answer>` 参考 Verilog
- 损失函数：标准 decoder-only 因果语言建模（负对数似然）
- 目的：让模型学会 CoT 格式的逐步推理式 RTL 生成

**Stage 2: CDPO 强化学习**（8,453 条 augmented prompt + testbench + 参考 PPA + preference vector）
- 从 SFT 模型出发，每 prompt 采样 $G=8$ 个候选（temperature=1.0, top_p=1.0）
- Batch size: 32 prompts × 8 = 256 rollouts
- 每个候选经层级门控依次评估 → 7 维奖励向量 → 组内标准化 → CDPO 更新
- 基座模型：CodeLlama-7B / CodeQwen-7B / DeepSeek-Coder-v1.5-7B / Qwen2.5-Coder-7B-Instruct

**训练硬件与框架**：
- 4× NVIDIA A100 80GB GPU，总训练时长约 **52 GPU 小时**（13 × 4 A100 GPU hours）
- 框架：DeepSpeed ZeRO-2（分片优化器）+ vLLM（高吞吐候选采样）+ VeRL（RL 训练循环）
- 门控 + 线程池并行 + 等奖励过滤：单步奖励计算从 869s 压到 58s（-93.5%）

### 6.2 实验设置

**Benchmark**：
- VerilogEval-Human v1/v2（功能正确性）
- RTLLM v1.1（5 题 × 2 方向 = 10 个扩展 prompt，功能 + 语法）
- RTLLM v2.0（29-30 题，包含 PPA 参考值，支持 EDAP 评测）

**评估指标**：
- 功能性：pass@1/5/10（Codex 无偏估计，公式 11）
- PPA 综合：EDAP（公式 14），同时报告 ADP、EDP
- 归一化协议（公式 15-21）：只评测功能正确的设计，归一化到 benchmark 参考设计的 PPA

**基线方法**：
- 非 Agent baseline：GPT-4o、CodeLlama、DeepSeek-Coder 等 vanilla/微调模型
- RTL 专训模型：OriGen（DeepSeek-Coder-7B+LoRA）、CraftRTL-Starcoder2（15B）
- RL 算法基线（Table 5）：GRPO、DAPO（与 CDPO 对比）

**消融设计**：
- SFT-only vs SFT + CDPO（Table 7）：验证 CDPO 的增量贡献
- CDPO vs GRPO vs DAPO（Table 5）：验证算法设计的有效性
- 跨 PDK / 跨综合工具鲁棒性（Table 9）：Sky130 / gf180 / ihp_sg13g2 × Yosys / Design Compiler

## 7. 创新点

### 创新点 1：完整 EDA 工具链进 RL 奖励（对比外部后处理）

论文对既有 PPA 优化路线的批判（Sec 1）：

| 路线 | 代表 | 问题 |
|------|------|------|
| SFT 微调 | RTLCoder、CodeV | 数据里没有 PPA 标注，模型只学"写对"，不学"写好"——**Table 7 直接证明：SFT 后 EDAP 反而恶化**（CodeLlama 0.94→1.47，DeepSeek 2.65→1.51，Qwen2.5 1.04→1.31）。"optimizing for functionality does not guarantee optimization for PPA" |
| 推理时后处理 | VeriGen-MCTS（MCTS 搜索）、RTLRewriter | 不改变模型内在能力；每次使用都要重新搜索/重写，开销大；依赖外部管线 |
| **ChipSeek（本作）** | — | 把"功能对"和"PPA 好"直接编码进 reward，**训练时改参数**。推理时一次生成就是 PPA 感知的 |

Table 7 的 SFT→CDPO 对比是全文最有说服力的一组数字：SFT 让功能涨但 EDAP 恶化，**CDPO 一步把 EDAP 全压回 1.0 以下**（CodeLlama 0.94，DeepSeek 0.84，CodeQwen 0.82，Qwen2.5 0.88）。这说明纯 SFT 没有机制学 PPA，而 reward 驱动的 RL 有。

### 创新点 2：CDPO 的三件套（解耦 advantage / 课程权重 / 偏好向量）

已在 §5 逐公式展开。横向对比它和已有 RLVR 算法的区别：

| 算法 | reward 聚合位置 | 课程机制 | 偏好控制 |
|------|----------------|----------|----------|
| 标准 PPO（单标量 reward） | reward 空间（加权和） | ❌ | ❌ |
| GRPO（表 5 基线） | reward 空间（组内标量标准化） | ❌ | ❌ |
| DAPO（表 5 基线） | reward 空间 | ❌ | ❌ |
| **CDPO** | **advantage 空间（每维独立标准化后聚合）** | ✅ EMA 课程衰减 | ✅ prompt 条件偏好向量 |

Table 5 的直接对比（DeepSeek-Coder-7B，指标越低越好）：

| 方法 | Delay | Area | Power | ADP | EDP |
|------|------:|-----:|------:|----:|----:|
| GRPO | 0.89 | 0.90 | 0.91 | 0.85 | 0.85 |
| DAPO | 0.92 | 0.90 | 0.89 | 0.87 | 0.86 |
| **CDPO** | **0.84** | **0.87** | **0.86** | **0.79** | **0.77** |

### 创新点 3：层级门控的 fail-fast 奖励计算

§4.2 已述。工程创新，但价值被低估：**没有门控，这套方案在算力上不可行**。Figure 7 是证据：门控 + 并行 + 等奖励过滤把单步奖励计算从 869s 压到 58s。这个 93.5% 的削减是"EDA-in-the-loop RL 能跑起来"的物理前提。

### 创新点 4：相对参考的 PPA 奖励 $r_m = ref_m / gen_m$

**为什么用比值而不是绝对值**：

```text
绝对奖励：r = -gen_power（越小越好）
  问题：大设计功耗 100mW，小设计 1mW。同一个小优化（-0.5mW）
       在两组里产生完全不同的梯度量级。跨题 batch 聚合时，
       大设计主导梯度。

相对奖励：r = ref_m / gen_m
  gen_m = 0.5·ref_m（面积砍半）→ r = 2.0
  gen_m = 2·ref_m（面积翻倍）  → r = 0.5
  问题被消除：奖励是关于"相对参考的改进率"，与设计规模无关
```

大于 1 = 优于参考，小于 1 = 劣于参考。这是一个**有锚点的奖励**——锚点就是人类专家写的参考设计（benchmark 提供）。**它把训练目标隐式定义成"超越人类工程师的 PPA 基线"**，而不是抽象的"越小越好"。

（工程细节：奖励截断在 max 3.0，防止极端样本主导；这是标准化总结里指出的"极限优化被裁剪"的代价。）

### 创新点 5：全自动多阶段数据管线（无人工标注）

```text
裸 Verilog ──▶ DeepSeek-R1（反向生成描述 + CoT）──▶ GPT-5（生成 TB）
   ──▶ Icarus 验证过滤 ──▶ EDA 提取参考 PPA ──▶ 偏好增强
```

全部自动化，且论文明确：**两个训练集都严格过滤掉 benchmark 题目**（"Both training datasets are strictly filtered to exclude any cases from the benchmark"）——直接回应了 MAGE 那类系统面临的数据污染质疑。

### 创新点 6：跨工具链鲁棒性（Table 9，容易被忽略但重要）

论文做了严格的敏感性实验，固定评测协议，每次只换一个变量：

| 变量 | 取值 |
|------|------|
| PDK 库 | Sky130 / gf180 / ihp_sg13g2 |
| 综合工具 | 开源 Yosys / 商业 Design Compiler |
| 综合优化目标 | timing-driven / area-driven |

ChipSeek 在所有配置下都是 EDAP 最低的（0.77~0.81），而多个基线的 EDAP 随工具/库切换大幅波动（如 RTLCoder：Yosys 2.43 vs DC 0.97，差 2.5 倍）。**结论：模型学到的是"结构性更好"的代码，而不是"过拟合某条工具链的翻车参数"**。这个实验是证明 PPA 提升不是奖励过拟合的关键证据。

### 创新点 7：与 MAGE 的范式对照 —— 训练时 RL vs 推理时编排

本资料包中，ChipSeek 与 [MAGE](../MAGE/论文深度讲解.md) 构成了两条互补的技术路线，理解两者的分野是读懂 AI4EDA RTL 生成方向的关键。

**根本差异**：

| 维度 | MAGE（推理时编排） | ChipSeek（训练时 RL） |
|------|------|------|
| **改进发生在** | 推理时（inference-time） | 训练时（SFT + CDPO + EDA Reward） |
| **EDA 工具的角色** | 给 Debug Agent 提供反馈信号（不更新模型） | 给 RL 提供 reward 信号（更新模型参数） |
| **反馈粒度** | 逐拍信号级（State Checkpoint，细） | 整条回答级 advantage（粗，token 共享） |
| **优化目标** | 功能正确（$s(r)=1$） | 功能正确 **+ PPA**（EDAP 越低越好） |
| **部署成本** | 每题 20~50 次 LLM 调用 + 多次仿真 | 训练后一次前向生成，零 EDA 调用 |
| **知识积累** | 无（每题独立，不跨题学习） | 有（参数吸收 PPA 优化模式） |
| **领域适应** | 换题换模型零成本 | 换工艺/换域需重新训练 |
| **上界** | 受基座模型能力限制 | 理论上可超越基座（RL 探索新策略） |
| **覆盖流程阶段** | ①② | ①②③（+⑤ 快速近似） |

**为什么两者互补而非互斥**：

1. **MAGE 解决的是"如何用现有 LLM 最好地写 RTL"**——通过推理时的多 Agent 编排、高温采样、仿真反馈来最大化基座模型潜力。代价是每题推理成本高，且不积累知识。
2. **ChipSeek 解决的是"如何让 LLM 学会写好的 RTL"**——通过训练时的 RL 闭环，让模型参数吸收 EDA 工具反馈（综合面积/延迟），使模型在推理时甚至不需要多轮反馈就能一次生成 PPA 优化的代码。代价是需要训练数据和训练算力（52 A100 GPU 小时）。
3. **理想组合**：用 ChipSeek 训练一个 PPA 感知的领域模型，再用 MAGE 的编排方式在推理时进一步放大——训练时 RL 提升模型的下限（基座 PPA 能力），推理时编排提升模型的上限（通过多候选 + 反馈迭代）。ChipSeek 的功能正确率在 RTLLM 上还有提升空间（pass@5 最高 87.2%），MAGE 的 debug 环节恰好补这个缺口。

**关键数据对比**：

| 指标 | MAGE (Claude 3.5 Sonnet) | ChipSeek (Qwen2.5-Coder-7B) |
|------|:---:|:---:|
| VerilogEval-V2 pass@1 | 95.7% | 62.2% |
| VerilogEval-V2 pass@5 | — | 73.7% |
| PPA 优化 | 不感知 | EDAP avg -18% |
| 模型训练 | 不需要 | SFT 29K + RL 8K |
| 推理时 EDA | 每次必调 | 不需要 |

注意：MAGE 的功能正确率远高于 ChipSeek（95.7% vs 73.7%），但这来自三个因素的不对等：(1) Claude 3.5 Sonnet 是更强的基座模型；(2) MAGE 使用了高温 20 候选 + 仿真排序 + 多轮 debug，计算量远大于 ChipSeek 的单次推理；(3) MAGE 不优化 PPA，目标函数更简单。两者的数字不能直接对比，但路线差异清晰：**MAGE 用推理时计算换功能正确，ChipSeek 用训练时计算换 PPA 能力**。

## 8. EDA 缩写解释

按出现顺序，全称 + 实质解释：

| 缩写 | 全称 | 是什么 |
|------|------|--------|
| **RTL** | Register Transfer Level（寄存器传输级） | 只描述寄存器间数据流动的数字设计抽象层，见 [芯片流程] ① |
| **LLM** | Large Language Model（大语言模型） | 本文基座为 7B 级代码模型 |
| **PPA** | Power, Performance and Area（功耗、性能、面积） | 硬件质量三大指标。**本文的核心优化目标**——这是它和 MAGE 的本质差异 |
| **EDAP** | Energy-Delay-Area Product（能量-延迟-面积积） | = power×delay×area，越低越好。论文主报告指标 |
| **EDA** | Electronic Design Automation（电子设计自动化） | 芯片设计工具链总称；本文特指被接入 RL 的编译/仿真/综合/后端工具 |
| **SFT** | Supervised Fine-Tuning（监督微调） | 用 (prompt, 标准答案) 训练。本文用它做冷启动（29,127 条） |
| **RL** | Reinforcement Learning（强化学习） | 用奖励信号更新策略。本文的 CDPO 是其算法 |
| **CoT** | Chain of Thought（思维链） | `<thinking>...</thinking>` 显式推理过程。SFT 数据由 DeepSeek-R1 生成，RL 阶段有专门的 Format Reward 强制格式 |

## 9. 与芯片流程的关系

### 10.1 训练时 vs 推理时的工具链使用

```text
【训练时】（ChipSeek 的 EDA 集成在这里）
  候选 Verilog
      │
      ▼
  ① RTL 设计（策略生成）─────┐
      │                       │  ← 每个候选都要走，但 fail-fast
  ② RTL 功能仿真（Icarus）    │     门控砍掉 90%+ 的无效评估
      ▼                       │
  ③ 逻辑综合（Yosys）───────┼── 奖励：r_syn, r_area, r_delay
      ▼                       │
  ⑤近似 / ⑬早期 PPA（OpenROAD）─┘  奖励：r_power, r_delay, r_area
      │
      ▼
  7 维奖励 → CDPO → 更新 θ

【推理时】（用户看到的样子）
  设计描述 + [Design Priority] → 一次前向 → <thinking> + <answer>Verilog
  零 EDA 调用
```

### 10.2 ChipSeek 和 MAGE 在流程上的分工互补

| 问题 | MAGE 回答 | ChipSeek 回答 |
|------|-----------|---------------|
| 功能正确 | ✅（推理时迭代到 s(r)=1） | ✅（训练时学，推理一次成） |
| PPA 优化 | ❌ 完全不感知 | ✅（EDAP 平均 -18%） |
| 可综合性 | ❌ 不验证 | ✅（r_sys 奖励强制） |
| 跨题知识 | ❌ | ✅（参数内化） |
| 每题成本 | 高 | 训练摊销后低 |

**在真实流程里的理想组合**（论文没提，但逻辑自洽）：ChipSeek 做第一轮生成（PPA 感知、一次成），MAGE 做功能失败时的兜底修复——ChipSeek 的功能正确率还有提升空间（RTLLM v1.1 pass@5 最高 87.2%），MAGE 的 debug 环节恰好补这个缺口。两个系统正交。

### 10.3 对阶段 ③ 的一个深层观察：可综合 \neq 综合得好

ChipSeek 把 $r_{sys}$（Yosys 综合成功）设为过程奖励，把 PPA 设为核心奖励——**这个分层本身就在教模型区分两个层次**：

```text
r_sys = 1（可综合）     —— 下限：代码能变成门
r_ppa = ref/gen         —— 上限：变出来的门好不好
```

barrel shifter 案例完美展示了这个梯度的价值：基准写法的 24 个 mux 实例**完全可综合**（r_sys=1），但综合出来的网表比行为级写法大 13.3%。**如果没有 PPA 这一层奖励，模型永远学不会"可综合但不好的写法要避免"**——这恰恰是 SFT 的盲区（Table 7：SFT 后功能涨、PPA 跌）。

### 10.4 PPA 奖励的工艺依赖（诚实边界）

训练时的 PPA 全部来自 **NanGate45** 工艺。芯片流程里有一个基本原则：**PPA 数值随工艺变化，但"结构性好坏"的趋势通常跨工艺保持**。ChipSeek 的 Table 9 用三个不同 PDK 验证了后一半（趋势保持），但论文没有验证训练数据用 NanGate45 学出来的策略在 3nm 上是否仍有效——先进工艺下互连延迟主导、门延迟占比剧变，过去"省面积/省功耗"的策略可能翻转。这是它和真实 ⑬ 签核流程之间的物理距离。

## 10. 讨论与局限

### 10.1 算力：EDA-in-the-loop RL 的真成本

训练共消耗 **13 × 4 = 52 A100 GPU 小时**（论文附录 B："13 x 4 A100 GPU hours to fully train our models"）。其中奖励计算占大头——**即使有门控，每一步仍要并行跑最多 32×8=256 个候选的编译/仿真/综合**。

对比账（为什么这个方案对"题目量"有规模门槛）：
- 训练数据 8,453 条 RL 样本，每条要被模型生成+评估多次（每个候选一次）
- 若题库只有 100 道题，训练成本摊不下来——MAGE 这种零训练方案更划算
- 论文 Figure 7 的加速（-93.5% 奖励计算时间）说明**工程优化决定了这套方法的经济可行性**，这个点读论文时容易滑过

### 10.2 奖励函数的结构性问题

**(a) 信用分配（credit assignment）粗**：advantage 是**整条回答共享的**（公式 1 对同一候选所有 token 相同）。模型无法知道"是哪一行 RTL 导致了面积减少"。它只能靠**统计相关性**学习——这导致优化模式偏向"整体风格迁移"（比如学会写行为级而不实例化），而不是"精准局部手术"。论文在局限里承认了这一点。

**(b) 功能奖励是二值的**：$r_{fun} \in \{0,1\}$——"全过"和"差一个用例"都是 0。这在门控设计上是刻意的（功能不过就不算 PPA），但代价是**梯度里没有"渐进正确"的信息**。对比 MAGE 的 $s(r)=1-m/tc$ 连续评分，ChipSeek 的功能信号是离散的。

**(c) PPA 奖励被截断在 3.0**：论文未在正文强调，但标准化总结标注了这个细节。$r_m \in [0, 3]$，意味着"面积比参考好 4 倍"和"好 3 倍"拿同样的奖励。设计意图是防极端样本主导梯度，副作用是极限优化无额外奖励。

**(d) $w_{func}=1.0$ 固定**：功能正确性的权重不随课程衰减。这个选择保证了功能底线，但如果 PPA 偏好权重（$p_m$）之和大于 1 的维度被放大，存在"功能-质量"冲突的潜在风险。门控（功能不过不评 PPA）提供了结构性保障，但论文没有做"$w_{func}$ 变化"的敏感性实验。

### 10.3 数据管线的模型依赖与一致性风险

训练数据完全依赖两个商业模型：
- **DeepSeek-R1** 生成设计描述 + CoT——如果 R1 的推理链有错，SFT 冷启动就学了错范式
- **GPT-5** 生成 testbench——**TB 质量直接决定功能奖励的上限**。TB 覆盖不足时，"功能正确"的奖励可以给到一段其实没测全的代码（这个问题和 MAGE 的 golden TB 依赖同构，但更隐蔽：这里 TB 是生成的，没有参考实现背书）

此外，论文 v1→v2（2026-04-10 更新）里 R1/GPT-5 的版本漂移会影响可复现性。

### 10.4 优化能力的不均匀分布（Figure 6）

优化策略统计：**Arithmetic 模块占优化案例的 34.1%**，Control 仅 4.5%，Memory 4.5%。论文假设是训练数据中 control/memory 类电路太少。**后果**：ChipSeek 的 PPA 优势主要集中在运算密集型设计（加法器、移位器、乘法器）——这些恰好是**结构规律性强、综合器能做 operator inference** 的电路。对状态机、cache 控制器这类"结构自由度低、协议复杂度高"的设计，它的优化手段基本失效。Table 10 的 AutoSilicon 扩展（CPU/NPU 块，560 LoC）部分回应了这个问题，但那是规模上的扩展，不是电路类型上的覆盖。

### 10.5 评测协议的一个结构性盲区：PPA 与功能的耦合测量

公式 (15) 的过滤（只评功能正确的设计）是必要的，但它回避了一个问题：**模型有没有"为了 PPA 牺牲边缘功能"的倾向**？当训练时 PPA 奖励放大而功能奖励固定，理论上存在这样的局部最优：一段"覆盖了 testbench 主路径但漏掉边界条件"的设计，在训练数据里能拿到 $r_{fun}=1$（因为 TB 没测到）。论文的防线是过滤 benchmark 泄漏 + 门控，但**没有做形式验证级的回归检查**（论文 future work 明确列了 formal equivalence check）。在"PPA 奖励越来越高"的训练后期，这是一个真实的隐患。

### 10.6 与 MAGE 的直接对比：两条路线的代价对称性

| | MAGE（推理时反馈） | ChipSeek（训练时反馈） |
|---|---|---|
| 训练成本 | 0 | 52 A100 GPU 小时 + 数据管线 |
| 推理成本 | 每题 20~50 次 LLM + 多次仿真 | 一次生成 |
| 领域适应 | 换题换模型零成本 | 换工艺/换域要重训 |
| 反馈分辨率 | 逐拍信号级（细） | 整条回答级（粗） |
| 优化目标 | 单一（功能） | 多目标（功能 + PPA） |
| 可解释性 | 每步有轨迹可查 | 黑盒（只有学到了什么统计模式） |
| 上界 | 受基座模型能力限制 | 受基座 + RL 探索限制，理论上可超基座 |

**"训练时 vs 推理时"是 2025 年后 RTL 生成领域最核心的设计分岔之一**：前者把计算成本前移到训练、换来部署时的零工具调用；后者把成本留在每次推理、换来零训练门槛。ChipSeek 和 MAGE 是这个分岔的两极，合读才能看到全貌。

### 10.7 开放问题

1. **token 级/块级 PPA 反馈**：论文 future work。如果能把 OpenROAD 的面积报告分解到代码块（哪段 always 块综合出了多少面积），advantage 就能从整条回答降到语句级，信用分配问题（9.2a）有望缓解。这是当前架构最值得扩展的方向。
2. **课程权重的可解释性**：公式 (3) 的 $\alpha_k = 1 - \mu_k$ 假设"成功率高 = 不需要学"，但对 PPA 这种连续目标，成功率永远接近 100%（因为 $r_{fun}$ 过了就算"成功"），课程机制对核心奖励不生效——**它只对二值过程奖励有意义**。这意味着 PPA 优化全靠偏好向量撑着，缺乏自己的"易到难"调度。
3. **偏好向量的语义一致性**：`[low_power]` 标签映射到 $(0.7,0.1,0.2)$ 的映射表是手写的。用户说"优先省功耗"时，到底该给 power 多少权重？不同任务的最优映射可能不同。论文没有做这个映射的消融。
4. **训练-推理的分布偏移**：训练时 temperature=1.0, top_p=1.0（高随机），评测时 top_p=0.7。模型学的是"高随机采样下的策略"，评测在更保守的分布上——论文没有讨论这个偏移是否影响 PPA 能力的外推。
5. **奖励模型的工艺迁移**（§8.4）：NanGate45 训练的策略在先进工艺是否仍优，没有实验证据。Table 9 只证明了"评测侧"的跨 PDK 鲁棒，不是"训练侧"的。

## 12. 一分钟复述版

ChipSeek（中科院计算所，arXiv 2507.04736）是**把完整 EDA 工具链反馈接进强化学习奖励的 RTL 生成训练框架**，与 MAGE 形成"训练时 vs 推理时"的镜像对照。

- **目标**：不仅写对（功能），还要写好（PPA）——Figure 1 显示多数模型的生成结果 EDAP 比人类专家还差
- **奖励**：候选 Verilog 依次过 Format → Icarus 编译 → testbench 仿真 → Yosys 综合 → OpenROAD 报 PPA，得到 7 维分层奖励，**门控 fail-fast** 保证上游失败不跑下游（奖励计算 -93.5%）
- **CDPO 三件套**：① 每维奖励独立标准化成 advantage（解决二值/连续奖励的尺度不匹配）；② 课程权重 $\alpha_k = 1-\mu_k$ 随掌握度 EMA 衰减（先学语法，后学 PPA）；③ 偏好向量 $p(q)=(p_P,p_D,p_A)$ 按 prompt 标签加权（`[low_power]` 等可控多目标）
- **数据**：DeepSeek-R1 反向生成 CoT + GPT-5 生成 TB + EDA 提取参考 PPA，全自动，严格过滤 benchmark 泄漏
- **结果**：RTLLM v2.0 pass@5 +11.4%、EDAP 平均 -18%；跨 3 个 PDK / 2 个综合工具保持最优（Table 9）；52 A100 GPU 小时训练出 7B 模型
