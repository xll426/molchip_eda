## 1. 一句话定位

**CASS-RTL 是首个面向"RTL 代码生成 LLM 内部正确性信号"的推理时子空间转向框架：用 KL 散度从多头自注意力的 ⟨EOS⟩ 激活中识别"对功能正确性敏感"的头（correctness-aware heads），把它们拼接起来用 LDA / PCA 构造低维正确性子空间，推理时把每一解码步的当前激活投影到子空间、向"正确类均值"方向加一个可调步长 α 的矫正向量 ΔX 做精确 steering——整套机制完全不重训、不调权重、不依赖真值标签，在 VerilogEval + CVDP 两个 benchmark 上让 CodeLlama-7B、QwenCoder-14B、CodeV 三个模型的 pass@1/5/10 一致提升 10–20%（VerilogEval）和 ~5%（CVDP），并通过 mask-ablation 因果验证和 logit-shift 分析证实这些 head 真的"管"着正确性。**

这句话里的七个技术承重点：

1. **"模型内部知道对不对"的洞察** — 受 "LLM 知道何时自己错了" [Azaria & Mitchell, EMNLP'23] 和 ITI（Inference-Time Intervention）[NeurIPS'23] 启发，把"挖掘模型内部正确性信号"做成一个独立 RTL 任务。这类"自我诊断"信号在自然语言里已被多次证实，但**在 RTL 这种结构化、强约束的代码上从未系统化**——这是 CASS-RTL 的根本动机。
2. **基于 KL 散度的注意力差分（C-I vs C-C）** — 同时构造两类样本对：正确-正确（C-C，同一指令的两个等价但风格不同的实现）和正确-不正确（C-I，同一指令的正确与错误实现）。对每一对样本，把每个头的注意力向量视作概率分布，计算归一化 KL 散度，**用差值 $D_{C-I} - D_{C-C}$ 去除"风格差异"带来的背景噪声**，剩下的就是"被正确性直接驱动的注意力变化"。
3. **Correctness Score + 长尾分布 + Top-K 头选取** — 把所有样本对的差分 KL 散度按 head 平均，得到每头的 $S_{\text{correctness}}^{(l,h)}$。论文 Figure 3 显示这是一个长尾分布（top-100 头 $y = 0.6676 e^{-0.019x}$ 的指数衰减），只取 Top-K=30 个头组成 steering 子集——这是"稀疏干预 + 强信号"的经典设计。
4. **PCA + LDA 构造低维正确性子空间** — 把 Top-K 个 head 在 EOS 位置的 $D_h$ 维 context vector 拼接成一个 $D_{\text{total}} = N_{\text{sel}} \cdot D_h$ 维向量，按正确/不正确两类分别算 $\mu^+, \mu^-$，中心化后做 PCA 抽出 top-k 主成分。论文 Figure 4 显示哪怕只投影到 2D，正确/不正确样本也已清晰可分；再用 LDA 证明是"线性可分"——这为方向性干预提供了数学保证。
5. **推理时子空间转向 + 几何感知矫正** — 在每一步自回归解码时，把当前激活 $X_{\text{current}}$ 投影到 PCA 子空间得到 $X_{\text{proj}} = BB^\top X_{\text{current}}$，把"差向量" $\Delta X = \mu^+ - X_{\text{proj}}$ 作为矫正信号，最终更新为 $X_{\text{steered}} = X_{\text{current}} + \alpha \cdot \Delta X$。**注意 ΔX 不是静态预存的方向，而是每次根据当前激活动态计算的几何矫正量**——这就是所谓的 "geometry-aware"。
6. **零训练 / 零标注 / 模型无关** — 整个 pipeline 不需要人工标注的真值对、不需要 SFT、不需要 RLHF。它和已有的 fine-tuning 方法（如 CodeV-R1）、inference-time scaling（如 ScaleRTL）、self-verification 全部正交——可在它们的基础上叠加，进一步推升正确率。
7. **跨模型、跨 benchmark 的一致增益** — 在 7B（CodeLlama）、14B（QwenCoder-2.5）和 RTL 微调模型（CodeV）上、VerilogEval 和 CVDP 两个 benchmark 上均观察到 5–20% 的 pass@k 提升；通过 mask ablation 验证因果性、通过 logit shift 验证信号方向——这些给出了"科学性而非玄学"的实证背书。

**覆盖率：1/17 核心 + 1/17 验证反馈 + 1/17 隐含互补。** CASS-RTL 聚焦在 ① 阶段（RTL 代码生成本身），并以 ② 阶段的仿真结果作为"正确性反馈的真值标签"——但这只用于离线度量，不进入推理循环。

> ⚠️ **容易误读的边界**：
> - CASS-RTL 的"功能正确"完全由 testbench / simulation 定义，**PPA 完全不在优化目标里**。即使 CASS-RTL 让 pass@1 涨了 10 个点，**也不能保证综合后的面积/功耗/时序有任何改善**
> - "子空间转向"改的是 *推理时激活分布*，不是 *模型权重*。所以模型大小、训练数据、许可证条款不变——这意味着部署它的工程风险比 SFT 小得多，但仍可能在边缘 case 上出现"和未转向模型不一样的偏差"
> - CASS-RTL **不做 SVA、断言、形式化**；它和 [ChipMATE](../ChipMATE/论文深度讲解.md)、[MAGE](../MAGE/论文深度讲解.md)、[RTLCoder](../RTL-Coder/论文深度讲解.md)、[CodeV-R1](../CodeV-R1/论文深度讲解.md)、[OriGen](../OriGen/论文深度讲解.md)、[ScaleRTL](../RTL-Coder/论文深度讲解.md)、[CraftRTL](../CraftRTL/论文深度讲解.md) 是**正交可叠加**关系
> - CASS-RTL 和同一团队前一工作 [DecoRTL](../DecoRTL/论文深度讲解.md)（解码策略增强）也是**正交**：CASS-RTL 改 attention head 内部信号，DecoRTL 改 token 选择与温度——两者可堆叠

## 3. 输入 / 输出

### 3.1 输入

**(a) 自然语言设计指令（NL Instruction）**

CASS-RTL 的输入是 design prompt，例如：

```text
Instruction:
Write a Verilog module that computes the bitwise AND of two 8-bit inputs a and b,
and outputs the result as out.
```

**(b) 待增强的预训练 RTL LLM**

论文主实验的目标模型是 **Qwen2.5-Coder-14B**（同时也跑了 CodeLlama-7B、CodeV）。 CASS-RTL 完全不改模型权重，只在每个解码步截取内部激活。

**(c) 阶段一所需的训练样本对**

- **C-I 对（正确-不正确）**：同一指令的两个 RTL 实现，一个功能正确、一个有 bug。来源论文未公开细节，但根据上下文（基本构造块如 control / memory / combinational / arithmetic），应来自 VerilogEval 的正确实现 + 人工注入 bug 的版本，或来自 RTL-Coder 的 self-debug 输出
- **C-C 对（正确-正确）**：同一指令的两个**功能等价但结构不同**的实现（例如循环展开 vs 状态机）

```text
对每个 (instruction, RTL_C, RTL_I) 三元组:
  对 RTL_C 跑 forward → 提取每 head 在 EOS 位置的注意力向量 P_C^{(l,h)}
  对 RTL_I 跑 forward → 提取每 head 在 EOS 位置的注意力向量 P_I^{(l,h)}
  对另一个 RTL'_C 跑 forward → 提取 P_{C'}^{(l,h)}

  D_{C-I}^{(l,h)} = KL(P_C^{(l,h)} || P_I^{(l,h)})    [非对称 KL]
  D_{C-C}^{(l,h)} = KL(P_C^{(l,h)} || P_{C'}^{(l,h)}) [风格散度]

  正确性 Sensitivity:
  S^{(l,h)} = D_{C-I}^{(l,h)} - D_{C-C}^{(l,h)}     [Eq. 7]
```

论文未明确说明 C-I 对和 C-C 对的总数 M，但从 Figure 3 的指数衰减拟合（$y = 0.6676 e^{-0.019x}$，attributed to top-100 头）反推应该有数十到数百个样本对。

### 3.2 中间产物

**(a) Correctness Score 矩阵** $S \in \mathbb{R}^{L \times H}$：$L$ 是模型层数，$H$ 是每层头数，每一格是该头在所有样本上的平均 KL 差分。

**(b) 选中的 Top-K correctness-aware heads** $H = \{(l_1, h_1), \ldots, (l_{N_{\text{sel}}}, h_{N_{\text{sel}}})\}$，其中 $N_{\text{sel}} = 30$（论文主设置）。

**(c) 拼接的 context 向量**：

$$
X^{(G)} = [o_{l_1,h_1,\text{eos}}^{(G)}, \ldots, o_{l_{N_{\text{sel}}},h_{N_{\text{sel}}},\text{eos}}^{(G)}] \in \mathbb{R}^{D_{\text{total}}}
$$

其中 $D_{\text{total}} = N_{\text{sel}} \cdot D_h$。

**(d) 类条件均值**：

$$
\mu^+ = \frac{1}{|D^+|} \sum_{X \in D^+} X, \quad \mu^- = \frac{1}{|D^-|} \sum_{X \in D^-} X
$$

**(e) PCA 投影矩阵** $B \in \mathbb{R}^{D_{\text{total}} \times k}$：top-k 主成分方向。

### 3.3 输出

**(a) Steering 后的完整 RTL 代码**（标准文本生成产物）

```verilog
module and_gate(
    input  [7:0] a,
    input  [7:0] b,
    output [7:0] out
);
    assign out = a & b;
endmodule
```

**(b) 推理时每个解码步都隐式产生的"逐头矫正量"** $\Delta X \in \mathbb{R}^{D_{\text{total}}}$，被 reshape 回原 head 维度后注入 attention head 输出。这部分对外部是黑盒，但被 ablation 实验（Figure 5）证明是"必需且足够"的。

**(c) 训练好的子空间**（$B, \mu^+, \mu^-$）被持久化保存，部署时只需加载这三个张量 + steering 强度 $\alpha$。

## 4. 方法与架构

### 4.1 整体 Pipeline

CASS-RTL 由**三个串联阶段**组成，全部在 forward pass 上完成，无梯度回传：

```text
                  CASS-RTL 三阶段推理时转向框架
   ═══════════════════════════════════════════════════════════════

   ┌──────────────────────────────────────────────────────────────┐
   │  离线一次性（per-model, per-benchmark, ~小时级）                │
   │                                                              │
   │  RTL_C, RTL_I, RTL'_C  ─┐                                   │
   │                         ▼                                   │
   │            ┌────────────────────────────┐                   │
   │            │ Forward pass on target LLM  │                   │
   │            │ 抓 EOS token 在每个 head    │                   │
   │            │ 的 attention 分布 P^{(l,h)}  │                   │
   │            └─────────────┬──────────────┘                   │
   │                          ▼                                  │
   │        ┌─────────────────────────────────┐                  │
   │        │ KL(P_C||P_I) - KL(P_C||P_C')    │  Eq.7 去噪声     │

### 4.2 模块 1：注意力机制与 EOS token 选择

每个 decoder-only Transformer 层 $\ell$ 和 head $h$ 的多头自注意力 (MHSA)：

$$
Q_{\ell,h} = X W_{\ell,h}^Q, \quad K_{\ell,h} = X W_{\ell,h}^K, \quad V_{\ell,h} = X W_{\ell,h}^V
$$

其中 $X \in \mathbb{R}^{S \times d}$，$W_{\ell,h}^{Q,K,V} \in \mathbb{R}^{d \times d_h}$。scaled dot-product attention：

$$
A_{\ell,h} = \mathrm{softmax}\left(\frac{Q_{\ell,h} K_{\ell,h}^\top}{\sqrt{d_h}}\right) \in \mathbb{R}^{S \times S}
$$

**为什么选 EOS token 的注意力向量作为"该 head 的状态指纹"？** 在自回归解码中，最后生成的 token "看见了整个序列"，它的 query 向量与其他所有 key 做点积，得到的注意力行向量是对"该 head 在该序列上如何分配注意力"的完整总结。论文用这个 $o_{\ell,h,\text{eos}} \in \mathbb{R}^{d_h}$ 作为单 head 表征，既包含统计信息（分布形状），又包含语义信息（关注哪些 token）。

### 4.3 模块 2：构造 C-I / C-C 样本对

论文要求构造两种样本对：

- **C-I（Correct-Incorrect）**：同一指令的两个 RTL，一个通过 testbench、一个不通过。这样"功能正确性"是唯一变量
- **C-C（Correct-Correct）**：同一指令的两个 RTL，**功能等价但风格不同**（如 while 循环 vs for 循环、`case` vs `if-else if` 链、不同变量命名）。这样"风格 / 写法"成为唯一变量

把每个 head 在 EOS 处的注意力向量视作离散概率分布（归一化到 $[0,1]$），计算归一化 KL 散度：

$$
D_{C-I}^{(l,h)} = D_{\mathrm{KL}}\left(P^{(T)}_{\ell,h} \,\|\, P^{(C)}_{\ell,h}\right) \in [0, 1]
$$

$$
D_{C-C}^{(l,h)} = D_{\mathrm{KL}}\left(P^{(T)}_{\ell,h} \,\|\, P^{(C')}_{\ell,h}\right) \in [0, 1]
$$

**关键设计**：单独用 $D_{C-I}$ 是有偏的——因为 $D_{C-I}$ 既包含"功能差异引起的注意力变化"也包含"任何代码风格差异引起的注意力变化"。直接做差分去掉风格噪声：

$$
S^{(T_i)}_{\text{correctness}}(l, h) = D^{(T_i)}_{C-I}(l, h) - D^{(T_i)}_{C-C}(l, h)
$$

这个减法只保留"风格无法解释的那部分注意力差异"，论文 Figure 2 的 (a)-(e)（C-C 散度热力图）与 (f)-(j)（C-I 散度热力图）的对比清晰展示了：前者大部分层 / 头都接近 0，后者则有明显的大块高亮区。

### 4.4 模块 3：Correctness Score + Top-K 选取

对 $M$ 个样本对取平均，得到每个 head 的 sensitivity score：

$$
S_{\text{correctness}}(l, h) = \frac{1}{M} \sum_{i=1}^{M} S^{(T_i)}_{\text{correctness}}(l, h)
$$

论文 Figure 3 显示 Top-100 head 的 $S_{\text{correctness}}$ 服从指数衰减（$y = 0.6676 e^{-0.019x}$），意味着只有少量头对正确性敏感。

**Top-K head 选择**：

$$
H = \{(l_1, h_1), (l_2, h_2), \ldots, (l_{N_{\text{sel}}}, h_{N_{\text{sel}}})\}, \quad N_{\text{sel}} = K
$$

取 $S_{\text{correctness}}$ 最大的前 $K$ 个 head。论文做 sweep（Figure 8）发现 $K=30$ 是 VerilogEval 上 Pass@1 的 sweet spot，$K=35\text{-}40$ 是 Pass@10 的 sweet spot。

### 4.5 模块 4：PCA 子空间构造

对每个被选中的 head $(\ell, h) \in H$，提取其在 EOS 处的 context vector：

$$
o^{(G)}_{\ell, h, \text{eos}} \in \mathbb{R}^{D_h}
$$

这些向量被拼接：

$$
X^{(G)} = [o^{(G)}_{\ell_1, h_1, \text{eos}}, o^{(G)}_{\ell_2, h_2, \text{eos}}, \ldots, o^{(G)}_{\ell_{N_{\text{sel}}}, h_{N_{\text{sel}}}, \text{eos}}] \in \mathbb{R}^{D_{\text{total}}}
$$

其中 $D_{\text{total}} = N_{\text{sel}} \cdot D_h$。

按正确 / 不正确标签分成两个集合 $D^+, D^-$，分别算类均值 $\mu^+, \mu^-$（Eq. 11），然后中心化做 PCA：

$$
B = \arg\max_{B^\top B = I} \mathrm{Tr}(B^\top \Sigma B)
$$

其中 $\Sigma$ 是中心化向量的协方差矩阵，$B \in \mathbb{R}^{D_{\text{total}} \times k}$ 包含 top-k 主成分。

论文 Figure 4(a) 显示即使只投影到 2 维，正确 / 不正确样本已肉眼可分；Figure 4(b) 显示 LDA 投影后类别中心几乎无重叠，验证"正确性"在该子空间内是**线性可分**的（这是 ITI 假设但未严格验证的前提，CASS-RTL 提供了实证）。

### 4.6 模块 5：推理时子空间转向 (Steering)

这是 CASS-RTL 的运行时部分，对生成的每一个 token 重复一次：

**Step 1**：抓当前 step $t$ 的多头激活 $X_{\text{current}} \in \mathbb{R}^{D_{\text{total}}}$（只抓选中 head 在 EOS / 当前正在解码 token 处的 context vector）

**Step 2**：投影到正确性子空间：

$$
X_{\text{proj}} = B B^\top X_{\text{current}} \in \mathbb{R}^{D_{\text{total}}}
$$

**Step 3**：计算几何矫正向量（Eq. 14）：

$$
\Delta X = \mu^+ - X_{\text{proj}}
$$

**Step 4**：更新激活（Eq. 15）：

$$
X_{\text{steered}} = X_{\text{current}} + \alpha \cdot \Delta X
$$

其中 $\alpha > 0$ 是可调 steering 强度。

**Step 5**：reshape 回原 head / head_dim 维度，注入对应 attention head 的输出位置，剩余计算流程不变。

### 4.7 模块职责矩阵

| 模块 | 输入 | 输出 | 用到的工具 / 模型 | 是否需训练 |
|------|------|------|-----------------|----------|
| Stage 1：HL 敏感头识别 | 多对 (RTL_C, RTL_I, RTL_C') | $S_{\text{correctness}}^{(\ell,h)}$ 矩阵 + 选中的 head 集合 $H$ | 目标 LLM（仅 forward） | **离线一次性**，不更新权重 |
| Stage 2：子空间构造 | $H$ 内每个 head 的 EOS context vector | $B, \mu^+, \mu^-$ | PCA（LDA 用于验证） | **离线一次性**，无梯度 |
| Stage 3：单步 steering | 当前激活 $X_{\text{current}}$ | $X_{\text{steered}}$ | 矩阵乘（$B B^\top \cdot X$, $(\mu^+ - X_{\text{proj}})$） | **零参数**，纯几何运算 |

## 5. 关键公式

### 5.1 注意力输出（背景）

$$
A_{\ell,h} = \mathrm{softmax}\left(\frac{Q_{\ell,h} K_{\ell,h}^\top}{\sqrt{d_h}}\right) \in \mathbb{R}^{S \times S}
$$

$$
O_{\ell,h} = A_{\ell,h} V_{\ell,h} \in \mathbb{R}^{S \times d_h}
$$

- $A_{\ell,h}$：第 $\ell$ 层 head $h$ 的注意力矩阵
- $d_h$：每个 head 的特征维数
- $S$：序列长度

**工程直觉**：注意力矩阵的每一行回答"当前位置在多大比例上参考了序列中其他位置"；row-sum = 1。

### 5.2 MHSA 拼接与投影（背景）

$$
\mathrm{MHSA}_\ell(X) = \mathrm{Concat}(O_{\ell,1}, \ldots, O_{\ell,H}) W_\ell^O
$$

- $W_\ell^O \in \mathbb{R}^{H d_h \times d}$：输出投影，把多头拼接结果投回模型维度

### 5.3 EOS token 的 context vector

$$
o_{\ell,h,\text{eos}} := o_{\ell,h, S-1} \in \mathbb{R}^{d_h}
$$

**为什么用 EOS**：在自回归解码里，最后生成的 token "看见"了整个 prompt + 已生成的所有 token。它的 query 向量与所有其他 token 的 key 做点积，是该 head 在该序列上注意力分配的完整代表。

### 5.4 类条件 KL 散度

$$
D^{(T_i)}_{C-I}(\ell, h) = D_{\mathrm{KL}}\!\left(P^{(T_i)}_{\ell,h} \,\|\, P^{(C_i)}_{\ell,h}\right) \in [0, 1]
$$

$$
D^{(T_i)}_{C-C}(\ell, h) = D_{\mathrm{KL}}\!\left(P^{(T_i)}_{\ell,h} \,\|\, P^{(C'_i)}_{\ell,h}\right) \in [0, 1]
$$

- $P^{(T_i)}_{\ell,h}, P^{(C_i)}_{\ell,h}, P^{(C'_i)}_{\ell,h}$：将注意力向量归一化得到的概率分布
- $D_{\mathrm{KL}}$：归一化 KL 散度

**注意**：归一化把 KL 散度裁剪到 $[0, 1]$，便于跨 head 比较。

### 5.5 Correctness Score

$$
S^{(T_i)}_{\text{correctness}}(\ell, h) = D^{(T_i)}_{C-I}(\ell, h) - D^{(T_i)}_{C-C}(\ell, h)
$$

- 当 C-I > C-C 时，差值为正 → 该 head 对"功能性"敏感
- 当 C-I ≤ C-C 时，差值 ≤ 0 → 该 head 只对"风格"敏感

### 5.6 跨样本聚合

$$
S_{\text{correctness}}(\ell, h) = \frac{1}{M} \sum_{i=1}^{M} S^{(T_i)}_{\text{correctness}}(\ell, h)
$$

- $M$：样本对数

### 5.7 拼接 context 表示

$$
X^{(G)} = [o^{(G)}_{\ell_1, h_1, \text{eos}}, \ldots, o^{(G)}_{\ell_{N_{\text{sel}}}, h_{N_{\text{sel}}}, \text{eos}}] \in \mathbb{R}^{D_{\text{total}}}
$$

- $D_{\text{total}} = N_{\text{sel}} \cdot D_h$

### 5.8 类条件均值

$$
\mu^+ = \frac{1}{|D^+|} \sum_{X \in D^+} X, \quad \mu^- = \frac{1}{|D^-|} \sum_{X \in D^-} X
$$

- $D^+, D^-$：正确 / 不正确样本的 context 向量集合

### 5.9 PCA 子空间

$$
B = \arg\max_{B^\top B = I} \mathrm{Tr}(B^\top \Sigma B) \in \mathbb{R}^{D_{\text{total}} \times k}
$$

- $\Sigma$：中心化向量的协方差矩阵
- $k$：保留的主成分数（论文未明确报告，但 figure 4 暗示 $k \approx 2\text{-}5$）

### 5.10 推理时投影

$$
X_{\text{proj}} = B B^\top X_{\text{current}} \in \mathbb{R}^{D_{\text{total}}}
$$

- $B B^\top$：到子空间的正交投影算子

### 5.11 几何矫正向量

$$
U = B B^\top \mu^+, \quad \Delta X = U - X_{\text{proj}}
$$

**直觉**：把当前激活投到子空间后，向"正确类均值在该子空间的投影"方向走一步，就得到矫正量。这种 ΔX 不是固定的全局方向，而是**由当前激活几何决定的局部方向**——所以论文称之为 "geometry-aware"。

### 5.12 最终 steering 更新

$$
X_{\text{steered}} = X_{\text{current}} + \alpha \cdot \Delta X
$$

- $\alpha \in \{0.1, 0.2, 0.3, 0.4\}$：论文 sweep 的取值，$\alpha = 0.3$ 是大多数模型 / benchmark 的最优

### 5.13 Logit Shift（验证 steering 效果）

$$
\Delta \ell(t_i) = \ell_{\text{steered}}(t_i) - \ell_{\text{orig}}(t_i)
$$

$$
\overline{\Delta \ell} = \frac{1}{T} \sum_{i=1}^{T} \Delta \ell(t_i)
$$

- $T$：ground-truth token 数
- $\Delta \ell > 0$：steering 提升了对 ground-truth token 的 confidence；正越多越有效

## 6. 训练与实验设置

### 6.1 是否需要训练

**CASS-RTL 本身零训练**——不更新模型任何权重。但构造子空间阶段确实需要一组已标注的 (RTL_C, RTL_I, RTL_C') 样本对来跑 forward + 算 KL 散度 + 算 PCA。论文用的是通用 RTL building blocks（控制、存储、组合、算术），所以这些样本对可以少量（数十到数百）就够。

### 6.2 实验设置

#### Benchmark

- **VerilogEval** [Liu et al., ICCAD'23]：经典 Human-set / Machine-set，**功能正确性由仿真 + testbench 判定**
- **CVDP** [Pinckney et al., 2025]：Comprehensive Verilog Design Problems，更大、更难、覆盖更多工业场景

#### Baseline

- **Base 模型无 steering**：仅 greedy / top-p 解码
- **ITI** [Li et al., NeurIPS'23]：作者严格复现——每个 head 训练一个 binary classifier（正确 / 不正确），取预测准确率 top-30 head，每 head 算"正确 - 错误均值差"作为方向向量，推理时按固定方向加 steering

#### 评估指标

- **Func@k**（Function Pass Rate）：对每个 prompt 采样 $k$ 次、任一通过 testbench 视为通过。这是 VerilogEval / CVDP 的标准指标
- **Pass@1**：单次生成通过率，最严格
- **Pass@5 / Pass@10**：多次采样后通过率
- **Logit Shift** $\Delta \ell$：steering 后 ground-truth token 的 logit 变化，验证信号方向
- **Ablation F1**：mask ablation 后功能正确率下降幅度，验证 head 因果性

#### Steering 强度 $\alpha$ sweep

论文 Figure 6 在 $\alpha \in \{0.1, 0.2, 0.3, 0.4\}$ 范围内测试，$\alpha = 0.3$ 一致优于 $\alpha = 0.1$（说明推力足够）和 $\alpha = 0.4$（说明未过冲）。

#### 头数 $N_{\text{sel}}$ sweep

论文 Figure 8 在 $N_{\text{sel}} \in \{5, 10, 20, 30, 40, 50, 60\}$ 上测试：Pass@1 / Pass@5 在 30 达峰，Pass@10 在 35-40 饱和。

论文 Figure 5 显示：

**这张图说明了什么**：

1. **重要 head 是 causally 必要**：mask 它们准确率掉 8 个百分点，远超 random mask 的 2 个百分点
2. **差值（~6 pp）就是"被选中的 head 实际贡献的功能正确性"**——这与 steering 注入后涨 ~10 pp 的幅度匹配（前者是去掉贡献，后者是加强贡献）
3. **因果关系的实验证据**：论文不仅仅是"看相关性"，而是实证"mask → 退化"和"steer → 提升"对称地存在

### 6.5 Steering 强度分析

论文 Figure 7：随着 $\alpha$ 增加，token-level logit shift 的分布从"集中于 0"逐步右移到"偏向正值"。$\alpha = 0.4$ 时分布集中在 0.2 附近，全部正。

## 7. 创新点

### 7.1 首个针对 RTL 代码生成的注意力-头级 correctness 提取框架

**贡献**：把"模型内部是否有正确性信号"从一个**通用 NLP 现象**变成一个**结构化、可度量、可执行**的 RTL-specific 框架。

**关键区别**：ITI / TruthX / TrFr / CCS 这些方法都在自然语言或开放域 QA 上做"事实正确性"。CASS-RTL **首次**在 RTL 这种：

- token 种类有限（关键字 + 运算符 + 标识符）
- 功能正确性有客观判据（testbench 通过 / 不通过）
- 结构性约束极强（位宽敏感、时序敏感、并发敏感）

的代码领域上做 head-level steering，并给出因果验证。

### 7.2 C-I vs C-C 差分 KL 散度（去风格噪声）

**贡献**：单独的 $D_{C-I}$ 是"功能性 + 风格性"的混合信号。CASS-RTL 用 $D_{C-I} - D_{C-C}$ **自动去除风格引起的注意力扰动**，把"功能性"信号单独留下来。

**为什么这么设计**：风格差异（变量命名、缩进、代码组织）在注意力图上会引起显著扰动。如果不去除，C-I 散度会把这些噪声 head 一并选中，导致 steering 后模型风格也被改。差分后，只有"对功能正确性独有的差异"被保留。

### 7.3 Geometry-aware 推理时 steering

**贡献**：矫正向量 $\Delta X = U - X_{\text{proj}}$ 不是预存的全局方向，而是**当前激活几何位置的函数**。这让 steering 在每一解码步根据"该步注意力的具体形态"动态调整方向。

**对比 ITI**：ITI 用的是"全局方向向量 + 固定缩放"（$X_{\text{steered}} = X + \alpha \cdot d$，$d$ 是常数）。CASS-RTL 的 $U = B B^\top \mu^+$ 在每步都重新计算。理论上这避免了 ITI 在"激活已经偏向正确方向时还要继续推"造成的过冲。

### 7.4 零训练 / 零标注 / 完全模型无关

**贡献**：CASS-RTL 不需要：
- 任何人工标注的真值（所有信号都是从模型自己生成的样本中提取的）
- 任何 backprop / fine-tuning（子空间通过 PCA / KL 散度解析构造）
- 任何 per-task 调整（一旦构造好，对新 prompt 不需重新做）

**意义**：可以无缝叠加在已有 SFT / RLHF / inference-time 方法（如 [CodeV-R1](../CodeV-R1/论文深度讲解.md)、[OriGen](../OriGen/论文深度讲解.md)、[CraftRTL](../CraftRTL/论文深度讲解.md)）之上，使这些"花了大钱训的模型"再次"榨取"额外性能。

### 7.5 因果 + 信号两个独立维度的实证

**贡献**：论文不只是"看到 pass@k 涨了"，而是给出：

- **mask ablation**（Figure 5）证明选中的 head 是 causally 必要
- **logit shift**（Figure 6 / Figure 7）证明 steering 在朝正确方向加力

这两个独立维度的实证让 CASS-RTL 比多数黑盒解码增强方法**更可解释、更可信**。

NL spec ─→ Base LLM ─→ RTL ─→ 综合 ─→ 仿真 ─→ 流片
                       ↑

NL spec ─→ Base LLM ──[ steer ]─→ RTL（更正确） ─→ 综合 ─→ ...
```

| [HierSVA](../HierSVA/论文深度讲解.md) | SVA 形式验证 | ⑥ | **正交可叠加**（CASS-RTL 让 RTL 更对，HierSVA 验证 SVA） |
| [TopoRTL](../TopoRTL/论文深度讲解.md) | RTL 表示学习 | ① 离线 | 不直接相关（输入粒度不同） |

### 9.2 与本资料包其他论文的具体关系

- **[DecoRTL](../DecoRTL/论文深度讲解.md)** 是同一作者团队（UCF）的"姊妹工作"：DecoRTL 处理 token 级解码（temperature / contrastive re-ranking），CASS-RTL 处理 attention head 内部信号。两者都是推理时增强方法，都可叠加
- **[HierSVA](../HierSVA/论文深度讲解.md)** 处理的是 ⑥ 形式验证阶段：CASS-RTL 在 ① 阶段减少生成的 bug，HierSVA 评估生成的 SVA 能否抓到 bug。两者可视为"RLT 正确性生态"的上下游
- **[OriGen](../OriGen/论文深度讲解.md)** 和 [CraftRTL](../CraftRTL/论文深度讲解.md) 在训练阶段用更多 / 更好数据，CASS-RTL 在推理阶段把已有数据榨得更准——*互补*关系

### 9.3 "仿真通过"和"能做成芯片"之间隔着什么

即使 CASS-RTL 把 pass@1 推高 10 个点，从"功能仿真通过"到"做成能流片的芯片"仍隔着至少 8 个环节：

1. **可综合性检查**：生成的 RTL 是否能被 Synopsys DC / Cadence Genus 综合？是否用了非可综合语句（`initial`、`#delays`、`force` 等）？
2. **时序收敛**：综合出的网表能否在目标频率下满足 setup / hold？
3. **面积 / 功耗优化**：CASS-RTL 完全不优化这些指标
4. **断言 / 形式验证**：是否生成了足以覆盖 corner case 的 SVA？——这是 [HierSVA](../HierSVA/论文深度讲解.md) 直接解决的问题
5. **跨模块集成**：单模块正确 ≠ 在 SoC 集成后正确（接口协议、时钟域、复位策略）
6. **DFT / 扫描 / BIST**：测试覆盖率约束
7. **物理设计**：布局 / CTS / 布线后是否仍满足时序
8. **签核**：DRC / LVS / IR Drop / EM / 功耗

CASS-RTL 解决的只是上述链条的**第一步**（"功能上大概对不对"），且仅在 testbench 给出的功能上，不能保证工业级覆盖率。

## 10. 讨论与局限

### 10.1 论文自述局限

1. **样本对构造依赖人工 / 现有工具**：C-I 对中的"错误 RTL"得来自某处（人工注入 / self-debug / 故意改 RTL），C-C 对中的"等价实现"也得手工生成或来自不同 LLM 同解。这些前期工作有劳动成本
2. **$\alpha$ 需要 per-model 调参**：Figure 6 显示最佳 $\alpha$ 因模型 / benchmark 略不同。论文用 0.3 作为默认，但没有自动化调优机制
3. **deep subset 之外的泛化未充分验证**：是否对工业级 SoC 设计（数百万行代码）一样有效？论文没做
4. **per-token steering 引入 ~3-5% 延迟**：每个解码步多一次矩阵乘，部署在低延迟实时场景需谨慎

### 10.2 代码 / 复现层面的问题

- **GitHub mhakyash/CASS-RTL**：论文给出的代码仓库地址。仓库尚未在本资料包生成时核验 commit 哈希；建议复现前**先锁定 commit** 并核对 Author 的复现说明
- **VC Formal 闭源依赖**：CASS-RTL 自身的实现只用 forward hook + numpy / pytorch 矩阵运算，但**评估目标仍然要靠仿真器**判定 pass@k，所以走的是 VerilogEval 标准流水线（iverilog / Verilator + testbench）
- **样本对来源未完全披露**：GitHub README 应有详细说明；若仅给代码而无样本对，复现者需自行从 VerilogEval 抽 prompt 然后人为构造 C-I / C-C

### 10.3 本资料包的批判性分析

1. **子空间线性可分假设**：PCA + LDA 证明正确 / 不正确样本在 $D_{\text{total}}$ 维空间线性可分。但线性可分**不等于线性可 steer**——一个样本可能因为"激活几何靠近 $\mu^+$ 而落在线性可分的那条边界的正确一侧"，但实际语义仍然有问题。CASS-RTL 不区分"恰好被分类正确"和"真的功能正确"
2. **Top-K 头选择忽略 head 间冗余**：$S_{\text{correctness}}$ 前 30 个头可能高度相关（同层相邻头常做相似的事），PCA 投影的"信号维度"可能远小于 30。一种改进是先用相关性聚类再选代表
3. **完全忽略 token 信息**：steering 只看 attention head 激活，不看当前 token 是什么 / prompt 的内容是什么。一种潜在改进是"按 token 类型动态决定 $\alpha$"——例如 `$alpha$ 在 syntax-critical token（如分号、endmodule）上小一些，在 semantic-rich token（如 `+`, `&`, `case`）上大一些"
4. **注意力头 vs 通道**：CASS-RTL 把 steering 加在 head 输出的整体维度上，而非某一通道。一种更细粒度的做法是直接修改 V 的输出通道，类似 Activation Steering / Representation Engineering 思路
5. **算力 vs 收益的非对称**：构造子空间需要数百次 forward，几小时 GPU；但部署阶段只是每 token 一次矩阵乘。论文没量化构造阶段的成本
6. **评估只覆盖两个 benchmark / 三个模型**：VerilogEval 是经典但相对容易，CVDP 是更新更难的。论文没有覆盖 RTL-BenchLS / ChipBench / ChipVerilog 等其他家族，是否普适仍待验证

### 10.4 与同类工作的边界

| 工作 | 作用层 | 是否需训练 | 是否需标注 | 推理开销 | 适用任务 |
|---|---|:---:|:---:|:---:|---|
| **CASS-RTL** | attention head | ❌ | ❌ | 微小（per-token 矩阵乘） | 任何 decoder-only LLM-for-RTL |
| ITI [23] | attention head | ❌（要训 head-level classifier） | ✅（要 truth label） | 微小 | 一般 NLP |
| TruthX [24] | latent space | ✅ | ✅ | 中（per-token 解码层） | NLP |
| Truth Forest [31] | multi-dim probe | ❌ | ✅ | 中 | NLP |
| CCS [29] | latent direction | ❌ | ❌ | 中（二元场景） | 二元 NLP |
| [DecoRTL](../DecoRTL/论文深度讲解.md) | 输出分布 | ❌ | ❌ | 微小（top-K rerank） | RTL / Code |
| [HierSVA](../HierSVA/论文深度讲解.md) | SVA 生成 | ✅（instrinsic） | ❌（self-verify） | 大（FPV tool） | 形式验证 |

CASS-RTL 的独特生态位：**唯一的"无需任何形式标注"的 RTL-specific head-level steer**——这是它在 [DecoRTL](../DecoRTL/论文深度讲解.md) 和 ITI 之间开辟出的差异化位置。

## 12. 一分钟复述版

1. **核心问题**：LLM 生成 RTL 代码时，即使语法对、功能也可能错（即 "function hallucination"）。已有方法要么训（SFT/RL）、要么外包验证（外部仿真器反复编译），都贵且不利用模型内部信号
2. **方法概述**：CASS-RTL = KL 散度找"对功能正确性敏感"的注意力头 → 用 LDA/PCA 构造低维正确性子空间 → 推理时把每步激活投影到子空间、向"正确类均值"方向加可调步长 $\alpha$ 的几何矫正向量 → 完全不重训
3. **核心数据**：在 CodeLlama-7B / QwenCoder-14B / CodeV 三个模型 × VerilogEval / CVDP 两个 benchmark 上，Pass@1 一致提升 5–13 个百分点，Pass@10 提升 ~3–7 pp
4. **关键结果**：与最强 baseline ITI 相比平均高 ~5 pp；与 fine-tuned CodeV 叠加后再涨 5–10 pp——证明与 SFT/RL 正交可叠加
5. **最大创新点**：C-I vs C-C 差分 KL 散度（去风格噪声）+ Geometry-aware 投影矫正（不是全局方向而是当前激活几何函数）+ 零训练 / 零标注 / 模型无关
6. **EDA 流程位置**：① RTL 设计阶段的 LLM 推理时（inference-time），不改模型权重，部署成本接近零
7. **与同类工作的关系**：与 [DecoRTL](../DecoRTL/论文深度讲解.md) 互补（attention 内 vs token 选）、与 [HierSVA](../HierSVA/论文深度讲解.md) 上下游互补（① RTL 正确率 vs ⑥ SVA 验证）、与 ITI / TruthX / TrFr 同思路但**首个面向 RTL**且**首个完全免标注**的
8. **局限**：构造阶段需几十到数百 forward 构造样本对；$\alpha$ / $N_{\text{sel}}$ 需 per-model 调；样本对来源依赖工具或人工；CVDP 上绝对涨幅小（基线太低）；不能替代 PPA 优化 / 综合验证 / 工业级覆盖率

## 附录 B：关键工程细节

### B.1 子空间维度选择

论文未给出 $k$（PCA 保留主成分数）的最优值。Figure 4 显示 2D 投影已能清晰分离——意味着 effective rank 很小。实践中常设 $k = \min(50, D_{\text{total}})$ 或基于"累计方差贡献率 ≥ 95%" 自动确定。

### B.2 Steering 注入点

论文选 EOS / 当前正在解码 token 的 query 位置注入。但理论上也可选 V 输出位置或 attention logit 位置。论文没做 ablation 对比。

### B.3 兼容多 GPU / KV-Cache 部署

由于 steering 只在选中的 K 个 head 上做局部矩阵乘，对 KV-Cache 完全透明，对 KV-Cache 复用性无破坏。这意味着 vLLM / TGI / SGLang 等服务框架**只要支持 attention hook** 就可直接挂接。

### B.4 何时不需要再构造一次子空间

- 同一模型同一 benchmark：直接复用
- 同一模型微调后（如微调成 CodeV）：必须重新构造（attention head 行为已经变了）
- 不同模型的同源（如 Qwen2.5-Coder-7B / 14B / 32B）：可能有一定迁移性，但未经验证
