## 1. 一句话定位

**RocketPPA 是首个把「LLM + MoE-MLP」端到端用于 HDL 代码级 PPA（Power / Performance（延迟）/ Area）预测的工作——LLM 编码 Verilog 为隐藏表示，MoE 的多个专家 MLP 各负责回归一个指标，配合 log + z-score 归一化和 Smooth L1（Huber）损失，在 VerilogEval 138 题测试集上 Area / Delay / Static Power 10% 阈值的 Pass Rate 分别比 Llama3-MetRex-8B 高 13.6 / 9.4 / 14.7 个百分点，并且 16 秒（0.12 秒/题）跑完全集，比 MetRex 快 20×、比 MasterRTL 快 30×。**

这句话里的 5 个承重点，后面逐一拆解：

1. **LLM 作为 HDL 编码器** — RocketPPA 不用传统「特征工程 + 树模型」思路，而是直接拿 LLaMA-3.1-8B-Instruct / CodeLlama-7B 等大模型当 Verilog 编码器，提取最后一层隐藏状态 h_L 并做平均池化得到 4096 维的 code embedding。这是首个把通用大模型端到端接到 PPA 回归头上的工作。
2. **MoE 回归头（Mixture of Experts MLP）** — N=6 个三层的 MLP 专家各出一个标量预测 y_k，一个线性门控网络 + softmax 给出权重 α，取 top-k=3 的专家后归一化得到 ~α_k，最终预测 ~y = Σ ~α_k y_k。多专家分流了 Verilog 模块的异构性（组合逻辑 vs FSM vs 加法器等），避免单一 MLP 被任一设计风格主导。
3. **Log + z-score 归一化 + Smooth L1 损失** — 由于 PPA 值跨度可达数个数量级（Figure 3），RocketPPA 先对每个指标做 log(x + ε) 压缩，再做训练集上的 z-score 标准化；用 Smooth L1 在小误差时二次（精细拟合）、大误差时线性（抑制 outlier），是回归 PPA 的标准防御策略。
4. **LoRA 参数高效微调** — 在 LLM 的每个 transformer block 权重上加 r=16 的低秩适配，只增加约 8.4M 可训练参数（占 0.1%），把 11 小时训练 + 41GB 显存压在单张 RTX A6000 上，无需张量并行或多卡。
5. **代码级 PPA 评估器：跳过综合的快路径** — RocketPPA 把综合 + STA（MetRex / MasterRTL 都得跑几秒到几百秒）替换为「LLM 直接回归」，136 题测试集 16 秒（0.12s/题）。定位是「RTL 设计早期快速反馈」，不是签核阶段的 PPA 精修。

## 2. EDA 阶段映射（①-⑰）

参照 [芯片流程.md](../芯片流程.md) 的 17 阶段标准编号。RocketPPA 处于「RTL 设计 → 逻辑综合」之间的反馈环，给出 PPA 的早期估计。

| 阶段 | 覆盖 | 说明 |
|------|:---:|------|
| **① RTL 设计** | ✅ **核心** | RocketPPA 的输入就是 Verilog RTL 源码；它不生成 RTL，而是评估给定 RTL 的 PPA 趋势，把 LLM 的语义编码转为 PPA 标量 |
| ② RTL 功能仿真 | ❌ | RocketPPA 不做仿真——它的训练目标值来自外部综合工具的 report，不是 testbench 仿真。它判定「PPA 准不准」也不靠仿真 |
| ③ 逻辑综合 | ✅ **间接触及** | 训练数据集的「真实 PPA 标签」由综合流程产生（论文用 Yosys + OpenSTA 跑出 area / delay / power），RocketPPA 本身不调综合工具，只是消费综合输出 |
| ④ 门级仿真 | ❌ | 不涉及——RocketPPA 不仿真门级网表，不关心 SDF 注入 |
| ⑤ STA（静态时序分析） | ✅ **间接触及** | 训练标签中 delay 来自综合后的 STA（OpenSTA）；RocketPPA 本身不跑 STA，但学 STA 的统计规律 |
| ⑥ 形式验证 | ❌ | 不涉及——RocketPPA 不做等价性检查，只回归 PPA 标量 |
| ⑦ 布局规划 (Floorplan) | ❌ | 不涉及——训练数据来自通用综合流程，没有 floorplan 特定参数 |
| ⑧ 标准单元摆放 (Placement) | ❌ | 不涉及 |
| ⑨ 时钟树综合 (CTS) | ❌ | 不涉及——CTS 信息不入训练标签，RocketPPA 学不到 skew / latency 的细粒度物理效应 |
| ⑩ 布线 (Routing) | ❌ | 不涉及——布线寄生 RC 不在训练标签里 |
| ⑪ 后仿真 | ❌ | 不涉及 |
| ⑫ 物理验证 (DRC + LVS) | ❌ | 不涉及 |
| ⑬ 签核 (Signoff) | ❌ | 不涉及——RocketPPA 是「RTL 之后、综合之前」的快速反馈工具，定位在 signoff 前若干小时/天的探索期 |
| ⑭ 流片 | ❌ | 不涉及 |
| ⑮ 制造 | ❌ | 不涉及 |
| ⑯ 封装 + 测试 | ❌ | 不涉及 |
| ⑰ 芯片到手 | ❌ | 不涉及 |

**覆盖率：3/17。** RocketPPA 直接覆盖 ①RTL 设计，间接消费 ③逻辑综合 + ⑤STA 的输出来构造训练标签。它是 RTL 之后、综合之前的「PPA 快速反馈器」，不进入物理实现流。

> ⚠️ RocketPPA 的标签来自开源综合工具链（Yosys + OpenSTA），没有工艺库的真实 SPICE / Liberty 校准，意味着它的「area」其实是「门数 + 关键路径估计」，「delay」是 OpenSTA 的线载模型延迟，「power」是粗粒度 toggle 概率 + 静态漏电。预测 PPA ≠ 流片 PPA——它的价值是「RTL 设计早期拿快速近似值做设计空间探索」，不是「签核阶段的精修」。

## 3. 输入 / 输出

### 3.1 输入

**(1) HDL 代码（核心输入）**：RocketPPA 接收一段 Verilog（SystemVerilog 子集）源码，限制在基础 LLM 的 token 上限内。如果代码超过 512 tokens（Figure 2 显示训练集中存在超长文件），RocketPPA 按 512 tokens 切成非重叠片段分别编码再取平均，得到统一的 code embedding。

最小具体例子（来自 VerilogEval Level 1 / 2 / 3 风格的 HDL）：

```verilog
// 4-bit 加法器 + 溢出标志
module adder4(
    input  [3:0] a, b,
    input        cin,
    output [3:0] sum,
    output       cout
);
    assign {cout, sum} = a + b + cin;
endmodule
```

**(2) 自然语言指标名 / 任务 token（控制信号）**：RocketPPA 的 MoE 头在推理时通过指标 token（`area` / `delay` / `power`）路由——不同 expert 子网专门预测不同指标，最终 ~y 是对应该指标的标量。

**(3) 训练阶段额外需要**：20,953 个 Verilog 模块 + 对应的 (log + z-score 归一化后的) area、delay、total power、static power 标量标签。这些标签由论文的 HDL 修复框架（Figure 5）保证可综合性后用 Yosys + OpenSTA 综合得到。

### 3.2 中间产物

**(1) Code embedding**：取 LLM 最后隐藏层 h_L，对序列维度做平均池化（Eq. 1），得到 4096 维向量（以 LLaMA-3.1-8B-Instruct 为例）：

$$
O_{\text{pooled}} = \frac{1}{n}\sum_{i=1}^{n} h_L[i]
$$

- $O_{\text{pooled}}$：定长 code embedding（4096 维），后续所有模块的输入
- $h_L$：LLM 最后一层隐藏状态张量，shape = (n, 4096)
- $n$：Verilog 代码的 token 数（≤ 512 / 片段）
- $i$：token 索引

**(2) Gating 权重 $\alpha \in \mathbb{R}^N$**：门控网络 = 一个线性层把 4096 维向量映射到 N 维向量，再 softmax（N=6）。

**(3) 专家标量预测 {y_1, ..., y_N}**：每个 expert 是三层 MLP，输出一个标量预测（针对当前路由到的指标）。

**(4) 归一化逆变换**：训练标签的归一化路径是 `log(x + ε) → z-score → 训练`，推理时把网络输出 ~y 沿同样路径反向变换（× σ + μ → exp(·) → -ε）得到原量纲 PPA 值。

### 3.3 输出

**(1) 三组标量预测**：area、delay、total power（动态 + 静态）、static power，单位分别是「综合报告中的等价门数 / ns / μW」（取决于 Yosys 输出的具体格式）。

**(2) Pass Rate 评估结果**：在 VerilogEval 138 题测试集上，RocketPPA @ LLaMA-3.1-8B-Instruct + MoE 的最优结果（论文 Table II）：

```text
Area      : 71.6% @ 10% RE   /   84.6% @ 20% RE
Delay     : 57.2% @ 10% RE   /   74.9% @ 20% RE
Total Power: 55.0% @ 10% RE  /   70.8% @ 20% RE
Static Pwr: 56.7% @ 10% RE   /   72.8% @ 20% RE
```

端到端 walkthrough（拿上面 `adder4` 模块走一遍）：

```text
input : module adder4(input [3:0] a,b, input cin, output [3:0] sum, output cout);
         assign {cout,sum} = a + b + cin;
         endmodule
        │
        ▼ [CodeLlama-7B / LLaMA-3.1-8B-Instruct forward]
h_L (n×4096)  →  O_pooled (4096)
        │
        ▼ [gate linear + softmax → α ∈ ℝ^6]
α = [0.05, 0.31, 0.18, 0.04, 0.27, 0.15]
top-k=3 indices = {2, 5, 6}, renormalized ~α = [0, 0.40, 0.23, 0, 0, 0.37]
        │
        ▼ [each expert MLP outputs a scalar y_k]
y_2 = -0.21, y_5 = 0.08, y_6 = -0.05  (z-score space, for "area" route)
        │
        ▼ [weighted sum ~y = Σ ~α_k y_k]
~y = 0.40*(-0.21) + 0.23*0.08 + 0.37*(-0.05) = -0.090
        │
        ▼ [inverse z-score: x_hat = exp(~y * σ + μ) - ε]
predicted_area ≈ 28  (gates, equivalent)
```

### 4.1 整体 Pipeline

│  │  Foundation LLM (frozen   │   LLaMA-3.1-8B-Instruct           │

### 4.2 核心模块逐个详解

#### A. Foundation LLM + LoRA 适配

**功能**：把 Verilog 源码编码为定长 4096 维向量。

**设计要点**：
- 选用 LLaMA-3.1-8B-Instruct 为主要骨干（论文 Table II 主结果），并用 CodeLlama-7B 和 LLaMA3-8B 做消融（Table III）。Llama-3.1-8B-Instruct 性能最佳——作者归因为「指令微调让 hidden state 对用户目标更对齐」。
- LoRA 注入到每个 transformer block 的权重矩阵上，rank r=16。论文统计约 8.4M 额外可训练参数（占模型总参数 ~0.1%）。
- 训练时不传梯度穿过 LLM 主干，41GB 显存即可在 RTX A6000 上跑 batch 前向 + 反传到 LoRA + MLP 头，无需模型并行。

**为什么这样设计**：相比全参微调（80 亿参数 → 80GB 显存 + 多卡），LoRA 把训练成本压到 1/1000，并允许在数据有限（~21k 模块）时不易过拟合。

#### B. 隐藏状态池化

**功能**：把变长 token 序列压成定长 code embedding。

**设计要点**：
- 取最后一层隐藏状态 h_L ∈ ℝ^(n×4096)，对 n 个 token 做平均池化（Eq. 1）。
- **超长文件切分**：当 Verilog 文件 > 512 tokens（Figure 2 显示训练集中存在大量超长文件，最长可达 ~4000+ tokens），RocketPPA 按 512-token 不重叠切片，每片独立编码后取平均，得到与单文件等价的 code embedding。
- 论文声称这种「分片 + 平均」等价于「把全文件给模型看」，但显存占用远低（每片 512 tokens 即可）。

#### C. MoE 回归头（核心创新点之一）

**功能**：用 N=6 个专家 MLP 把 code embedding 映射为标量预测。

**设计要点**：
- 每个 expert 是一个三层 MLP（输入 4096 → 隐层 → 隐层 → 标量），含激活 + dropout，全部参与训练（约 4.7M 额外参数）。
- **门控网络**：线性层 `Linear(4096 → 6)` + softmax，把 code embedding 投影到专家分布。
- **Top-k 选择**：选权重最高的 k=3 个专家，剩余 3 个权重置零。
- **重归一化**：`~α_k = α_k / Σ_{j∈K} α_j`，让被选专家权重和为 1。
- **加权求和**：`~y = Σ_{k=1}^N ~α_k y_k`，得到一个标量。

**为什么这样设计**：
- 单一 MLP 容易「被任一设计风格主导」——比如训练集里加法器多，网络会倾向于给所有模块预测成「中等大小」。MoE 让不同专家专攻不同模块类型（组合逻辑、FSM、加法器、状态寄存器……），门控网络学习「这个模块属于哪一族」。
- Top-k=3 而非 dense N=6：减少冗余计算（3 个专家 0 梯度更新），并提高泛化。
- 论文 Figure 7 验证：N=6, k=3 比 N=4, k=2 在所有指标上高 1~3 个百分点，再增 N 收益饱和。

#### D. 数据预处理：Log + z-score + Smooth L1

**功能**：处理 PPA 标签的数量级跨度。

**设计要点**：
- **Log 压缩**：`log(x + ε)`，ε 是小常数避免 log(0)。原因：PPA 值在训练集上跨数个数量级（Figure 3），linear scale 下优化器会被 max-value 模块绑架。
- **Z-score 标准化**：在训练集上算 μ 和 σ，然后 `(log(x+ε) - μ) / σ`，让标签落在 N(0,1) 附近。
- **Smooth L1（Huber）损失**：阈值 β=1。小误差走二次（精细拟合），大误差走线性（不放大 outlier）。论文用 Figure 4 说明：inlier 用 MSE 风格精细调节，outlier 走线性 regime 不被极端样本绑架。

**为什么这么组合**：PPA 回归的标准防御——log 处理数量级，z-score 处理均值/方差，Smooth L1 处理 outlier。三者互补。

#### E. HDL 修复框架（Figure 5）

**功能**：把原始 Verilog（很多有语法错误）修复为可综合。

论文未给详细伪代码，只说明「用内部 LLM-based HDL 修复框架」，分阶段处理：

1. **语法修复**：用 LLM 重写 syntax error；
2. **语义检查**：用 Yosys 编译，确认能生成 netlist；
3. **STA 抽取**：用 OpenSTA 跑 delay / power，生成 PPA 标签。

论文未公开框架代码（"internal"），可推断是 LLM prompt → 重生成 → 编译验证循环。

#### F. 推理时（无训练）

```text
forward Verilog → h_L → O_pooled → α → top-k → experts → ~y → invert z+log → predicted PPA
```

总耗时 0.12 秒/题（论文实测，全 138 题 16 秒），瓶颈在 LLM forward（4096 维向量 + 多层 transformer）。

## 5. 关键公式

RocketPPA 共 7 个编号公式，逐一覆盖。

### 5.1 平均池化（Eq. 1）

$$
O_{\text{pooled}} = \frac{1}{n}\sum_{i=1}^{n} h_L[i]
$$

- $O_{\text{pooled}}$：定长 code embedding（4096 维），后续所有模块的输入
- $h_L$：LLM 最后一层的隐藏状态张量，shape = (n, 4096)
- $n$：Verilog 代码的 token 数（≤ 512 / 片段）
- $i$：token 索引

**工程直觉**：等价于「让 LLM 对每个 token 给出一个 4096 维特征，平均后作为整段代码的指纹」。简单、稳定，对 token 数不敏感。

**为什么这么设计**：替代方案有「取 [CLS] / 取最后一 token / 取 max-pool」。RocketPPA 选平均——对 Verilog 这种「每个 token 都有语义」（关键字、信号名、操作符）的内容，平均比 last-token 更稳定。

### 5.2 Gating 网络（Eq. 2）

$$
\alpha = \text{Softmax}(W_{\text{gate}} \cdot O_{\text{pooled}})
$$

- $\alpha \in \mathbb{R}^N$：N=6 个专家的初始权重
- $W_{\text{gate}}$：可训练矩阵，shape = (N, 4096)
- $O_{\text{pooled}}$：4096 维 code embedding

**工程直觉**：把 4096 维 code embedding 投影到 N 维「专家亲和度」空间，softmax 让亲和度变成概率分布——「这个模块由哪个专家负责最合适？」

### 5.3 Top-k 重归一化（Eq. 3）

$$
\tilde{\alpha}_k = \frac{\alpha_k}{\sum_{j \in K} \alpha_j}, \quad \text{for } k \in K
$$

- $\tilde{\alpha}_k$：被选专家 $k$ 的最终权重
- $K$：top-k 专家索引集合（k=3）
- $\alpha_k$：softmax 后的初始权重
- 分母：被选专家权重之和

**工程直觉**：让被选专家的权重和为 1，等价于「在 top-k 内重新分配重要性」——专家要么贡献，要么不贡献，没有半吊子。

### 5.4 MoE 加权求和（Eq. 4）

$$
\hat{y} = \sum_{k=1}^{N} \tilde{\alpha}_k \cdot y_k
$$

- $\hat{y}$：模型最终标量预测（z-score 空间）
- $\tilde{\alpha}_k$：第 $k$ 个专家的 top-k 重归一化权重（不在 $K$ 内的为 0）
- $y_k$：第 $k$ 个 expert MLP 的标量输出
- $N$：专家总数 6

**工程直觉**：每个专家投票一个数字，门控决定谁的票重要——这就是 MoE 的「加权民主」。

### 5.5 z-score 标准化（Eq. 5）

$$
\hat{x}_i = \frac{\log(x_i + \varepsilon) - \mu}{\sigma}
$$

- $\hat{x}_i$：归一化后的训练标签（z-score 空间）
- $x_i$：原始 PPA 值（来自 Yosys + OpenSTA report）
- $\varepsilon$：小常数（避免 log(0)），论文未给具体值，经验上 1e-6 ~ 1e-3
- $\mu, \sigma$：训练集上 log 变换后的均值和标准差

**工程直觉**：先 log 把指数分布压成近似正态，再 z-score 把均值拉零方差拉一——让 loss landscape 对所有 PPA 区间敏感程度相当。

### 5.6 Smooth L1 损失（Eq. 6）

$$
\mathcal{L} = 
\begin{cases}
0.5 (\hat{y}_i - z_i)^2, & \text{if } |\hat{y}_i - z_i| < 1 \\
|\hat{y}_i - z_i| - 0.5, & \text{otherwise}
\end{cases}
$$

- $\mathcal{L}$：单样本的 Smooth L1 损失
- $\hat{y}_i$：模型预测（z-score 空间）
- $z_i$：真实标签（z-score 空间）
- 阈值 1：inlier / outlier 的分界

**工程直觉**：在小误差区间（$|\hat{y}_i - z_i| < 1$）用 MSE（精细调节），大误差用 MAE（不放大 outlier）。Huber 损失的经典动机——既要稳定梯度，也要抗噪声。

**为什么不用纯 MSE**：训练集中存在 outlier（Figure 3 显示某些模块 power 极高，是中位数的 1000×），MSE 对 outlier 平方会绑架梯度；纯 MAE 在零点不可导。Smooth L1 是 sweet spot。

### 5.7 Pass Rate 评估指标（Eq. 7）

$$
\text{PassRate}(\tau) = \frac{1}{M} \sum_{i=1}^{M} \mathbf{1}\big(RE_i \leq \tau\big)
$$

- $\text{PassRate}(\tau)$：相对误差阈值 $\tau$ 下的通过率
- $M$：测试样本数（138 = VerilogEval 全集；或 Level 3 的 72）
- $RE_i$：第 $i$ 个样本的相对误差（$\text{Pass Rate}$ 论文定义的相对误差）
- $\tau$：阈值，论文用 10% 和 20% 两个值
- $\mathbf{1}(\cdot)$：指示函数，满足条件为 1，否则为 0

**工程直觉**：不像 RMSE / MAE 那样「对每个样本一视同仁」，Pass Rate 是「分类型指标」——「这个样本能不能用」比「整体偏多少」对设计者更有意义。论文与 MetRex [18] 对齐，10% / 20% 是常用设计裕量。

## 6. 训练与实验设置

### 6.1 是否需要训练

**需要训练**——但是参数高效微调，不是从头训。

- **基础模型**：LLaMA-3.1-8B-Instruct（主结果），CodeLlama-7B / LLaMA-3-8B（消融）
- **LoRA 配置**：rank r=16，加在每个 transformer block 的权重矩阵上，约 8.4M 可训练参数（占 ~0.1%）
- **MoE 头**：N=6 个三层 MLP 专家 + 1 个线性门控，全部从头训练，约 4.7M 参数
- **总可训练参数**：~13M（其中 LoRA ~8.4M + MoE ~4.7M）
- **损失函数**：Smooth L1（Huber，β=1）
- **优化器**：论文未显式给，按 PyTorch 标准 SFT 实践推断 AdamW
- **训练轮数**：24 epoch
- **训练时长**：约 11 小时
- **硬件**：单张 NVIDIA RTX A6000（48GB VRAM），显存占用 ~41GB
- **批大小**：论文未明说，按 RTX A6000 + LoRA + 8B 模型推断 batch size 4~8 + grad accumulation
- **随机种子**：训练 10 次（不同 seed），std < 1%

### 6.2 实验设置

**数据集划分**：
- **训练集**：20,953 个 Verilog 模块（来自 MG-Verilog 9,239 + curated GitHub 7,791 + VeriGen 3,923），按 80/20 划分为训练 / 验证
- **测试集**：VerilogEval [17] 的 138 个 HDL 模块（仅 Level 1 / 2 / 3 三层全用）
- **Level 3 子集**：72 个复杂模块（FSM、复杂组合逻辑、高级时序电路），最长门数达 607 gates

**基线**：
1. **Llama3-MetRex-8B**（来自 MetRex 论文 [18]）——同样用 LLM + LoRA 回归 PPA，但用 chain-of-thought 推理，输出 text-based gate count + critical path reasoning
2. **MasterRTL [25]**——传统 pre-synthesis 框架：RTL → Simple Operator Graph (SOG) → 树模型（GBRDT 等）回归 timing / power / area，CPU 密集

**评估指标**：Pass Rate（Eq. 7），阈值 10% 和 20%

**评估硬件**：
- RocketPPA：RTX A6000（48GB），138 题 16 秒
- MetRex CoT：H100，~30 秒
- MasterRTL：CPU，~514 秒（CPU 预处理 + 回归）
- Yosys + OpenSTA 全流程：~680 秒

## 7. 创新点

### 创新点 1：LLM-as-Encoder + MoE-MLP Regressor 端到端回归

**和已有方法的关键区别**：MetRex [18] 用 LLM 做 CoT 推理（生成 gate count + critical path 的文字解释再回归）；MasterRTL [25] 手工构造 Simple Operator Graph（SOG）特征再喂树模型。RocketPPA **直接把 LLM hidden state 当特征，喂给轻量 MoE-MLP 出标量**——LLM 退化成「encoder」，回归头退化成「轻量 MLP」，二者端到端联合优化。这是首次把 LLM 和回归头合并为一个可微 pipeline 的 PPA 预测工作。

**为什么这样好**：CoT 推理的中间文字是「投影到人类语言空间」的信息瓶颈，丢失了精细语义；手工 SOG 特征是「人类工程师的领域知识近似」，无法覆盖所有结构变体。LLM hidden state 是「未经压缩的语义」，对 Verilog 的细粒度变化敏感。

### 创新点 2：Log + z-score + Smooth L1 的归一化三件套

**和已有方法的关键区别**：MetRex [18] 和 MasterRTL [25] 都没显式处理 PPA 标签的数量级跨度——直接 MSE 训练会让模型被 max-value 模块绑架。RocketPPA 把「log + z-score + Smooth L1」组合成完整防御：
- log 压指数分布
- z-score 居中标准化
- Smooth L1 抗 outlier

**为什么这么设计**：PPA 在训练集上跨数个数量级（Figure 3 显示 power 从 ~10^-6 到 ~10^-1 W），MSE 会被极端样本的平方梯度支配，MAE 在零点不可导且梯度恒定。Smooth L1 是 sweet spot。

### 创新点 3：MoE 多专家分流 Verilog 模块异构性

**和已有方法的关键区别**：单一 MLP 难以同时学好「组合逻辑」「FSM」「加法器」「状态寄存器」等异构设计风格——平均化所有训练样本的梯度会抹平结构特异性。MoE 让 N=6 个专家各自专攻一类，门控网络学「这个模块属于哪一族」，top-k=3 选择 + 重归一化避免冗余。

**为什么这么设计**：论文 Figure 7 验证 N=6/k=3 比 N=4/k=2 高 1~3 pp。N 再大增益饱和。代价是 +4.7M 参数（占 LLM 0.06%）。

### 创新点 4：LLM-based HDL 修复框架（Figure 5）

**和已有方法的关键区别**：训练需要大量「可综合」的 Verilog，但原始数据（MG-Verilog、GitHub、VeriGen）很多有语法错误。RocketPPA 构造了一个内部 LLM-based 修复框架，把 syntax error 自动修成可综合 Verilog，再喂给 Yosys + OpenSTA 生成 PPA 标签。这避免了「手动清洗 20k+ 模块」的人力成本。

**为什么这样设计**：手工清洗 21k 个 Verilog 模块每个 ~50-500 行，需要数人月。LLM 修复可把工作量压到数人周。论文声明代码未开源，但流程公开。

### 创新点 5：Level-3 鲁棒性

**和已有方法的关键区别**：在 VerilogEval Level 3（72 个复杂模块，最长 607 gates）的退化分析显示——RocketPPA 在 10% 阈值下只退化 7%（静态功耗），而 MasterRTL 退化 18-26%，MetRex 退化 16%。RocketPPA 是「复杂设计场景下退化最小」的 PPA 预测器。

**为什么重要**：Level 3 模块接近真实工业设计的复杂度（FSM、复杂控制流），其他方法在简单模块上表现尚可但在 Level 3 上崩盘，RocketPPA 是首个在 Level 3 仍保持鲁棒的预测器。

## 9. 与芯片流程的关系

### 9.1 在全流程中的位置

RocketPPA 是「RTL 设计早期 → 综合前」的 PPA 快速反馈工具，定位在 17 阶段中的 ①RTL 设计 与 ③逻辑综合 之间。

```text
① RTL 设计 ──▶ ② RTL 功能仿真 ──▶ ③ 逻辑综合 ──▶ ⑤ STA ──▶ ... ⑬ 签核 ──▶ ⑭ 流片
       │                                  ▲
       │                                  │
       └──▶ [RocketPPA] ──── 快速预测 ─────┘
              (0.12s/题)
```

具体地：

- **接手**：刚写好的 Verilog RTL（testbench 通过、但还没综合）
- **交棒**：4 个标量预测（area / delay / total power / static power），用于「设计空间探索」——让设计者在跑综合之前快速比较多个 RTL 变体的 PPA 趋势
- **不接手**：综合后的门级网表、SDF、SDC、布局布线信息

**价值场景**：
- **场景 1**：硬件工程师写了 10 个 RTL 变体（不同 FSM 编码、加法器架构），想知道哪个 PPA 最好。综合 + STA 跑全流程要 680 秒/题，10 题 6800 秒 ≈ 2 小时；RocketPPA 跑 10 题只要 1.2 秒，筛掉 8 个差的，再综合 2 个最可能赢的——总耗时 ~25 分钟。
- **场景 2**：RTL 智能体（类似 MAGE [11]）生成 K 个 Verilog 候选，需要快速打分挑出最可能的赢家。RocketPPA 的 0.12s/题让它能用于在线过滤。

### 9.2 「代码级 PPA」到「可流片 PPA」的鸿沟

RocketPPA 声称的「PPA 预测」与真实流片 PPA 之间隔着至少 5 个环节：

1. **工艺库失真**：训练标签来自 Yosys + OpenSTA + 通用工艺库（Sky130 / FreePDK 之类），不是工业 28nm / 7nm 工艺库。预测的「area」是「等价门数」，「delay」是「线载模型估算」，「power」是「粗粒度 toggle + 静态漏电」。**工业流程用 Liberty 文件 (.lib) + SPEF 寄生 RC，RocketPPA 看不到这些。**

2. **没有布局布线信息**：RocketPPA 学不到 wire load model 之外的真实走线延迟、寄生 RC、串扰、IR drop——这些是 ⑦-⑪ 阶段的输出，PPA 评估器在 RTL 阶段拿不到。

3. **没有时钟树信息**：clock skew、latency、CTS buffer 的负载变化都不在训练标签里。RocketPPA 看到的 delay 是「无 CTS 的综合延迟」。

4. **没有 signoff corner 覆盖**：训练标签来自单一 corner（典型 TT 工艺角），但签核要扫 20+ 个 corner（SS/FF/TT × 温度 × 电压）。RocketPPA 不能预测最坏情况。

5. **没有动态功耗精度**：total power 来自粗粒度 toggle 概率估计，不考虑 glitch power、crosstalk-induced switching、internal node activity。工业 power signoff 用 PrimePower / PT-PX 做带波形 + SPEF 的功耗分析，RocketPPA 看不到 SDF + SPEF。

**一句话**：RocketPPA 的「PPA」≈「RTL 设计者心算的 PPA」+ 「LLM 学到的代码风格 → 统计 PPA 关联」，精度高于心算但远低于真实签核。**它的价值是「早期快速反馈」而非「签核精修」**。

## 10. 讨论与局限

### 10.1 论文自述的局限

1. **训练数据局限性**：20,953 个模块来自开源仓库（MG-Verilog、GitHub、VeriGen），风格偏向「教学 Verilog / 学术 benchmark」，**不代表工业设计的代码风格**——工业设计有大量 IP 复用、参数化 generate 块、跨模块接口，这些在训练集中覆盖不足。

2. **没有物理信息**：RocketPPA 的标签是 RTL 级综合结果（无 floorplan、无 CTS、无 routing），不反映「真实流片 PPA」。论文声称「early in the design cycle」，但没说清楚「early 到什么程度」——设计者在 floorplan 之后能用的 PPA 信息，RocketPPA 给不出来。

3. **依赖开源 EDA 工具链**：训练标签靠 Yosys + OpenSTA，**通用工艺库**（Sky130 / FreePDK）的精度远低于工业 Liberty 文件。论文没有说明如果用工业 .lib 训练会怎样——很可能需要重新生成数据集。

4. **Level 3 退化**：尽管 RocketPPA 在 Level 3 上退化最小（7%），但 72 个模块的 baseline pass rate 仍然只到 60-70% 区间（论文 Figure 6 显示 RocketPPA 在 10% 阈值下静态功耗 pass rate 约 50%）。复杂设计的 PPA 预测仍是开放问题。

5. **未开源代码**：论文声明代码「internal」，2026-08-06 仍未公开仓库。这意味着第三方无法验证 Table II/III 的数字，也无法在自己数据集上复现。

### 10.2 代码 / 复现层面的问题

1. **HDL 修复框架未公开**：Figure 5 描述的修复流程是「LLM 重写 → Yosys 编译 → OpenSTA 抽 PPA」，但具体 prompt、迭代次数、修复成功率都没给。没有这个框架，第三方无法重新生成训练集。

2. **训练超参不全**：优化器、学习率、warm-up、batch size 都没在论文中说明。沿用 PyTorch SFT 标准实践可推断 AdamW + cosine schedule，但具体数值未知。

3. **Smooth L1 β 值未显式给**：Eq. 6 用 `|y_i - z_i| < 1` 作为阈值，但 PyTorch SmoothL1Loss 默认 β=1——论文是否沿用默认未明说。

4. **z-score 的 μ 和 σ 未公开**：推理时需要把预测从 z-score 空间反变换回原量纲，需要训练集的 μ 和 σ（每个指标 4 组）。论文未提供这些统计量。

5. **测试硬件未对齐**：RocketPPA 在 RTX A6000（46 TFLOPS FP16）跑 16 秒，MetRex 在 H100（1000 TFLOPS FP16）跑 30 秒——**硬件差 22×，但论文声称「20× speedup」**——按 FP16 算 H100 比 A6000 快 ~22×，加速比几乎被硬件差抵消。**RocketPPA 的真实速度优势是「用更少的 LLM forward 步数」而非「硬件更好」**。

### 10.3 本资料包的批判性分析

1. **隐含前提：LLM 见过类似 Verilog**：RocketPPA 的有效性依赖 LLM 在预训练时见过类似结构的 Verilog。如果训练集是「教学 Verilog」，测试集是「工业 Verilog」，LLM 的 hidden state 分布会失配——预测精度会急剧下降。这是「代码级 PPA 评估器」方法的通用脆弱性。

2. **MoE 路由可解释性**：门控网络的 top-k=3 选择无法直接解释为「这个模块属于 FSM / 加法器 / 状态寄存器」。论文没给 expert specialization 的可视化（哪个 expert 学到什么），只是报告数字提升。

4. **MoE 增量限制**：Table III 显示 MoE 在三个 LLM 上都只增加 +2~5 pp——MoE 不是灵丹妙药，主要增益来自「LLM hidden state 的语义」本身，MoE 只是「特征 → 标量」的最后一公里改进。

5. **Pass Rate 阈值与工业标准不匹配**：论文用 10% / 20% 相对误差作为通过率——但工业 signoff 要求更严（5% 以内）。RocketPPA 在 10% 阈值下只 60-70% 通过率，到 5% 阈值会更低。论文没有给 5% 阈值的数据。

6. **没有与签核工具对比**：论文没在工业 signoff flow（Genus + PrimeTime + PrimePower）上对比，只在开源 Yosys + OpenSTA 上。这意味着 RocketPPA 的「预测 PPA」与「工业 PPA」的差距未被量化。

7. **训练数据清洗依赖未审计**：Figure 5 的修复框架是 LLM-based——LLM 自己也可能产生 syntax 错误。论文没说修复成功率，也没说修复后是否真能综合成功。如果有 5% 的「假阴性」（LLM 说修好了但 Yosys 跑不通），这些模块的 PPA 标签是缺失的——数据集偏差未知。

8. **评测基准的局限**：VerilogEval 是 NVIDIA 提出的学术 benchmark，138 题是「小型模块」风格。工业设计包括跨模块接口、IP 复用、参数化 generate——RocketPPA 在这些场景下表现如何未知。

## 12. 一分钟复述版

1. **问题**：RTL 设计早期缺乏快速 PPA 反馈。综合 + STA 跑完要 680 秒/题，没法在线筛 100 个 RTL 变体。MetRex 用 LLM + CoT 文字推理预测 PPA，但精度低、慢（30s/题）；MasterRTL 用手工 SOG 特征 + 树模型，比 LLM 还慢（514s/题）。需要一个又快又准的「代码级 PPA 评估器」。

2. **方法**：RocketPPA = LLM (LLaMA-3.1-8B-Instruct, LoRA r=16) + MoE 回归头（N=6 个三层 MLP 专家 + 线性门控，top-k=3）+ Log + z-score 归一化 + Smooth L1 损失。LLM 把 Verilog 编码为 4096 维向量；MoE 头把向量映射为标量预测；训练用 21k 模块（Yosys + OpenSTA 生成的 PPA 标签），24 epoch / 11 小时 / 单 A6000。

3. **结果**：VerilogEval 138 题上 @ 10% 阈值，Area 71.6% / Delay 57.2% / Static Power 56.7% pass rate，比 Llama3-MetRex-8B 高 13.6/9.4/14.7 pp，比 MasterRTL 高 20.4/6.5/9.2 pp。速度 16 秒跑完全集（0.12s/题），比 MetRex 快 20×、比 MasterRTL 快 30×。Level 3 困难模块退化最小（7% vs MasterRTL 18-26%）。

4. **局限**：（1）训练集是教学 Verilog 不是工业 Verilog；（2）没有物理信息（floorplan / CTS / routing）；（3）依赖开源工艺库，精度低于工业 Liberty；（4）HDL 修复框架未公开；（5）Pass Rate 阈值 10% 比工业 signoff 标准（5%）宽松；（6）评测基准 VerilogEval 单模块小风格，工业多模块扩展性未知。
