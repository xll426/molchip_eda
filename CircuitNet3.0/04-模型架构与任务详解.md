## 1. 两个核心任务定义

论文 Section 5.1 明确定义了两个预测任务：

### 任务一：时序预测 (Timing Prediction)

```
┌─────────────────────────────────────────────────────────┐
│ 任务目标：在 RTL 阶段预测最终物理版图的时序性能          │
│                                                         │
│ 输入：Verilog RTL 代码（纯文本）                         │
│                                                         │
│ 输出（三个时序指标）：                                    │
│   • AT  (Arrival Time)        — 信号传播延迟（ns）       │
│   • WNS (Worst Negative Slack) — 最差路径时序余量（ns）   │
│   • TNS (Total Negative Slack) — 全部违例总和（ns）       │
│                                                         │
│ Ground Truth 来源：                                      │
│   Synopsys DC compile_ultra 综合                         │
│   → Cadence Innovus MCMM 布局布线                        │
│   → Post-route STA 提取 AT/WNS/TNS                       │
│                                                         │
│ 意义：实现"Shift-Left"——还没画版图就知道时序有没有问题    │
└─────────────────────────────────────────────────────────┘
```

**为什么这是个难题？** RTL 阶段没有任何物理信息——不知道走线多长、寄生电容多大、单元放在哪里。但时序恰恰取决于这些物理因素。模型必须从 RTL 的"行为描述"中隐式推断出物理实现的时序特征。

### 任务二：功耗预测 (Power Prediction)

```
┌─────────────────────────────────────────────────────────┐
│ 任务目标：在 RTL + 网表阶段预测最终芯片功耗              │
│                                                         │
│ 输入：Verilog RTL 代码 + 门级网表（图结构）               │
│                                                         │
│ 输出（两个功耗指标）：                                    │
│   • Toggle Rate  — 信号切换活跃度（0~1）                 │
│   • Total Power  — 总功耗（mW）                          │
│                                                         │
│ Ground Truth 来源：                                      │
│   Synopsys PrimePower 签核级功耗分析                      │
│   （基于 post-route SPEF 寄生参数）                       │
│                                                         │
│ 功耗公式：P_dynamic = α × f × C_eff × VDD²              │
│   α = Toggle Rate, f = 1GHz, VDD = 1.05V                 │
└─────────────────────────────────────────────────────────┘
```

**为什么需要 RTL + 网表？** 论文 Section 5.2 的消融实验证明（MOSS w/o Multi-Modal vs MOSS Full）：RTL 提供"功能意图"（这个电路是一个加法器），网表提供"结构实现"（用了哪种加法器架构），两者结合才能精确估计功耗。缺任何一个都会大幅降低预测准确率。

**论文对 RTLDistil 效果的量化描述**（Section 5.2, line 856-857）：
- AT 预测 PCC 达到 0.885，**比 MasterRTL 提升 70.4%**，比 RTL-Timer 提升 6.0%
- WNS 预测 MAPE 35.28%，**比 MasterRTL 误差降低 45.8%**
- TNS 预测 PCC 0.918（最高），证明了在捕获累积时序违例方面的卓越能力

**论文对蒸馏机制的描述**（Section 5.2, line 1203-1206）：
> "layout-level physical information, when distilled into RTL-stage models through multi-granularity knowledge transfer, enables accurate early-stage predictions. This cross-stage paradigm effectively bridges the abstraction gap between behavioral descriptions and physical implementations."

**深入澄清：训练 vs 推理用的是什么模型？为什么有了 GT 还要老师网络？**

> 上面的架构图容易让人产生两个常见误解，这里专门澄清。

**误解一：teacher 比 student 大，student 向 teacher 靠（标准蒸馏思路）。**

RTLDistil 是 **cross-stage（跨阶段）蒸馏**，teacher / student 的区分关键不是「网络大小」，而是「输入模态」：

| | 老师网络 Teacher | 学生网络 Student |
|---|---|---|
| 输入 | **版图图像**（含走线延迟/寄生电容等真实物理信息） | **RTL 代码**（只有文本） |
| 任务 | 预测 AT/WNS/TNS | 预测 AT/WNS/TNS |
| 训练时 | ✅ 在跑 | ✅ 在跑 |
| 推理时 | ❌ 丢弃 | ✅ 只用它 |

两者干同一件事，只是老师手里多了「版图」这张底牌。

**误解二：训练和推理用的是同一套模型。**

- **训练**：teacher + student **两个**网络同时跑。
- **推理**：**只剩 student 一个**，teacher 整个丢掉。student 训练完的权重原封不动拿去推理，架构不变，只是训练时多接了「模仿老师」的损失分支，推理时这条分支不存在。

> 一句话：**训练时"偷看"版图学物理知识，推理时只需 RTL。** 老师是训练期的"作弊器"，推理期不需要了。

**核心问题：既然训练时有准确的时序 GT，学生直接对着 GT 学（普通监督学习）不就行了，为什么还要费劲搞老师网络让学生模仿？**

首先纠正一个隐含误解——**不是「GT vs 老师」二选一，学生一直在学 GT。** 损失函数是 `MSE + KL散度`：MSE 就是学生对齐 GT（正常监督），KL 才是模仿老师。即：

```
学生总损失 = α · MSE(学生预测, 真实GT)  +  (1-α) · KL(学生输出, 老师输出)
            └── 对齐正确答案 ──┘         └── 模仿老师 ──┘
```

蒸馏没有放弃 GT，是在 GT 基础上**额外加一路信号**。真正的问题是：**这路额外信号凭啥有用？** 三个理由：

**① GT 把物理信息压缩成了一个标量，信息被丢光了。**

GT 是因果链的终点，背后一整段物理过程被压进一个数字：

```
RTL代码 → 逻辑综合 → 网表 → 布局布线 → 走线延迟/寄生电容(版图物理) → 时序 GT
                                              ↑
                                    这一大段全被压进了一个数字，不可逆丢失
```

学生只看 RTL 直接回归 GT，等于要它一个人凭空重建中间那整段物理流程——太难。老师看过版图，它的输出（尤其中间层特征）已经走完了物理那段路；学生模仿老师，等于老师把"走过物理路得到的结论"递给学生，搭了脚手架。

**② GT 只能管最后一层，老师能管中间层（multi-granularity）。**

GT 是一个标量，**只能在最后一层**给学生监督，中间几十层特征没有直接监督。而文档强调的 *multi-granularity knowledge transfer* 正是让老师网络的**中间层特征**（编码了寄生参数空间分布等版图物理结构）逐层对齐学生网络——这是 GT 结构上给不了的：一个标量管不了一堆中间层。

**③ 软目标比硬标签信息量大（Hinton 蒸馏经典论点）。**

GT 是"硬目标"（一个点），梯度只在该点附近有意义；老师的输出是"软目标"，它对不同 RTL 输入给出的预测之间存在**相对关系、变化趋势**。学生学的是老师的**整个输出函数**而非一堆离散点，更易泛化到没见过的设计。

**类比**：预测"这栋楼建好后会不会塌"（时序违例）。
- 只用 GT：给学生图纸（RTL），只告诉他"塌了/没塌"。施工应力、地基沉降全被压成一个 bit，学生只能瞎猜图纸哪根线相关。
- 加老师：找个**看过工地照片和应力报告**（版图）的工程师当老师，他心里有完整的"图纸→施工→应力→塌不塌"因果链。学生模仿其判断过程，就间接偷到了"应力"那段知识——哪怕推理时根本看不到工地。

**诚实标注**：
- ✅ **文档/论文明确**：损失为 `MSE + KL散度`；蒸馏是 multi-granularity、cross-stage（RTL↔layout）。
- ⚠️ **推断（蒸馏通用原理）**：第 ②③ 点中"中间层逐层对齐""软目标更易泛化"是 Hinton 蒸馏的标准解释，RTLDistil 大概率遵循；但是逐层对齐还是只对齐最终输出、teacher 是否预训练，文档未细说，需查原文（Wang et al., ICML 2025）确认。

**论文对 MOSS 消融实验的解读**（Section 5.2, line 1199-1203）：

全模型 92.6% 的功耗预测准确率（PCC=0.948，MAPE=7.4%）的背后是：RTL 提供了**功能层面的信息**（这个电路在做什么），网表提供了**物理实现信息**（用了哪些门、是怎么连的），两者的结合才能"全面表征功耗"。

**横向对比：RTLDistil vs MOSS--为什么用两个模型？指标怎么读？**

> 时序和功耗分别讲完了，这里把两个 SOTA 模型放一起对比，并解释评估指标怎么读。

**一、两个模型都是"多模态"，但模态组合不一样**

| | **RTLDistil** (ICML 2025) | **MOSS** (DAC 2025) |
|---|---|---|
| 任务 | **时序**预测 | **功耗**预测 |
| 输入模态 | RTL + **版图**（图像） | RTL + **网表**（图） |
| 架构 | 跨阶段知识蒸馏：老师看版图，学生看 RTL | 双路编码：LLM 编码 RTL 文本 + GNN 编码网表图，融合回归 |
| **推理时**实际输入 | **只用 RTL**（版图仅训练期蒸馏用） | RTL + 网表（两路都在用） |
| 输出 | AT / WNS / TNS | Toggle Rate / Total Power |
| 借的是什么 | 版图的**物理延迟**知识 | "功能意图" + "门结构" |

关键：RTLDistil 的多模态 = RTL + **版图**；MOSS 的多模态 = RTL + **网表**。两者借的"第二模态"不同。

**二、为什么用两个模型，而不是一个统一模型预测 PPA？**

先澄清：**严格说这里预测的是 PP（功耗 + 时序性能），没有 Area**。本文全程没有面积预测任务（见第 1 节，只定义了时序和功耗两个任务）。

用两个模型的根本原因--**时序和功耗对物理信息的依赖点不同，所以各自需要不同的模态组合和架构**：

```
            时序 (RTLDistil)              功耗 (MOSS)
            ──────────────                ──────────
物理本质:   路径延迟 = 走线长度×单位延迟   P = α × f × C × V²
            ↑ 死磕"版图几何"               ↑ α由功能定, C由结构+版图定
            (走线多长直接决定延迟)         (翻转多频繁 × 充放电电容)

最缺的信息:  版图（走线长度/寄生电容）      RTL功能意图 + 网表门结构
            -> 所以借【版图】蒸馏           -> 所以用【RTL+网表】双路

推理输入:   只 RTL（更"左"，最早能预测）    RTL + 网表（需综合后，稍"右"）
```

- **时序**对"版图几何"极度敏感（走线长度直接变成延迟），但 RTL 阶段没版图 -> RTLDistil 用版图蒸馏把物理延迟知识塞进学生网络，推理时只需 RTL，能最早预测。
- **功耗** = 翻转活动（α，由**功能**决定）× 电容（C，由**门结构**决定）-> MOSS 用 LLM 抓功能意图 + GNN 抓门结构，两路推理时都要用。

所以不是"一个多模态大模型通吃 PPA"，而是**两个任务各自有物理上最相关的信息源，论文给每个任务配了验证过的 SOTA 模型**（RTLDistil 专做时序、MOSS 专做功耗，都是引用的已有工作）。理论上能做统一多头模型，但论文选择"专模专用"。

**三、评估指标 PCC / R² / MAPE 怎么算、怎么读**

文档只说"PCC=相关性 / R²=决定系数 / MAPE=百分比误差"（见评估配置），未给公式。下面是通用定义：

```
设 n 个样本，yᵢ = 真实值，ŷᵢ = 预测值，ȳ = 真实值均值，ŷ̄ = 预测值均值

① PCC (皮尔逊相关系数) ── 衡量"线性相关 / 趋势对不对"
   r = Σ(yᵢ-ȳ)(ŷᵢ-ŷ̄) / √[ Σ(yᵢ-ȳ)² · Σ(ŷᵢ-ŷ̄)² ]
   范围 [-1, 1]，越接近 1 越好。只看趋势和排序，不管绝对值准不准。

② MAPE (平均绝对百分比误差) ── 衡量"绝对值偏多少"
   MAPE = (100%/n) · Σ |(yᵢ - ŷᵢ) / yᵢ|
   越小越好。MAPE=7.4% = 平均误差是真实值的 7.4%。
   ⚠️ 分母是真实值 yᵢ，yᵢ->0 时会爆炸。

③ R² (决定系数) ── 衡量"模型解释了多少方差"
   R² = 1 - Σ(yᵢ-ŷᵢ)² / Σ(yᵢ-ȳ)²
   越接近 1 越好。
```

**为什么必须 PCC + MAPE 一起看**（读论文表格的钥匙）：

| 情况 | PCC | MAPE | 含义 |
|---|---|---|---|
| 理想 | 高 | 低 | 趋势对、绝对值也准 |
| 系统偏差 | 高 | 高 | 趋势对但有整体平移/缩放 |
| 乱预测 | 低 | 高 | 趋势和绝对值都不行 |

PCC 高 ≠ 预测准：一个恒定偏移 10ns 的模型 PCC 可以是 1.0 但 MAPE 爆表。所以论文同时报三个指标。

**一个能解释表格现象的坑**（⚠️ 推断，文档未说）：时序的 MAPE 普遍远高于功耗--

```
时序:  AT 28.96%   WNS 58.65%   TNS 38.74%   ← 都偏高，WNS 最高
功耗:  Total Power 7.4%   Toggle Rate 14.4%  ← 都很低
```

WNS 是时序**余量**（slack），设计往往卡在 0 附近（如 -0.1ns 这种小数）。MAPE 分母是真实值，**真实值接近 0 时 MAPE 会爆炸**--分母极小，一点绝对误差就被放大成大百分比。而 Total Power 是几十上百 mW 的大正数，分母大，MAPE 自然低。所以**时序的高 MAPE 部分是 MAPE 指标本身的缺陷，不完全代表模型差**--这也是为什么看时序要重点看 PCC（0.918/0.968 很高）而不能只盯 MAPE。

**诚实标注**：
- ✅ **文档/论文明确**：两个模型的任务、输入模态、架构、输出；评估指标为 PCC + R² + MAPE；本文无面积预测任务。
- ⚠️ **推断**：指标公式为通用定义（文档未给公式）；"WNS 真实值接近 0 导致 MAPE 爆炸"是按 MAPE 定义推断的解释，论文未明说。
