## 0. 一句话说清楚这篇论文

> 做了一个包含 **15,863 个芯片设计**的开源数据集，每个设计都有从 **RTL 代码 → 逻辑网表 → 物理版图**的完整数据（文本+图+图像三种模态）。通过 **AST 语法树改写** + **任务导向筛选**两层数据增强，让 AI 模型可以在设计早期（还没画版图的时候）就准确预测芯片的**时序**和**功耗**。用了这个数据集训练的多模态模型，时序预测误差降低 **36%**，功耗预测误差降低 **13%**。

## 1. 背景：芯片设计为什么需要 AI？

### 1.1 芯片设计有多难？

一块芯片从想法到制造，需要经历三个大阶段：

```
RTL 设计          逻辑综合           物理设计
(写代码描述     →  (把代码变成      →  (把门电路摆放
 电路行为)         门电路网表)         并连线到硅片上)

  Verilog          网表 (Netlist)      版图 (Layout)
  文本              图结构              图像
```

传统做法是**瀑布模型**——必须把三个阶段顺序走完，做出最终版图，才能验证性能和功耗。如果发现不达标，就要回头改 RTL 重新来，一轮迭代可能花**几周甚至几个月**。

![Figure 1: 传统瀑布模型 vs 现代左移模型](figures/fig1-waterfall-shiftleft.png)

**论文原图 Figure 1**：左侧为传统瀑布模型——RTL→网表→版图顺序执行，版图完成后才能做 PPA 分析，发现问题需要 ECO 回溯修改；右侧为左移模型——在每个阶段提前进行预测性分析，大幅缩短设计周期。

> **ECO（Engineering Change Order，工程变更指令）**：当版图验证发现时序或功耗不达标时，工程师发出的修改指令。"回溯"指的是你得往回退、修改之前阶段的产出物——最坏情况要退到 RTL 阶段重新写代码，然后综合→版图→验证全部重跑。一轮 ECO 回溯可能花**几天到几周**，如果一次修不完（通常修不完），就会像 Figure 1(a) 里画的那样反复循环，这就是传统瀑布模型迭代周期长的根本原因。左移模型（Figure 1(b)）的绿色 "Time Saving" 箭头就是靠 AI 在 RTL 阶段提前发现问题，避免"画完版图才发现、再回头改 RTL、再等版图重画"这个循环。

### 1.2 左移 (Shift-Left) 思想

如果在 RTL 阶段（还没画版图）就能预测最终的时序和功耗，就能在最早阶段发现问题，省掉大量返工时间。这就是"左移"——把验证从流程后端移到前端。

但问题是：RTL 阶段没有任何物理信息（走线延迟、寄生电容等），很难准确预测最终性能。这就需要 **AI 来学习 RTL 和最终物理实现之间的复杂映射关系**。

### 1.3 AI 做 EDA 缺什么？缺好数据！

训练 AI 需要大量高质量数据，但芯片设计数据极度缺乏：
- **知识产权壁垒**：芯片设计是公司核心机密，不会公开
- **生成成本高**：需要商业 EDA 工具（一套 License 几十万美元）+ 专业工程师 + 大量计算资源
- **现有数据集要么太小、要么太窄**：有的只有 RTL 没有版图，有的只有版图没有 RTL，有的 RTL 只有个位数

**CircuitNet 3.0 就是来解决这个问题的。**

## 2. CircuitNet 3.0 是什么？

一个**大规模、开源、多模态、多阶段**的芯片设计数据集，专门用于训练 AI 模型做**早期时序预测**和**早期功耗预测**。

### 核心数字

| 指标 | 数值 |
|------|------|
| 总设计数 | **15,863** |
| 原始 RTL 设计 | **8,659**（从互联网收集并严格验证） |
| 增强生成的设计 | **~7,200**（通过 AST 改写+任务导向过滤） |
| 数据模态 | **3 种**（文本 / 图 / 图像） |
| 设计阶段 | **3 个**（RTL / 网表 / 版图） |
| 功能分类 | **4 大类 16 子类** |
| 工艺节点 | **45nm CMOS** (GSCLIB 商业 PDK) |
| 构建耗时 | **约 8 个月** |

## 3. 数据集里有什么？

### 3.1 三类数据模态

![Figure 2: EDA 工作流中不同阶段的设计表示](figures/fig2-design-representations.png)

**论文原图 Figure 2**：三个设计阶段对应三种模态——RTL 代码（文本，通过 LLM/语言模型编码）、网表（图结构/Simple Operator Graph，通过 GNN/图神经网络编码）、版图（Layout Image，通过 CNN/卷积神经网络编码）。每种模态提取不同层次的特征。

#### 3.1.1 网表 vs 版图：本质区别是什么？

很多人会混淆网表和版图——都是"电路的实现"，但它们是**两个完全不同的抽象层**。用一个半加器例子从头讲清楚：

```verilog
module half_adder (input A, input B, output Sum, output Cout);
    assign Sum  = A ^ B;
    assign Cout = A & B;
endmodule
```

**网表（Netlist）= 逻辑连接关系（图模态）**：综合工具把 RTL 翻译成门级电路——告诉你"用了哪些标准单元、它们之间怎么连线"。标准单元是工艺库里预制好的基本门：

| 单元名 | 功能 | 驱动 |
|--------|------|------|
| `AND2X1` | 2输入与门 | 弱，省电 |
| `AND2X4` | 2输入与门 | 强，带载多 |
| `XOR2X2` | 2输入异或 | 中等 |

同一个 `assign Cout = A & B;`，综合工具可能选 `AND2X1` 或 `AND2X4`——**选哪个对功耗和时序影响巨大，但 RTL 代码完全看不出差别**。网表揭示了 RTL "行为"背后的"实现选择"，以**图（Graph）**的形式存储（节点=标准单元，边=连线），论文用 **GNN** 处理。

**版图（Layout）= 物理几何位置（图像模态）**：把网表中每个标准单元的物理版图（预制好的矩形块）摆放到硅片的具体坐标上，然后实际连线。版图告诉你每个门放在 (x,y) 的哪个位置、走线实际走了多长、某个区域挤不挤。以**图像（Image）**形式存储，论文用 **CNN** 处理。

**关键的差别：寄生参数**。在网表阶段，连线被当作理想的零延迟导线。但在版图阶段，连线是真实的金属段——它有寄生电阻 R（导致压降和发热）和寄生电容 C（信号翻转需要充放电）。功耗公式 `P = α×f×C_eff×VDD²` 里的 **C_eff 只有版图完成后才能提取**。没有版图就没有寄生参数，没有寄生参数就算不准真实时序和功耗——而这两个恰恰是 AI 模型的预测目标。这就是为什么 CircuitNet 3.0 必须覆盖版图阶段。

| 维度 | 网表（Netlist） | 版图（Layout） |
|------|---------------|--------------|
| 本质 | 逻辑连接关系 | 物理几何位置 |
| 数据形式 | 图（节点=门，边=连线） | 图像 + 坐标数据 |
| 连线建模 | 理想导线（零延迟） | 真实金属线（有寄生 R/C） |
| 生成工具 | Synopsys DC | Cadence Innovus |
| 生成时间 | 秒~分钟 | 分钟~小时（10-50次迭代） |
| 有寄生参数？ | ❌ | ✅（SPEF 文件） |
| 能算真实时序？ | 只能估算 | ✅ Post-route STA |
| 能算真实功耗？ | 只能估算 | ✅ PrimePower 签核级 |

#### 3.1.2 三类数据模态总结

```
┌─────────────────────────────────────────────────────┐
│  RTL 阶段              网表阶段           版图阶段    │
│  ┌──────────┐      ┌──────────┐      ┌──────────┐   │
│  │Verilog代码│  →   │ 门级网表  │  →   │ 物理版图  │   │
│  │          │      │          │      │          │   │
│  │module add│      │  D  Q    │      │ ██░░██░░  │   │
│  │(a,b,sum)│      │  ├──┤    │      │ ░░██░░██  │   │
│  │...       │      │  │FF│    │      │ ██░░██░░  │   │
│  └────┬─────┘      └────┬─────┘      └────┬─────┘   │
│       │                 │                 │         │

└─────────────────────────────────────────────────────┘
```

每个设计实例都包含：
- **RTL 代码**：Verilog/SystemVerilog，可综合的行为描述
- **网表**：门级标准单元 + 连接关系图（综合后生成）
- **版图**：物理布局图像 + 寄生参数 (SPEF)（布局布线后生成）
- **性能标签（Ground Truth）**：用商业 EDA 工具跑出来的真实时序/功耗数值

### 3.2 四类功能电路

用 **Claude Opus 4** 做自动分类 + 三位硬件专家人工验证（一致率 94.3%），分成 4 大类 16 子类：

| 主类（占比） | 子类（数量） | 典型例子 |
|-------------|------------|---------|
| **算术逻辑单元** (23.6%) | 加法器/减法器(645)、乘法器/除法器(774)、ALU/累加器(519)、其他(114) | 做加减乘除和各种逻辑运算 |
| **控制时序电路** (17.9%) | 计数器/定时器(906)、有限状态机/序列器(392)、控制逻辑(242)、其他(8) | 控制芯片的工作节奏和状态跳转 |
| **数据处理单元** (29.9%) | 比较器/选择器(1,453)、编码器/解码器(431)、FIFO/缓冲器(407)、其他(292) | 数据的传输、比较、编解码 |
| **通信与存储** (28.6%) | 存储/寄存器(1,061)、总线接口(943)、串行接口(445)、其他(27) | 存数据和芯片间通信 |

### 3.3 性能标签（预测目标）

时序标签（由 Synopsys PrimePower + Cadence Innovus 提取）：
- **AT (Arrival Time)**：信号到达时间，即信号从起点传播到终点花了多久
- **WNS (Worst Negative Slack)**：最关键单条路径的时序余量——负数说明"来不及了"，正数说明"来得及"
- **TNS (Total Negative Slack)**：全部时序违规路径的违规量总和

功耗标签（由 Synopsys PrimePower 提取）：
- **Toggle Rate**：电路中信号翻转的活跃程度（在 0~1 之间）
- **Total Power**：总功耗（毫瓦 mW）

## 4. 数据增强是怎么做的？⭐

![Figure 4: 论文原图 — CircuitNet 3.0 工作流框架](figures/fig4-workflow.png)

> **Figure 4**：完整 Pipeline —— RTL 数据收集与清理 → AST-Based Rewrite 扩展 → EDA Flow 多阶段数据生成（综合→布局布线→仿真）→ 特征提取（Slack/AT/Power/Map）。这是整个数据集构建的总览图。

这是论文最核心的技术贡献。数据增强分**两层**：

### 4.1 第一层：AST 语法树改写（快速批量生成 RTL 变体）

#### 为什么不用随机生成？

随机生成 Verilog 代码 → 大概率语法错误或综合失败 → 浪费时间。论文的思路是：**在已经验证过的优质设计上做"微整形"，不大改结构，只调细节。**

#### 具体怎么做的？（Algorithm 2）

```
输入：一个验证过的 RTL 代码 R
输出：N 个变异后的 RTL 变体

Step 1  用 PyVerilog 把 RTL 解析成 AST（抽象语法树）
        ┌─────────────────────────┐
        │  assign sum = a ^ b;    │  解析后变成
        │  assign cout = a & b;   │  →  Module
        └─────────────────────────┘      ├─ Assign: sum = XOR(a, b)
                                          └─ Assign: cout = AND(a, b)

Step 2  遍历 AST 中每个节点，标记"可变异"节点
        - 算术运算节点：+, -, *, /, %    → 可变异
        - 逻辑运算节点：&&, ||, &, |, ^  → 可变异
        - 关系运算节点：==, !=, >, <     → 可变异
        - 时序边沿：posedge ↔ negedge    → 可变异
        - 赋值方式：<= ↔ =               → 可变异
        - 常量数值：8'd10 → 8'd11         → 可变异
        - 模块名/端口名                   → 不可变异！（保持接口兼容）

Step 3  对每个可变异节点，列出候选变异方案
        例：AST 中找到一个 "a + b" 节点
        → 候选1: 改成 "a - b"（类型兼容，都是算术）
        → 候选2: 改成 "a * b"
        → 不会候选：改成 "a && b"（类型不兼容，算术↛逻辑）

Step 4  从所有候选中随机采样 N 个

Step 5  逐个执行变异，每执行一个就做一致性检查
        - 检查 always 块里是否混用了阻塞和非阻塞赋值
        - 如果是，用"多数投票法"统一

Step 6  把变异后的 AST 转回 Verilog 代码

Step 7  送进 Synopsys Design Compiler 做综合验证
        → 通过了 → 保留！
        → 失败了 → 降级为文本级变异重试（极少发生）
```

#### 六类变异算子详解

| 变异类型 | 原始代码 | 变异后 | 通俗解释 |
|---------|---------|--------|---------|
| **算术替换** | `c = a + b` | `c = a - b` | 加法器变减法器，电路结构完全不同 |
| **算术替换** | `c = a * b` | `c = a / b` | 乘法器变除法器（有除零保护） |
| **逻辑替换** | `if (a && b)` | `if (a \|\| b)` | 与逻辑变或逻辑，决策条件不同 |
| **位操作替换** | `c = a & b` | `c = a \| b` | 按位与变按位或 |
| **关系反转** | `if (a > b)` | `if (a < b)` | 大于变小于，比较边界反转 |
| **等价反转** | `if (a == b)` | `if (a != b)` | 等于变不等于 |
| **时钟沿切换** | `@(posedge clk)` | `@(negedge clk)` | 上升沿触发变下降沿 |
| **赋值方式** | `q <= d` | `q = d` | 非阻塞变阻塞（影响仿真行为） |
| **常量微调** | `8'd10` | `8'd11` | 阈值 +1（位宽不变） |

#### 关键约束

- **类型保持**：算术和算术之间换，逻辑和逻辑之间换，不乱跨界
- **上下文感知**：不在敏感列表里做算术变异（`always @(posedge clk)` 里的 `posedge` 是时序信号不能改算术）
- **位宽保持**：`8'd10` 只能变成 `8'dXX`，不能变成 `16'dXX`
- **赋值一致性**（Algorithm 3）：always 块里所有赋值要么全是 `<=` 要么全是 `=`，混用的用多数投票统一

### 4.2 第二层：任务导向增强（在网表和版图级别精炼+过滤）

![Figure 5: 论文原图 — 数据增强三路流程](figures/fig5-data-augmentation.png)

> **Figure 5**：(a) AST-based Rewrite — 对 RTL 语法树进行变异算子改写；(b) Timing-Task-Oriented — DC compile_ultra + Innovus 优化到密度>90%，只保留成功且路径长的设计；(c) Power-Task-Oriented — 同一 RTL 用不同配置综合出多个网表变体，Voltus 做无向量功耗分析筛选活跃逻辑。

第一层 AST 改写生成的大量变体中，约 **73% 会被丢弃**（综合失败、过于相似、无训练价值）。保留下来的进入第二层：

#### 时序任务增强（Figure 5b 流程）

```
AST改写后的 RTL
      │
      ▼
[Synopsys Design Compiler] compile_ultra
  综合成最优网表（时序优先优化）
      │
      ▼
[Cadence Innovus] 迭代优化到布局密度 > 90%
  做完整的布局布线，直到密度达标
      │
      ├── 成功 ──→ 提取 AT/WNS/TNS 标签 ──→ 加入"时序数据集"
      │
      └── 失败 ──→ 丢弃（Innovus 也无法物理实现的设计）
      │
      ▼
过滤：只保留"路径较长"的设计
  → 丢弃那些时序极其宽松的简单电路
  → 因为 AI 需要学的是"难"案例，不是轻松能过的案例
```

**为什么这么筛？** 工业场景里，一个预测模型的价值由它在**极限时序场景**的准确率决定。如果训练数据全是 `WNS = +5ns`（很宽松）的设计，模型遇到 `WNS = -1ns`（有违例）的设计就不会预测。**故意往训练集里塞"硬骨头"，模型才能学到真本事。**

#### 功耗任务增强（Figure 5c 流程）

```
同一个 RTL 代码
      │
      ├── [Design Compiler] 配置A（面积优先） → 网表_v1
      ├── [Design Compiler] 配置B（时序优先） → 网表_v2
      └── [Design Compiler] 配置C（默认）     → 网表_v3
      │
      ▼
[Cadence Voltus] 对每个网表做"无向量动态功耗分析"
  给定所有输入一个 20% 的默认翻转率，
  让工具自动传播翻转活动到所有内部节点，
  看哪些门的输出从不翻转（死逻辑）
      │
      ├── "活逻辑"比例高 → 保留，加入"功耗数据集"
      └── "死逻辑"比例高 → 丢弃（训练价值低）
```

**为什么同一 RTL 要生成多个网表？** 同一个 RTL 语句可以被综合工具映射成完全不同的门级实现：

```
RTL: assign c = a + b;

综合配置A（面积优先）→ 用最少的门实现，但跑得慢
综合配置B（时序优先）→ 用更多并行门实现，跑得快但功耗大

这两种实现的功耗完全不同！AI需要学会这种对应关系。
```

**为什么用无向量分析筛选？** 如果一段逻辑在任何输入下输出都不翻转（比如死代码），它对功耗预测模型没有任何训练价值，反而会引入噪声。

### 5.2 五大独特优势

**① 全流程可追溯——真正的一条龙**

其他数据集要么有 RTL 没版图（RTLCoder），要么有版图但 RTL 才几个（CircuitNet 2.0 只有 8 个 RTL）。CircuitNet 3.0 是第一个做到 **"每个设计都有 RTL + 网表 + 版图 + 性能标签"完整链条**的。这对多模态 AI 至关重要——模型可以学习同一电路在不同抽象层之间的对应关系。

**② AST 改写 vs 随机生成——精细活 vs 乱枪打鸟**

RTLCoder 用 LLM 随机生成 RTL，问题是语法错误多、综合通过率低、电路不现实。CircuitNet 3.0 在**已经过综合+仿真双重验证的真实设计**上做局部微调，最终接受率只有 27%——意味着 73% 的生成物被严格丢弃，留下来的都是高质量变体。

**③ 面向"难案例"——专啃硬骨头**

传统的做法是"收集能跑通的设计"，CircuitNet 3.0 反其道而行之——**故意筛选难的**：
- 时序任务：优先保留长路径、时序紧张的设计（WNS 为负的）
- 功耗任务：优先保留逻辑活跃、有实质功耗变化的设计
- 密度：特意探索 85%-100% 全范围（极端拥挤的也要）

这样训练出的模型在工业场景的边界案例上更可靠。

**④ 防数据泄露——比多数数据集严格**

- 测试集**100% 是原始未增强设计**
- 如果一个原始设计分到了测试集，它的所有增强变体**完全排除**在训练和验证之外
- 还额外引入外部开源项目的子模块作为测试补充
- 用**网表级别图比较**验证没有结构相同的设计泄露

**⑤ 商业级工具链 + 迭代收敛——标签是真的准**

不是跑一次 EDA 工具就拿结果，而是 **10-50 次迭代直到三个条件同时满足：**
- 布局密度变化 < 0.5%
- 时序指标（WNS/TNS）稳定在 2% 公差内连续三次
- 功耗变化 < 3%

这保证了 Ground Truth 标签的质量达到工业级。整个过程耗时约 **8 个月**。

## 6. 模型分别做什么？输入输出是什么？⭐

论文所有模型服务于两个 EDA 预测任务：

### 6.1 任务全景图

```
                    ┌───────────────┐
  RTL代码 (文本) ──→│               │
                    │   多模态AI    │──→ 时序预测: AT, WNS, TNS
  网表 (图结构)  ──→│   融合模型    │
                    │               │──→ 功耗预测: Toggle Rate, Power
  版图 (图像)    ──→│               │
                    └───────────────┘
```

### 6.2 任务一：时序预测

**要解决的问题**：在只有 RTL 代码时（还没画版图），预测最终芯片的时序性能。

**输入**：Verilog RTL 代码（纯文本字符串）
**输出**：三个时序数值
- **AT (Arrival Time)**：信号从起点到终点的传播延迟（纳秒 ns），越小越好
- **WNS (Worst Negative Slack)**：全芯片最关键路径的时序余量——**负数 = 时序违例（跑不到目标频率），正数 = 安全**。芯片设计最重要的指标之一
- **TNS (Total Negative Slack)**：全部违例路径的违例值总和，衡量整体时序健康状况

#### 时序预测模型逐个拆解

| 模型 | 输入是什么 | 怎么做的 | 通俗理解 |
|------|----------|---------|---------|
| **MasterRTL** | 仅 RTL 代码文本 | 从 RTL 提取特征，直接回归 AT/WNS/TNS | 基线方法，相当于"看着代码猜性能" |
| **RTL-Timer** | 仅 RTL 代码文本 | MasterRTL 的改进版，能做更细粒度的**逐行时序标注** | 不仅猜整体性能，还能指出"这几行代码会拖慢芯片" |
| **RTLDistil** ⭐ | RTL 代码 + **版图信息（知识蒸馏）** | 训练时：老师网络看版图学物理信息 → 把知识"蒸馏"给学生网络；推理时：学生网络只需要 RTL 输入 | **核心创新**——训练时偷看版图学物理知识，推理时只需 RTL 就能做准预测 |

**RTLDistil 的训练 vs 推理（最巧妙的设计）**：

```
【训练阶段】                          【推理阶段】
  版图图像                               RTL 代码
    │                                       │
    ▼                                       ▼
┌─────────┐                           ┌─────────┐
│ 老师网络  │ ──→ 知道真实物理信息       │ 学生网络  │ ──→ 预测时序
│ (看版图)  │     (走线延迟/寄生电容)    │ (只看RTL) │     不需要版图！
└────┬────┘                           └─────────┘
     │                                    ↑
     │    ┌─────────────────┐             │
     └───→│ 蒸馏损失函数     │←────────────┘
          │ (让学生模仿老师)  │
          └─────────────────┘
```

**这解决了什么矛盾？** RTL 阶段没有版图，但时序高度依赖版图中的物理参数。通过蒸馏，学生网络在推理时只需 RTL 输入，但已经"隐式学会了"版图里才有的物理信息。这就是**左移**的技术实现。

### 6.3 任务二：功耗预测

**要解决的问题**：在设计早期（RTL + 网表阶段）预测最终芯片功耗。

**输入**：RTL 代码（文本）+ 网表（图结构——门单元节点 + 连线边）
**输出**：两个功耗指标
- **Toggle Rate（切换率）**：0~1 之间的值，表示电路中信号翻转有多频繁。翻转越频繁，动态功耗越大。公式：P_dynamic = α × f × C_eff × VDD²，其中 α 就是 Toggle Rate
- **Total Power（总功耗）**：最终芯片总功耗，单位毫瓦（mW）

#### 功耗预测模型逐个拆解

| 模型 | 输入是什么 | 怎么做的 | 通俗理解 |
|------|----------|---------|---------|
| **GRASPE** | 仅 RTL 代码 | 把 RTL 构建成算子图，用 GNN 推断功耗 | 纯从"功能描述"猜功耗，看不到真实门实现 |
| **MasterRTL** | 仅 RTL 代码 | 综合前 PPA 估计框架 | 基线，和时序预测同一个架构 |
| **VIRTUAL** | 仅 RTL 代码 | 解耦多模态的向量化动态功耗估计 | 纯 RTL 方案中最强的 |
| **DeepSeq2** | 仅网表（图） | 时序电路的解耦表示学习 | 只看门级结构猜功耗，不看设计意图 |
| **MOSS (消融版)** | 仅网表（图） | MOSS 去掉多模态部分 | 用于证明"只看网表不够" |
| **MOSS (完整版)** ⭐ | **RTL 代码 + 网表图** | 双路编码：LLM 处理 RTL 文本 → 语义特征；GNN 处理网表图 → 结构特征；特征融合后回归 | **多模态最优方案** |

**MOSS 为什么比只看网表或只看 RTL 都好？**

```
RTL 代码                        网表
"assign c = a + b;"         NAND2 + INV + NOR2 串起来的加法器
(告诉AI：这是一个加法器)       (告诉AI：用了3个门，走线这么连的)
        │                              │
        ▼                              ▼
   [LLM编码]                      [GNN编码]
   功能语义特征                   结构实现特征
        │                              │
        └──────────┬───────────────────┘
                   ▼
            特征拼接 + 融合层
                   │
                   ▼
           回归头 → 功耗预测
```

**通俗类比**：RTL 告诉你"我要吃晚饭"（意图），网表告诉你"具体菜单是牛排+沙拉+红酒"（实现）。只看意图你猜不出花了多少钱（功耗），只看菜单你也不理解为什么要这么吃。两者结合才能精确估计。

### 6.4 多模态框架总结

```
设计阶段:    RTL阶段              网表阶段            版图阶段
           ┌──────────┐       ┌──────────┐       ┌──────────┐
数据形式:   │Verilog代码│       │ 门级网表  │       │ 物理版图  │
           │ (文本)    │       │ (图)      │       │ (图像)    │
           └────┬─────┘       └────┬─────┘       └────┬─────┘
                │                  │                  │
编码器:         ▼                  ▼                  ▼
           LLM (大语言模型)   GNN (图神经网络)   CNN (卷积神经网络)
           提取语义特征       提取结构特征      提取空间几何特征
                │                  │                  │
                └──────────────────┼──────────────────┘
                                   │
                                   ▼
                          多模态特征融合
                                   │
                    ┌──────────────┴──────────────┐
                    ▼                             ▼
             时序预测头                       功耗预测头
         输出: AT, WNS, TNS             输出: Toggle Rate, Power
```

## 10. 核心洞察与总结

### 🔟 十大关键洞察

1. **多模态远胜单模态**：RTL（文本）+ 网表（图）+ 版图（图像）三种信息融合使用，比任何一种单用都好。RTLDistil 比最好的纯 RTL 方法 RTL-Timer 的 PCC 平均提升 8%，MAPE 平均降低 18.2%。

2. **知识蒸馏是左移的关键技术**：RTLDistil 的训练技巧——让老师网络在训练时看版图，把物理知识蒸馏给学生网络，推理时学生只需要 RTL 输入。这是"早期预测物理实现结果"的核心技术路线。

3. **数据增强对所有模型都有效**：不管是最简单的 MasterRTL 还是最复杂的 RTLDistil，在增强数据上都比在原始数据上表现好，原始数据又比 Resyn-27k 好。证明增强策略具有普适性。

4. **AST 改写比随机生成靠谱得多**：在已验证的真实设计上做局部微调，综合通过率远高于 LLM 随机生成 Verilog。27% 的最终接受率说明质量筛选相当严格。

5. **面向"难"案例训练是正确思路**：工业场景最关心的是极限情况下的准确率。故意筛选时序紧张、功耗大的设计做训练，模型泛化能力更强。

6. **RTL + 网表双模态对功耗预测尤其重要**：MOSS 的消融实验证明——去掉 RTL 信息只看网表（或反过来），性能大幅下降。RTL 提供"功能意图"，网表提供"结构实现"，两者缺一不可。

7. **数据质量 > 数据数量**：从 100,000+ 行 RTL 中只保留 8,659 个设计（8.7%），增强生成又丢弃 73%（AST 变异接受率 27%），说明严格的质量控制比堆数量更有效。

8. **商业 EDA 工具 + 迭代优化保证标签质量**：不是跑一次就拿结果，而是 10-50 次迭代直到三个指标都收敛。这保证了 Ground Truth 的可靠性。

9. **工艺可迁移性**：虽然数据集基于 45nm GSCLIB，但整个流程脚本不绑定特定工艺节点。有权限访问其他 PDK 的用户可以替换工艺文件重新跑流程。

10. **严格的防泄漏设计**：按源设计级别划分数据集（不是随机打散），测试集全是原始设计，其增强变体完全不参与训练。这是很多 ML 基准测试忽略的细节。

### 🎯 一句话总结

> CircuitNet 3.0 通过 **AST 语法树改写**（生成多样性）+ **任务导向过滤**（保留硬骨头）+ **商业 EDA 迭代优化**（保证标签准）三层设计，构建了首个覆盖 **RTL→网表→版图**完整链条的大规模开源芯片设计数据集，证明了**多模态 AI 模型在芯片设计的早期阶段准确预测最终性能是可行的**——这为 AI 驱动的芯片设计自动化奠定了基础。
