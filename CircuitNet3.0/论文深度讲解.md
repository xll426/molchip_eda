## 1. 一句话定位

**CircuitNet 3.0 是全球首个大规模、开源、覆盖 RTL->网表->版图完整设计链的多模态芯片设计数据集——包含 8,659 个验证过的原始 RTL 设计（经 AST 语法树改写增强后共 15,863 个实例），每个设计同时具备文本（RTL 代码）、图（门级网表）、图像（物理版图）三种模态的数据，以及由商业 EDA 工具生成的签核级时序/功耗标签（AT、WNS、TNS、Toggle Rate、Total Power）。通过 AST 语法树增强和任务导向过滤两层数据增强策略，CircuitNet 3.0 使多模态 AI 模型能在 RTL 设计阶段（流程阶段 ①）准确预测最终物理实现的时序和功耗——时序预测误差降低 36.0%，功耗预测误差降低 12.9%。**

这句话里的五个技术承重点，后面逐一拆解：

1. **全流程可追溯的多模态数据** -- CircuitNet 3.0 的每个设计实例都包含 RTL 代码->综合网表->物理版图的完整链路，拥有文本（RTL/LLM 编码）、图（网表/GNN 编码）、图像（版图/CNN 编码）三种模态和对应的签核级性能标签。前代 CircuitNet 2.0 只有 8 个 RTL 设计（但有 10,791 个版图），RTLCoder 有 2.6 万个 RTL 但没有网表和版图——3.0 是第一个做到"8,659 个原始 RTL 配 15,863 个版图，且每个都有网表完整配对"的数据集。

2. **AST 语法树改写增强（核心技术创新）** -- 不是 LLM 随机生成 Verilog 代码（语法错误多、综合通过率低），而是在已验证的真实设计上，用 PyVerilog 解析 RTL 为抽象语法树（AST），对算术/逻辑/关系/时序/赋值/常量六类运算节点做类型保持的局部改写。改写后约 73% 被三层过滤（综合失败/结构相似>97%/无训练价值）丢弃——最终约 27% 被保留。

3. **任务导向的数据增强与过滤** -- 时序任务：用 Synopsys DC compile_ultra 综合 + Cadence Innovus 迭代优化到密度>90%，只保留路径长、时序紧张的"硬骨头"设计。功耗任务：同一 RTL 用不同综合配置产生多个网表，用 Cadence Voltus 做无向量功耗分析，丢弃死逻辑比例高的设计。这种"面向难案例"的策略使模型在工业边界场景上更可靠。

4. **多模态 SOTA 模型验证** -- RTLDistil（ICML 2025）：用版图（图像）训练老师网络，再通过知识蒸馏把物理信息传给只看 RTL 的学生网络——推理时只需 RTL 代码即可预测时序，是"左移预测"的核心技术实现。MOSS（DAC 2025）：LLM 编码 RTL 功能意图 + GNN 编码网表门级结构，双路融合预测功耗——消融实验证实两者缺一不可。

5. **防泄漏的严格数据划分** -- 按源设计级别划分 80/10/10，测试集 100% 是原始未增强设计，增强变体完全排除在训练和验证之外，还额外用网表级图比较验证无结构相同设计泄露。

## 2. EDA 阶段映射（①-⑰）

参照 [芯片流程.md](../芯片流程.md) 的 17 阶段标准编号。CircuitNet 3.0 的核心价值是**左移（Shift-Left）预测**：在 RTL 阶段（①）预测最终物理实现的时序和功耗（阶段 ③/⑤/⑬ 的签核级指标）。

| 阶段 | 覆盖 | 说明 |
|------|:---:|------|
| **① RTL 设计** | ✅ **核心输入** | 8,659 个经过 5 步验证的 Verilog RTL 设计，这是多模态预测的起点。论文的 RTLDistil 在推理时**仅需 RTL 代码**即可预测最终时序 |
| ② RTL 功能仿真 | ✅ | 用 Icarus Verilog/Verilator 做语法编译检查 + testbench 功能仿真，确保原始设计的逻辑功能正确 |
| **③ 逻辑综合** | ✅ **核心** | Synopsys Design Compiler 2020.09 + compile_ultra 最高优化生成门级网表。网表作为"图模态"输入，也是时序和功耗标签生成的必经环节。对于功耗任务增强，同一 RTL 用不同综合配置产生多个网表变体 |
| ④ 门级仿真 | ❌ | CircuitNet 3.0 不跑门级仿真——数据生成的验证是综合成功+物理实现成功，不依赖门级仿真做功能验证 |
| **⑤ STA（静态时序分析）** | ✅ **标签来源** | Post-route STA 提取 AT/WNS/TNS 作为时序预测的 Ground Truth。论文的时序标签不是综合后估算，而是布局布线后含真实走线延迟的签核级数据 |
| ⑥ 形式验证 | ❌ | — |
| **⑦ 布局规划 (Floorplan)** | ✅ | Cadence Innovus 19.11 自动 Floorplan：IO 引脚自动摆放、电源网络多层级铺设（M1-M11 共 11 层金属） |
| **⑧ 标准单元摆放 (Placement)** | ✅ | 密度 70%（pre-CTS），Tool 自动做全局 uniform density placement |
| ⑨ 时钟树综合 (CTS) | ✅ | 有用 skew 优化，密度上限 80% |
| **⑩ 布线 (Routing)** | ✅ | Timing-driven routing + wire spreading/widening + post-route 优化到密度 95% |
| ⑪ 后仿真 | ❌ | — |
| ⑫ 物理验证 (DRC+LVS) | ✅ | 每个设计自动跑 DRC verify + connectivity check，目标 0 violation |
| **⑬ 签核 (Signoff)** | ✅ **标签来源** | Synopsys PrimePower 签核级功耗分析（基于 post-route SPEF 寄生参数），生成 Total Power / Toggle Rate 作为功耗预测 Ground Truth；时序标签也在此最终确定（WNS/TNS 稳定在 2% 公差内） |
| ⑭-⑰ 流片->制造->封装测试->芯片 | ❌ | — |

**覆盖率：9/17。** CircuitNet 3.0 覆盖了从 RTL 设计到签核的全部数字前端+后端流程。它的独特定位是：**输入是阶段 ① 的 RTL 代码，输出预测的是经过阶段 ③->⑤->⑦->⑧->⑩->⑬ 完整物理实现的签核级性能——中间整个后端流程被 AI 模型"跳过"了。** 这是全资料包中跨阶段最广的论文。

> ⚠️ **最容易误读的边界**：CircuitNet 3.0 本身是一个**数据集和评测基准**，不是单一模型。论文评估的 RTLDistil 和 MOSS 是引用的已有模型（分别出自 ICML 2025 和 DAC 2025），CircuitNet 3.0 是它们的训练和评测平台。另外，论文只预测**时序和功耗**（PP），不预测面积（Area）——RTLDistil 和 MOSS 都不输出面积指标。前代 CircuitNet 1.0/2.0 数据在 [../CircuitNet/](../CircuitNet/) 目录（面向后端物理设计任务：拥塞预测/IR Drop/DRC hotspot），与 3.0 的任务定位完全不同——3.0 是前端->后端跨阶段预测，1.0/2.0 是后端预测。

## 3. 输入 / 输出

本节围绕 CircuitNet 3.0 数据集提供的四类模态数据和两个核心预测任务的输入输出展开。

### 3.1 数据集输入（给 AI 模型训练用的多模态特征）

#### 3.1.1 文本模态：RTL 代码（阶段 ①）

每个设计实例包含完整的可综合 Verilog/SystemVerilog RTL 代码。以半加器为例：

```verilog
module half_adder (
    input  A,
    input  B,
    output Sum,
    output Cout
);
    assign Sum  = A ^ B;
    assign Cout = A & B;
endmodule
```

- **编码器**：LLM（大语言模型），从 RTL 文本中提取**功能语义特征**——"这是一个加法器"、"这些信号之间的逻辑关系是异或和与"
- **数据规模**：8,659 个原始 RTL 设计，来自 GitHub / OpenCores / HuggingFace / RISC-V 四个来源，经过 5 步严格验证（语法->综合->仿真->Lint->复杂度分析），最终通过率约 8.7%
- **功能分类**：4 大类 16 子类（算术逻辑 23.6%、控制时序 17.9%、数据处理 29.9%、通信与存储 28.6%），由 Claude Opus 4 分类+三位专家验证（一致率 94.3%）

#### 3.1.2 图模态：门级网表（阶段 ③）

RTL 经 Synopsys Design Compiler compile_ultra 综合后的门级网表：

```text
节点：标准单元（AND2X1, XOR2X1, DFFHQX1, INVX1...）
边：单元之间的连线（net）
图类型：有向异构图（节点类型包括组合逻辑门、时序元件、输入/输出端口）
```

- **编码器**：GNN（图神经网络），从网表图中提取**结构实现特征**——用了哪些门、门之间怎么连、关键路径经过哪些节点
- **为什么网表是"图"模态**：综合后，RTL 代码中的 `assign Sum = A ^ B` 变成了一个具体的 `XOR2X1` 门实例，`assign Cout = A & B` 变成了 `AND2X1`——已经从"行为描述"变成了"门级结构"。

#### 3.1.3 图像模态：物理版图（阶段 ⑦⑧⑩）

Cadence Innovus 物理实现后生成的版图图像，以及从版图提取的寄生参数 SPEF：

- **版图图像**：含标准单元放置和金属走线的 2D 图像，编码器为 CNN（卷积神经网络），提取**空间几何特征**——单元密度分布、走线拥塞热区、宏单元布局
- **SPEF（Standard Parasitic Exchange Format，标准寄生交换格式）**：每根连线的寄生电阻 R 和电容 C 的精确数值。这是从版图中提取的物理量，RTL 和网表阶段都没有这些信息
- **关键认知**：RTL 阶段连线被当作零延迟理想导线；网表阶段引入门延迟但连线延迟仍是估算；**只有版图完成后才能提取真实的走线 RC 寄生参数**——这是时序和功耗最终预测精度的物理基础

#### 3.1.4 表格模态：统计特征

从各个设计阶段提取的结构化统计量——门数、路径深度、时序元件比例、布局密度、翻转率分布等。可用 XGBoost / MLP 处理，提供快速的统计级别推理。

### 3.2 数据集输出（Ground Truth 性能标签）

| 标签 | 含义 | 工具 | 分析阶段 |
|------|------|------|---------|
| **AT** (Arrival Time) | 信号传播延迟（ns）——信号从寄存器输出经组合逻辑到达下一寄存器输入的总时间 | Cadence Innovus post-route STA | ⑩/⑬ |
| **WNS** (Worst Negative Slack) | 全芯片最关键路径的时序余量（ns）。负值=违例（跑不到目标频率），正值=安全 | Cadence Innovus post-route STA | ⑩/⑬ |
| **TNS** (Total Negative Slack) | 全部时序违例路径的违例值总和（ns），衡量整体时序健康度 | Cadence Innovus post-route STA | ⑩/⑬ |
| **Toggle Rate** | 信号翻转活跃度（0~1），值越接近 1 表示信号翻转越频繁 | Synopsys PrimePower vectorless analysis | ⑬ |
| **Total Power** | 总功耗（mW），含动态功耗和静态功耗 | Synopsys PrimePower vectorless analysis | ⑬ |

### 3.3 两个预测任务的端到端 Walkthrough

#### 任务一：时序预测 -- 输入 RTL，输出 AT/WNS/TNS

以论文中的一个典型加法器为例：

```
【输入】Verilog RTL 代码（阶段 ①，纯文本）
module adder_8bit(
    input  [7:0] a, b,
    input        clk,
    output reg [8:0] sum
);
    always @(posedge clk)
        sum <= a + b;
endmodule

【RTLDistil 推理过程】
  RTL 文本 → LLM 编码器 → 语义特征向量
                                    │
          ┌─────────────────────────┘
          ▼
   学生网络（训练时已通过蒸馏从 CNN 老师网络学到了版图的物理信息）
          │
          ▼
  时序预测头（3 个并行回归器）

【输出】三个数值（模型预测的是布局布线后的签核级结果）
  AT  = 0.873 ns   — 信号从输入 a/b 经 8 位加法器到达 sum 寄存器输入的延迟
  WNS = -0.153 ns  — 最差路径延迟超过 1ns 目标周期 0.153ns，存在时序违例！
  TNS = -2.371 ns  — 全部违例路径的违例总和为 -2.371ns
```

**关键洞察**：RTL 代码只说了 `sum <= a + b`，完全没提加法器用什么架构（行波进位/超前进位）、用哪些门、门放哪里、走线多长。但 8 位加法器行波进位的组合逻辑深度是 8 级，每级约 0.15ns，在 1GHz 目标频率下可能超时——这就是 RTLDistil 需要从版图蒸馏学到的"隐式物理知识"。

#### 任务二：功耗预测 -- 输入 RTL + 网表，输出 Toggle Rate / Total Power

同一个加法器：

```
【输入】
  ① RTL 文本（同上）
  ② 门级网表（Synopsys DC compile_ultra 综合后）
     - 8 个 1-bit Full Adder 模块
     - 共 40 个标准单元（AND2X1 × 8, XOR2X1 × 16, OR2X1 × 8, INVX1 × 8）
     - 连线数：56 条

【MOSS 推理过程】
  RTL 文本 → LLM 编码器 → [功能意图特征]  "这是一个 8 位加法器，每个周期翻转一次"
                                          │
  门级网表 → GNN 编码器  → [结构实现特征]  "40 个门，8 级进位链，负载电容总计 0.8pF"
                                          │
                            ┌─────────────┘
                            ▼
              特征拼接 + 融合层（跨模态交互）
                            │
                            ▼
                    功耗回归头

【输出】
  Toggle Rate = 0.45     — 平均 45% 的信号节点在每个周期翻转
  Total Power = 3.2 mW   — 1GHz 下这个加法器预计消耗 3.2mW
```

**MOSS 为什么比单模态好**：RTL 的 `always @(posedge clk)` 告诉 MOSS "这个加法器每个周期都在用"（高活跃度），网表的 "8 级行波进位"告诉 MOSS "进位链长，中间信号翻转多"（高动态功耗）。只看 RTL 不知道用了多少门，只看网表不知道翻转多频繁——两者结合才能精确估计功耗。

### 4.3 RTLDistil：跨阶段知识蒸馏（时序预测 SOTA，Figure 2 论文架构）

RTLDistil 的核心思路是"训练时偷看版图，推理时只看 RTL"——这是 **Shift-Left 最关键的技术实现**。

```text
═══════════ 训练阶段（两个网络同时运行） ═══════════

  ┌──────────┐                          ┌──────────┐
  │ 版图图像  │                          │ RTL 代码  │
  │ (Layout) │                          │  (文本)   │
  │          │                          │          │
  │ 含走线   │                          │ 只有行为  │
  │ 延迟/寄生│                          │ 描述      │
  │ 电容     │                          │          │
  └────┬─────┘                          └────┬─────┘
       │                                     │
       ▼                                     ▼
  ┌─────────┐                          ┌─────────┐
  │ 老师网络  │                          │ 学生网络  │
  │ (Teacher)│        蒸馏损失           │ (Student)│
  │          │◄═════════════════════════│          │
  │ 知道真实  │   让学生模仿老师的行为    │ 只看 RTL  │
  │ 物理信息  │   KL(学生输出‖老师输出)  │ 学习"隐式  │
  │          │                          │ 物理知识" │
  └────┬─────┘                          └────┬─────┘
       │                                     │
       ▼                                     ▼
  真实时序标签                            预测时序
  (AT/WNS/TNS)                          (AT/WNS/TNS)
       │                                     │
       │    ┌──────────────────┐             │
       └───>│ 损失函数          │◄────────────┘
            │ Loss = MSE(学生,GT)│
            │  + KL(学生,老师)  │
            └──────────────────┘

═══════════ 推理阶段（只剩学生网络） ═══════════

  ┌──────────┐
  │ RTL 代码  │──→ [学生网络] ──→ AT / WNS / TNS 预测
  └──────────┘     (不需要版图！不需要老师网络！)
```

**为什么有 GT 还要蒸馏？** 损失函数 = MSE(学生, GT) + KL(学生, 老师)，学生同时在学 GT 和模仿老师。老师网络的价值在于：
- GT 是一个标量，只能给最后一层监督；而老师的**中间层特征**（如 CNN 编码的寄生参数空间分布）能为学生提供 multi-granularity 的逐层对齐信号
- 老师的输出是"软目标"——对不同 RTL 输入的预测之间存在**相对关系和变化趋势**，比离散的 GT 点信息量更大，有助于泛化

**推理时的实际输入**：只需 RTL 代码。学生网络在训练阶段已通过蒸馏将版图的物理延迟知识"内化"到自身参数中。这使 RTLDistil 成为全资料包中预测时机**最早**的模型——在阶段 ① 就能预测阶段 ⑬ 的签核级指标。

### 4.5 三层数据增强详解

#### 第一层：AST 语法树改写（RTL 级别，对应论文 Algorithm 2 & Figure 5(a)）

在已验证的 8,659 个真实 RTL 设计上做**局部、类型保持**的 AST 节点改写，而非 LLM 随机生成新代码。

**六类变异算子**：

| 变异类型 | 原始 | 变异 | 通俗解释 | 约束 |
|---------|------|------|---------|------|
| 算术替换 | `c = a + b` | `c = a - b` | 加法器变减法器，电路结构完全不同 | 类型保持（算术之间互换） |
| 逻辑替换 | `a & b` | `a \| b` | 按位与变按位或，等价于用了不同门 | 位宽匹配 |
| 关系反转 | `a > b` | `a < b` | 比较边界反转，控制流变化 | 同类型操作数 |
| 时钟沿切换 | `posedge clk` | `negedge clk` | 上升沿触发变下降沿（不同寄存器类型） | 仅时序块内 |
| 赋值方式 | `q <= d` | `q = d` | 非阻塞变阻塞（影响仿真行为） | always 块一致性（Algorithm 3） |
| 常量微调 | `8'd10` | `8'd11` | 阈值+1（探索相邻参数设计点） | 位宽保持、进制保持 |

**Algorithm 2 七步流程**：

```
Step 1: ast ← ParseVerilogToAST(R)       # PyVerilog 1.3.0 解析 RTL → AST 树
Step 2: node_paths ← BuildNodePaths(ast) # 为每个节点建 (parent, attr, index) 路径
Step 3-9: 遍历所有节点，IsMutable()? → GetMutationCandidates(node) → 收集候选变异
Step 10: selected ← RandomSample(mutations, N)  # 多策略采样（类型过滤+多样性+可行性）
Step 11-14: 逐条应用变异 + CheckConsistency()    # 位宽匹配/除零/赋值一致性检查
Step 15: R' ← ASTToVerilog(ast)                 # 语法树→代码（语法保证正确）
Step 16-18: if not PassesSynthesis(R'): 降级保守改写
Step 19: return R'
```

**三层过滤与 27% 接受率**：

```
AST 变异后的 RTL 变体
    │
    ├── 第一层：综合验证（Synopsys DC compile_ultra）
    │     综合失败 → 丢弃（组合环路/不可综合结构）
    │
    ├── 第二层：结构相似度（网表级图比较）
    │     与源设计相似度 ≥ 97% → 丢弃（"伪变异"，德摩根等价变换）
    │
    └── 第三层：训练价值评估（分任务）
          时序任务：关键路径太短 → 丢弃
          功耗任务：死逻辑比例高 → 丢弃
          通过 → 保留！
    ────────────────────────
    最终：约 27% 通过，73% 被丢弃
```

**为什么 AST 改写比 LLM 随机生成靠谱得多**：
- LLM 生成的代码有语法错误、不可综合结构（initial 块、组合环、意外 latch）
- AST 改写全程在语法树层面操作——变异结果**语法保证正确**
- 基于已验证的真实设计改写——综合通过率远高于随机生成

## 5. 关键公式

### 5.1 动态功耗公式

从论文 Equation (1) 提取，这是所有功耗预测任务的物理基础：

$$
P_{\text{dynamic}} = \alpha \cdot f \cdot C_{\text{eff}} \cdot V_{\text{DD}}^{2}
$$

- $P_{\text{dynamic}}$：动态功耗（W），芯片因信号翻转消耗的功率
- $\alpha$：Toggle Rate（切换活动因子），0~1 之间，论文默认 $\alpha = 0.2$
- $f$：时钟频率（Hz），论文目标频率 $f = 1 \text{ GHz}$
- $C_{\text{eff}}$：有效负载电容（F），从 post-route SPEF 寄生参数提取
- $V_{\text{DD}}$：电源电压（V），论文 $V_{\text{DD}} = 1.05 \text{ V}$

**工程直觉**：动态功耗 = 每秒钟充放电次数 $\times$ 每次充多少电 $\times$ 充到多高电压。$\alpha$ 和 $f$ 决定了"翻多快"，$C_{\text{eff}}$ 决定了"每次翻动用多少电"，$V_{\text{DD}}^{2}$ 是物理常数。RTL 阶段这三个量全不知道——$\alpha$ 取决于功能（触发器在加法器和移位寄存器里翻转频率完全不同），$C_{\text{eff}}$ 取决于版图（走线长度、门驱动强度）——这就是为什么需要多模态。

**为什么这么设计**：论文选了 vectorless（无向量）功耗分析——给所有输入默认 20% 翻转率，让工具自动传播翻转活动。这使功耗差异**完全由电路结构决定**（而非特定的测试向量），更适合学习结构->功耗的映射关系。

### 5.2 RTLDistil 知识蒸馏损失

从论文 Section 5.2 的模型描述和对 RTLDistil 原论文的引用中提取：

$$
\mathcal{L}_{\text{distil}} = \text{MSE}(\hat{y}_{\text{student}}, y_{\text{GT}}) + \lambda \cdot \text{KL}(p_{\text{student}} \parallel p_{\text{teacher}})
$$

- $\mathcal{L}_{\text{distil}}$：RTLDistil 的总损失函数
- $\text{MSE}(\cdot, \cdot)$：均方误差损失（Mean Squared Error），学生预测与真实时序标签的偏差
- $\hat{y}_{\text{student}}$：学生网络（仅看 RTL）的时序预测值
- $y_{\text{GT}}$：Ground Truth 时序标签（来自 post-route STA）
- $\text{KL}(\cdot \parallel \cdot)$：KL 散度（Kullback-Leibler divergence），度量学生输出分布与老师输出分布的差异
- $p_{\text{student}}$：学生网络的输出分布
- $p_{\text{teacher}}$：老师网络（观看版图）的输出分布
- $\lambda$：蒸馏损失权重，平衡监督损失和蒸馏损失

**工程直觉**：第一项 $\text{MSE}(\hat{y}, y_{\text{GT}})$ 是传统监督学习的"对答案"，第二项 $\text{KL}(p_s \parallel p_t)$ 是"模仿老师"。老师看过版图，知道物理延迟的特点，学生模仿老师的过程就是在"偷学物理知识"。

**两阶段训练**：老师网络先独立训练（版图图像 → 时序标签），冻结后再训练学生网络（RTL 文本 → 时序标签 + 蒸馏损失）。

### 5.3 AST 信号依赖回溯（对 Algorithm 2 的形式化）

给定 Verilog 模块的 AST，定义信号依赖图：

$$
G_{\text{AST}} = (V_{\text{sig}} \cup V_{\text{logic}}, E_{\text{dep}})
$$

- $V_{\text{sig}}$：所有 wire/reg/logic 信号节点
- $V_{\text{logic}}$：逻辑操作节点（assign、always、运算符等）
- $E_{\text{dep}}$：有向边 $(u, v)$，表示信号 $u$ 的赋值依赖信号/操作 $v$（即 $v$ 是 $u$ 的 RVALUE 的一部分）

对于任意信号节点 $s$，其 $L$ 阶依赖锥：

$$
\Gamma_L(s) = \bigcup_{\ell=1}^{L} \{ v \in V_{\text{sig}} \mid \text{dist}(v, s) \leq \ell, v \neq s \}
$$

- $\Gamma_L(s)$：信号 $s$ 在 $L$ 阶深度内的所有前驱信号集合
- $\text{dist}(v, s)$：$v$ 到 $s$ 在依赖图上的最短路径长度
- $L$：回溯深度（trace_level），控制追溯多少层依赖

**工程直觉**：AST-WT（AST-based Waveform Tracing）并非 CircuitNet 3.0 的核心机制——它来自 VerilogCoder 论文的调试工具。但在数据增强的 AST 变异流程中，同样的依赖图被用于 CheckConsistency()：检查变异节点是否会影响其所在 always 块的赋值一致性，确保变异后不产生阻塞/非阻塞混用。

### 5.4 评估指标公式

论文使用三个指标评估所有模型。以下公式为通用定义（论文未显式给出公式，但定义了使用方式）：

**PCC（Pearson Correlation Coefficient，皮尔逊相关系数）**：

$$
\text{PCC} = \frac{\sum_{i=1}^{n}(y_i - \bar{y})(\hat{y}_i - \bar{\hat{y}})}{\sqrt{\sum_{i=1}^{n}(y_i - \bar{y})^2} \cdot \sqrt{\sum_{i=1}^{n}(\hat{y}_i - \bar{\hat{y}})^2}}
$$

- $y_i$：第 $i$ 个样本的真实值
- $\hat{y}_i$：第 $i$ 个样本的预测值
- $\bar{y}$：真实值的均值
- $\bar{\hat{y}}$：预测值的均值
- 范围 $[-1, 1]$，越接近 1 说明预测趋势与真实值越线性相关

**MAPE（Mean Absolute Percentage Error，平均绝对百分比误差）**：

$$
\text{MAPE} = \frac{100\%}{n} \sum_{i=1}^{n} \left| \frac{y_i - \hat{y}_i}{y_i} \right|
$$

- $n$：样本数
- 分母是真实值 $y_i$，当 $y_i \to 0$ 时 MAPE 会**爆炸**——这是 WNS 的 MAPE（35~65%）远高于 Total Power MAPE（7~15%）的根本原因。WNS 值常在 -1ns 到 0 之间，真实值接近 0 时分母极小，绝对误差被放大为大百分比。

**R-squared（决定系数）**：

$$
R^{2} = 1 - \frac{\sum_{i=1}^{n}(y_i - \hat{y}_i)^2}{\sum_{i=1}^{n}(y_i - \bar{y})^2}
$$

- $R^{2}$：模型解释的方差比例，越接近 1 越好
- $R^{2} < 0$ 说明模型表现比"直接猜均值"还差——论文中 MasterRTL 在 Resyn-27k 上的 TNS $R^{2} = -0.384$ 就是这种情况

**三个指标必须一起看**：PCC 高但 MAPE 也高说明有系统偏差（趋势对了但有整体偏移），PCC 和 MAPE 都高才是好模型。论文 RTLDistil 的 AT PCC=0.935 + MAPE=28.96% 说明趋势几乎完美但绝对值有约 29% 误差——这在 EDA 早期预测中已属顶尖水平。

### 5.5 数据增强接受率定义

从论文 Appendix F.7 Table 19 中提取：

$$
\text{AcceptRate} = \frac{\#\{\text{variants that pass synthesis} \cap \text{structural similarity} < 97\% \cap \text{training-valuable}\}}{\#\text{total AST-mutated variants}} \approx 27\%
$$

即约 73% 的 AST 变异产物被三层过滤丢弃，这一严格的筛选确保了增强数据的质量而非数量。

**这张表说明什么**：RTLDistil 在三个指标上全面超越纯 RTL 基线。AT 的 MAPE 从 43% 降到 20%——多模态蒸馏让模型从"瞎猜"提升到"比较靠谱"。TNS 的 PCC 达到 0.918，说明模型在捕获累积时序违例方面尤其出色。

**功耗预测——多模态 vs 单模态（论文 Table 4(b)）**：

| 指标 | DeepSeq2 (仅网表) | MOSS 消融 (仅网表) | **MOSS Full** | vs DeepSeq2 提升 |
|------|:---:|:---:|:---:|:---:|
| Toggle Rate PCC | 0.759 | 0.674 | **0.871** | +14.8% |
| Toggle Rate MAPE | 29.5% | 34.7% | **14.4%** | 误差-51.2% |
| Total Power PCC | 0.872 | 0.815 | **0.948** | +8.7% |
| Total Power MAPE | 22.2% | 27.7% | **7.4%** | 误差-66.7% |

**这张表说明什么**：MOSS Full 平均误差只有 7.4%——在芯片功耗预测中这是极强结果。消融版去掉 RTL 后 MAPE 从 7.4% 跳到 27.7%（差 3.7 倍），证明"RTL 功能意图 + 网表门结构"缺一不可。DeepSeq2 只看网表（22.2% MAPE）都不如 MOSS Full，说明 RTL 的语义信息对功耗预测至关重要。

**数据增强效果——RTLDistil 在三个数据集上的表现（论文 Table 5）**：

| 数据集 | AT PCC | AT MAPE | WNS PCC | WNS MAPE | TNS PCC | TNS MAPE |
|------|:---:|:---:|:---:|:---:|:---:|:---:|
| Resyn-27k (旧) | 0.842 | 40.73% | 0.676 | 73.45% | 0.705 | 48.32% |
| 原始数据 | 0.887 | 35.28% | 0.756 | 65.12% | 0.785 | 43.25% |
| **增强数据** | **0.935** | **28.96%** | **0.926** | **58.65%** | **0.968** | **35.42%** |

**这张表说明什么**：所有模型在三个数据集上单调提升（Resyn-27k < 原始 < 增强）——数据增强对所有模型都有普适正面效果。RTLDistil 在增强数据上 TNS PCC 达到 0.968（$R^{2}=0.927$），模型解释了 92.7% 的时序方差。

**跨数据集功耗预测——VIRTUAL 和 GRASPE（论文 Table 6）**：

| 模型 | Resyn-27k MAPE | 原始数据 MAPE | **增强数据 MAPE** | vs Resyn-27k 提升 |
|------|:---:|:---:|:---:|:---:|
| GRASPE | 30.41% | 28.45% | **26.55%** | -12.7% |
| VIRTUAL | 27.48% | 26.85% | **23.92%** | -12.9% |
| MasterRTL | 32.67% | 30.28% | **27.16%** | -16.9% |

## 7. 创新点

### 创新点 1：全流程可追溯的多模态开源数据集

**已有方法的状态**：CircuitNet 2.0 有 10,791 个版图但只有 8 个 RTL；RTLCoder 有 2.6 万个 RTL 但无网表/版图/性能标签；VerilogEval / RTLLM 只有 RTL 文本且无综合验证；ForgeEDA 有多模态但不开源且无版图阶段；EDALearn 有完整流程但只有几个设计。

**CircuitNet 3.0 的做法**：从互联网收集 100,000+ 行 RTL，经五步严格验证（语法/综合/仿真/Lint/复杂度）保留 8,659 个原始设计（8.7%），每个设计都走完完整 EDA 流程（Synopsys DC 综合 -> Cadence Innovus 物理实现 -> PrimePower 功耗签核），生成 15,863 个设计实例——每个实例同时具备 RTL 代码 + 门级网表 + 物理版图 + 签核级标签。

**为什么这很难做**：商业 EDA 工具 License 昂贵；每个设计需迭代 10-50 次到收敛；整个过程耗时约 8 个月；91.3% 的原始收集被严格丢弃。

### 创新点 2：基于 AST 语法树的数据增强框架

**已有方法的状态**：LLM 随机生成 RTL（RTLCoder）——语法错误多、综合通过率低、电路不现实。文本级正则替换——语法无保证、容易误伤注释/信号名、多行格式难以匹配。

**CircuitNet 3.0 的做法**：把编译器前端的完整技术栈引入数据增强——PyVerilog 解析 RTL 为 AST -> 对六类运算节点做类型保持的局部改写 -> CheckConsistency 做语义一致性校验（位宽/除零/赋值一致性 Algorithm 3） -> AST 转回 Verilog（语法保证正确） -> Synopsys DC 综合验证。

**三层过滤确保质量**：综合失败（丢弃） -> 结构相似度 >= 97% 的"伪变异"（丢弃） -> 训练价值低（丢弃） -> 最终约 27% 通过，73% 被丢弃。这不是浪费——恰恰证明了筛选严格。

**Algorithm 3（多数投票法）的价值**：AST 变异可能引入阻塞/非阻塞赋值混用（Verilog 中的大忌——仿真与综合行为不一致），Algorithm 3 通过统计 always 块内两种赋值的数量，以多数类型统一全部赋值，从根源上消除混用问题。

### 创新点 3：任务导向的"面向难案例"数据增强

**已有方法的状态**：传统数据集的过滤是"排除不能跑通的"，保留的都是"能正常工作的设计"——WNS > 0（时序安全）、功耗低、密度适中。

**CircuitNet 3.0 的做法**：反其道而行——**故意筛选难的**。

- 时序任务：优先保留 WNS 为负、路径长的设计。丢弃时序极其宽松的电路。训练数据 WNS 范围从 [-2.5, 0] 扩展到 [-6, 0] ns。
- 功耗任务：同一 RTL 用不同综合配置生成多个网表变体，用 Voltus 做无向量功耗分析，丢弃死逻辑比例高的设计。功耗范围从集中在 <60mW 扩展到均匀覆盖 0~160mW。

**为什么这是正确思路**：工业场景中预测模型的价值由**极限案例**上的准确率决定。如果训练数据里全是"轻松达标"的设计，模型遇到真正有时序风险的电路就会预测失败。CircuitNet 3.0 故意往训练集塞"重症患者"，让模型学会"什么样的 RTL 结构会导致时序/功耗问题"。

### 创新点 4：严格防泄漏的数据划分策略

**已有方法的常见问题**：随机打散分成 train/test（同一设计的变体可能出现在两边）；不验证测试集和训练集之间是否有结构相同的设计。

**CircuitNet 3.0 的做法**：
- 按源设计 ID 级别划分（不是按实例）
- 测试集 **100% 是原始未增强设计**
- 如果一个源设计分到测试集，它的所有 AST 变体**完全排除**在训练和验证之外
- 额外引入外部开源项目子模块作为测试补充
- 网表级图比较验证无结构相同设计泄露

### 创新点 5：以多模态 SOTA 模型证明数据价值

**核心 insight**：好的数据集需要通过好的模型来"兑现"其价值。

- **RTLDistil** 证明了"RTL->版图跨阶段蒸馏"是 Shift-Left 的关键技术——训练时老师网络看版图学物理延迟，学生网络通过 KL 散度蒸馏学会隐式物理知识，推理时只需 RTL 输入。这是全资料包中预测时机最早的方案。

- **MOSS** 证明了功耗预测需要"功能意图（RTL）+ 结构实现（网表）"双模态——消融实验：去掉 RTL 后 Toggle Rate MAPE 从 14.4% 跳到 34.7%，Total Power MAPE 从 7.4% 跳到 27.7%。

## 9. 与芯片流程的关系

### 9.1 在全流程中的位置

```text
  人写 RTL (阶段 ①)
              │
              ▼
  ┌───────────────────────────────────────────────┐
  │  CircuitNet 3.0 的多模态 AI 模型               │
  │                                               │
  │  RTL 文本 ──→ LLM 编码器 ──→ 语义特征          │
  │                          ↘                    │
  │                           多模态融合 ──→ 预测   │
  │                          ↗                    │
  │  网表(图) ──→ GNN 编码器 ──→ 结构特征          │
  │                                               │
  │  版图(图像) ──→ CNN 编码器(仅训练期蒸馏用)     │
  │                                               │
  │  ↓ 预测输出：                                  │
  │  时序: AT / WNS / TNS  ← 相当于跳过了 ③→⑤→⑩→⑬ │
  │  功耗: Toggle Rate / Total Power ← 同上        │
  └────────────────┬──────────────────────────────┘
                   │
                   ▼
  如果预测结果不满足指标 → 回到 ① 修改 RTL（Shift-Left）
  如果预测结果满足指标 → 继续标准流程：
         ③ 逻辑综合 → ④ 门级仿真 → ⑤ STA → ⑦ Floorplan
      → ⑧ Placement → ⑨ CTS → ⑩ Routing → ⑪ 后仿真
      → ⑫ DRC+LVS → ⑬ 签核 → ⑭ 流片 → ... → ⑰ 芯片
```

CircuitNet 3.0 的 AI 模型**不替代**标准 EDA 流程中的任何一步——它是在 RTL 阶段插入一个**快速代理预测器**。预测结果指导设计者"现在修改 RTL"还是"继续往下走"。如果预测显示 WNS 严重为负，设计者可以在 RTL 阶段就重新架构数据通路、插入流水线寄存器——避免画完版图才发现跑不到目标频率的灾难性返工。

### 9.2 "早期预测准确"和"签核级精确"之间隔着什么

**RTLDistil 在推理时不需要版图，这既是最大优点也是最大局限**：

| 维度 | RTLDistil 预测 | 真实签核 STA | 差距来源 |
|------|:---:|:---:|------|
| 门延迟 | 隐式学习（蒸馏自老师看过的版图样本） | 真实标准单元库延迟表 | 训练数据中见过的设计类型 vs 未见过的 |
| 连线延迟 | 隐式学习（蒸馏自 CNN 老师的版图特征） | 真实 post-route SPEF 寄生 RC | 蒸馏是近似，不可能完美复现 |
| 工艺角 | TT（数据只有一种 corner） | SS/TT/FF x 温度 x 电压 | 未见 corners 的泛化能力未验证 |
| AT MAPE | 28.96% | 0%（签核基准） | 约 29% 的平均相对误差——对早期筛选足够，但不足以取代签核 |
| WNS MAPE | 58.65% | 0% | 在 WNS 接近 0 的区域误差大（分母小） |

**结论**：RTLDistil 的定位是**早期设计空间探索**——它告诉设计者"这个 RTL 架构大概率会有什么时序特征"，而非"这个设计的签核 WNS 精确值是多少"。在真实的工业流程中，RTLDistil 的预测结果可以帮助筛选候选架构、识别风险设计，但最终签核仍需跑完整后端流程。

## 10. 讨论与局限

### 10.1 论文自述的局限

1. **仅 45nm 工艺节点**：数据集基于 GSCLIB 45nm PDK。虽然脚本工艺无关（可替换 PDK 重跑），但 7nm/5nm 等先进节点受 NDA 限制，无法公开版图数据。

2. **没有面积预测**：论文只预测时序（AT/WNS/TNS）和功耗（Toggle Rate/Total Power），未覆盖 PPA 中的 A（Area）。完整的 PPA 三目标预测是未来方向。

3. **WNS MAPE 偏高**：WNS 的 MAPE 在 35~65% 范围内，这是因为 WNS 真实值常在 -1ns 到 0ns 之间，MAPE 的分母小容易放大误差。需要用 PCC（0.871~0.926）等指标共同评估。

4. **商业工具依赖**：数据生成依赖 Synopsys DC + Cadence Innovus + PrimePower，个人研究者难以完全复现。

5. **构建成本极高**：从 100,000+ 行 RTL 中只保留 8.7%，73% 增强变体被丢弃，整个构建耗时约 8 个月。

6. **仅单工艺角（TT）**：所有数据基于 TT corner，未覆盖 SS/FF 等极端工艺角。

### 10.2 代码/复现层面的问题

1. **数据集依赖商业 EDA 工具**：CircuitNet 3.0 的数据不是"下载即可用"——是已生成好的数据集。想重新生成数据需要 Synopsys DC 2020.09 + Cadence Innovus 19.11 等商业工具 License。

2. **复现完整实验需大量算力**：8x A100 (80GB) GPU，RTLDistil 和 MOSS 各需从头训练。

3. **AST 变异脚本未开源**：论文提供了数据集下载，提供了使用示例代码。AST 变异和 EDA 工具链脚本需要 EDA 工具 License 才能运行。

4. **部分模型是引用模型**：RTLDistil (ICML 2025)、MOSS (DAC 2025)、MasterRTL (ICCAD 2023) 等模型的完整代码在其各自的代码仓库中，CircuitNet 3.0 仓库提供的是在这个数据集上使用这些模型的实验配置。

### 10.3 批判性分析

**方法的前提假设**：
- RTL 到物理实现的映射是可学习的（基于足够多样化的训练数据）
- 蒸馏（RTLDistil）能充分传递版图的物理延迟信息到 RTL 编码器
- 向量无关功耗分析（Toggle Rate = 0.2）产生的标签能代表真实功耗的相对排序

**评测的公平性**：
- 模型比较中，Resyn-27k 是没有物理标签的纯 RTL 数据集——用 CircuitNet 3.0 训练的模型天然有优势（因为有 GT 标签可用）。论文的"增强数据 > 原始数据 > Resyn-27k"的结论需要区分是"数据更多"还是"标签存在"的作用
- VIRTUAL（纯 RTL 功耗预测最强基线）在增强数据上 MAPE 23.92%，MOSS Full（需要 RTL+网表）MAPE 7.4%——但 MOSS 的推理需要网表（综合后才能获得），比 VIRTUAL 的预测时机晚（需要经过阶段 ③）

**可扩展性天花板**：
- 数据集均为模块级设计（<100K 门），最大的也只相当于 SoC 的一个小 IP 块。扩展到百万门级、多时钟域的真实 SoC 设计的路径不清晰
- 45nm 的物理行为（寄生 RC、门延迟、功耗）与先进节点（3nm/5nm）有本质差异——线延迟占主导、FinFET 漏电特性、布线拥塞特性都不同
- 单工艺角（TT）是个重要限制——真实签核需要在 20+ 个 PVT corner 下同时满足，单一 corner 训练的模型能否泛化到其他 corner 完全未知

**与同生态位工作的对比**：
- [CircuitNet 1.0/2.0](../CircuitNet/) 面向后端物理设计（拥塞/DRC/IR Drop 预测），3.0 转向前端->后端跨阶段预测
- [RTLCoder](../RTL-Coder/) 用 LLM 生成 RTL 训练数据（数量多但无综合/物理验证），3.0 用 AST 改写真实设计（质量高但数量较少）
- [DeepGate2](../DeepGate2/) 做门级网表的表示学习，3.0 的网表编码可以与之互补——DeepGate2 预训练的 GNN 编码器可作为 MOSS 的网表编码器基础

## 12. 一分钟复述版

CircuitNet 3.0（ICLR 2026）是全球首个大规模、全流程、多模态的芯片设计开源数据集——8,659 个原始 RTL 经 AST 语法树增强生成 15,863 个设计实例，每个都含 RTL（文本）+ 网表（图）+ 版图（图像）+ 签核级时序/功耗标签。

三大核心创新：

1. **AST 语法树改写增强**：不是 LLM 随机生成，而是用 PyVerilog 把已验证的真实 RTL 解析为语法树，对算术/逻辑/关系/时序/赋值/常量六类运算节点做类型保持的局部改写。73% 被三层过滤丢弃，27% 保留——比随机生成靠谱得多。

2. **任务导向的"面向难案例"策略**：时序任务故意保留路径长、WNS 为负的硬骨头；功耗任务用不同综合配置生成多变体 + Voltus 无向量分析筛掉死逻辑。最终 WNS 范围从 [-2.5,0] 扩展到 [-6,0] ns，功耗覆盖 0~160mW——模型在工业边界场景更可靠。

3. **多模态 SOTA 验证**：RTLDistil（ICML 2025）用版图蒸馏让 RTL 级模型偷学物理延迟——推理时只需 RTL，WNS MAPE 从 65% 降到 29%。MOSS（DAC 2025）LLM+GNN 双路融合——功耗 MAPE 仅 7.4%，消融证明 RTL 功能意图和网表门结构缺一不可。

左移（Shift-Left）的本质：在阶段 ① RTL 设计阶段就能预测阶段 ⑬ 签核级的时序和功耗——不用跑整个后端流程就能知道"这个架构行不行"。和 [CircuitNet 1.0/2.0](../CircuitNet/)（后端物理设计任务）形成互补，构成了从 RTL 到签核的完整 AI4EDA 数据基础设施。
