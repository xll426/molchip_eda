## 1. 一句话定位

提出 **Synthesis-in-the-Loop** 评测框架与 **Hardware Quality Index (HQI)** 指标，将 32 个 LLM 在 202 个 Verilog 任务上跑出 **"语法 → 综合 → 仿真"** 三道闸门，最终用综合后面积、关键路径延迟、警告数相对于专家 golden reference 在 Nangate45 45nm 工艺下的归一化得分 (0–100) 取代传统 pass/fail 评估，并据此划分出 **Tier 1 / Tier 2 / Tier 3** 三档能力梯队，揭示仿真通过率可比 HQI 平均高出 7.5 点、最多 15 点的"评测盲区"。

## 3. 输入/输出

### 3.1 输入

**任务来源（输入数据集）**：

| 来源 | 任务数 | 特点 | Prompt 形式 |
|---|---|---|---|
| VerilogEval | 155 | 单模块、固定 top-level 接口 | `module-completion` 风格 prompt（原样 verbatim） |
| RTLLM | 47 | 真实 RTL，含 barrel shifter、clock divider、FSM、多级流水线等多模块设计 | 自然语言规格 (natural-language spec) |
| **合计** | **202** | 复杂度权重 C_t ∈ [1, 24]，由 golden reference 的 AST 依赖边数线性归一化得到 | 全部 single-turn, zero-shot |

**模型输入（被评测的 32 个 LLM）**：

- 选取策略三维度：
  - **Usage-driven (高频使用模型)**：DeepSeek-V3.2、Kimi-K2.5、MiniMax-M2.5、Gemini-2.0-Flash 等（按 OpenRouter token 消耗排名）
  - **Longitudinal (代际演化)**：OpenAI 全部非弃用模型 GPT-4o → GPT-5 全家
  - **Frontier (旗舰/开源代表)**：Anthropic Claude 全家、Google Gemini 2.5-Pro → Gemini-3-Pro，以及 Qwen3.5-397B-OSS、LLaMA-4-Maverick、Mistral-Nemo、Doubao-Seed16
- 统一通过 **OpenRouter** API 访问，保留 provider 默认超参，**不**做 per-model tuning
- 全部 API 调用时间：2026 年 2–3 月

**每次"模型 × 任务"输入**：K = 5 次独立生成（single-turn, zero-shot）

**综合工具链输入**：
- 语法：Icarus Verilog
- 综合：Yosys + Nangate45 45 nm Open Cell Library
- 仿真：testbench（取自 VerilogEval / RTLLM 原仓库）
- 跨工艺验证：IHP SG13G2 (130 nm) & OSU 0.35 μm

### 3.2 输出

**Per-attempt 决策**：

```
对于每个 (model, task, attempt_k)：
  pass_string 必须显式出现 且 之前无 fail 信号       → 仿真被判为 PASS
  else                                            → 仿真 FAIL
  若 Icarus 解析失败                              → 语法失败（不进 Yosys）
  若 Icarus 通过、Yosys 综合失败                  → 综合失败（9 类 taxonomy）
  若 Icarus + Yosys + 仿真均通过                  → 进入 HQI 计算
```

**Per-attempt HQI 输出**（task t，attempt k）：

| 情况 | HQI 值 |
|---|---|
| 任何 gate 失败 | 0 |
| 任务无 golden reference（26/202） | NaN（不参与质量聚合，但计入 Coverage） |
| 三道闸门全过 | 由 cost 公式计算 |

**聚合输出（每模型）**：

| 指标 | 公式含义 |
|---|---|
| Coverage(m) | 复杂度加权任务通过率（best-of-5，至少 1/5 成功即可） |
| Global HQI(m) | 复杂度加权 best-of-5 能力上限（取 max over 5 attempts） |
| Expected HQI(m) | 复杂度加权单次期望质量（mean over 5 attempts） |
| Gap = Global HQI − Expected HQI | 部署就绪度差距 |

**最终输出三类可视化**：

1. 图 1：**Coverage–Global HQI 二维散点 + Tier 1 缩放插图**，圆形=proprietary、方形=open-weight
2. 图 2：**Best-of-5 pass rate vs Pass Rate=HQI 的散点**，点偏离对角线揭示仿真过估
3. 图 3 / 图 4：**8 个硬件类别 × 32 个模型的双热力图**（best-of-5 + per-attempt）

**示例输出（节选自 Table 1）**：

| 模型 | Coverage | Global HQI | Expected HQI | Tier |
|---|---|---|---|---|
| Gemini-3-Pro | 87.5% | 85.1 | 78.5 | Tier 1 |
| GPT-5.4-Pro | 84.5% | 81.3 | 77.5 | Tier 1 |

## 4. 方法与架构

### 4.1 整体 Pipeline

```
                   ┌─────────────────────────────────────────────────┐
                   │            OpenRouter Unified API               │
                   │  (32 models × 5 attempts × 202 tasks = 32,320)  │
                   └─────────────────────┬───────────────────────────┘
                                         │  zero-shot prompt
                                         ▼
   ┌─────────────────────────────────────────────────────────────┐
   │                  Generated Verilog (k=1..5)                  │
   └─────────────────────┬───────────────────────────────────────┘
                         │
                         ▼
   ┌─────────────────────────────────────────────────────────────┐
   │  Gate 1:  Syntax validity (Icarus Verilog parser)            │
   │           fail → SYNTAX FAIL (excluded)                      │
   └─────────────────────┬───────────────────────────────────────┘
                         │  pass
                         ▼
   ┌─────────────────────────────────────────────────────────────┐
   │  Gate 2:  Synthesizability (Yosys + Nangate45 45 nm)         │
   │           fail → 9-class taxonomy tagging                    │
   │           pass → ok                                          │
   └─────────────────────┬───────────────────────────────────────┘
                         │  pass
                         ▼
   ┌─────────────────────────────────────────────────────────────┐
   │  Gate 3:  Functional correctness (testbench simulation)      │
   │           fail-first matching: must explicitly print "pass"  │
   │           with no preceding failure signal                   │
   └─────────────────────┬───────────────────────────────────────┘
                         │  pass
                         ▼
   ┌─────────────────────────────────────────────────────────────┐
   │  HQI Computation:  area / delay / warning vs golden_ref      │
   │      a_t*, d_t*, w_t* pre-computed via same flow             │
   │      cost = 0.5*(a/a_t*) + 0.5*(d/d_t*) + 0.1*max(0, w-w_t*)│
   │      HQI = min(100/cost, 100)                                │
   └─────────────────────┬───────────────────────────────────────┘
                         │
                         ▼
   ┌─────────────────────────────────────────────────────────────┐
   │  Per-task inference metadata (OpenRouter):                   │
   │      API cost, reasoning token ratio, throughput, TTFT,      │
   │      total completion tokens                                 │
   └─────────────────────┬───────────────────────────────────────┘
                         │
                         ▼
   ┌─────────────────────────────────────────────────────────────┐
   │  Cross-library validation:                                   │
   │  All passing designs re-synth under IHP SG13G2 (130 nm)       │
   │  and OSU 0.35 μm to confirm ranking transfers (Spearman >0.99)│
   └─────────────────────────────────────────────────────────────┘
```

### 4.2 评测 Pipeline 关键设计

**fail-first matching**（防假阳性）：仿真必须在前面没有 "fail" 信号的前提下显式出现 "pass" 字符串，纯防止 `pass` 仅在末尾出现但 std-output 早期已经 fail 的情况。

**Top-module resolution**（防 eval 误差）：RTLLM 任务在 golden reference 中嵌入 target module 之前会有 helper submodule 定义。Pipeline 会先 strip 注释，再用任务派生的 module name 匹配；若失败则 fall back 到第一个 syntax 上的 `module` 关键字。**不能**直接用第一个 module 关键字，否则会把"evaluator 错误"误标为"模型失败"。

**Complexity weights C_t**：

```
对每个任务的 golden reference：
  e_min = min(dep_edges_ast)   over all 202 tasks
  e_max = max(dep_edges_ast)   over all 202 tasks
  e_t   = AST dependency edge count of task t's golden reference
```

然后线性归一化到 [1, 24]：

C_t 值越大，说明该任务的多模块依赖结构越复杂。

### 4.3 HQI 与聚合指标

**Per-attempt HQI**：

任务 t 三个 gate 全过后得到 a_hat, d_hat, w_hat；golden reference 在同一 flow 下得到 a_t*, d_t*, w_t*。

**Normalized cost**：

cost = 0.5*a_hat/a_t* + 0.5*d_hat/d_t* + 0.1*max(0, w_hat - w_t*)

若 cost < 1 说明硬件整体优于 golden；若 cost > 1 则劣于。

**HQI**：

HQI = min(100/cost, 100)

100 = 与 golden 完全持平；超过 100 截断为 100（防止单 metric 优势放大整体得分）。**经验上没有任何模型 Global HQI 超过 85.1**，所以截断在实践中不压缩排名。

**为什么 area/delay 各 0.5、warning 0.1？**

- 等权 area 与 delay：标准 QoR 实践
- 较小 warning 系数：警告是"软信号"（soft signal），仅在 *超过* golden 警告数时扣分 (max(0, w_hat - w_t*))
- 论文做了 10 种权重扰动（area-only、delay-only、3× warning），**Spearman ρ ≥ 0.985，rank 位移 ≤ 3**

**聚合到模型维度**：

- T_m^+ = 模型 m 至少 1/5 次尝试成功的任务集合
- T^doubleDagger = 拥有有效 golden 综合 reference 的任务集合（|T^doubleDagger| = 176）

三个聚合指标：

Coverage(m) = Σ_{t∈T_m^+} C_t  /  Σ_{t∈T} C_t  × 100%

Global HQI(m) = Σ_{t∈T^doubleDagger} C_t * max_k HQI_{m,t,k}  /  Σ_{t∈T^doubleDagger} C_t

Expected HQI(m) = Σ_{t∈T^doubleDagger} C_t * mean_k HQI_{m,t,k}  /  Σ_{t∈T^doubleDagger} C_t

### 4.4 三 Tier 划分

对 32 模型的 Global HQI 做 k-means (k=3, silhouette=0.59)，k-means 在 rank 14 / rank 15 之间找到 3.7 点的天然 gap，rank 29 / rank 30 之间找到 7.0 点的 gap：

| Tier | 范围 (Global HQI) | 模型数 | 代表 |
|---|---|---|---|
| Tier 1 | ≥ 66 | 14 | Gemini-3-Pro (87.5%, 85.1), GPT-5.4-Pro, Claude-4.6-Opus, all 5 Claude variants, 7 GPT-4o→GPT-5.4 OpenAI, 2 Google |
| Tier 2 | 43–66 | 15 | Gemini-2.5-Pro (64.3), DeepSeek-V3.2 (58.8), Qwen3.5-397B (58.2), GPT-5 base (50.5) |
| Tier 3 | < 43 | 3 | Gemini-2.0-Flash (39.6), GPT-5-Nano (35.0), Mistral-Nemo (18.1) |

最强与最弱模型间 Global HQI 跨度达 **4.7 倍**。

## 5. 关键公式

### 5.1 复杂度权重 C_t

$$
C_t = 1 + 23 \cdot \frac{dep\_edges_{ast}(D_t) - e_{min}}{e_{max} - e_{min}}
$$

- `C_t`: 任务 t 的复杂度权重（取值 [1, 24]）
- `dep_edges_ast(D_t)`: 任务 t 的 golden reference Verilog 代码的 AST 依赖边数
- `e_min`: 全部 202 个任务中 dep_edges_ast 的最小值
- `e_max`: 全部 202 个任务中 dep_edges_ast 的最大值
- `D_t`: 任务 t 的 golden reference 设计
- 公式将 AST 依赖边数线性归一化到 [0,1] 后平移到 [1, 24]

### 5.2 归一化综合成本

$$
cost = 0.5 \cdot \frac{\hat{a}}{a_t^*} + 0.5 \cdot \frac{\hat{d}}{d_t^*} + 0.1 \cdot \max(0, \hat{w} - w_t^*)
$$

- `cost`: 归一化综合成本（cost < 1 优于 golden，cost > 1 劣于）
- `a_hat`: 模型生成设计在 Nangate45 下的综合后面积
- `a_t^*`: 任务 t 的 golden reference 在同一 flow 下的综合后面积
- `d_hat`: 模型生成设计的关键路径延迟
- `d_t^*`: 任务 t 的 golden reference 的关键路径延迟
- `w_hat`: 模型生成设计的综合警告数
- `w_t^*`: 任务 t 的 golden reference 的综合警告数
- `max(0, ·)`: 单边惩罚——超过 golden 的警告才扣分，低于不奖
- `0.5 / 0.5 / 0.1`: area、delay、warning 的三档权重；等权 area 与 delay 反映标准 QoR 实践

### 5.3 单 attempt HQI

$$
HQI = \min\!\left(\frac{100}{cost},\, 100\right)
$$

- `HQI`: 单 attempt、单个任务的硬件质量指数
- `100 / cost`: 倒置放大（cost=1 → 100, cost=2 → 50, cost=0.5 → 200 再被截断）
- `min(·, 100)`: 防止单 metric 优势放大整体得分（数据集上无模型 Global HQI > 85.1，故截断在实践中不压缩排名）
- HQI = 0 表示 3 道 gate 任意一道失败

### 5.4 复杂度加权 Coverage

$$
Coverage(m) = \frac{\sum_{t \in T_m^+} C_t}{\sum_{t \in \mathcal{T}} C_t} \times 100\%
$$

- `Coverage(m)`: 模型 m 至少 1/5 次尝试通过三道闸门任务的总复杂度权重 / 全部任务总复杂度权重
- `T_m^+`: 模型 m 通过至少 1 个 attempt 的任务集合
- `T`: 全部 202 个任务（含 26 个无 golden reference 的）
- `C_t`: 任务 t 的复杂度权重
- 比例值再乘 100% 得到百分比形式

### 5.5 复杂度加权 Global HQI（best-of-5 能力上限）

$$
GlobalHQI(m) = \frac{\sum_{t \in T^{\ddagger}} C_t \cdot \max_{k} HQI_{m,t,k}}{\sum_{t \in T^{\ddagger}} C_t}
$$

- `GlobalHQI(m)`: 模型 m 在 176 个有 golden reference 任务上的 best-of-5 能力上限
- `T^{\ddagger}`: 拥有有效 golden 综合 reference 的任务集合（|T^{\ddagger}| = 176）
- `HQI_{m,t,k}`: 模型 m 在任务 t 的第 k 次 attempt（k = 1..5）的 HQI
- `max_k`: 取 5 次尝试中最佳一次——这衡量的是"模型能给出什么"的 *能力上限*
- 分子分母均以 C_t 加权

### 5.6 复杂度加权 Expected HQI（单 attempt 期望质量）

$$
ExpHQI(m) = \frac{\sum_{t \in T^{\ddagger}} C_t \cdot \overline{HQI}_{m,t}}{\sum_{t \in T^{\ddagger}} C_t}
$$

- `ExpHQI(m)`: 模型 m 在 176 个任务上单次调用的期望质量
- `\overline{HQI}_{m,t}`: 任务 t 上 5 次 attempt HQI 的算术平均
- 这衡量的是"一次调用大概得到什么"的 *部署质量*
- 论文中常省略顶部横线，用 mean over k 表示

### 5.7 部署就绪度 Gap

$$
Gap(m) = GlobalHQI(m) - ExpHQI(m)
$$

- `Gap(m)`: 模型 m 的能力上限与单次期望质量之差
- Gap 越大说明模型"碰运气才能发挥实力"，agentic pipeline 的 first-attempt 模式越吃亏
- 论文实测：Tier 1 范围内 Gap ∈ [3.7, 17.8]（中位数 8.7），最强 Gemini-3-Pro Gap = 6.6
- Tier 2/3 较大 Gap 超过 15 点，最大 Gap = 22.1

### 5.8 Best-of-5 Pass Rate 与 HQI 的差

$$
\Delta_{sim}(m) = PassRate_{5}(m) - GlobalHQI(m)
$$

- `Δ_sim(m)`: 仿真通过率对硬件就绪度的"过估量"
- `PassRate_5(m)`: 至少 1/5 次 attempt 通过 testbench 仿真的任务占比
- 论文实测：32 模型平均 Δ_sim = 7.5 点，最大 13.9 (GPT-4.1)、14.9 (Gemini-2.0-Flash)
- 含义：仿真通过 ≠ 硬件可达成

### 5.9 跨工艺排名稳定性

$$
\rho_{tech} = Spearman(\text{rank}_{Nangate45},\ \text{rank}_{IHP\ SG13G2\ or\ OSU\ 0.35\mu m})
$$

- `ρ_tech`: 跨工艺库（technology library）的模型排名 Spearman 秩相关系数
- 实测：3 个工艺库下 Spearman ρ > 0.99
- 含义：Nangate45 排名基本可迁移到 IHP SG13G2 (130 nm) 与 OSU 0.35 μm

### 6.3 评估协议

- **K = 5** 次独立 attempt（per model × task）
- **Prompt 模式**：single-turn, zero-shot，原样 verbatim 使用 VerilogEval 的 module-completion prompt 或 RTLLM 的自然语言 spec
- **3 道 gate 顺序判断**：语法 → 综合 → 仿真
- **综合工具链**：Yosys + Nangate45 45 nm Open Cell Library（baseline）；跨工艺：IHP SG13G2 130 nm、OSU 0.35 μm
- **仿真器**：Icarus Verilog（自带 testbench）
- **仿真判定**：fail-first matching——必须显式出现 "pass" 字符串且之前无 "fail" 信号
- **Top-module 处理**：RTLLM 任务先 strip 注释，再用任务派生的 module name 匹配，否则 fallback 到第一个 `module` 关键字
- **综合失败分类**：9 类 taxonomy，对 Yosys 诊断输出做基于模式的 pattern matching
- **Inference metadata**：通过 OpenRouter 记录 API cost、reasoning token ratio、throughput、TTFT、completion tokens

### 6.4 关键实验参数

- **K-means 聚类**：k=3, silhouette coefficient = 0.59
- **Tier 边界**：3.7 点 gap（rank 14 ↔ 15），7.0 点 gap（rank 29 ↔ 30）
- **Spearman 稳定性测试**：10 种 HQI 权重扰动（area-only、delay-only、3× warning penalty）+ 多种 complexity weighting 方案，ρ ≥ 0.985 且 rank 位移 ≤ 3
- **跨工艺验证**：所有"过 3 道 gate"设计在 3 个工艺库下重新综合，Spearman ρ > 0.99
- **每位 cost 测量**：5 个 deployment 维度，cost 跨度 5 个数量级
- **Reasoning overhead 测量**：GPT-5-Pro 90% 输出为 reasoning，TTFT = 142 s，对比 Gemini-3-Flash TTFT = 1.2 s
- **失败样本**：32,320 次 attempt 中 195 次综合失败（设计 pass Icarus 但 fail Yosys）

### 6.5 运行环境

- GPU/CPU 资源（具体型号未在论文中列出）：K-means 跑在 CPU 上即可
- 工具：Yosys（开源综合）、Icarus Verilog（开源仿真）、Nangate45 45 nm Open Cell Library（开源 PDK）
- 高性能计算：NYUAD 与 Kansas State University 集群

## 7. 创新点

### 7.1 评测范式升级：simulation-only → synthesis-in-the-loop

**出发点**：现有 VerilogEval / RTLLM / OpenLLM-RTL 均以 *testbench pass rate* 作为唯一质量准则，但仿真通过 ≠ 硬件可综合、不等于 area-timing efficient。一个 pass 所有 assertion 的设计可能 *含 non-synthesizable construct* 或 *area 2–5× 大于 expert reference*。

**做法**：在 3 道 gate (Icarus 解析 → Yosys+Nangate45 综合 → testbench 仿真) 全过之后，再用面积/延迟/警告数与 expert golden reference 在同一 flow 下做归一化。

**意义**：评测盲区被显式量化——仿真通过率可比 HQI 平均高出 7.5 点（最大 15 点）。

### 7.2 Hardware Quality Index (HQI) 0–100 复合指标

**形式**：三个 gate 全过才有非零分，否则 HQI = 0；归一化 cost 公式 + min(100/cost, 100) 截断，保证基准可比且不易 blow up。

**核心设计选择**：
- area 与 delay 等权（0.5/0.5）：标准 QoR 实践
- warning 0.1 单边惩罚：warning 是软信号，只在超 golden 时扣分
- 截断 100：防止单 metric 优势放大整体得分

**鲁棒性**：10 种权重扰动 + 多种 complexity 加权方案下，Spearman ρ ≥ 0.985、rank 位移 ≤ 3。

### 7.3 三 Tier 能力梯队（ecosystem-wide characterization）

首次对 32 个 LLM 在 *综合后硬件质量* 维度做生态级画像，揭示 k=3, silhouette=0.59 的天然分层：
- Tier 1 (≥ 66, 14 模型)：以 Gemini-3-Pro (87.5%, 85.1) 为首，全部 GPT-4o→GPT-5.4 OpenAI、5 个 Claude 变体、2 个 Google 模型
- Tier 2 (43–66, 15 模型)：含最强开源 Qwen3.5-397B-OSS (58.2)、DeepSeek-V3.2 (58.8)
- Tier 3 (< 43, 3 模型)：Gemini-2.0-Flash、GPT-5-Nano、Mistral-Nemo

最弱与最强间 4.7× HQI 差距；开源前沿比 Tier 1 最低分低约 10 个 HQI 点。

### 7.4 9 类综合失败 taxonomy

把 195 次综合失败（既能 pass Icarus 又 fail Yosys 的设计）按 Yosys 诊断输出 pattern 划分：

| 类别 | 占比 | 性质 | 集中于 |
|---|---|---|---|
| Late syntax error | 30.0% | 解析通过但 elaboration 失败（malformed always-block、begin/end 错位） | 55/59 来自 RTLLM，多模块结构复杂 |
| Undefined module reference | 25.4% | 忘记 `module top_module (...); endmodule` wrapper | 主要在 VerilogEval |
| Non-synthesizable construct | 20.8% | while-loop 非定常边界、initial block 等 | 31/41 来自 RTLLM |
| Simulation-only system tasks | 7.1% | `$finish` / `$display` 嵌入被综合模块体 | — |
| Synthesis timeout | 7.1% | 30 秒综合预算耗尽，netlist 过大或嵌套过深 | VerilogEval tasks，且**专属 proprietary** |
| Invalid nesting | 5.6% | 嵌套 always-block 等 | — |
| 其他 | 3.9% | 零碎 | — |

**核心发现——proprietary vs open-weight 系统性分裂**：

- **Proprietary 模型（103 failure tags）**：fail late。主导模式是 late syntax error (46%)，加 12% 的 synthesis timeout（独家出现在 proprietary），表明他们的训练语料接触过 synthesis-grade Verilog，结构上"看起来合理"的代码流到 elaboration 阶段才被拒。
- **Open-weight 模型（92 failure tags）**：fail early。undefined module (40%) + non-synthesizable (29%) + simulation-only system tasks (13%) 三类合计 82%，说明训练语料偏向 simulation-oriented Verilog 而非 synthesis-grade RTL。

**含义**：开源模型需要 *模块 wrapper 约定* 的监督微调；闭源模型需要 *netlist 复杂度控制* 的微调。这是未来工作明确指出的优化杠杆。

### 7.5 部署就绪度 Gap（Best-of-5 vs Per-Attempt）

```text
Gap = Global HQI - Expected HQI
```

- Tier 1 范围内 Gap ∈ [3.7, 17.8]（中位数 8.7）
- 即使最强 Gemini-3-Pro 也掉 6.6 HQI 点
- Tier 2/3 部分模型 Gap > 15，最大 22.1

**含义**：当前 LLM 在 agentic pipeline 中的 *first-attempt* 不可靠；5 次独立抽样的能力上限与单次成功率之间存在系统性产能瓶颈。

### 7.6 跨工艺库排名稳定性

IHP SG13G2 (130 nm) + OSU 0.35 μm + Nangate45 (45 nm) 三工艺下重新综合 all-passing 设计，Spearman ρ > 0.99。说明 Nangate45 这一单一工艺下的相对排名 *很大概率* 迁移到工业级工艺。

### 7.7 类别级分析（category-level weakness map）

8 大硬件类别 × 32 模型 × 2 (best-of-5 / per-attempt) = 4 张热力图。

- **最容易**：Combinational Logic（Tier 1 模型 87–95，最弱也超 40）
- **最难**：FSM & Protocols、Memory & Buffers（高方差，Tier 3 接近 0）
- **双峰**：Waveform Reverse Engineering（Tier 1/2 超 75，Tier 3 直接为 0）
- **per-attempt 热图整体下移**：能力上限与单次期望差距在最难类别上最显著

### 7.8 推理特性画像（5 维度部署图）

OpenRouter 记录 5 个部署维度：
- **成本**：相差 5 个数量级，但贵 ≠ 最好；GPT-5-Pro ($0.26/task, 80.5) 被 Gemini-3-Pro ($0.01/task, 85.1) Pareto 支配
- **Reasoning ratio**: GPT-5-Pro 90% 输出是 reasoning，TTFT 142 s，但 HQI 低于非 reasoning 的 Gemini-3-Flash (81.2)
- **Throughput**: 与 reasoning 强反向
- **TTFT**: log scale 跨度 3 数量级
- **Verbosity**: 与质量无相关性——RTL 质量靠 *精度* 而非 *长度*

**Cost-efficiency frontier**: Gemini-3-Flash ($0.002, 81.2) / GPT-5.3-Codex ($0.005, 80.8) / Gemini-3-Pro ($0.01, 85.1) 提供 Tier 1 质量但成本低 10–130×。

### 7.9 失败模型特写

- **Mistral-Nemo**: 57/195 = 29% 失败，集中在 undefined module + non-synthesizable
- **Claude-4.5-Sonnet**: 4/5 timeout（复杂 netlist）
- **Claude-3.7-Sonnet**: invalid nesting
- **GPT-5.4 / -Pro**: 各 3 次失败但 pass > 80% 任务

## 10. 讨论与局限

### 10.1 方法学局限（论文明确声明）

1. **Single-turn, zero-shot prompting**：未涉及迭代式 synthesis-feedback refinement。理论上 iterative refinement 可缩小 capability gap。
2. **数据污染风险**：VerilogEval 与 RTLLM 是公开基准，模型可能在训练时见过。被记忆的解也能综合得很好，但 HQI 不证明 *novelty*。需要一个 held-out 任务集作为更强保证。
3. **开源工具 + 开源 PDK**：面积/延迟数字与工业级 Cadence、Synopsys 流不同，但 3 工艺库 Spearman ρ > 0.99 表明相对排名可迁移。
4. **未触及下游检查**：lint、CDC、reset-quality、DFT、MMMC timing closure 都不在评测范围。
5. **无 P&R 指标**：congestion、hold-time violation 等可能进一步区分模型。
6. **任务集排除项**：system-level integration、analog/mixed-signal、floorplan-aware design 都不在评测集。
7. **快照性**：benchmark 是 2026 年 2–3 月的快照，模型更新后排名会演化。

### 10.2 评测设计局限

1. **Claude-3.5-Sonnet 等旧模型仍在前 14**：可能因为 API 稳定性 > 推理能力；这是 evaluation 跨时间的固有问题。
2. **cost 跨 5 个数量级**：但 paper 不做 cost-constrained Pareto front 的形式化论证。
3. **Nangate45 综合的 QoR**：是 *静态* 估计，没有 *动态* power、没有 IR drop、没有工艺角 (PVT corner)。
4. **HQI 截断 100**：实践中没模型达到上限，但若未来某模型综合质量真的大幅超越 golden，截断会压缩排名。
5. **9 类 taxonomy 是基于 pattern matching**：Yosys 诊断输出文本可能模糊，分类误差未量化。

### 10.3 部署与生态局限

1. **Open-weight 落后 10 HQI 点**：开源前沿在 Tier 2 顶端，但无 *Tier 1 级* 开源模型。
2. **Agentic pipeline 与 first-attempt gap**：22.1 点的最大 Gap 意味着当前 LLM 远未准备好插入 unsupervised agentic 流水线。
3. **闭源 vs 开源失败模式分裂**：开源模型需要 *module wrapper* 监督微调；闭源模型需要 *netlist complexity* 控制。这是论文建议的改进杠杆，但需要另行实验验证（observational data 不蕴含 causation）。
4. **25.4% undefined module reference**：哪怕对 GPT-4.1 这种前沿模型也存在，表明 RTL 格式约束（如"必须以 `module top_module` 开头"）在 prompt 中未被显式纳入。

### 10.4 未来方向

- **Synthesis-grade RTL corpus 整理**：开源模型训练需要包含大量 synthesis-grade Verilog，而不只是 simulation-oriented
- **Module wrapper 约定监督微调**：直接降低 25.4% 的 undefined module reference 失败
- **Netlist complexity 控制**：让闭源模型避免生成超 30 秒综合预算的嵌套结构
- **多 objective 训练**：cost × quality × latency 三维权衡
- **Held-out 任务集**：彻底排除数据污染
- **P&R-aware 评估**：在物理设计后阶段再评测，区分综合后指标相似的模型
- **CDC / lint / DFT 集成**：让评测更接近真实 sign-off

## 12. 一分钟复述版

**主线**：RTL 生成不只是代码生成——设计必须 *语法合法 + 可综合 + 功能正确 + 面积/时序高效*。现有 VerilogEval / RTLLM 评测只看 *testbench pass rate*，把"仿真通过"等同于"硬件可达成"，但一个 pass 所有 assertion 的设计可能 *含 non-synthesizable construct* 或 *area 2–5× 大于 expert*。论文提出 **Synthesis-in-the-Loop** 框架 + **Hardware Quality Index (HQI)** 0–100 指标，把 32 个 LLM × 202 任务 (VerilogEval 155 + RTLLM 47) × 5 次 attempt = 32,320 次生成跑过 Icarus 语法 → Yosys+Nangate45 综合 → testbench 仿真 三道闸门。全过后用 *post-synthesis area / delay / warning count* 与 expert golden reference 在同 flow 下归一化：cost = 0.5·a/a* + 0.5·d/d* + 0.1·max(0, w-w*)，HQI = min(100/cost, 100)。任何一道 gate 失败直接 HQI = 0。

**三大核心发现**：

1. **三 Tier 梯队**：k=3, silhouette=0.59 把 32 模型切成 Tier 1 (≥66, 14 模型，Gemini-3-Pro 87.5% / 85.1 HQI 领跑) / Tier 2 (43–66, 15 模型) / Tier 3 (<43, 3 模型)；最强最弱 4.7× 差距。
2. **仿真过估**：仿真通过率可比 HQI 平均高 7.5 点（最大 15 点），且会让 GPT-4.1 vs GPT-5.4-Pro 排名反转 7 位——premise 的评测结论可被 premise 设定颠覆。
3. **闭源 vs 开源系统性分裂**：闭源 *fail late*（elaboration error / synthesis timeout），开源 *fail early*（undefined module / non-synth construct）——前者训练数据接触过 synthesis-grade RTL，后者偏 simulation-oriented。

**部署就绪度 Gap**：Global HQI − Expected HQI = 3.7–22.1 点。在 agentic pipeline 中 *first attempt propagates downstream*，k 候选 × n 阶段 = k^n 组合爆炸使 multi-sample 路径不可承受。当前 LLM 还没准备好插入 unsupervised agentic 设计流。

**最佳性价比**：Gemini-3-Pro ($0.01/task, 85.1 HQI) Pareto 支配 GPT-5-Pro ($0.26/task, 80.5 HQI)；Gemini-3-Flash ($0.002, 81.2) 提供 Tier 1 质量但成本低 130×。

**意义**：把 EDA 评测从"功能仿真通过"升级到"综合后硬件质量"，建立 0–100 复合指标 + 跨工艺鲁棒排名 + 失败模式分类，为 LLM-for-RTL 提供了 *评估-改进-部署* 的可量化闭环。
