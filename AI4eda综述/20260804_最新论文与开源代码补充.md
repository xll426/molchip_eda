# AI4EDA 最新论文与开源代码补充（核验至 2026-08-04）

> 检索窗口：重点覆盖 2026-07-01—2026-08-03 新增论文，并回查此前论文后来补发的官方代码/数据。  
> 核验原则：优先采用 arXiv/OpenReview、作者或实验室 GitHub、Hugging Face/Zenodo 等一手入口；“论文公开”“代码可见”“有明确开源许可证”“端到端可复现”是四种不同状态。  
> 与本地索引的关系：本文是增量调研，不直接计入现有“38 篇逐论文详细解读”；只有在 PDF 归档、逐篇文档和本地证据审计完成后，才应增加该计数。

## 0. 检索与筛选方法

- 对 arXiv 2026-07-01—2026-08-03 的 RTL、Verilog、circuit、EDA、physical design、formal verification、PCB/RFIC 等组合词进行宽检索，初筛 57 条候选记录。
- 逐篇读标题、摘要、版本日期和论文中的 Code/Data Availability；排除纯软件代码生成、与电子设计无直接关系以及只有第三方聚合链接的结果。
- 对既有 2025—2026 工作反向检查作者组织、论文脚注、GitHub/Hugging Face/Zenodo，寻找论文发布后才补出的资产。
- 最终保留本文 24 项增量工作：10 项有某种官方代码/数据/artifact，14 项只有论文或尚未核验到稳定官方实现。开放状态只按 2026-08-04 快照判断。

## 1. 本轮结论

本轮找到的增量不是简单的“又多几篇 spec-to-RTL 论文”，而是出现了四条更值得补入综述的变化：

1. **更接近真实工程的 RTL benchmark**：ChipVerilog 把评测推进到 64 个来自 OpenCores 处理器、FPU、I2C 和 CORDIC 的局部、多模块与整系统任务；RTL-BenchLS 则强调 round-trip、masked design 与 repository issue，并使用形式等价证据。
2. **验证从生成 testbench 扩展到覆盖率、形式修复与定理证明**：GoGoTB、MechMem-RTL、Rtl2lean 和开放形式工具链研究分别覆盖 coverage closure、复用已验证修复机制、RTL→Lean 4、Yosys/SymbiYosys/Z3 反例闭环。
3. **Agent 评测开始同时考虑 PPA、跨阶段闭合和成本**：ARES 把推理 effort 与美元/token 成本纳入 RTL 优化；FluxBench 与 CLOSER-Bench 直接暴露 RTL-to-GDS、多阶段工具交互的失败模式。
4. **开放资产仍明显落后于论文数量**：截至核验日，真正新增且可确认官方代码/数据入口的重点项目主要是 ChipVerilog、RTL-BenchLS、CircuitEvo、StructRTL、RF-Agent、CircuitWeave、PDAGENT-BENCH 和 Weave；其中数个仓库没有检测到仓库级 LICENSE，不能仅因 GitHub 可访问就称为严格开源。

### 2.1 状态分级

| 状态 | 本文含义 |
|---|---|
| A | 官方代码、核心数据/评测器和明确许可证基本齐全；仍需固定 commit 和环境验证 |
| B | 官方仓库可见且有较实质资产，但许可证、权重、数据、工具或完整复现链至少缺一项 |

### 2.3 三个最容易被误写的细节

- **公开 GitHub ≠ 有开源许可证**：ChipVerilog、CircuitEvo、StructRTL、Weave 在本轮核验时均未检测到仓库级 LICENSE。可以说“官方代码公开可见”，不能无条件说“可自由修改和再分发”。
- **论文池规模 ≠ 当前仓库 release 规模**：RTL-BenchLS 的 10,028 是论文中的整体构建口径；当前仓库可见 release 文件只是其中的若干切片/任务集，引用结果时必须写 commit 和实际文件数量。
- **数据集出现 ≠ 工具环境已开放**：PDAGENT-BENCH 已不再是纯“未来开放承诺”，但当前 HF 页面不足以证明物理设计环境、checker、PDK/工具镜像均已公开。

## 4. 对现有三篇综述导读的实质补充

### 4.1 对 LLM4EDA 综述

原综述以“生成—验证—物理设计 Agent”为主线仍然成立，但需要增加两个正交维度：

- **成本维度**：不仅比较 pass rate/PPA，也固定 token、reasoning effort、EDA 调用次数和美元成本；ARES、FluxBench 是代表。
- **开放资产维度**：分别记录 paper/code/data/weights/evaluator/tool/PDK/license，不能再用一个“开源：是/否”字段压缩。

### 4.2 对 Circuit Foundation Model 综述

建议新增两类跨阶段表示：

- StructRTL 的 RTL CDFG、自监督表示和 synthesis-stage knowledge distillation；
- CircuitEvo 的 graph-structured program/AIG 与 ABC 确定性反馈。

这两类工作说明 circuit foundation model 不应只按“门级图预训练”理解，还包括 RTL→综合 QoR 的跨阶段表示，以及可以被 EDA 工具执行和演化的结构化程序表示。

### 4.3 对 Verilog 生成综述

建议把“规格→单模块 RTL”的主表扩成四条证据链：

1. **真实层次/系统任务**：ChipVerilog；
2. **数据筛选质量**：RTLCurator；
3. **多模态 topology/behavior contract**：CircuitWeave；
4. **验证与证明闭环**：GoGoTB、MechMem-RTL、Rtl2lean、开放形式工具链研究。

## 5. 建议的本地复现排期

| 优先级 | 项目 | 首轮动作 | 成功判据 | 主要风险 |
|---:|---|---|---|---|
| P0 | ChipVerilog | 固定官方 commit，审计目录、任务 manifest、许可证和参考 RTL 来源；先跑不调用 LLM 的 evaluator smoke test | 能从任务 ID 回溯 prompt/reference/checker，复现 README 中至少一个确定性检查 | 无仓库级 LICENSE；部分 reference/Yosys/有界等价有已知口径问题 |
| P1 | RTL-BenchLS | 统计当前实际 release 文件，跑 parser/unit test；把商业 formal 与可开源运行部分分开 | 本地记录精确样本数、hash、许可证和可运行 checker | 10,028 总池与当前切片混淆；完整形式环境可能依赖商业工具 |
| P1 | CircuitEvo | 核对 ABC 版本和输入真值表，先做不含大规模 API 成本的单例 smoke test | 脚本可生成候选并由 ABC 返回确定性 QoR | 无仓库级 LICENSE；API 模型和 Prompt 漂移 |
| P2 | StructRTL | 审计 data schema、split、依赖和训练入口，尝试单 batch 前向 | 记录 dataset 样本单位、图构建和 area/delay 标签来源 | 仓库较新、提交少、许可证未检测到 |
| P2 | RF-Agent | 先做数据 provenance/license 抽样，不立刻把语料用于训练 | 对每类来源建立可追溯清单，再跑 benchmark/harness | 论文/教材来源与二次数据许可可能需要额外确认 |
| 跟踪 | CircuitWeave / PDAGENT-BENCH | 定期检查是否补充代码、模型、harness、release/tag | 从 C 升级到 B/A 后再纳入正式复现队列 | 当前主要是数据入口或压缩包 |

## 6. 复现实验必须新增的记录字段

在现有 paper/code/data/evaluator 字段之外，建议统一加入：

- `asset_verified_at`：链接最后核验日期；
- `repo_commit`、`dataset_revision`、`archive_sha256`；
- `license_code`、`license_data`、`upstream_ip_license` 分列；
- `paper_total_pool` 与 `released_sample_count` 分列；
- `formal_backend`、`commercial_dependency`、`proof_scope`；
- `reasoning_effort`、`tokens`、`tool_calls`、`dollar_cost`；
- `paper_reported` 与 `locally_verified` 分列。

## 7. 本轮没有升级为“已开源”的工作

- FormalRTL：截至 2026-08-04 仍只核验到论文的未来开放表述，没有找到稳定官方仓库。
- ACE-RTL：没有核验到与论文明确绑定的完整官方 release。
- GoGoTB、ARES、FluxBench、CLOSER-Bench、MechMem-RTL、Rtl2lean：均只列论文，不使用“代码已开源”的措辞。
- 论文《Benchmarking LLMs for Verilog Design Flows》虽声称开放平台和 50 个任务，但本轮没有从论文元数据或检索结果中确认唯一作者官方仓库，因此暂不加入已核验仓库表。
